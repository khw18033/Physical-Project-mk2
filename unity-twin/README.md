# unity-twin — 디지털 트윈 뷰어 (VZ-U-02)

로봇·센서의 **전역 좌표를 받아 공간에 배치하는 Unity 뷰어**다. 웹 대시보드와 **나란히**
같은 목 게이트웨이에 붙는 두 번째 클라이언트이며, 웹 대시보드는 그대로 둔다.

**이번 범위는 뷰어뿐이다.** 시뮬레이션·물리·제어 UI는 없다. 왜 그 순서인지는 아래 §왜 뷰어부터인가.

---

## 필요한 것

| | |
|---|---|
| Unity | **6000.3 LTS 계열** 에서 개발·검증했다 (6000.3.3f1). 2022.3 LTS 에서도 동작하도록 API 를 골랐다 |
| 렌더 파이프라인 | **빌트인.** URP·HDRP 를 도입하지 않는다 |
| 패키지 | `com.unity.nuget.newtonsoft-json` (3.2.1) **하나뿐** |
| API 호환성 | .NET Standard 2.1 (기본값). `System.Net.WebSockets.ClientWebSocket` 이 필요하다 |
| 에셋 | 없음. 프리팹·머티리얼·폰트 전부 선택 사항이다 |

### 왜 Newtonsoft 인가 (`JsonUtility` 가 아니라)

계약 봉투에는 **null 허용 필드**(`zone`, `coordinate_frame`, `progress_pct` …)와
**다형 필드**(`aggregation` 은 문자열이거나 객체, `payload` 는 채널마다 다르다)가 있다.
`JsonUtility` 는 둘 다 다루지 못한다. 그리고 `VZ-C-06` 의 원천 종류 표기는
**"키가 아예 없다"와 "키는 있는데 값이 이상하다"를 구분해야 하는데**, `JsonUtility` 로는
그 구분이 불가능하다 — 둘 다 기본값이 된다. 그 구분이 이번 작업의 핵심 중 하나다.

> 그 외 패키지는 도입하지 않았다. 에셋 스토어 · TextMeshPro · DOTween 전부 없다.

## 씬 세팅 — 3분

1. Unity Hub 에서 **빈 3D(빌트인) 프로젝트**를 `unity-twin/` 에 만든다.
   (이미 `Assets/Scripts/` 가 있으므로 Unity 가 그대로 읽는다.)
2. **Window ▸ Package Manager ▸ + ▸ Add package by name** → `com.unity.nuget.newtonsoft-json`
3. 빈 씬을 만든다. **카메라·조명도 필요 없다** — 없으면 코드가 만든다.
4. 빈 GameObject 를 하나 만들고 이름을 `TwinViewer` 로 한다.
5. 그 오브젝트에 **`TwinViewer` 스크립트 하나만** 붙인다.
6. 인스펙터에서 `Gateway Ws Url` / `Gateway Http Url` 이 목 게이트웨이 주소와 맞는지 본다.
   기본값은 `ws://127.0.0.1:8787` · `http://127.0.0.1:8787`.
7. 재생(▶).

프리팹·머티리얼을 붙이고 싶으면 인스펙터의 `Robot Prefab` 등에 넣으면 된다.
**비워 두면 프리미티브(캡슐·원기둥·큐브)로 대체 생성**되므로 아무것도 없어도 돌아간다.

### 조작

| | |
|---|---|
| 우클릭 드래그 | 카메라 회전 |
| 휠 | 확대·축소 |
| 가운데 버튼 드래그 | 평행 이동 |
| **F1** | 진단 패널 접기/펴기 |
| **H** | 손잡이 플래그 뒤집기 (검증용) |

### 이름표에 한글이 네모로 보이면

빌트인 `TextMesh` 는 기본 폰트에 한글 글리프가 없을 수 있다. `TwinViewer` 인스펙터의
`Label Font` 에 한글 폰트(예: `C:\Windows\Fonts\malgun.ttf` 를 프로젝트로 끌어다 놓은 것)를
넣으면 된다. **폰트를 넣지 않아도 뷰어 동작에는 영향이 없다.**

## 목 게이트웨이 기동

Unity 는 값을 만들지 않는다. 게이트웨이가 떠 있어야 씬이 채워진다.

```powershell
cd web-dashboard
npm install          # 최초 1회
npm run dev:mock     # 목 게이트웨이만 (기본 포트 8787)
```

웹 대시보드까지 같이 띄우려면 (검증 9 — 두 화면 대조):

```powershell
cd web-dashboard
npm run dev          # 목 게이트웨이 + Vite 동시
```

### 포트가 8788 인 경우

`web-dashboard/.env.local` 이 `8788` 을 가리키고 있으면 웹은 그 포트를 쓴다.
그때는 게이트웨이를 `MOCK_PORT=8788 npm run dev:mock` 으로 띄우고, Unity 인스펙터의
두 주소도 8788 로 맞춘다. **하드코딩된 곳은 없다.**

### 시나리오 재생 (검증용)

```powershell
curl http://127.0.0.1:8787/scenario/camera-silence   # camera-02 침묵 → 60초 뒤 판단 불가
curl http://127.0.0.1:8787/scenario/sensor-offline   # sensor-02 연결 끊김 → 장애
curl http://127.0.0.1:8787/scenario/robot-mission    # robot-01 임무 모드(50ms 발행)
curl http://127.0.0.1:8787/scenarios                 # 전체 목록
```

## 왜 뷰어부터인가

Unity 가 시뮬레이터와 뷰어를 겸하면 **뷰어가 시뮬레이터의 내부 상태를 직접 읽는 지름길**이
생긴다. 그러면 화면은 완벽한데 파이프라인은 한 번도 안 거치고, 실제 백엔드를 붙이는 순간
전부 어긋난다. 디지털 트윈이 아니라 씬이 혼잣말하는 상태다.

뷰어를 먼저 게이트웨이에 붙여 두면 **왕복이 구조적으로 강제**되고, 그 뒤에 목의 가짜 장치를
Unity 시뮬로 하나씩 갈아끼워도 경로가 유지된다.

그래서 이 코드에는 **씬 안의 오브젝트가 서로의 Transform 을 직접 읽는 경로가 없다.**
위치는 오직 수신한 봉투에서만 온다.

```
수신 봉투 → TwinStore → PoseBuffer → PoseInterpolator → EntityView
```

(단 하나의 예외는 `WorldLabel` 의 빌보드가 카메라 Transform 을 읽는 것이다. 트윈 상태를
나르지 않는 순수 표현이고, 그 사실을 해당 파일 머리말에 남겨 두었다.)

## 손잡이(handedness) — 기본값과 근거

### 무엇이 문제인가

Unity 는 **왼손 좌표계**다. 계약 `BE-C-04` 는 `y=위 · 바닥 x-z · 미터` 로 **축만** 정하고
손잡이를 말하지 않는다. 백엔드가 로보틱스 관례(오른손)로 값을 주면 **좌우가 뒤집혀 보인다.**
회전이 섞이면 눈으로 잡기도 어렵다.

### 어디서 처리하는가

**`View/FrameConvert.cs` 한 곳뿐이다.** 이 파일 밖에 축을 만지는 코드가 없다.

이것은 "좌표 변환 금지"(`BE-C-04` · `DT-03`)의 예외가 아니라 **표현 변환**이다.
좌표 변환은 *어느 기준점에서 잰 값인가*를 바꾸는 일이고 백엔드 단독 책임이다.
표현 변환은 *같은 점을 이 렌더러의 관례로 그리는* 일이고, 그리는 쪽이 흡수해야 한다 —
백엔드가 특정 렌더러 관례를 떠안기 시작하면 **뷰어가 둘이 될 때 무너지기** 때문이다.
자세한 근거는 [`contracts/twin-viewer.md`](../contracts/twin-viewer.md) §3.

### 기본값: **OFF (변환하지 않음)**

| | |
|---|---|
| OFF | 수신 좌표를 Unity 왼손계 값으로 **그대로** 그린다 |
| ON | 수신 좌표를 오른손계로 보고 **z 부호를 뒤집어** 그린다 |

기본을 OFF 로 둔 이유 셋 —

1. **아직 합의 전이다.** ON 을 기본으로 두면 "백엔드가 오른손으로 준다"를 코드가 먼저
   단정하는 것이 된다. 확정되지 않은 것을 기본값으로 굳히지 않는다.
2. **계약 문구가 이미 렌더러 친화적이다.** `BE-C-04` 는 `y=위 · 바닥 x-z` 라고 썼다.
   로보틱스 관례(ROS)는 `z=위` 이므로, y-up 을 명시했다는 것은 작성자가 이미 그래픽스
   쪽 프레임을 염두에 두었다는 신호로 읽는다. 확증은 아니지만 기본값을 고를 근거는 된다.
3. **"아무것도 하지 않음"이 안전한 기본이다.** 규칙 3(좌표 변환 금지)의 기본 자세와
   같은 방향이고, 변환은 명시적으로 켜는 선택으로 남는다.

**플래그는 인스펙터에서 언제든 켜고 끌 수 있다**(`TwinViewer.flipHandedness`, 재생 중에도
`H` 키로). 합의되면 플래그를 없애고 한쪽으로 고정한다.

### 비대칭 마커 — 가장 값싼 보험

씬 원점에 **대문자 F 모양 표식**이 서 있다. 대칭인 물체(캡슐·구)만 있는 씬은 좌우가
뒤집혀도 아무도 못 알아챈다. 로봇이 원을 그리며 돌면 뒤집힌 궤적도 똑같이 원이다.
F 는 거울상을 즉시 알아볼 수 있는 형태이고, 계약 좌표의 z-y 평면에 세워 두었으므로
**z 부호를 뒤집는 손잡이 변환이 정확히 이 F 를 뒤집는다.** 축 세 개에도 이름표가 붙어 있다.

마커도 다른 모든 것과 **같은 변환을 거쳐** 그려진다. 마커만 Unity 좌표로 직접 그리면
플래그를 뒤집어도 마커는 그대로라 무엇이 기준인지 알 수 없게 된다.

## 계약 — 이 뷰어가 다시 만들지 않는 것

전부 계약이지 구현 선택이 아니다. 각 규칙이 어느 요구사항에서 왔는지는 해당 파일 주석에 있다.

1. **`stale` 판정은 서버가 한다.** 마지막 수신 시각으로 다시 계산하지 않는다 — 사용자 PC
   시계에 의존하게 되고 웹과 판정이 갈린다 (`Data/StatusModel.cs`)
2. **상태 3층을 단일 값으로 뭉치지 않는다.** `device_status` / `availability` / `deployment`
   를 각각 보관하고 표시값은 파생시킨다 (`Data/TwinStore.cs` · `StatusModel.cs`)
3. **좌표 변환을 하지 않는다.** 봉투에 오는 것은 이미 변환된 전역 좌표이고
   `coordinate_frame` 은 **읽어서 표시만** 한다 (`Data/TwinStore.cs`)
4. **구독은 계약 축 `{entity, node, channel}`.** 토픽 문자열을 조립하지 않는다 (`Transport/`)
5. **구독 즉시 현재값 1회 푸시**를 받아 걸러내지 않는다 (`BE-T-06` / `VZ-I-02`)
6. **재연결 시 기존 구독을 자동 복원**한다. 지수 백오프 (`Transport/GatewayWebSocketTransport.cs`)
7. **미배포 대상을 레지스트리 근거로 그린다.** `robot-03` 은 아무 값도 발행하지 않지만
   씬에 있다 (`VZ-I-03`)
8. **집약 표기를 읽고 재집약하지 않는다.** 못 읽는 표기는 `raw` 가 아니라 `unknown` 으로
   두고 연산을 막는다 (`Data/AggregationSpec.cs`)
9. **권한 범위 밖 대상은 구분해 표시한다.** 지우지 않는다 — 조작 차단과 존재 은폐는 다르다
10. **원천 종류 표기를 읽는다.** 없거나 못 읽으면 `unknown` (`Data/OriginKindSpec.cs`)

> **웹의 `src/data/` 코드를 옮겨 붙이지 않았다.** 같은 규칙을 C# 관용구로 다시 썼다.
> 두 곳에 있는 규칙 목록과 "어긋나면 어디가 먼저 티가 나는가"는
> [`contracts/twin-viewer.md`](../contracts/twin-viewer.md) §2 에 있다.

## 씬에서 무엇이 어떻게 보이는가

### 상태 4종 (VZ-U-01) — **색만으로 구분하지 않는다**

관제 화면에서 색약·저조도·프로젝터 투사는 흔한 조건이고, 그때 색만 다른 네 상태는
한 상태가 된다. 그래서 상태마다 **색 + 형태 + 자리**가 함께 바뀐다.

| 상태 | 색 | 형태 | 자리 |
|---|---|---|---|
| 정상 | 초록 | 표식 없음 | 제자리 |
| 장애 | 빨강 | 머리 위 **세로 막대** (멀리서·가려져도 보인다) | 제자리 |
| 의도적 미배포 | 회색 | 머리 위 **납작한 판**, 몸체 60% 크기·반투명 | 살짝 가라앉음 + 바닥에 자리 고리 |
| 판단 불가 | 호박색 | 머리 위 **기운 원반**(후광) | 제자리, **크기 그대로** |

- **판단 불가를 "사라짐"으로 표현하지 않는다.** 없는 것과 모르는 것은 다르고, 관제에서
  이 둘을 섞으면 위험하다. 작게 그리지도 않는다 — 모르는 것은 덜 중요한 것이 아니다.
- **미배포도 자리에 있다.** 흐리게라도 있어야 "여기 있어야 할 게 안 왔다"가 보인다.

### 원천 종류 (VZ-C-06) — 실물과 시뮬레이션이 같아 보이면 안 된다

대상 오른쪽 위에 작은 표식이 붙는다. **색과 모양이 함께** 바뀌므로 흑백에서도 갈린다.

| 원천 | 색 | 모양 | 이름표 |
|---|---|---|---|
| 실물 | 흰색 | 정육면체 | 실물 |
| 시뮬레이션 | 청록 | 구 | 시뮬레이션 |
| 기록 재생 | 보라 | 캡슐 | 기록 재생 |
| **미상** | 짙은 회색 | **납작한 원반** | 원천 미상 / 원천 표기 불명 |

**목 게이트웨이는 아직 이 표기를 싣지 않는다.** 그래서 지금 재생하면 **전부 "원천 미상"**
으로 뜬다 — 그것이 이번 범위에서 확인해야 하는 상태다. 표기가 없다고 실물로 단정하지
않는다. 필드 형태 제안은 [`contracts/twin-viewer.md`](../contracts/twin-viewer.md) §4.

### 권한 범위 (VZ-C-04)

범위 밖 대상은 **채도가 낮아지고 이름표에 `[권한 범위 밖]`** 이 붙는다. 씬에서 지우지
않는다. 이번 범위에 제어 UI 자체가 없으므로 잠글 버튼은 없고, 표시 구분만 한다.

### 보간 (VZ-U-02)

- 수신값(임무 중 50ms) 사이를 메워 **매 프레임** 그린다. 씬 상태 반영(100ms 병합)과 **다른 축**이다.
- **외삽하지 않는다.** 최신 표본을 넘어서면 거기서 멈춘다 — 수신이 끊겼을 때 마지막
  속도로 계속 미끄러지면 **죽은 로봇이 화면에서 계속 움직인다.** 관제에서 가장 나쁜 거짓말이다.
- 정지 조건 둘 — ① `availability` 가 `stale`·`offline` 이면 즉시, ② 마지막 수신 이후
  `stale_threshold_ms` 경과. **임계는 서버가 준 값이다.** 뷰어가 임의 상수를 만들지 않는다.
- 정지해도 **사라지지 않는다.** 있던 자리에 선다.

## 알려진 제약

### WebGL 빌드에서는 지금 구현체가 돌지 않는다

`System.Net.WebSockets.ClientWebSocket` 은 소켓과 스레드를 쓰므로 **WebGL 에서 동작하지
않는다.** 에디터·데스크톱에서는 문제가 없다.

웹 대시보드 경유 안으로 가거나 WebGL 빌드가 필요해지면
**`GatewayWebSocketTransport.cs` 를 통째로 갈아끼우는 자리**다. 그때 상위 코드
(`Data/` · `View/`)는 한 줄도 바뀌지 않는다 — 전송을 `ITwinTransport` 뒤로 격리해 둔 이유다.

### 빌드 시 셰이더

머티리얼을 코드에서 만들므로(`StatusPalette`) 빌드에서 `Standard` 셰이더가 스트립될 수 있다.
**Project Settings ▸ Graphics ▸ Always Included Shaders** 에 `Standard` 를 넣으면 된다.
에디터 재생에는 영향이 없다. 코드에는 `Legacy Shaders/Diffuse` → `Unlit/Color` 대체 사슬이 있다.

### 자세(orientation)가 계약에 없다

봉투는 **위치만** 준다. 로봇이 어느 쪽을 보고 있는지 그릴 수 없다. `velocity` 로 추정할
수는 있지만 **추정이므로 하지 않았다** — 보간과 추정을 가르는 것과 같은 이유다.
계약 미결 항목이다.
