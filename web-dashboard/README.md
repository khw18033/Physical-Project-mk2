# web-dashboard

가시화 레이어의 웹 프런트엔드. 현재는 **계약 검증용 프로토타입 단계**다.

## prototype.html 실행 방법

브라우저는 `file://`로 열린 페이지가 로컬 JSON을 읽는 것을 차단하므로, 저장소
루트에서 정적 서버를 띄워야 한다.

```bash
# 저장소 루트에서
python -m http.server 8000
```

→ http://localhost:8000/web-dashboard/prototype.html

### 라이프사이클 초기 상태 지정

특정 상태의 화면을 그대로 보거나 캡처하려면 쿼리 파라미터를 쓴다.

```
?lifecycle=camera-01:active,batch-processor-01:active
```

상태 값은 `active`(정상) / `undeployed`(의도적 미배포) / `failed`(장애)이며,
화면에서 버튼으로도 전환할 수 있다.

## 이 프로토타입이 하는 일

백엔드(Go 코어 엔진) 없이 `contracts/examples/`의 **실제 계약 파일만 읽어**
대시보드를 구성한다. 계약 사본을 두지 않으므로 계약이 바뀌면 이 화면도 바로
따라 바뀐다.

| 요구사항 | 프로토타입에서의 구현 |
|---|---|
| F1 (REQ-101~104) | 디스크립터를 읽어 필드·단위·값범위·enum 값을 해석 |
| F2 (REQ-201~203) | 라이프사이클 3상태 전환. **의도적 미배포와 장애를 서로 다른 화면으로 구분** |
| F4 (REQ-401~404) | `edges`를 따라 source→transform→sink 실행. `resample`, `unit-convert` 연산자 구현 |
| F5 (REQ-501~503) | 렌더러 카탈로그 4종(text / table / graph / video-stream). `rendererConfig` 반영 |
| F7 (REQ-701~702) | 데이터소스 디스크립터를 읽어 표시(질의는 목으로 대체) |

## 프로토타입의 한계 (실제 구현과 다른 부분)

1. **데이터 소스가 목(mock)이다.** 실제 코어는 `source.query`(PromQL 등)를
   DataSource에 넘겨 해석하지만, 여기서는 질의 문법을 해석할 수 없으므로
   sink가 가리키는 디스크립터 필드의 메타데이터(`valueRange`, `enumValues`,
   `unit`)로부터 값을 합성한다. 역설적으로 이것이 REQ-103 메타데이터가 충분한지에
   대한 검증이 된다.
2. **파이프라인 그래프를 선형 체인으로만 순회한다.** 분기/합류(join) DAG는
   아직 다루지 않는다.
3. **영상 스트림은 플레이스홀더다.** 실제 스트림 연결은 백엔드가 필요하다.
4. **F8 validator가 없다.** 참조 무결성(존재하지 않는 렌더러·필드 참조 등)은
   런타임에 패널 안에서 오류로만 표시된다.
5. **F6 이벤트 규칙은 미구현이다.** 이번 초안 범위에서 제외했다.
