## 1. 이 엣지가 하는 일 — 데이터 세 갈래

### 1-1. 갈래마다 길이 따로다

| 갈래 | 파이 → 엣지 | 엣지 안 | 엣지 → 서버 | 지금 |
|---|---|---|---|---|
| **업무**(상태 · 등록 · 심박) | 파이 브로커(`:1883`) → **파이 브리지** → 이 노트북 브로커 | **가용성 판정기**가 판정 → **Prometheus** 가 15초마다 쌓음 | **엣지 브릿지(E2)** → 서버 Kafka `100.102.8.102:9095` | 엣지까지 ✅ · 서버로는 ❌(S1) |
| **관측**(OTel — CPU · 메모리 · 디스크 · 발행 성공/실패 · 명령 경로 추적) | 파이가 **이 노트북 Collector `:4317`** 로 직접 보냄 | Collector → 지표는 **Prometheus**, 로그 · 추적은 **파일**(`C:\mk2_edge\logs\otel_*.jsonl`) | 지표: **서버가 엣지 Prometheus 에서 당김**(S3) · 로그 · 추적: Collector → 서버 `4316`(S2) | 받는 쪽 ✅ · 파이가 안 보냄 ❌(T2) · 서버로는 ❌ |
| **영상** | (RTP `5004`) | (수신단 E6) | (송신기 E7 → 서버 `8766`) | 이 엣지의 범위 밖 |

- 세 갈래는 **같은 노트북을 지나지만 서로 다른 프로그램**이다. 하나가 죽어도 다른 둘은 돈다.
- **엣지에는 DB 가 없다.** 업무 데이터의 원본은 서버(TSDB · MySQL)에 쌓이고, 엣지는 중계한다. 엣지에 남는 것은 ① Prometheus 의 지표 원본 ② (엣지 브릿지를 띄우면) 형식이 틀린 메시지 · 서버로 못 보낸 메시지 파일 ③ Collector 의 로그 · 추적 파일이다.

### 1-2. 서버와 끊기면

| 갈래 | 끊긴 동안 | 다시 붙으면 |
|---|---|---|
| 업무(엣지 브릿지를 띄운 뒤) | 메시지마다 5분까지 들고 기다린다 | 5분 안의 것은 자동으로 다시 보낸다. 넘긴 것은 `C:\mk2_edge\logs\unsent_edge.jsonl` 에 남는다(다시 흘려 넣는 도구는 아직 없다) |
| 관측 지표 | 엣지 Prometheus 가 계속 쌓는다(15일 보관) — 엣지에서 언제든 조회 | 서버는 **그 순간 값만** 당긴다 — 끊긴 동안의 값은 엣지에만 있다 |
| 관측 로그 · 추적 | 지금은 엣지 파일에 쌓는다 | (S2 에서 서버로 보내게 바꾸면) 메모리 대기 + 5분 재시도 뒤 버림 — 디스크에 들고 있다 보내려면 따로 설정(S2 의 정할 것) |

### 1-3. VZ · DS 와의 관계 — 서로 건드리지 않는다

- **VZ**(이 노트북 브라우저 `localhost:5174`)는 로봇 상태 · 명령을 **각 파이 브로커에 직접**(`ws://<파이>:9001`) 주고받는다. 이 엣지 브로커를 거치지 않는다.
  서버 연동(S1) 뒤에는 VZ 「백엔드 WS 게이트웨이」 칸에 서버 주소를 넣어 **서버를 거친 데이터**도 볼 수 있다(S6).
- **DS** 는 WSL(`Ubuntu-26.04`) 안에서 돌고(바탕화면 DS 런처), 파이 브로커 · 카메라에서 직접 받는다. WSL 에 Tailscale 이 따로 있다(`100.125.104.23`).
- 엣지 · VZ · DS 의 포트는 겹치지 않는다(부록 A).

### 4-1. `C:\mk2_edge\mosquitto_edge.conf` — 브로커 + 파이 브리지 다섯


| 줄 | 뜻 |
|---|---|
| `listener 1883 0.0.0.0` · `allow_anonymous true` | 모든 주소에서 1883 을 받는다 · 인증 없음(이번 범위 — 결정 K8 (b)) |
| `log_dest …` | 화면과 `logs\mosquitto.log` 둘 다에 쓴다 |
| `connection <파이>` · `address` | 파이 브리지 하나 — 그 파이 브로커에 붙는다(DS 주소 파일의 tailnet 주소) |
| `remote_clientid edge-book4vg1edpvi5-<파이>` | 파이 브로커에 보이는 이름 |
| `cleansession true` | 이 노트북이 꺼진 동안 파이 쪽에 쌓아 두지 않는다(파이 부담 없음 · 그동안 것은 못 받는다) |
| `notifications true` · `notifications_local_only true` | 브리지가 붙었는지(1) · 끊겼는지(0)를 **이 노트북 브로커에만** `$SYS/broker/connection/edge-book4vg1edpvi5-<파이>/state` 로 알린다 |
| `topic +/+/+/state in 1`(status · heartbeat 도) | 이 세 채널만 **받기만** 한다(QoS 1). 사진(`frame`) · 스캔 · 명령 응답(`terminal/…`)은 끌어오지 않는다. **파이 쪽에는 아무것도 쓰지 않는다** |
| (없는 줄) 다시 붙는 간격 | Mosquitto 기본 — 5초에서 30초까지 늘려 가며 계속 다시 붙는다. 파이가 꺼져 있으면 연결 실패 · 다시 시도 줄이 반복되는 것이 정상 |

정한 것(2026-11-20): B1 다섯 다 · B2 세 채널만 · B3 받기만 · B4 다섯 다 넣고, 파이를 켰을 때 pi7 · pi1 의 `go1-001` 이 겹치는지 보고 겹치면 그때 하나를 뺀다(8-1) · 세부 값 위 표대로.
