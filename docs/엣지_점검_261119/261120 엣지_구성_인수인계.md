## 1. MK2 가 무엇인가

- **국가 인프라 전제의 엣지–클라우드 관측 백엔드 + 디지털 트윈**(BE 담당 이대규). 센서 · 이동체 · 엣지 · AI 가 내는 데이터를 **성격(업무 · 관측 · 영상)에 따라**
  저장 · 중계 · 번역한다. MQTT · Kafka · OpenTelemetry · K3s · Tailscale 은 **지금 쓰는 구현(교체 가능)** 이다 — `CLAUDE.md` §0 「프로젝트 개요」.
- **5구간**(`CLAUDE.md` 「흐름 요약」 · `00-architecture.md` §2):
  1. 말단 ↔ 엣지 = 업무 MQTT / 관측 OTLP / 명령 하달 MQTT / 생사 LWT + 하트비트
  2. **엣지 내부 = Mosquitto + MQTT→Kafka 브릿지 + Collector(Agent) + 엣지 Prometheus + K3s** ← 이 방의 대상
  3. 엣지 ↔ 서버 = 업무 Kafka / 관측 페더레이션 요약 / log · trace 원본 / 명령 Kafka — 전부 하나의 Tailscale 터널
  4. 서버 내부 = Kafka 다중 소비자 → AI · TSDB · 트윈 · MySQL(감사 · 레지스트리) · 가용성 통합 단일 지점 · Collector(Gateway) → Loki · Tempo
  5. 서버 ↔ 사용자 = WS 게이트웨이(실시간 push) · 조회 프록시 · 미디어 WS 중계
- **진행:** Phase 0 ~ 4 완료 → 실측 재개(2026-10-21 ~ 11-13, 이대규 PC 를 엣지로 · 끊김 버티기 실측) 완료 → 다음은 합동 실측과 Phase 5(가용성 판정기)
  (`01-standalone-implementation-plan.md` 「지금 당장 할 일」 ⑥-4 · ⑦).
- **지금(2026-11-19 사용자):** 원래 **로봇 → 엣지(노트북) → 서버** 였는데 지금은 **로봇 → 엣지** 까지만 돈다. 서버를 안 거치는 것은 괜찮다(목적은 잘 도는 것).
  다만 **설계가 엣지에 두기로 한 것을 엣지에 먼저 확실히 세우고, 그다음 원격 서버 연결.**
- **저장소:** `https://github.com/khw18033/Physical-Project-mk2` — BE 브랜치 `ldg_BE` · HW 브랜치 · VZ 브랜치 `khw_VZ`. **저장소가 Public 이다**(실주소 · 토큰을 커밋하지 않는다).

## 3. MK2 가 데이터를 어떻게 다루기로 했나 — 설계

근거: `00-architecture.md` §2 · §3 · §4 · §5 · §6-4 · §8-1 · §8-3 · §8-5 · `CLAUDE.md` §1 원칙 · `작업지시_phase3_관측파이프라인.md` 단계 8 ·
`requirement-traceability.md` BE-S-02 · S-03 · S-06 · T-02 · `reports/2026-11-13_2100_실측시연.md` · v2.4 §3-2(나) · HW `BACKEND_AGENDA.md` §6 · §10-2 · §12.

### 3-1. 데이터는 세 갈래 — 갈래마다 길이 따로다 (원칙 2 「데이터 성격이 채널을 결정한다」)

| 갈래 | 말단 → 엣지 | 엣지 안 | 엣지 → 서버 | 서버 안(저장) | 화면 |
|---|---|---|---|---|---|
| **업무**(상태 · 등록 · 심박 · 명령) | MQTT `1883` | **E1 Mosquitto** · **E2 MQTT→Kafka 브릿지**(2단 검증 · 격리) | Kafka `100.102.8.102:9095` | 계측 → TSDB · 감사 · 레지스트리 · 임무 실행 기록 → MySQL | WS `8765/state` |
| **관측**(metric · log · trace) | OTLP gRPC `4317` | **E3 Collector(Agent)** · **E4 엣지 Prometheus**(metric 원본 보관) | metric 은 **서버가 엣지 `9090` 에서 요약만 당긴다**(페더레이션) · log · trace 는 원본 그대로 서버 Collector `4316` | 서버 Prometheus · Loki · Tempo | Grafana |
| **영상** | RTP/UDP `5004`(홉1) | **E6 미디어 게이트웨이**(홉1 수신 · 프레임 재조립) | WS `8766/ingest`(홉2 — E7) | 저장 안 함(중계만) | WS `8765/media` |

- 세 갈래는 같은 엣지를 지나지만 **엣지 안에서 다른 프로그램**이다. 하나가 죽어도 다른 둘은 흐른다.
- 엣지 → 서버는 전부 **엣지가 서버로 나가는 방향**이다. **예외 하나 — 페더레이션만 서버가 엣지 `9090` 으로 들어온다**(엣지 방화벽에 서버 주소를 연다 — v2.4 단계 5).
- 영상 픽셀은 MQTT · Kafka · OTLP 에 싣지 않는다(원칙 3).

### 3-2. 관측은 세 층 — 어디서 만들고 어디에 쌓나 (`00-architecture.md` §8-3)

| 층 | 무엇 | 만드는 곳 | 쌓는 곳 | 엣지와의 관계 |
|---|---|---|---|---|
| A. 백엔드 자기 관측 | 브릿지 · 저장 · 게이트웨이가 잘 도는가(`be_*`) | BE 프로그램 | 서버 Prometheus · Loki | 엣지 브릿지도 낼 수 있다(`MK2_OTEL_ENDPOINT`) — 지금 엣지 브릿지는 **끈다**(빈칸 하나) |
| **B. 말단 노드 관측** | 노드 CPU · 메모리 · 디스크 · MQTT 발행 성공/실패 · 발행 지연 + 명령 경로 span | **말단**(HW `otel_metrics.py` · `otel_trace.py`) | **엣지 Collector → 엣지 Prometheus(원본)** → 서버는 요약만 · log · trace 는 서버 Loki · Tempo | **엣지가 받는 층 — E3 · E4 의 존재 이유** |
| C. 업무 값의 관측 표현 | 수위 · 배터리 · 속도 같은 업무 값을 지표로도 | 값을 받은 쪽 — 지금 구현은 **서버 저장 소비자**(`backend/storage/derive.py`) 하나 | 서버 Prometheus | 엣지에는 구현이 없다 |

B층 다섯(HW `otel_metrics.py`) — 엣지 Prometheus 에서는 점이 밑줄로 바뀌어 `system_cpu_utilization…` · `system_memory_utilization…` · `system_filesystem_free…` ·
`hw_publish_count_total` · `hw_publish_duration_…` 로 보인다. resource 속성 `service.name = hw-<종류>-node` · `hw.entity_id` · `hw.node_id` · `hw.zone_id`.

### 3-3. DB — 엣지에는 DB 를 두지 않는다

- TSDB · MySQL · Kafka 브로커는 **서버에만** 있다(브릿지는 서버 Kafka 에 원격으로 쓴다 — §4-2 「엣지에 Kafka 브로커/저장소는 없다」).
- 엣지에 남는 기록: ① **엣지 Prometheus 의 metric 원본** ② 엣지 브릿지의 **격리 파일 · 미전송 파일** ③ (말단 쪽) HW 노드의 spool(브로커와 끊긴 동안 말단이 쌓는 것)
  ④ 🆕 **이번에 더한다 — Collector 의 log · trace 로컬 파일**(서버가 없는 동안, 사용자 결정 11-20 — 6장).

### 3-4. 정해 둔 규칙 — 그대로 지킨다

| 규칙 | 근거 |
|---|---|
| **엣지 Prometheus 가 원본(raw)을 짊어진다** — 서버로 원본을 몰지 않는다(부하가 구역 수에 비례) | 원칙 14 · §4-3 · §5-2 · BE-S-03 |
| **경계 표기** — 엣지 Prometheus 가 `external_labels` 로 `zone_id: zoneA` · `agg_layer: edge` 를 붙인다. 서버가 직접 모은 것에는 이 표가 없다 | BE-S-06 · 단계 8-4 |
| **장치 생사 · 치명 오류는 metric 요약에 섞지 않는다** — 서버 페더레이션 `match[]` 에 `up` · 생사를 넣지 않는다 | 원칙 6 · 단계 8-6 |
| **장치 최종 가용성은 서버(백엔드)가 단일 지점에서 판정한다 — 충돌 시 업무 평면(MQTT 세션) 우선** | 원칙 7 · §6-4 · Phase 5 |
| log · trace 는 요약하지 않고 원본을 유지한다 | 원칙 6 · §5-3 |
| 관측 라벨에 값이 계속 바뀌는 것(시각 · `session_id` · `sequence_id` · 상관키 …)을 넣지 않는다 | `contracts/common/README.md` 「관측 신호 힌트와 라벨 금지」 |
| 브로커 인증은 이번 범위가 아니다 — **엣지 방화벽 `1883` 인바운드가 실질 통제** | v2.4 §3-2(나) · `엣지_세우기.md` 2-3 |

### 3-5. 「서버와 끊기면 엣지에 저장했다가 나중에 보낸다」 — 설계가 실제로 정한 것

사용자 기억(11-20): *"서버 연결 끊기면 엣지에서 뭐 저장하고 있다가 나중에 보낸다. 혹은 일단 엣지에 저장하고 나중에 확인한다. … otel, 프로메테우스도 엣지에 두면 엣지에 데이터가 모이고 서버로는 보내는 것뿐."*
갈래마다 다르다.

| 갈래 | 서버와 끊긴 동안 | 다시 붙으면 | 근거 |
|---|---|---|---|
| **업무**(E2) | 메시지 하나당 **5분까지** 브릿지(생산자) 메모리에 들고 기다린다 | 5분 안의 것은 **자동으로 다시 보낸다**(켠 뒤 3 ~ 8초 · 순서 · 중복 문제 없음). 5분을 넘긴 것 · 대기열이 넘친 것 · 종료 때 남은 것은 **미전송 파일에 원본 그대로** 남는다 — **그 파일을 다시 흘려 넣는 도구는 없다**(「필요해지면 만든다」) | §4-2 「끊김 버티기」 · `2026-11-13_2100_실측시연.md` · BE-T-02 gap |
| **관측 metric**(E3 → E4) | **엣지 Prometheus 가 계속 쌓는다**(보존 기본 15일) — **엣지에서 언제든 조회**한다 | 서버는 `/federate` 로 **그 순간의 현재 값**만 당긴다 → **끊긴 동안의 값은 서버로 채워지지 않는다**(엣지에만 있다) | §5-2 · BE-S-03 gap ③ · [Prometheus 문서](https://prometheus.io/docs/operating/federation) 「the `/federate` endpoint allows retrieving the current value」 |
| **관측 log · trace**(E3) | 설계는 **원본을 서버로 바로 전달**(엣지에 쌓지 않는다). 🆕 서버가 없는 지금은 **엣지 로컬 파일**(6장) | 파일에 쌓인 것은 서버로 다시 가지 않는다. 서버 연결 뒤 Collector 의 서버 전송은 기본이 **메모리 대기열 + 5분 재시도 → 그 뒤 버림** · 디스크에 들고 있다 보내려면 **persistent queue(`file_storage`)** 를 켜야 한다 — 서버 단계 결정(12장 S2) | §5-3 · [OTel Collector Resiliency](https://opentelemetry.io/docs/collector/resiliency/) |
| 말단 ↔ 엣지(HW 노드) | 브로커와 끊기면 **말단 spool** 이 쌓는다 | 이산 사건은 전량 · 연속값은 1 Hz 로 줄여 다시 보낸다(`replayed: true`) | HW `BACKEND_AGENDA.md` §12 |
| **엣지 자율 운용**(끊긴 동안 구역 안 기능 범위 · 다시 붙은 뒤 상태 맞추기) | — | **설계가 유예한 항목**이다(발동 조건 「원격 구역 배포 시」) | §8-5 표 「엣지 자율 운용」 |

→ **「엣지에 데이터가 모이고 서버는 받기만」 은 metric 에만 맞다.** 업무 데이터의 원본은 서버(TSDB · MySQL)이고 엣지는 **중계**한다(끊김 5분 버티기 + 못 보낸 것 기록).
log · trace 는 원래 엣지에 안 쌓고 서버로 넘긴다 — 지금의 로컬 파일은 **서버가 없는 동안의 대체**다.

### 3-6. 가용성(E8)과 서버 — 「엣지에서 안 알려주면 서버가 알 턱이 없다」

- **맞는 부분:** 서버는 엣지를 거쳐야만 말단 소식을 안다.
- **설계의 길:** 생사의 원신호(심박 `heartbeat` · 등록 `status` 의 birth / summary / shutdown · LWT death)는 **E2 브릿지가 업무 데이터로 서버 Kafka 에 보낸다**
  (브릿지가 구독하는 셋 = `+/+/+/state` · `+/+/+/status` · `+/+/+/heartbeat`). 서버는 이미 세 채널을 TSDB 에 저장한다 —
  Phase 5 의 서버 최종 판정(업무 평면 우선)은 **「판정기의 입력이 조회 한 번으로 나온다」**(Phase 5 「Phase 2 이월」). 원칙 7 · §5-5 · §6-4.
- **E8 의 자리:** HW 의 **엣지 1차 판정**(참조 구현) — 하트비트 · LWT · 등록 사건으로 online / offline_planned / offline_fault / stale 을 매기고
  **수신 쪽 시계로** 끊긴 시각을 잡는다(LWT 본문 시각은 접속 시점 값이라 못 쓴다 — `availability.py` [G3]). 엣지 Prometheus 가 긁으면 **엣지에서** 보고 쌓인다.
  Phase 5 는 「엣지 판정을 **신호로** 받아들이되 최종 판정은 백엔드」 로 둘의 관계를 정리하기로 했다(Phase 5 「Phase 1 이월」).
- **이름 — 정정:** 11-18 판 `availability.py` 는 이미 **`hw_entity_up`** · `hw_availability_state` · `hw_heartbeat_age_seconds` 를 낸다(BE 요청 21 반영 — 코드 161 ~ 178행).
  **`엣지_점검.md` 4장 E8 줄의 「이름 `up` 을 그대로 내면 … 개명 요청」 은 낡은 문구다.**
- **서버 단계로 넘기는 물음(12장 S3):** 세 이름이 `hw_` 로 시작해 서버 페더레이션 `match[]` `{__name__=~"hw_.*"}` 에 **걸린다.** 단계 8-6 은 「`up` · 장치 생사를 `match[]` 에 넣지 않는다(원칙 6)」 였다.
- 엣지 ↔ 서버 선 자체가 끊기면 서버는 「로봇이 죽었다」 와 「선이 끊겼다」 를 가르지 못한다 — 그 구분은 위 「엣지 자율 운용」(유예)의 몫이다.

### B-6. 엣지 Windows 방화벽 — **띄우기 전에** (관리자 PowerShell · K8)

**왜 먼저인가.** 프로그램이 `0.0.0.0` 으로 처음 열 때 규칙이 없으면 Windows 가 「Windows 보안 경고」 창을 띄운다. 거기서 **「취소」 를 누르면 그 프로그램을 막는 규칙이 생기고,
막는 규칙은 허용 규칙보다 앞선다**(Microsoft 문서 — 관리자 권한이 없는 계정이면 무엇을 골라도 막는 규칙이 생긴다). 그래서 **허용 규칙을 먼저, 범위를 좁혀** 넣는다.

```powershell
$LOGB = "C:\mk2_edge\logs\install_$(Get-Date -Format yyMMdd).txt"
& {
  "== B-6 엣지 방화벽 — $(Get-Date -Format 'yyyy-MM-dd HH:mm:ss')"
  Get-NetFirewallProfile | Format-Table Name, Enabled, DefaultInboundAction        # 방화벽이 켜져 있나
  # ① 서버가 엣지 Prometheus 를 당길 자리 — 서버 주소 하나만 (서버 단계 대비, 지금 넣는다)
  New-NetFirewallRule -DisplayName "MK2 edge prometheus 9090 (server)" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 9090 `
    -RemoteAddress 100.102.8.102 -Program "C:\mk2_edge\obs\prometheus-3.9.1.windows-amd64\prometheus.exe" -Profile Any | Out-Null
  # ② 말단이 관측을 밀 자리 — 말단 주소만 (말단 주소를 알 때만 이 두 줄을 넣는다. 모르면 빼고 T2 를 켤 때)
  New-NetFirewallRule -DisplayName "MK2 edge otelcol 4317 (terminals)" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 4317 `
    -RemoteAddress <pi1 실험실 망 주소>,<pi7 실험실 망 주소> -Program "C:\mk2_edge\obs\otelcol-contrib.exe" -Profile Any | Out-Null
  Get-NetFirewallRule -DisplayName "MK2 edge *" | ForEach-Object {
    $r = $_; $a = $r | Get-NetFirewallAddressFilter; $pf = $r | Get-NetFirewallPortFilter
    "{0,-36} {1,-8} {2,-6} {3,-6} port={4} remote={5}" -f $r.DisplayName, $r.Direction, $r.Action, $r.Enabled, ($pf.LocalPort -join ','), ($a.RemoteAddress -join ',') }
} *>&1 | Tee-Object -Append -FilePath $LOGB
```

### C-2. 확인 블록 — 읽기만, 결과를 파일로

발신이 끝나면 **바로**(늦어도 5분 안 — Collector 의 `metric_expiration` 기본 5분이 지나면 지표가 사라진다, Phase 4 보고 「작업 중 발견한 것」 8) 같은 「확인 창」 에 통째로 붙인다.

```powershell
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
$OUT3 = "C:\mk2_edge\logs\edge_verify_$(Get-Date -Format yyMMdd_HHmm).txt"
$m1 = [uri]::EscapeDataString('{__name__=~"hw_.*"}')
$m2 = [uri]::EscapeDataString('{__name__=~"system_(cpu|memory)_.*"}')
& {
  "# MK2 엣지 설치 확인 C-2 — $(Get-Date -Format 'yyyy-MM-dd HH:mm:ss')"
  "== 1 듣는 포트 (1883 · 4317 · 8888 · 8889 · 9090 · 9105)"
  $ports = 1883, 4317, 8888, 8889, 9090, 9105
  Get-NetTCPConnection -State Listen -ErrorAction SilentlyContinue | Where-Object { $ports -contains $_.LocalPort } | Sort-Object LocalPort |
    ForEach-Object { "{0,-6} {1,-16} {2}" -f $_.LocalPort, $_.LocalAddress, (Get-Process -Id $_.OwningProcess -ErrorAction SilentlyContinue).Path }
  "== 2 E3 Collector 8889 — 엣지 Prometheus 가 긁는 곳에 B층 지표가 있나"
  try { ((Invoke-WebRequest -UseBasicParsing http://127.0.0.1:8889/metrics).Content -split "`n") | Where-Object { $_ -match '^(hw_|system_)' } | Select-Object -First 15 } catch { "8889 응답 없음" }
  "== 3 E3 Collector 자기 지표 8888 — 받은 것 · 보낸 것 · 못 보낸 것"
  try { ((Invoke-WebRequest -UseBasicParsing http://127.0.0.1:8888/metrics).Content -split "`n") | Where-Object { $_ -match '^otelcol_(receiver_accepted|receiver_refused|exporter_sent|exporter_send_failed)' } } catch { "8888 응답 없음" }
  "== 4 E3 로컬 파일 (log · trace)"
  Get-ChildItem C:\mk2_edge\logs\otel_*.jsonl -ErrorAction SilentlyContinue | Format-Table Name, Length, LastWriteTime -AutoSize
  "--- log 파일에 가짜 발신의 service.name(hw-sensor-node)이 있나"
  Select-String -Path C:\mk2_edge\logs\otel_logs.jsonl -Pattern 'hw-sensor-node' -SimpleMatch -Quiet
  "--- trace 파일에 cmd.receive 가 있나"
  Select-String -Path C:\mk2_edge\logs\otel_traces.jsonl -Pattern 'cmd.receive' -SimpleMatch -Quiet
  "== 5 E4 엣지 Prometheus 9090"
  try { Invoke-RestMethod http://127.0.0.1:9090/-/healthy } catch { "9090 응답 없음: $($_.Exception.Message)" }
  try { (Invoke-RestMethod http://127.0.0.1:9090/api/v1/targets).data.activeTargets |
          ForEach-Object { "{0,-18} {1,-6} {2}  {3}" -f $_.labels.job, $_.health, $_.scrapeUrl, $_.lastError } } catch { "대상 목록 못 읽음" }
  try { (Invoke-RestMethod -Uri http://127.0.0.1:9090/api/v1/query -Body @{ query = 'count by (__name__, job) ({__name__=~"hw_.*|system_.*"})' }).data.result |
          ForEach-Object { "{0,-44} {1,-18} {2}" -f $_.metric.__name__, $_.metric.job, $_.value[1] } } catch { "질의 실패" }
  "== 6 서버가 당길 모양 — 엣지 자신의 /federate (match[] 는 서버 edge_federate 잡과 같은 둘)"
  try { ((Invoke-WebRequest -UseBasicParsing -Uri "http://127.0.0.1:9090/federate?match[]=${m1}&match[]=${m2}").Content -split "`n") |
          Where-Object { $_ -and $_ -notmatch '^#' } | Select-Object -First 12 } catch { "federate 못 읽음: $($_.Exception.Message)" }
  "== 7 E8 가용성 9105 (머리줄 # 포함)"
  try { ((Invoke-WebRequest -UseBasicParsing http://127.0.0.1:9105/metrics).Content -split "`n") | Where-Object { $_ } | Select-Object -First 25 } catch { "9105 응답 없음" }

} *>&1 | Tee-Object -FilePath $OUT3
"남김: $OUT3"
```

## 15. 이 방의 규칙 — 사용자가 정해 둔 것 (원문은 `CLAUDE.md` · 사용자 설정)

- **한국어로 답한다.** 약자(E1 · K3 · S2 …)를 쓸 때는 무엇인지 매번 풀어 쓴다.
- **기반 문서는 grep 으로 훑지 말고 전문을 읽는다**(필수 넷). 대화가 압축되면 **요약만 보지 말고 기반 문서로 돌아간다.**
- **사실을 다 받기 전에 해법을 내지 않는다** — 확인 블록 결과(파일)를 받고 판단한다(`CLAUDE.md` §1-A 규율 2).
- **문서와 현실이 다르면 차이를 먼저 보고하고 결정을 받는다**(규율 3). 사용자가 시키지 않은 설계 값 · 선택은 **채팅에서 먼저 묻는다** —
  긴 문서에 「사용자가 정함」 이라고 적는 것으로 대신하지 않는다. 사용자가 정한 값은 **글자 그대로** 구현한다. 개념을 먼저 설명하고 선택지를 낸다.
- 코드 · 설정 변경은 **무엇을 만들고 고칠지 먼저 전부 설명하고 승인**을 받는다. **HW · VZ 코드는 고치지 않는다(제안만).**
- **엣지 기기 · 서버의 명령은 사용자(또는 그 기기 앞의 사람)가 직접 붙인다** — Claude 는 블록을 주고, 돌려 받은 결과로 판단한다. 서버에 붙지 않는다.
- 설치 · 실행 리허설을 Claude 작업 공간에서 하지 않는다 — **어디서(엣지 · 이대규 PC · 서버) 돌리는지** 구분해 그곳에서 돌릴 블록을 준다.
- **기록은 손으로 옮기지 않는다**(파일로 남긴다). 작업로그는 정확하게 · 뒤에만 붙인다. 파일을 만들거나 고치면 **어느 경로의 어느 이름으로** 했는지 정확히 말한다.
- 수정본 파일은 같은 이름으로 덮어쓰지 말고 **버전을 올린다**(v2 …). 새 파일은 PC 에만 — **claude.ai 프로젝트에는 올리지 않는다**(사용자가 말할 때까지).
- **토큰 값을 채팅에 출력 · 인용하지 않는다.** `.env` 를 통째로 주지 않는다. 저장소(Public)에는 실주소 · 토큰 금지(자리표시자).
- 터미널(창)은 상주 창이 동시에 필요할 때만 나눈다. 화면(UI) 지시는 어느 창의 어느 단추를 누르고 무엇을 보는지 정확히 쓴다.
- 문제는 **소프트웨어 · 설정을 먼저** 보고 물리(배선 · 회선)는 그다음. 사소한 문제는 이슈로 올리지 않는다.
- 되돌리는 법은 「비상용 — 돌리지 말 것」 으로 따로 둔다. 다이어그램 · 그림은 사용자가 요청하기 전에 만들지 않는다.
- (서버 단계) `docker compose down` 금지 · compose 에는 서비스 이름 필수 · 이미 가입된 기기에서 `tailscale up` 을 다시 치지 않는다 ·
  서버 지시는 「파일 목록 → 서버 경로 → 명령」 · PC ↔ 서버 전송은 `sftp -P 8522 dg@210.110.250.33` · 서버로는 서버가 실행하거나 읽는 파일만.
