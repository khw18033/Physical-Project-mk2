## 1. 카메라 배치 제약

출처: Investigation of ArUco Marker Placement for Planar Indoor Localization
(arXiv:2509.17345) — **[원문 확인]**. Logitech C920 Pro(1080p, 대각 78° FOV), ArUco
6×6(1000종 ID), 15×15cm 마커로 두 배치(바닥 마커+천장 카메라, 천장 마커+바닥 카메라)를
직접 실측한 논문.

| 제약 | 수치 | 설계 함의 |
|---|---|---|
| 카메라 높이 | 1.334m → 오차 ~2.75cm / 2.991m → 오차 ~45.29cm(16배 이상 악화) | **낮고 촘촘하게** 배치, "높이 달아 넓게 커버"는 정확도를 크게 희생함 |
| 동시 가시 마커 수 | 5개 이상일 때 오차가 뚜렷이 낮아지고 그 이상은 개선 폭 급감 | 구역 내 모든 지점에서 카메라(또는 마커) 5대 이상 시야 확보를 목표로 배치 |
| 화면 내 마커 위치 | 화면 중심부 마커의 50%가 20cm 이상 오차 vs 가장자리는 31%만 | 여러 카메라 시야를 겹칠 때 이 렌즈 왜곡 특성을 감안(가장자리가 더 정확) |
| 마커-카메라 상대각 | 카메라를 정면(90°)으로 보는 마커가 가장 안정적 | 마커 부착 각도를 카메라 예상 위치에 맞춰 설계 |

## 2. 로봇 마커(ArUco/AprilTag) 제약

출처: 여러 검색 결과(FTC 공식 문서, roboticsknowledgebase, YoloTag 논문 등) — **[검색
요약, 원문 미확인]**. 정확한 상수·조건은 [validation/edge-step1-experiment-plan.md](../validation/edge-step1-experiment-plan.md)의
S1-2/S1-3에서 우리 카메라로 재확인해야 한다.

| 제약 | 내용 |
|---|---|
| 거리-크기 관계 | distance ≈ k × (실제 마커 크기) / (화면상 마커 픽셀 폭). 마커 격자 한 칸이 화면에서 최소 ~10픽셀은 돼야 안정적으로 디코딩됨 |
| 작은 태그(10~20cm) | 대략 4m 넘으면 인식 실패 |
| 큰 태그(48~60cm) | 대략 2m보다 가까우면 오히려 인식 실패(화면에 다 안 들어오거나 초점 문제) |
| 상대 각도 | 마커 법선이 카메라 방향과 60도 이상 벌어지면 인식이 불안정해짐 |
| 로봇 이동 중 | 정지 대비 회전 중 pose 오차가 각도 최대 20°, 위치 최대 0.75m까지 벌어짐(YoloTag 논문 인용) |
| 부착 위치 | 창고 AGV 사례(다수 인용)는 로봇 상단 마커 1개 + 천장 카메라 방식. 카메라가 다양한 각도에서 볼 가능성이 있으면 로봇 몸체 여러 면에 마커를 부착하는 "정육면체 타워" 방식이 대안으로 보고됨 |

**우리 배치와의 정합성**: 우리 고정 카메라는 천장 단일 배치가 아니라 구역 곳곳에
다양한 각도로 배치될 가능성이 높다(§1의 "낮고 촘촘하게" 결론과도 일치). 따라서
**로봇 몸체 여러 면에 마커를 부착하는 방식을 1차 후보로 채택**한다 — 어느 카메라가
보든 60° 제한 안에 드는 면이 최소 하나는 있도록.

## 3. RSSI 핸드오버 관련 제약

| 제약 | 내용 | 근거 |
|---|---|---|
| 핑퐁 방지 | 신호가 경계에서 흔들리면 반복 전환이 발생 — 히스테리시스(비대칭 지연) 필요 | 검색 요약, 통신 분야 정설 |
| 위치추정 오차 | RSSI 기반 lateration은 보통 0.65~5m 오차 | 검색 요약 |
| 벤더 비일관성 | RSSI 절대값은 제조사·기기마다 의미가 달라 절대 임계값 방식이 신뢰하기 어려움 | 검색 요약 |

**이미 충족됨**: `perception_framework/ondevice/link_handover.py`(AI-N-03)가 절대
임계값이 아니라 추세(trend)+비대칭 이력 기반으로 이미 구현되어 있어 위 세 제약을
전부 설계 차원에서 만족한다 — 새로 만들 것 없음, §2(실험 계획)에서 **실제 RSSI
잡음으로 이 로직의 파라미터(`floor`, `reduction_lead_seconds`, `restore_margin` 등)가
유효한지만 재검증한다.
