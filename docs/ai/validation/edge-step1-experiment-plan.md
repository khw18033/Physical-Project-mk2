# 엣지 Step 1 실험 계획 — 노드 위치·신원 발행

상태: **계획 — 아직 실행 전.** 제약·근거 출처는
[design/edge-position-identity-constraints.md](../design/edge-position-identity-constraints.md)를
따른다. 여기 나온 수치는 전부 재측정 대상이며, 이 실험이 끝나기 전에는 어떤 카메라
높이·마커 크기·거리도 "확정"으로 취급하지 않는다(AI-B-01).

## 0. 실험 대상과 사용할 실제 알고리즘

Step 1이 풀어야 할 두 문제:
1. 고정 카메라가 로봇을 보고 **"어느 로봇인지"(신원) + "어디 있는지"(zone 좌표계 위치)**를
   동시에 얻는다.
2. 로봇의 통신 상태·엣지 핸드오버 판단에 RSSI를 보조 신호로 쓴다.

**마커 인식 알고리즘은 `cv2.aruco`(OpenCV 내장)로 확정한다.** AprilTag 전용 라이브러리
(`pupil-apriltags` 등)를 새로 추가하는 대신 OpenCV를 쓰는 이유: 이 저장소가 이미
`opencv`를 의존성으로 갖고 있어(`pip install -e ".[dev]"`) 새 의존성 추가 없이 바로
실험 가능하고, `cv2.aruco.estimatePoseSingleMarkers`가 검출+ID 디코딩+pose 추정을
한 번에 제공해 §1의 파이프라인을 그대로 구현할 수 있다.

## 1. 데이터 흐름 (이 실험이 검증할 파이프라인)

```text
고정 카메라 프레임
  → cv2.aruco 마커 검출 (ID + 화면상 코너 4점)
  → cv2.aruco.estimatePoseSingleMarkers (카메라 기준 상대 pose)
  → ID → robot_id 매핑 테이블 조회 (AI-B-09: 신규 로봇은 "등록"만 하면 됨, 코드 수정 없음)
  → 카메라 자신의 camera_extrinsic(보정 프로파일, AI-E-02)으로 ZONE 좌표계 변환
  → node_pose + pose_source="fixed_camera_marker" + pose_uncertainty 로 발행
```

## 2. 세부 실험

각 실험은 독립적으로 실행 가능(하드웨어 확보되는 대로 순서 무관하게 시작 가능).

### S1-1. 카메라 높이 스윕
- **변수**: 카메라 설치 높이(예: 1.0m, 1.5m, 2.0m, 2.5m대 — 실제 설치 가능한 높이로 조정)
- **방법**: 같은 마커를 각 높이의 카메라로 촬영, `estimatePoseSingleMarkers` 결과와 줄자로 잰 실측 위치를 비교
- **측정 지표**: 위치 오차(cm), 각도 오차(도)
- **성공 기준**: 참고 논문의 "낮을수록 정확" 경향이 우리 카메라·해상도에서도 재현되는지 확인 — 재현 안 되면 우리 환경에 맞는 높이별 오차 곡선을 새로 그린다

### S1-2. 마커 크기 스윕
- **변수**: 마커 실제 크기(예: 10cm, 15cm, 20cm)
- **방법**: 로봇이 실제로 위치할 것으로 예상되는 거리 범위(구역 크기 기준)에서 각 크기의 마커를 동시에 놓고 검출 성공률·디코딩 안정성 측정
- **측정 지표**: 거리별 검출 성공률(%), 디코딩 신뢰도
- **성공 기준**: 우리 실제 운용 거리에서 안정적으로 읽히는 최소 크기 확정

### S1-3. 마커 각도 스윕
- **변수**: 마커 법선과 카메라 방향의 각도(0°~90°, 10°~15° 간격)
- **방법**: 회전 지그에 마커를 놓고 각도별 검출 성공률 측정
- **측정 지표**: 검출 성공률, 60° 부근에서 급격히 떨어지는지 여부
- **성공 기준**: 실패 임계각을 확인해 §3(다면 마커 부착)의 면 배치 각도 설계에 반영

### S1-4. 정지 vs 이동 비교
- **변수**: 로봇 정지 상태 / 실제 주행 속도(회전 포함)
- **방법**: 같은 구간을 정지 촬영과 주행 중 촬영으로 반복, pose 오차 비교
- **측정 지표**: 위치·각도 오차, 검출 유실률(모션 블러로 인한 실패)
- **성공 기준**: 이동 중 오차가 로봇 안전 판단(§4의 pose_uncertainty)에 반영해도 될 수준인지 판단

### S1-5. 동시 가시성 매핑
- **변수**: 구역 내 여러 지점(격자로 샘플링)
- **방법**: 각 지점에서 몇 개의 카메라/마커가 동시에 보이는지 기록
- **측정 지표**: 지점별 가시 카메라 수
- **성공 기준**: "5개 이상" 기준이 우리 구역 크기·카메라 대수로 실제 달성 가능한지 확인 — 안 되면 카메라 추가 배치나 목표 기준 재조정 논의

### S1-6. 신원 매핑 + Zone 좌표 변환 검증
- **방법**: 로봇 여러 대(또는 마커 여러 개로 대체 시뮬레이션)에 서로 다른 ArUco ID 부착 → 동시에 여러 대가 시야에 있을 때 ID별로 정확히 분리되는지, 그리고 카메라 extrinsic을 곱해 나온 ZONE 좌표가 실측값과 일치하는지 확인
- **측정 지표**: 신원 오인식률(다른 로봇으로 잘못 매핑되는 빈도), ZONE 좌표 오차
- **성공 기준**: 오인식 0건(마커 기반이라 원칙적으로 0이어야 함 — 0이 아니면 검출 파이프라인 버그로 취급)

### S1-7. RSSI 히스테리시스 재검증
- **방법**: 실제 로봇을 이동시키며 RSSI를 기록(합성 신호가 아닌 실측), 이 로그를 `LinkTransitionPolicy.observe()`에 그대로 흘려 판단이 튀지 않는지 확인
- **측정 지표**: 불필요한 전환 횟수(`false_reductions`), 실제 연결 끊김 대비 반응 지연
- **성공 기준**: 기존 기본 파라미터(`floor=0.25`, `reduction_lead_seconds=1.5` 등)가 실제 RSSI 잡음 특성에서도 유효한지 — 안 맞으면 파라미터만 조정(로직 자체는 이미 히스테리시스 구조라 재설계 불필요)

## 3. 필요 하드웨어

- 고정 카메라 최소 1대(높이 조절 가능한 거치대 있으면 S1-1에 유리)
- ArUco 마커 인쇄물 여러 크기(S1-2)
- 회전 가능한 지그 또는 손으로 각도 조절(S1-3)
- 이동형 로봇 최소 1대(S1-4, S1-6, S1-7) — 없으면 마커를 손으로 이동시켜 근사
- 줄자/각도기 등 실측 도구(ground truth 비교용)

## 4. 실행 순서 제안

S1-2(마커 크기) → S1-3(각도) → S1-1(카메라 높이)은 정적 촬영만으로 가능해 하드웨어
제약이 가장 적다. S1-4~S1-6은 로봇이 필요하다. S1-7은 RSSI 로그만 있으면 되므로
독립적으로 아무 때나 진행 가능.

## 5. 이 실험이 끝나면

각 실험 결과를 `reports/`에 실측치로 기록하고, §2 제약 문서의 "검색 요약" 항목을
"원문 확인" 대신 "자체 실측"으로 교체한다. 이후 `data_dictionary.py`의 `node_pose`/
`pose_source`/`pose_uncertainty` 실제 값 범위와 `edge/calibration_profile.py`의
`camera_extrinsic` 스키마를 이 결과에 맞춰 확정한다.
