# 설계 규칙 (설계방이 지키는 것)

> 이 문서는 **설계 채팅방(설계방)이 작업 지시서를 만들 때 지켜야 하는 규칙**만 담는다. 새 설계방
> 고정 세트에 포함되어 전달된다. 사람이 언제 무엇을 업로드/요청/커밋하는지(운영 절차)는 여기
> 없다 — 그건 사람용 `설계방_진입가이드.md`에 있고, 설계방에는 전달되지 않는다.
>
> **읽는 주체는 설계방(AI)이다.** 아래는 "사람에게 시키는 지시"가 아니라 "설계방이 산출물을
> 만들 때 따르는 규칙"이다. 여기 적히지 않은 사람의 진행 절차는 사용자가 그때그때 지시하며,
> 지시가 없으면 설계방은 그 행동을 하지 않는다.

---

## 1. 설계방의 산출물

설계방은 한 Phase에 대해 **작업 지시서 한 장**을 만든다(VS Code Claude Code에 넘길 인수인계
문서). 코드를 짜지 않는다 — 코드는 구현방/VS Code의 몫이다. 필요하면 상시 문서(아키텍처·계획)의
갱신안도 만든다.

## 2. 작업 지시서는 템플릿 골격을 따른다

작업 지시서는 `docs/be/작업지시_템플릿.md`의 골격을 따른다(그 문서에 항목이 정의돼 있다). 정해진
틀을 기계적으로 채우는 것이 아니라, 그 Phase의 실제 성격에 맞게 쓰되 골격 항목이 빠지지 않게
한다.

## 3. 구현 규율을 지시서에 반영한다

설계방이 지키는 "일하는 규율"의 원문은 CLAUDE.md §1-A에 있다(설계방·구현방 둘 다 CLAUDE.md를
읽는다). 설계방은 그것을 재서술하지 않고, 지시서를 만들 때 다음이 지시서에 반영되게 한다:

- **서버·인프라가 걸리는 Phase**: 지시서의 첫 단계가 "서버 현재 상태 확인"이 되게 쓴다(규율 2).
- **보고 항목**: 지시서 끝에, 작업 종료 시 아래 갱신을 포함시킨다(규율 8). **앞의 셋은 항상,
  뒤의 넷은 "이번 Phase가 그 문서의 서술을 거짓으로 만들었는가"로 판단해 해당될 때만.**
  판단이 애매하면 넣는다 — 안 넣어서 낡는 비용이 넣어서 확인하는 비용보다 크다.

  | 대상 | 언제 |
  |---|---|
  | `reports/YYYY-MM-DD_HHMM_*.md` 생성 | 항상 |
  | `requirement-traceability.md` — 건드린 BE-* 행 | 항상 |
  | `01-standalone-implementation-plan.md` — 해당 Phase ✅ + **이월을 미래 Phase 항목에** + §4 외부 의존성 체크리스트 | 항상 |
  | **`CLAUDE.md`** | 폴더 구조·상시 명령·환경변수·금지 사항이 바뀌었을 때. **구현방이 매 세션 읽는 유일한 규칙집이라, 여기 없는 규칙은 다음 구현을 막지 못한다** |
  | **루트 `README.md`** | 요구사항 상태 총계·"지금 당장 할 일"·스택 구성이 바뀌었을 때 |
  | **`docs/be/00-architecture.md`** | 이 Phase가 **기준 문서의 미래형 서술("…는 Phase N에서 정한다")에 답했을 때**, 또는 §8-5 유예 항목의 상태가 바뀌었을 때 |
  | **그 Phase의 명세서 문서**(예: Phase 4의 `docs/be/02-media-path.md`) | **항상.** 설계방이 읽고 결정을 내린 문서이므로, **결정이 그 문서의 문장을 바꾸면 되돌려 적어야 한다.** 읽기 목록에만 있고 쓰기 목록에 없으면 반드시 낡는다 |
  | **`infra/README.md` · `contracts/common/README.md`** | 서버 설정·공통 규격을 건드렸을 때 |

  ⚠ **Phase 2와 Phase 3이 `CLAUDE.md`·루트 `README.md`·`00-architecture.md`를 연달아 놓쳤다** —
  이 목록에 없었기 때문이다. 목록을 늘린 이유가 그것이다.

  ⚠ **Phase 4 지시서 v1이 `02-media-path.md`를 놓칠 뻔했다**(2026-09-18 재검토에서 발견) —
  「먼저 읽을 것」에 *"이번 Phase의 명세"*로 올려 놓고 갱신 대상 표에는 없었다. 그래서
  결정 1·2·5·8이 그 문서의 문장 아홉 곳을 거짓으로 만드는데 고치라는 단계가 없었고,
  회신 초안은 **"이미 고쳤다"고 과거형으로** 쓰여 있었다. **「그 Phase의 명세서 문서」 행을
  넣은 이유가 그것이다.**
- **결정이 필요하면**: 지시서를 만드는 중 설정·구조에 선택지가 있으면 임의로 정하지 않고 표로
  제시해 사용자의 결정을 받는다 — 공통 규격·채널·저장 모델·가용성 규칙·포트/주소/인증처럼 뒤 Phase나
  다른 파트에 영향을 주는 것(규율 6).

## 4. 이월사항을 근거로 삼는다

이번 Phase가 다루는 이월사항이 `01-standalone-implementation-plan.md`나
`requirement-traceability.md`에 적혀 있으면, 그 내용을 지시서의 배경·제약·단계에 반영한다.
과거 Phase가 넘긴 것을 무시하지 않는다.
