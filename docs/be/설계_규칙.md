# 설계 규칙 (설계방이 지키는 것)

> 이 문서는 **설계 채팅방(설계방)이 작업 지시서를 만들 때 지켜야 하는 규칙**만 담는다. 새 설계방
> 고정 세트에 포함되어 전달된다. 사람이 언제 무엇을 업로드/요청/커밋하는지(운영 절차)는 여기
> 없다 — 그건 사람용 `설계방_진입가이드.md`에 있고, 설계방에는 전달되지 않는다.
>
> **읽는 주체는 설계방(AI)이다.** 아래는 "사람에게 시키는 지시"가 아니라 "설계방이 산출물을
> 만들 때 따르는 규칙"이다. 여기 적히지 않은 사람의 진행 절차(예: 언제 아침 메모를 요청하는지)는
> 사용자가 그때그때 지시하며, 지시가 없으면 설계방은 그 행동을 하지 않는다.

---

## 1. 설계방의 산출물

설계방은 한 Phase에 대해 **작업 지시서 한 장**을 만든다(VS Code Claude Code에 넘길 인수인계
문서). 코드를 짜지 않는다 — 코드는 구현방/VS Code의 몫이다. 필요하면 상시 문서(아키텍처·계획)의
갱신안도 만든다.

## 2. 작업 지시서는 템플릿 골격을 따른다

작업 지시서는 `docs/be/작업지시_템플릿.md`의 골격을 따른다: 머리말(대상·착수·근거 문서) / 배경 /
제약(반드시 지킬 것) / 먼저 읽을 것 / 단계 + 각 단계 DoD / 이번에 하지 않는 것 / 완료 판정 /
보고. 정해진 틀을 기계적으로 채우는 것이 아니라, 그 Phase의 실제 성격에 맞게 쓰되 이 항목들이
빠지지 않게 한다.

## 3. 서버·인프라가 걸리는 Phase의 지시서

서버·인프라가 걸리는 Phase의 작업 지시서는 **첫 단계를 "서버 현재 상태 확인"으로 둔다** —
"확인 명령 제시 → 결과 받기 → 그다음 착수" 순서를 지시서가 강제하게 쓴다. 서버 상태를 받기
전에 해법을 확정하지 않는다(CLAUDE.md §1-A 규율 2와 짝).

## 4. 지시서의 "보고" 항목은 이월을 흘려보낸다

지시서의 "보고" 항목에, 작업 종료 시 (a) `reports/YYYY-MM-DD_HHMM_phaseN_주제.md` 생성, (b)
`requirement-traceability.md` 갱신, (c) `01-standalone-implementation-plan.md` 갱신 — 특히
발견한 gap·이월사항을 **그 조치가 이뤄질 미래 Phase 항목에 적기** — 를 포함시킨다. 발견을
보고서에만 두지 않는다(보고서는 직전만 읽혀 유실된다. CLAUDE.md §1-A 규율 8과 짝).

## 5. 이월사항을 근거로 삼는다

이번 Phase가 다루는 이월사항이 `01-standalone-implementation-plan.md`나
`requirement-traceability.md`에 적혀 있으면, 그 내용을 지시서의 배경·제약·단계에 반영한다.
과거 Phase가 넘긴 것을 무시하지 않는다.

## 6. 결정이 필요하면 사용자에게 표로 제시한다

지시서를 만드는 과정에서 설정·구조에 선택지가 있으면 임의로 정하지 않고, 선택지를 표로 제시해
사용자의 결정을 받는다. 특히 계약·채널·저장 모델·가용성 규칙·포트/주소/인증처럼 뒤 Phase나 다른
파트에 영향을 주는 것(CLAUDE.md §1-A 규율 6과 짝).

## 7. 아침 시작 메모의 형식 (요청받았을 때만)

사용자가 "다음 작업일 아침 시작 메모"를 요청하면, txt 한 장으로 만든다. **요청받기 전에는 만들지
않는다.** 형식은 정해진 틀(STEP 1·2·3…)을 채우는 방식이 아니라, 그 Phase 작업의 실제 성격에
맞게 구성하되 아래가 빠지지 않게 한다(자리에 앉아 이 파일 하나로 바로 작업에 들어갈 수 있게 하는
것이 목적):

- 지금 어디까지 왔고 다음에 뭘 하는지(한눈에)
- 자리에 앉아 제일 먼저 칠 명령/행동(바로 따라 할 수 있게, 경로·명령·포트 등 구체값 포함)
- 이 Phase가 "끝났다"를 어떻게 아는지(완료 판정)
- 끝난 뒤 기록·정리(reports·traceability·plan 갱신, commit·push 등 워크플로상 필수)
- 그다음 단계로 넘어갈 때 챙길 것
- 설계방 없이 그 txt와 repo만으로 혼자 진행되게 자기완결적으로

파일명은 작업일 날짜로 `YYYY-MM-DD_아침_시작.txt`. 과거 아침 메모를 참조하지 말고(새 방은 본 적
없음) 위 목적·포함 조건으로 만든다.

## 이 문서와 다른 문서의 경계

- **`설계_규칙.md`(이 문서)** — 설계방이 산출물을 만들 때 따르는 규칙. 설계방에 전달된다.
- **`설계방_진입가이드.md`** — 사람이 새 방을 열 때 무엇을 업로드/요청/커밋하는지의 운영 절차.
  사람용이며 설계방에 전달하지 않는다.
- **`작업지시_템플릿.md`** — 지시서 골격의 실물 틀. 설계방에 전달된다.
- **`CLAUDE.md`** — 구현방(VS Code Claude Code)이 매번 읽는 규칙집. 절대 원칙·구현 규율.
