# 작업 지시서 템플릿 (모든 Phase 공통 골격)

> 설계방이 각 Phase 작업 지시서를 뽑을 때 **이 골격을 따른다.** 이 템플릿은 새 설계방에 전달되는
> 고정 세트에 포함되므로(진입가이드 §1-A), 어느 방이든 지시서를 같은 구조로 만들 수 있다.
> 근거: 김현우 `작업프롬프트_통합_260827.md` 구조 = Phase 0 지시서 구조의 일반화.
>
> 작업 지시서는 **VS Code Claude Code에 넘기는 일회용 인수인계 문서**다. 태스크마다 새로 만들고,
> 그 Phase 구현이 끝나면 `docs/be/tasks/_archive/`로 옮긴다(누적 참조 대상이 아니다).
> 저장 위치: `docs/be/tasks/작업지시_phaseN_주제.md`.

---

## 왜 이 골격인가 (채우기 전에 읽을 것)

이건 **빈칸 채우기 틀이 아니라**, "Claude Code가 헛돌지 않고 범위대로 구현하려면 있어야 하는
것들"이다. Phase 0에서 지시서에 이 요소가 약해 작업이 반복 헛돌았다(범위 넘기·임의 결정·서버
상태 안 받고 착수). 각 Phase의 실제 성격에 맞게 내용을 쓰되, 아래 항목이 빠지지 않게 한다.

---

## 골격 (순서대로)

### 1. 머리말
- **대상:** Phase N — (한 줄 제목)
- **착수:** 언제 / 어느 사이클
- **근거 문서:** 이 작업의 명세가 어느 문서인지 (`01-...plan.md`의 해당 Phase, `00-architecture.md`
  관련 절, `02-media-path.md` 등). 링크로.
- (한 줄) "이 문서는 VS Code Claude Code가 읽고 구현하는 인수인계 문서다. CLAUDE.md와 이
  지시서를 함께 읽고, 지시서 범위대로 구현한다. 설계는 끝났으므로 새로 설계하지 않는다."

### 2. 배경
- 왜 지금 이걸 하는가. 앞 Phase와의 연결. 이 Phase가 딛고 서는 것.

### 3. 제약 — 반드시 지킬 것 (번호 매김)
- 이 Phase에서 절대 어기면 안 되는 것. CLAUDE.md 절대 원칙(§1) 중 이 작업에 걸리는 것 +
  이 작업 고유 제약. 예: RBAC·MongoDB 금지, 봉투 계약 준수, 비밀값 커밋 금지(Public), LF·UTF-8,
  서버에 도는 것 지웠다 다시 깔지 않기 등.

### 4. 먼저 읽을 것
- 착수 전에 훑어야 할 문서·코드와 그 이유. (Claude Code가 정독을 건너뛰지 않게 명시 —
  CLAUDE.md §1-A 규율 1과 짝.)

### 5. 단계 + 각 단계 DoD
- 순서대로. **서버·인프라가 걸리는 Phase면 1단계는 반드시 "서버 현재 상태 확인"**
  ("확인 명령 제시 → 결과 받기 → 그다음 착수" — CLAUDE.md §1-A 규율 2와 짝).
- 각 단계마다 "무엇을 하면 이 단계가 된 것인가"(판정 기준)를 붙인다.

### 6. 이번에 하지 않는 것 (범위 울타리)
- 다음 Phase로 미루는 것을 명시. Claude Code가 범위를 임의로 넓히지 않게 하는 울타리
  (CLAUDE.md §1-A 규율 5와 짝). 예: "TSDB는 Phase 2", "인증·TLS는 나중".

### 7. 완료 판정 (체크리스트)
- 아래가 전부 참이어야 이 작업이 끝난 것 — 형태로. 검증 수단 명시
  (Phase 0은 헬스체크, Phase 1부터 pytest). "테스트 없는 완료 금지"(CLAUDE.md §3).

### 8. 보고 (작업 끝에 무엇을 남기나) — 반드시 포함
작업이 끝나면 아래를 기록·커밋하도록 지시서에 못박는다. 이 항목이 CLAUDE.md §1-A 규율 8을
그 Phase에서 실제로 발동시키는 트리거다.
- **`reports/YYYY-MM-DD_HHMM_phaseN_주제.md` 생성** — 배경 / 한 일 / 검증 / 다음.
  이 Phase가 발견한 gap·이월사항, 다음 Phase로 넘길 것을 "다음"에 적는다.
- **`requirement-traceability.md` 갱신** — 이 Phase가 건드린 BE-* 요구사항의 상태·구현 위치·
  테스트·gap을 갱신(미착수→부분→완료).
- **`01-standalone-implementation-plan.md` 갱신** — (a) "지금 당장 할 일" 체크박스, (b) 발견한
  이월사항을 그 조치가 이뤄질 **미래 Phase 항목에 적기**(보고서에만 두지 않는다 — 보고서는
  직전만 읽히므로 유실된다. 규율 8).
- **"막히거나 결정이 필요하면 임의로 정하지 말고 보고서에 남기고 멈춘다."**

## 아침 시작 메모 (지시서와 세트로)

지시서를 뽑은 뒤, 사람용 "다음 작업일 아침 시작 메모" txt도 세트로 요청한다. 상세한 요청 방식
(목적 + 포함 조건, 정형화 금지)은 진입가이드 §3 단계1에 있다. 파일명 `YYYY-MM-DD_아침_시작.txt`.
