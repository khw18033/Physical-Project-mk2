# MK2 노트북 상태 JSON 설명 (시각화용) v2

작성 2026-11-26 · 이대규(BE) · 받는 사람: VZ(가시화) 담당
v2: 만드는 스크립트가 v4 로 바뀜(수집 대상의 `last_scrape_age_s` 가 음수로 나오던 것을 고침). JSON 칸 · 형식은 그대로(`schema_version` 3).
**한 줄로:** 엣지 노트북(`BOOK-4VG1EDPVI5`)이 30초마다 「엣지 · Prometheus · OTel · 임무 이력 서버 · DB 가 잘 도는지」 를 JSON 으로 남긴다. 시각화는 이 파일만 읽으면 「잘 되어요」 를 화면에 보여 줄 수 있다. **어떻게 읽어 갈지(파일을 가져가는 방법)는 시각화 쪽에서 정한다.**

## 1. 어디에 · 언제 생기나

| 무엇 | 값 |
|---|---|
| 만드는 것 | 엣지 노트북 바탕화면 **「MK2 전체 켜기」**(v4 — `C:\mk2_edge\launcher\mk2_all_start_v4.ps1`). 켜면 엣지 스택 넷 + 노트북 서버를 켜고, 상태 화면이 30초마다 새로 보며 그때마다 저장한다 |
| 폴더 | `C:\mk2_edge\logs\mk2_status\` |
| 구동마다 새 파일 | `mk2_status_<구동 시각 yyMMdd_HHmmss>.jsonl` — **한 번 볼 때마다 JSON 한 줄**(JSON Lines). 같은 내용의 사람용 글은 같은 이름의 `.txt` |
| 최신 한 번 | `mk2_status_latest.json` — 가장 최근 한 번(볼 때마다 덮어씀 · 줄바꿈 들여쓰기된 JSON 하나) |
| 간격 | 약 45 초(30 초 기다림 + 상태를 보는 데 10 ~ 15 초) |
| 끝 | 상태 화면에서 Q → Y 로 끄면 「끈 뒤」 의 한 줄을 더 쓰고 그 구동 파일은 끝난다 |
| 글자 | UTF-8(BOM 없음) · 줄 끝은 `\n` — 어떤 JSON 파서로도 읽힌다 |
| 시각 | 모두 노트북 시각(KST) + 오프셋 — 예: `2026-11-25T20:10:02+09:00` |
| 형식 판 | 줄마다 `schema_version` — 지금 **3**. 칸이 바뀌면 이 수를 올린다. 11-25 19:07 · 19:09 · 19:36 구동 파일은 이 칸이 없는 옛 꼴(v2)이다 |

### 읽어 가는 방법 (시각화가 정할 것)

- 브라우저는 보안상 `C:\` 파일을 스스로 열지 못한다. 예: VZ 개발 서버(같은 노트북)가 `mk2_status_latest.json`(지금 상태)과 `.jsonl`(시간 흐름)을 읽어 화면에 넘겨 주는 방식. 정하는 것은 VZ 쪽.
- 촘촘한 실제 값(15초마다의 장치 판정 등)이 필요하면 JSON 에 다 옮기지 않고 **Prometheus 에 직접 물을 수 있다** — 주소 · 쓸 질의는 JSON 의 `sources` 에 적어 두었다. 노트북 안에서는 `http://127.0.0.1:9090`. Prometheus 는 `0.0.0.0:9090` 으로 열려 있어 다른 tailnet 기기에서는 노트북 Windows 주소 `100.112.161.94:9090` 으로 닿을 것이다(확인 안 함 · 브라우저에서 바로 묻는 것이 되는지(CORS)도 확인 필요).

## 2. 「잘 되어요」 를 보여 주는 법 — 먼저 `summary`

`summary` 의 다섯 항목이 신호등이다. 항목마다 `{ "ok": true | false, "reason": "사유" | null }`.

| 항목 | 뜻 | `ok` 가 참인 조건 | 거짓일 때 `reason` 예 |
|---|---|---|---|
| `laptop_server` | 노트북 서버 — WSL · PostgreSQL · 임무 이력 서버 · DB | WSL 켜짐 · 서비스 셋 `active` · 임무 이력 서버 응답 · DB 읽힘 | `WSL 꺼짐` · `서비스 active 2/3` · `임무 이력 서버 응답 없음` · `DB 를 못 읽음` |
| `edge_stack` | 엣지 스택 넷 — 브로커(Mosquitto) · Collector(OTel) · Prometheus · 가용성 판정기 | 넷 다 떠 있음 | `꺼짐: 엣지 Prometheus` |
| `pi_to_edge` | 로봇 · 파이 → 노트북 데이터 | 파이 브리지가 하나 이상 붙음 · 5초 동안 새 업무 메시지가 있음 | `붙은 파이 브리지 없음(파이가 꺼져 있다)` · `5초 동안 새로 들어온 업무 메시지 없음` |
| `otel` | 관측(OpenTelemetry) — 말단 CPU · 메모리 등 | Collector 가 받은 것이 있음 | `받은 것 없음 - 말단이 관측을 보내지 않는다(파이 무변경이면 0)` — **지금은 이것이 정상**(파이를 고치지 않기로 해서 파이가 관측을 안 보낸다) |
| `prometheus` | 엣지 Prometheus 가 수집하고 있나 | 켜져 있고 수집 대상이 모두 up | `Prometheus 꺼짐` · `수집 대상 up 1/2` |

그다음 보여 주면 좋은 것: 장치 카드(`prometheus.devices[]`) · DB 숫자(`laptop_server.db`) · 최근 임무 판(`laptop_server.mission_history.latest_runs`) · 업무 메시지 흐름(`pi_to_edge.messages_per_min`). `.jsonl` 을 시간 순서로 이으면 「언제 장치가 꺼졌다 켜졌나 · 언제 판이 늘었나」 를 시간선으로 그릴 수 있다.

## 4. 칸 설명

**맨 위**

| 칸 | 형 | 뜻 |
|---|---|---|
| `schema_version` | 수 | 이 꼴의 판(지금 3). 11-26 13:55 구동 파일은 v3 스크립트가 쓴 것이라 `last_scrape_age_s` 가 음수일 수 있다 — 그 뒤 파일은 v4 |
| `time` | 글(시각) | 이 줄을 본 시각 |
| `run_id` | 글 | 이 구동의 이름(= 파일 이름의 시각) — 한 파일 안의 줄은 모두 같다 |
| `refresh_s` | 수 | 다시 보기 전 기다리는 초(30) |
| `sources` | 묶음 | 원본 주소 — Prometheus · 쓴 질의 · 임무 이력 서버 · Collector · 판정기 · 브로커 |
| `summary` | 묶음 | 2장의 신호등 다섯 |

**`laptop_server`** — 노트북 서버

| 칸 | 형 | 뜻 |
|---|---|---|
| `wsl_running` | 참·거짓 | WSL(`Ubuntu-26.04`)이 켜져 있나 |
| `services` | 묶음 | 서비스 셋의 상태 글자 — `active` 가 정상. WSL 이 꺼져 있으면 `null` |
| `mission_history.ok` | 참·거짓 | 임무 이력 서버(`/api/v1/health`)가 답했나 |
| `mission_history.run_count_all` | 수 | 서버가 아는 판 수(적합성 검사 판 `000101` 포함) |
| `mission_history.run_count_listed` | 수 | **VZ 에 보이는 판 수**(검사 판 뺌 — VZ 「서버 판 N개」 와 같다). 임무를 하나 끝내면 1 는다 |
| `mission_history.latest_runs[]` | 목록 | 최근 판 셋 — `date` · `run` · `record_kind`(`mission` · `control`) |
| `db.ok` | 참·거짓 | DB 를 읽었나(노트북 PostgreSQL `mk2` — 읽기 계정) |
| `db.runs` · `db.images` | 수 | DB 에 있는 판 수 · 그림 행 수(검사 판 뺌) — **「DB 에 쌓이고 있다」 의 증거** |
| `db.last_saved` | 글(시각) | 마지막으로 판이 저장 · 갱신된 시각 |
| `db.size_mb` | 수 | DB 크기(MB) |
| `last_backup` | 글 | 가장 새 백업 폴더 이름(`daily_…` 매일 22:00 · `manual_…` 손으로) |

**`edge_stack[]`** — 엣지 구성요소 넷: `name`(mosquitto · otelcol · prometheus · availability) · `label` · `port` · `up`(참·거짓)

**`pi_to_edge`** — 로봇 · 파이 → 노트북

| 칸 | 형 | 뜻 |
|---|---|---|
| `broker_up` | 참·거짓 | 노트북 브로커(1883)가 떠 있나 |
| `bridges[]` | 목록 | 파이 브리지마다 `name` · `short`(pi7 등) · `connected`(1 붙음 · 0 끊김). 브리지마다 한 줄 |
| `bridges_connected` | 수 | 붙은 브리지 수 |
| `live_messages_5s` · `messages_per_min` | 수 | 5초 동안 **새로** 들어온 업무 메시지(state · status · heartbeat) · 그것을 1분당으로(×12) |
| `topics_5s[]` | 목록 | 그 메시지의 토픽별 건수 |
| `retained_topics[]` | 목록 | 보관(retained) 메시지 토픽 — **지금 보낸 것이 아니라** 브로커에 남아 있던 마지막 값이다. 살아 있다는 증거로 쓰지 않는다 |

**`otel`** — `collector_up` · `accepted_total`(켠 뒤 받은 누적) · `accepted_since_last`(지난 줄 뒤로 받은 수 — 구동의 첫 줄은 `null`) · `lines`(Collector 지표 원문) · `otel_metric_names`(Prometheus 에 들어온 OTel 지표 이름 수)

**`prometheus`**

| 칸 | 형 | 뜻 |
|---|---|---|
| `up` | 참·거짓 | 엣지 Prometheus(9090)가 답하나 |
| `targets[]` | 목록 | 수집 대상마다 `job` · `health`(`up`) · `url` · `last_error` · `last_scrape`(마지막 수집 시각) · `last_scrape_age_s`(몇 초 전 — 15 초 남짓이면 정상) · `scrape_duration_s` |
| `devices[]` | 목록 | 장치마다 — 아래 |
| `devices_online` · `devices_samples_ok` | 수 | online 인 장치 수 · 끊김 없이 쌓인 장치 수 |
| `metric_names[]` | 목록 | 쌓인 지표 이름 · 시계열 수(`hw_*` · `system_*`) |

**`prometheus.devices[]`** — 장치 카드의 재료

| 칸 | 형 | 뜻 |
|---|---|---|
| `entity_id` · `entity_type` · `zone` | 글 | 장치 이름표(예: `go1-001` · `robot` · `zoneA`). 판정기가 붙인 이름표가 그대로 들어온다 |
| `up` | 수 | 1 살아 있음 · 0 아님 |
| `state` · `state_name` | 수 · 글 | 0 `online` · 1 `offline_planned`(계획 정지) · 2 `offline_fault`(장애) · 3 `stale`(소식 끊김) |
| `samples_10m` · `samples_expected_10m` | 수 | 최근 10분 동안 Prometheus 에 쌓인 횟수 · 기대값(15초 수집 → 40) |
| `samples_ok` | 참·거짓 | 36(90%) 이상 — **「끊김 없이 쌓였다」** |
| `heartbeat_age_s` | 수 | 마지막 심박이 몇 초 전인지. 심박을 안 보내는 장치는 `null` |
| `has_heartbeat` | 참·거짓 | 심박이 있나. **거짓이면 상태 메시지 하나로만 판정된 것** — online 이어도 살아 있다는 증거가 아니다(아래 5장) |

**`files`** — `logs[]`(mosquitto.log · otel_logs.jsonl · otel_traces.jsonl 의 크기 · 마지막 수정) · `prom_data_mb`(Prometheus 저장 크기)

## 5. 해석할 때 알아 둘 것 (11-25 실기기 시험에서 본 것)

- **EP(`ep-001` · `ep-1`)는 시험에서 쓰지 않았는데 `ep-001` 이 online 으로 보였다** — 브로커에 남아 있던 예전 상태 메시지(보관 메시지) 하나 때문이다. `has_heartbeat: false` · `pi_to_edge.retained_topics` 에 EP 가 보이면 「살아 있음」 으로 그리지 않는 것이 맞다. 같은 EP 가 `ep-001` · `ep-1` 두 이름으로 나온다(HW 쪽 이름 문제).
- **Go1 은 임무를 하는 동안 잠깐 `stale`(3)** 로 바뀌었다가 돌아온다 — 임무 중 심박을 끄는 알려진 한계. Go1 파이가 재부팅될 때도 `stale` 로 보인다(값만으로는 둘을 가르지 못한다).
- **OTel(`summary.otel`)이 거짓인 것이 지금은 정상**이다 — 파이를 고치지 않기로 해서 파이가 관측을 보내지 않는다.
- `samples_10m` 은 Prometheus 가 껐다 켜도 앞의 기록을 갖고 있어 앞 구동 시간까지 센다. 켠 직후의 값은 그 전 기록에 따라 다르다.
- 360° 카메라 · 드론 영상은 DS(데이터 스트림)의 몫이라 이 JSON 에 없다.
- 임무 이력 서버 · DB 는 엣지 스택을 꺼도 계속 돈다(WSL 이 켜져 있는 동안). 노트북이 잠들면 같이 멈춘다.
