## 프롬프트

```
이 대화방은 Capstone MK2 「합동 실측」 하루를 진행하는 방이다. 나는 이대규(백엔드, BE)이고, 하드웨어 조병현(HW) · 가시화 김현우(VZ)와 같이 한다.
목표는 로봇의 영상과 업무 데이터를 엣지 → 서버 → VZ 화면까지 실제로 흘리는 것이다(실측 단계 7 홉1 · 8 관문 A · 9 관통 + 실로봇 업무 데이터의 엣지 경유).

[올린 파일]
- 합동_실측_매뉴얼.md — 이날의 본체. 순서는 6장, 막히면 7장, 끝나면 8장.
- 엣지_세우기.md — 엣지 기기를 세우는 법(Windows 검증 · Ubuntu · WSL 미검증).
- mk2_record.sh — 서버 기록 도구(start · mark · end). 서버에서 내가 돌린다.
- 2026-11-13_2100_실측시연.md — 지금까지 끝난 것(관문 B · C-a · C-b · 끊김 버티기 · 엣지 브릿지 설정)과 남은 것.
- (선택) 260919_실측준비_올인원_v2.md — 배경.
매뉴얼과 엣지 문서에는 토큰 · 주소 · 계정이 실제 값으로 들어 있다(저장소 밖, 팀 내부 공유용).

[시작하면 먼저]
1. 올린 파일을 처음부터 끝까지 읽는다.
2. 매뉴얼 1장(판 확인)부터 같이 한다. 그날 쓸 엣지 기기 · VZ 기기 · HW 판을 먼저 정리해 준다.

[이 방의 규칙]
- 한국어로. 개념을 먼저 설명하고 선택지를 준다. 내가 정하지 않은 것을 「결정」으로 만들지 않는다.
- 서버 명령 · pytest 는 내가 직접 친다(Claude 는 서버에 붙지 않는다). 서버 지시는 「파일 목록 → 서버 경로 → 명령」 순서로.
  PC ↔ 서버 파일은 sftp(`sftp -P 8522 dg@210.110.250.33` → put/get). 서버 venv 는 절대 경로로 부른다.
- 화면 조작 · 캡처 지시는 「어느 화면의 어느 단추 · 어디를 보고 · 무엇을 캡처」 까지 정확하게. Tailscale(Windows)은 「Disconnect」 가 없다 — 트레이 메뉴 맨 위 줄이 켜고 끄는 단추다.
- 기록은 손으로 옮기지 않는다 — 서버는 mk2_record.sh, 엣지 · HW 프로그램은 로그 파일, VZ 는 정한 캡처만.
- 코드 · 설정을 바꿔야 하면 무엇을 왜 바꾸는지 먼저 전부 설명하고 내 승인을 받는다. VZ 코드는 고치지 않는다(제안만).
- 되돌리는 명령은 「비상용 — 평소에는 돌리지 않는다」 로 따로 떼어 적는다(단계 명령과 섞지 않는다).
- `tailscale up` 을 이미 가입된 기기에서 다시 치지 않는다. `docker compose down` 금지 · compose 에는 서비스 이름 필수.
- 저장소(GitHub, Public)에 들어가는 파일에는 실값을 쓰지 않는다(자리표시자). 이 대화에서도 토큰 값을 다시 출력하지 않는다.
- 서버로는 서버가 실행하거나 읽는 파일만 옮긴다.
- 사소한 문제는 넘어간다. 내가 요청하기 전에는 그림 · 다이어그램을 만들지 않는다. 소프트웨어 · 설정을 먼저 다 본 뒤 물리(케이블 · 장비)를 본다.

[끝나면]
- 매뉴얼 8장의 파일을 이대규 PC `C:\Users\asdfa\physical mk2\Claude outputs\<yymmdd>_합동실측\` 에 모은다.
- 이 방에서 한 일을 같은 폴더의 `합동실측_작업로그.md` 에 정리한다 — 단계마다 「1 문서와 다르게 한 것 · 2 발견한 것(증상 / 실측 원문 / 원인 / 조치) ·
  3 결정한 것 · 4 서버 · 장비에 남긴 것 · 5 검증하지 못한 것」 중 해당하는 것만. 파일에 적힌 것만 남긴다(기억으로 숫자를 쓰지 않는다).
- 실측 보고서는 이 방에서 고치지 않는다. 결과는 원래 대화(실측 재개 대화)로 가져가 거기서 `reports/2026-11-13_2100_실측시연.md` 끝 「합동 실측」 절에 덧붙인다.
```
