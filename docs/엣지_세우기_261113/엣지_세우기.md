## 0. 엣지가 하는 일 — 이것만 알면 된다

엣지는 로봇 옆(같은 망)에 두는 컴퓨터다. 두 가지 길이 엣지를 지나간다.

| 길 | 로봇 → 엣지 | 엣지 안 | 엣지 → 서버 |
|---|---|---|---|
| **업무 데이터**(상태값 · 생존 · 심박) | 로봇이 **엣지 Mosquitto `1883`** 으로 MQTT 발행 | **엣지 브릿지**(BE 코드)가 받아 검사 | 엣지 브릿지가 **서버 Kafka `100.102.8.102:9095`** 로 보낸다 |
| **영상** | 로봇 → 엣지 홉1 수신단(HW 코드) | HW 홉2 송신기 | HW 송신기가 **서버 `ws://100.102.8.102:8766/ingest`** 로 보낸다 |

- 이 문서가 세우는 것은 **업무 데이터 길(Mosquitto + 엣지 브릿지)** 과 **서버로 나가는 길(Tailscale · 서버 방화벽)** 이다.
- 영상 길의 HW 프로그램(홉1 수신단 · 홉2 송신기)은 HW 저장소의 것을 쓴다. 서버 쪽 목적지 · 형식은 `합동_실측_매뉴얼.md` 「HW 절」.
- **서버와 끊겨도 엣지가 업무 데이터를 들고 기다린다** — 메시지 하나당 최대 5분. 5분을 넘긴 것과 대기열이 넘쳐 버린 것은
  **엣지의 미전송 파일**(`unsent_edge.jsonl`)에 원본 그대로 남는다(2026-11-13 실측 — 두 번 다 서버에서 빠진 순번과 정확히 같았다).

## 2. Windows (✅ 검증된 길)

PowerShell 창을 쓴다. **관리자 PowerShell** 이라고 적은 곳만 관리자로 연다(시작 단추 오른쪽 클릭 → 「터미널(관리자)」 또는 「Windows PowerShell(관리자)」).

### 2-1. Tailscale 가입 · 주소 읽기

1. 받은 Tailscale 설치 파일을 실행해 설치한다.
2. 작업 표시줄 오른쪽 아래 알림 영역의 **Tailscale 아이콘**(안 보이면 `^` 를 눌러 펼친다)을 **오른쪽 클릭** → **「Log in…」**.
3. 브라우저가 뜨면 **「Sign in with Google」** → 1-2 의 팀 계정으로 로그인 → 「Connect」.
4. 일반 PowerShell 에서:
   ```powershell
   tailscale ip -4
   tailscale ping sysai-server2
   Test-NetConnection 100.102.8.102 -Port 9095 | Format-List RemoteAddress,RemotePort,TcpTestSucceeded
   ```
   - 첫 줄의 `100.x.x.x` 가 **이 엣지의 주소**다 — **이대규에게 보낸다**(2-2 에 필요).
   - `pong from sysai-server2 (100.102.8.102) … in Nms` 가 나오면 서버까지 닿는다. `via DERP` 가 아니라 `via <주소>:<포트>` 면 직접 경로다.
   - `TcpTestSucceeded : True` 면 서버 Kafka 가 보인다.

> **Tailscale 끄고 켜기(끊김 시험 때만):** 같은 아이콘 오른쪽 클릭 → 메뉴 **맨 위 「Tailscale / Connected」 줄**을 왼쪽 클릭하면 꺼지고
> (`tailscale status` 가 `Tailscale is stopped.`), 같은 줄을 다시 누르면 로그인 없이 다시 붙는다. 메뉴에 「Disconnect」 는 없다.
> 「Log out」 은 계정 줄(`>`) 안에 있다 — **누르지 않는다.** 「Exit」 은 아이콘만 끈다.

### 2-2. 서버 방화벽에 이 엣지를 넣는다 — BE · 서버 창

서버 방화벽은 **아는 기기만** 받는다. 영상 입구 `8766` 은 지금 이대규 PC · HW PC 둘만 들어 있다.
**새 기기면 BE 가 서버에서 두 줄을 넣는다**(`<엣지 주소>` 는 2-1 에서 받은 값, `<기기 이름>` 은 알아보기 쉬운 이름):

```bash
sudo ufw status numbered | grep -E "8766|9095"
sudo ufw allow from <엣지 주소> to any port 8766 proto tcp comment 'mk2 edge ingest (<기기 이름>)'
sudo ufw allow from <엣지 주소> to any port 9095 proto tcp comment 'mk2 edge kafka (<기기 이름>) - docker port, binding is real control'
sudo ufw status numbered | grep -E "8766|9095"
```

- 첫 줄에 이미 그 주소가 있으면 넣지 않는다.
- `9095` 는 도커가 연 포트라 방화벽 줄이 없어도 닿는다(2026-10-22 실측) — 기록을 맞추려고 넣는다. **영상(`8766`)은 이 줄이 없으면 막힌다.**

### 2-3. Mosquitto 설치 · 설정 — 관리자 PowerShell

```powershell
$EXE = "$env:USERPROFILE\Downloads\mosquitto-2.1.2-install-windows-x64.exe"
$MQ  = "C:\Program Files\mosquitto"
(Get-FileHash $EXE -Algorithm SHA256).Hash     # 1-3 의 SHA256 과 같아야 한다(대문자로 나온다)
Unblock-File $EXE
Start-Process -FilePath $EXE -ArgumentList "/S" -Wait
Test-Path "$MQ\mosquitto.exe"                  # True
Stop-Service mosquitto -ErrorAction SilentlyContinue
Set-Service mosquitto -StartupType Manual
Get-Service mosquitto | Format-Table Name,Status,StartType     # Stopped · Manual
```

- 🔴 **조용한 설치(`/S`)는 Windows 서비스 `mosquitto` 를 깔고 바로 띄운다** — 그대로 두면 우리 브로커와 `1883` 이 겹친다. 위 두 줄로 멈추고 수동으로 바꾼다.

**방화벽(이 엣지 기기)** — 로봇(pi7)과 서버만 `1883` 으로 들어오게 연다(같은 관리자 창):

```powershell
New-NetFirewallRule -DisplayName "MK2 edge mosquitto 1883" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 1883 `
  -RemoteAddress 100.72.109.9,100.102.8.102 -Program "$MQ\mosquitto.exe" -Profile Any
Get-NetFirewallApplicationFilter -Program "$MQ\mosquitto.exe" | Get-NetFirewallRule | Format-Table DisplayName,Direction,Action,Enabled
```

- 로봇이 pi7 이 아닌 다른 기기에서 발행하면 그 기기의 tailnet 주소를 `-RemoteAddress` 에 더한다
  (`Set-NetFirewallRule -DisplayName "MK2 edge mosquitto 1883" -RemoteAddress 100.72.109.9,100.102.8.102,<더할 주소>`).

**영상(홉1)도 이 엣지로 받으면** — pi7 이 엣지로 보내는 RTP(UDP `5004`)를 연다(같은 관리자 창). ⚠ **미검증** — HW 가 쓰던 엣지(HW PC)는
이미 받고 있었다. 받는 프로그램(HW 홉1 수신단)의 파이썬 경로를 알면 `-Program <그 python.exe>` 를 붙여 더 좁힌다.

```powershell
New-NetFirewallRule -DisplayName "MK2 edge hop1 RTP 5004" -Direction Inbound -Action Allow -Protocol UDP -LocalPort 5004 -RemoteAddress 100.72.109.9 -Profile Any
```

**폴더 · 설정 파일**(일반 PowerShell 로 돌아와서):

```powershell
New-Item -ItemType Directory -Force C:\mk2_edge\logs | Out-Null
@"
listener 1883 0.0.0.0
allow_anonymous true
log_dest stdout
log_dest file C:\mk2_edge\logs\mosquitto.log
log_timestamp_format %Y-%m-%dT%H:%M:%S
"@ | Set-Content -Encoding ascii C:\mk2_edge\mosquitto_edge.conf
Get-Content C:\mk2_edge\mosquitto_edge.conf
```

- 처음 세 줄이 서버 브로커와 같은 설정이다. Mosquitto 2.x 는 `listener` · `allow_anonymous` 를 안 적으면 이 기기 안에서만 받는다.
- `log_dest file` 줄은 로그를 파일로도 남긴다(⚠ **이 줄은 미검증** — Mosquitto 가 뜨지 않으면 이 줄을 지우고 다시 띄운다).
- 인증은 걸지 않는다(이번 범위). 위 방화벽 규칙이 실질 통제다.

**띄우기 — 「창 1 · 브로커」**(이 창은 계속 둔다):

```powershell
cd C:\mk2_edge
& "C:\Program Files\mosquitto\mosquitto.exe" -c .\mosquitto_edge.conf -v
```

기대: `Opening ipv4 listen socket on port 1883.` · `mosquitto version 2.1.2 running`

### 2-5. 엣지 브릿지 띄우기 — 「창 2 · 브릿지」(계속 둔다)

새 PowerShell 창에서 **이 블록을 통째로** 붙인다:

```powershell
cd C:\mk2_edge\Physical-Project-mk2
$env:MK2_MQTT_HOST = "127.0.0.1"
$env:MK2_MQTT_PORT = "1883"
$env:MK2_KAFKA_BOOTSTRAP = "100.102.8.102:9095"
$env:MK2_QUARANTINE_PATH = "C:\mk2_edge\logs\quarantine_edge.jsonl"
$env:MK2_UNSENT_PATH = "C:\mk2_edge\logs\unsent_edge.jsonl"
$env:MK2_KAFKA_CONNECT_TIMEOUT_MS = "5000"
$env:MK2_KAFKA_IDEMPOTENCE = "1"
$env:MK2_OTEL_ENDPOINT = " "
$env:PYTHONUNBUFFERED = "1"; $env:PYTHONIOENCODING = "utf-8"
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
cmd /c "C:\mk2_edge\venv\Scripts\python.exe -m backend.ingest.bridge 2>&1" | Tee-Object -FilePath "C:\mk2_edge\logs\bridge_$(Get-Date -Format yyMMdd_HHmm).log"
```

기대 줄(순서대로):

```
… INFO mk2.observability 관측 비활성: MK2_OTEL_ENDPOINT 가 비어 있다 — 계측 no-op, 업무 경로는 그대로 돈다
… INFO mk2.ingest ingest 기동: MQTT 127.0.0.1:1883 → Kafka 100.102.8.102:9095 / 격리파일 C:\mk2_edge\logs\quarantine_edge.jsonl
… INFO mk2.ingest Kafka 생산자: {'socket.connection.setup.timeout.ms': 5000, 'enable.idempotence': True} / 미전송파일 C:\mk2_edge\logs\unsent_edge.jsonl
… INFO mk2.ingest MQTT 접속: 127.0.0.1:1883 (client_id=mk2-ingest)
… INFO mk2.ingest READY — 구독 완료 ['+/+/+/state', '+/+/+/status', '+/+/+/heartbeat'] …
```

| 환경변수 | 값 | 뜻 |
|---|---|---|
| `MK2_MQTT_HOST` · `MK2_MQTT_PORT` | `127.0.0.1` · `1883` | **이 엣지 자신의 브로커**(서버가 아니다) |
| `MK2_KAFKA_BOOTSTRAP` | `100.102.8.102:9095` | 서버 Kafka 의 엣지 입구 |
| `MK2_QUARANTINE_PATH` | `…\logs\quarantine_edge.jsonl` | 형식이 틀린 메시지가 가는 곳 — **엣지에 있다** |
| `MK2_UNSENT_PATH` | `…\logs\unsent_edge.jsonl` | 서버로 못 보내고 버린 메시지(형식은 맞음)가 가는 곳 |
| `MK2_KAFKA_CONNECT_TIMEOUT_MS` | `5000` | 끊겼다 돌아왔을 때 다시 붙는 시도 하나의 한계. 없으면 Windows 에서 21초씩 늦었다 |
| `MK2_KAFKA_IDEMPOTENCE` | `1` | 다시 보낼 때 중복을 거르고 순서를 지킨다 |
| `MK2_OTEL_ENDPOINT` | `" "`(빈칸 하나) | 관측을 끈다. 🔴 Windows PowerShell 에서 `""` 는 변수를 **지워** 버려 서버 주소로 관측을 보내려 한다 — 빈칸 하나로 준다 |

- 메시지 하나가 기다리는 한계(5분)와 대기열 상한(10만 건)은 따로 주지 않는다 — 라이브러리 기본값이다.
- **한 엣지에 브릿지는 하나만** 띄운다(같은 이름으로 브로커에 붙는다).
- 끌 때는 이 창에서 `Ctrl+C`. ⚠ 끈 뒤의 줄(종료 신호 · 남은 것 처리)은 로그 파일에 남지 않는다 — `Ctrl+C` 가 `Tee-Object` 도 같이 끈다.

## 4. WSL (⚠ 미검증 — Windows 기기면 2장을 먼저 권한다)

WSL 은 기본이 **NAT** 라서 로봇(pi7)이 WSL 안의 `1883` 에 바로 들어오지 못한다. **미러 모드**(Windows 11 22H2 이상)로 바꿔야 한다.

| | |
|---|---|
| Tailscale | **Windows 쪽에 하나만** 깐다(2-1). WSL 안에는 깔지 않는다 — 미러 모드면 WSL 이 Windows 의 망을 같이 쓴다 |
| 엣지 주소 | Windows PowerShell 의 `tailscale ip -4` 값(WSL 안에서는 `tailscale` 이 없다) |
| 서버 방화벽 | 2-2 와 같다 |

**4-1. 미러 모드 켜기**(Windows 일반 PowerShell):

```powershell
@"
[wsl2]
networkingMode=mirrored
"@ | Set-Content -Encoding ascii "$env:USERPROFILE\.wslconfig"
wsl --shutdown
wsl --version            # WSL 버전 2.0 이상이어야 한다
```

WSL(Ubuntu)을 다시 열고 `ip -4 addr | grep 100.` 에 Windows 의 tailnet 주소가 보이면 미러 모드다.

**4-2. 1883 을 들이는 방화벽 둘**(관리자 PowerShell) — 미러 모드에서는 Windows 방화벽과 **Hyper-V 방화벽**을 둘 다 지난다:

```powershell
New-NetFirewallRule -DisplayName "MK2 edge mosquitto 1883 (WSL)" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 1883 -RemoteAddress 100.72.109.9,100.102.8.102 -Profile Any
New-NetFirewallHyperVRule -Name "MK2-edge-1883-WSL" -DisplayName "MK2 edge mosquitto 1883 (WSL)" -Direction Inbound -VMCreatorId '{40E0AC32-46A5-438A-A0B2-2B479E8F2E90}' -Protocol TCP -LocalPorts 1883
# 영상(홉1)도 WSL 에서 받을 때만:
New-NetFirewallRule -DisplayName "MK2 edge hop1 RTP 5004 (WSL)" -Direction Inbound -Action Allow -Protocol UDP -LocalPort 5004 -RemoteAddress 100.72.109.9 -Profile Any
New-NetFirewallHyperVRule -Name "MK2-edge-5004-WSL" -DisplayName "MK2 edge hop1 RTP 5004 (WSL)" -Direction Inbound -VMCreatorId '{40E0AC32-46A5-438A-A0B2-2B479E8F2E90}' -Protocol UDP -LocalPorts 5004
```

**4-3. 나머지는 WSL(Ubuntu) 안에서 3-3 ~ 3-6 그대로**(3-1 Tailscale 은 건너뛴다. 3-3 의 `ufw` 는 WSL 안에서는 보통 꺼져 있어 건너뛴다).

- 서버 확인(2-6)에서 60건이 오면 엣지 → 서버는 된 것이다. **로봇 → 엣지(1883)는 합동 실측에서 로봇이 붙어야 확인된다** — 그때 안 되면
  4-2 의 방화벽 둘을 먼저 보고, 그래도 안 되면 **Windows 쪽 Mosquitto(2-3) + WSL 브릿지**로 바꾼다(미러 모드에서는 WSL 의 `127.0.0.1` 이 Windows 와 같다).
