## 4. HW 절 — 로봇 → 엣지 → 서버

### 4-1. 업무 데이터 — 로봇 노드 → 엣지 브로커

**목적지:** `<엣지 tailnet 주소>:1883` (MQTT, 인증 없음).
🔴 **pi7 자기 브로커나 서버 브로커가 아니다.** pi7 자기 브로커로 보내면 아무 데도 안 가고, 서버 브로커로 보내면 엣지를 안 거친다.
엣지 기기 방화벽에 pi7(`100.72.109.9`)이 `1883` 으로 들어오게 열려 있어야 한다(`엣지_세우기.md` 2-3 · 2-8 · 3-3).

**토픽:** `{구역}/{개체 타입}/{개체}/{채널}` — 로봇이면 `zoneA/robot/go1-001/state` · `zoneA/robot/go1-001/status` · `zoneA/robot/go1-001/heartbeat`.
엣지 브릿지는 `+/+/+/state` · `+/+/+/status` · `+/+/+/heartbeat` 셋을 받는다.

**본문(JSON) — 필수 칸:**

| 칸 | 값 | 규칙 |
|---|---|---|
| `schema_version` | `"2.0"`(통합데이터규약 v3) · 옛 `"1.x"` 도 받는다 | `숫자.숫자` |
| `source_id` | `"go1-001"` | |
| `node_id` | `"pi7"` | |
| `zone_id` | `"zoneA"` | 🔴 다르면 VZ 화면이 빈다(연결은 됨) |
| `timestamp` | 값을 잰 순간 · 예 `"2026-11-20T14:10:31.086+09:00"` | 밀리초 3자리 · `+09:00` |
| `sequence_id` | 발행마다 1씩 느는 정수(권장) | 빠짐 · 역전을 서버가 이걸로 센다 |
| `session_id` | 노드 프로세스가 뜰 때마다 새로 만든 12자리 hex(권장) | 순번이 다시 시작되는 경계 |
| `state` 본문(로봇) | `reason` · `device_status` · `battery_pct` · `position{x, y, heading_deg}` · `speed_mps` · `robot_mode` · `internal_seq` | **일곱 다 필수**(값이 `null` 이어도 칸은 있어야 한다). `mission` 은 선택 |
| `status` 본문 | `event`(`birth` · `death` …) · `status`(`online` · `offline` …) | retained 로 보낸다. 급사(LWT)도 이 채널 |
| `heartbeat` | 본문 없음(공통 칸만) | QoS 0 이어도 된다 |

예(로봇 `state` 한 건):

```json
{"schema_version": "2.0", "source_id": "go1-001", "node_id": "pi7", "zone_id": "zoneA",
 "timestamp": "2026-11-20T14:10:31.086+09:00", "sequence_id": 1532, "session_id": "9f2c1a7b04e6",
 "channel": "state", "reason": "periodic", "device_status": "ok", "battery_pct": 87.5,
 "position": {"x": 12.34, "y": -3.5, "heading_deg": 91.2}, "speed_mps": 0.42, "robot_mode": "idle", "internal_seq": 15832}
```

**형식이 틀리면** 그 메시지는 서버로 안 가고 **엣지의 격리 파일**(`quarantine_edge.jsonl`)에 사유와 함께 남는다. 실노드 업무 데이터가 엣지를
거치는 것은 이날이 처음이다 — 격리가 나오면 그 파일의 `reason` 을 보고 로봇 노드를 고친다.

**확인**

| 어디서 | 무엇 | 합격 |
|---|---|---|
| 엣지 창 2(BE) | `produce: zoneA/robot/go1-001/state → mk2.telemetry.state (source_id=go1-001, sequence_id=…, etype=robot, …)` | 발행 주기마다 한 줄 |
| 엣지 창 1(BE) | `New client connected from 100.72.109.9…` | pi7 이 붙었다 |
| 엣지 `logs\quarantine_edge.jsonl` | | 생기지 않는다 |
| 서버(BE) `recent go1-001 5` | 최근 5분 세션별 행 수 · 순번 · 마지막 도착 · 가장 오래 기다린 초 | 행이 늘고, 기다린 초가 1초 남짓 |
| 서버(BE) `srvbridge go1-001 5` | 서버 브릿지가 받은 go1-001 | **0건**(엣지 경로) |

### 4-2. 영상 — 홉2 송신기 → 서버 영상 입구

**목적지:** `ws://100.102.8.102:8766/ingest?camera_id=go1-001_front&token=jU1Hf9VbMQuCOJwCqMOqQQfDgsW14BaX`

- 엣지가 **클라이언트로** 붙는다(엣지에 들어오는 쪽을 열 필요 없음). 서버 방화벽 `8766` 에 그 엣지 주소가 있어야 한다(1-1).
- 토큰은 **환경변수로** 준다 — 명령줄에 그대로 치면 셸 기록 · 프로세스 목록에 남는다.
- **카메라 하나에 소켓 하나.** 같은 `camera_id` 로 둘째가 붙으면 서버가 `4409` 로 끊는다.

**메시지 한 개 = 프레임 한 장**(H.264 액세스 유닛 하나), 8MB 이하, 바이너리:

```
[4바이트 빅엔디언 = 헤더 길이][JSON 헤더(UTF-8)][H.264 바이트 그대로]
```

**헤더 v2(평평한 모양)** — 필수 칸:

| 칸 | 값 | 규칙 |
|---|---|---|
| `schema_version` | `"2.0"` | |
| `source_id` | `"go1-001"` | 카메라가 달린 장비 |
| `node_id` | 엣지 이름(예 `"hw-edge"`) | 이 프레임을 만든 컴퓨터 |
| `zone_id` | `"zoneA"` | |
| `timestamp` | 그 프레임을 **손에 넣은 순간** · 밀리초 3자리 · `+09:00` | 보낸 순간이 아니다 |
| `sequence_id` | 카메라마다 세는 프레임 순번 — **손에 넣는 순간** 매긴다 | 재기동하면 0부터 |
| `session_id` | 송신 프로세스가 뜰 때마다 새로 만든 12자리 hex | |
| `camera_id` | `"go1-001_front"` | 🔴 **접속 주소의 `camera_id` 와 같아야 한다** — 다르면 프레임마다 거부 |
| `encoding` | `"h264"` | |
| `keyframe` | 그 프레임 안에 IDR(NAL 5)이 있으면 `true` | H.264 면 필수. **서버가 이걸로 느린 뷰어를 키프레임에서 다시 시작시킨다** |
| `width` · `height` | `464` · `400` | |
| `codec` | `"avc1.424028"` — **SPS 에서 읽는다**(상수로 박지 않는다) | H.264 면 필수. 틀리면 VZ 디코더가 못 연다 |

예:

```json
{"schema_version": "2.0", "source_id": "go1-001", "node_id": "hw-edge", "zone_id": "zoneA",
 "timestamp": "2026-11-20T14:10:31.123+09:00", "sequence_id": 4837, "session_id": "a1b2c3d4e5f6",
 "camera_id": "go1-001_front", "encoding": "h264", "keyframe": true, "width": 464, "height": 400, "codec": "avc1.424028"}
```

- 옛 v1 헤더(`frame_ref` 묶음)도 서버가 아직 받는다(과도기). 1-2 에서 어느 쪽인지 기록한다.
- 링크가 막히면 송신 쪽도 서버와 같은 규칙으로 버린다 — **다음 키프레임까지 통째로.**

**서버가 하는 것:** 토큰 확인 → 헤더의 **필수 칸 · 타입만** 검사 → 구독 중인 뷰어에 나눠 보낸다. 영상 바이트는 열지 않는다.
헤더가 틀리거나 8MB 를 넘으면 **그 프레임만 버리고 연결은 유지**한다.

| 끊김 코드 | 뜻 | 할 일 |
|---|---|---|
| `4401` | 토큰 없음 · 틀림 | 엣지 토큰인지(뷰어 토큰과 다르다). **다시 시도해도 같다** |
| `4400` | `camera_id` 가 주소에 없음 | 주소 |
| `4404` | 경로가 `/ingest` 가 아님 | 주소 |
| `4409` | 같은 카메라로 이미 다른 송신기가 붙어 있음 | 앞의 송신기를 끈다 |

**확인**

| 어디서 | 무엇 | 합격 |
|---|---|---|
| 서버(BE) `vsnap`(10초 간격 두세 번) | `ingress` · `sent` · `dropped` · `rejected` | **`ingress` 가 초당 약 30씩 는다** · `rejected` 그대로 |
| 서버(BE) 아래 명령 | 영상 입구 접속 · 거부 줄 | `/ingest 접속 camera_id=go1-001_front` · `헤더 거부` 줄 없음 |
| VZ | 5-2 ③ 영상 칸 | 그림이 뜨고 `받음` 이 는다 |

```bash
journalctl -q -u mk2-ws-echo --since "-5 min" --no-pager | grep -E "/ingest|거부"
```

### 4-3. 홉1 — 로봇 → 엣지 (HW 프로그램)

HW 저장소의 방법대로 한다. 서버 쪽에서 볼 것이 없는 구간이라 아래만 확인한다.

| 확인 | 왜 |
|---|---|
| pi7 카메라 뷰어(브라우저)에 그림이 나온다 | 서비스가 떠 있는 것만으로는 카메라가 살아 있는지 모른다 |
| pi7 송신기의 **목적지 주소가 엣지 주소**로 채워져 있다 · 포트 `5004` | 🔴 비우면 오류 없이 MQTT 브로커 주소로 나간다(UDP 라 성공으로 보인다) |
| 송신기를 **실제로 켰다**(`stream_start`) · 카메라 **정면 하나만** | 프로세스가 떠 있는 것만으로는 안 나간다 |
| 엣지 기기 방화벽에 UDP `5004`(pi7 에서) | `엣지_세우기.md` 2-3 「영상(홉1)도 이 엣지로 받으면」 |
| 엣지 홉1 수신단이 받는다 | HW 수신단의 로그 · 파일 크기(30초에 2MB 근처가 정상 범위) |

## 5. VZ 절 — 서버 → 화면

### 5-1. 연결 설정 — 화면에 넣을 값

1. VZ 앱(`http://localhost:5174`)에서 **「⇄ 연결 관리」** 를 연다(머리줄의 「연결 미확인 (누르면 연결 관리)」 칩을 눌러도 열린다).
2. **「백엔드 WS 게이트웨이」** 칸:
   - WebSocket: `ws://100.102.8.102:8765/state?token=zxsalAbLdWIxyS5SiDqHq1KZhJghYM4b`
   - HTTP: 기본값 그대로(`http://127.0.0.1:8790`)
   - **구역 식별자: `zoneA`** (🔴 `zone-503` 이면 연결은 되고 화면만 빈다)
   - 서버 지표 주소: 비운다
3. **「영상 소켓」** 칸:
   - WebSocket: 「직접 입력」 → `ws://100.102.8.102:8765`
   - 카메라 키: `go1-001_front`
   - 뷰어 토큰: `zxsalAbLdWIxyS5SiDqHq1KZhJghYM4b`
4. **「적용」**.

- 🔴 **이 「연결 관리」 판은 토큰이 그대로 보인다 — 캡처하지 않는다.**
- VZ 기기가 `100.125.71.51` · `100.78.11.92` 가 아니면 연결 시도 자체가 막힌다(토큰 문제처럼 보이지만 서버 방화벽이다) — 그 주소를 BE 에게 주고
  BE 가 서버에서 `sudo ufw allow from <VZ 기기 주소> to any port 8765 proto tcp comment 'mk2 viewer (<기기 이름>)'` 를 넣는다.

## 부록 A — BE 서버 창에서 쓰는 함수 (한 번 붙여 두고 쓴다)

```bash
cd /home/dg/capstone-db/phase1_work/Physical-Project-mk2
q(){ curl -s 'http://localhost:7861/api/v1/query' --data-urlencode "query=$1" | python3 -c 'import sys,json; r=json.load(sys.stdin)["data"]["result"]; print(r[0]["value"][1] if r else "없음")'; }
tsdb(){ docker exec -i capstone_timescaledb psql -U postgres -d mk2 -tAc "$1"; }
vsnap(){ echo "$(TZ=Asia/Seoul date +%T) ingress=$(q 'sum(be_gateway_media_ingress_total)') sent=$(q 'sum(be_gateway_media_frames_total{outcome="sent"})') dropped=$(q 'sum(be_gateway_media_frames_total{outcome="dropped"})') rejected=$(q 'sum(be_gateway_media_rejected_total)')"; }
recent(){ tsdb "SELECT channel, coalesce(session_id,'-'), count(*), min(sequence_id), max(sequence_id), to_char(max(received_at) AT TIME ZONE 'Asia/Seoul','HH24:MI:SS'), round(max(extract(epoch FROM received_at - ingest_at))::numeric,1) FROM telemetry WHERE source_id='${1:-go1-001}' AND received_at > now() - interval '${2:-5} minutes' GROUP BY 1,2 ORDER BY 1,2;"; }
srvbridge(){ echo "서버 브릿지가 받은 ${1:-go1-001}(최근 ${2:-5}분): $(journalctl -q -u mk2-ingest --since "-${2:-5} min" --no-pager | grep -c "produce:.*source_id=${1:-go1-001},")건"; }
chk(){ tsdb "SELECT count(*), count(DISTINCT sequence_id), min(sequence_id), max(sequence_id), round(max(extract(epoch FROM received_at - ingest_at))::numeric,1) FROM telemetry WHERE session_id='$1';"; tsdb "WITH m AS (SELECT s FROM generate_series(1,$2) s EXCEPT SELECT sequence_id FROM telemetry WHERE session_id='$1') SELECT min(s), max(s), count(*) FROM (SELECT s, s - row_number() OVER (ORDER BY s) AS g FROM m) t GROUP BY g ORDER BY 1;"; }
```

| 함수 | 쓰는 법 | 나오는 것 |
|---|---|---|
| `vsnap` | `vsnap` | 지금 시각(KST) · 영상 입구 받은 수 · 뷰어로 보낸 수 · 서버가 버린 수 · 거부 수 — **두 번 찍어 차이로 본다**(서비스가 다시 뜨면 0부터) |
| `recent` | `recent go1-001 5` | 최근 5분 그 장치의 채널 · 세션별: 행 · 첫 순번 · 끝 순번 · 마지막 도착(KST) · 가장 오래 기다린 초 |
| `srvbridge` | `srvbridge go1-001 5` | 최근 5분 **서버** 브릿지가 그 장치를 받은 수 — 엣지 경로면 0 |
| `chk` | `chk <session_id> <보낸 수>` | 첫 줄은 세로 막대로 이은 다섯 칸(행 · 순번 종류 · 첫 순번 · 끝 순번 · 가장 오래 기다린 초) · 둘째 줄부터 빠진 순번 구간(없으면 안 나온다) — 가짜 발행처럼 순번이 1부터일 때 |

- 로봇 v1 처럼 `sequence_id` 가 늘 0 이면 `chk` 의 빠짐 계산은 뜻이 없다 — `recent` 의 행 수로 본다. 실노드가 순번을 올리면(HW 2026-09: 12 → 146 단조 증가) `mk2_record.sh end` 가 세션별 빠진 구간까지 계산한다.
