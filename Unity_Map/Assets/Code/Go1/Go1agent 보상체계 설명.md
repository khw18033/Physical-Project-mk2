# GO1Agent 보상체계 설명

## 개요
이 문서는 `GO1Agent.cs`에 구현된 보상 항목을 한눈에 정리하고, 각 파라미터를 어떻게 변경하면 학습 행태가 어떻게 변하는지 실무적으로 설명합니다. 튜닝 시 참고용으로 빠르게 이해할 수 있게 구성되어 있습니다.

---

## 핵심 보상 항목(요약)
- 스텝 패널티: `AddReward(-0.001f)`
- 회전 저크 패널티: `-Mathf.Abs(smoothedTurn - previousTurn) * 0.003f`
- 정렬 보상(heading): `AddReward(nextFacing * 0.01f)`
  - 보너스: `if (nextFacing > 0.95f) AddReward(0.002f)`
  - 역방향 페널티: `if (nextFacing < 0f) AddReward(-0.005f)`
- 경로 접근 보상: `(previousPathDist - pathDist) * 1.5f` (clamp -0.05 ~ +0.05)
- 웨이포인트 접근 보상: `Clamp(previousWaypointDist - waypointDist, -0.05, 0.05)`
- 코너 통과 보너스: `AddReward(0.3f)` (코너를 실제로 지나친 순간, 단발)
- 복도 중앙 정렬: `AddWallClearanceReward()` → `corridorCenteringWeight` (기본 0.01f)
- 충돌 패널티: 기본 `-0.02f`, 장애물(`Obstacle`) 추가 `-0.05f`, 과다 충돌 시 `-1.0f`로 에피소드 종료
- 막힘(stuck) 패널티: `AddReward(-0.01f)` 및 누적 임계치로 실패 처리
- 목표 도달 보상(학습 모드): `AddReward(10.0f)`

## 파라미터별 권장 변경 및 기대 효과
아래는 실무적 권장값 범위와 '바꿨을 때 기대되는 행동 변화'입니다. 항상 한 번에 1~2개만 바꾸어 비교하세요.

1. 스텝 패널티 (`-0.001f`) `AddReward(-0.001f)`
   - 권장: -0.001 → -0.005 (실험), -0.01 (공격적)
   - 기대: 에피소드 단축, 빠른 목표 지향 행동 유도
   - 주의: 충돌률 증가 가능 → 충돌 패널티와 균형 필요

2. 회전 저크 패널티 (`0.003f`) `-Mathf.Abs(smoothedTurn - previousTurn) * 0.003f`
   - 권장: 0.003 → 0.006~0.01
   - 기대: 좌우 진동 감소, 부드러운 회전
   - 주의: 회전 자체 억제될 수 있으므로 정렬 보상과 같이 조정

3. 정렬 보상 (`0.01f`) `AddReward(nextFacing * 0.01f)`
   - 권장: 0.01 → 0.02~0.05
   - 기대: 목표를 향한 빠른 회전/정렬 증가, 경로 추종 개선
   - 주의: 회전 벌점 크면 정렬을 피함 → 함께 튜닝

4. 경로 접근 보상 (scale 1.5, clamp ±0.05)
   - 권장: scale 1.5 → 2.5, clamp 상한 → 0.1
   - 기대: 거리 감소에 민감해져 빠른 전진 선호
   - 주의: 안전 무시 우려 → 충돌 패널티 유지 강화

5. 웨이포인트 보상 (clamp ±0.05)
   - 권장: ±0.05 → ±0.1
   - 기대: 정확한 코너 통과 증가
   - 주의: 프레임 단위 보상 누적 파밍 고려 (현재 코너 보너스는 단발)

6. 코너 보너스 (0.3)
   - 권장: 조정 가능(0.1 ~ 0.6)
   - 기대: 값↑ → 웨이포인트 통과 적극성↑
   - 주의: 너무 크면 인위적 행동 유도 가능

7. 복도 중앙 정렬 (`corridorCenteringWeight` 기본 0.01)
   - 권장: 0.01 → 0.02~0.1
   - 기대: 좁은 복도에서 중앙 유지, 벽 스크래치 감소
   - 주의: 목표 접근 속도 저하 가능

8. 충돌 패널티 (기본 -0.02 / 장애물 -0.05)
   - 권장: 기본 -0.02 → -0.05, 장애물 -0.05 → -0.15~ -0.3
   - 기대: 충돌 회피 강화
   - 주의: 지나치면 소극적 행동, 정지/우회 반복 발생

9. 막힘 페널티 (`-0.01`) 및 민감도
   - 권장: 패널티 유지 또는 소폭 증가, 막힘 임계 감소
   - 기대: 막힘 시 빠른 탈출 유도 또는 재경로 시도
   - 주의: 잦은 재시작으로 학습 신호 감소 가능

10. 목표 도달 보상 (`10.0f`)
    - 권장: 대부분 경우 유지
    - 기대: 최종 보상으로 도달 행동 강력 유도

## 실험 조합 예시 (권장)

- 안전 우선 (A) — 권장 세팅(상세)
   - 목표: 충돌·스크래치 최소화, 안정성 우선
   - 권장 파라미터
      - 충돌 기본 패널티: `-0.05`
      - 장애물 태그 충돌 패널티: `-0.2`
      - `corridorCenteringWeight`: `0.05`
      - 스텝 패널티: `-0.001` (기본 유지)
      - 회전 저크 페널티: `0.003 → 0.006` (진동 억제)
   - 적용 이유: 충돌 패널티를 크게 두어 충돌 위험을 신속히 억제하고, 복도 중앙 유지 가중치를 높여 벽 긁기 감소.
   - 기대 지표 변화: 충돌 수↓, 장애물 충돌↓, 평균 보상 안정화(낮지만 신뢰도↑).
   - 주의: 충돌 패널티가 너무 크면 에이전트가 지나치게 보수적으로 행동할 수 있으니 관찰 후 소폭 완화 권장.

- 빠른 도달 (B)
   - 요약: 스텝 패널티 증가(`-0.005`) + 접근 보상 강화 → 목표에 빨리 도달하도록 유도
   - 주의: 충돌 증가 가능성 있음

- 매끄러운 주행 (C)
   - 요약: 회전 저크 패널티 강화 + 정렬 보상 소폭 증가 → 진동 감소, 안정적 궤적

## 실험 절차(권장)
1. 한 번에 1~2개 파라미터 변경.
2. 각 실험은 충분한 반복(권장: 5k~50k 에피소드 또는 예산에 맞게 설정).
3. 수집 지표: 도착률, 평균 스텝, 평균 충돌 수, 막힘 이벤트 수, 평균 보상.
4. 베이스라인 대비 통계적 비교(동일 시드/환경 가능하면 고정).

---

## 구현상 유의점
- 일부 값(예: approach scale 1.5, clamping 값)은 코드 내부 하드코드입니다. 에디터 노출 변수가 아니므로 실험 전 코드 수정/컴파일 필요.
- `AddWallClearanceReward()`에서 한쪽 벽 근접 패널티 로직은 현재 주석 처리되어 있어, 필요하면 해당 로직을 복원하여 사용하세요.
