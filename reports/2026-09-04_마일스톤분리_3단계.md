# 마일스톤 분리 3단계 — 서비스 경계와 강제 디코딩 (지시서 §3, 경계만)

**지시서**: `작업프롬프트_마일스톤분리_260904.md` §3
**선행**: 2단계 (`edbe0b0`) — `solveDeps` 와 `verify:dep-rules`
**범위 제한**: **엔진은 붙이지 않는다** (모델 미결정). `gen-lab` 은 계약 검증만 하는 스텁이다
**날짜**: 2026-09-04

## 한 줄

**생성 서비스를 보는 면을 하나 만들고, 그 면이 없어도 화면이 도는 것을 검사로 못박았다.**
문법은 계약에서 뽑고, 손으로 쓴 문법 파일은 저장소에 하나도 없다.

## 계약에서 문법을 뽑는 방식

`src/generate/gbnf.ts` — `contracts/mission.schema.json` → GBNF. 순수 함수이고 계약을
**인자로 받는다**(import 로 묶어 두면 「계약을 고치면 문법이 바뀌는가」를 검사할 수 없다).

계약 5개(`mission`·`milestone`·`task`·`action-item`·`evaluation`)를 따라가며 규칙 40개를
낸다. **허용 목록(enum)이 문법의 알맹이다** — 그것이 강제 디코딩이 실제로 하는 일이다.

```
milestone-status ::= ("\"pending\"" | "\"running\"" | "\"done\"" | "\"failed\""
                    | "\"skipped\"" | "\"awaiting_evaluation\"" | "\"not_executed\""
                    | "\"rerunning\"") ws
task-node-kind   ::= ("\"sense\"" | "\"decide\"" | "\"act\"" | "\"verify\"" | "\"report\"") ws
task-evaluation  ::= task-evaluation-0 | evaluation      # anyOf: null | evaluation
```

2단계에서 계약에 올린 `node_kind` 가 **선택 필드**라는 것까지 문법에 실린다:

```
task ::= "{" ws … "\"evaluation\"" ws ":" ws task-evaluation
         ("," ws "\"node_kind\"" ws ":" ws task-node-kind)? "}" ws
```

문법 4,533바이트 · 지문 `40f9279d9d1505d7`.

### 정한 것 셋

1. **객체 키 순서를 계약의 `properties` 차례로 고정한다.** JSON 객체는 원래 순서가 없지만
   문법으로 순서를 풀면 규칙이 조합 폭발한다. 고정 순서는 계약을 어기지 않는다 —
   어느 순서든 같은 객체이고, 우리가 그중 하나를 고른 것뿐이다.
2. **`minItems` 는 1까지만 문법으로 강제한다.** 그 이상은 세는 규칙이 폭발한다.
   남는 것은 서비스의 계약 검증이 잡는다 — 그래서 스텁도 검증을 한다.
3. **못 옮기는 타입은 조용히 넘기지 않고 던진다.** 문법이 계약보다 느슨하면 강제 디코딩이
   계약 밖 출력을 통과시키고, 그러면 「강제 디코딩이 실제로 듣는가」를 재는 축(스키마)이
   무의미해진다. `verify:gen-port` 가 이것을 대조군으로 확인한다.

### 문법을 **클라이언트가** 뽑아 보낸다 — 그 선택의 대가

`LlmClient` 가 계약에서 뽑아 요청에 실어 보낸다. 그래서 **부르는 쪽이 계약 밖 출력을
요구할 수 없다.** 대신 서비스가 강제하는 것은 아니다.

**엔진이 붙으면 서비스도 같은 계약에서 다시 뽑아 지문을 대조해야 한다.** 지금 스텁은 받은
지문을 되돌려 주기만 하고 `extra.grammar_enforced: false` 로 그 사실을 적는다.
숙제로 남긴 자리이고, `gen-lab/README.md` 에도 적어 두었다.

## 서비스가 꺼졌을 때 실제로 꺼지는 것

`src/generate/availability.ts` — `stt/availability.ts` 와 같은 모양의 순수 함수 하나.

| | 서비스 있음 | **서비스 없음** |
|---|---|---|
| 발화 → 임무 생성 (`VZ-G-01`·`VZ-G-02`) | ○ | **✗ — 이것만 꺼진다** |
| 대본 재생 (키워드 대조) | ○ | ○ |
| 되감기 (기록 열 접기) | ○ | ○ |
| 노드 캔버스 | ○ | ○ |
| 명령 출구 (게이트웨이) | ○ | ○ |
| 계약 → 문법 뽑기 | ○ | ○ (계약은 빌드에 박혀 있다) |

아래 넷은 **타입이 `true` 로 고정되어 있다** — 상태에 따라 잠글 수 있게 만들면 언젠가
잠긴다(`manualInput` 과 같은 규칙). 배치 ①(생성 꺼짐)이 기본형이므로 이 성질이 곧
심사·평가 배포의 성질이다.

`verify:no-llm` 이 함수만 부르는 것이 아니라 **구조도 본다** — 대본 재생·되감기·캔버스·
명령 출구의 파일 14개가 `src/generate/` 를 import 하지 않는지. 함수가 `true` 를 돌려주는
것만으로는 부족하고, 그 넷이 애초에 생성 서비스를 모르는지가 「생성만 꺼진다」의
구조적 근거다.

## 배치와 번들 크기

모델은 브라우저에 들어가지 않는다. `LlmClient` 를 화면에 붙였을 때의 실측:

| | 이전 | 생성 계층 포함 | 늘어난 양 |
|---|---:|---:|---:|
| 모듈 수 | 120 | 130 | +10 |
| `app.js` | 445.04 kB | 461.11 kB | **+16.07 kB** |
| gzip | 136.59 kB | 142.33 kB | **+5.74 kB** |

지시서가 「사이드카면 `LlmClient` 는 fetch 래퍼라 몇 KB다」라고 적은 그대로다.
늘어난 16 kB 의 대부분은 **계약 JSON 5개**이고 모델은 0바이트다.

(이 숫자는 §6 화면 적용의 예상치다 — 지금은 아무도 `LlmClient` 를 import 하지 않으므로
`dist/` 는 그대로 445.04 kB 이고 `verify:standalone` 은 무개정 통과한다.)

## `gen-lab` — 스텁

`stt-lab` 과 같은 모양의 FastAPI. `python -m server.main`, 포트 8802, npm·Vite·node_modules 없음.

### 스텁이 실제로 하는 일은 계약 검증 하나다

띄워서 확인한 실동작:

```
GET  /generate/health    → engine=stub · contracts=12 · goldset_missions=4
POST /generate/mission   → engine=stub · schema_checked=True · schema_errors=0
                           grammar.bytes=4533 · extra.stub=True · milestones=1
```

**고정 응답은 정답셋을 베껴 오지 않는다.** 정답을 그대로 돌려주면 채점기가 만점을 내고,
그 만점이 「스텁이라서」인지 「모델이 잘해서」인지 구별되지 않는다. 계약만 만족하는 최소
임무 하나를 돌려준다 — 스키마 축은 통과하고 나머지 축은 낮게 나오는 것이 정직한 모습이다.

**목임을 감추지 않는다** — `engine: "stub"` 과 `extra.stub: true`, 그리고 왜 스텁인지의 사유.

### 계약 사본을 두지 않는다

`server/main.py` 가 저장소 루트의 `contracts/` 를 직접 읽는다. gen-lab 안에 베껴 두면
저장소가 계속 피해 온 「두 벌이 조용히 갈라진다」가 그대로 난다 —
`verify:gen-port` 가 gen-lab 안의 `*.schema.json` 을 0건으로 못박는다.

검증기도 `jsonschema` 패키지를 끌어오지 않고 `contracts/` 가 실제로 쓰는 문법만 다루는
최소 구현을 안에 두었다(1단계의 `scripts/lib/json-schema.mjs` 와 같은 범위).
의존성은 FastAPI + uvicorn 둘뿐이다.

### 엔진 자리

`server/engines/__init__.py` 의 `available()` 이 **빈 목록**을 돌려준다. 붙일 때 파일 하나를
더하고 `main.py` 가 그것을 고르게 한다 — **서버 파일에 엔진 이름이 나오면 안 된다**
(`stt-lab` 과 같은 규칙 · REQ-1302).

`stt/engines/*.py` 처럼 원본에서 이식하는 것이 아니라 여기서 새로 쓴다. 그래서
`verify:stt-port` 같은 바이트 동일성 검사가 이 폴더에는 없다.

### `npm run dev` 는 gen-lab 을 띄우지 않는다

일부러 그렇게 두었다. **배치 ①(생성 꺼짐)이 기본형**이고, 안 떠 있는 것이 정상 상태다.
`dev-all` 에 넣으면 설치 안 된 개발자의 화면에 매번 실패 줄이 뜬다. 띄우는 절차는
`gen-lab/README.md` 에 있다.

## 새 검사 둘

### `verify:no-llm`

`verify:no-stt` 와 같은 모양 셋 + 하나.

1. 서비스가 전부 실패하는 상태에서 `probe()` 가 **던지지 않고** `alive:false` + 사유(주소 포함)
2. 그 상태의 `capabilities()` 가 **생성만** 끄는가 (세 상태 × 네 기능 전부)
3. `generateMission()` 이 `LlmUnavailableError('offline')` 을 던지는가
4. **대본 재생·되감기·캔버스·명령 출구가 생성 계층을 import 하지 않는가** ← `no-stt` 에 없는 것

대조군 2건 — 대본 재생을 생성 상태에 묶은 사본 · 되감기 저장소에 생성 import 를 주입한 사본.

### `verify:gen-port`

**이름은 `verify:stt-port` 를 따랐지만 보는 것이 다르다.** 그쪽은 이식본이 원본과 바이트
동일한지(복사가 갈라지지 않는지)를 보고, 여기는 **면이 하나인지**를 본다. 생성에는 이식본이
없기 때문이다 — `gen-lab/server/engines/` 는 새로 쓰는 자리이지 복사가 아니다.
목적은 같고(조용히 갈라지는 것을 막는다) 갈라질 대상만 다르다: 저쪽은 파일 두 벌,
이쪽은 **주소와 문법**이다.

1. 생성 주소를 아는 코드가 `src/generate/` 밖에 없는가
2. `CONNECTION_TARGETS` 의 `generate` · 대상별 포트 충돌 · **연결 저장소의 대비값과
   클라이언트 기본값이 같은가**
3. **손으로 쓴 문법 파일이 저장소에 0건인가** (`*.gbnf`·`*.lark`·`*.ebnf`·`*.bnf`)
4. **계약을 고치면 문법이 따라 바뀌는가** · 못 옮기는 타입에서 던지는가
5. gen-lab 이 계약 사본을 두지 않는가

대조군 3건 — `src/generate/` 밖의 생성 호출 주입 · 계약을 고친 사본에서 문법이 바뀜 ·
옮길 수 없는 타입에서 던짐.

## 검사

`typecheck` · **24종 전부 통과** (기존 22 + 신설 2).
`verify:standalone` **무개정 통과** — 아무도 `src/generate/` 를 import 하지 않으므로

`scenarios/*.json` 무수정 · `verify:scenario` 통과.

### 도중에 잡힌 것 — `verify:no-stt` 가 내 주석을 잡았다

`LlmClient.probe()` 의 주석에 STT 의 전사 경로를 예로 적었더니 `verify:no-stt` 가
「`src/stt/` 밖에서 STT 주소를 안다」로 잡았다. **검사를 느슨하게 하지 않고 주석을 고쳤다** —
문자열은 언젠가 코드가 되고, 그 검사는 정확히 그것을 막으려고 있다.

## 지시서와 다르게 한 곳

1. **문법을 클라이언트가 뽑아 보낸다.** 지시서는 「생성 시점에 변환한다」까지만 적었다.
   서비스가 뽑는 편이 더 강하지만(누가 부르든 강제된다) 지금은 엔진이 없어 Python 쪽
   변환기를 만들어도 **검사할 수단이 없다** — 파이썬이 없는 환경에서 조용히 건너뛰는
   검사가 된다. TypeScript 로 두면 `verify:gen-port` 가 계약을 바꿔 문법이 따라 바뀌는지까지
   본다. 엔진이 붙을 때 서버 쪽 재도출·대조를 더하는 것을 숙제로 적어 두었다.
2. **`probe()` 에 전용 헬스 경로를 두었다.** `SttClient` 는 라우팅을 늘리지 않으려고 같은
   경로에 GET 을 던져 405 를 신호로 쓴다. 생성은 「무엇이 떠 있는가」(스텁인가 엔진인가)를
   화면이 적어야 하므로 405 로는 부족하다 — **목임을 감추지 않는다**가 그 자리를 요구한다.
3. **JSON import 에 `with { type: 'json' }` 를 붙였다.** 계약을 직접 import 하는데 그것 없이는
   Node 가 열지 못해 `verify:no-llm` 이 `LlmClient` 를 못 부른다. typecheck·build 둘 다 통과했고,
   개발 서버가 저장소 루트의 계약을 읽도록 `vite.config.ts` 에 `server.fs.allow: ['..']` 한 줄을 더했다.
4. **`dev-all` 에 gen-lab 을 넣지 않았다** (위 참조).
5. **`utterance.confidence`(§7.8)에 막히지 않았다.** 스텁의 고정 응답은 **저작된 문장**이므로
   대본과 같은 규칙으로 `1` 을 쓴다(`scenarios/types.ts` 의 `ScriptUtterance`). 실제 STT 수치를
   어디에 싣는지는 그 결정이 난 뒤에 정하면 되고, 이번 범위는 발화를 거치지 않으므로
   결정을 앞당길 이유가 없다. 그 사실을 `main.py` 주석에 적어 두었다.
