# 2. 문서와 어긋난 것 — 4건

## 2-1. REQ-1002 무손실 왕복 — 구현 없음, 문서는 "계약 재사용"이라 서술

**문서**: 보고서 `1525`는 "새 그래프 형식을 만들지 않고 기존 `pipeline.schema.json`의 구조를 사용했다"고 적었다.

**코드**: 편집기의 노드 타입은 다음이다.

```ts
type GraphNode = CatalogNode & { id: string; x: number; y: number };
// CatalogNode = { type, label, kind, input, output, executionLocation }
```

계약의 `node`는 `additionalProperties: false`이며 kind별로 `source` / `transform` / `sink` 설정 객체가 **필수**다. 즉 현재 초안은 `pipeline.schema.json` 검증을 통과할 수 없다.

**근거**: `dataSourceRef` · `queryMode` · `query` · `rendererType` · `componentRef` · `fieldRef`가 `web-dashboard/` 전체에 **0건**이다. 계약에서 빌린 것은 `kind` · `executionLocation` · `edges[]` 세 낱말뿐이고, 나머지는 편집기 고유 형식이다.

또한 REQ-1002는 "편집기 고유 정보(노드 좌표 등)는 계약을 오염시키지 않는 별도 영역에 둔다"고 못박는데, `x` · `y`가 노드 객체에 직접 박혀 있다.

**영향**: 백엔드 실물 계약이 오면 "HTTP 어댑터만 교체"로 끝나지 않는다. 초안 자료구조와 직렬화 계층을 다시 만들어야 한다. 지금 문서는 그 비용이 없는 것처럼 읽힌다.

## 2-2. REQ-1003 카탈로그 자동 구성 — 요건의 핵심이 빠짐

**문서**: 보고서 `1525`는 "카탈로그는 목 게이트웨이에서 내려오며 UI에 엔진별 분기나 고정 노드 버튼을 만들지 않았다"고 적었다. UI 측면은 사실이다.

**코드**: `mock-gateway/pipeline-editor.ts`의 `NODE_CATALOG`는 7종을 나열한 **코드 상수 배열**이다.

**요건**: "등록된 디스크립터·렌더러·데이터소스로부터 자동 구성해 제시해야 한다. **개발자가 편집기 코드를 고쳐 노드를 추가하는 일이 없어야 한다.**" 현재는 노드를 늘리려면 게이트웨이 코드를 고쳐야 한다. 위치가 UI에서 서버로 옮겨갔을 뿐 조건은 그대로 깨져 있다.

`contracts/examples/`에 `component-descriptor` · `renderer` · `datasource` 예시가 이미 있는데 카탈로그와 연결돼 있지 않다.

## 2-3. REQ-1007 역방향 관측 — 구현 없음, 문서에도 없음

**요건(Medium)**: "반영된 그래프가 실제로 처리하고 있는 현실 데이터를 편집기 화면에서 확인할 수 있게 해야 한다. 편집기는 구성 도구인 동시에 관측 도구다."

**코드**: 화면이 보여주는 것은 목 시험 실행 결과(`rows` · `elapsed_ms`)와 `active` / `previous` 버전 문자열뿐이다. 반영된 그래프에 흐르는 실제 값을 보는 경로가 없다.

**문제**: 구현현황의 "아직 없는 것 6건"에도, 보고서 `1525`의 "남은 경계"에도 이 요건이 없다. **누락 자체가 문서에서 사라져 있다.** 나머지 셋과 성격이 다르다 — 저건 구현 수준의 문제고, 이건 추적 실패다.

## 2-4. 임무 그래프가 `robot-01`에 고정

**코드**:

```
NodeGraphView.tsx:28   entities.get('robot-01')
NodeGraphView.tsx:19~22  robot-01 · camera-02 · sensor-01 · actuator-01 하드코딩
```

**문제**: `VZ-C-05`의 설계 전제는 장치 20이고, 프로젝트 전체가 "하드웨어에 의존적이지 않은 범용 프레임워크"를 내세운다. 근거 노드 카탈로그가 레지스트리에서 오지 않고 상수라, 장치가 늘면 화면이 따라가지 못한다. 이 한계는 보고서의 "남은 경계"에 없다.

(반면 "연결 편집이 브라우저 세션 초안이라 새로고침하면 기본 연결로 돌아간다"는 `1547`에 정확히 적혀 있다. 이건 문제가 아니다.)
