## 2. 「`?lang=ko` 가 한 글자도 안 바뀌었는가」 — 어떻게 확인했나

**이것이 이 단계 합격 기준의 절반**이라 기계로 확인했다.

착수 커밋(`16dbcbd`)의 소스에서 표시용 한글 **603개**를 뽑고, 각각이 지금 `ko.ts` 에
**글자 그대로** 있는지 대조했다. 자리표시(`${}`→`{n}`)와 강조 표기는 정규화해 비교했다.

**그 대조가 진짜 손실을 하나 잡았다.**

```
착수 전:  BE('BE-T-04', '장치 등록·구역 소속 및 가용성 관리(Birth/Death)')   ← 한 곳
          BE('BE-T-04', '장치 등록·구역 소속 및 가용성 관리')                ← 다른 곳
사전:     'req.BE-T-04': '장치 등록·구역 소속 및 가용성 관리'                ← (Birth/Death) 가 사라졌다
```

요구사항 제목을 `req.<ID>` 로 키를 만들면서 **같은 ID 가 제목이 다른 채로 두 번** 나오는 것을
Map 에 담았고, 뒤엣것이 이겨 괄호가 조용히 없어졌다. **한국어 화면이 그만큼 바뀌었으므로
§4 위반이고, 유일한 위반이다.** 온전한 쪽으로 되돌렸다.

**그리고 검사로 못박았다** — `verify:i18n-demo-path` 가 이제 자리표시 id 중복과
`req.*` 키 존재를 본다. 다음에 같은 일이 나면 사람이 아니라 검사가 잡는다.

나머지 132건은 도구가 거칠어서 나온 것이다 — **조각을 한 문장으로 합친 자리**(§2 ③가
요구한 바로 그것)와 여러 줄 JSX 를 정규식이 잘못 자른 것. 하나씩 눈으로 확인했다.

> **한계를 적어 둔다.** 이 대조는 「사전에 그 글자가 있는가」이지 「화면에 그대로 그려지는가」가
> 아니다. 후자는 브라우저로 봐야 한다 — §6.

> `verify:i18n-demo-path` 가 이제 이것을 파일 단위로 보지만, **파일 안의 두 번째 컴포넌트는
> 아직 못 잡는다** — 파일에 `useLang()` 이 한 번이라도 있으면 통과한다. 5단계에서 조일 자리다.

### ② 모듈 최상위 상수 — **일곱 개**를 함수나 키로 바꿨다

지시서는 시연 경로에 10곳이라 했고 실제로 표를 지운 것이 일곱이다.


## 5. 지시서에 없던 장치 둘

### `src/i18n/RichText.tsx` — 긴 산문을 한 문단씩

도움말은 강조가 문장 안에 잘게 박혀 조각이 **74개**였다. 조각마다 키를 주면 번역가가 문장을
통째로 못 보고 어순도 못 바꾼다 — §2 ③가 금지하는 모양이다.

```
ko: '계획을 만드는 것은 AI지만 **가시화에 …는 백엔드**입니다. 중계 단계(`relay_stage`)는 …'
<p className="help-note"><Rich id="help.approval.p1" /></p>
```

`**…**` → `<b>`, `` `…` `` → `<code>` **두 표기뿐이다.** 마크다운을 넣는 것이 아니고
의존성도 안 늘렸다. 표기가 안 맞으면 그 자리만 글자 그대로 나오고 던지지 않는다 —
번역 한 줄의 오타가 도움말 전체를 못 열게 만들면 안 된다.

조각 74개가 **문단 30개**가 됐다.

### 자리표시 위치로 문장 가르기

`<b>`·`<code>` 가 문장 가운데 하나만 있는 경우엔 `Rich` 까지 갈 것 없다.

```tsx
const readyParts = t('gen.ready', { engine, url }).split('{strong}');
<p>{readyParts[0]}<b>{t('gen.ready.strong')}</b>{readyParts[1]}</p>
```

**`t()` 가 값 없는 자리표시를 그대로 두는 성질**을 쓴다 — 채울 것만 채우고 나머지 자리에서
자른다. 처음에는 NUL 문자를 감시자로 썼는데 **그게 파일을 바이너리로 만들어 `grep` 이 안
먹었다.** 자리표시 자체로 가르는 편이 낫다.

## 8. 지시서와 다르게 한 곳 — 여섯

### ① 범위 밖 파일 **둘**을 건드렸다

범위 목록을 「한글을 품은 파일」로 만들었는데, **자기 한글은 없고 남의 한글을 그려 주기만
하는 파일**이 있었다.

- `views/StatusLegend.tsx` — `STATE_STYLE.label` 을 그린다
- `src/main.tsx` — `shapeLabel()` 결과를 그린다 (`useLang()` 한 줄만 넣었다)

안 건드리면 영문 화면에서 범례와 그래프 머리줄만 한국어로 남는다. `main.tsx` 의 문구 50개는
4단계 몫으로 그대로 뒀다.

### ② `RichText` 를 만들었다 (§5)

### ③ 요구사항 제목 61개를 번역했다

용어집 §3 의 「ID 는 안 바꾼다」에 걸릴까 망설였다. **찾아갈 수 있는 원본은 ID(`HW-C-04`)
쪽이고 제목은 풀이**라 옮겼다 — 영문 화면에 한국어 61줄이 남으면 「시연이 영어로 돈다」가
성립하지 않는다.

### ④ `대기` 를 `Pending` 으로 안 옮겼다

용어집이 `Pending` 을 **자리표시**에 고정해 놨다. 같은 화면에서 태스크가 `Pending` 이고
데이터 칸도 `Pending` 이면 서로 다른 둘이 같은 말이 된다. 태스크 쪽은 **`Waiting`** 이다.
**용어집을 한 줄 정밀하게 만든 것이라 거기에도 적어야 한다.**

### ⑤ `verify:i18n-demo-path` 에 검사 항목을 하나 더 넣었다

§7 은 셋을 적었는데(한글 0 · ko↔en 키 · 대조군) **자리표시 id 중복**을 넷째로 넣었다.
§2 의 손실이 정확히 거기서 났다.

### ⑥ 개발자용 한글 둘을 안 옮겼다

`throw new Error` 는 프로그래밍 실수를 알리는 자리이고 화면에 안 뜬다. 옮기면 사전이 화면
문구와 개발 메시지를 섞어 담게 되고, 4단계 번역 품질 검수에서 무엇을 봐야 하는지가 흐려진다.
