## 2. 발견한 것

### ① 🔴 타입 검사가 못 잡던 자리 — 탐지 수신부의 단언

**증상(예상)** — `frame_ref` 를 정수에서 객체로 바꿨는데 **타입 검사가 통과한다.**
그런데 런타임에는 박스가 안 그려진다.

**원문** — `src/tabs/data/vision.ts`

```ts
else if (envelope.channel === 'detections')
  buffer.pushDetection(envelope.payload as DetectionResult);
```

**원인** — `as` 단언이라 컴파일러가 **아무것도 안 본다.** 타입을 객체로 바꿔도
`envelope.payload` 는 여전히 `unknown` 에서 통째로 단언되므로, 목 게이트웨이가 보내는
정수가 그대로 들어와 `frame_ref.sequenceId` 가 `undefined` 가 된다.

화면에는 **「박스가 안 그려진다」로만 보인다.** 어느 단계에서 어긋났는지 신호가 없다.

**조치** — 단언을 걷고 `normalizeDetection()` 을 입구에 뒀다. 정수와 객체를 둘 다 받고,
모르는 칸은 `null` 로 둔다. 가리키는 프레임을 모르는 탐지는 **버린다** — 모르는 채로
「정합했다」고 그리는 것보다 안 그리는 쪽이 낫다.

검사가 `payload as DetectionResult` 의 재등장을 잡는다.

### ② 서버 탐지가 통째로 드롭되고 있었다

**원문**

```ts
const tier = result.origin?.tier;
if (tier !== 'device' && tier !== 'edge') return;
```

`server` 가 타입·`Map` 키·순회 세 곳에 없어서, 서버 비전이 낸 결과는 **도착해도 버려졌다.**
백엔드가 「나중에 넣으면 계약을 다시 바꿔야 한다」고 짚은 자리가 이것이다.

**조치** — `DETECTION_TIERS = ['device', 'edge', 'server']` 하나로 모으고 세 곳이 그것을 본다.

### ③ `ObservabilityPanel` 이라는 부품이 없다

관문 C-a 판정 수단으로 든 「관측 패널의 봉투 수」가 **화면에 없다.** `envelope_count` 는
`selfObservability` 가 60초마다 `/observability/client-metrics` 로 **POST 할 뿐** 아무 데도
안 그린다. 저장소 전체에 그 이름이 0건이다.

→ 화면 판정을 레지스트리 밖 카드의 「받은 봉투 n건」으로 잡고, **판정 자리가 하나뿐이라는
사실을 정리 문서 §5 에 적었다.** 없는 판정 수단을 있다고 적지 않는다.

### ④ 정리 문서 §4 #8 이 틀렸다

「`bbox_space.format` 기본값 `absolute` → `normalized`, 자리 `vision.ts:46`」이라고 적었는데
**그 줄은 타입 union 이다.** VZ 쪽에는 기본값이 없다 — `bbox_space` 는 발신자가 선언하고
화면은 `normalized`·`absolute` 둘 다 읽는다. 목의 기본값은 `gateway/vision.ts` 의
`bboxFormat` 이고 **좌표계 전환 시나리오가 그걸 쓴다.**

→ **회신 사항으로 옮겼다.** 우리 코드 변경이 아니다.

### ⑤ `VZ-C-07` 은 안 깨져 있었다 — 깨진 것은 낱말이다

백엔드가 *"구독·명령 출구는 여전히 하나다"* 와 소켓 둘이 부딪힌다며 문면 재협상이
필요하다고 했고, 나도 회신에 「고치겠다」고 적었다. **원문을 다시 읽으니 그렇지 않았다.**

> **출입구는 여전히 하나입니다.** 주소만 런타임에 바뀌고, **나가는 길은 그대로 하나**입니다.

근거절이 **「나가는 길」**이고, `/media` 는 제어 메시지가 없으며 우리도 **아무것도 안 보낸다**
(`src/media/` 에 `send()` 0건). 명령 출구는 여전히 하나다.

문제는 **「출입구」라는 낱말**이 들어오는 길과 나가는 길을 한 데 묶어서, 받는 소켓이 하나
느는 것만으로 규칙이 깨진 것처럼 읽힌 것이다.

**조치** — 문면을 「나가는 길은 하나입니다」로 고치고 경위를 같이 적었다.
그리고 **영상 소켓의 수신 전용을 검사로 못 박았다** — 거기서 한 줄이라도 내보내기 시작하면
그때는 규칙이 진짜로 깨지므로 그 순간을 잡는다. 회신도 「재협상할 것이 없다」로 고쳤다.

### ⑥ `verify:gen-port` 가 union 순서를 박아 두고 있었다

```js
if (!/'gateway'\s*\|\s*'stt'\s*\|\s*'generate'/.test(source)) …
```

`ConnectionTargetId` 에 `media` 를 **끼워 넣기만 해도** 깨졌다. 묻는 것은 「`generate` 가
목록에 있는가」이지 「이웃이 누구인가」가 아니다 — union 을 뽑아 원소를 보게 고쳤다.

### ⑦ 장비 id 는 주석에도 못 적는다

`verify:physical-port` 가 새 파일의 **설명 주석**에 적은 로봇 개체 키를 잡았다. 그 검사는
주석을 안 걷는다. 규칙의 뜻(*"로봇을 아는 면이 `src/physical/` 하나"*)을 보면 주석도 안 적는
쪽이 맞다 — 다음 사람이 거기서 값을 복사해 간다.

## 3. 결정한 것

### ① 별도 소켓인가, 전송 계층 확장인가 — **별도 소켓**

인계문서는 `WsTransport` 에 4단계를 넣으라고 적었다. 그런데 두 소켓은 말이 다르다:

```
게이트웨이   {type:'subscribe', selector} · {channel, topic, key, message}
/media       제어 메시지 없음 — 붙는 것이 켜기, 끊는 것이 끄기
```

구독 규약을 안 쓰는 연결을 그 클래스에 얹으면 `subscribe()`·`subs` 복원·`sendSubscribe` 가
**그 연결에는 뜻이 없는 분기**로 남는다. `src/capability/`·`src/detect/` 와 같은 경계 모양으로
갔고 `verify:media-port` 가 그 경계를 지킨다.

전송 계층에는 **백엔드가 명시적으로 부탁한 카운터만** 넣었다 — 그쪽은 「게이트웨이가 JSON
아닌 것을 보냈다」는 다른 신호다.

### ② 영상 칸의 자리 — **대상 상태 오버레이** (사용자 지적)

처음엔 마일스톤 오른쪽 기둥에 상설 판으로 뒀다. **과했다** — 영상은 늘 보는 값이 아니라
한 장비의 카메라에 딸린 것이고, 기둥을 셋으로 나누면 하드웨어·기능이 좁아진다.

근거가 두 개 있었다. `DeviceStatusOverlay` 머리말이 *"카메라 연결 상태는 … **그 칸도
자리표시 대신 없앴다**"* 라고 적어 뒀다 — **줄 값이 없어서 뺀 자리**이고 이제 생겼다.
그리고 백엔드도 §8 에서 카메라 상태를 「VZ-D-07 대상 상태 조회의 한 칸」이라고 했다.

**뷰 노드는 축이 다르다** — 뷰 노드는 태스크에 붙어 범위가 정해지는데(`VZ-N-02`) 영상은
태스크가 아니라 카메라에 붙는다. `verify:view-nodes` 의 참조 계수 규칙도 목의
`video_frame`(도형) 축이라 한 부품에 두 축이 섞인다.

**열면 붙는다**(「패널 열 때 붙으면 온디맨드」 — 백엔드 표현). 한 번 더 누르게 하면
관문 B 에서 「왜 안 나오지」의 첫 원인이 그 버튼이 된다.

### ③ `alignment` 부재를 어떻게 볼 것인가 — **옛 계약**

통지의 fail-safe 는 *"부재·모르는 값 포함 전부 unaligned"* 다. 그대로 하면 **목 게이트웨이의
정합 시연이 통째로 죽는다** — `alignment` 를 안 보내기 때문이다.

```
alignment === 'frame'   정합
그 밖의 값이 실려 옴     정합 안 함 — 토글이 켜져 있어도
부재                     옛 계약 — 토글이 정한다
```

새 계약이 오면 `alignment` 가 실려 오므로 그때부터는 통지 규칙 그대로다. **회신에서 되물었다.**

그리고 정합하지 **않았다는 사실이 보고서와 화면에 남는다**(`aligned`·`declaredAlignment`).
안 적으면 정합 안 된 박스가 정합된 것처럼 보인다.

### ④ 버퍼 키가 쌍인데 옛 프레임엔 소스가 없다 — **양쪽 다 알 때만 대조**

키는 `(source_id, sequence_id)` 다. 그런데 목의 프레임에는 `source_id` 가 없다(그 세계는
카메라가 하나였다). 한쪽만 알 때 **억지로 안 맞다고 하면 목 시연이 죽는다.**

→ 둘 다 알 때만 대조하고, 한쪽이라도 모르면 순번으로 짚는다. 검사가 세 경우를 다 본다.

### ⑤ 영상 소켓 칸을 셋으로 나눈 이유

인계문서 §7 은 「주소를 통째로 화면에서 받으므로 코드 변경 0」이라고 적었다. 그 말대로 한
칸으로 받으면 **카메라를 바꿀 때마다 토큰을 다시 붙여 넣어야** 하고, 그러다 토큰이 화면 밖
어딘가에 복사되어 남는다. 주소·카메라 키·토큰 셋으로 갈랐다.

검사가 **토큰처럼 생긴 상수**가 소스에 박히는 것을 잡는다.
