## 3. STT — 원인은 STT가 아니었다

### 어디서 잡혔나 — **진단 순서 1번**

지시서가 「답이 여기 있을 확률이 가장 높다」고 한 `npm run dev` 콘솔의 첫 줄에서 잡혔다.

```
[mock-gateway] 기동 실패 — 포트 8790 이 이미 사용 중이다.
[exited with code 1]
```

포트를 실제로 뒤져 보니 **이전 세션이 통째로 살아 있었다.**

```
port 8790 held by pid 25100   (목 게이트웨이)
port 5174 held by pid 10436   (vite)
```

`dev-all.mjs` 는 필수 프로세스(게이트웨이·vite) 하나가 죽으면 `stop()` 으로 전부 내린다 —
**STT 도 함께.** 그래서 이런 일이 벌어졌다.

1. 이전 세션의 게이트웨이·vite 가 8790·5174 를 잡은 채 살아 있다
2. 새 `npm run dev` 는 게이트웨이 바인딩에 실패해 **즉시 종료**하고, 그러면서 **자기가 띄운
   STT 까지 같이 내린다**
3. 그런데 브라우저는 **옛 세션**의 vite·게이트웨이에 그대로 붙어 있다 — 화면도 뜨고
   상단도 「게이트웨이 연결됨」이다
4. 없어진 것이 STT 하나뿐이라, 증상이 **「STT 서비스에 닿지 않습니다」 한 줄**로만 보인다

포트를 정리하고 다시 띄우니 세 줄이 다 떴다.

```
[mock-gateway] 기동 — WS ws://127.0.0.1:8790 …
  VITE v6.4.3  ready in 385 ms   ➜  Local: http://localhost:5174/
INFO:     Uvicorn running on http://127.0.0.1:8801 (Press CTRL+C to quit)
```

서비스 자체는 멀쩡했다 — `GET /stt/transcribe` 가 **405** 를 돌려주고
`access-control-allow-origin: http://localhost:5174` 도 정상으로 실려 왔다.
지시서가 배제해 둔 항목들(가상환경·registry 경로·CORS 목록·strictPort·엔진 임포트·이식본
무결성)은 전부 그대로 유효했고, 4번(포트 점유)도 **STT 포트 8801 은 비어 있었다** —
점유된 것은 8790·5174 였다.

### 고친 것 셋

**① `probe()` 가 사유를 버리지 않는다.**

```ts
export type SttProbe = { alive: boolean; reason: string | null };
```

브라우저의 `fetch` 는 「서비스가 없다」와 「서비스는 있는데 CORS 로 막혔다」를 **똑같은
`TypeError: Failed to fetch`** 로 던진다 — 지시서 3번이 「증상이 같아 지금은 구별할 수 없다」고
지적한 그것이다. 실패 경로에서만 `mode: 'no-cors'` 로 **한 번 더** 던져 가른다: 프로세스가
살아 있으면 불투명(opaque) 응답이라도 돌아오고, 꺼져 있으면 여기서도 실패한다.

| 상황 | 화면에 뜨는 문장 |
|---|---|
| 프로세스 없음 | `서비스가 떠 있지 않습니다 (http://127.0.0.1:8801) — npm run dev:stt 로 따로 띄워 사유를 보세요. 원문: TypeError: Failed to fetch` |
| 살아 있는데 CORS 거부 | `서비스는 떠 있는데 브라우저가 막았습니다 (http://127.0.0.1:8801) — stt/service.py 의 ALLOWED_ORIGINS 에 이 페이지 주소가 있는지 확인하세요.` |
| 그 외 | 원문 그대로 |

`capabilities()` 의 계약은 **바꾸지 않았다.** 셋째 인자 `detail` 이 늘었지만 그 값은
`note` 에만 실리고 `manualInput`·`canRecord`·`canTranscribe` 판단에는 **닿지 않는다** —
`verify:no-stt` 가 그것을 새로 검사한다(사유를 넘겼을 때 수동 입력이 잠기거나 음성 판단이
바뀌면 실패).

**② `dev-all.mjs` 가 왜 죽는지 마지막에 적는다.** 위쪽 로그는 vite 출력에 묻힌다.

```
[dev] 필수 프로세스가 코드 1 로 종료됐다 — 개발 스택 전체를 내린다.
[dev] **STT 서비스도 함께 내려간다.** 화면에 「STT 서비스에 닿지 않습니다」만 보이더라도
[dev] 원인은 STT 가 아니라 위 로그의 종료 사유다. 포트가 이미 사용 중이라면
[dev] 이전 세션이 살아 있는 것이고, 그때 브라우저는 옛 세션에 붙어 있어 화면은 멀쩡해 보인다.
[dev]   Get-NetTCPConnection -LocalPort 8790,5174,8801 -State Listen |
[dev]     ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
```

포트를 일부러 점유해 이 경로를 재현하고 문구가 실제로 뜨는 것까지 확인했다.

**③ `stt/README.md` 에 「먼저 볼 것」 절을 더했다** — 원인이 환경 준비 쪽이므로 지시서가
지시한 자리다. 정리 명령과 「정상이면 뜨는 세 줄」을 함께 적었다.

`stt/engines/*.py` 는 **한 글자도 고치지 않았다** (`verify:stt-port` 통과).
`stt/service.py` 도 고칠 것이 없었다.

## 1. 노드 그래프 → 마일스톤 되돌아가기

머리줄 맨 위에 **이동 경로**를 뒀다.

```
마일스톤  ›  MS-C 위험 수위 도달 시 닫기  ›  T-43c close_gate 발행
└ onBack()                     └ onGraph()          └ 지금 자리(글자)
```

- **맨 앞 「마일스톤」은 항상 있고 항상 눌린다** — 사용자가 요구한 되돌아가기가 이것이다.
- 가운데 칸은 지금 보고 있는 마일스톤. **범위가 「임무 전체」면 `임무 전체 N노드`** 로 적는다.
  액션 팝업이 열려 있을 때만 눌리는 칸이 되고(그래프로 돌아간다), 아니면 현재 자리 표시다.
- 마지막 칸은 **액션 아이템 팝업이 열려 있을 때만** 나온다(`openTask` 프롭).
- `replay`·`failure` 화면도 같은 `GraphScreen` 이라 함께 풀렸다 — 그 둘도 똑같이 갇혀 있었다.

**`navigate()` 헬퍼를 쓴다** — 그것이 `modalTask` 정리까지 함께 한다. 직접 `setScreen` 을
부르면 팝업 상태가 남는다. 「마일스톤」 칸은 `setScope('milestone')` 도 함께 되돌린다.

상단 공통 바의 임무 이름 버튼은 **그대로 뒀다** — 지금 동작하는 유일한 길이고 단독
빌드(전달본)에서도 같은 자리다. 전달본 화면은 **머리줄에 한 줄이 느는 것뿐**이다.

## 2. 「임무 전체」 그래프가 화면 밖으로 나가던 것

### 접기 배치(band wrap)

`dagLayout(tasks, availableWidth)` · `treeLayout(tasks, availableWidth)` 로 서명을 바꾸고,
`TaskGraph` 가 `ResizeObserver` 로 **자기 자리의 실제 폭을 잰다**(못 쟀을 때 대비값 1,120px —
옛 `.graph-canvas` 의 `min-width` 와 같은 값이라 첫 프레임 배치가 예전과 같다).

```
perBand = max(MIN_COLS=3, floor((폭 - 30) / 220))
band    = floor(깊이 / perBand)      col = 깊이 % perBand
x       = 30 + col * 220
y       = 밴드 시작 + row * 150      (밴드 시작은 앞 밴드들의 실제 높이 누적)
```

**밴드 높이는 그 밴드에서 가장 높은 열의 노드 수로 정한다.** 상수로 두면 1편 MS-D 처럼 한
열에 노드가 셋인 밴드가 다음 밴드와 겹친다 — `verify:layout` 이 상자 겹침으로 잡는다.

### 세 편이 실제로 몇 밴드 × 몇 열이 됐나

| 자리 폭 | 한 밴드 | `MSN-260831-01` (17노드·깊이 14) | `MSN-260831-02` (18노드·깊이 14) | `MSN-260831-03` (16노드·깊이 15) |
|---|---|---|---|---|
| **1,088 px** (창 1180px · 최소) | 4열 | 4밴드 × 4열 · 870 × 1,125 px | 4밴드 × 4열 · 870 × 975 px | 4밴드 × 4열 · 870 × 825 px |
| **1,828 px** (창 1920px) | 8열 | 2밴드 × 8열 · 1,750 × 685 px | 2밴드 × 8열 · 1,750 × 535 px | 2밴드 × 8열 · 1,750 × 385 px |

접기 전에는 1편 3,330 · 2편 3,290 · 3편 3,550 px 였다. 이제 **어느 폭에서도 자리 안에 든다.**

`.graph-canvas` 의 `min-width:1120px` 을 없애고 바깥에 `.graph-scroll{overflow-x:auto}` 를 뒀다.
접힌 배치는 잰 폭 안에 들어오므로 평소에는 가로 스크롤 막대가 **생기지 않는다** — 사용자가
노드를 오른쪽으로 끌었거나 창이 `MIN_COLS`(3열 ≈ 650px) 아래로 좁아져 접기를 포기한 경우에만
나온다(한 열짜리로 접으면 세로가 터무니없이 길어져 접기가 더 나쁘다).

드래그 경계도 **새 폭**을 쓴다(`Math.min(width - NODE_WIDTH, …)` 의 `width` 가 잰 폭 기준).
`NODE_WIDTH`·`NODE_HEIGHT` 를 `layout.ts` 로 옮겨 화면·배치·검사가 **같은 값 하나**를 본다.

### 밴드를 넘는 엣지 — `↵` 실선 파랑

두 가지 중 「아래로 크게 도는 곡선」을 골랐다. 오른쪽으로 빠져나가 **밴드 사이 통로**로
내려온 뒤 왼쪽으로 달려 다음 밴드의 왼쪽으로 들어간다.

| | 모양 | 색 | 표시 |
|---|---|---|---|
| **줄바꿈** (밴드 넘김) | **실선** | **파랑 `#1768c5`** | `↵ 줄바꿈` |
| 되돌아감 (참조 엣지) | 점선 `7 5` | 주황 `#b9862d` | `↺ {label}` |

선 종류·색·글자 셋이 다 다르다. 하나는 「줄바꿈」이고 하나는 「루프」다.

판정은 **기준 배치**로 한다 — 사용자가 노드를 끌었다고 선 모양이 바뀌면 안 되기 때문이다.
`deps` 는 낮은 깊이 → 높은 깊이라 한 밴드 안에서는 늘 오른쪽으로 가므로, **왼쪽·아래로
가는 것이 곧 줄바꿈**이다.

### 사용자가 옮긴 위치

`useEffect(() => setMovedPositions({}), [layoutMode])` 의 의존 배열에 **`layoutWidth` 를 넣지
않았다** — 창 크기가 바뀌면 기준 배치만 다시 계산되고 옮긴 노드는 그대로다.

## 지시서와 다르게 한 곳

### 1. `dev-all.mjs` 를 손댔다

지시서 3번은 「`probe()` 사유 표시」와 「원인 진단」만 요구했고 `dev-all.mjs` 는 언급하지
않았다. 그런데 **원인이 바로 그 파일의 조용한 동작**이었다 — 게이트웨이가 죽으면서 STT 를
같이 내리는데 그 사실이 어디에도 안 적혔고, 브라우저는 옛 세션에 붙어 있어 화면이 멀쩡해
보였다. 사유를 마지막에 한 번 더 적는 것이 「다음에 또 막혔을 때 진단이 몇 초로 줄어든다」는
지시서 3번의 목적에 가장 직접적이라 판단해 넣었다. **동작은 바꾸지 않았다** — 종료 시
정리하는 순서와 종료 코드는 그대로이고, 늘어난 것은 `console.error` 다섯 줄뿐이다.

### 2. `NODE_WIDTH`·`NODE_HEIGHT` 를 `layout.ts` 로 옮겼다

지시서에 없지만 필요했다. 「폭 안에 들어왔는가」는 노드 **오른쪽 끝**으로 재야 하는데, 그
값이 `TaskGraph.tsx` 안의 지역 상수라 `verify:layout` 이 볼 수 없었다. 손으로 베껴 적으면
세 곳(화면·배치·검사)이 갈라진다.

### 3. 이동 경로의 가운데 칸은 팝업이 열렸을 때만 눌린다

지시서의 그림은 가운데 칸에 「누르면 이 마일스톤의 그래프」를 달아 두었다. 그래프 화면에서는
그 칸이 **이미 보고 있는 자리**라 눌러도 아무 일이 없다 — 눌리는 것처럼 보이면 거짓말이 된다.
그래서 액션 팝업이 열려 있을 때만 버튼이고, 그 밖에는 현재 자리 표시(굵은 글자)다.
