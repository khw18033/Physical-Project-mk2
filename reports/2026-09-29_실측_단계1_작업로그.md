## 단계 1-d — 엣지 입구 8766 (2026-09-22)

### 1 문서와 다르게 한 것

**① `.env` 를 한 줄이 아니라 두 줄 고쳤다**

### 2 발견한 것

**① 8766 을 열어도 relay 12건이 풀리지 않는 구멍 — 문서·스냅샷이 그 자리에서 틀렸다**

- **증상 예측:** 스냅샷과 앞 로그가 *"8766 을 열면 skip 12 가 줄어든다"* 로 적어 두었다. 코드를 열어 보니 안 줄어든다.
- **실측 원문(파일·줄 그대로):**

  ```

                            """엣지 입구 바인딩(단일 주소). 단계 2 = loopback, 단계 7 = <서버 tailscale IP>."""
  backend/settings.py:265   base = os.environ.get("MK2_MEDIA_INGEST_URL") or "ws://127.0.0.1:{}/ingest".format(...)

  ```
  단계 8 되돌림 기록의 skip 사유도 그대로다 — *"엣지 입구(8766)에 닿지 않는다 … **(127.0.0.1:8766)**"*.

  바인딩되고, 시험은 `media_ingest_url()` 기본값인 **`127.0.0.1:8766`** 으로 붙는다 → 계속 거부 → 계속 skip.
  **8765 는 `MK2_WS_HOST` 가 주소 둘을 받아 loopback 으로도 붙지만, 8766 은 코드가 단일 주소만 받는다.**
- **조치:** `.env` 에 `MK2_MEDIA_INGEST_URL=ws://<서버 tailnet 주소>:8766/ingest` 를 한 줄 넣었다.
  `media_ingest_url()` 이 그 값을 **쿼리 없는 base** 로 받아 `source_id`·토큰을 뒤에 붙이는 구조라 모양이 맞다.
- **결과:** **`326 passed in 255.76s` — skipped 0.** 314 + 12 = 326, 기대값과 정확히 일치.
  **relay 12건이 실제로 돌아 전부 통과했다.** 115s → 256s 는 실소켓·타이밍 시험 12건이 붙은 값이다.

  **다른 설정**이고, 단일 주소 바인딩에서는 loopback 이 자동으로 따라오지 않는다.
  한 줄만 고쳤으면 12건은 계속 skip 이고 8766 관통은 단계 2 에서야 처음 봤을 것이다.

## 단계 1-e — 브라우저 관측 입구 4318 (2026-09-29)

**v2.3 에서 신설된 갈래다**(v2.2 에는 없었다 — 09-21 VZ 회신으로 정해졌다). **관측 입구라 관문 B·C-a 와 무관하다.**

근거는 `docs/be/vz-media-interface.md` 에서 열어 확인했다 —
`:513` *"origin 은 넷을 다 열겠다 — 두 기기 × `:5174`(통합 빌드)·`:5175`(단독 빌드)"* ·
`:514` *"http 그대로 + ufw `/32`"* · `:508` *"exporter 는 JSON"* ·
`:500-506` *"사이드카 `vz-stt`·`vz-gen` 도 셋 다 `4318`"*(결정 ④) ·
`:678` *"관제 웹 origin 문자열 — 필요 없다. 기기 주소를 받았으므로 origin 넷이 자동으로 정해진다"*.

### 1 문서와 다르게 한 것

**① CORS origin 을 넷이 아니라 여덟 넣었다**

- v2.3 과 VZ 회신은 **넷**(두 기기 × `:5174`·`:5175`)이다. `localhost`·`127.0.0.1` 판 넷을 더했다.
- **이유:** origin 은 **VZ 가 브라우저 주소창에 친 URL 이 정한다.** 자기 노트북에서
  `http://localhost:5174` 로 열면 Origin 은 `http://localhost:5174` 이고 tailnet 주소 넷이 다 안 맞는다.
  그러면 preflight 가 막히고 증상은 **「연결은 되는데 지표만 안 옴」**이라 진단이 나쁘다.
  `:678` 의 *"기기 주소를 받았으므로 origin 넷이 자동으로 정해진다"* 는 **우리 추론이고 VZ 가 한 말이 아니다.**
- **노출은 넓어지지 않는다.** 4318 의 도달 통제는 **compose 발행 바인딩 + ufw `/32`** 라
  다른 기계 브라우저는 애초에 4318 에 닿지 못한다. CORS 목록은 그 두 기기가 **어느 URL 로 열었든**
  통과시키는 역할만 한다.

**② v2.3 의 「tailnet 주소에 바인딩」이 컨테이너에는 성립하지 않는다 — 문서가 부정확하다**

- v2.3 단계 1-e 는 *"Collector `otlp/http` receiver 를 **서버 tailnet 주소에만** 바인딩"* 이라고 적었다.
- **컨테이너는 호스트의 tailnet 주소에 바인딩할 수 없다.** 안에서는 `0.0.0.0:4318` 이 맞고(gRPC 4317 과 같은 이유),
  실제 통제는 **compose 발행 `<서버 tailnet 주소>:4318:4318`** 이다. 같은 문서가 다른 칸에서는
  *"도커 발행 포트라 실제 통제는 바인딩 주소다"* 로 맞게 적어 두었다 — **두 문장이 갈려 있다.**
- 설정 파일에 그 이유를 주석으로 박았다.

### 2 발견한 것

**① 내가 md5 교차 검증을 틀리게 안내했다 (내 잘못. 서버·파일 결함 아님)**

- **증상:** 서버 편집본이 `collector 7a35997d…` · `compose cfed1a72…` 로 나왔는데, 내가 예고한 값은
  `42d5f5f5…` · `0553d6e6…` 였다.
- **원인:** PC 에서 만든 편집본과 **채팅에 붙여 넣은 서버 스크립트의 주석 특수문자가 다르다**
  (`§`→없음 · `④`→`4` · `⚠`→`주의:` · `×`→`x`). 붙여넣기 안전을 위해 내가 바꿨는데,
  그걸 감안하지 않고 *"바이트 동일해야 한다"* 고 적었다. compose 는 그 차이 하나만 되돌리니
  재현 md5 가 **서버 값과 정확히 일치**했다 — 차이가 주석뿐이라는 증거다.
- **조치:** md5 대조를 버리고 **기능 줄 전수 대조**로 닫았다(`grep -nE "endpoint:|allowed_origins|allowed_headers|max_age|http:|grpc:"`).
  `grpc 0.0.0.0:4317` · `http 0.0.0.0:4318` · origin 8 · headers 4 · `max_age 7200` · exporter 셋 — 의도와 일치.
- **남길 것:** 🔴 **붙여넣기용으로 문자를 바꾸면 md5 대조가 깨진다.** 둘 중 하나로 한다 —
  ⓐ 서버에 줄 스크립트를 **그대로** PC 에서도 돌려 md5 를 뜬다, ⓑ 대조를 **기능 줄**로 한다.
  섞으면 이번처럼 「달라졌다」가 결함인지 주석인지 모른다.

**② `state`·`status` 와 무관한 발견 — TSDB 기준선이 움직였다**

relay 12건이 실제로 돌면서 발행이 생겼다. **2,381행 → 2,864행**(state 1,561 / heartbeat 767 / status 536).
차이 483행(state +413 · heartbeat +21 · status +49)이 회귀 발행분이다.
**단계 2 의 차분은 2,864 를 기준선으로 본다.**

⚠ TSDB 는 MySQL 과 달리 `docker exec` 로 붙는다 — 계정이 `postgres` 수퍼유저이고 컨테이너 안 소켓을 쓴다.
`mk2_app@'172.18.%'` 제약은 MySQL 쪽 이야기다.
(처음에 `backend/storage/writer.py::TsdbWriter` 로 조회하는 명령을 냈는데 **그 클래스가 없다** —
`writer.py` 에는 `TelemetryWriter`·`TimescaleTelemetryWriter` 가 있고 TSDB 구현은 `tsdb_writer.py` 다. 돌리기 전에 잡았다.)

## 규율 추가 — 규율 0-b: 읽은 뒤에도 다시 연다 (2026-09-29)

> 🔴 **이름 주의 — 이것은 이 파일 안의 이름이다.** `CLAUDE.md` §1-A 의 규율 번호는 **1~8** 이고

> `docs/be/hw-envelope-conformance.md` **§10-5** 가 남긴 한 줄 —
> *"인용할 문서는 그 자리에서 연다 — 우리가 쓴 문서일수록 더"* — 이고, 이 파일 머리말이 그것을

### 왜 0-b 인가 — 규율 0 이 막지 못한 자리

규율 0 은 **읽는 것**을 강제한다. 그런데 이 방에서 반복된 실수는 **읽은 뒤**에 났다.
전문을 읽어도 답할 때 보는 것은 **읽으면서 만든 압축**이고, 그 압축은 읽던 시점에 중요해 보인 것만
남긴다. 한 번 굳은 요약은 다음에 원문보다 먼저 떠오른다. 규율 0 은 「열어라」이고
**「판단하는 순간에 다시 열어라」가 아니다.** 0-b 는 그 자리를 방아쇠로 막는다.
