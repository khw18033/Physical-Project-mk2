## 1. 0절 확인 결과

### 엣지 렌더러는 꺾인 경로를 그릴 수 있다 — 그런데 그것으로는 안 됐다

**꺾인 경로는 된다.** `TaskGraph.tsx` 의 엣지는 경로 문자열을 받아 그리고, `wrapPath()` 가
이미 `L` 직선 구간을 쓴 엘보를 그리고 있었다. 렌더러의 한계가 아니었다.

**그런데 목표 모양이 안 나온다.** 엣지는 `task.deps` 의 **노드쌍마다 하나씩** 그려지는데,
1절이 요구한 것은 여덟이 **공유하는** spine 하나다. 쌍마다 엘보를 그리면 세로 구간 여덟이
같은 x 에 포개져 한 줄처럼 보일 뿐 실제로는 여덟 겹이고, 「화살표끼리 겹치지 않는다」를
통과했다고 말할 수 없다.

**그래서 분기선을 직접 그렸다.** 다만 배경 레이어를 새로 만들지는 않았다 — 이 파일에는
이미 흐름·되돌아감(`↺`)·줄바꿈(`↵`)·소속 네 종류의 선이 각자 경로 함수를 갖고 공존하는
구조가 있어서, **다섯째 종류**로 넣는 것이 새 레이어를 올리는 것보다 결이 맞았다.
엣지 렌더러 자체는 고치지 않았고, 여덟 쌍만 기본 경로에서 건너뛰게 했다.

```
{fan !== null && (
  <g className="edge--fan">
    <path className="edge edge--fan-trunk" .../>   부모 오른쪽 → spine (화살촉 없음)
    <path className="edge edge--fan-spine" .../>   세로 spine
    {fan.arrows.map(...)}                          가로 화살표 여덟 (화살촉 있음)
  </g>
)}
```

| 값 | 전 | 후 |

| 여덟의 세로 전체 | 1,200px | **472px** |

카드에서 **id 줄·장비 줄·실행 상태 줄을 뺐다.** id(`T-A4-3`)가 말하는 것을 제목

뷰포인트 상태와 축이 달라 한 카드에 두 축이 섞인다. 빼지 않으면 52px 에서 판정 글자가
잘린다 — **첫 캡처에서 실제로 잘렸다.**

실측: 여덟의 아래끝이 527px 로 기준 높이 560px 안에 든다. 실제 화면에서 캔버스 673px,

## 3. 미선정과 선정에 쓴 값 넷

`style.css` 의 `:root` 한 블록에 있다.

| | 채움 | 테두리 | 글자 | 불투명도 |
|---|---|---|---|---|
| 대기 `pending` | 없음 | 1px 점선 `#cfd6df` | `#9aa5b3` · 400 | 0.5 |
| 탐색 중 `scanning` | 없음 | 2px `#4a8fd4` + 점멸 | `#2f6ba8` · 600 | 1 |
| **미선정 `rejected`** | `#f4f5f6` | **1px** `#dfe3e8` | `#a8b0ba` · **400** | **0.42** |
| **선정 `selected`** | `#d8f0e2` | **3px** `#1f8a4d` | `#125c33` · **700** | **1** |

미선정에는 `filter: saturate(0)` 을 더해 채도를 완전히 죽였다. 선정에는 그림자를 한 겹
얹었다(`0 0 0 4px` 초록 후광 + 아래 그림자). **깜빡이지는 않는다** — `scanning` 이 점멸이라
둘이 섞이면 무슨 상태인지 못 읽는다.

색만으로 구분하지 않는 것이 2절의 요점이라, 넷을 같이 움직였다. 테두리 굵기는 1px 대 3px
로 세 배, 불투명도는 0.42 대 1.0 으로 두 배 넘게 벌렸다. 글자도 400 대 700 이다.
프로젝터에서 초록과 회색이 둘 다 밝은 회색으로 보여도 **굵기와 흐림으로 구분된다.**

판정 글자도 남긴다 — 미선정은 「문 없음」, 선정은 「문 있음 · 93%」. 색이 다 죽어도 이
글자가 마지막 근거다.

## 5. 지시서와 다르게 한 곳

### 상태를 쪼개면서 `fill.ts` 를 건드렸다

3절이 「상태 갱신 로직은 손대지 마라」인데 2절은 「판정 완료를 둘로 쪼개라」다. 2절이 더
구체적이라 그쪽을 따랐다. 건드린 것은 **도착한 값에서 이름을 정하는 자리**까지다.

```
applyDetection: phase = frame.door ? 'selected' : 'rejected'
```

프레임이 `rotation_index` 로 노드를 찾는 규칙, 사건 형식, `atSec` 축, 대본 파일은 손대지
않았다. `verify:viewpoint-fill` 의 뒤섞기 50회와 「대본 입구·라이브 입구가 같은 프레임」
검사가 그대로 통과한다.

### 배치 엔진에 여덟 대신 대표 하나를 넘긴다

지시서에 없는 조치다. **첫 캡처에서 드러난 문제를 고친 것이다.**

여덟을 다 넘기면 `dagLayout` 이 그 열을 `ROW`(150) × 8 = **1,200px** 로 본다. 실제 화면은
472px 인데 엔진은 모른다. 그래서 세로가 모자란다고 판단해 밴드를 더 접고, 판단·근거
노드가 아래 밴드로 내려가 **캔버스가 1,688px** 이 됐다.

`TaskGraph` 가 여덟 중 **다른 태스크가 의존하는 것만**(`T-A4-2`) 엔진에 넘기고, 나머지
일곱의 자리는 특례가 대표의 열에 세운다. 엔진은 그 열을 노드 하나짜리로 알면 된다.
캔버스가 1,688px → **673px** 이 됐다.

배치 엔진은 한 줄도 고치지 않았다. 고친 것은 **무엇을 넘기는가**다.

### 판단·근거 노드가 둘째 밴드에 있다

`T-A5`·`T-A6` 가 줄바꿈 엣지(`↵`)를 타고 아래 밴드에 놓인다. 실제 잰 폭이 1,346px 이고
깊이 열이 여섯이라 엔진의 폭 상한 계산에 걸린다.

**고치지 않았다.** 그 판단은 엔진의 것이고, 고치면 뷰포인트가 아닌 노드의 배치가 움직인다
— 3절이 금지한 자리다. 여덟·부모·판단·근거가 **스크롤 없이 한 화면에 다 보이므로** 1절의
요건은 충족한다. 다만 줄바꿈 선이 뷰포인트 열 근처를 지나 보기 좋지는 않다. 2단계에서
엔진의 폭 상한을 볼 때 같이 보는 것이 맞다.

## 6. 검사가 못 잡고 캡처가 잡은 것 둘

기록해 둘 값어치가 있다. **좌표 검사를 통과했는데 화면이 틀렸다.**

1. **판정 글자가 잘렸다.** 52px 카드에 id 줄까지 들어가 「문 있음 · 93%」의 아랫부분이
   잘려 나갔다. 좌표 검사는 상자 위치만 보므로 안쪽 글자가 넘치는 것을 모른다.
2. **캔버스가 1,688px 이었다.** 여덟 자체는 527px 안에 들어 검사를 통과했는데, 엔진이
   밴드를 접어 전체가 두 배 넘게 길어졌다. 검사가 여덟만 보고 **화면 전체를 안 봤다.**

둘 다 고쳤고, 2번은 `verify:viewpoint-layout` 에 검사를 새로 넣었다 — `TaskGraph` 와 같은
규칙으로 태스크를 줄여 MS-A 전체 높이를 재고, 「여덟을 다 넘긴 사본」이 더 길어지는 것을
대조군으로 확인한다. 1번은 검사로 못 잡는다(글꼴 렌더링이 필요하다). **캡처가 그 검사다.**

9/9 에 원형이 깨진 것도 같은 자리였다 — `verify:layout` 이 상자 겹침만 쟀고 겹친 것은
화살표였다. 이번에 화살표 구간을 좌표로 재는 검사를 넣었다.

## 8. 후속 — 「연결됐는데 색이 같다」 (같은 날 지적)

**증상**: 90도 노드에서 판단 노드로 선이 나가 있는데 카드 색은 다른 일곱과 똑같다.

**확인한 것**: 재생이 끝난 뒤에는 **정상이다.** 단독 빌드와 통합 빌드 둘 다에서 일곱
미선정 · 하나 선정으로 나온다(게이트웨이를 띄우고 승인까지 몰아 확인). 증상이 나오는
것은 **탐지가 도착하기 전** 화면이다 — 승인 전, 또는 게이트웨이가 없어 사건이 안 오는 때.

**진단**: 색이 같은 것이 맞았고 **선이 틀렸다.** 여덟이 다 대기인데 90도에서만 굵은 선이
나가면, 화면이 「이게 답이다」를 탐지보다 먼저 말하는 셈이다. 260909 §4 의 「승인 즉시
여덟이 다 보이되 전부 대기」와 화면이 어긋나 있었다.

**고친 것 둘**

| | |
|---|---|
| 판정 전 나가는 선 | 흐린 점선(`.edge--unjudged`, 불투명도 0.28). 탐지가 오면 선명해진다 |
| 대기 상태의 글자 | 「대기」를 적는다. 낮은 카드에서 실행 상태 줄을 숨기면서 여덟만 아무 말이 없어져 「고장났다」로 읽혔다 — 내가 만든 회귀다 |

캡처 둘을 남겼다. `_대기.png` 가 탐지 전, `.png` 가 탐지 후다.

**선택지였던 다른 길**: 90도 노드를 미리 강조하는 방법도 있었지만 **하지 않았다.** 그러면
로봇이 보기도 전에 화면이 답을 아는 것이 되고, 「근거가 도달해야 통과」라는 이 저장소의
규칙과 정면으로 부딪힌다. 시연에서 「돌면서 하나씩 찾는다」는 이야기도 사라진다.
