# 추가 개선 2단계 — 하드웨어 카드 더블클릭 → 대상 상태

**지시서**: `작업프롬프트_추가개선_260904.md` §2
**대상 요구사항**: `VZ-D-07`(대상 배정과 **대상 상태 조회**) — **요구사항 신설 없음**
**기준 커밋**: `4308ce0` (추가 개선 1단계)

---

## 무엇이 문제였나

하드웨어 카드는 **드래그로 배정만** 됐다. 눌러도 아무 일이 없었다. `VZ-D-07` 은 「대상 배정과
대상 상태 조회」인데 뒷절이 화면에 없었다. 새 기능이 아니라 **미구현분**이다.

## 무엇을 했나

### 카드 더블클릭 → 오버레이

`하드웨어` 패널의 카드(옛 편의 실측 목록도, 대본 세계의 등장 장비도) 양쪽 다 더블클릭하면
그 대상의 상태가 열린다. 패널 안내줄에 **「더블클릭 → 대상 상태」**를 적었다 — 발견할 수 없는
길은 없는 길이다(260901 결정).

규칙은 `VZ-N-05`(확대) 그대로다.

| 조건 | 여기서 |
|---|---|
| 오버레이다 | `ZoomOverlay`·`ActionModal` 과 같은 `.modal-backdrop` 위에 얹는다 |
| 뒤를 교체하지 않는다 | 마일스톤·하드웨어 목록의 **형제**로 얹힌다. 언마운트되지 않으므로 닫으면 같은 자리 |
| 동시 하나 | 상태가 **문자열 하나**(`statusDeviceId`). 배열이면 둘이 열리고, 둘이 열리면 분할 화면이고, 분할 화면은 곧 탭이다 |
| 닫는 길이 둘 이상 | 닫기 버튼 · `Esc` · 배경 누르기 |

### `device-strip` 을 부품으로 꺼냈다

`ActionModal` 안에 인라인으로 있던 일곱 칸(배터리·네트워크·IP·펌웨어·관절 온도·하트비트 +
머리 칸)을 `src/views/DeviceStrip.tsx` 로 꺼내 **두 곳이 같은 부품을 쓴다.** 지시서의 이유가
그대로다 — 두 곳에 다른 상태 화면을 만들면 어휘가 갈린다(한쪽은 「관절 온도」, 다른 쪽은
「온도」가 되는 식). `ActionModal` 의 화면은 **한 픽셀도 바뀌지 않았다.**

## 자리표시로 남긴 것과 그 사유

### 일곱 칸 전부 — 기본 모드에서는 값이 아니라 자리표시 카드다

대본(registry 세계) 장비의 실측값은 **남이 줄 데이터**다(8/31 결정). 그래서 더블클릭하면
뜨는 것은 값이 아니라 **「무엇을 · 누구에게서 기다리는가」 카드**다. 그것이 이 화면의 요지다.

- `robot-status-strip` — 기다리는 상대가 다섯이다: `HW-R-02`(하트비트 전송) ·
  `HW-R-03`(상태 데이터 전달) · `HW-C-04`(장치 상태·구역 등록 관리) ·
  `HW-C-07`(device_id 기반 식별) · `BE-T-04`(장치 등록·가용성 관리)
- 옛 편(`MSN-260826-01`)처럼 시나리오에 `hardware` 목록이 실려 있으면 일곱 칸을 그릴 수는
  있지만 **그것도 `PendingSource` 안에** 있어 기본 모드에서는 자리표시가 이긴다.
- 대본 세계에서는 `Hardware` 객체 자체가 없으므로 자리표시만 뜬다. `entity` 를 넘기지 않아
  **대본 합성값으로도 채워지지 않는다** — 하드웨어 실측은 어느 대본도 몰지 않는다.

### 카메라 연결 상태 — 「상대 없음 — 회의 안건」

**계약에 필드가 없다.** `Hardware` 타입에 배터리·RSSI·지연·IP·펌웨어·관절 온도·하트비트는
있고 **카메라만 없다.** 하드웨어 시트에서 대응 항목을 찾지 못했다.

그래서 `Hardware` 에 필드를 늘리지 않았고, 값을 지어내지도 않았다. 새 자리표시
`device-camera-link` 를 만들어 **`from: []` + `missing` 사유**로 등록했다 — 이 저장소의
자리표시 표는 상대가 없을 때 그것을 명시하는 칸을 이미 갖고 있고(`verify:placeholder-default`
가 「상대가 비면 사유가 반드시 있어야 한다」를 검사한다), 화면에는 **「상대 없음 — 회의 안건」**
이 크게 붙는다.

| | |
|---|---|
| 무엇 | 대상에 달린 카메라가 붙어 있는가 · 스트림이 살아 있는가 |
| 누가 | **상대 없음** — 하드웨어 계약에 해당 필드가 없다 (요구사항정의서 §7.10 「열림」) |
| 우리 자리 | `VZ-D-07` |
| 평면 | 미디어 평면 (업무·관측 브로커에 싣지 않는다 — `AI-C-14` · `HW-R-07`) |

`VZ-U-04` 가 「상대 없음」으로 삭제된 전례가 있다. **만들기 전에 하드웨어 파트와 맞추는 것이
먼저다** — 다음 회의 안건이다.

## 검증

- **기존 verify 18종 + `typecheck` 전부 통과.** `verify:standalone` **무개정 통과**(Windows) —
  단독 의존 그래프가 49 → **51개 파일**(새 부품 둘). `tabs/`·`shell/` import 는 여전히 0건.
- `verify:placeholder-default` — 새 자리표시가 네 가지(무엇·누가·우리 자리·평면)를 채웠고,
  상대가 빈 자리에 사유가 있으며, 표의 id 가 화면에서 실제로 참조되는지까지 통과.
- `verify:no-tabs` — 아래 §「검사를 고친 곳」.

## 검사를 고친 곳 — `verify:no-tabs` ②

**이 단계에서 한 번 깨졌고, 우회하지 않고 검사를 고쳤다.**

②(「닫으면 정확히 같은 자리」)가 `main.tsx` 의 **첫 `onClose`** 하나를 정규식으로 집고 있었다.
대상 상태 오버레이가 파일 앞쪽(`Milestones`)에 생기면서 그 첫 자리를 차지했고, 검사가
**확대의 닫기 대신 새 오버레이의 닫기를 보고** 「`setZoomedId(null)` 이 없다」고 실패했다.

확대의 닫기 경로는 한 글자도 바뀌지 않았다 — 검사의 앵커가 자리 순서였던 것이 문제다.
그래서 **오버레이 이름을 앵커로 삼고, 규칙을 둘 다에 건다**:

- `ZoomOverlay` 의 닫기는 `setZoomedId(null)` **하나만** 되돌린다
- `DeviceStatusOverlay` 의 닫기는 `setStatusDeviceId(null)` **하나만** 되돌린다
- 둘 다 `Esc` 로 닫힌다
- 음성 대조군 — 두 앵커가 같은 것을 집으면 실패로 잡는다

느슨해진 것이 아니라 **검사 대상이 하나에서 둘로 늘었다.** 규칙(닫으면서 다른 상태를 만지지
않는다)은 원래 모든 오버레이에 걸려야 했던 것이다. 정규식을 `new RegExp` 문자열이 아니라
이름 위치를 찾아 자르는 방식으로 바꿨다 — 템플릿 문자열 안의 역슬래시가 한 번 더 먹히는
함정을 없앤다.

## 지시서와 다르게 한 곳

**카메라 자리표시를 `device-strip` 안이 아니라 대상 상태 오버레이에만 넣었다.**

`device-strip` 은 `ActionModal` 과 공유하는 부품이라, 여덟째 칸을 넣으면 이번 범위가 아닌
액션 아이템 팝업의 화면까지 바뀐다. 카메라 연결 상태는 **「대상 상태 조회」(`VZ-D-07`)의
항목**이므로 그 화면에만 둔다. 공유하는 일곱 칸의 어휘는 두 곳이 여전히 **완전히 같다** —
지시서가 막으려던 「두 곳에 다른 상태 화면」은 생기지 않았다.

## 하지 않은 것

- `Hardware` 타입에 필드를 늘리지 않았다 (계약 변경 없음).
- 대본 세계 장비의 실측값을 지어내지 않았다.
- 상대 요구사항 ID를 지어내지 않았다 — 없으므로 `missing` 에 사유를 적고 비웠다.
