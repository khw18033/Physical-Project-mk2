# 발화·문장으로 들어온 정량 명령이 임무가 된다 (2026-09-22)

**지시** 정량 명령을 임무 시작 버튼 옆에 따로 만들 것이 아니라 **발화나 문장 입력**으로
정량 명령을 생성해도 작동해야 한다.

```
1. 정량 명령만              Go1이 1m 앞으로 전진해
2. 정량 명령이 포함된 명령   Go1을 90도 왼쪽으로 회전시킨 후 거울 위치를 탐지한 후 거기까지 이동해
```

---

## 0. 먼저 정정 — **2번도 대본에 안 맞는다**

「2번은 되는 걸로 안다」고 하셨는데, 재 보니 둘 다 대본 매칭에서 떨어진다.

```
Go1이 1m 앞으로 전진해                        match: none
Go1을 90도 왼쪽으로 … 거기까지 이동해          match: none
저기 문 쪽으로 가                              match: matched (MSN-260909-01)
```

즉 **둘 다 생성(LLM)으로 넘어간다.** 2번이 「되는 것처럼」 보였다면 생성이 그럴듯한 임무를
만들어 준 것이고, 1번이 안 됐던 것은 **모델이 만들 수 없는 것을 만들려 했기 때문**이다 —
「1m 전진」은 모델에게 물을 것이 아니라 **사람이 이미 숫자로 다 적은 것**이다.

---

## 1. 고친 것 — 통째로 읽히면 그것으로 임무를 세운다

발화·직접 입력 두 자리에서, 대본 매칭보다 **먼저** 정량 해석을 시도한다.

| 문장 | 결과 |
|---|---|
| `Go1이 1m 앞으로 전진해` | **임무가 선다** — 태스크 1개(`↑ 1.00 m (vx 0.30)`) |
| `오른쪽 90도 회전 후 1m 전진 후 왼쪽 90도 회전` | 태스크 3개, 차례대로 매달림 |
| `Go1을 90도 왼쪽으로 … 거기까지 이동해` | **손대지 않고 지나보낸다** → 대본·생성이 하던 대로 |

**통째로 읽혔을 때만** 이 길로 온다. 섞인 문장은 `reject` 가 붙고 그때는 건드리지 않는다 —
앞부분만 내면 **사람이 적은 것과 다른 것이 로봇에게 간다.** 「절반만 읽고 나머지를 지어내지
않는다」가 여기서도 그대로다.

> 2번을 갈라 실행하려면 **임무 어휘**(탐지·이동…)를 정의해 정량 부분과 나눠야 한다.
> 그건 설계가 필요한 별도 작업이라 이번에 안 했다 — §4 에 적는다.

---

## 2. 제안의 종류가 셋이 됐다

```
script   미리 써 둔 편 중 하나를 골랐다        — missionId 만 들고 본문은 라이브러리에
ai       모델이 만들었다                      — 본문 + 모델·규칙·프롬프트 지문
steps    사람이 숫자로 적었다 (신설)            — 본문 + 그 문장 자체
```

**모델 제안으로 뭉치지 않았다.** `AiProvenance` 는 모델 이름과 프롬프트 지문을 드는데,
거기에 지어 넣으면 「AI·백엔드·사람 중 누가 만든 값인가」(논문 §4-3)가 **사람의 문장을
모델의 산출로** 답하게 된다. 대본 제안으로도 못 뭉친다 — 방금 만들어져 라이브러리에 없다.

제안 카드도 갈랐다. 「대본을 골랐습니다」는 거짓말이고 「모델이 만들었습니다」는 더 나쁘다 —
**「사람이 적은 정량 명령입니다 — 규칙으로 읽어 걸음 n개를 세웠습니다」**로 적는다.

기록도 같은 칸에 **다른 값**이 들어간다: 모델은 지문, 이쪽은 `{ origin: 'steps',
sentence, read_by: 'rules' }`.

---

## 3. 승인 뒤에 나간다

`shouldIssueStepMission()` 이 스캔 관문과 **같은 자리·같은 규칙**이다. 다른 것은 준비
단계를 안 보는 것뿐이다 — 이 임무에는 `T-A1`·`T-A2` 가 없다.

**승인만으로는 안 쏜다.** 승인은 「이 문장대로 해도 좋다」이고 시작은 「지금 하라」다.
말한 것만으로 로봇이 걷기 시작하면 되돌릴 자리가 없다.

걸음은 **임무에 실려 있다**(`params.step_commands`). 화면이 그린 태스크와 로봇에 나갈
걸음이 같은 출처여야 둘이 갈리지 않는다.

## 4. 검사

`verify:step-script` 에 **7절**을 더했다.

- 정량 명령만인 문장 → 임무가 서고, 태스크 수 = 걸음 수, 차례대로 매달린다
- **섞인 문장 → 통째로 안 읽었다고 하고 한 걸음도 안 낸다**
- 화면이 그 갈래를 실제로 쓴다 · 「통째로 읽혔을 때만」 조건이 있다
- 정량 제안이 **모델 제안으로 안 뭉쳐진다**
- 승인·시작 없이는 안 나간다

**변조 사본** — 「통째로 읽혔을 때만」 조건을 빼면 `섞인 문장이 반만 실행된다` 로 잡힌다.

```
검사 91개 (standalone 제외) — 실패 0
verify:standalone           — 통과 (174개 파일)
typecheck                   — 통과
번들                         1,132.56 → 1,134.64 kB (+2.08 kB, gzip +0.73 kB)
```

## 5. 남은 것

- **화면으로 확인해야 한다.** 발화나 직접 입력에 「Go1이 1m 앞으로 전진해」를 넣고
  ① 제안 카드가 「사람이 적은 정량 명령」으로 뜨는지, ② 승인 → 임무 시작으로 로봇이
  1m 가는지.
- **섞인 문장(2번)을 갈라 실행하는 것** — 임무 어휘를 정의해 정량 부분과 나누는 작업.
  지금은 생성으로 지나간다.
- 머리줄의 입력칸은 **그대로 둔다.** 임무를 안 세우고 바로 쏘는 길이라 시험에 빠르다 —
  발화 경로와 목적이 다르다.
- `odo_m` 대조와 pi7 §10 질의는 앞 보고서 그대로 남아 있다.
