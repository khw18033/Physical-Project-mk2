## 2. 원인 — Node 21+ 에도 `navigator` 가 있다

```
$ node -e "console.log(navigator.language)"
en-US
```

`language.ts` 의 `fromNavigator()` 가 `typeof navigator === 'undefined'` 만 봤다.
그래서 **검사 스크립트 안에서 `t()` 가 영어를 돌려줬다.**

```
t('check.robot.stale', { sec: 40 })
  → "No signal for 40s — the last value is not treated as current"
```

`verify-connection-panel.mjs:97` 이 그 자리에서 `소식이 없습니다` 를 찾는다.
한국어 윈도우에서는 `navigator.language` 가 `'ko-KR'` 이라 `'ko'` 로 떨어져 통과했다.

## 3. 고침 — `navigator` 가 아니라 **브라우저인가**를 본다

Node 에는 `navigator` 는 있어도 `window` · `document` 는 없다.

```ts
function fromNavigator(): Lang | null {
  try {
    // 브라우저 신호다. Node 의 `navigator` 를 브라우저로 착각하면 안 된다.
    if (typeof window === 'undefined' || typeof document === 'undefined') return null;
    if (typeof navigator === 'undefined') return null;
    ...
```

**검사 환경의 기본값이 언제나 `'ko'` 가 된다.** 영어 경로를 재려면 검사가 `setLang('en')` 을
명시적으로 부른다 — **환경이 정하게 두지 않는다.** 이것이 2단계의 규약이다.

브라우저 동작은 그대로다. `window` 와 `document` 가 다 있으므로 `navigator.language` 를 전과 같이 본다.

## 4. 검사 보강 — `verify:lang-switch`

- **`installGlobals()` 가 `window` 도 심는다.** 안 심으면 기존 `navigator` 경우 둘이 통째로 안 돈다
- **6번 신설** — 브라우저 전역을 하나도 안 심고, **Node 가 원래 갖고 있던 `navigator` 를 되돌려 놓은 채**
  언어를 물어 `'ko'` 인지 본다. 앞의 경우들이 `navigator` 를 지우므로 모듈 맨 위에서 미리 붙든다 —
  안 그러면 **검사가 아무것도 안 재고 통과한다**
- **대조군 넷째** — 브라우저 판정 줄이 사라지면 잡는다

### 실증

브라우저 판정을 도로 걷어내 260916 상태를 재현했더니 둘 다 잡혔다.

```
❌ verify:lang-switch
- 검사 환경 기본값이 'en' 다 — 이 기계의 navigator.language 가 'en-US' 이라 따라갔다
- fromNavigator() 의 브라우저 판정이 사라졌다 — 검사 결과가 기계 로캘을 따라간다
❌ verify:connection-panel
- 낡았다는 사실을 안 적었다
```

원복하면 둘 다 통과한다.
