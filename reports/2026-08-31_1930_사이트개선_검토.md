## 남은 것 둘

### 1. 모드 스위치가 「우측 상단」이 아니다 — 가운데에 있다

요구 4의 문장은 「**우측 상단**에서 확인 및 변경」이었고 문서도 「상단 바 우측에」라고 적고 있는데,
실제 화면에서는 상단 바 **가운데**에 있다(`reports/assets/site-improvement-260831-final.png`).

원인은 CSS 한 줄이다.

```css
.global-bar{ ... grid-template-columns:300px 1fr auto; ... }
```

세 칸짜리 격자인데 요구 1에서 **가운데 칸에 있던 안내 문단 2줄을 지웠다.** 남은 자식이
`mission-identity` 와 `nav` 둘뿐이라 `nav` 가 가운데 `1fr` 칸으로 올라왔고, 오른쪽 `auto` 칸이
비어 있다. 그래서 스위치·`?`·연결 상태·임무 버튼 묶음이 통째로 왼쪽으로 당겨졌다.

고치는 법: `grid-template-columns:300px 1fr` 로 줄이고 `nav` 에 `justify-self:end`.
요구 1과 요구 4가 같은 줄을 건드리면서 생긴 것이라 둘 중 어느 쪽 검증에도 안 걸렸다.

### 2. 3편 정지 미리보기의 수문 개도율이 이야기와 반대다

`MSN-260831-03` 은 **열려 있던 수문을 닫는** 이야기다. 대본도 그렇게 적혀 있다.

```json
"initial": { "actuator-01": { "position_pct": 100, "physical_state": "open" } }
```

그런데 `script_preview` 는 `worldTimeline` 의 `atSec === 0` 프레임만 반영하고 `initial` 은
반영하지 않는다(구현 보고서 §판단 4-3이 스스로 밝혀 둔 대로다). 3편의 t=0 프레임에는
`sensor-01`·`sensor-02` 수위만 있고 액추에이터가 없어서, **미리보기의 개도율은 평시값 0%(닫힘)**
로 보인다 — 대본의 출발 상태와 정반대다.

**지시서가 「t=0 프레임만」이라고 좁게 쓴 탓이다.** `initial` 은 대본이 말하는 t=0 세계 그 자체이고,
게이트웨이의 재생 경로도 `startPlayback()` 에서 `initial` 을 먼저 반영한 뒤 프레임을 민다.
미리보기만 그 한 단계를 건너뛴다.

고치는 법: `previewScript()` 에서도 `initial` 을 `commands.primeState()` 로 반영한다
(재생 경로와 같은 세 줄). 「값을 지어내지 않는다」는 원칙에 어긋나지 않는다 — 지어내는 것이
아니라 대본에 적힌 출발 상태를 그대로 놓는 것이다.
