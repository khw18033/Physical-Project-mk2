## 2. 고친 자리 셋

### ① 줄끝 — `verify:trace-append` 의 대조군 둘이 안 만들어졌다

`traceStore.ts` 가 CRLF 인데 대조군이 `\n` 이 든 여러 줄 문자열을 찾았다. 치환이 아무것도
못 바꾸고 「대조군을 만들지 못했다」로 떨어졌다. **한 줄짜리 대조군 둘은 멀쩡히 통과해서
여러 줄을 찾는 것만 조용히 죽었다.**

`scripts/lib/source.mjs` 를 신설했다.

```js
export function readSource(...parts) {          // 줄끝을 LF 로 정규화해 읽는다
export function mutate(source, from, to)        // 안 바뀌었으면 null — 빼먹을 수 없게
```

`mutate()` 는 지시서에 없던 것이다. 각 스크립트가 `if (code === source) failures.push(…)` 를
손으로 적고 있었는데, **그 한 줄을 빼먹으면 대조군이 원본과 같은 채로 통과한다** — 검사가
아무것도 안 재게 된다. 판정을 헬퍼에 모아 두면 빼먹을 수 없다.

치환 문자열은 **안 고쳤다**(지시서 §1). 읽는 쪽이 맞춰 준다.

> **바이트 동일성을 재는 검사는 이걸 쓰면 안 된다** — `verify:stt-port` 에서는 줄끝도
> 비교 대상이다. 그쪽은 `readFileSync` 그대로다. 헬퍼 주석에 적어 뒀다.

### ② 한글 경로 — `.pathname` 은 퍼센트 인코딩이다

```
pathname       C:/Users/user/Desktop/%EB%8C%80%ED%95%99/4%ED%95%99%EB%85%84_%EC%BA%A1%EC%8A%A4%ED%86%A4/…
fileURLToPath  C:\Users\user\Desktop\대학\4학년_캡스톤\…
```

`verify-places.mjs:13` · `extract-places.mjs:21` **같은 줄이 두 벌**이었다. 둘 다
`fileURLToPath(new URL('../../', import.meta.url))` 로 바꾸고, 손으로 붙였던
`.replace(/^\/([A-Za-z]:)/, '$1')` 도 같이 지웠다 — 있어야 할 이유가 없어진다.

`scripts/` 전체를 훑어 `.pathname` 을 파일 경로로 쓰는 자리가 더 있는지 봤다. **없다.**
`autodrive-ai-relay.mjs:50` 이 하나 걸리지만 **요청 URL 을 검사하는 자리**라 해당 없다
(`gateway/server.ts` 와 같은 이유). 지시서가 미리 짚은 그대로다.

### ③ 임시 폴더 — 조용한 정리 실패

`scripts/lib/scratch.mjs` 를 신설했다.

- **만들 때 같은 접두사의 오래된 형제를 먼저 지운다** — 앞 실행이 흘려도 다음이 치운다
- **정리 실패를 안 삼킨다** — 모아 뒀다가 `process.on('exit')` 에서 목록으로 적는다.
  검사 결과는 통과시키되 눈에 띄게 남긴다(지시서 §3②)
- `isScratchPath()` — 훑는 쪽이 제외에 쓴다

`process.on('exit')` 로 적는 것은 지시서에 없던 선택이다. 스크립트마다 손으로 부르게 하면
**빼먹는 곳이 생기고, 빼먹은 그 조용함이 원래 문제**였다.

## 3. §1 의 목록 — 여러 줄을 찾는 대조군

**다음에 누가 그 파일을 만졌을 때 어디가 터질지가 이 표다.**

| 스크립트 | 여러 줄 대조군 | 대상 파일 | 줄끝 | 상태 |
|---|---:|---|---|---|
| `verify-trace-append.mjs` | 2 | `src/shared/stores/traceStore.ts` | **CRLF** | **이번에 고쳤다** — `readSource` |
| `verify-human-trace.mjs` | 1 | `src/data/trace.ts` | **CRLF** | 이미 **인라인 대응**이 있었다 |

`scripts/*.mjs` 전체를 훑어 `.replace(…)`·`mutate(…)` 의 **첫 인자 문자열에 `\n` 이 든** 것을
찾았다. 저 둘이 전부다.

`verify-human-trace.mjs:172` 는 이미 이렇게 되어 있었다.

```js
// **줄끝을 맞춰 둔다.** … 자리표에 `\n` 이 들어간 사본은 그때 안 만들어지고,
// 검사는 「원본이 바뀌었나?」라고 말한다 — 원본은 그대로인데.
const source = readFileSync(tracePath, 'utf8').replaceAll('\r\n', '\n');
```

**누군가 전에 같은 함정을 밟고 그 자리에서만 고쳐 뒀다.** 그래서 안 깨져 있었고, §1 이
「안 깨진 것을 예방 삼아 고치지 마라」라고 해서 **손대지 않았다.**

> 다만 이것은 `readSource()` 와 같은 일을 하는 두 번째 구현이다. 다음에 그 파일을 만질 때
> 헬퍼로 합치기를 권한다 — 지금 바꾸면 범위를 벗어난다.

## 4. 이관한 스크립트 — **13개가 아니라 8개**였다

지시서 §3②가 「13개 스크립트를 이걸로 옮긴다」고 했다. 실제로 `mkdtempSync` 를 부르는 것은
**11개**이고, 그중 **`src/` 안에 만드는 것은 8개**다.

| 스크립트 | 만드는 자리 | 옮겼나 |
|---|---|---|
| `verify-dep-rules` (2자리) · `verify-gen-port` · `verify-human-trace` · `verify-no-llm` · `verify-placeholder-default` · `verify-replay` · `verify-scenario-mode` · `verify-trace-append` | **`src/` 안** | **옮겼다** (8개 · 9자리) |
| `verify-mission-record` · `verify-no-stt` · `verify-voice-audit` | `os.tmpdir()` | **안 옮겼다** |

`tmpdir()` 쪽을 뺀 이유는 **§3 이 막으려는 사고를 낼 수 없어서**다. 거기 남은 것은 `src/` 를
훑는 검사의 판정을 바꿀 수 없고 OS 가 치운다. 게다가 접두사가 `.verify-` 가 아니라
(`mission-records-` 등) 헬퍼의 계약과도 안 맞는다. **억지로 옮기면 「검사가 무엇을 막는가」가
흐려진다.**

### 동작이 달라진 곳

**하나도 없다.** 판정 로직은 한 줄도 안 건드렸다. 바뀐 것은 셋뿐이다.

```
mkdtempSync(join(A, '.verify-x-'))   →  makeScratch(A, '.verify-x-')       + 형제 청소
join(scratch, name)                  →  scratch.file(name)
try { rmSync(…) } catch { warn(…) }  →  scratch.cleanup()                  + 실패를 모아서 보고
```

## 5. §3① 훑기 제외 — 손으로 센 11개가 아니라 **14개**였다

`src/` 를 훑는 검사 전부에 `if (isScratchPath(path)) continue;` 를 넣었다.

**손으로 찾을 때 3개를 놓쳤다.** `verify-autodrive-ai` · `verify-detect-map` · `verify-nav-feed`
— 이 셋은 `function walk` 가 아니라 `const walk = (dir) => readdirSync(dir).flatMap(…)` 꼴이라
제가 건 grep 에 안 걸렸다.

**신설한 `verify:verify-hygiene` 이 첫 실행에서 그 셋을 잡아냈다.** 검사가 제 몫을 한
사례라 그대로 적는다 — 사람이 훑어 만든 목록은 새지만, 규칙으로 잡으면 안 샌다.

> 두 개(`verify-gen-port` · `verify-no-llm`)는 `if (!name.startsWith('.'))` 로 **우연히** 막고
> 있었다. 규칙이 다르므로(모든 점 디렉터리 제외) 그대로 두고 명시적 제외를 덧붙였다.

## 6. 신설 — `verify:verify-hygiene`

```
✅ 파일 경로 — 76개 스크립트가 .pathname 대신 fileURLToPath() 를 쓴다 (한글 경로에서도 돈다)
✅ 임시 폴더 — src/ 안에 만드는 8개 스크립트가 전부 makeScratch() 를 지난다
✅ 훑기 — src/ 를 훑는 14개 검사가 전부 .verify-* 를 제외한다
✅ 대조군 4건 — 위반은 잡고, 비슷하지만 정당한 것(HTTP 경로 · tmpdir)은 통과시킨다
```

대조군을 **넷** 뒀다. 둘은 「위반을 잡는가」이고 **둘은 「정당한 것을 안 잡는가」**다 —
HTTP 경로의 `.pathname` 과 `tmpdir()` 의 `mkdtempSync`. 후자가 없으면 검사가 과해져서
경계 자체를 막는다.

대조군은 **실제 파일이 아니라 손으로 만든 문자열**에 판정식을 먹인다. 실측값을 재료로 쓰면
진짜 위반이 하나라도 있을 때 대조군이 그것 때문에 통과/실패해서 무엇을 확인한 것인지
알 수 없어진다.

## 8. 지시서와 다르게 한 곳 — 여섯

### ① 합격 기준 숫자를 58 → **59** 로 읽었다

지시서가 「58 통과 / 0 실패」라 적었는데, 착수 시점이 58종이고 §5 가 `verify:verify-hygiene`
신설을 지시하므로 끝나면 59종이 된다. 0절에서 이 점을 먼저 보고하고 진행했다.

### ② 0절 기준선이 57/1 이 아니라 56/2 였다 (§1)

### ③ 이관 대상이 13개가 아니라 8개 (§4)

### ④ `mutate()` 를 헬퍼에 넣었다 (§2①)

지시서는 `readSource()` 만 요구했다. 「대조군이 안 만들어졌는지」 판정도 같이 모았다 —
그 한 줄을 빼먹으면 검사가 조용히 무의미해지는 자리라서다.

### ⑤ `verify-verify-hygiene.mjs` 를 자기 검사 대상에서 뺐다

§6 의 대조군이 **「위반하는 코드」를 문자열로** 들고 있어서 자기 규칙에 자기가 걸린다.
문자열 리터럴을 지우고 훑는 방법도 있지만 그러면 **진짜 위반도 같이 안 보인다** — ①·②가
찾는 것이 바로 코드 조각이기 때문이다. 대조군을 잃느니 이 파일 하나를 빼는 편이 낫다.
그 사유를 파일 안에 적어 뒀다.

### ⑥ `verify-human-trace.mjs` 를 안 고쳤다 (§3)

§1 의 「안 깨진 것을 예방 삼아 고치지 마라」를 따랐다. 목록에만 넣었다.

## 9. 덧 — 작업 중에 같은 함정을 **세 번** 밟았다

이관을 기계적으로 하려고 쓴 임시 스크립트가 `\n` 이 든 여러 줄 문자열로 치환을 시도했다가
세 번 연속 아무것도 못 바꿨다. 대상이 CRLF 였기 때문이다 — **§1 이 고치는 바로 그 문제.**

```
verify-autodrive-ai.mjs    제외 0자리      ← 여러 줄 치환이 CRLF 에서 안 먹었다
verify-detect-map.mjs      제외 0자리
verify-nav-feed.mjs        제외 0자리
```

import 삽입 정규식이 `from 'node:url';\n` 을 기대한 것도 같은 이유로 실패해서 12개 검사가
한 번 통째로 깨졌다(`ReferenceError: isScratchPath is not defined`). 줄끝에 무관한 방식으로
다시 해서 고쳤다.

**이 저장소에서 여러 줄 문자열로 소스를 다루면 거의 반드시 이 함정을 밟는다.** §3 의 표가
왜 필요한지가 이 일로 한 번 더 확인됐다.
