## 무엇이 문제였나

지난 작업(8/31)은 시나리오 연계를 **자리(slot) 층에서만** 했다. `PendingSource` 에 `axis` 를
붙여 「이 대본에는 해당 없음」을 만든 것까지는 맞았는데, **그 위의 패널과 탭은 그대로 서 있었다.**

1편(로봇 이동)을 틀어도 탭③에는 `actuator-01 · 수문 제어` 제목과 버튼 줄과 감사 표가 그대로
있고 안쪽 칸만 「해당 없음」이었다. 로봇 이야기를 보는 사람 앞에 수문이 있었던 셈이다.
칩 몇 개로는 그 인상이 지워지지 않는다 — **뼈대가 남아 있기 때문이다.**

이번 작업은 연계를 **자리 층에서 패널·탭 층으로 올린 것**이다.

## 0. 남은 것 둘 — 둘 다 닫았다

### 0-1. 모드 스위치가 이제 우측 상단에 있다

`.global-bar` 가 `300px 1fr auto` 3열 격자인데 요구 1에서 가운데 칸의 안내 문단을 지워
남은 자식이 둘뿐이 되면서 `nav` 가 가운데 `1fr` 칸으로 올라와 있었다.

```css
/* 전 */ .global-bar{ grid-template-columns:300px 1fr auto; }
/* 후 */ .global-bar{ grid-template-columns:300px 1fr; }
         .global-bar nav{ justify-self:end; flex-wrap:wrap; justify-content:flex-end }
```

**문서에서 단서도 지웠다** — `가시화_프로토타입_설명서.md` 의 「지금은 가운데에 있습니다」
괄호와 `현재상황_읽기순서.txt` 의 「지금은 바 가운데에 있다」 줄, 그리고 「지금 남은 것 둘」
항목 전체. 고쳐 놓고 문서에 남겨 두면 다음 사람이 또 찾는다.

### 0-2. 3편 정지 미리보기의 수문 개도율이 이야기와 맞는다

`MSN-260831-03` 은 **열려 있던 수문을 닫는** 이야기이고 대본의 `initial` 이 `position_pct: 100`
(열림)이다. 그런데 `previewScript()` 는 `worldTimeline` 의 `atSec === 0` 프레임만 반영하고
`initial` 을 건너뛰어, 미리보기의 개도율이 평시값 0%(닫힘) — 출발 상태의 정반대 — 로 섰다.

**재생 경로와 같은 한 곳을 쓴다.** `startPlayback()` 안에 있던 `commands.primeState()` 세 줄을
`ScriptEngine.applyInitial(script)` 로 뽑아 재생과 미리보기가 **둘 다 그 하나**를 지나게 했다
(두 벌로 적으면 갈라진다).

값을 지어낸 것이 아니다 — `initial` 은 대본이 적어 둔 t=0 세계 그 자체이고, `primeState()` 는
수행 중인 대상을 건드리지 않으므로 명령 우회도 아니다.

**검사도 붙였다** (`verify:scenario-mode`, 게이트웨이 왕복 안):
재생에서 `close_gate` 가 수문을 닫힘 쪽으로 몰아 둔 상태(측정값 3.2%)에서 `script_preview` 를
보내면 `actuator_state` 의 `position_pct` 에 **100 이 나타나야** 통과한다.

> 닫는 동작은 실시간 6초라(엔진 타이밍은 배속을 따르지 않는다 — `script-engine.ts` 머리말)
> 재생 종료 시점 값이 정확히 0 이 아닐 수 있어, 전제는 「50 미만(닫힘 쪽)」으로 두었다.
> 확인하려는 것은 **미리보기가 100 으로 되돌리는가**이지 재생 종료값이 아니다.

## 1. 「임무 승인 · 서브태스크 진행」 → 「임무 승인」

### 뺀 것

| 뺀 것 | 왜 |
|---|---|
| `SegmentTrack` (구간 목록·진행 요약) | 계획 구간은 **마일스톤과 같은 값**이다. `gateway/plans.ts` 머리말이 그렇게 적고 있고, `ScriptEngine` 이 `foldMilestones()` 결과를 `plans.applyScriptMilestones()` 로 되돌린다. 한 화면에서 같은 것을 두 번 그리고 있었다 |
| 실패 상세 (`faildetail`) | 탭①에 실패 경로 강조 화면(`screen === 'failure'`)이 이미 있고, 그쪽이 더 넓다 |
| 중계 단계 (`relay_stage`) 표시 | 백엔드 내부 상태다. **목·개발 모드로 내렸다**(`useDevTools()` — 지웠다기보다 옮겼다) |

### 남긴 것

- **승인·거부**는 임무의 관문이라 그대로다. 자리만 **탭① 마일스톤 화면의 제안 카드 안**으로 옮겼다.
- **계획 근거 4층은 결정 전에 펼친 채로 유지**했다 — 승인은 되돌리기 어려운 조작이라 접어 두면
  안 보는 근거가 된다(원 설계 판단 1). 다만 **「구간별 계획」 절만 한 줄**로 줄였다:
  `3구간 — 아래 마일스톤과 같음`.
- **거부는 사유 없이 보낼 수 없다** — 기존 규칙 그대로.

### 2차 수정 — 결정이 끝나면 한 줄 영수증 (사용자 피드백)

첫 구현을 화면에서 확인한 결과, **승인이 끝난 뒤에도** 근거 4층과 산출 경로가 화면 한가운데를
그대로 차지해 마일스톤(MS-A·MS-B…)을 아래로 밀고 있었다. 그 시점에는 이 화면에서 결정할 것이
하나도 없다 — 마일스톤 화면의 주인은 마일스톤이다.

원 설계 판단 1(「펼쳐 봐야 보이는 근거는 안 보는 근거」)이 말하는 것은 **결정하기 전**이다.
결정이 끝난 뒤에도 펼쳐 두는 것은 근거를 보이는 일이 아니라 자리를 차지하는 일이다.

| 상태 | 화면 |
|---|---|
| 승인 전(제안) | 머리글 + 경고 + **근거 4층 펼침** + 생성기 각주 + `[승인][거부]` — 관문이라 그대로 |
| 결정 후 | `✓ 승인됨 · 14:55:18 · plan-…-scr · VZ-U-07 · [근거 ▾]` **한 줄**. 머리글도 없앴다 |
| `근거 ▾` 펼침 | 근거 4층 + `RouteStrip` + `ProvenanceTrack`(실측 4단계와 시각) |

`RouteStrip`(경로 hop)과 `ProvenanceTrack`(중계 4단계)은 **승인 전 화면에서 빠졌다.** 그건
「이 계획을 승인할 것인가」가 아니라 「이 시스템이 어떻게 동작하는가」이고, 그 **뜻풀이는
우상단 `?` 설명서**로 옮겼다(탭① 전용 절 「계획 승인 — 어디서 와서 어디로 돌아가는가」).
화면에 남은 것은 이 계획의 **실측 단계와 시각**이고, 그것도 결정 뒤 「근거 ▾」 안에만 있다.
승인 수신·재생 시작 두 단계는 애초에 결정 뒤에야 생기므로 자리가 맞는다.

근거 4층 마크업은 `EvidenceList` 로 뽑아 승인 전 화면과 「근거 ▾」가 **같은 것 하나**를 쓴다.

결정 뒤 영수증이 그리는 세 값(`decision`·`decided_at`·`plan_id`)이 실제로 채워지는지는
아래 승인 → 재생 확인 실행에서 함께 봤다 — `approved · 2026-09-01T06:21:47.339Z · plan-…-scr`.

### 자리 — 마일스톤 목록 **위**

`main.tsx` 의 `Milestones` 는 `planApproval ?? (proposal-fallback)` 구조라 통합·단독이 이미
같은 슬롯을 쓰고 있었다. 그 슬롯을 「제안 상태」 안내와 묶어 `proposal-card` 하나로 만들고
**마일스톤 목록 위로** 올렸다 — 근거의 「구간별 계획」이 「**아래** 마일스톤과 같음」이라고
적으므로 카드가 목록보다 위에 있어야 말이 맞는다.

### 승인 → 재생이 끊기지 않았음을 무엇으로 확인했는가

**한 문장으로 끝까지 돌렸다.** 게이트웨이를 띄우고 「월류방어벽 자동 개폐 시스템을 가동해.」를
발화로 보낸 뒤, **화면의 승인 버튼이 부르는 바로 그 함수**(`src/tabs/data/plans.ts` 의
`decidePlan(planId, 'approve')`)를 그대로 불렀다. React 렌더만 빠진 실제 호출 경로다.

```
제안 도착 — plan-mti96nbx-scr MSN-260831-03 · decision = pending
승인 전 대기 1.5초 — trace_event 0건
전송 계층 상태 — open
decidePlan( plan-mti96nbx-scr , 'approve') 호출 — 화면 승인 버튼과 같은 경로
재생 시작 — trace_event 21건 · 첫 노드 T-41a · 마지막 노드 T-42a
계획 상태 — approved · relay_stage dispatched
세계 채널 — sensor-01 수위 표본 1.42, 1.42, 1.43 …
✅ 승인 → 재생 끊기지 않음
```

즉 `decidePlan()` → 백엔드 채널(`plan_decision`) → `PlanEngine` → `onScriptApproved` →
`startPlayback()` 이 그대로 걸린다. `verify:scenario-mode` 의 게이트웨이 왕복도 같은 경로를
승인 → 재생 → 감사 → 닫기까지 매번 돌린다.

## 2. 시나리오가 탭을 끌고 가게 — 세 층

### 표는 `axes.ts` 하나

축은 이미 대본에서 유도하고 있었다(`axesOfScript`). 그 **옆에** 축→탭 표와 패널→축 표를 두었다.

```
position → ②      speed → ④        water → ② ④      coverage → ② ④
video → ⑤         actuator·command → ③              risk → ②   observability → ④
(임무 축)  → ① 항상 (표에 없다 — tabsOfAxes() 가 늘 얹는다)
```

| 패널 id | 탭 | 축 |
|---|---|---|
| `risk` | ② | `risk` — 어느 대본도 안 미는 축이라 시나리오에서는 늘 접힌다 |
| `zone-map` | ② | `coverage` · `position` |
| `device-grid` | ② | `position` · `water` |
| `control` | ③ | `actuator` · `command` |
| `metrics-query` | ④ | `speed` · `water` · `coverage` |
| `metrics-push` | ④ | `observability` — 어느 대본도 안 민다 |
| `video` | ⑤ | `video` |

### 층 1 — 탭 바

대본이 안 쓰는 탭은 흐리게 + `· 이 대본엔 없음`. **막지 않는다** — 눌러서 확인할 수 있다
(막으면 「왜 안 눌리지」가 새 질문이 된다). `verify:tab-scope` 가 `disabled` 가 붙는 것을 잡는다.

### 층 2 — 패널 (본체)

`PanelGate` / `TabGate`(`src/tabs/ScenarioGate.tsx`)가 **제목·버튼 줄·표까지 통째로** 접는다.
탭 전체가 그런 경우에는 탭 본문을 한 장으로 대체한다.

```
이 대본(MSN-260831-01)은 ③ 제어 패널을 쓰지 않습니다
  이 편에는 액추에이터 명령이 없습니다.
  살아나는 편 — MSN-260831-03 「월류방어벽 자동 개폐」  [그 대본으로 바꾸기]
  일반 모드로 돌아가면 이 자리의 원래 화면이 그대로 보입니다.
```

「그 대본으로 바꾸기」는 모드 스위치의 대본 선택과 **같은 경로**를 부른다 —
진입 네 단계를 `src/scenarios/enterPreview.ts` **하나**로 뽑고 모드 스위치도 그것을 쓴다.

접힘은 자리표시(`PendingSource`)와 반대로 **자리 크기를 지키지 않는다.** 자리표시는 「나중에
이 자리에 그대로 들어간다」를 보이려 크기를 유지하지만, 접힘은 「이 이야기에 없다」이므로
화면을 짧게 만드는 것이 맞다.

### 층 3 — 자리

- `audit-history`(탭③ 감사 이력) → `entity` + `axis="command"`. 3편에서는 대본 명령이 실제
  엔진을 통과하므로 값이 차고, 1·2편에서는 패널째 접힌다.
- 탭② `RiskPanel` 안의 `device-cards` → **패널이 접히면서 함께 해소**됐다.

**의도적으로 남긴 셋**은 접지도 축을 주지도 않았고, 그 이유를 `?` 오버레이에 적었다
(「시나리오 중에도 자리표시로 남기는 셋 — 왜」).

| 자리 | 남긴 이유 |
|---|---|
| 탭① `hardware-pool-status` | 대본 등장 장비라도 실측 3행(배터리·RSSI·온도)은 **남이 줄 데이터** — 8/31 `VZ-D-07` 결정. 대본은 장비 id 까지만 말한다 |
| `mission-history` | 임무 이력은 백엔드가 보관한다 (`BE-S-01`·`BE-Q-01`) |
| `registry` | 레지스트리는 백엔드가 주는 목록이다 (`BE-Q-03`) |

### 세 편에서 어느 탭이 접혔고 어느 탭이 살았나 — 지시서 표와 대조

| 편 | 쓰는 탭 | 안 쓰는 탭(한 장으로 대체) | 지시서 표와 |
|---|---|---|---|
| `MSN-260831-01` 엘리베이터 이동 | ① ② ④ ⑤ | **③** | **일치** |
| `MSN-260831-02` 사각지대 탐지 | ① ② ④ ⑤ | **③** | **일치** |
| `MSN-260831-03` 월류방어벽 개폐 | ① ② ③ ④ | **⑤** | **일치** |

패널 단위까지 보면 이렇다 (`verify:tab-scope` 가 이 표를 못으로 박고 있다).

| 편 | 접히는 패널 | 사는 패널 |
|---|---|---|
| 1편 | `risk` · `control` · `metrics-push` | `zone-map`(궤적) · `device-grid` · `metrics-query`(속도) · `video` |
| 2편 | `risk` · `control` · `metrics-push` | `zone-map`(맵+궤적) · `device-grid` · `metrics-query`(커버리지) · `video` |
| 3편 | `risk` · `zone-map` · `metrics-push` · `video` | `device-grid`(수위) · `control` · `metrics-query`(수위) |

3편에서 **탭②는 살고 그 안의 구역 맵만 접힌다** — 수위 대본에는 궤적도 커버리지도 없다.
층 2가 탭 단위가 아니라 패널 단위인 이유가 여기서 보인다.

### 일반 모드에서는 아무것도 접히지 않는다

흐림도 접힘도 **시나리오 모드에서만**이다. 판정 재료를 `renderMode.getScenarioAxes()` 하나로
모아, 일반 모드와 목·개발 모드에서는 `null` 이 나오게 했다(`null` = 접지 않는다).
`verify:scenario-mode` 가 세 모드를 각각 눌러 본다.

## 3. 대본 띠 — 「지금 무엇이 어디서 보이는지」

띠를 두 줄로 늘렸다.

```
대본 MSN-260831-03 「월류방어벽 자동 개폐」 · 합성 데이터 · 재생 중 T+162s — cast 밖 장비는 자리표시
지금: MS-C close_gate 발행                                        [③ 제어 패널로]
```

- 「지금」은 **재생 머리(`headSec`) 기준 진행 중인 노드**다. 상태는 이미 접혀 있으므로
  (`foldStatuses`) 새로 계산하는 것이 없다.
- **갈 탭**은 그 노드가 마지막으로 움직인 시각부터 지금까지의 창 안에서 나간 `commands` 와
  `worldTimeline` 의 drive 키로 축을 뽑아 축→탭 표로 정한다. 후보가 둘이면 둘 다 적는다.
  창 안에 아무것도 없는 판정 노드에서는 대본 전체의 축으로 넓힌다(빈 안내는 쓸모가 없다).
- **정지 미리보기**에서는 `T+0 · 시작 상태 — 첫 마일스톤 MS-A …`.
- **재생이 끝나면** 「재생 끝 — 장치는 마지막 상태를 유지합니다」. 기존 동작 그대로.
- 이 줄은 **셸이 그린다**(`AppShell`). 탭이 그리면 탭을 옮길 때 사라져서 「보면서 확인」이
  성립하지 않는다.

## 지시서와 다르게 한 곳

### 1. `axes.ts` 를 둘로 갈랐다 — `axes.ts` + `scriptScope.ts`

지시서는 「축→탭 표를 `axes.ts` 에 둔다」였고 표는 그대로 거기 있다. 다만 **대본 목록에 묻는
조회 넷**(`axesOfMission` · `scriptsWithAxis` · `scriptsUsingTab` · `scriptsUsingPanel`)만
`src/scenarios/scriptScope.ts` 로 옮겼다.

이유는 `verify:tab-scope` 다. 검사가 표를 **직접 읽어야** 하는데, `library.ts` 가 대본 JSON 을
`import` 하고 있어 Node ESM 에서 import attribute 없이는 열리지 않는다. 검사가 표를 손으로
베끼면 「같은 대응이 두 곳에 적힌다」는 이번 작업이 막으려던 실패를 검사가 저지르게 된다.
**규칙과 표는 여전히 한 곳**이고, 갈라진 것은 「어느 편이 이 축을 미는가」라는 조회뿐이다.

같은 이유로 상태 접기(`statusesAt`)의 알맹이를 `src/data/fold.ts` 로 뽑았다 —
`data/scenario.ts` 가 옛 편 JSON 을 import 해서 Node 에서 안 열리는데, 안내줄 규칙
(`nowPlaying`)이 그 접기를 쓰기 때문이다. `scenario.ts` 의 `statusesAt()` 은 기본 인자
(`displayMission().view`)만 남은 껍데기이고 **호출부는 한 줄도 안 바뀌었다.**

### 2. `nowPlaying()` 이 대본을 인자로 받는다

같은 이유(Node 에서 돌려 봐야 한다)로 `libraryEntry()` 를 안에서 부르지 않고 셸이 찾아 넘긴다.

### 3. 구역 맵 미니뷰를 `DeviceGrid` 밖으로 꺼냈다

`ZoneMapMini` 는 `DeviceGrid` **안에** 있었는데, 구역 맵의 축(`coverage`·`position`)과 현황판의
축(`position`·`water`)이 달라서 안에 두면 **현황판이 접힐 때 살아 있어야 할 맵까지 함께**
사라진다. 세 편에서는 그 조합이 나오지 않지만 다음 대본에서 나올 수 있는 지뢰라
`tabs/index.tsx` 로 꺼내 세 패널이 각자 접히게 했다. 화면 순서는 위험도 → 구역 맵 → 현황판.

### 4. `relay_stage` 를 지우지 않고 목·개발 모드로 내렸다

지시서가 「필요하면 목·개발 모드로」라고 열어 둔 쪽을 택했다. 시연 화면에서는 사라지고
개발 중에는 볼 수 있다.

### 5. 결정 뒤 근거 4층을 접는다 (2차 수정 · 사용자 결정)

지시서는 「계획 근거 4층은 펼친 채로 유지한다」였다. 화면에서 확인해 보니 그 규칙이
**결정이 끝난 뒤에도** 적용돼 마일스톤을 밀어내고 있었고, 사용자가 「마일스톤 탭에는
마일스톤만 있어야 한다」고 지적했다. 세 안(① 결정 후에만 접기 ② 항상 접기 ③ 상단 띠로 빼기)을
제시해 **①**을 골랐다 — 승인 전 펼침(관문)은 그대로이고 결정 후에만 접힌다.
