## 1. 앞 작업이 시연 화면에 만든 것 중 무엇을 걷어 냈는가

`RobotPanel` 이 마일스톤 화면에 그리던 것 중 **넷을 걷어 냈다.**

| 걷어 낸 것 | 무엇이었나 |
|---|---|
| `robot-preset` | 프리셋 넷을 고르는 셀렉트 |
| `robot-address` | 주소 입력 칸 |
| `robot-ping` + 왕복 시간 | 연결 확인 버튼 |
| `robot-conn` | 브로커 연결 배지 |

넷째는 지시서가 명시하지 않았지만 같이 뺐다. 표시등이 셸 머리줄로 갔는데 같은 것을 두
군데서 그리면 「어느 쪽이 진짜냐」가 그대로 생긴다.

**남긴 것**은 연결이 아니라 **임무 진행**이다.

| 남긴 것 | 왜 |
|---|---|
| 진행률 `ack/of` | 임무가 어디까지 갔는가 |
| 접근 시작 버튼 | `door_turn` 뒤에 사람이 누르는 자리 |
| 거절·실패 문구 | `robot_state_dead` 같은 사유를 그대로 |
| 정지 실패 문구 · 「정지됨」 띠 · 해제 버튼 | **안전 기능** |

`verify:one-broker-address` 가 걷어 낸 넷이 다시 들어오는 것을 막는다 — `RobotPanel` 에
`<input>`·`<select>`·`BROKER_PRESETS`·`issuePing`·`saveConnections` 가 있으면 실패한다.

## 2. 브로커 상태와 로봇 상태를 가른 자리

**`src/shared/connectionCheck.ts` 의 `checkPhysical()` 이다.** 줄 둘을 낸다.

```
브로커  WebSocket 연결이 서 있는가   실패하면 → 주소·포트·망
로봇    ping 왕복이 도는가           실패하면 → 로봇 전원·상태
```

셋을 지킨다.

1. **브로커가 붙었으면 로봇이 죽어도 브로커 줄은 초록이다.** 연결은 성공이고 왕복은 실패다
2. **브로커가 안 붙었으면 로봇 줄은 「못 물어봤습니다」다** — 실패가 아니라 못 물어본 것이다.
   로봇을 안 켰다고 오해하면 엉뚱한 데를 본다
3. **줄이 하나라도 빨가면 그 대상은 초록이 아니다** (`targetOk()`)

대조군으로 「브로커와 로봇을 한 줄로 뭉친 사본」을 넣었다 — 로봇이 죽으면 브로커까지
빨개지는 것이 우리 것과 갈린다는 확인이다.

상태를 들고 있는 자리도 갈랐다. `connections.ts` 는 **설정**(어디에 붙을 것인가),
`connectionHealth.ts` 는 **결과**(눌러 봤더니 어땠는가)다. 한 파일에 두면 주소를 고칠
때마다 결과가 같이 흔들린다.

## 3. 시연 화면 표시등이 무엇을 읽는가

**`src/shell/ConnectionLamp.tsx`** 가 `connectionHealth` 의 `firstBroken(CHECKED_TARGETS)`
하나를 읽는다.

| 상태 | 화면 | 언제 |
|---|---|---|
| 회색 | `연결 미확인 — 누르면 연결 관리` | 아직 아무것도 안 눌러 봤다 |
| 빨강 | `로봇 로봇 끊김 — 누르면 연결 관리` | 끊긴 **대상과 줄 이름**을 짚는다 |
| 초록 | `연결 3/4 확인됨` | 확인한 것이 다 초록 |

**읽기 전용이다.** 주소 입력도 프리셋도 확인 버튼도 없다. 누르면 연결 관리 팝업이 열리고
고치는 것은 거기서 한다.

**「모른다」와 「빨갛다」를 가른다.** 안 눌러 본 것을 빨갛게 칠하면 발표 직전에 「원래
저런가」가 되고 진짜 빨강이 묻힌다.

셸 머리줄에 뒀다 — 정지 버튼과 같은 자리다. 마일스톤을 열었든 뷰 노드를 열었든 늘 떠
있어야 하는데 `RobotPanel` 은 마일스톤 화면에만 있어서 그 조건을 못 지킨다.

---

## 4. 발표 직전 점검 순서

1. **연결 관리를 연다** (머리줄 「⇄ 연결 관리」 또는 표시등을 누른다)
2. **`physical`** — 「확인」을 누른다. **브로커 초록 · 로봇 초록**. 왕복 시간을 본다
3. **`detect`** — 지금은 「2단계-B 에서 잇습니다」가 뜬다. 2단계-B 뒤에는 초록이어야 한다
4. **`stt` · `generate`** — 「확인」을 누른다. 초록
5. **닫는다. 시연 중에는 다시 열지 않는다**

**넷 중 하나라도 빨간 채로 무대에 오르지 않는다.**

시연 중에는 머리줄 표시등만 본다. 빨개지면 그때 누른다.

## 6. 지시서와 다르게 한 곳

### 표시등을 시연 화면이 아니라 셸 머리줄에 뒀다

§4 는 「시연 화면 한구석에 작은 표시등 하나」다. 머리줄에 뒀다.

이유는 배선과 조건 둘이다. 팝업 상태는 `AppShell` 이 들고 있어서 시연 화면에서 열려면
콜백을 아래로 내려야 하고, 더 중요하게는 **`RobotPanel` 이 마일스톤 화면에만 있다.**
뷰 노드를 열어 둔 동안에는 표시등이 사라진다. 정지 버튼을 머리줄에 둔 것과 같은 이유다.

머리줄은 시연 화면의 일부이므로 §4 의 뜻은 지킨다고 본다.

### `robot-conn` 배지도 걷어 냈다

지시서가 명시한 것은 프리셋 UI 와 확인 버튼 둘이지만, 브로커 연결 배지도 같이 뺐다.
표시등이 같은 것을 말하는데 두 군데서 그리면 §0 이 막으려던 「어느 쪽이 진짜냐」가 그대로
생긴다.

### `verify:no-detect` 를 새로 만들었다

§6 표에 `verify:no-physical` 과 나란히 적혀 있는데 저장소에 없었다. 새로 만들었다.
탐지는 2단계-B 까지 **늘 없는 상태**라, 그것이 나머지 셋을 끌어내리지 않는지가 지금부터
계속 확인돼야 한다.

### `detect` 확인을 지금 부르지 않는다

§2 는 `detect` 의 확인 방법을 `GET /health` 로 적었지만 §7 은 「실제 확인 로직은
2단계-B」다. 자리만 만들고 **누르면 「2단계-B 에서 잇습니다」라고 답한다.**

지금 `GET /health` 를 부르면 붙을 곳이 없는 주소에 매번 실패가 쌓이고 빨간 줄이 늘 하나
켜져 있게 된다. 그러면 §5 의 「넷 중 하나라도 빨간 채로 무대에 오르지 않는다」가 2단계-B
전까지 애초에 불가능해진다.

## 7. 하지 않은 것 (§7 그대로)

- **시연 화면의 주소 입력·프리셋** — 걷어 냈고 검사가 다시 들어오는 것을 막는다
- **긴급 정지를 연결 관리로 옮기기** — 안전 기능이라 시연 화면에 그대로. 검사가 연결
  관리에 정지가 들어가면 실패시킨다
- **대비값을 `connections.ts` 로 되돌리기** — `physical` 의 `fallback` 은 여전히 빈 문자열
- **`detect` 의 실제 확인 로직** — 위 6절
- **`stt`·`generate` 동작 변경** — 기존 `probe()` 를 부르기만 한다
