## 2. 발견한 것

### ① 재연결로는 구역이 안 따라온다 — 끊고 다시 거는 대상이 다르다

**증상(예상)** — 구역만 연결 설정으로 옮기고 기존 재연결 배선에 기대면, 주소를 바꿔
다시 붙어도 **옛 구역으로 구독**한다.

**원문** — `src/transport/WsTransport.ts`

```
subscribe(selector, handler, scope) {
  const sub = { id, selector, scope, handler };
  this.subs.set(id, sub);          // ← selector 가 여기 값으로 박힌다
...
ws.onopen = () => {
  for (const sub of this.subs.values()) this.sendSubscribe(sub);   // ← 박힌 그대로
```

**원인** — 주소 변경의 반영 방식은 `singleton.close(); singleton.connect();` 이고,
`onopen` 이 **저장된 selector 를 그대로 재전송**해 구독을 복원한다. 그 복원이 구역에는
불리하게 작동한다 — 주소만 새것이고 selector 는 옛것이다.

**조치** — 끊고 다시 거는 대상을 **소켓이 아니라 구독**으로 잡았다. 문법은 같다:

```
transport/index.ts   applied 합성 키 비교 → close(); connect();
tabs/data/index.ts   applied 구역 비교    → unsubscribe(); subscribeZone(next);
```

### ② 🔴 3층 모양이 아닌 payload 를 「미배포」로 단정한다

**증상** — 관문 C-a 에서 백엔드가 보낸 로봇이 화면에 **「미배포」**로 뜬다.

**원문** — `src/tabs/data/statusModel.ts`

```ts
if (layers === null) return 'unknown';
if (layers.deployment !== 'deployed') return 'not_deployed';   // ← 여기
```

**원인** — 실측대비용 `/state` 어댑터는 **원래 메시지를 통째로** payload 에 넣는다
(실측준비 v2.2 §3-1-1). 가용성 판정이 Phase 5 라 `availability`·`deployment` 가 없다.
그러면 `undefined !== 'deployed'` 가 참이 되어 첫 분기에서 빠져나간다.

**미배포는 「배포된 적이 없다」는 사실 주장**인데 우리가 아는 것은 「모양을 모른다」뿐이다.
없는 상태를 지어내는 쪽이 빈 화면보다 나쁘다 — 빈 화면은 이상하다고 느끼지만
「미배포」는 그럴듯해서 그대로 믿는다.

**조치** — 3층 모양이 아니면 「알 수 없음」으로 두는 가드를 앞에 넣었다. 기존 판정 6종은
검사로 그대로임을 못 박았다.

### ③ `ObservabilityPanel` 이 없다 — 봉투 수는 화면에 안 뜬다

**증상** — 프롬프트가 든 판정 수단 하나를 쓸 수가 없다.

**원문** — `src/tabs/data/selfObservability.ts`

```ts
const body = JSON.stringify(snapshot());        // envelope_count 가 여기 들어간다
void fetch(GATEWAY.http + '/observability/client-metrics', { method: 'POST', ... });
```

**원인** — 자체 관측은 **발행만 한다.** 60초 주기로 POST 하고 그 값을 그리는 부품이 없다
(`src/tabs/views/` 에 `MetricsView` 는 있지만 이 값을 안 읽는다). 저장소 전체에
`ObservabilityPanel` 이라는 이름이 0건이다.

**조치** — 화면 판정을 새 카드의 「받은 봉투 n건」(`EntityRecord.envelopeCount`)으로 잡고,
**판정 수단이 한 자리뿐이라는 사실을 정리 문서 §5 에 적었다.** 새 패널을 만들지는 않았다 —
프롬프트 범위 밖이고, 필요하면 별도로 정할 일이다.

### ④ 장비 id 는 주석에도 못 적는다

**증상** — `verify:physical-port` 가 새 파일을 잡았다.

```
❌ src\tabs\views\UnregisteredCard.tsx: 하드웨어 장비 id 이 경계 밖에 있다
```

**원인** — 그 검사는 주석을 걷지 않는다. 설명에 예시로 적은 로봇 개체 키가 걸렸다.
규칙의 뜻(*"로봇을 아는 면이 `src/physical/` 하나"*)을 보면 **주석도 안 적는 쪽이 맞다** —
다음 사람이 거기서 값을 복사해 갈 수 있다.

**조치** — 주석에서 실제 키를 빼고 「로봇 개체 키」로 바꿨다. 왜 안 적는지도 같이 적었다.

## 3. 결정한 것

### ① 구역 값을 어디에 둘 것인가

**물음** — `zone-503` 을 `zoneA` 로 바꿀 것인가?

**선택지**
- (가) 상수를 `zoneA` 로 바꾼다 → **목 게이트웨이 구독이 0건**이 돼 기존 시연 경로가 빈 화면
- (나) 상수를 `zone-503` 으로 둔다 → **관문 C-a 가 성립하지 않는다**
- (다) 값을 **붙는 게이트웨이를 따라가게** 한다

**답 — (다).** 인계문서가 「목 게이트웨이는 그대로 두고 `/state` 를 추가한다」고 했으므로
둘이 공존해야 하고, 그러면 구역은 주소와 **한 묶음**이어야 한다. (가)·(나)는 둘 다
어느 한쪽을 죽인다. 기본값은 `zone-503`(목) 그대로 두어 **기존 경로가 그대로 돈다.**

### ② `RiskPanel` 은 구독 구역과 같은 값을 써야 하는가 — **그렇다**

`RiskPanel.tsx` 는 `r.registry?.zone === <구역>` 으로 거른다. 구독 구역과 갈라야 할 이유를
찾아봤으나 없다:

- 거르는 대상이 `entities` 이고, 그 `entities` 를 채우는 것이 **바로 그 구독**이다.
  구독 구역이 `zoneA` 인데 필터가 `zone-503` 이면 **들어온 값을 스스로 다시 버리는** 꼴이다.
- `DeviceGrid` 가 **같은 축**으로 거른다. 둘이 다른 값을 쓰면 같은 화면의 두 판이 다른
  개체 집합을 보인다.

→ 셋 다 같은 `useZoneId()` 를 쓴다.

### ③ `canvas/scope.ts` 의 `ViewScope.zoneId` 를 갈라야 하는가 — **아니다**

프롬프트가 「갈라야 할 이유가 있으면 고치지 말고 보고하라」고 했으므로 끝까지 따라갔다.

```
canvas/scope.ts  viewScopeFor() → ViewScope.zoneId
  → tabs/viewNodes.tsx:94   useZoneSummary(scope.zoneId)
    → tabs/data/hooks.ts    new ZoneSummaryFeed(store, zoneId)
      → tabs/data/summary.ts:31   if (rec.registry?.zone !== zoneId) continue;
```

**같은 축이다** — 레지스트리의 구역으로 집계를 거른다. `DeviceGrid`·`RiskPanel` 과 다르지
않다. **갈라야 할 이유가 없어서 같이 옮겼다.** 정리 문서 §8 ②를 이 결과로 닫았다.

### ④ 레지스트리 밖 카드에 `DeviceCard` 를 재사용할 것인가 — **아니다**

`DeviceCard` 는 payload 가 3층인 것을 전제로 층별 배지를 그린다. 백엔드 어댑터의 payload
에는 그 층이 없다. 재사용하면 **없는 판정**(「미배포」·「정상」)을 말하게 된다 — ②와 같은
종류의 거짓말이다. 그래서 **판정을 하지 않는** 별도 카드를 만들었고, 적는 것은 아는 넷뿐이다:
개체 키 · 받은 봉투 수 · 채널별 마지막 `ts`·`seq` · payload 원문.

검사가 그 성질을 못 박는다 — 그 카드가 `deriveDisplayStatus`·`DeviceCard` 를 쓰면 실패한다.

### ⑤ `useConnections()` 를 그대로 쓸 것인가 — **아니다**

그 훅은 주소 묶음 **전체**를 돌려주므로, STT 주소만 바꿔도 구역을 보는 부품이 전부 다시
그려진다. 값 하나로 좁힌 `useZoneId()` 를 뒀다.
