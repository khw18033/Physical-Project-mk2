# 분기와 루프 2단계 — 규칙이 갈래와 되돌아감을 만든다 (모델을 안 부른다)

**선행**: `253f9a9`(1단계 · 계약)
**대상**: `solveDeps.ts` · `VZ-G-02`
**날짜**: 2026-09-08

---

## 결론 먼저

**10단계 §7 이 찾은 실패가 규칙 층에서 사라졌다.** 마일스톤에 주석 한 줄을 적으면
`solveDeps` 가 갈래를 갈라 매달고, 뒤를 합류시키고, 되돌아가는 엣지를 낸다.

```
발화: 사람을 찾을 때까지 5층 복도를 계속 이동해   (마일스톤에 주석이 적혀 있을 때)

  T-1 [act]    복도 이동        deps=[]
  T-2 [verify] 이동 확인        deps=["T-1"]
  T-3 [sense]  관측             deps=["T-2"]
  T-4 [decide] 사람 판정        deps=["T-3"]
  T-5 [report] 발견 보고        deps=["T-4"]        ← pass 갈래
  T-6 [act]    이동 계속        deps=["T-4"]        ← fail 갈래 · 서로 안 매달린다
  T-7 [report] 임무 요약        deps=["T-5","T-6"]  ← 합류
  되돌아가는 엣지: T-6 → T-1                        ← deps 가 아니다
```

10단계에 나온 것은 `… → 이동 중지 → 정지 확인 → **이동 계속** → 종료` 였다.
**갈래 둘이 순차로 꿰여 「둘 다 차례로 한다」로 읽히던 것**이 이제 갈린다.

그리고 **11단계의 모양 경고가 저절로 조용해졌다.** 되돌아가는 엣지를 실제로 세도록
인자를 열어 뒀던 것이 값을 했다 — 경고 코드는 한 글자도 안 고쳤다.

**모델은 아직 이 주석을 안 낸다.** 그것이 3단계다.

---

## 1. 검사를 먼저 넣었다 — 실패하는 것을 보고 규칙을 고쳤다

계획이 정한 순서다. 규칙을 고치기 전에 검사를 넣으면 **고치기 전에는 실패하고 고치면
통과하는** 검사가 되고, 그것이 이 단계가 실제로 무언가를 했다는 증거다.

넣은 직후의 실패가 이랬다.

```
- MSN-260831-02: 규칙이 낸 되돌아감이 [없음] 인데 대본은 [T-27c→T-23a] 다
- 배타 분기: fail 갈래가 판정에 안 매달렸다 — C1 deps=["B1"]
- 배타 분기: 두 갈래가 순차로 꿰였다 — 「둘 중 하나」가 「둘 다 차례로」가 된다
- 합류: 분기 뒤가 갈래 전부에 안 매달렸다 — D1 deps=["C1"]
- 없는 마일스톤을 가리킨 주석을 무시했다는 기록이 없다
```

**둘째·셋째 줄이 10단계 §7 에서 본 그 실패다.** 손으로 만든 최소 목록에서 같은 모양이
재현됐고, 규칙을 고치자 사라졌다.

### 주석을 손으로 적는다 — 대본에서 뽑지 않는다

대본의 `refEdges` 에서 마일스톤 주석을 역산해 넣으면 **정답에서 입력을 만드는 것**이라
검사가 아무것도 확인하지 않게 된다. 그래서 「사람이 적었다면 이렇게 적었을 것」을
검사에 손으로 두고, 규칙이 그것을 펴서 **대본의 원래 엣지**를 내는지 본다.

```
PLAN_ANNOTATIONS['MSN-260831-02'] = [{ id: 'MS-F', repeatOf: { to: 'MS-C', when: 'fail' } }]
  → 규칙이 낸 것: T-27c → T-23a
  → 대본이 손으로 적은 것: T-27c → T-23a
```

이 주석이 정답셋으로 옮겨 갈지는 **3단계**에서 정한다(`extract-goldset` 이 지금은 일부러
안 뽑는다).

## 2. 규칙 — 「앞 블록」이 어느 블록인가만 바뀌었다

경계 규칙의 본문은 그대로다. 바뀐 것은 **매달릴 앞 블록을 고르는 자리** 하나다.

| | 앞 블록 |
|---|---|
| 갈래 (`branch.from` 을 적었다) | **그 마일스톤 하나.** 형제 갈래에는 안 매달린다 |
| 합류 (갈래가 아닌데 바로 앞이 같은 판정의 갈래들) | **그 갈래 전부** |
| 그 외 | 직전 블록 하나 (지금까지와 같다) |

되돌아감은 `deps` 를 **한 글자도 안 건드린다.** `layout.ts` 의 `depths()` 가 순환에서
무한 재귀하므로 그리기 전용 참조 엣지로만 편다 — 5단계에 겪었고 대본 2편 주석에 적혀 있다.
펴는 규칙은 「**끝 노드 → 첫 노드**」이고, 1단계가 그것으로 대본을 복원함을 확인했다.

### 주석은 선택 인자다 — 안 주면 글자 하나 안 바뀐다

```
solveDeps(nodes)                  지금까지와 완전히 같다
solveDeps(nodes, milestones)      주석이 있는 마일스톤만 규칙이 갈린다
```

그것이 **복원 기준선 46/51 이 안 흔들린 근거**다. 검사가 그것도 본다 — 빈 주석을 넘겼을
때 `deps` 가 같은지, 주석이 없는데 되돌아가는 엣지를 만들지 않는지(지어내기 §5).

### 앞을 안 가리키는 주석은 무시하고 **센다**

모델은 없는 마일스톤이나 **뒤**를 가리킬 수 있다. 그대로 매달면 순환이 생기므로 버리는데,
**조용히 버리면 왜 안 갈렸는지 아무도 모른다.** `ignoredPlan` 이 그 수를 센다 — 0이 정상이다.
`utterance` 덮어쓰기(9단계)·모델이 낸 `deps`(10단계)와 같은 규칙이다.

## 3. 클라이언트 호출 자리를 이었다

규칙이 서도 **앱의 유일한 호출자가 주석을 못 넘기면 죽은 코드**다. `proposal.ts` 가
생성된 임무의 마일스톤에서 `branch`·`repeat_of` 를 읽어 그대로 넘긴다 — 계약이 1단계에
그 자리를 열어 뒀으므로 모델이 적기 시작하면(3단계) 화면이 바로 그린다.

**노드에 얹지 않고 따로 넘긴다.** 노드마다 같은 값을 복사해 넣으면 그 둘이 어긋날 수
있고, 어긋난 순간 규칙이 조용히 다른 그래프를 만든다(계획의 위험 4).

그리고 `viewFromGenerated` 의 `refEdges: []` 가 실제 값으로 바뀌었다. 주석이 없으면
여전히 빈 배열이다 — **§5 가 막는 것은 지어내기**이고, 발화가 명시적으로 요구한 되풀이를
안 만드는 것은 원칙을 지키는 것이 아니라 사용자가 준 단계를 빼는 것이다.

### 새 대조군 둘은 **따로 봐야 했다**

기존 대조군 루프는 주석 없이 복원 수만 본다. 분기·되돌아감은 **주석을 넘겨야 도는
규칙**이라 복원 수가 한 글자도 안 바뀌고, 그 루프에 넣으면 「대조군이 통과했다」로 잘못
잡힌다. 무력화한 축은 그 축의 방법으로 봐야 대조가 성립한다 — 사본 둘을 따로 만들어
`solveDeps(nodes, plan)` 으로 확인했다.

사본마다 다른 파일 이름을 쓰는 것도 지켰다(11단계에 Node 모듈 캐시로 한 번 당했다).

## 5. 남은 것

1. **3단계 — 프롬프트.** 모델이 마일스톤에 `branch`·`repeat_of` 를 적게 한다.
   10단계 E 판의 교훈대로 **예시도 함께 켠다.**
2. **`branch` 축의 정답이 없다** (1단계에서 찾음). 정답셋의 갈라짐은 셋 다 병렬이다.
   계획에 적어 둔 선택지 셋 중에서 골라야 하는데, **이제 규칙이 무엇을 만드는지 봤으므로
   고를 수 있다** — 규칙은 배타 분기를 「같은 판정에 나란히 + 뒤에서 합류」로 만들고,
   그것은 병렬(제약이 없어서 남는 것)과 `deps` 모양이 **같다.**
   즉 **`deps` 만 봐서는 배타와 병렬을 못 가른다** — 채점은 `branch` 주석 자체를 봐야 한다.
   이것이 계획의 위험 3이 채점기에서 나타나는 정확한 형태이고, ③(2편의 재탐색을 배타
   분기로도 읽기)을 고르더라도 축은 주석을 보는 쪽으로 만들어야 한다는 뜻이다.
3. **4단계 — 화면.** 배타 분기와 병렬이 `deps` 모양이 같으므로 **캔버스에서도 같아
   보인다.** 「둘 다 한다」와 「둘 중 하나」를 표시로 갈라야 한다(계획의 위험 3).
   위 2번과 같은 뿌리다.
