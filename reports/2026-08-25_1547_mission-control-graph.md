# 2026-08-25 15:47 — 노드 그래프를 임무 관제 중심으로 정정

**직전 보고서**: `2026-08-25_1525_node-graph-editor.md`
**정정 이유**: 직전 구현은 데이터 파이프라인 편집기였고, 교수님이 요청한 핵심은 Sub task와 관측 노드를 잇는 임무 진행 관제였다.

## 무엇이 잘못 해석됐나

직전 그래프는 기존 `pipeline.schema.json`을 따라 다음 연결을 관리했다.

```text
데이터 source → transform → renderer sink
```

이것도 시스템에 필요한 구성 편집 기능이지만 교수님 방향의 주 그래프는 아니었다. 원하는
중심 모델은 다음이다.

```text
전체 임무 → Sub task 1 → Sub task 2 → …
               ├─ 로봇 실행 상태
               ├─ 영상 관측
               ├─ 센서 판단 입력
               └─ 제어 실행 결과
```

따라서 기존 구현을 폐기하지 않고 **데이터 파이프라인 보조 모드**로 내렸으며, 노드 그래프
탭의 기본 화면을 임무 관제로 교체했다.

## 구현 결과

- `plan`에서 전체 임무, Sub task 제목·구역·승인 상태를 구성한다.
- `plan_progress`에서 각 Sub task의 대기·진행·완료·실패·건너뜀 상태를 즉시 반영한다.
- 전체 임무에서 첫 Sub task, Sub task 사이의 선후행 연결을 그린다.
- 각 Sub task에 로봇·영상·수위 센서·수문 제어 노드를 연결하거나 해제할 수 있다.
- 근거 노드는 같은 데이터 스토어에서 해당 Entity의 실제 수신 상태를 표시한다.
- 실패 Sub task에는 실패 사유를 직접 표시하고, 이후 미하달 구간은 건너뜀으로 구분한다.
- 승인 대기 계획은 그래프에서 승인할 수 있으며 승인 전에는 진행 이벤트가 없어야 한다.
- 정상 임무와 4번 Sub task 실패 임무를 그래프 화면에서 재생할 수 있다.

## 화면 구조

| 모드 | 역할 |
|---|---|
| **임무 관제** (기본) | 임무·Sub task 실행 순서와 연결된 영상/센서/제어 근거를 실시간 관제 |
| 데이터 파이프라인 | source→transform→sink 구성 편집, 시험 실행, 명시적 반영, 되돌리기 |

두 그래프를 한 의미로 합치지 않았다. 임무 그래프는 **무엇을 어떤 순서로 수행하는가**, 데이터
파이프라인은 **데이터를 어떻게 가공해 표현하는가**를 관리한다.

## 검증

실제 목 게이트웨이 WS에 접속해 실패 임무를 재생하고 승인했다.

```text
Sub task 수                  5개
승인 전 plan_progress        0건
승인 후 진행 이벤트          8건
최종 상태                    done → done → done → failed → skipped
```

## 남은 경계

- Sub task와 근거 노드의 연결 편집은 현재 브라우저 세션 초안이다. 실제 임무 정의에 저장하는
  백엔드 계약이 없으므로 새로고침 후 기본 연결로 돌아간다.
- 영상 노드는 수신 상태와 연결 관계를 표시한다. 영상 픽셀은 기존 `영상 오버레이` 탭의
  프레임 버퍼를 사용하며, 임무 캔버스 안에 실제 영상을 삽입하는 것은 후속 UX 작업이다.
- 여러 Sub task의 병렬 실행·합류 조건은 현재 계획 계약이 순차 구간만 제공하므로 표현하지
  않았다. 백엔드가 의존성 edge를 제공하면 순차 배열 대신 그 edge를 그려야 한다.
- LLM은 임무나 그래프를 직접 운영 반영할 수 없다. 추후 초안 생성만 담당하고 사람 승인과
  시험·반영 경계를 그대로 거친다.
