# 로봇 어댑터(브리지) 인터페이스 계약

> 갱신: 2026-09-07 · 담당: HW 파트 · 브랜치: `HW`
> 목적: "새 로봇 = 어댑터 1개"를 성립시키는 **최소 계약**을 정의한다. 이 문서만 보고
> 새 로봇용 브리지를 작성하면 Unity 디지털 트윈·자율주행·명령 규약·말단 노드가 무수정으로 붙는다.

관련: 상위 명령 규약(MQTT5+Protobuf)은 [`README.md`](README.md), 배포 경로는 메모리 `pi1-deploy-path`.

## 0. 위치 — 어댑터는 어디에 있나

```
 Unity(디지털 트윈, PC)              라즈베리파이(엣지/온디바이스)              로봇
 ─────────────────────              ────────────────────────────            ──────
  경로계획·시각화·텔레옵   ── UDP ──►  [브리지]  ── 로봇 SDK ──►  액추에이터
  가상 GO1(상태 추종)      ◄─ UDP ──   go1_sdk_pc   ◄─ 텔레메트리 ─   IMU/odom
```

- **브리지는 로봇 옆(엣지)에 둔다.** 제어 루프가 ms 단위라 클라우드 지연을 허용하지 않기 때문이다.
- **로봇 종속 코드는 브리지 한 곳에만 있다.** 위층(Unity·규약·노드)은 로봇을 모른다.
- 레퍼런스 구현: `pi/robot/go1_sdk_pc.cpp` (Unitree Go1). 새 로봇은 이 파일에 대응하는 1개를 만든다.

## 1. 브리지가 해야 하는 일 — 두 줄 요약

| 방향 | 해야 할 변환 |
|---|---|
| **수신** (상위 → 로봇) | UDP로 온 속도 명령/경로를 그 로봇의 SDK 명령으로 변환해 구동 |
| **송신** (로봇 → 상위) | 로봇의 위치추정(odometry/IMU)을 표준 상태 포맷으로 만들어 UDP로 발신 |

이 둘만 계약대로 구현하면 나머지는 재사용된다.

---

## 2. 포트 맵 (기본값)

| 포트 | 방향 | 용도 | 페이로드 |
|---|---|---|---|
| 15100 | 상위 → 브리지 | 텔레옵 명령 / 모드 토글 | 텍스트 |
| 15110 | 상위 → 브리지 | 경로(자율주행) / 취소 | JSON / 텍스트 |
| 15101 | 브리지 → 상위 | 로봇 상태(위치·자세·속도) | 텍스트 |
| 15102 | 브리지 → 상위 | 명령 미러(상위가 보낸 게 실제 적용됐는지) | 텍스트 |
| 15104 | 브리지 → 상위 | 웨이포인트(시각화) | 텍스트 |
| 5009 | 브리지 → 상위 | 이동 여부(state_change) | JSON |

- 상위(Unity/planner) 주소·로봇 IP는 브리지 실행 인자로 받는다: `--robot_ip`, `--unity_ip`.
- 전송은 **평문 UDP**(제어/상태). 영상만 별도로 UDP+RTP(H.264).

## 3. 수신 계약 (상위 → 브리지)

### 3.1 텔레옵 — 15100
공백 구분 텍스트. 로봇 본체 기준(body frame) 속도.
```
<vx> <vy> <wz> <estop>
예) 0.200 0.000 0.000 0      # 전진 0.2 m/s
    0.000 0.000 0.500 0      # 좌회전 0.5 rad/s
    0 0 0 1                  # 정지(estop)
```
- `vx`=전진(+)/후진(−) m/s, `vy`=좌(+)/우(−) 횡이동 m/s, `wz`=좌회전(+) rad/s, `estop`=1이면 정지.
- 횡이동이 없는 로봇(차동구동)은 `vy`를 무시한다.
- **모드 토글**: `MODE 1`(상위 명령 적용) / `MODE 0`(무시). 상위가 텔레옵을 쓰기 전에 `MODE 1`을 보낸다.

### 3.2 경로 — 15110
`go1_path` JSON. 상위가 계획한 경로를 로봇 시작 자세 기준 상대 좌표로 전달.
```json
{"type":"go1_path","frame":"go1_local_start","path_id":1,
 "start_pose":{"x":0,"z":0,"yaw_deg":0},
 "position_tolerance":0.12,"default_speed":0.25,"point_count":2,
 "points":[{"index":0,"x":0.0,"z":0.0,"yaw_deg":0.0,"use_yaw":false},
           {"index":1,"x":0.0,"z":0.30,"yaw_deg":0.0,"use_yaw":true}]}
```
- 점 필드 순서 고정: `index, x, z, yaw_deg, use_yaw`. `z`=전진축, `x`=횡축(로컬).
- 최소 2점. 큰 JSON은 `CHUNK <pid>/<total>/<idx> <부분>` 로 분할 도착 → 재조립 필요.
- **취소**: `PATH_CANCEL` (텍스트) 수신 시 즉시 정지 + 경로 폐기.
- 브리지는 경로 시작 시 로봇 현재 yaw를 기준(anchor)으로 잡아 로컬→월드 변환한다.

## 4. 송신 계약 (브리지 → 상위)

### 4.1 상태 — 15101 (필수)
공백 구분 텍스트, 10필드. 매 제어주기 발신.
```
<seq> <tms> <x> <z> <yaw> <vx> <vy> <wz> <estop> <mode>
```
| 필드 | 의미 |
|---|---|
| seq | 증가 시퀀스 |
| tms | 타임스탬프(ms) |
| x, z | dead-reckoning 위치(m). z=전진축 |
| yaw | 자세(**라디안**) — 진행 방향과 일치하도록 보정 |
| vx, vy, wz | 현재 속도 |
| estop | 1=정지 상태 |
| mode | 로봇 모드. **99=경로완료 통지**, 98=취소 ACK |

- 위치는 odometry가 있으면 그걸, 없으면 **명령속도 적분(dead-reckoning)** 으로 만든다.
- Unity 가상 로봇은 이 스트림을 그대로 따라 움직인다(digital twin).

### 4.2 이동 여부 — 5009 (필수, 트윈 정합용)
로봇이 실제 이동 중일 때 상위가 "가상이 실로봇을 따라가야 한다"를 알도록 하는 신호.
```json
{"state_change": true, "motion_active": true, "source": "<bridge>",
 "mode": 2, "vx_cmd": 0.200, "vy_cmd": 0.000, "wz_cmd": 0.000}
```
- `state_change` = 이동 중(true)/정지(false). 변화 시 즉시, 그 외 ~0.3s 주기 발신.
- **필수 필드**: `state_change`, `motion_active` 둘 다 있어야 상위 파서가 인식한다.
- 이게 없으면 자율주행 이동 구간이 가상에 안 보이고 도착 시 순간이동한다(실측 확인된 함정).

### 4.3 명령 미러 — 15102 / 웨이포인트 — 15104 (선택)
- 15102: 실제 로봇에 적용된 최종 `vx vy wz estop`를 되돌려보냄(디버그·검증).
- 15104: `WAYPOINTS <n> <x0> <z0> <x1> <z1> ...` 월드 좌표(시각화).

## 5. 안전 계약 (필수 — 로봇마다 재검증)

이 부분은 공통화되지 않는다. 새 로봇마다 브리지에 다시 넣고 실기 검증한다.

| 요구 | 기준 |
|---|---|
| 무입력 자동정지 | 텔레옵/경로 입력이 일정 시간(레퍼런스 0.15s) 없으면 자동 정지 |
| E-stop | `estop=1` 수신 즉시 정지, 이후 재정지 상태 유지 |
| idle 자세 | 명령 없을 때 안전 자세(레퍼런스 Go1: force-stand) |
| 속도 클램프 | 상위가 보낸 값이 로봇 한계를 넘지 않도록 상한 클램프 |

> E-stop과 무입력 정지는 상위(LLM/Unity) 계획과 **무관하게** 엣지에서 항상 동작해야 한다.

## 6. 상위 명령 규약(MQTT5+Protobuf)과의 관계

- 위 UDP 계약은 **Unity 디지털 트윈 ↔ 로봇** 실시간 경로다.
- 별도로 관제/백엔드는 **MQTT5+Protobuf 규약**([`README.md`](README.md))으로 명령한다. 로봇의 능력은
  접속 시 `Capability{device_id, actions[]}`로 자동 발행되고, 각 명령은 `validate()`로 사전 검증된다.
- 새 로봇을 규약에 편입하려면 노드의 `ACTIONS{action: handler}`와 `validate(action, params)`만 구현한다.
- **주의(계약 설계가 상위 기능을 제한하는 실례)**: 현행 규약의 `Command.parameters`는
  `map<string,double>`(수치 전용)이라, "구역명" 같은 문자열 인자를 쓰는 태스크 배정은
  스키마 확장(문자열/열거형)이 선행돼야 한다.

## 7. 새 로봇 이식 체크리스트

1. 브리지 1파일 작성: `<robot>_bridge`(레퍼런스 `go1_sdk_pc.cpp` 복제 후 SDK 부분 교체)
   - 수신: 15100 텔레옵·`MODE`, 15110 경로·`PATH_CANCEL`·CHUNK → 로봇 SDK 명령
   - 송신: 15101 상태(10필드), 5009 state_change → 로봇 odom/IMU 기반
2. 안전 계층(무입력 정지·estop·idle·클램프) 구현·**실기 검증**
3. 정적 링크 권장(실행 위치 의존 제거). systemd 서비스로 등록(로봇 기립 동작이면 부팅 자동시작 금지)
4. 명령 규약 편입: 노드 `ACTIONS`/`validate` 구현 → Capability 자동 발행 확인
5. 좌표/자세 정합: yaw 기준(시작 자세 통일 또는 정렬 절차) — 절대 방위 센서 없으면 필수

**재사용(무수정)**: Unity 씬 전체 · MQTT5+Protobuf 규약 · 말단 노드(하트비트/LWT/버퍼) · 카메라 뷰어 구조.
**교체 대상**: 브리지 1파일 + 안전 계층 재검증. **로봇별 재확인**: 좌표 정합, 트윈 충실도(Sim-to-real).

## 8. 레퍼런스 값 (Go1)

- 로봇: `192.168.123.161`, HighCmd UDP `8082`, 브리지 localPort `8090`
- 속도 상한: 전진/횡 0.4 m/s, 회전 2.0 rad/s
- 무입력 정지: 0.15 s / dead-reckoning: 명령속도 적분 + IMU yaw
- 빌드: `g++ -O2 -std=c++17 -I include go1_sdk_pc.cpp libunitree_legged_sdk.a -lpthread -o go1_sdk_pc` (정적)
