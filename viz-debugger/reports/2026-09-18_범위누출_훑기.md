## 1. 훑은 방법

범위 22개 파일이 `import` 하는 이름을 따라가, **그 이름의 선언 몸통 안에 한글이
있는지**를 봤다. 파일 단위가 아니라 **가져온 이름 단위**다 — 「함수 하나만
가져왔는데 한글은 다른 export 에 있는」 경우를 세지 않기 위해서다.

### 훑기를 처음 돌렸을 때 놓친 것

선언 몸통을 자를 때 괄호를 세는데, 타입 표기가 먼저 나오면 속는다.

```ts
export const CONNECTION_TARGETS: readonly ConnectionTarget[] = [
//                                                        ^^ 열자마자 닫힌다
```

`T[]` 의 대괄호에서 깊이가 0으로 돌아가 **몸통을 한 글자도 안 읽었다.**
그래서 1차 결과가 「4곳 20건」이었고, 가장 큰 24건이 통째로 빠져 있었다.
`=` 뒤부터 세도록 고치니 **33곳 130건**이 나왔다.

> 검사에 이 함정을 주석으로 남겼다. 같은 실수를 다음 사람이 할 자리다.

### 결과

| 갈래 | 건수 |
|---|---:|
| 범위 파일이 **직접 그리는 값** — 2단계가 놓친 것 | **108** |
| 범위 밖 **컴포넌트**가 스스로 그리는 것 — 4단계 몫 | 22 |

당신이 찾은 27건이 아니라 **108건**이었다.

### 값이 아니라 **키**를 담는다

이 목록들 대부분이 **모듈 최상위 상수**다. 거기서 `t()` 를 부르면 `import` 시점에
한 번 평가되어 **그때의 언어로 굳고, 언어를 바꿔도 안 변한다** (1단계 보고서 §3 ①).

```ts
// 전
export const CONNECTION_TARGETS = [{ id: 'physical', label: '로봇 (MQTT 브로커)', … }];

// 후 — 이름까지 바꿨다. 다음 사람이 그 칸에 한글을 도로 적지 않게.
export const CONNECTION_TARGETS = [{ id: 'physical', labelKey: 'conn.target.physical', … }];
//                                              ↑ 읽는 자리에서 t() 로 푼다
```

함수 안의 문자열(`nowPlaying()`·`checkPhysical()`·`pauseMission()`)은 그릴 때마다
불리므로 **만드는 자리에서 그냥 `t()`** 를 부른다. 굳을 일이 없다.

## 3. 옮기지 **않은** 것 셋 — 옮기면 안 되는 것들

### ① `PROVISIONAL_NOTE` — 계약에 실려 나간다

`UtterancePanel` 이 이 문자열을 명령의 `threshold_status` 파라미터로 **그대로
싣는다.** 게이트웨이와 기록에 남는 기계가 읽는 값이고, 화면 언어에 따라 달라지면
**같은 판정이 두 값으로 기록된다.**

계약 값으로 그 파일에 남기고, 화면에 적을 때 쓸 키(`stt.provisionalNote`)를 따로
뒀다 — 한국어 값은 같은 글자다. 검사가 이 이름을 예외로 못박고, 대조군이
「계약 값은 잡으면 안 된다」를 시험한다.

### ② `HealthLine.reason` 과 클라이언트의 `detail`

그 칸에는 `error.message`·`status.reason`·탐색기가 돌려준 사유처럼 **우리가 쓴 적
없는 문장**이 실린다. 키로 바꿀 수 없다. 우리가 쓴 사유만 만들 때 풀어 넣는다.

확인을 누른 뒤 언어를 바꾸면 그 줄은 눌렀을 때의 언어로 남는다 — **지난 사건의
기록**이므로 그것이 맞다고 판단했다.

### ③ 언어 세그먼트의 「한국어」·「English」

각 언어를 그 언어로 적는다. 영문 화면에서 `Korean` 이면 한국어 쓰는 사람이 못 찾는다.
**보조 이름 둘**(앞의 「언어」와 화면 낭독용 이름)만 옮겼다.

## 4. 의존 없는 두 파일은 키만 돌려준다

`stt/availability.ts`·`generate/availability.ts` 는 머리 주석이
「**의존 없는 순수 함수 하나**」라고 적어 두었고, `verify:no-stt`·`verify:no-llm` 이
그 함수를 그대로 불러 검사한다. 거기서 `t()` 를 부르면 사전과 언어 모듈이 딸려
들어와 그 성질이 깨진다.

그래서 `note: string` 을 둘로 갈랐다.

```ts
noteKey: string | null;      // 우리가 쓴 문장 — 사전 키
noteDetail: string | null;   // probe() 가 준 사유 — 글자 그대로
```

읽는 자리(`UtterancePanel`)가 둘을 붙여 적는다. 검사 둘은 이름을 따라가고
**한 칸 더 본다**: 키가 있는지만이 아니라 **사전에 그 키의 값이 있는지**까지.
없으면 화면에 키 문자열이 그대로 뜬다.

## 5. 검사 — 무르게 하지 않고 잣대를 옮겼다

옛 글자를 짚던 검사 **일곱**이 빨개졌다. 전부 규칙은 그대로 두고 키 대조로 바꾸면서,
**모두 한 칸씩 더 보게** 했다.

| 검사 | 무엇이 바뀌었나 |
|---|---|
| `verify:connection-panel` | 줄 이름 → 키. **그 키가 사전에 있는지**도 본다 |
| `verify:one-broker-address` | 〃 + **사전 값이 「로봇」 그대로인지** |
| `verify:mission-history` | 결과 딱지 → 키. ko 값 대조 + **en 에도 있는지** |
| `verify:notifications` | `SOURCE_WORDS` → `SOURCE_WORD_KEYS` 이름 추적 |
| `verify:nav-feed` | 문구 → 키. 사전 값이 「유니티로 세우라」를 말하는지 |
| `verify:no-stt` · `verify:no-llm` | `note` → `noteKey`+`noteDetail`. 사유가 **키를 안 바꾸는지** 새로 본다 |

`verify:mission-history` 는 **글자만 보던 탓에** 「완료·실패·정지」가 영문 화면에
남아 있는 것을 못 봤다. 이제 영어 사전까지 본다.

### 신설 — `verify:i18n-scope-leak` (63번째)

파일 목록으로 그은 범위가 **다시 새지 않게** 한다.

1. 두 검사(`i18n-demo-path`·`i18n-scope-leak`)가 **같은 범위 목록**을 본다 — 갈라지면
   서로 다른 것을 지킨다
2. 범위 파일이 `import` 한 이름의 몸통에 표시용 한글이 **0건**
3. 4단계로 미뤄 둔 둘이 **실재하고 아직 한글이 남아 있다** — 다 옮겼는데 목록에
   남겨 두면 그 파일을 눈감는다

**대조군 셋** — 원천 모듈에 한글 상수를 심은 사본은 **잡고**, `import type` 과
계약 값은 **통과시킨다**.

> `import type` 을 통과시키는 것이 중요하다. 타입만 가져오면 값이 안 오고,
> 글자도 안 온다. 이것을 안 가르면 검사가 잡는 것의 절반이 헛것이 된다.

## 6. 덤 — `verify:voice-audit` 가 검사 위생을 안 지키고 있었다

`confidence.ts` 가 사전을 들이자 이 검사가 죽었다.

```
Cannot find module 'C:\…\Temp\i18n\dict.ts'
  imported from C:\…\Temp\verify-utterance-8WOQqS\confidence.ts
```

대조군 사본을 `os.tmpdir()` 에 만들고 있었다. 이것은 **`scripts/lib/scratch.mjs` 의
머리 주석에 적혀 있는 바로 그 함정**이다 —

> 「상대 경로가 풀리려면 **원본 옆**에 있어야 한다. `os.tmpdir()` 에 두면 import 가 깨진다.」

260917 검사 위생 때 12개 검사를 옮겼는데 이것 하나가 빠져 있었고, 원본에 상대
import 가 없어서 **그때까지는 드러나지 않았다.** `makeScratch` 로 옮기고, 사본이
한 칸 깊어지는 만큼 상대 경로를 올리는 `reroot()` 를 뒀다.

## 9. 사람이 눌러 봐야 하는 것

**브라우저 자동화가 이 저장소에 없다. 내가 화면을 본 적은 없다.** 아래는
이번 변경이 실제로 닿는 자리이고, 눌러 봐야 아는 것들이다.

`?lang=en` 으로 열고:

1. **연결 관리 (⇄)** — 대상 아홉의 이름·설명·주소 칸이 전부 영어인가.
   「확인」을 눌러 나오는 줄 이름(Broker · Agent · Robot)과 사유가 영어인가.
2. **주소 프리셋 드롭다운** — 로봇과 객체 탐지. 항목 이름과 마우스를 올렸을 때
   뜨는 설명이 영어인가.
3. **상단 표시등** — 끊긴 줄이 있을 때 「Robot Broker down」처럼 뜨는가.
4. **임무 이력 (◷)** — 결과 딱지가 Done/Failed/Stopped 인가.
5. **상단 안내줄** — 재생 전/중/끝에서 영어인가.
6. **알림 판** — 갈래가 External AI · Command · Connection 인가.
7. **자리표시 카드와 팔레트** — 축 이름(Position · Water level …)이 영어인가.
8. **발화 패널** — STT 를 꺼 놓고 열어 「The STT service is unreachable…」이 뜨는가.
   판정 딱지가 Accept/Needs re-confirmation/Reject 인가.
9. **정지 버튼** — 브로커를 끊고 눌러 「Could not send the stop command …」가 뜨는가.
10. **언어 세그먼트** — 앞의 이름이 `Language` 이고 버튼은 여전히
    `한국어` · `English` 인가. **버튼이 `Korean` 이 되면 그것이 잘못된 것이다.**

그리고 `?lang=ko` 로 다시 열어 **①~⑩ 이 전과 한 글자도 다르지 않은지.**

> ⑨ 는 브로커를 실제로 끊어야 보인다. ①의 「확인」은 상대가 없어도 사유 줄이
> 뜨므로 볼 수 있다.

  (≈10%) 인데, `flex-wrap: wrap` 과 `min-height` 가 있어 잘리지 않고 늘어날 것으로
  본다. **본 적 없다.**
- 이번에 늘어난 문장 중 **연결 관리 판의 `what` 설명**이 영어로 가장 길다
