# HCI 전달본 — 임무 디버깅 가시화 초안

`npm run build`의 `dist/`는 6탭 통합 셸이며, `npm run build:standalone`의 `dist-standalone/`는 탭①만 담는다. 둘 다 임무 `MSN-260826-01` 데이터를 번들에 내장하므로 게이트웨이 없이도 화면이 채워진다. 로컬 개발은 `npm run dev`로 실행한다.

## 화면 다섯 개

1. **마일스톤 진입 화면**: 발화 패널, 마일스톤 7건, 하드웨어 7대를 함께 본다. 하드웨어 카드를 마일스톤에 드롭하면 하위 태스크의 대상 표시가 바뀌고, 마일스톤 클릭으로 그래프에 진입한다.
   **발화 패널은 이제 목이 아닙니다** — 마이크로 말하면 실제로 인식되고, 파형은 실제 입력 레벨이며, 인식된 문장을 그 자리에서 고칠 수 있습니다(원문과 수정본을 둘 다 보관합니다). 진행 막대 다섯 칸 중 **앞 두 칸만 실제**이고, 뒤 세 칸(`의도 분석`·`마일스톤 분리`·`태스크 생성`)은 아직 목이라 `목` 배지가 붙어 있습니다. STT 서비스를 띄우지 않으면 음성 기능만 꺼지고 문장을 직접 넣는 경로가 열립니다.
2. **태스크 그래프**: MS-C의 분기·합류 DAG와 태스크 상태, 배정 장비 연결 상태를 본다. 스크래치 블록처럼 노드를 드래그해 옮길 수 있고 연결선이 따라간다. 노드를 더블클릭하면 액션 상세로 내려간다. DAG/트리 토글로 두 표현을 비교한다.
3. **D-03 액션 아이템 상세**: T-31의 네 액션과 Unitree Go1 상태 스트립, 평가 근거를 한 팝업에서 본다. 버튼 조작은 메모리와 콘솔에 `produced_by=human`으로 남는다.
4. **D-04 리플레이**: D-02와 같은 그래프에 재생 시각을 주입한다. 슬라이더를 움직이면 해당 시점 상태로 다시 칠하고, 아래 타임라인과 임무 이력을 함께 본다.
5. **D-05 실패 수정**: T-35 실패와 역방향 관련 노드를 강조한다. 팝업 입력값을 바꿔 반사실 실행 또는 재실행을 눌러볼 수 있다.

초안은 정보 구조 논의를 위한 것이며 색, 여백, 애니메이션, 반응형은 의도적으로 다듬지 않았다. 모든 자료는 목 데이터다.

## 논의하고 싶은 항목 8건

1. **계층 전환** — 세 계층을 한 화면에 둘 것인가, 계층별로 전환할 것인가
2. **상태 여덟 개의 표시** — 색·테두리·아이콘·회차 배지를 어떻게 조합할 것인가. 특히 건너뜀과 미수행이 한눈에 구분되어야 한다
3. **실패 경로 격리의 표현** — 나머지를 숨길 것인가, 흐리게 할 것인가, 접을 것인가
4. **되감기 조작** — 슬라이더·단계 이동·사건 지점 점프 중 무엇을 줄 것인가
5. **사용자 계층별 표시 깊이** — 비전문가에게 무엇을 감출 것인가
6. **하드웨어 배정 방식** — 드래그로 마일스톤에 놓는 방식이 자연스러운가
7. **명령 버튼의 배치** — 보는 화면에 실행 버튼을 섞을 때의 오조작 위험
8. **인식 결과 수정을 어디서 하게 할 것인가** — 발화 패널 안인가, 별도 확인 단계인가. 지금은 패널 안에서 바로 고치게 되어 있는데, 잘못 인식된 문장이 이미 화면에 보이는 상태에서 고치는 것이 편한지 아니면 "이 문장이 맞습니까" 단계를 따로 두는 것이 안전한지가 갈립니다. 신뢰도가 낮을 때는 지금도 재확인 체크를 요구합니다
