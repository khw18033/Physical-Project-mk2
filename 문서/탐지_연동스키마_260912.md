# 관제 웹 ↔ 객체 탐지 — 연동 스키마 (2026-09-12 · **2026-09-14 갱신**)

## 요점 하나

**필드 이름을 바꿔 달라고 하지 않는다.** `door_example/` 에 있는 모양 그대로 주면 된다 —
`rotation_deg` 도 `found` 도 `box_xyxy` 도 `final_score` 도 그대로다. 화면이 읽는 모양으로
바꾸는 것은 **관제 웹이 한다**(`src/detect/parse.ts` 한 곳).

**바꿔 달라고 하는 것은 없다.**

---

## 1. 탐지 → 관제 웹 : 우리가 받아 간다

**밀어 주지 말고 열어만 주면 된다.** 관제 웹은 브라우저 페이지라 남이 보내는 요청을 못
받는다. 우리가 주기적으로 물어본다 — 한 각도가 도는 동안은 1.5초마다, 여덟을 다 본 뒤에는
6초마다.

**한 판의 경계를 우리가 알려 주지 않는다.** 시작·종료를 알리는 명령이 없고 `command_id` 도
안 붙는다. 한 판은 **새 결과가 들어오는 것**으로 잡으면 된다.

**언제부터 묻나.** 사람이 화면에서 「임무 시작」을 누른 뒤부터다. 승인만 해서는 요청이
하나도 안 나간다. 각도별 결과는 로봇이 돌기 시작한 뒤에 는다.

**시작 때 남아 있던 결과는 지난 판으로 본다** (2026-09-14). 「임무 시작」 첫 물음에 이미 각도
결과가 있으면 화면은 그것을 쓰지 않고, **목록이 비워진 뒤 새로 쌓이는 것만** 받는다. 새 스캔이
시작될 때 지난 판 산출물을 지우는 지금 수신기의 동작(`scan_start` → 정리)이 그대로 맞다.

### ① 각도별 결과 — `target_summary.json` 과 같은 모양

```http
GET /detect/results?target=door
```

```json
{
  "target_class": "door",
  "frames": [
    { "frame": "frame_000001.jpg", "rotation_deg": 0.0, "found": false },
    { "frame": "frame_000113.jpg", "rotation_deg": 270.0, "found": true,
      "absolute_bearing_deg": 16.3,
      "rel_depth": 10.02, "distance_cm": 0.0, "in_valid_calibration_range": false }
  ]
}
```

| 필드 | 우리가 어떻게 쓰나 |
|---|---|
| `rotation_deg` | **칸 번호로 바꾼다** — `rotation_deg / step_deg`. 0·45·…·315 → 0~7 |
| `found` | 그 칸이 「문 있음」인가 |
| `absolute_bearing_deg` | **근거에만** 적는다. 화면이 가리키는 방향은 `rotation_deg` 다 |
| `distance_cm` | `in_valid_calibration_range` 가 `true` 일 때만 쓴다 |

`localization_ok` 는 **안 쓴다.** 시료에 있으니 그대로 둬도 되고 빼도 된다.

**아직 안 본 각도는 배열에서 빼면 된다.** `found: null` 같은 걸 넣지 않아도 된다.
한 각도가 끝날 때마다 배열이 하나씩 느는 것이 우리가 기대하는 모양이다.

### ② 각도별 근거 — `frame_0000NN/evidence.json` 과 같은 모양

```http
GET /detect/evidence?target=door&frame=frame_000113.jpg
```

```json
{
  "frame": "frame_000113.jpg", "rotation_deg": 270.0,
  "box_xyxy": [140.76, 89.67, 160.93, 143.73],
  "feature_similarities": { "a door's handle": 0.2319, "…": 0.0 },
  "final_score": 0.2696,
  "mandatory_gates": {
    "color_gate":  { "required": true, "passed": true, "winning_color": "a door's light blue color" },
    "shape_gate":  { "required": true, "passed": true, "winning_shape": "a rectangular shape" },
    "reference_image_gate": { "required": true, "passed": true, "similarity": 0.79, "threshold_min": 0.75 },
    "saturation_gate": { "required": true, "passed": true, "median_saturation": 108, "min_saturation": 85 }
  }
}
```

**못 찾은 각도에는 이 파일이 없는 것이 정상이다.** 404 로 주면 된다 — 우리는 찾은 각도만
물어본다.

우리가 여기서 하는 일 셋.

- `box_xyxy` → `[x, y, w, h]` 로 바꾼다 (**우리가 한다.** 바꿔 주지 않아도 된다)
- `final_score` 를 **「특징 최고값」**이라고 적는다. 확률이 아니므로 퍼센트로 안 그린다
- `mandatory_gates` 로 **한국어 한 문장을 우리가 조립한다** — `reason` 을 안 줘도 된다

> 화면에 뜨는 실제 문장:
> `색 light blue · 모양 rectangular · 기준영상 0.79/0.75 · 채도 108/85 통과 · 특징 최고값 0.27`

### ③ 경로 산출 — `evidence.json` 과 같은 모양

```http
GET /detect/path?target=door
```

`robot_position_cm` · `current_heading_map_deg` · `turn_instruction` ·
`forward_distance_cm` · `standoff_cm` · `goal_cm` · `path_calculation` 를 그대로 주면 된다.

`path_calculation` 의 **식과 대입값이 문자열로 들어 있는 것이 특히 좋다.** 화면이 그대로
네 줄로 그려서 「왜 90도를 돌았나」에 답한다 — 우리가 다시 계산하지 않는다.

**스캔이 끝나야 나오는 것이 맞다.** 그 전에는 404 로 주면 된다.

### ④ 무엇을 그 클래스라고 물었나 — `features_sent.json`

```http
GET /detect/features?target=door
```

### ⑤ 그림

```http
GET /detect/frame?target=door&frame=frame_000113.jpg&kind=original
→ image/jpeg
```

`kind` 는 `original` · `rpn_overlay` · `target_overlay` · `target_crop` 넷.

```http
GET /detect/path_overlay?target=door
→ image/jpeg   (도면 위에 경로를 그린 것)
```

**로컬 절대경로를 JSON 에 넣어 주는 것은 소용이 없다.** 받은 시료의
`/home/jin24/…/original.jpg` 같은 값은 브라우저가 못 연다. 위 주소로 바이트를 주면 된다.

### ⑥ 헬스 체크

```http
GET /health → 200
```

발표 직전에 눌러 볼 버튼용이라 가벼울수록 좋다.

### ⑦ 자세 역산 — `unidepth_localization/localization_evidence.json` 과 같은 모양 (신설)

```http
GET /detect/localization
```

```json
{
  "ok": true,
  "door_position_cm_fixed_from_gt": [922.8, 327.8],
  "robot_position_cm": [236.2, 126.9],
  "current_heading_map_deg": 106.3,
  "rotation_calculation": { "step1_map_bearing_to_pedestal": { "formula": "…", "substituted": "…" } }
}
```

**스캔보다 먼저 올 필요가 없다** (2026-09-14 변경). 지금 수신기처럼 **한 바퀴를 다 받은 뒤에**
계산해 내주면 된다.

전에는 화면의 `T-A1`·`T-A2` 가 이 값을 기다렸는데, 그러면 두 노드가 대기인 채로 로봇이 돌았다.
이제 그 둘은 화면이 돌기 전에 스스로 끝낸다.

| 노드 | 무엇으로 끝나나 |
|---|---|
| `T-A1` 2D 맵에서 문 위치 확인 | ⑧ 도면을 받는다. 문 자리는 `DOOR_PX` 와 **같은 GT 고정값**을 화면도 들고 있다 |
| `T-A2` 로봇 현재 위치와 각도 파악 | 로봇이 5초마다 보내는 `state.position.heading_deg` (오도메트리 방위) |

이 값이 오면 `T-A2` 의 액션 아이템에 **「탐지가 역산한 도면 기준 방위」** 로 덧붙는다.
로봇이 보고한 방위와 나란히 놓여 견줄 수 있다. 문 자리가 `DOOR_PX` 에서 바뀌면 화면의
`viz-debugger/src/detect/floorPlan.ts` 도 같이 바꿔야 한다.

`target` 을 안 붙인다. 문과 받침대 어느 한쪽의 산출물이 아니라 **둘을 합쳐 만든 것**이라
클래스 폴더 밖에 있다.

### ⑧ 기본 도면 (신설)

```http
GET /detect/map
→ image/jpeg   (아무것도 안 그린 도면)
```

시료의 `unidepth_localization/map_original.jpg` 다. 화면은 `T-A1` 이 끝나면 이 도면을 2D 맵 자리에
띄우고, 경로가 나오면 ⑤ 의 `path_overlay` 로 바꾼다.

**새 판 직후 404 여도 된다** (2026-09-14). 도면은 판마다 바뀌는 결과가 아니라 방의 그림이라,
창구에 아직 없으면 화면은 저장소에 있는 같은 도면으로 대신한다. 각도 결과·경로 같은 판의
산출물은 대신하지 않는다.

## 2. CORS

브라우저에서 직접 부르므로 **응답에 헤더가 필요하다.** 없으면 요청 자체가 막혀 화면에는
「닿지 않습니다」만 뜬다.

```
Access-Control-Allow-Origin: *
```

그림(`image/jpeg`)에도 같이 붙여야 한다.

## 3. 우리 쪽이 이미 정한 것 (참고)

탐지 쪽에서 해 줄 일은 없고, 화면이 어떻게 그리는지 알고 있으면 좋은 것들이다.

| 상황 | 화면이 하는 일 |
|---|---|
| 여덟을 다 보기 전 | **아무 판정도 안 칠한다.** 칸은 「탐색 중」으로 켜져 있고 답은 없다 |
| 여덟째가 들어온 순간 | 여덟이 **한 번에** 갈린다 — 초록 하나와 흐림 일곱 |
| 여러 각도에서 `found` | **초록은 하나.** 점수가 가장 높은 각도. 동점이면 먼저 본 각도 |
| 찾았지만 안 고른 각도 | 「문 후보 — 점수가 더 높은 각도가 있어 안 고름」. **「문 없음」이 아니다** |
| 하나도 못 찾음 | 「문을 찾지 못함」에서 멈춘다. **임의로 한 방향을 고르지 않는다** |
| `in_valid_calibration_range: false` | 거리를 **안 그린다** (0.0m 로 그리면 거짓이다) |

**부분 결과로 부분 판정을 하지 않는다** (2026-09-14 변경). 세 각도만 와 있으면 세 칸이
「탐색 중」일 뿐이고 초록도 탈락도 없다. 전에는 못 찾은 각도를 오는 대로 흐리게 칠했는데,
화면에서는 **여덟이 하나씩 희미해지다가** 하나만 남는 모양이 돼서 답이 각도마다 정해지는
것처럼 보였다. 실제 순서는 그 반대다.

받은 시료에서 270도와 315도가 **둘 다** 찾혔고 점수 차이가 `0.0016` 이었다. 첫 줄의 규칙이
첫 판부터 쓰인다는 뜻이다.

## 4. 붙기 전에 미리 맞춰 두는 길

연결 관리의 **객체 탐지 → 「테스트」** 를 켜면 화면이 `door_example/` 을 진짜 결과처럼
읽는다. 목을 지어낸 것이 아니라 **받은 값 그대로**다.

그래서 탐지 서비스가 서기 전에 화면 쪽은 이미 다 맞춰져 있다. 서비스가 서면 체크를 끄고
주소를 넣는 것으로 끝난다 — 그때 위 §1 의 모양이 같으면 코드를 안 고친다.

시료를 읽을 때 **한 각도씩 4초 간격으로** 내놓는다. 파일에는 여덟이 다 들어 있지만 그대로
쓰면 시작하자마자 답이 정해진 화면이 되기 때문이다. 실제 서비스에서도 같은 모양을 기대한다.

### 지금 실제로 오가는 것 (2026-09-14)

서비스가 서면 화면이 던지는 요청은 이 순서다. **여기 없는 것은 안 던진다.**

| 순서 | 요청 | 언제 |
|---|---|---|
| 1 | `GET /detect/localization` | 「임무 시작」 직후부터 **올 때까지** 매 폴링. 오면 안 묻는다 |
| 2 | `GET /detect/results?target=door` | 1.5초마다. 여덟이 다 차면 6초마다 |
| 3 | `GET /detect/evidence?target=door&frame=…` | **찾은 각도만**, 각도마다 한 번 |
| 4 | `GET /detect/features?target=door` | **올 때까지** 매 폴링. 오면 안 묻는다 |
| 5 | `GET /detect/path?target=door` | 여덟이 다 찬 뒤부터 |
| 6 | `GET /detect/map` · `/detect/path_overlay?target=door` · `/detect/frame?…` | 화면이 그림을 그릴 때 |
| — | `GET /health` | 연결 관리에서 「확인」을 누를 때만 |
