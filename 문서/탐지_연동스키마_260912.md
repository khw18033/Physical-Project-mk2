# 관제 웹 ↔ 객체 탐지 — 연동 스키마 (2026-09-12)

탐지 담당에게 전달하는 문서다. [`탐지_명령규약_260910.md`](탐지_명령규약_260910.md) 를
**받은 산출물에 맞춰 다시 쓴 것**이고, 그 문서를 대체한다.

## 요점 하나

**필드 이름을 바꿔 달라고 하지 않는다.** `door_example/` 에 있는 모양 그대로 주면 된다 —
`rotation_deg` 도 `found` 도 `box_xyxy` 도 `final_score` 도 그대로다. 화면이 읽는 모양으로
바꾸는 것은 **관제 웹이 한다**(`src/detect/parse.ts` 한 곳).

바꿔 달라고 하는 것은 **하나뿐**이다 — 아래 §4.

---

## 1. 관제 웹 → 탐지 : 명령 둘

### 스캔 시작

```http
POST /detect/mission/start
Content-Type: application/json

{
  "command_id": "cmd-vjsnbjlz",
  "target_class": "door",
  "steps": 8,
  "step_deg": 45,
  "angles": [0, 45, 90, 135, 180, 225, 270, 315]
}
```

로봇에 `scan_mission` 을 쏘는 것과 **같은 순간**에 보낸다. `command_id` 도 같은 값이다 —
그 값으로 한 판을 묶어 주면 된다.

`steps` 와 `step_deg` 는 **화면에서 바뀐다.** 8·45 로 박아 두지 말 것. 12·30 으로 도는 판도
있을 수 있고, 그때 각도 목록은 위 `angles` 그대로다.

응답은 `200` 이면 충분하다. 몸통은 없어도 된다.

### 스캔 종료

```http
POST /detect/mission/stop

{ "command_id": "cmd-vjsnbjlz", "reason": "완료" }
```

`reason` 은 `완료` 또는 `중단`. 못 보내고 끊길 수 있으니 **새 `start` 가 오면 앞판은
자동으로 닫히는 편**이 안전하다.

---

## 2. 탐지 → 관제 웹 : 우리가 받아 간다

**밀어 주지 말고 열어만 주면 된다.** 관제 웹은 브라우저 페이지라 남이 보내는 요청을 못
받는다. 우리가 주기적으로 물어본다 — 한 각도가 도는 동안은 1.5초마다, 여덟을 다 본 뒤에는
6초마다.

### ① 각도별 결과 — `target_summary.json` 과 같은 모양

```http
GET /detect/results?command_id=…&target=door
```

```json
{
  "target_class": "door",
  "localization_ok": true,
  "frames": [
    { "frame": "frame_000001.jpg", "rotation_deg": 0.0, "found": false },
    { "frame": "frame_000113.jpg", "rotation_deg": 270.0, "found": true,
      "absolute_bearing_deg": 16.3,
      "rel_depth": 10.02, "distance_cm": 0.0, "in_valid_calibration_range": false }
  ]
}
```

| 필드 | 우리가 어떻게 쓰나 |
|---|---|
| `rotation_deg` | **칸 번호로 바꾼다** — `rotation_deg / step_deg`. 0·45·…·315 → 0~7 |
| `found` | 그 칸이 「문 있음」인가 |
| `absolute_bearing_deg` | **근거에만** 적는다. 화면이 가리키는 방향은 `rotation_deg` 다 |
| `distance_cm` | `in_valid_calibration_range` 가 `true` 일 때만 쓴다 |
| `localization_ok` | `false` 면 「문은 찾았는데 어디로 갈지 모른다」로 그린다 |

**아직 안 본 각도는 배열에서 빼면 된다.** `found: null` 같은 걸 넣지 않아도 된다.
한 각도가 끝날 때마다 배열이 하나씩 느는 것이 우리가 기대하는 모양이다.

### ② 각도별 근거 — `frame_0000NN/evidence.json` 과 같은 모양

```http
GET /detect/evidence?command_id=…&target=door&frame=frame_000113.jpg
```

```json
{
  "frame": "frame_000113.jpg", "rotation_deg": 270.0,
  "box_xyxy": [140.76, 89.67, 160.93, 143.73],
  "feature_similarities": { "a door's handle": 0.2319, "…": 0.0 },
  "final_score": 0.2696,
  "mandatory_gates": {
    "color_gate":  { "required": true, "passed": true, "winning_color": "a door's light blue color" },
    "shape_gate":  { "required": true, "passed": true, "winning_shape": "a rectangular shape" },
    "reference_image_gate": { "required": true, "passed": true, "similarity": 0.79, "threshold_min": 0.75 },
    "saturation_gate": { "required": true, "passed": true, "median_saturation": 108, "min_saturation": 85 }
  }
}
```

**못 찾은 각도에는 이 파일이 없는 것이 정상이다.** 404 로 주면 된다 — 우리는 찾은 각도만
물어본다.

우리가 여기서 하는 일 셋.

- `box_xyxy` → `[x, y, w, h]` 로 바꾼다 (**우리가 한다.** 바꿔 주지 않아도 된다)
- `final_score` 를 **「특징 최고값」**이라고 적는다. 확률이 아니므로 퍼센트로 안 그린다
- `mandatory_gates` 로 **한국어 한 문장을 우리가 조립한다** — `reason` 을 안 줘도 된다

> 화면에 뜨는 실제 문장:
> `색 light blue · 모양 rectangular · 기준영상 0.79/0.75 · 채도 108/85 통과 · 특징 최고값 0.27`

### ③ 경로 산출 — `evidence.json` 과 같은 모양

```http
GET /detect/path?command_id=…&target=door
```

`robot_position_cm` · `current_heading_map_deg` · `turn_instruction` ·
`forward_distance_cm` · `standoff_cm` · `goal_cm` · `path_calculation` 를 그대로 주면 된다.

`path_calculation` 의 **식과 대입값이 문자열로 들어 있는 것이 특히 좋다.** 화면이 그대로
네 줄로 그려서 「왜 90도를 돌았나」에 답한다 — 우리가 다시 계산하지 않는다.

**스캔이 끝나야 나오는 것이 맞다.** 그 전에는 404 로 주면 된다.

### ④ 무엇을 그 클래스라고 물었나 — `features_sent.json`

```http
GET /detect/features?command_id=…&target=door
```

### ⑤ 그림

```http
GET /detect/frame?command_id=…&target=door&frame=frame_000113.jpg&kind=original
→ image/jpeg
```

`kind` 는 `original` · `rpn_overlay` · `target_overlay` · `target_crop` 넷.

```http
GET /detect/path_overlay?command_id=…&target=door
→ image/jpeg   (도면 위에 경로를 그린 것)
```

**로컬 절대경로를 JSON 에 넣어 주는 것은 소용이 없다.** 받은 시료의
`/home/jin24/…/original.jpg` 같은 값은 브라우저가 못 연다. 위 주소로 바이트를 주면 된다.

### ⑥ 헬스 체크

```http
GET /health → 200
```

발표 직전에 눌러 볼 버튼용이라 가벼울수록 좋다.

## 3. CORS

브라우저에서 직접 부르므로 **응답에 헤더가 필요하다.** 없으면 요청 자체가 막혀 화면에는
「닿지 않습니다」만 뜬다.

```
Access-Control-Allow-Origin: *
```

그림(`image/jpeg`)에도 같이 붙여야 한다.

## 4. 바꿔 달라고 하는 것 — 하나

### `index` 를 같이 실어 달라

```json
{ "frame": "frame_000113.jpg", "rotation_deg": 270.0, "index": 6, "found": true }
```

지금은 우리가 `rotation_deg / step_deg` 로 유도한다. 여덟이 다 오는 동안은 맞지만,
**한 프레임이라도 빠지거나 각도가 45.0 이 아니라 44.7 로 오면 그 순간 어긋난다.**
어긋나도 화면은 그럴싸하게 돌아간다 — 여덟이 차례로 켜지고 초록도 하나 뜬다. 눈으로는
못 잡는다.

`index` 하나가 있으면 그 위험이 통째로 사라진다.

## 5. 우리 쪽이 이미 정한 것 (참고)

탐지 쪽에서 해 줄 일은 없고, 화면이 어떻게 그리는지 알고 있으면 좋은 것들이다.

| 상황 | 화면이 하는 일 |
|---|---|
| 여러 각도에서 `found` | **초록은 하나.** 점수가 가장 높은 각도. 동점이면 먼저 본 각도 |
| 찾았지만 안 고른 각도 | 「문 후보 — 점수가 더 높은 각도가 있어 안 고름」. **「문 없음」이 아니다** |
| 하나도 못 찾음 | 「문을 찾지 못함」에서 멈춘다. **임의로 한 방향을 고르지 않는다** |
| `localization_ok: false` | 문은 찾았고 경로만 못 낸 상태로 그린다 |
| `in_valid_calibration_range: false` | 거리를 **안 그린다** (0.0m 로 그리면 거짓이다) |

받은 시료에서 270도와 315도가 **둘 다** 찾혔고 점수 차이가 `0.0016` 이었다. 첫 줄의 규칙이
첫 판부터 쓰인다는 뜻이다.

---

## 6. 붙기 전에 미리 맞춰 두는 길

연결 관리의 **객체 탐지 → 「테스트」** 를 켜면 화면이 `door_example/` 을 진짜 결과처럼
읽는다. 목을 지어낸 것이 아니라 **받은 값 그대로**다.

그래서 탐지 서비스가 서기 전에 화면 쪽은 이미 다 맞춰져 있다. 서비스가 서면 체크를 끄고
주소를 넣는 것으로 끝난다 — 그때 위 §2 의 모양이 같으면 코드를 안 고친다.
