# 작업 지시: 8분할 뷰포인트 UI 수정 (1단계)

**날짜**: 2026-09-10
**선행**: `작업프롬프트_시연대본_260909.md` 로 만든 `MSN-260909-01`
**범위**: 화면만. 대본·사건 형식·상태 갱신 로직은 건드리지 않는다

> **앞 지시서 4절의 「원형 배치」를 세로 나열로 대체한다.** 원형은 화살표가 겹쳐서 못 쓴다.

---

## 왜 하나

시연 화면을 띄워 놓고 보니 둘이 걸린다.

1. 여덟 노드를 원형으로 두니 **부모에서 나가는 화살표가 서로 겹친다.** 캔버스에 공간은 남는데 배치가 그 공간을 안 쓴다.
2. 문이 잡힌 노드와 아닌 노드의 **차이가 약하다.** 발표장 프로젝터에서는 더 죽는다. 멀리서 대충 봐도 "저기다"가 보여야 하는 화면인데 지금은 눈을 붙여야 보인다.

둘 다 발표에서 바로 드러나는 문제라 먼저 고친다.

---

## 0. 착수 전에 확인할 것

| 확인 | 무엇을 |
|---|---|
| 8분할 노드를 그리는 파일 | 배치 좌표를 어디서 계산하는가 · 원형 특례를 어디에 넣었는가 |
| 노드 상태값 정의 자리 | 지금 상태가 몇 개이고 이름이 무엇인가 |
| 엣지 렌더링 | 노드쌍 직선만 되는가, **꺾인 경로(elbow)를 그릴 수 있는가** |
| 색·굵기 상수 자리 | 테마·토큰 파일이 따로 있는가, 컴포넌트에 박혀 있는가 |

3번이 이 작업의 갈림길이다. 꺾인 경로를 못 그리면 1절의 분기선을 **배경 레이어에 SVG로 직접** 그린다.
엣지 렌더러 전체를 고치지 마라.

---

## 1. 배치 — 세로 나열, 한 줄에서 분기

첨부 이미지가 목표 모양이다.

```
                    ┌──────────────┐
                 ┌─▶│ 0도 방향 탐색 │
                 │  └──────────────┘
                 │  ┌──────────────┐
                 ├─▶│ 45도 방향 탐색│
┌────────────┐   │  └──────────────┘
│ 로봇이     │   │         ⋮
│ 1바퀴 돈다 │───┤  ┌──────────────┐
└────────────┘   ├─▶│315도 방향 탐색│
                 │  └──────────────┘
```

- 여덟을 **세로 한 열**로. 위에서 아래로 0 · 45 · 90 · 135 · 180 · 225 · 270 · 315도. 인덱스 순서 그대로
- 부모에서 **가로선 하나**가 나가 세로 spine을 만들고, spine에서 각 노드로 **가로 화살표 여덟**
- 화살촉은 각 노드의 **왼쪽 변 중앙**에 붙는다
- 노드 크기와 세로 간격은 여덟 다 같다
- **화살표끼리 겹치지 않는다.** 이것이 이 절의 합격 기준이고 4절에서 좌표로 검사한다

### 원형 코드는 지운다

토글로 남겨 두지 마라. 쓰지 않을 분기가 남으면 다음 사람이 어느 쪽이 진짜인지 묻게 된다.

### 여덟이 한 화면에 들어와야 한다

세로로 세우면 길어진다. 스크롤이 생기면 시연에서 못 쓴다.
노드 높이·간격·기본 확대율을 조정해 **마일스톤을 연 직후 여덟이 다 보이게** 맞춰라.
부모 노드와 오른쪽의 판단·근거 노드까지 같은 화면에 들어오면 가장 좋다.

---

## 2. 상태 — 「미선정」을 신설한다

지금 판정이 끝난 노드를 한 상태로 묶고 있다면 **둘로 쪼갠다.**

| 상태 | 계기 | 화면 |
|---|---|---|
| 대기 `pending` | 초기 | 흐린 테두리, 채움 없음, 글자 흐림 |
| 탐색 중 `scanning` | 회전 인덱스 도착 | 테두리 점멸, 채움 없음 |
| **미선정 `rejected`** | 탐지 결과 `door: false` | **죽은 회색.** 채도 없음, 전체 불투명도 낮춤, 테두리 얇고 흐림, 글자도 흐림 |
| **선정 `selected`** | 탐지 결과 `door: true` | **초록 채움.** 테두리 굵게, 글자 진하고 어둡게, 불투명도 최대 |

### 색 하나로 구분하지 마라

이 절의 요점이다. 초록과 회색만 바꾸면 프로젝터에서 둘 다 밝은 회색으로 보인다.
**네 가지를 같이 움직여라** — 채움 · 테두리 굵기 · 글자 진하기 · 불투명도.

미선정을 확실히 죽이는 쪽이 선정을 밝히는 것보다 효과가 크다.
여덟 중 일곱이 가라앉고 하나만 남으면 눈이 저절로 간다.

선정 노드에 그림자나 테두리 강조를 한 겹 더 얹어도 좋다. 다만 **깜빡이지는 않게** —
`scanning`이 점멸이라 둘이 섞이면 무슨 상태인지 못 읽는다.

값은 저장소의 색·굵기 상수 자리에 넣는다. 컴포넌트 안에 직접 박지 마라.
