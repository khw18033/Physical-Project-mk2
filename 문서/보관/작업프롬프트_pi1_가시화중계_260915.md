# pi1 → 가시화 중계 추가 (자율주행 편 · 2026-09-15)

> **정정 (같은 날 · pi1 조사 보고 반영)** — 아래 원문은 보낸 그대로 둔다. 바뀐 것은 `문서/보관/pi1_답신_260915.md` 에 있다.
> ① pi1 의 브리지(`go1_sdk_pc`)는 mode 99 를 **한 번만** 보내고 98 은 안 보낸다 — §2 의 「여러 주기 · 0 이 아닌 값」 규칙은 틀렸다.
> ② `estop` 은 15100 텔레옵 4번째 필드로만 센다. ③ 경로 사건은 브리지 로그(journal)에서 먼저 얻는다.
> ④ `nav_state` 에 선택 키 `yaw_odometry_deg`(IMU)를 더했다. ⑤ pi1 에 브로커가 없어 설치가 필요하다.

아래 「붙여 넣을 프롬프트」를 **pi1 에서 작업하는 AI 에게 그대로** 붙여 넣는다.
가시화 쪽 수신부는 이미 이 계약(§3)대로 만들어 두었다 — `viz-debugger/src/physical/navFeed.ts` 가 받는 쪽 정본이고
`npm run verify:nav-feed` 가 계약대로 온 봉투로 한 판을 흘려 검사한다. pi1 이 계약과 다르게 할 수밖에 없으면
보고를 받고 가시화 쪽을 맞춘다.

## 붙여 넣을 프롬프트

나는 관제 웹(가시화) 담당이다. 이 라즈베리파이(**pi1**)에 **「받은 데이터를 가시화 쪽으로 전해 주는 것」 하나만** 더해 달라.
기존 코드·서비스는 최대한 건드리지 않는다. 아래 순서대로 하고, **§0 조사 결과를 먼저 보고한 뒤** 구현에 들어가라.

### 배경

- 새 임무 「문 앞까지 자율주행」에서 **로봇(Go1)은 유니티가 몬다.** pi1 은 유니티로부터 두 가지를 받는다.
  - 경로대로 이동하라는 명령 — UDP `15110` 의 `go1_path` JSON (큰 경로는 `CHUNK <path_id>/<total>/<idx> <부분>` 분할)
  - 경로가 바뀔 때 이전 경로 명령을 취소하고 정지하라는 명령 — UDP `15110` 의 텍스트 `PATH_CANCEL`
- 가시화는 **보기만 한다.** pi1 에 명령을 보내지 않는다. 가시화가 pi1 에서 쓰는 것은 넷이다.
  - 로봇 배터리 확인 → 배터리 %
  - 로봇 위치 확인 → **yaw 만**
  - 목적지까지 이동 → 경로를 받았다 / 경로 끝에 닿았다
  - 경로 재탐색 → 취소를 받았다 / 취소 처리됐다 / 새 경로를 받았다
- 참고 구성 (다른 기계 **pi7** — 코드가 비슷하다고 들었지만 **가정하지 말고 pi1 에서 확인하라**):
  - mosquitto `1883`(TCP) + `9001`(WebSocket), 인증 없음 — `pi/deploy/mosquitto-hw.conf`
  - `robot-node` 가 `zoneA/robot/go1-001/{status,state,heartbeat}` 로 JSON 발행 (`battery_pct`, `position.heading_deg`)
  - 유니티 UDP 브리지 `go1-sdk`(`go1_sdk_pc`, C++) 또는 `pi/robot/unity_bridge.py` — 15110 경로·취소 수신,
    15101 로 상태 `seq tms x z yaw(rad) vx vy wz estop mode` 송신 (`mode` 99 = 경로 완료 통지, 98 = PATH_CANCEL 처리 ACK),
    5009 로 이동 여부 `{"state_change":…, "motion_active":…}`
  - 계약 문서: 저장소 `HW` 브랜치 `HW-interface/bridge-contract.md`

### 지킬 것 (어기지 마라)

1. **기존 파일을 고치지 않는다.** 새 파일·새 서비스로 더한다. 기존 파일을 고쳐야만 한다면 **멈추고** 어느 파일의 어디를
   왜 고쳐야 하는지와 diff 안을 먼저 보고한다. 예외 하나 — mosquitto 에 WebSocket 리스너가 없으면
   `/etc/mosquitto/conf.d/` 에 **새 파일**을 더하는 것은 된다(재시작은 로봇이 멈춰 있을 때만, 보고서에 시각을 적는다).
2. **로봇을 움직일 수 있는 일은 하지 않는다.** 유니티 포트(15100 · 15110)로 아무것도 보내지 않는다. `go1-sdk`/브리지를
   재시작하지 않는다(기동 시 로봇이 기립한다). HighCmd·Go1 내부 MQTT 로 명령을 내지 않는다.
3. **이미 쓰이는 포트를 bind 하지 않는다** (15100 · 15101 · 15102 · 15104 · 15110 · 15200 · 15201 · 5009 · 1883 · 9001 등
   §0 에서 확인한 것 전부). `SO_REUSEPORT` 로 같은 UDP 포트를 나눠 받는 방식도 **금지** — 유니캐스트는 한 소켓만 받으므로
   브리지가 경로를 못 받을 수 있다.
4. **값을 지어내지 않는다.** 모르는 값은 `null` 이다. 배터리를 못 읽었는데 0 이나 마지막 값을 새 값처럼 싣지 않는다.
5. **중계가 죽어도 유니티 ↔ 브리지 경로는 그대로여야 한다.** 별도 프로세스로 돌리고, 파싱 오류는 로그만 남기고 계속 돈다.

### §1 브로커

가시화 브라우저는 **`ws://<pi1 Tailscale 이름>:9001/mqtt`** 로 붙는다(MQTT 5, 인증 없음 — pi7 과 같다).
9001 WebSocket 리스너가 없으면 `mosquitto-hw.conf` 와 같은 내용으로 conf.d 에 **새 파일**을 더한다.
기본 `mosquitto.conf` 에 이미 있는 항목(persistence 등)을 중복으로 적으면 mosquitto 가 기동을 거부하니 주의한다.

### §2 중계 서비스 — 새 파일로

`pi/robot/viz_nav_feed.py` (이름은 바꿔도 된다) + `pi/deploy/viz-nav-feed.service`. 로봇을 움직이지 않으므로 부팅 자동 시작이 된다.
`Restart=always`. 로컬 브로커(`localhost:1883`)로 발행한다.

**데이터를 얻는 방법 — 위에서부터 되는 것을 쓴다.**

- **배터리**: robot-node 가 로컬 브로커에 `…/state`(또는 `status`) 의 `battery_pct` 를 내고 있으면 **그것을 구독해서** 옮긴다.
  없으면 기존 모듈을 **읽기 전용으로** import 해서 읽는다(예: `robot.go1_link.Go1Link` — 명령을 내는 함수는 부르지 않는다).
  둘 다 안 되면 `null` 로 두고 보고한다.
- **yaw**: 브리지가 유니티에 보내는 상태(15101)의 yaw 를 우선한다 — 유니티가 경로를 계산하는 좌표계와 같은 값이다
  (라디안 → 도, `yaw_source: "bridge_state"`). 그걸 못 얻으면 robot-node 의 `heading_deg`(`yaw_source: "go1_odometry"`).
  **둘 다 얻을 수 있으면 같은 순간의 두 값을 보고서에 한 번 나란히 적어라** — 부호·기준이 어떻게 다른지 가시화가 알아야 한다.
- **경로·취소·완료 사건**: 브리지를 고치지 않고 **수동 캡처**로 본다.
  - `AF_PACKET` raw 소켓(`socket(AF_PACKET, SOCK_RAW, htons(ETH_P_ALL))`)으로 들어오는 UDP dst `15110`(유니티 → 브리지)과
    나가는 UDP dst `15101`(브리지 → 유니티)을 파이썬에서 IP/UDP 헤더를 뜯어 거른다. 소켓을 bind 하지 않으므로 브리지의
    수신을 빼앗지 않는다. `CAP_NET_RAW` 가 필요하다 — 서비스에 `AmbientCapabilities=CAP_NET_RAW` (root 로 돌리지 않는다).
  - 유니티가 브리지와 같은 기계에서 보내면 `lo` 도 봐야 한다 — 모든 인터페이스를 본다.
    인터페이스마다 링크 헤더가 다르다(`wlan0`·`eth0`·`lo` 는 이더넷 14바이트, `tailscale0` 같은 tun 은 헤더 없이 IP 부터) —
    `recvfrom` 이 주는 인터페이스 번호로 종류를 보고 IP 헤더 위치를 정한다. 유니티가 테일넷으로 보내는지 랜으로 보내는지 §0 에서 확인한 대로.
  - `CHUNK` 는 재조립한 뒤 한 건으로 친다. 15101 의 `mode` 98/99 는 브리지가 **여러 주기 연달아** 싣는다 — 0 이 아닌 값이
    처음 보인 주기만 사건으로 친다.
  - 캡처가 안 되는 이유가 있으면(권한 · 인터페이스) 대안을 **먼저 보고**하라. 최후 수단은 브리지 수신부에
    「받은 데이터그램을 `127.0.0.1:<새 포트>` 로 한 번 더 보내는 한 줄」인데, 이것은 기존 파일 수정이라 **승인 전에 하지 않는다.**
- **이동 여부**: 5009 `state_change`/`motion_active` 를 같은 방법으로 보면 `moving` 에 싣는다. 못 보면 `null`.
- 캡처하는 포트 번호는 **환경변수로 바꿀 수 있게** 만든다(§4 시험에서 바꾼다).

### §3 계약 — 이대로 발행하라

토픽 둘. `<zone>` · `<entity_id>` 는 robot-node 가 쓰는 값 그대로(없으면 `zoneA` · `go1-001`). 전부 UTF-8 JSON 객체.

| 토픽 | QoS | retain | 언제 |
|---|---|---|---|
| `<zone>/robot/<entity_id>/nav_state` | 0 | **false** | 0.5초마다 (2 Hz) |
| `<zone>/robot/<entity_id>/nav_event` | 1 | **false** | 일어날 때마다 즉시 |

retain 을 쓰지 마라 — 중계가 죽은 뒤에도 옛 값이 새로 붙은 화면에 「지금 값」처럼 들어온다.

**`nav_state`** — 아래 키를 **항상 전부** 싣는다(모르면 `null`, 키를 빼지 않는다).

```json
{
  "schema": "viz-nav/1",
  "node_id": "pi1",
  "entity_id": "go1-001",
  "ts_ms": 1789000000000,
  "battery_pct": 82,
  "yaw_deg": -12.5,
  "yaw_source": "bridge_state",
  "moving": false,
  "path_active": false,
  "path_id": null
}
```

| 키 | 뜻 |
|---|---|
| `schema` | 고정 `"viz-nav/1"`. 모양을 바꾸면 `viz-nav/2` 로 올리고 알려 달라 — 가시화는 모르는 schema 를 버린다 |
| `ts_ms` | pi1 시계 epoch ms (표시용) |
| `battery_pct` | 0~100 숫자 또는 `null` |
| `yaw_deg` | 도, -180~180 으로 정규화, 소수 1~2자리. 모르면 `null` |
| `yaw_source` | `"bridge_state"` 또는 `"go1_odometry"`. `yaw_deg` 가 있으면 **반드시** 싣는다 — 없으면 가시화가 yaw 를 버린다 |
| `moving` | 5009 의 최신 이동 여부. 모르면 `null` |
| `path_active` | 중계가 사건으로 계산한 값 — `path_received` 뒤 `path_done`·`path_cancel`·`estop` 전까지 `true` |
| `path_id` | 지금 따라가는 경로의 `path_id`. 없으면 `null` |

**`nav_event`**

```json
{
  "schema": "viz-nav/1",
  "node_id": "pi1",
  "entity_id": "go1-001",
  "seq": 17,
  "ts_ms": 1789000000123,
  "event": "path_received",
  "path_id": 3,
  "point_count": 12,
  "source": "udp15110",
  "note": ""
}
```

| `event` | 언제 | `path_id` | `source` 예 |
|---|---|---|---|
| `feed_started` | 중계 프로세스가 뜰 때 한 번 | `null` | `"startup"` |
| `path_received` | 완성된 `go1_path` 한 건(CHUNK 재조립 뒤) | 그 JSON 의 `path_id` | `"udp15110"` |
| `path_cancel` | `PATH_CANCEL` 수신 | 직전 경로의 id (없으면 `null`) | `"udp15110"` |
| `cancel_ack` | 15101 `mode` 98 이 처음 보인 주기 | 직전 경로의 id | `"udp15101_mode98"` |
| `path_done` | 15101 `mode` 99 가 처음 보인 주기 | 직전 경로의 id | `"udp15101_mode99"` |
| `estop` | estop 0 → 1 전이 (15101 `estop` 또는 15100 텔레옵 4번째 필드) | 직전 경로의 id | `"udp15101_estop"` |

- `seq` 는 프로세스가 뜰 때 1 부터 1씩 늘린다. `point_count` 는 `path_received` 에만(나머지 `null`). `note` 는 자유 문구(없으면 `""`).
- 경로 좌표(`points`)는 싣지 않는다 — 필요해지면 따로 요청한다.

가시화는 이것을 이렇게 쓴다(참고): 판을 연 뒤 받은 지금 `battery_pct` 가 기준 이상이면 「로봇 배터리 확인」 완료 →
`yaw_deg` 로 「로봇 위치 확인」 완료 → `path_received` 로 「목적지까지 이동」 시작, `path_done` 으로 완료 →
`path_cancel` 로 「경로 재탐색」 시작, 다음 `path_received` 로 재탐색 완료 + 이동 다음 회차 시작.

### §4 시험 — 로봇을 움직이지 않고

1. `nav_state` 가 0.5초마다 오는가: `mosquitto_sub -h localhost -t '+/robot/+/nav_state' -v -C 6`
2. **사건 로직은 비어 있는 포트로 시험한다.** 캡처 포트를 환경변수로 아무도 bind 하지 않은 포트(예: 경로 `25110`, 상태 `25101`)로
   바꿔 띄우고, 거기로 유니티 흉내 패킷을 보낸다 — 브리지는 그 포트를 안 받으므로 로봇이 안 움직인다.
   보낼 것: `go1_path` 한 건 · CHUNK 로 쪼갠 `go1_path` 한 건 · `PATH_CANCEL` · 상태 줄 `mode 98` 세 줄 연속 ·
   상태 줄 `mode 99` 세 줄 연속 · `estop 1` 상태 줄. 기대: 사건이 각각 **정확히 한 건씩**
   (`mosquitto_sub -h localhost -t '+/robot/+/nav_event' -v`).
3. **테일넷 밖에서 WebSocket 으로 붙는가.** 다른 테일넷 기기에서:
   `python3 -c "import paho.mqtt.client as m;c=m.Client(m.CallbackAPIVersion.VERSION2,transport='websockets');c.ws_set_options(path='/mqtt');c.on_message=lambda c,u,x:print(x.topic,x.payload[:120]);c.connect('<pi1 Tailscale 이름>',9001);c.subscribe('+/robot/+/nav_state');c.loop_forever()"`
4. 실제 유니티 경로로 보는 시험은 **사람이 입회하고 가시화 쪽과 시간을 맞춰서** 한다. 이번에 하지 않았으면 안 했다고 적는다.
5. 시험이 끝나면 캡처 포트를 원래 값(15110 · 15101 · 5009)으로 되돌려 서비스를 띄운다.
