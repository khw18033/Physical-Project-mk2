# 작업 지시: 단독 빌드 정합 (`dist` ↔ `dist-standalone`)

**날짜**: 2026-09-16
**선행**: 없음
**후속**: 이것이 끝나야 `문서/보관/작업프롬프트_영문화1단계_260916.md` 로 간다 — **영문화는 멈춰 있다**
**범위**: 경계를 다시 긋는다. **기능을 새로 만들지 않는다**

> 이 작업이 끝나도 `npm run dev` 화면은 **한 글자도 안 바뀐다.**
> 바뀌는 것은 `dist-standalone` 뿐이고, 거기에 **이미 있었어야 할 것**이 뜬다.

---

## 왜 하나

단독 빌드가 조용히 뒤처졌다. 아무도 뒤처뜨리기로 결정한 적이 없다는 것이 문제다.

`verify-standalone.mjs` 는 단독 진입점이 **`shell/` 과 `tabs/` 를 가져오면 실패**한다. 이 규칙을
그은 것이 `d33a9cc`(2026-08-28)이고, 그때 `shell/` 은 **탭 전환 기계**였다. 즉 「`shell/` 금지」는
그 시점에 「탭②~⑤ 부하 금지」와 같은 말이었고, 검사 머리줄이 적은 사유도 그것이다 —
*"관제·영상 탭 코드가 섞이면 측정이 오염된다."*

그 뒤 `shell/` 은 **상단 바에 붙는 것들의 서랍**이 됐다.

```
08-28  d33a9cc  standalone.tsx · verify-standalone.mjs   ← 경계를 긋고 그 뒤 한 줄도 안 고쳤다
08-31  90c51ca  ModeSwitch · HelpOverlay      → shell/
09-04  9d5df87  ConnectionsPanel              → shell/
09-10  ebb5a02  ConnectionLamp                → shell/
```

연결 관리 폼도 모드 세그먼트도 도움말도 「관제·영상 탭 코드」가 아니다. 그런데 **같은 폴더에
떨어졌다는 이유만으로** 전달본에서 빠졌다. 검사는 대리 지표(`shell/`)를 지켰고, 그 대리 지표가
가리키던 진짜 기준(`tabs/`)에서 멀어졌다.

### 전제 하나가 이미 거짓이다

`src/shell/missionBridge.ts:10` 이 이렇게 적고 있다.

> **셸에만 있다.** 탭① 코어(단독 빌드)는 **게이트웨이가 없으므로** 이 다리도 없다

**지금은 거짓이다.** 단독 빌드의 의존 그래프에 `transport/` 5개 · `physical/` 22개 ·
`detect/` 13개 · `stt/` 4개 · `generate/` 8개 · `autodrive/` 4개가 들어 있다.
붙는 법을 아는 클라이언트는 다 있고 **붙기를 시작하는 코드만 없다.**

260831 에 참이던 문장이 고쳐지지 않은 채 남아 근거 노릇을 하고 있었다. 이 작업은 그 문장도
같이 고친다.

### 그래서 지금 빠져 있는 것

| 디렉터리 | 단독 | 통합 | 차 | 무엇이 빠졌나 |
|---|---:|---:|---:|---|
| `tabs/` | 0 | 30 | 30 | **정당하다** — 대시보드 · 논문 측정축 D |
| `shell/` | 0 | 6 | 6 | AppShell · 모드 스위치 · 연결 관리 · 연결 램프 · 도움말 · 임무 브리지 |
| `physical/` | 23 | 27 | 4 | **정지 · 일시정지 · 재개 · 접근 버튼** · 자율주행 제어 |
| `scenarios/` | 6 | 8 | 2 | 대본 미리보기 진입 · 「지금 재생 중」 |
| `shared/` | 18 | 20 | 2 | 연결 점검 · 연결 상태 |
| `views/` | 6 | 7 | 1 | 재시작 · 초기화 |
| `detect/` | 13 | 14 | 1 | 탐지 화면 |
| **합계** | **120** | **166** | **47** | `tabs/` 30을 빼면 **16개가 이유 없이 빠져 있다** |

> **절대 수는 2026-09-16 재측정값이다** (`src/` 안만, 재내보내기 포함). 초판은 118·163·45 로
> 적혀 있었는데 `export … from` 을 세느냐에서 갈린다. **차(差) 열은 일곱 줄이 전부 초판과 같고,
> 「그 밖 16개」도 그대로다.** 세는 방식이 달라도 결론이 안 흔들린다는 뜻이라 굳이 통일하지 않는다 —
> 대신 0절의 합격 기준을 총계가 아니라 **16개 목록**으로 둔다.

**그 16개 안에 긴급정지가 있다.** 로봇을 모는 화면을 전달본으로 건네면서 세우는 버튼이 없다.

## 1. 경계는 `tabs/` 다 — `shell/` 이 아니다

이 작업의 전부가 이 한 줄이다.

`src/tabs/index.tsx:16-18` 이 이미 그렇게 적어 놨다.

> **폴더 이름은 `tabs/` 그대로 둔다.** 이 이름은 이제 「탭이었던 화면들」이 아니라
> **「단독 빌드에 들어가면 안 되는 것들」**이라는 뜻이고, `verify:standalone` 이 그 경계를
> 그 이름으로 검사한다.

**의도는 이미 옳게 적혀 있었고 검사만 옛 대리 지표에 머물러 있었다.** 검사를 의도에 맞춘다.

단독 빌드가 **끝까지 못 갖는 것**은 이 셋이고, 이건 안 바뀐다.

- `tabs/` 전부 — 대시보드 데이터 계층 · 관제 · 영상 · 지표
- `PlanApproval` (VZ-U-07 승인 화면) — `tabs/views/` 에 있다
- 뷰 노드 렌더러 4종 — `tabs/viewNodes.tsx` 에 있다. 팔레트가 비어 보이는 것이 맞다

## 2. `useTabsDataLayer()` 를 가른다

지금은 성질이 다른 셋이 한 함수에 묶여 있다 (`src/tabs/index.tsx:47-52`).

```ts
export function useTabsDataLayer() {
  useEffect(() => startDataLayer(ZONE_ID), []);   // ① 구역 축 구독 — tabs 전용
  useAiFailureNotifications();                     // ② tabs/aiFailureBridge.ts — tabs 전용
  return useConnectionStatus();                    // ③ getTransport() 만 본다 — 아무 데서나 된다
}
```

**③ 때문에 ①②가 셸에 딸려 들어가고 있다.** 상단 바의 `conn` 배지가 필요할 뿐인데 대시보드
데이터 계층 전체가 같이 온다.

### 할 일

**③ 을 `src/shared/connectionStatus.ts` 로 옮긴다.** `getTransport()` 만 보므로 `shared/` 가
제자리다. `tabs/data/hooks.ts` 는 **그것을 다시 내보낸다** — 기존 호출부를 한 곳도 안 고친다.

### ⚠ 이 한 줄이 단독 빌드의 동작을 바꾼다 — 알고 넘어가라

`getTransport()` 는 조회 함수가 아니다. **첫 호출에 전송 계층을 만들고 곧바로 붙는다**
(`src/transport/index.ts:67-72`).

```ts
singleton = new WsTransport(() => ({ url: GATEWAY.ws, httpBase: GATEWAY.http }));
singleton.connect();          // ← 여기
```

지금 단독 빌드는 셸이 통째로 없어서 이 경로를 **한 번도 안 탄다.** 셸이 들어가면
`AppShell` 이 `conn` 배지를 그리려고 부르는 순간 **전달본이 열리자마자 게이트웨이에 붙으러 간다.**

이 지시서는 그것을 **의도한 변화로 본다** — 「붙는 법을 아는 클라이언트는 다 있고 붙기를
시작하는 코드만 없다」가 애초의 문제 제기였다. 다만 **그 결과가 화면에 어떻게 보이는지는
아무도 안 봤으므로** 7절에서 반드시 눈으로 확인하고 8절에 적어라.

붙는 것 자체를 막고 싶어지더라도 **이 작업에서 결정하지 마라.** 관측한 것만 보고하고
판단은 사람에게 넘긴다 — 측정축 D 와 같은 취급이다.

**①② 는 주입으로 바꾼다.** 셸은 「데이터 계층을 기동해 달라」는 요청만 받는다.

```ts
// src/shared/appServices.ts (신설)
export function registerAppService(start: () => (() => void) | void): void;
export function useAppServices(): void;   // 등록된 것을 기동. 없으면 아무것도 안 한다
```

`integrated.tsx` 가 `registerAppService(() => startDataLayer(ZONE_ID))` 를 심고,
`standalone.tsx` 는 안 심는다. **`registerViewNodes()` 와 똑같은 꼴이다** — 셋째 패턴을 만들지 마라.

`useAiFailureNotifications()` 도 같은 길로 보낸다.

## 3. `missionBridge` 의 `store` 를 주입으로 바꾼다

`src/shell/missionBridge.ts` 가 `tabs/` 에 닿는 자리는 **한 줄**이다.

```ts
import { store } from '../tabs/data/index.ts';   // :23
...
store.apply(envelope);                            // :70  ← 여기 하나뿐
```

봉투를 받아 대시보드 저장소에도 넣는 것이고, 단독 빌드에는 그 저장소가 없다.

### 할 일

```ts
// src/shared/envelopeSink.ts (신설)
export function registerEnvelopeSink(sink: (envelope: Envelope) => void): void;
export function fanOutEnvelope(envelope: Envelope): void;
```

`missionBridge` 는 `store.apply(envelope)` 대신 `fanOutEnvelope(envelope)` 를 부른다.
`integrated.tsx` 가 `registerEnvelopeSink(store.apply)` 를 심고 단독은 안 심는다.
**등록된 것이 없으면 아무 데도 안 보내고 조용히 지나간다** — 그것이 단독 빌드의 정상 상태다.

이 한 줄이 바뀌면 `missionBridge` 의 `tabs/` 도달이 **16개에서 0개**가 되고,
따라서 `AppShell` 의 도달도 0개가 된다.

### 주석도 같이 고친다

`missionBridge.ts:10-11` 의 「게이트웨이가 없으므로」와 `:57-59` 의 「단독 빌드에는 이 다리가
없고」는 **이 작업 뒤 거짓이 된다.** 지우지 말고 **무엇이 바뀌었는지 적어라** — 이 저장소의
주석은 결정의 기록이고, 뒤집힌 결정은 뒤집혔다고 적는 것이 이 저장소의 방식이다.

## 4. `standalone.tsx` 가 셸을 쓴다

`integrated.tsx` 를 본뜨되 **`tabs/` 에서 오는 둘을 안 넣는다.**

```tsx
// 통합에만 있는 것 — 단독은 이 셋을 안 한다
registerViewNodes(VIEW_NODE_RENDERERS);          // tabs/viewNodes.tsx
registerAppService(() => startDataLayer(ZONE_ID)); // tabs/data/
<MissionDebugger planApproval={<PlanApproval />} /> // tabs/views/
```

`MissionDebugger` 는 두 프롭이 **이미 선택**이다 (지금 `standalone.tsx:6` 이 프롭 없이 부르고
있다). 그대로 두면 된다.

단독 진입점은 이렇게 된다 — `integrated.tsx` 와 **구조가 같고 주입만 없다.**

```tsx
createRoot(document.getElementById('root')!).render(
  <StrictMode>
    <AppShell debuggerView={<MissionDebugger navigation={navigation} />} ... />
  </StrictMode>,
);
```

`<main className="standalone">` 래퍼가 지금 있다. 셸이 `<main className="app-shell">` 을 직접
그리므로 **겹치지 않게 정리해라.** CSS 가 어느 쪽에 붙어 있는지 보고 정한다.

## 5. 검사를 고친다 — 둘이다

### `scripts/verify-standalone.mjs`

```js
if (rel.startsWith('shell/') || rel.startsWith('tabs/')) forbidden.push(rel);   // :22 지금
if (rel.startsWith('tabs/')) forbidden.push(rel);                              // 이렇게
```

**음성 대조군도 같이 바꾼다** (`:37`). 지금은 `shell/AppShell.tsx` import 를 주입해 잡히는지
보는데, 그게 이제 정상이라 대조군 구실을 못 한다. **`tabs/` 의 무언가를 주입해라** —
`tabs/data/index.ts` 가 맞다. 대조군이 검사의 절반이다. 지우지 마라.

### `scripts/verify-view-nodes.mjs`

`:34` · `:44-45` · `:55` 가 같은 금지어를 갖고 있다. `shell/` 을 뺀다.

**단, `:34` 의 「캔버스는 `tabs/`·`shell/` 을 모른다」는 그대로 둔다.** 그건 단독 빌드 경계가
아니라 **캔버스 계층 경계**다 — 다른 이유로 서 있는 줄이고, 이 작업이 건드릴 것이 아니다.
단독 진입점을 보는 `:55` 만 고친다.

### 신설 — `verify:build-parity`

**이 작업에서 가장 중요한 산출물이다.** 나머지는 한 번 고치면 끝이지만 이건 **다시 벌어지는
것을 막는다.** 없으면 석 달 뒤 같은 보고서를 또 쓴다.

`scripts/verify-build-parity.mjs` — 두 진입점의 도달 집합을 재서 **차이가 `tabs/` 뿐인가**를 본다.

```
통합 − 단독  ⊆  { tabs/**, integrated.tsx }
```

- 이 밖의 파일이 하나라도 나오면 **실패**하고, 그 파일 이름과 **어느 import 사슬로 빠졌는지**를
  찍는다. 이름만 찍으면 왜 빠졌는지 찾느라 또 반나절이 간다
- 대조군 — `shell/HelpOverlay.tsx` import 를 `integrated.tsx` 에만 주입한 사본이 반드시 잡혀야 한다
- `package.json` 에 `verify:build-parity` 를 넣는다

## 6. 하지 않을 것

- **기능 신설.** 단독에 없던 화면을 새로 그리지 마라. **옮기는 것뿐이다**
- **`tabs/` 를 단독 번들에 넣기.** 측정축 D 가 이것 하나로 무너진다
- **`tabs/` 폴더 이름 바꾸기** — `tabs/index.tsx:16-18` 이 그 이유를 적어 뒀다 (검사·문서 열 곳)
- **영문화.** 별건이고 이것이 끝난 뒤다. `src/i18n/` · `language.ts` · `LangSwitch` 를 만들지 마라
- **측정축 D 재측정.** 번들이 커지는 것은 사실이고 재야 할 수도 있지만 **이 작업의 몫이 아니다.**
  7절에 크기 변화만 적고 판단은 사람에게 넘겨라
- **`verify-view-nodes.mjs:34`** 의 캔버스 계층 경계 — 위에 적은 대로 그대로 둔다
- `dist/` 쪽 동작 변경. 통합 화면은 **한 글자도 안 바뀌어야 한다**

| **기존 verify 전종** | **통과.** 통합 화면을 안 바꿨으므로 하나도 깨지면 안 된다 |
| 손 확인 · 통합 | `npm run dev` — 상단 바 · 모드 스위치 · 연결 관리 · 긴급정지가 **전과 같은가** |
| 손 확인 · 단독 | `dist-standalone/standalone.html` 을 열어 **정지 버튼이 뜨는가** · 모드 스위치가 도는가 · 연결 관리가 열리는가 |
| **손 확인 · 단독의 연결 시도** | **게이트웨이를 안 띄운 채로** 열어 `conn` 배지가 무엇으로 뜨는가 · 개발자도구 네트워크에 재시도가 몇 초 주기로 찍히는가 |
| 손 확인 · 단독의 빈자리 | 팔레트에 뷰 노드 4종이 **없는** 것이 맞다. 승인 카드가 **없는** 것도 맞다. 없다고 화면이 깨지지 않는가 |

마지막 줄이 이 작업의 진짜 위험이다. 지금까지 단독 빌드는 셸이 통째로 없어서 **셸이 `tabs/`
없이 도는 경로가 한 번도 안 돌아 봤다.** 빈 `useAppServices()` · 빈 `fanOutEnvelope()` ·
`planApproval` 없는 `MissionDebugger` 를 실제로 열어 봐라.

### `conn` 배지 — 「연결 종료」가 아닐 것이다

초판은 게이트웨이 없이 열면 「연결 종료」로 뜬다고 적었는데 **코드를 보면 아니다.**
`closed` 는 명시적 `close()` 에서만 나온다(`WsTransport.ts:129`). 게이트웨이가 없으면
`connecting` → `reconnecting` 에 머물고 **지수 백오프로 영원히 재시도한다** —
500ms 에서 시작해 2배씩, 상한 15초에 ±25% 지터(`transport/backoff.ts`).

그러니 예상 화면은 **「재연결 중」과 다음 재시도까지 남은 시간**이다. 실제로 그런지 확인하고,
다르면 무엇으로 떴는지 적어라.

**전달본은 게이트웨이 없이 여는 파일이다.** 학회에서 열어 두면 15초마다 계속 붙으러 간다.
그것을 그대로 둘지, 단독에서는 처음부터 「게이트웨이 없음」으로 세울지는 **이 작업이 정하지 않는다.**
관측 결과를 8절에 적고 판단은 사람에게 넘겨라.
