# 정지 명령 규약 (안)

**작성** 2026-09-10 · 김현우 (가시화)
**보내는 곳** 하드웨어 담당
**왜** 확인된 action 셋(`ping` · `scan_mission` · `move_forward`)에 **멈추는 명령이 없다.**
시연 중 로봇이 사람 쪽으로 걸어가면 화면에서 멈출 길이 있어야 한다.

기존 봉투를 그대로 쓴다. 스키마는 고치지 않는다.

---

## 1. 명령

```
action     = "abort"
parameters = { "reason": 1 }        // 생략 가능
```

토픽·QoS는 다른 명령과 같다 — `terminal/go1-001/downlink`, QoS 1.

### 이름을 `abort` 로 한 이유

그쪽 응답 어휘에 이미 **`event: "aborted"`** 와 **`CommandResult{ABORTED}`** 가 있다.
받는 쪽에 중단 개념이 이미 있다는 뜻이라, 같은 말을 쓰는 편이 붙이기 쉽다고 봤다.
다른 이름이 더 맞으면 그쪽 이름을 따르겠다.

### `reason` 코드

`parameters` 가 `map<string, double>` 이라 문자열을 못 넣는다. 숫자로 보낸다.

| 값 | 뜻 |
|---|---|
| 1 | **사람이 긴급 정지 버튼을 눌렀다** |
| 2 | 화면 판단으로 중단 (문을 못 찾음 등) |
| 3 | 연결 이상 |

기록용이다. **로봇 동작은 값과 무관하게 같아야 한다** — 무엇이든 즉시 멈춘다.
읽기 어려우면 무시해도 된다.

---

## 2. 대상을 지정하지 않는다

`abort` 는 **그 로봇이 지금 하는 것 전부**를 멈춘다. 어느 임무를 멈출지 지정하지 않는다.

시연은 로봇 한 대에 임무 하나다. 대상을 지정하면 「멈추라고 했는데 다른 걸 멈췄다」가
생길 수 있고, 긴급 정지에서 그건 최악이다. **고를 것이 없는 편이 안전하다.**

---

## 3. 바라는 응답

`abort` 자신과, 멈춰지는 임무 쪽이 따로 응답한다.

| 무엇 | command_id | 응답 |
|---|---|---|
| `abort` 명령 자체 | 새로 만든 id | `Acceptance{accepted:true}` → `CommandResult{SUCCEEDED}` |
| 돌던 `scan_mission` | 원래 id | `CommandStatus{event:"aborted"}` → `CommandResult{ABORTED}` |

두 번째 줄이 있어야 화면이 **어느 임무가 어디서 끊겼는지** 표시할 수 있다.
`event: "aborted"` 의 `step` 에 몇 번째에서 멈췄는지가 들어오면 좋다.

---

## 4. 지켜 주었으면 하는 것 셋

### ㉠ 거절하지 않는다

`abort` 는 **어떤 상태에서도 `accepted: true`** 여야 한다.

로봇이 꺼져 있어도, 아무 임무도 안 돌고 있어도 받아 주고 `SUCCEEDED` 로 끝내면 된다.
정지가 거절당하는 상황은 만들지 않는 게 좋다 — 누른 사람은 멈춘 줄 알고 다가간다.

### ㉡ 여러 번 눌러도 된다

같은 결과여야 한다. 두 번째 `abort` 가 오류가 되면 안 된다.
사람은 급하면 여러 번 누른다.

### ㉢ 빠를수록 좋다

받는 즉시 모터가 서는 것이 목표다. **실제로 몇 ms 걸리는지 알려 주면 그대로 적겠다** —
발표에서 물어볼 수 있는 숫자다.

---

## 5. 확인이 필요한 것

| 질문 |
|---|
| `abort` 라는 이름으로 괜찮은가. 다르면 그쪽 이름을 쓰겠다 |
| `scan_mission` 이 도는 중에 받으면 남은 ACK 는 어떻게 되는가 (그냥 끊기는가, `aborted` 하나로 닫히는가) |
| 정지 뒤 로봇은 어떤 자세로 서는가 — 그 자리에 서는가, 앉는가 |
| 정지 뒤 다시 명령을 받으려면 뭘 해야 하는가. 그냥 다음 명령을 쏘면 되는가 |
| **연결이 끊기면 로봇이 스스로 멈추는 장치가 있는가** (watchdog) |

마지막이 실질적으로 가장 중요하다.

화면 정지는 네트워크를 타고 나간다. Wi-Fi가 끊기거나 브로커가 죽으면 **명령이 아예
안 나간다.** 그때 로봇이 계속 걷고 있으면 화면으로는 아무것도 못 한다.

로봇 쪽에 "일정 시간 명령이 없으면 선다"가 있으면 그 시간을 알려 달라.
없으면 **없다는 것도 알아야 한다** — 그 경우 시연 중 안전은 전적으로 조종기를 든
사람에게 달린다는 뜻이고, 발표 자료에도 그렇게 적을 것이다.

---

## 6. 우리 쪽에서 하는 것

명령이 안 나가도 화면은 멈춘다. 정지 버튼을 누르면 우리 쪽에서 이 넷이 일어난다.

1. `abort` 발행
2. 진행 중 명령 추적 중단 — 뒤늦게 오는 상태로 화면이 더 진행하지 않게
3. 화면 타이머·폴링 정지
4. 화면을 「정지됨」으로 잠금 — 사람이 다시 승인해야 풀린다

**1번이 실패하면 화면에 크게 표시한다.** 「정지 명령을 보내지 못했습니다」.
조용히 성공한 척하지 않는다.
