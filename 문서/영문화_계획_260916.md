# 화면 영문화와 언어 선택 — 구현 계획 (2026-09-16)

대상: `viz-debugger` 통합 셸(5174)과 그것이 기대는 세 곳 — `registry.json` · `scenarios/*.json` · `gen-lab/server/prompt.py`.
교수님 요청 4건에 대한 답과 착수 순서다. 범위는 **전부**(생성 결과 포함), 기한은 **다음 보고 전 1~2주**로 잡았다.

계획을 세우기 전에 저장소를 실측했다. 아래 숫자가 이 문서의 모든 판단 근거다.

이 저장소가 처음부터 표시 문자열과 ID를 갈라 놨기 때문이다. 영문화 비용이 생각보다 낮은 이유가 여기 있다.

## 1. 요청 3번에 대한 답 — **텍스트만 분리한다**

사이트를 두 벌로 관리하지 않는다. 이유 넷.

**① 구조가 갈라질 데가 없다.** 화면은 탭이 아니라 노드 캔버스 하나다(`verify:no-tabs`).
한국어판과 영어판이 다른 것은 오직 문자열뿐인데, 파일만 두 배가 된다.

**② 이 저장소의 원칙과 정면으로 어긋난다.** `verify:one-gateway` · `verify:single-egress` ·
`verify:one-broker-address` · `verify:stt-port` — 전부 「면을 하나로 유지한다」를 검사로 못박은 것들이다.
사이트를 두 벌로 나누면 그 원칙이 화면 층에서만 깨진다. 논문에서 방어하기 어려운 종류의 균열이다.

**③ `standalone.html` 전달본이 두 벌이 된다.** 단일 파일로 건네는 이점이 사라진다.

**④ 어긋남은 반드시 생긴다.** 자리표시 문구 15개를 한 표에 모아 둔 것(`pendingSources.ts`)이
두 벌이 되는 순간, 「누가 언제 주느냐」 표가 두 개의 다른 답을 갖는다.

## 2. 층을 셋으로 나눈다

이 계획의 골자다. **한 기계로 처리하려 하면 3층에서 반드시 막힌다.**

| 층 | 무엇 | 어디에 둘 것인가 | 언제 갈아끼우나 |
|---|---|---|---|
| **L1 화면 문구** | 라벨·버튼·자리표시·오류 문장 | `src/i18n/ko.ts` · `en.ts` 사전 | 렌더마다 |
| **L2 도메인 데이터** | 장비명·구역명·대본 제목·장소 목록 | 원본 JSON에 `_en` **병기** | 데이터를 읽을 때 |
| **L3 생성 결과** | LLM이 만든 마일스톤·태스크 제목 | 프롬프트 판을 ko/en 둘로 | 생성 한 번, 그 뒤 고정 |

### L3을 나눠야 하는 이유 — 기록은 되돌릴 수 없다

기록 열은 **덧붙이기 전용**이다(REQ-1404 · `TraceStore`). 수정·삭제 경로가 아예 없다.
그래서 **이미 한국어로 생성돼 기록에 들어간 마일스톤 제목을 나중에 영어로 바꿔 쓸 수 없다.**
바꾸면 그건 번역이 아니라 기록 위조다.

결론: **언어는 화면의 설정이 아니라 임무에 붙는 속성이다.**
임무 객체에 `lang: 'ko' | 'en'` 을 하나 둔다. 생성 시점에 정해지고 그 뒤로 안 바뀐다.
화면 언어를 영어로 바꿔도 한국어로 생성된 옛 임무는 한국어 제목 그대로 뜨고,
그 옆에 「이 임무는 한국어로 생성됐습니다」 한 줄이 붙는다. 숨기지 않고 보이게 하는 쪽이 맞다.

## 3. 요청 2번 — 언어 선택 기능

### 저장소: 새 패턴을 만들지 않는다

`src/shared/connections.ts` 와 **같은 꼴**로 짠다 — `useSyncExternalStore` + `localStorage` + `subscribe`.
이 저장소에는 이미 그 패턴이 둘(`connections.ts` · `renderMode.ts`) 있다. 셋째를 만들 이유가 없다.

```
src/shared/language.ts
  export type Lang = 'ko' | 'en'
  getLang() / setLang() / subscribeLang() / useLang()
```

### 결정 순서

```
URL ?lang=   >   localStorage   >   navigator.language   >   'ko'
```

**URL을 맨 위에 두는 이유가 실무적이다.** 학회에서 링크 하나 보내면 상대가 영문 화면을 그대로 연다.
설명이 필요 없어진다. 「일반적인 웹사이트처럼」이라는 요청의 핵심도 사실 이것이다.

### 라우터는 넣지 않는다

`/ko` · `/en` 경로 분리는 하지 않는다. 지금 의존성은 넷뿐이고(`react` · `mqtt` · `protobufjs` · `ws`)
라우터 하나 넣자고 `verify:dep-rules` 가 지키는 선을 넘을 일이 아니다.
`standalone.html` 단일 파일 전달본에서는 경로 분리가 아예 동작하지도 않는다. `?lang=en` 이 같은 일을 한다.

### 자리와 모양

`global-bar` 우측, `ModeSwitch` 옆에 세그먼트 하나.

```
모드 [ 일반 ][ 시나리오 ▾ ][ 목·개발 ]        언어 [ 한국어 ][ English ]
```

`ModeSwitch.tsx` 가 이미 같은 모양이라 컴포넌트를 본뜬다. 새 디자인을 만들지 않는다.
전환할 때 `<html lang>` 을 같이 바꾼다 — 줄바꿈 규칙과 스크린리더가 이걸 본다.

## 4. 사전 골격

### 키를 한국어 원문으로 쓰지 않는다

```ts
t('stt.offline')          // 좋다
t('STT 서비스에 닿지 않습니다')  // 나쁘다
```

원문을 키로 쓰면 한국어 문구를 한 글자만 다듬어도 영어가 통째로 떨어진다.
키는 `영역.항목` 으로 짓는다 — `stt.offline` · `pending.plane.business` · `mode.scenario`.

### 누락은 실패가 아니라 **한국어 fallback**

1~2주 안에 1,249줄을 다 옮기지 못한다. 전제로 깔고 설계한다.

```ts
t(key) → en 사전에 없으면 ko 값을 돌려주고 콘솔에 한 줄 남긴다
```

빈 문자열도, 키 원문(`stt.offline`)도 화면에 그리지 않는다. **부분 번역 상태로도 화면은 정상이어야 한다.**
이게 없으면 마감에 쫓겨 번역을 못 채운 자리가 그대로 깨진 화면이 된다.

### `${}` 164곳 — 여기가 제일 위험하다

문장을 조각으로 쪼개서 이어붙이면 안 된다. 영어는 어순이 반대라 그 순간 번역이 불가능해진다.

```ts
// 나쁘다 — 영어로 옮길 방법이 없다
t('elapsed.prefix') + sec + t('elapsed.suffix')

// 좋다 — 자리표시 치환
t('elapsed', { sec })        // ko: "경과 {sec}초"  en: "{sec}s elapsed"
```

복수형 처리(`Intl.PluralRules`)까지는 가지 않는다. 언어가 둘뿐이라 과하다.
필요한 자리가 나오면 그때 키를 둘로 나눈다(`item.one` · `item.other`).

## 5. 요청 4번 — STT는 **한 모델, 언어를 화면이 보낸다**

### 지금 상태

```python
# stt/service.py:133
language: str = Form(default="ko"),
```

폼 기본값으로 `ko` 가 박혀 있고, **화면은 이 값을 아예 안 보낸다**(`SttClient.transcribe()` 확인).
쓰고 있는 faster-whisper large-v3-turbo 는 **이미 다국어 모델이다.**
즉 모델을 바꿀 일이 아니라, **모델에게 언어를 안 알려주고 있었을 뿐**이다.

### 할 일은 두 줄

- `SttClient.transcribe()` 가 `language` 를 FormData에 싣는다
- `service.py` 는 이미 받고 있다 — **손댈 것이 없다**
- `engines/*.py` 는 **한 글자도 안 건드린다** (`verify:stt-port` 바이트 동일성 유지)

### 번역 경유는 넣지 말 것

「영어 화면에서 한국어로 말하면 한국어로 인식한 뒤 영어로 번역」 — 이건 안 만드는 쪽이 맞다. 이유 셋.

**① 신뢰도 판정이 무력해진다.** 지금 음성 경로는 인식 신뢰도 임계 하나로 사용자에게 확인을 받는다(REQ-1306).
번역을 끼우면 「인식은 맞았는데 번역이 틀린」 경우가 생기고, **그건 신뢰도 수치에 안 잡힌다.**
사용자는 통과한 문장을 믿는데 내용이 틀려 있다. 지금 구조에서 가장 나쁜 실패 모양이다.

**② 장비 그라운딩이 깨진다.** `vocab.py` 가 `registry.json` 의 `display_name` 과 `aliases[]` 에서
hotword를 매 요청 새로 뽑는다. 번역기를 거치면 「엣지 노드 A」가 임의의 영어 표현으로 바뀌고,
그 표현은 registry 어디에도 없다. 임무 생성이 장비를 못 찾는다.

**③ 생길 상황이 아니다.** 영문 화면을 쓰는 사람이 한국어로 말하지 않는다.

### 대신 이렇게 한다

**인식 언어는 화면 언어를 따라가되, 발화 패널에서 따로 고를 수 있게 둔다.**
한국인이 영문 화면으로 리허설하면서 한국어로 말하는 경우는 실제로 생긴다.
그때 화면 언어는 그대로 두고 인식 언어만 바꾼다. 선택지는 `화면 언어 따름` · `한국어` · `English` 셋.

**자동 감지(`language=None`)를 기본값으로 쓰지 않는다.** 임무 명령은 한 문장이라 짧고,
짧은 발화에서 언어 감지가 틀리면 **통째로 엉뚱한 언어로 전사된다.**
다만 응답에 `detected_language` 와 `language_probability` 가 이미 실려 온다(`engines/faster_whisper.py:203`).
이걸 버리지 말고, **「지정한 언어와 다르게 들린다」는 경고를 띄우는 데만 쓴다.**
사용자가 언어를 잘못 두고 말했을 때 원인을 화면이 알려주게 된다.

### hotwords

`vocab.py` 에 언어 인자를 더한다. registry에 영어 별칭이 들어간 뒤(L2)
해당 언어 어휘만 뽑아 준다. 두 언어 어휘를 한꺼번에 밀어넣지 않는다 — 인식률이 떨어진다.

## 6. L3 생성 — 가장 위험한 자리

`gen-lab/server/prompt.py` 의 `RULES` 12줄, 장소·장비 렌더, few-shot 예시가 전부 한국어다.
그리고 **`goldset/` 4편과 `score:generation` 베이스라인 숫자가 그 한국어 프롬프트 기준이다.**

영어 프롬프트를 만들면 그 숫자와 **비교할 수 없다.** 프롬프트가 다르면 다른 실험이다.

### 그래서

- 영어 규칙은 `RULES_EN` 으로 **나란히** 둔다. `rules_for(..., lang=)` 이 고른다
- **한국어 경로의 문자열을 한 글자도 안 바꾼다.** 그래야 기존 베이스라인이 그대로 유효하다
- 영어판 점수는 **따로 재고 따로 보고한다.** 한국어 숫자와 같은 표에 넣지 않는다
- 영어 goldset 재작성은 1~2주에 안 된다. **영어 생성은 「돌아간다」까지가 이번 목표**이고,
  정량 평가는 다음 단계로 미룬다. 이걸 미룬다고 적어 두는 것이 이 문서의 몫이다

## 7. 검증

### 신설 3종

| 검사 | 보는 것 |
|---|---|
| `verify:i18n-complete` | ko 사전의 키가 en에 다 있는가. **없어도 실패가 아니라 목록을 찍는다.** 단 「시연 경로」로 표시한 키 집합은 필수 |
| `verify:no-raw-korean` | JSX 텍스트 노드에 한글이 직접 박혀 있는가 — 사전을 우회한 자리를 잡는다. 주석·타입·대본 JSON은 제외 |
| `verify:lang-switch` | 언어를 바꿔도 `renderMode` · 연결 주소 · 기록 열이 안 바뀌는가. **언어가 다른 상태를 오염시키지 않는다** |

### 기존 7종 수정

`verify-autodrive-ai` · `verify-emergency-stop` · `verify-mission-record` · `verify-scenario-mode` ·
`verify-script-autodrive` · `verify-stt-port` · `verify-viewpoint-layout`.

한글 문구를 직접 대조하던 것을 **사전 키 대조로 바꾼다.**
`includes('대본 닫기')` → `includes(t('scenario.close'))` 또는 키 존재 검사.
문구가 아니라 키를 보게 하면 번역이 바뀌어도 검사가 안 깨진다.

`verify-stt-port` 는 예외다 — 여기 걸린 한글(`이식:`)은 UI 문구가 아니라 이식본 주석 표식이라 그대로 둔다.

## 8. 순서 — 1~2주

| 언제 | 무엇 | 끝나면 확인되는 것 |
|---|---|---|
| **1일** | `language.ts` + 세그먼트 UI + `t()` + 빈 en 사전 | 토글이 돈다. 영어는 아직 없다 — **여기서 한 번 멈추고 교수님께 보인다** |
| 2~3일 | 시연 경로 문구 추출 (global-bar · ModeSwitch · 발화 패널 · 승인 · 노드 캔버스) | 전체의 30% 남짓. **시연이 영어로 돌아간다** |
| 4~5일 | registry·대본 `_en` 병기 + STT `language` 인자 + 발화 패널 인식 언어 선택 | 영어 음성 입력이 장비명을 잡는다 |
| 2주차 전반 | 나머지 화면 문구 | 한국어 fallback이 눈에 띄게 줄어든다 |
| 2주차 후반 | `RULES_EN` + 검증 3종 신설 + 기존 7종 수정 | 영어 생성이 돈다. 회귀가 잡힌다 |

**1일차에 멈추는 것이 계획의 일부다.** 골격만 놓고 한 번 보이면,
용어 선택과 범위를 번역을 1,000줄 쓰기 전에 고칠 수 있다.

- **`gateway/` 한글 28,289자.** 목 게이트웨이는 개발 도구라 후순위로 둔다

| 마일스톤 / 태스크 / 액션 아이템 | Milestone / Task / Action Item | 논문 용어와 맞춰야 한다 |
| 자리표시 | Placeholder / Pending | 「못 만든 게 아니라 못 받은 것」 논거가 여기 걸려 있다 |
| 대본 | Script / Scenario | `renderMode` 의 `scenario` 와 겹친다 |
| 되감기 | Rewind / Replay | A-3 선행연구(record-replay)와 구분이 필요하다 |
| 접기 | Fold / Collapse | UI의 collapse와 헷갈린다 |

**② 요구사항 ID와 파트명.** `VZ-*` · `REQ-*` 는 **그대로 두길 권한다** — 엑셀 원본이 그 ID다.
파트명(하드웨어/AI/백엔드)만 Hardware/AI/Backend로 옮긴다. 그 1건이 §0의 타입 리터럴이다.

**③ 번역을 누가 쓰나.** 기계번역 초벌 + 검수인가, 처음부터 손으로인가.
전자를 권한다. 단 §10-① 용어집에 든 말은 치환에서 빼고 손으로 고정한다.

**④ `standalone.html` 을 언어별로 두 벌 뽑나.** 한 벌 권장 — 사전이 작아서 둘을 다 실어도 부담이 없고,
`?lang=` 이 파일 하나에서도 동작한다.

**⑤ 시연 경로에 무엇을 넣나.** `verify:i18n-complete` 가 필수로 잡을 키 집합이다.
