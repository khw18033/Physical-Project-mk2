# 작업 지시: 시연 대본 「문 쪽으로 가」 — 로봇 없이 화면부터 세운다

**날짜**: 2026-09-09
**대상**: 대본 라이브러리 5편째 `MSN-260909-01`
**쓰는 자리**: 2026-09-16 캡스톤 계획발표 시연
**근거**: 시연 순서도 이미지(최신). 공유문서 텍스트와 겹치면 순서도를 따른다

---

## 왜 하나

시연은 로봇·탐지 AI·온디바이스가 다 붙어야 완성되지만, 그 셋은 아직 형식 합의 중이다.
붙기를 기다리면 화면 작업이 발표 사흘 전으로 밀린다.

**그래서 대본으로 먼저 화면을 완성한다.** 기존 대본 4편과 같은 방식이다 —
발화를 키워드로 맞춰 대본을 고르고, 승인하면 `atSec` 축으로 재생한다.
실제 로봇이 붙는 시점에 **대본 재생을 라이브 이벤트로 갈아끼우는 것**이 목표이고,
그러려면 대본이 내보내는 사건 모양이 실제 채널과 같아야 한다. 6절이 그 조건이다.

**LLM은 이번에도 아니다.** `VZ-G-01`은 미착수 그대로 두고 키워드 매칭으로 간다.

---

## 0. 착수 전에 코드로 확인할 것

지시서에 적힌 이름을 그대로 믿지 말고 저장소에서 먼저 확인해라. 다르면 저장소가 맞다.

| 확인 | 무엇을 |
|---|---|
| `scenarios/*.json` 4편 | 파일 구조 · 필드 이름 · `atSec` 축이 실제로 어떻게 생겼는가 |
| `contracts/mission.schema.json` · `task.schema.json` | `node_kind`가 계약에 올라갔는가, 값의 목록은 무엇인가 |
| 대본 매칭 코드 | 키워드 목록을 어디에 두는가 · `no_script_match` 거부 경로 |
| `layout.ts` | 노드 배치가 depth 기반인가 — 8분할 원형 배치에 특례가 필요한지 |
| `shared/registry.ts` | 이번 대본의 장비를 여기 등록해야 하는가 |
| `verify` 목록 | 지금 몇 종이고 무엇을 보는가 |

**아래 3절의 `node_kind` 값은 제안이다.** 저장소의 실제 라벨 집합에 맞춰 바꿔라.
없는 라벨을 새로 만들지 말고, 맞는 게 없으면 보고서에 적고 가장 가까운 것을 쓴다.

## 1. 발화와 매칭

| | |
|---|---|
| 대본 id | `MSN-260909-01` |
| 원 발화 | 저기 문 쪽으로 가 |

발화 변형을 넷 등록한다. **마일스톤·태스크 정답은 넷 다 같다.**

- 저기 문 쪽으로 가
- 문 쪽으로 가
- 문으로 가줘
- 문 앞으로 이동해줘

STT 오인식 대비로 `문쪽`, `문 쪽` 띄어쓰기 양쪽을 다 넣는다.
`stt/vocab.py`에 hotword를 더할 수 있으면 「문」을 올린다.

발표장에서 음성이 실패할 때를 대비해 **텍스트 입력으로 같은 대본이 걸리는지**를 반드시 확인한다.
발표 중에 손이 갈 자리이므로 입력창이 화면에서 바로 보여야 한다.

## 2. 마일스톤 셋

순서도 기준이다. 공유문서 본문에는 둘로 적혀 있으나 **순서도가 최신이다.**

| id | 제목 |
|---|---|
| `MS-A` | 문을 찾는다 |
| `MS-B` | 문에 접근한다 |
| `MS-C` | 임무 완료 |

`MS-C`는 태스크가 없는 종료 마일스톤이다. 상태만 갖는다.
비어 있는 마일스톤을 화면이 못 그리면 `MS-C`에 「임무 종료 확인」 태스크 하나를 두고
보고서에 그렇게 적어라.

## 3. 태스크 — 순서도를 그대로 옮긴다

### MS-A 문을 찾는다

| id | 제목 | node_kind(제안) | deps |
|---|---|---|---|
| `T-A1` | 2D 맵에서 문 위치 확인 | sense | — |
| `T-A2` | 로봇 현재 위치와 각도 파악 | sense | `T-A1` |
| `T-A3` | 로봇이 1바퀴 돈다 | act | `T-A2` |
| `T-A4-0` ~ `T-A4-7` | 0·45·90·135·180·225·270·315도 방향 탐색 | sense | `T-A3` (여덟이 **모두** `T-A3`에 매달린다) |
| `T-A5` | 문이 있는 방향으로 판단 | decide | `T-A4-2` (90도) |
| `T-A6` | 근거 가시화 | verify | `T-A5` |

`T-A4-*` 여덟이 `T-A3` 하나에 나란히 매달리는 것이 순서도의 부채꼴 모양이다.
**`solveDeps` 규칙과 충돌하면 규칙을 고치지 말고 대본에 `deps`를 직접 적어라** —
이번 대본은 사람이 쓴 정답이지 생성 결과가 아니다.

`T-A5`가 `T-A4-2` 하나에만 매달리는 것도 순서도 그대로다. 나머지 일곱에서는 선이 나가지 않는다.

### MS-B 문에 접근한다

| id | 제목 | node_kind(제안) | deps |
|---|---|---|---|
| `T-B1` | 2D 맵 기반 경로 산출 | decide | `T-A6` |
| `T-B2` | 전방으로 직진 | act | `T-B1` |
| `T-B3` | 문과 가까워지면 정지 | act | `T-B2` |

`T-B2`·`T-B3`의 **제목은 위 표 그대로 화면에 뜬다.** 실제로 나가는 명령은 거리값이 든
전진과 정지이고, 그 사실을 화면에 드러내지 않는다. 별도 추상화 층을 만들지 말고
대본의 `params`에 거리를 넣어 두는 선에서 끝낸다.

### 2D 맵은 이번 범위가 아니다

`T-A1`·`T-A2`·`T-B1` 세 태스크는 **노드로만 선다.** 맵 화면은 다른 담당이고,
경로 산출 결과(전진 거리)는 나중에 받아 쓴다. 지금은 대본의 `params`에 상수로 둔다.
**맵 뷰를 만들지 마라.** 자리만 비워 두고 보고서에 적어라.

## 4. 8분할 뷰포인트 — 이 작업의 본체

### 배치

`MS-A`를 열면 `T-A4-*` 여덟이 **원형으로** 놓인다. 0도가 위, 시계 방향으로 45도씩.
`layout.ts`가 depth 기반이면 이 여덟에만 특례를 준다. 레이아웃 엔진 전체를 고치지 마라.

### 상태 셋

| 상태 | 계기 | 화면 |
|---|---|---|
| 대기 | 초기 | 빈 테두리, 흐림 |
| 탐색 중 | 해당 인덱스의 회전 사건 도착 | 테두리 점멸 |
| 판정 완료 | 해당 인덱스의 탐지 사건 도착 | 문 없음 회색 / 문 있음 **초록** |

승인 즉시 여덟이 다 보이되 전부 대기 상태다. **회전이 지나가면서 하나씩 채워진다.**
전부 채워진 뒤 한꺼번에 색이 바뀌는 방식은 안 된다.

### 타임라인

회전 1회당 **1초 회전 + 1초 유지**, 여덟이면 16초다. 대본 `atSec`을 이렇게 깐다.

| atSec | 사건 |
|---|---|
| 0 | 승인, `T-A3` 시작, 노드 여덟 배치 |
| 0 · 2 · 4 … 14 | 인덱스 0~7 회전 시작 → 해당 노드 탐색 중 |
| 1 · 3 · 5 … 15 | 인덱스 0~7 탐지 결과 → 해당 노드 판정 완료 |
| 16 | `T-A3` 완료, `T-A5` 초록 노드에서 선이 나감 |

배속 압축은 기존 대본과 같은 방식으로 한다. **대본에는 실시간 초를 적는다.**

### 초록은 90도 하나

`T-A4-2`만 문 있음이다. 나머지 일곱은 문 없음. 순서도의 초록 칸이 그것이다.

## 5. 판단·근거 노드

`T-A5`와 `T-A6`가 초록 노드 오른쪽으로 두 칸 나간다.

- `T-A5` — 선택된 각도(90도)와 신뢰도
- `T-A6` — 근거 문장과 bbox를 입힌 이미지

근거 문장은 대본에 상수로 적는다. 예시로 아래 정도면 된다. 발표에서 읽힐 문장이니
탐지팀이 실제로 낼 수 있는 형태로 적어 두고, 형식이 확정되면 그대로 갈아끼운다.

```
문틀 수직선 2개와 손잡이를 검출. 폭 0.9m로 추정되어 통행 가능한 문으로 판단.
```

이미지는 지금 없다. **자리를 만들고 없으면 비워 둔다.** 더미 이미지를 그려 넣지 마라.

## 6. 나중에 라이브로 갈아끼우기 위한 조건

이번 대본이 내보내는 사건과 실제 채널이 **같은 모양**이어야 한다.
지금 이걸 안 맞춰 두면 로봇이 붙는 날 화면을 다시 짜야 한다.

| 채널 | 실제로 올 것 | 대본이 내보낼 것 |
|---|---|---|
| 로봇 상태 | `{ rotation_index, yaw, state, last_cmd, result }` | 같은 필드. `yaw`는 인덱스 × 45로 채움 |
| 탐지 결과 | `{ index, angle_deg, door, bbox, confidence, reason }` | 같은 필드. index 2만 `door: true` |

**`rotation_index`가 노드를 채우는 유일한 열쇠다.** yaw로 노드를 고르지 마라 —
실제 로봇은 드리프트가 있어서 각도로 매칭하면 어긋난다.

노드 갱신 코드는 이 두 형식만 보고, 그것이 대본에서 왔는지 게이트웨이에서 왔는지 몰라야 한다.
가르는 자리는 한 곳뿐이어야 한다.

## 7. 승인 앞 정지

기존과 같다. 매칭 결과는 **제안**이고, 사람이 승인하기 전에는 아무것도 재생되지 않는다
(`VZ-U-07`, 기존 `PlanApproval`). 승인 화면에 마일스톤 셋과 태스크 목록이 다 보여야 한다 —
발표에서 "이걸 사람이 확인하고 승인합니다"를 말할 자리다.

매칭 실패는 `no_script_match`로 거부하고 상단 알림. 조용히 넘어가지 않는다.
