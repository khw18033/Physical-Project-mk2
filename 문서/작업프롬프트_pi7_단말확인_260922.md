# 작업 프롬프트 — pi7 단말 노드가 답하지 않는다 (2026-09-22)

> 라즈베리파이 `pi7`의 AI 에이전트에게 붙여 넣는 용도. 가시화 웹(`viz-debugger`) 쪽에서 잰 값과 배제한 것을 그대로 옮겼다.

---

## 한 줄

**브로커는 살아 있고 단말 노드가 안 떠 있다.** `terminal/go1-001/downlink` 를 구독하는 클라이언트가 브로커에 하나도 없어서, 웹이 보낸 `ping` 이 브로커에 접수된 뒤 그대로 버려진다.

가시화 화면에는 이렇게 뜬다.

```

로봇   ?  단말이 답하지 않아 물어보지 못했습니다
```

## 우리가 잰 것 (2026-09-22 오후, 랩 노트북 → Tailscale)

붙은 주소는 `ws://pi7.tailcb6bfb.ts.net:9001/mqtt` 다. 이름은 `100.72.109.9` 로 풀리고 9001 포트는 열려 있다.

### 1. 브로커는 정상이다

| 항목 | 값 |
|---|---|
| `$SYS/broker/version` | `mosquitto version 2.0.21` |
| `$SYS/broker/uptime` | `1308731 seconds` (약 15.1일) |
| CONNACK | `rc=0`, 인증 없이 통과 |
| SUBACK | `terminal/+/uplink` QoS 1 · `zoneA/+/+/{status,state,heartbeat}` 전부 성공 |

### 2. 마지막으로 온 것은 **어제 종료 메시지**다

붙는 즉시 retained 세 건이 오고, 그 뒤로는 아무것도 오지 않는다.

| 토픽 | 내용 |
|---|---|
| `zoneA/robot/go1-001/status` | `event:"shutdown"` · `status:"offline"` · `timestamp:"2026-09-21T16:03:43.978+09:00"` · `reason:"graceful_shutdown"` · `session_id:"58b32a8f2db0"` · `uptime_s:552.5` · `battery_pct:15.0` · `link:"ok"` · `sdk:{ready:false, autostart:true}` |
| `zoneA/sensor/wl-001/status` | `event:"shutdown"` · `status:"offline"` · `timestamp:"2026-09-21T16:03:43.979+09:00"` · `uptime_s:1904.0` · `publish_failures:3` |
| `terminal/go1-sim/sim/state` | `timestamp:"2026-09-10T17:46:51+0900"` — 시뮬레이터 흔적으로 보인다 (아래 ④에서 묻는다) |

**와일드카드 `#` 로 12초 동안 들었을 때 새 메시지 0건.** `heartbeat` 도 `state` 도 없다. `status` 주기가 5초라고 들었으므로, 노드가 떠 있으면 이 창에서 최소 두 건은 와야 한다.

### 3. 명령 평면에 **듣는 사람이 없다** — 이게 결정적이다

MQTT 5 는 QoS 1 발행에 대해 「배달할 구독자가 없었다」를 PUBACK 사유 코드 `16` 으로 돌려준다. 그것으로 쟀다.

| 발행한 토픽 | PUBACK 사유 코드 | 뜻 |
|---|---|---|
| `probe/self/check` (우리가 구독한 대조군) | `0` | 성공 — 계측이 정상이다 |
| **`terminal/go1-001/downlink`** | **`16`** | **아무도 안 듣는다** |
| `terminal/wl-001/downlink` | `16` | 아무도 안 듣는다 |
| `zoneA/robot/go1-001/state` | `16` | 아무도 안 듣는다 |

대조군이 `0` 이므로 측정 자체는 믿을 수 있다. 즉 **브로커에 노드가 붙어 있지 않다.**

## 우리 쪽에서 배제한 것

이건 우리가 이미 확인했으니 다시 보지 않아도 된다.

| 의심 | 확인한 것 |
|---|---|
| 웹이 명령을 안 보낸다 | 보낸다. 브로커가 PUBACK 으로 접수했다 |
| 봉투(protobuf) 가 틀렸다 | `ping` 이 **31바이트**로 나간다 — 그쪽이 실측해 준 기준값과 같다. 바이트를 그쪽 `.proto` 로 되읽으면 `{command:{command_id, target:"go1-001", action:"ping"}}` 로 정확히 복원된다. hex: `0a1d0a0c636d642d...1a0470696e67` |
| 토픽이 틀렸다 | `terminal/go1-001/downlink` (QoS 1). 위 PUBACK 측정에서 `terminal/wl-001/downlink` 도 같이 쐈고 둘 다 `16` 이다 |
| 장비 이름을 우리가 지어냈다 | 아니다. 그쪽 retained `status` 의 `registration.entity_id` 를 그대로 쓴다 |
| 구독보다 발행이 빨라 응답을 놓쳤다 | 아니다. `terminal/+/uplink` 의 **SUBACK 을 받은 뒤**에 발행한다 |
| clientId 가 노드를 밀어냈다 | 아니다. 웹은 `web-<난수>` 로 붙는다. 장비 id 를 clientId 로 쓰지 않는다 |
| 응답 대기가 너무 짧다 | 4초다. 그 안에 uplink 가 **한 건도** 안 온다. 애초에 구독자가 없으므로 시간 문제가 아니다 |

## 부탁

### ① 단말 노드를 올려 주세요 — 이게 본론

어제 16:03:43 에 `graceful_shutdown` 으로 정상 종료된 뒤로 다시 안 떴다. 브로커(mosquitto)는 15일째 돌고 있으니 파이 자체는 켜져 있다. **브로커만 살아 있고 노드만 죽은 상태**다.

올린 뒤 이것만 확인해 주면 된다.

```bash
# 노드가 브로커에 붙었는가 — 여기에 uplink 가 흐르면 됨
mosquitto_sub -h localhost -t 'terminal/+/uplink' -t 'zoneA/#' -v

# 웹이 보내는 것과 같은 명령을 직접 쏴 본다 (그쪽 스크립트가 있으면 그것으로)
#   토픽:   terminal/go1-001/downlink
#   페이로드: Envelope{ command{ command_id, target:"go1-001", action:"ping" } }  = 31바이트
```

### ② 왜 꺼졌고, 다시 꺼질 것인가

- 어제 종료가 **의도한 것**이었는지 (실험 종료 후 수동 종료인지, 아니면 배터리·오류로 내려간 것인지)
- 종료 직전 `battery_pct: 15.0` · `device_status: "degraded"` 였다. 이게 종료 사유와 관계있는지
- **부팅하면 자동으로 뜨는가.** 안 뜬다면 우리 쪽은 시연 때마다 「누가 pi7 에 들어가서 켰는지」를 확인해야 한다. systemd 유닛으로 `enable` 되어 있는지 알려 주면 좋겠다
- 유닛 이름과 로그 보는 법 (`journalctl -u <이름>`) 을 알려 주면 다음부터 우리가 먼저 보고 묻겠다

### ③ `Capability` 를 retained 로 발행해 줄 수 있는가

지금 `Capability` 는 노드가 브로커에 붙는 순간 한 번 발행하고 끝이라, **웹이 늦게 붙으면 영영 못 받는다.** 그러면 웹은 장비가 누구인지 retained `status` 의 `registration` 으로만 알 수 있는데, pi7 에는 장비가 둘(`go1-001` · `wl-001`)이고 **둘 다 `registration` 을 실어 보내서** 명령 대상이 자동으로 안 정해진다.

지금은 우리 쪽 화면에 「명령 대상 고르기」 칸을 만들어 사람이 고르게 해 두었다(그래서 지금은 막히지 않는다). 다만 `Capability` 가 retained 면 이 문제가 근본에서 사라진다 — 붙는 순서와 무관하게 「명령을 받는 장비가 누구인지」가 확정되기 때문이다.

- retained 로 바꾸는 데 걸림돌이 있는가?
- 아니면 `registration` 에 「이 장비는 명령을 받는다」를 나타내는 칸을 하나 넣어 줄 수 있는가?

둘 중 어느 쪽이든 좋다. **우리가 기종 이름(`robot` 은 명령을 받고 `sensor` 는 안 받는다) 으로 가르는 것은 하지 않으려 한다** — 장비가 늘 때마다 웹 코드를 고쳐야 하고, 그때 화면은 아무 말도 안 하기 때문이다.

### ④ `terminal/go1-sim/sim/state` 는 무엇인가

9월 10일자 retained 메시지가 남아 있다. 시뮬레이터 설정값으로 보인다. 지금도 쓰는 것이면 그대로 두고, 안 쓰는 것이면 지워 주면 좋겠다 — `terminal/…` 아래에 있어서 명령 평면을 볼 때마다 눈에 걸린다.

## 부록 — 우리 쪽 재현 절차

같은 것을 그쪽에서 확인하고 싶을 때. 노트북에서 돌린 것이다.

1. `ws://pi7.tailcb6bfb.ts.net:9001/mqtt` 에 MQTT 5 로 붙는다 (인증 없음)
2. `#` 을 구독하고 12초 기다린다 → retained 3건 외 **0건**
3. `terminal/go1-001/downlink` 로 QoS 1 발행하고 PUBACK 사유 코드를 읽는다 → **16**
4. 대조군으로 자기가 구독한 토픽에 같은 발행을 한다 → **0**

3번과 4번의 차이가 이 보고의 근거 전부다.
