# 작업 지시: 정량 명령 직접 입력 (2026-09-22)

사람이 **「1m 전진 후 오른쪽 90도 회전」**처럼 숫자로 적은 명령을 로봇이 그대로 실행하게 한다.
연결은 시연과 같다 — pi7 의 브로커로 protobuf 명령을 발행하는 그 경로다.

**로봇 쪽은 고치지 않는다.** pi7 이 이미 받는 `turn` · `move_forward` 만 쓴다. 명령을 차례로 내고
앞엣것이 끝나야 다음을 내는 장치도 이미 있다(`issueApproach`). 없는 것은 **사람이 적은 문장에서
숫자를 꺼내 그 장치에 넘기는 자리** 하나다.

## 2. 규약이 주는 제약 — 로봇의 한계와 어휘의 한계를 가른다

### 2-1. 쓸 수 있는 것

| action | 파라미터 | 범위 |
|---|---|---|
| `turn` | `deg` | 오른쪽 +, **5~360** |
| `move_forward` | `distance_m` · `vx` | **0.05~10 m** · **0.05~0.30 m/s** (생략하면 0.15) |

### 2-2. 10m 를 넘는 직진은 **끊어 보내면 된다**

10m 는 명령 한 건의 상한이지 이동 거리의 상한이 아니다. 15m 는 `move_forward 7.5` 둘이다.
**차례로 내는 장치가 이미 있으므로 새로 만들 것이 없다** — 자르는 규칙만 §4 에 둔다.

### 2-3. 뒤로 가기 · 옆으로 걷기 — **로봇이 아니라 어휘의 한계다**

Go1 은 뒤로도 옆으로도 걷는다. 막는 것은 pi7 이 열어 둔 명령 목록이다. `move_forward` 의
범위는 거리도 속도도 **양수 자리만** 적혀 있고, 음수를 넣으면 어떻게 되는지는 **문서에 없고
쏴 본 적도 없다.** 거절될 수도 있고 절댓값으로 읽혀 **앞으로 갈 수도** 있다.

- **옆으로 가기는 지금도 된다** — `turn 90` → `move_forward 1` → `turn -90`. 게걸음이 아니라
  결과가 같은 것이다. 몸이 도는 것이 문제가 되는 경우(카메라가 계속 앞을 봐야 한다든지)에만
  진짜 횡보가 필요하다.
- **뒤로 가기는 흉내 낼 수 없다.** `turn 180` 은 돌아서는 것이지 후진이 아니다.
- **음수를 실험으로 알아보지 않는다.** §10 으로 묻고, 답을 받고 나서 만든다.

## 3. 문장 → 걸음 목록 — `src/physical/stepScript.ts` (신설)

정규식으로 읽는다. **모델을 부르지 않는다** — 숫자를 지어내면 로봇이 그만큼 움직인다.
대본 매칭이 LLM 이 아닌 것과 같은 이유다(`scenarios/matcher.ts` 머리주석).

### 읽는 것

| 갈래 | 받는 표기 |
|---|---|
| 거리 | `1m` `1 m` `1미터` `50cm` `0.5m` |
| 각도 | `90도` `90°` |
| 방향 | `왼쪽` `좌` `반시계` → **음수** · `오른쪽` `우` `시계` → **양수** |
| 동작 | `전진` `직진` `앞으로` · `회전` `돌아` `돌아라` |
| 이어붙임 | `후` `다음` `그리고` `,` `→` |

### 거부하는 것 — **절반만 읽고 나머지를 지어내지 않는다**

| 문장 | 결과 | 왜 |
|---|---|---|
| `90도 회전` | **거부** | 방향이 없다. 기본값을 정해 두면 반대로 도는 날이 오고, 그것은 로봇이 실제로 움직이는 일이다 |
| `조금만 앞으로` | **거부** | 수치가 없다 |
| `1m 전진 후 어쩌고` | **거부** | 일부만 읽고 내면 사람이 적은 것과 다른 것이 나간다 |

거부할 때는 **무엇을 못 읽었는지** 말한다 — 「방향을 적어 주세요 — 왼쪽 90도 / 오른쪽 90도」.

결과는 기존 `TaskCommand[]` 모양 그대로 낸다. 발행기가 이미 읽는 형식이다(`missionLink.ts`).

## 4. 규약에 맞게 자르기 — 같은 파일

### 구간 길이는 **속도에서 거꾸로 계산한다**

`STEP_TIMEOUT_MS` 가 60초다. 속도를 안 실으면 로봇 기본값 0.15 m/s 이고 **10m 에 67초** —
시한을 넘겨 다음 구간을 안 내고 멈춘다. 규약 상한만 보고 자르면 이 자리에서 걸린다.

```
구간 상한 = min(10m, vx × 45초)      // 45 = 60초 − 기립·가감속 여유 15초
```

| vx | 계산 | 실제 상한 |
|---|---|---|
| 0.30 m/s | 13.5m | **10m** (규약이 먼저 걸린다) |
| 0.15 m/s (기본값) | 6.75m | **6.75m** |

### 나머지

- 회전 360도 초과 → 여러 번으로 나눈다.
- **5도 미만 회전 · 0.05m 미만 직진은 안 낸다.** 규약이 안 받는다. 그 사실을 화면에 적는다.
- **자른 것을 숨기지 않는다** — 「직진 15m → 7.5m 두 번으로 나눠 보냅니다」를 보내기 전에 적는다.

### 끊어 보낼 때 생기는 것

- **오차가 쌓인다.** 구간마다 서고 다시 출발하니 가감속이 반복되고, 걸음 수로 재는 거리라
  조금씩 어긋난다. 중간에 방향을 다시 잡아 주는 장치가 없다. 결과의 `odo_m` 을 구간마다
  더해 **「명령 15m / 실제 14.6m」**로 보여 준다 — 지어서 맞추지 않는다.
- **정지가 들을 틈이 생긴다.** 구간 사이마다 `canIssueRobotCommand()` 를 다시 묻는다.
  이미 나간 구간은 로봇이 다 걷지만, 다음 구간은 안 나간다.

## 5. 발행기를 공통으로 — `robotCommands.ts` 수정

지금 `issueApproach` 안에 있는 반복을 **`issueSteps(client, steps)`** 로 떼어낸다.

```
한 걸음 발행 → 종료 응답 대기 → 실패·거절이면 멈추고 사유 반환 → 다음 걸음
```

- `issueApproach` 는 그 함수를 부르게만 바꾼다. **동작이 바뀌면 안 된다** —
  `verify:approach-plan` · `verify:command-log` 가 착수 전 그대로 통과하는지가 합격 기준이다.
- 새 기능도 같은 함수를 부른다. **추적기·감사·정지 관문을 한 벌만 지나간다**
  (`verify:command-through-tracker` · `verify:single-egress`).
- 구간마다 결과의 `odo_m` 을 모아 합계를 돌려준다.
- `command_id` 는 멱등키다. 기존 `nextCommandId()` 를 그대로 쓴다 — 새로 만들지 않는다.

### 두 박자로 나눈다 — 읽은 결과를 먼저 보여 준다

1. 입력칸에 문장을 적고 **「보낼 명령 확인」**

화면 문구를 파일에 직접 적지 않는다 — `src/i18n/dict.ts` 를 거친다.

## 9. 실물 시험 순서

**조종기 든 사람이 옆에 있어야 한다.** 로봇을 들어 허공에서 걷게 하고 먼저 돌린다.

1. `ping` 왕복 — 초록을 보고 시작한다
2. `turn 90` 하나 — **회전만 하는가, 직진 한 걸음이 붙는가**(§10-4)
3. `move_forward 1` 하나 — `odo_m` 확인
4. `1m 전진 후 오른쪽 90도` — 두 걸음이 이어지는가
5. `15m 전진` — 두 구간으로 잘려 나가는가, 시한에 안 걸리는가
6. 5 의 중간에 **정지** — 다음 구간이 안 나가는가
7. 바닥에 내려놓고 짧은 거리부터 — 오차 측정은 여기서부터다

**음수 실험은 이 목록에 없다.** §10 답을 받고 나서 한다.

## 11. 하지 않을 것

- **pi7 수정** — 이번 범위 밖이다. §10 은 질의이지 작업이 아니다
- **음수 거리·속도 발행** — 답을 받기 전에는 안 쏜다
- **모델로 문장 읽기** — 숫자를 지어내면 로봇이 움직인다. 규칙으로 읽고 못 읽으면 거부한다
- **방향 없는 회전에 기본값 주기** — 되묻는다
- **시연 대본에 넣기** — 무대는 일반 모드에서 「저기 문 쪽으로 가」 한 편이다. 이건 그 옆의 도구다
- **pi1(자율주행 편)과 엮기** — 이 명령은 pi7 로만 간다
- **`physical_demo` 수정** — 탐지 폴더는 따로 진행 중이다
- **`.proto` 수정** — `HW` 브랜치 것이다
- **탐지 경로(`planApproach`)의 동작 변경** — 발행기를 공유할 뿐 계산은 건드리지 않는다
