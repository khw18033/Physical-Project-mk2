# 작업 지시: 객체 탐지 연동 (2단계-B)

**날짜**: 2026-09-10 (탐지 쪽 협의 반영)
**선행**: 2단계-A 하드웨어 연동 (`작업프롬프트_하드웨어연동_260910.md`)
**범위**: 탐지 HTTP 채널과 전역 뷰 노드 셋
**규약**: `문서/탐지_명령규약_260910.md` — 탐지 담당에게 보낸 안. **형식의 근거는 그 문서다**

---

## 0. 협의로 정해진 것

| | |
|---|---|
| 프레임 경로 | **로봇 → 탐지.** 관제 웹을 거치지 않는다 |
| bbox | **탐지가 입혀서 준다.** 우리는 그리지 않는다 |
| 관제 웹이 보내는 것 | **명령 둘뿐** — 스캔 시작·종료 |
| 결과 받는 방향 | **우리가 가져간다.** 브라우저는 받는 쪽이 못 된다 |
| 셋을 묶는 열쇠 | **`command_id`** — 관제 웹이 만들고 로봇·탐지가 같은 값을 쓴다 |

```
관제 웹 ──① scan_mission (command_id) ──▶ 로봇
관제 웹 ──② POST /detect/mission/start ──▶ 탐지   (같은 command_id)
로봇   ──③ 프레임 + command_id + step ──▶ 탐지
탐지   ──④ GET /detect/results ◀────────── 관제 웹이 가져간다
```

**`command_id`가 이 절의 요점이다.** 2단계-A에서 이미 만들어 쏘고 있는 값이고,
그것을 탐지에도 그대로 알려 주면 셋이 한 판으로 묶인다. 새 식별자를 만들지 마라.

## 1. 착수 전에 확인할 것

| 확인 | 무엇을 |
|---|---|
| 2단계-A 결과물 | `command_id`를 만드는 자리 · `step → index` 변환 자리 |
| 뷰 노드 | 화면 도구 줄에 `+ 장치·위험` · `+ 지표` · `+ 영상`이 있다. **전역 노드로 놓는 경로가 이미 있다** |
| `+ 영상`이 왜 비활성인가 | 「이 대본엔 없음」으로 꺼져 있다. 대본이 무엇을 선언해야 켜지는지 |
| 연결 관리 | `physical`을 등록한 자리. `detect`도 같은 방식으로 올린다 |

**새 뷰 노드 종류를 만들지 마라.** `+ 영상` 계열을 쓴다. 대본 선언만으로 켜지는 구조라면
`MSN-260909-01`에 선언을 더하는 일이 된다.

## 2. 두 출처가 만나는 자리

| 무엇 | 출처 |
|---|---|
| 몇 번째 각도를 보고 있는가 | **로봇** — `CommandStatus.detail.step` (1부터) |
| 그 각도에 문이 있는가 | **탐지** — 결과의 `index` (0부터) |

탐지 쪽에 `index`를 0부터로 맞춰 달라고 요청했다. **그대로 오면 변환이 없다.**
1부터 오면 받는 자리에서 한 번만 −1 한다 — **여러 곳에서 빼지 마라.**

## 3. 탐지에 보내는 명령 둘

규약 1절 그대로다.

```
POST /detect/mission/start
{ "command_id": "cmd-...", "steps": 8, "angles": [0,45,90,135,180,225,270,315] }

POST /detect/mission/stop
{ "command_id": "cmd-...", "reason": "완료" }
```

**`start`는 로봇에 `scan_mission`을 쏘는 것과 같은 순간에 나간다.**
둘 중 하나만 성공하면 판이 어긋난다. 순서는 탐지 `start` → 로봇 `scan_mission`이 낫다 —
탐지가 준비되기 전에 프레임이 도착하는 것보다 낫다.

**탐지가 없어도 로봇 명령은 나가야 한다.** `start`가 실패해도 스캔은 돈다.
그 경우 뷰 노드 셋만 꺼지고 노드는 대본 값으로 찬다.

`stop`은 `CommandResult`가 오면 `완료`로, 사용자가 중단하면 `중단`으로 보낸다.
못 보내고 끊길 수 있으니 **여기에 기대지 마라** — 다음 판은 새 `command_id`로 갈린다.

## 4. 결과 가져오기

```
GET /detect/results?command_id=...      여덟 전부
GET /detect/current?command_id=...      현재 프레임 (image/jpeg)
GET /detect/frame?command_id=...&index=n 각도별 프레임
GET /health                              살아 있는지
```

주소는 연결 관리에 `detect`로 올린다. **탐지 서비스가 없으면 뷰 노드 셋만 꺼진다.**

### 결과 붙이는 규칙

- **도착 순서가 아니라 `index`로 노드를 찾는다.** 2단계-A와 같다
- `command_id`가 지금 판과 다르면 **버린다**
- 이미 확정된 노드에 같은 `index`가 또 오면 **나중 것으로 덮는다**
- 배열에 없는 각도는 **아직 안 본 것**이다. `door: false`로 치지 마라

마지막 줄이 중요하다. 결과에 없는 것과 문이 없는 것은 다르다.
없는 각도는 노드를 「탐색 중」이나 「대기」에 둔다.

## 5. 전역 뷰 노드 셋

마일스톤 A에 **전역 노드로** 붙인다. 스캔이 도는 16초 내내 떠 있어야 한다.

| 뷰 노드 | 내용 | 출처 |
|---|---|---|
| `VIEW-CAM` | 객체 탐지 영상 — bbox 입힌 현재 프레임 | `GET /detect/current` |
| `VIEW-MAP` | 2D 맵 — **받아서 띄우기만 한다** | 다른 담당 |
| `VIEW-REASON` | 현재 각도의 판단 문장 | `GET /detect/results`의 최신 것 |

### `VIEW-REASON`과 `T-A6`는 다르다

| | 무엇을 |
|---|---|
| `VIEW-REASON` | 스캔이 도는 동안 **흐른다.** 지금 보는 각도의 문장 |
| `T-A6` 근거 가시화 | 끝난 뒤 **남는다.** 최종 선정된 방향의 문장 |

같은 컴포넌트를 쓰되 데이터 출처를 갈라라.

### `VIEW-MAP`은 자리만

맵을 받을 형식이 아직 없다. **더미 이미지를 그려 넣지 마라.**
자리를 만들고 「맵 대기 중」으로 두고, 형식이 오면 채운다.

## 6. 폴링 규칙

**WebSocket이나 SSE를 새로 깔지 마라.** 붙을 시간이 없다.

| 언제 | 무엇을 | 간격 |
|---|---|---|
| 스캔 도는 중 | `/detect/current` | 500ms |
| 스캔 도는 중 | `/detect/results` | 1s |
| 그 외 | 없음 | **멈춘다** |
| 각도별 프레임 | 그 노드를 열었을 때만 | 1회 |

`start`를 보낼 때 켜고, `CommandResult`가 오면 끈다. 규약 4절로 탐지 쪽에 알려 두었다.
스캔이 아닐 때도 폴링이 돌면 발표 중에 네트워크가 시끄러워진다.

## 7. 목 탐지 서버

`mock/` 아래에 하나 둔다. 3·4절 엔드포인트를 흉내 낸다.

- `start`로 받은 `command_id`를 기억하고, 다른 `command_id`로 물으면 빈 결과
- index 2만 `door: true`, `confidence: 0.93`. 나머지 일곱은 0.1~0.4로 흩어 놓는다
- 2단계-A의 목 uplink와 **같은 시계로** 결과를 내놓는다 — 회전 1초+1초에 맞춰
- **결과가 한 번에 다 있지 않게** 하라. 시간이 지나며 배열이 하나씩 는다
- **한 번은 3초 늦게** 내보내 늦은 결과가 제대로 붙는지 본다
- 프레임은 각도 숫자를 크게 쓴 단색 JPEG. **실사진을 흉내 내지 마라**
- CORS 헤더를 붙여 둔다 — 실제 서비스에서 빠졌을 때 목에서는 되고 실물에서 안 되는
  상황을 만들지 않기 위해, 목은 **일부러 실물과 같은 조건**으로 둔다

## 8. 검증

| 검사 | 무엇을 |
|---|---|
| **`verify:detect-index`** (신설) | `index`(0~7)가 노드에 옳게 붙는가 · **뒤섞어 넣어도 제자리를 찾는가** · 늦게 온 것이 덮는가 · **다른 `command_id`를 버리는가** · 배열에 없는 각도를 `door: false`로 치지 않는가 |
| **`verify:mission-id`** (신설) | 로봇에 쏜 `command_id`와 탐지 `start`에 보낸 값이 **같은가** · 새 판에서 앞판 결과가 안 섞이는가 |
| **`verify:no-detect`** (신설) | 탐지가 없어도 **로봇 명령은 나가고** 뷰 노드 셋만 꺼지는가 · 대본 재생·되감기·캔버스가 도는가 |
| **`verify:detect-port`** (신설) | 탐지 주소를 아는 면이 `src/detect/` 하나인가 |
| **`verify:poll-lifecycle`** (신설) | 스캔이 아닐 때 폴링이 실제로 멈추는가 (`CommandResult` 뒤 요청 0건) |
| 2단계-A · 1단계 검사 | 그대로 통과 |
| `verify:standalone` | 증가분을 숫자로 남긴다 |
| 기존 전종 | 통과 |

`verify:mission-id`가 이번의 핵심이다. **리허설을 여러 번 돌리는 것이 전제**라
판이 안 갈리면 두 번째부터 화면이 틀린다. 그리고 그건 눈으로 보면 그럴싸하게 돌아간다.

## 9. 하지 않을 것

- **bbox를 우리가 그리는 것** — 탐지가 입혀서 준다. 그리는 코드를 만들지 마라
- 프레임을 관제 웹이 받아 탐지로 넘기는 경로 — 로봇이 직접 보낸다
- 2D 맵 자체 구현 — 더미 이미지도 그리지 않는다
- WebSocket·SSE 탐지 채널 신설
- 새 뷰 노드 종류 신설 — 기존 `+ 영상` 계열을 쓴다
- 새 임무 식별자 신설 — `command_id`를 쓴다
- 뷰포인트 노드의 배치·색 (1단계) · 로봇 명령 경로 (2단계-A)

## 11. 우리가 정해야 할 것 둘

**탐지 쪽 답이 아니라 우리 판단이다.**

### 문이 두 방향에서 잡히면

시연은 90도 하나만 `true`지만 라이브에서는 둘 이상이 뜬다. 복도에서 45도와 90도가
같은 문을 걸치는 경우가 흔하다.

**최고 confidence 하나만 초록으로 한다.** 나머지도 `door: true`였다는 기록은
노드를 더블클릭하면 보이게 남긴다. 화면에서 초록은 하나다.

### 아무 데서도 안 잡히면

여덟이 다 미선정이면 `MS-B`로 갈 선이 없다. **「문을 찾지 못함」 상태를 하나 두고
거기서 멈춰라.** 임의로 한 방향을 고르지 마라.

시연에서는 안 나올 경우지만, 안 만들어 두면 리허설에서 화면이 얼어붙는다.
