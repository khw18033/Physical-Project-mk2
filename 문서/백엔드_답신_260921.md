## 붙여 넣을 답신

그 결과까지 같이 적는다.

먼저 **문서 둘이 `/state` 에 대해 반대로 말한다**는 것을 확인했다 —
`vz-media-interface.md` §3 은 「바꾸지 마라」이고 실측준비 v2.2 §3-3 은 「이번에 함께 붙인다」다.
**나중 것(09-21 개정)을 따랐다.** 다만 그 문장이 *"와이어 어댑터를 만들어 둔다"* 는 예정형이라,
**그 어댑터가 서버에 실제로 올라갔는지** 먼저 알려 달라(아래 「우리가 묻는 것」 ①).

### 1. §10 의 다섯

| # | 무엇 | 답 |
|---|---|---|
| ① | 관제 웹 기기의 tailnet 주소 | 《`tailscale ip -4` 출력을 여기 적는다》 |
| ② | CORS 허용 origin + exporter 종류 | origin 은 《아래 후보 중 실제로 쓸 것》 · exporter 는 **OTLP/HTTP + JSON** |
| ③ | https 로 서빙하는가 | **아니다 — http 다.** 《바꿀 계획이 있으면 여기 적는다》 |
| ④ | 실제 `source_id` | 받았다. 개체 `go1-001` · 카메라 `go1-001_front` 로 이해했고, **둘을 갈라서** 쓰고 있다 |
| ⑤ | 「발화 원문」 라벨의 실제 키 이름 | 아래 참조 |

**② origin 후보.** 관제 웹은 Vite 로 서빙하고 포트가 판마다 다르다:

```
통합 빌드(지금 쓰는 것)   http://<관제 웹 기기>:5174
단독 빌드                  http://<관제 웹 기기>:5175
```

시연 때 어느 쪽을 띄울지는 정하면 알려 주겠다. **둘 다 열어 두는 것이 편하면 둘 다** 적어 달라.
origin 에는 경로가 안 들어가므로 위 형태 그대로다.

**② exporter 종류 — JSON.** 브라우저에서 보낼 것이고, 지금 저장소에 OTel 의존성이 **0건**이라
(발행 코드가 아직 없다) 넣을 때 `@opentelemetry/exporter-metrics-otlp-http` 를 쓸 것이다.
그쪽 기본이 JSON 이다. protobuf 변형이 필요하면 말해 달라 — 패키지가 갈린다.

**③ http 다.** Vite 개발·미리보기 서버를 그대로 쓰고 TLS 설정이 없다. 그래서 `http://<서버>:4318`
로 보내도 mixed content 가 안 난다. **https 로 바꾸게 되면 미리 알리겠다** — 그때 4318 에 TLS 가
필요해지고 그건 결정 7 범위 밖이라고 적어 둔 것을 봤다.

**⑤ 「발화 원문」 — 지금은 라벨로 안 내보낸다.**

정확히 적는다. 우리 자체 관측(`VZ-O-04`)이 60초마다 보내는 것은 **숫자 여섯뿐이고 라벨이 하나도
없다**:

```
source · period_sec · measured_at · envelope_count · apply_delay_avg_ms · apply_delay_max_ms
```

그러니 **오늘 기준으로는 금지 라벨에 넣을 것이 없다.** 발화 원문이 있는 자리는 관측이 아니라
임무 계약이고, 거기서의 이름은 **`utterance.text`** 다(`contracts/mission.schema.json` —
`utterance` 의 필수 넷 중 하나). 라벨로 평탄화할 일이 생기면 **`utterance_text`** 로 내보내겠다.
그 이름으로 `FORBIDDEN_LABELS` 에 미리 넣어 두면 우리가 실수해도 막힌다.

### 2. `node_ref` — 그러겠다

DAG 노드 식별자를 `node_ref` 라는 이름으로 내보내겠다. 그쪽 공통 헤더의 `node_id` 가
**발행 물리 노드**라는 것과 뜻이 다르다는 지적이 맞다.

### 3. `vz-stt`·`vz-gen` 이 어디서 도는가 — **관제 웹과 같은 기기다**

둘 다 관제 노트북에서 도는 사이드카다. 기본 주소가 `http://127.0.0.1:8801`(STT) ·
`http://127.0.0.1:8802`(생성)이고 브라우저와 같은 기계다.

→ **방화벽 `/32` 대상이 갈리지 않는다.** ① 로 보내는 주소 하나면 셋(`vz-viewer`·`vz-stt`·`vz-gen`)이
다 덮인다. 사이드카는 브라우저가 아니므로 gRPC 를 쓸 수 있다 — 어느 쪽이 편한지 알려 주면 맞추겠다.

### 4. 탐지 규격 정합 (§6) — 넷 다 답이 나왔다

| 물음 | 답 |
|---|---|
| `coord` ↔ `bbox_space` — 어느 이름으로 | **`bbox_space` · `format` · `reference`** 로 해 달라. 「초안이라 비용이 0」이라고 한 그쪽 제안을 받는다 |
| `format` 기본값을 `normalized` 로 | **우리 쪽에는 기본값이 없다.** `bbox_space` 는 발신자가 선언하고 화면은 `normalized`·`absolute` **둘 다 읽는다**. 무엇을 기본으로 보낼지는 그쪽이 정하면 된다 |
| `origin.tier` 에 `server` 추가 | ✅ **넣었다.** 전에는 `tier !== 'device' && tier !== 'edge'` 로 **서버 탐지를 통째로 드롭**하고 있었다 |
| `alignment` fail-safe | ✅ **구현했다.** 아래 참조 |

**`alignment` 를 이렇게 구현했다.**

```
alignment === 'frame'   프레임 정합
그 밖의 값이 실려 옴     정합하지 않는다 — 사용자 토글이 켜져 있어도
값이 아예 없음           옛 계약 — 사용자 토글이 정한다
```

마지막 줄만 그쪽 규칙과 다르다. 통지는 *"부재·모르는 값 포함 전부 unaligned"* 인데,
**부재까지 unaligned 로 두면 목 게이트웨이의 정합 시연이 통째로 죽는다** — 그 시연이 이 화면의
존재 이유라 살려 뒀다. 새 계약이 오면 `alignment` 가 실려 오므로 그때부터는 그쪽 규칙 그대로다.
이 판단이 곤란하면 알려 달라.

그리고 **정합하지 않았다는 사실을 화면이 적는다.** 안 적으면 정합 안 된 박스가 정합된 것처럼
보인다.

### 5. `frame_ref` 는 객체로 받고 있다

정수 하나가 아니라 `{source_id, capture_timestamp, sequence_id}` 로 받는다. 버퍼 키는
`(source_id, sequence_id)` 쌍이고, **순번이 줄면 새 세션으로 보고 버퍼를 비운다** — 헤더에 세션
식별자가 없다는 지적대로다.

옛 계약(정수)도 같은 입구에서 받는다. 그때 `source_id`·`capture_timestamp` 는 **모르는 것이므로
`null`** 이고 지어 채우지 않는다.

### 6. `/media` 수신 경로는 섰다 — 아직 붙어 보지 못했을 뿐이다

§5 의 넷을 다 만들었다.

```
① binaryType='arraybuffer'   ② 문자열/바이너리 갈래
③ [4B][JSON][페이로드] 파서   ④ JPEG=createImageBitmap · H.264=WebCodecs
```

- **파서는 던지지 않는다.** 사유를 값으로 돌려주고 넷으로 가른다(짧음·길이초과·JSON아님·
  필수칸없음). 30fps 30초치 900장을 11ms 에 뜯는 것을 확인했다.
- **버리는 자리마다 센다.** 화면에 받음·뜯음·그림·밀려서 버림·세션 다섯을 늘 적는다.
  부탁한 대로 **전송 계층의 `catch { return }` 에도 카운터를 붙였다.**
- **코덱 문자열은 헤더에서 읽는다.** 상수로 안 박았다 — 스키마 예시의 `avc1.42E01E` 를 복사하지
  말라는 경고를 봤다.
- HW 가 실기에서 고친 다섯(소프트웨어 디코드 선호 · 최신 프레임만 · 보조 타이머 ·
  `desynchronized` 제거 · 캐시 금지)을 처음부터 넣었다. **뷰어가 자기 큐를 관리한다** —
  `decodeQueueSize` 가 임계를 넘으면 버린다. 서버 drop-old 가 여기까지 못 온다는 실측 지적대로다.
- **4401·4404·4400 은 재시도하지 않는다.**

붙는 자리는 **하드웨어 카드를 더블클릭하면 나오는 대상 상태(VZ-D-07)** 안의 한 칸이다.
§8 에서 카메라 상태를 「VZ-D-07 대상 상태 조회의 한 칸」이라고 한 것과 같은 자리다.
**열면 붙고 닫으면 끊긴다**(「패널 열 때 붙으면 온디맨드」).

⚠ 다만 **장비와 카메라의 대응표가 없어서** 지금은 화면에 손으로 넣은 카메라 키 하나로 붙는다.
레지스트리가 Phase 5/6 이라는 것을 알고 있고, 그때까지는 화면이 「대응표가 아직 없다」를
그대로 적는다.

### 7. 구역 식별자 — 상수가 아니라 연결 설정으로 옮겼다

`zone-503`(목) ↔ `zoneA`(그쪽) 문제다. 값을 통째로 `zoneA` 로 바꾸면 **기존 시연 경로가 빈
화면**이 되고, 그대로 두면 관문 C-a 가 성립하지 않는다 — 어느 쪽을 골라도 한쪽이 죽는다.

그래서 구역을 **게이트웨이 연결 설정의 한 칸**으로 옮겼다. 주소를 바꾸는 사람이 구역도 같이
바꾼다. 구독 selector 모양 `{entity:'*', node:<zone>, channel:'*'}` 은 그대로다 — 그쪽이 이 모양에
맞췄다고 한 것을 봤다.

### 8. 🔴 `state` payload 가 `StateLayers` 모양이 아니다 — 알리기만 한다

우리 화면은 상태 3층(`device_status`·`availability`·`deployment`·`last_seen`·
`stale_threshold_ms`·`reason`)을 기대하는데, 실측대비용 어댑터는 **원래 메시지를 통째로**
payload 에 넣는다. 가용성 판정이 Phase 5 라 `availability` 가 없는 것도 맞다.

**이번 실측을 막지는 않는다.** 3층 모양이 아니면 「알 수 없음」으로 두는 가드를 넣었고,
레지스트리 밖 개체 칸은 애초에 판정을 안 그리고 원문을 적는다.

알리는 것은 사실 하나다 — **이번 판에서 로봇 상태는 화면에 「알 수 없음」으로 보인다.**
어댑터가 `StateLayers` 를 채울지는 **Phase 5 정식 계약과 함께 정하자.** 실측대비용 임시 구현에
3층을 억지로 채우게 하면 그 모양이 그대로 굳는다.

**잠정값 셋은 확인했고 문제없다** — `quality="good"` 는 저장만 하고 읽는 화면이 없고,
`aggregation:"raw"` 는 정상 RAW 로 처리되고, `coordinate_frame:null` 은 그 줄만 숨긴다.
**그 자리를 먼저 맞춰 줄 필요 없다.**

### 9. `VZ-C-07` 문면 — 다시 읽어 보니 **규칙은 안 깨진다**

문면 재협상이 필요하다고 한 지적을 받고 원문을 다시 봤다. 우리 요구사항의 실제 문장은
이렇다:

> **출입구는 여전히 하나입니다.** 주소만 런타임에 바뀌고, **나가는 길은 그대로 하나**입니다.
> 여기저기서 주소를 읽게 만들면 「명령 출구는 하나」라는 규칙이 무너집니다.

근거절이 **「나가는 길」**이다. 그리고 `/media` 는 **제어 메시지가 없고**(붙는 것이 켜기)
우리도 그쪽으로 **아무것도 보내지 않는다** — 명령 출구는 여전히 하나다. 즉 **규칙은 안 깨졌고
깨진 것은 낱말**이었다: 「출입구」가 들어오는 길과 나가는 길을 한 낱말에 묶는 바람에,
**받는 소켓이 하나 느는 것만으로 규칙이 깨진 것처럼** 읽혔다.

그래서 문면을 **「나가는 길은 하나입니다」**로 고치고, 왜 고쳤는지를 같이 적었다.
그리고 **영상 소켓이 수신 전용이라는 것을 검사로 못 박았다** — 거기서 한 줄이라도 내보내기
시작하면 그때는 진짜로 규칙이 깨지므로, 그 순간을 잡는다.

정리하면 **재협상할 것이 없다.** 알려 줘서 고맙다 — 덕분에 낱말을 고쳤다.

## 바로잡는 것 하나

앞서 우리가 보낸 관측 회신에서 **「HW 실제 주기를 확인해 달라」**고 했는데, 그쪽이 HW 는
이미 15초로 종결됐다고 알려 줬다(SRS §9.11). 확인했고 **우리 60초는 그대로 간다** — 주기는
발신자 몫이고 Collector 가 어떤 주기든 받는다는 답도 확인했다.
