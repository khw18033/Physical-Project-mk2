# 관제 웹 ↔ 객체 탐지 — 명령 규약 (안)

**작성** 2026-09-10 · 김현우 (가시화)
**전제** 프레임은 하드웨어가 탐지로 직접 보낸다. 관제 웹은 **명령만** 보내고 결과를 받는다.

---

## 0. 세 파트가 어떻게 묶이는가

```
관제 웹 ──① scan_mission (command_id) ──▶ 로봇
관제 웹 ──② 스캔 시작 (command_id) ─────▶ 탐지
로봇   ──③ 프레임 + command_id + step ──▶ 탐지
탐지   ──④ 결과 (command_id, index) ────▶ 관제 웹 (웹이 가져간다)
```

**`command_id` 하나가 셋을 묶는 열쇠다.** 관제 웹이 만들고, 셋이 같은 값을 쓴다.
이미 하드웨어 봉투에 `command_id` 필드가 있으니 새로 만들 게 없다.

이게 없으면 리허설 두 번째 판이 첫 번째 결과 위에 얹힌다.

---

## 1. 관제 웹 → 탐지 : 명령 둘

### 스캔 시작

```
POST /detect/mission/start
Content-Type: application/json

{
  "command_id": "cmd-f444b6f0",
  "steps": 8,
  "angles": [0, 45, 90, 135, 180, 225, 270, 315]
}
```

로봇에 `scan_mission`을 쏘는 것과 **같은 순간**에 보낸다. 같은 `command_id`다.
이 값으로 결과를 묶어 주면 된다.

응답은 `200`이면 충분하다. 몸통은 없어도 된다.

### 스캔 종료

```
POST /detect/mission/stop

{ "command_id": "cmd-f444b6f0", "reason": "완료" }
```

`reason`은 `완료` 또는 `중단`. 리허설을 다시 돌릴 때 앞판을 닫는 용도다.
못 보내고 끊길 수도 있으니, **새 `start`가 오면 앞판은 자동으로 닫히는 편**이 안전하다.

---

## 2. 탐지 → 관제 웹 : 우리가 가져간다

**보내 주지 말고 받아 갈 수 있게 열어만 주면 된다.**
관제 웹은 브라우저 페이지라 남이 보내는 요청을 받을 수 없다. 우리가 주기적으로 물어본다.

### 각도별 결과

```
GET /detect/results?command_id=cmd-f444b6f0

{
  "command_id": "cmd-f444b6f0",
  "results": [
    { "index": 2, "angle_deg": 90, "door": true,
      "confidence": 0.93,
      "bbox": [212, 96, 148, 320],
      "reason": "문틀 수직선 2개와 손잡이 검출. 폭 0.9m로 추정",
      "ts": 1789020000.0 },
    ...
  ]
}
```

| 항목 | 값 |
|---|---|
| `index` | **0~7 정수.** 로봇의 `step`은 1부터이니 여기서 −1 해서 넣어 주면 된다 |
| `angle_deg` | 0·45·90…315 |
| `door` | `true` / `false` |
| `confidence` | **0~1 실수.** 0~100이면 알려 줄 것 |
| `bbox` | `[x, y, w, h]` **원본 프레임 픽셀 기준.** 정규화 좌표면 알려 줄 것 |
| `reason` | 한국어 한 문장. 화면의 「근거 가시화」 노드에 그대로 나간다 |
| `ts` | 탐지 시각 |

아직 안 본 각도는 **배열에서 빼면 된다.** `door: null` 같은 걸 넣지 않아도 된다.

### 현재 프레임

```
GET /detect/current?command_id=cmd-f444b6f0
→ image/jpeg (bbox 입힌 것)
```

### 각도별 프레임

```
GET /detect/frame?command_id=cmd-f444b6f0&index=2
→ image/jpeg (bbox 입힌 것)
```

### 헬스 체크

```
GET /health
→ 200
```

발표 직전에 눌러 볼 버튼용이다. 가벼울수록 좋다.

---

## 3. 놓치기 쉬운 것 둘

### CORS 헤더

**이게 없으면 붙는 날 아무것도 안 된다.**
관제 웹은 다른 주소에서 도는 브라우저 페이지라, 응답에 아래가 없으면 요청 자체가 막힌다.

```
Access-Control-Allow-Origin: *
```

`POST`에는 사전 요청(preflight)도 온다. `OPTIONS`에 같은 헤더로 `200`을 주면 된다.
시연 범위에서는 `*`로 충분하다.

### 프레임 크기

폴링으로 받는다. **한 장 300KB 이하**로 부탁한다. 640×480 JPEG이면 충분하다.

---

## 4. 폴링 간격 — 우리 쪽 약속

부담을 미리 알려 둔다.

| 언제 | 무엇을 | 간격 |
|---|---|---|
| 스캔 도는 중 | `/detect/current` | 500ms |
| 스캔 도는 중 | `/detect/results` | 1s |
| 스캔이 아닐 때 | **없음** | 멈춘다 |

스캔 한 판이 16초 남짓이니 그동안만 요청이 간다.

---

## 5. 하드웨어 쪽에 같이 부탁할 것

프레임이 로봇에서 탐지로 바로 가므로, **그 프레임에 둘이 실려야 한다.**

| 실을 것 | 왜 |
|---|---|
| `command_id` | 어느 임무의 프레임인지 |
| `step` (1~8) | 몇 번째 각도인지. **이게 빠지면 결과를 어느 노드에 붙일지 알 수 없다** |

`step`은 이미 `CommandStatus.detail`에 들어 있는 값이다. 프레임에도 같이 실어 주면 된다.

---

## 6. 확인이 필요한 것

- **탐지 서비스가 어느 주소에서 도는가.** 라즈베리파이인지 별도 PC인지, 포트는 몇 번인지
- 「연결을 내 PC의 MAC로」는 **DHCP 예약으로 내 PC IP를 고정한다**는 뜻으로 이해했다.
  맞다면 방향은 그대로 **관제 웹이 탐지로 요청을 보내는 쪽**이다. 다르게 뜻한 것이면 알려 줄 것
- 위 응답 형식으로 괜찮은지. 다르면 그쪽 형식에 맞추겠다 — **형식보다 확정이 급하다**
