# 드론 말단(Raspberry Pi 5) 설치 가이드

**날짜** 2026-09-22 · 김현우 (가시화)
**상대** 파이에 직접 설치하는 사람
**근거** `jny-drone/drone_rpi/` 조사 (README · deploy.sh · install_service.sh · agent.py · config.json)
**목표** 전원을 넣으면 파이가 스스로 카메라를 물고 `:8890` 창구를 여는 상태까지

> **결론부터 — 폴더 복사만으로는 안 된다.**
> 복사 대상은 `drone_rpi` 하나가 맞지만(`edge/` 는 GPU 쪽이라 파이에 올라갈 일이 없다),
> 파이 OS 쪽 준비 셋과 venv 구성이 따로 필요하다. 1절이 손으로 할 몫, 2절부터가 스크립트 몫이다.

---

## 0. 무엇을 올리나

| 올린다 | 안 올린다 |
|---|---|
| `drone_rpi/` 의 `*.py` 4개 · `config.json` · 스크립트 | **모델 가중치** — 말단에 신경망이 없다 |
| | `edge/` 전체 — GPU 기기 몫 |
| | `spool/` · `*.jsonl` · `records_snapshot.json` — 파이에서 생긴 결과 |

**말단이 하는 일은 셋뿐이다** — 캡처, 프레임 간 움직임 추정(KLT), 엣지가 준 장애물을
현재 좌표로 옮겨 내보내기. 검출·거리·의미 해석은 전부 엣지 몫이라 파이썬 의존성이
`numpy` 와 `opencv-python-headless` 둘뿐이다.

**Docker 는 쓰지 않는다.** `Dockerfile` 이 첫머리에 「재현·CI용이지 비행 정본이 아니다」라고
스스로 못박아 뒀다 — `rpicam-vid` 가 호스트 libcamera 스택에 묶여 있어 버전이 어긋나면
**카메라만 조용히 실패한다.** 비행 정본은 venv 다.

---

## 1. 파이 쪽 준비 — 한 번만, 손으로

스크립트가 안 해 주는 부분이다. 파이에 SSH 로 들어가서 한다.

### 1-1. OS 가 Raspberry Pi OS 인가

```bash
cat /etc/os-release          # Debian 12(bookworm) 또는 13(trixie)
```

`rpicam-vid` 는 라즈베리파이 전용 카메라 스택이다. **Ubuntu 를 올렸다면 여기서 멈춘다** —
카메라가 안 잡히고, 이 설계에서 카메라 없는 말단은 할 일이 없다.

### 1-2. 카메라가 보이는가

```bash
rpicam-hello --list-cameras
```

- 카메라 목록이 뜨면 통과다.
- `command not found` 면 `sudo apt install -y rpicam-apps`
- 목록이 비면 리본 케이블 방향과 `raspi-config` 의 카메라 설정을 본다.

기대 구성은 **Camera Module 3 Wide 1대**(`config.json` 의 `cameras` 가 index 0 하나).
2대로 늘리면 프레임당 310→500~590ms 로 늘었던 실측이 있어서 1대로 고정해 둔 것이다.

### 1-3. venv 를 만들 수 있는가

```bash
python3 -V                   # 3.11 이상
sudo apt install -y python3-venv
```

### 1-4. 테일넷에 붙어 있는가

```bash
tailscale status
```

창구를 `0.0.0.0:8890` 에 여는 설계다 — **노출 범위는 이 설정이 아니라 테일넷 ACL 이 정한다.**
`ufw` 를 켜 뒀다면 8890 을 열어 준다(기본 Raspberry Pi OS 는 꺼져 있다).

- [ ] Raspberry Pi OS 확인
- [ ] `rpicam-hello --list-cameras` 에 카메라가 뜬다
- [ ] `python3-venv` 설치됨
- [ ] 테일넷 붙음

## 2. 설치 — 두 갈래 중 하나

### 갈래 A — 개발 PC 에서 밀어 넣기 (권장)

PC 에 `rsync` 와 SSH 키가 있을 때. 코드 전송 + venv + pip 를 한 번에 한다.

```bash
cd jny-drone/drone_rpi
DRONE_HOST=<pi주소> DRONE_USER=<계정> ./deploy.sh
```

| 옵션 | 쓸 때 |
|---|---|
| `--no-venv` | 코드만 갱신(의존성 건드리지 않음) |
| `--password` | SSH 키 대신 비밀번호 (`sshpass` 필요) |
| `--dir <이름>` | 기본 `~/drone_rpi` 말고 다른 경로 |

**재실행해도 안전하다(멱등).** `spool/` · `*.jsonl` · `records_snapshot.json` 은 rsync 에서
빠져 있어 파이에서 생긴 결과를 PC 것으로 덮어쓰지 않는다.

> ⚠️ **지금 이대로 돌리면 마지막 줄에서 실패한다.** 3절을 먼저 읽는다.

### 갈래 B — 파이에서 직접 (USB 나 git clone)

PC 에 rsync 가 없거나 현장에서 바로 할 때.

```bash
# drone_rpi 폴더를 ~/drone_rpi 로 복사해 둔 뒤
cd ~/drone_rpi
python3 -m venv venv
./venv/bin/pip install --upgrade pip
./venv/bin/pip install -r requirements.txt
./venv/bin/python -c 'import numpy, cv2; print("deps OK")'
```

마지막 줄에 `deps OK` 가 뜨면 설치는 끝이다. 갈래 A 와 결과가 같다.

## 3. 지금 그대로면 걸리는 것 둘

둘 다 `jny-drone` 이 탐지 담당 저장소(`JNY03/physical_demo`)라 **손대지 않고 남겨 뒀다.**
아래는 고치지 않고 넘어가는 방법이다.

### 3-1. `deploy.sh` 가 마지막 검증에서 죽는다

`deploy.sh:79` 가 `import numpy,onnxruntime,cv2` 를 확인하는데 **`onnxruntime` 은
`requirements.txt` 에 없고 코드 어디서도 import 하지 않는다.** RPN 을 걷어낸 옛 설계의
잔재다. 원격 셸이 `set -e` 라 이 줄에서 스크립트가 멈춘다.

**실제 피해는 「배포 완료」가 안 찍히는 것뿐이다** — 파일 전송과 pip 설치는 이미 끝난 뒤다.
그래도 성공/실패 신호가 뒤집혀 있으니, 파이에서 직접 확인하고 넘어간다.

```bash
ssh <계정>@<pi주소> 'cd ~/drone_rpi && ./venv/bin/python -c "import numpy, cv2; print(\"deps OK\")"'
```

`deps OK` 가 뜨면 배포는 정상이다. 아니면 `--no-venv` 로 코드만 밀고 갈래 B 의 pip 줄을
파이에서 직접 돌린다.

### 3-2. systemd 유닛이 계정명 `physical` 로 하드코딩돼 있다

`drone-agent.service` 가 `User=physical` · `WorkingDirectory=/home/physical/drone_rpi` 다.
`deploy.sh` 는 `--user` 로 아무 계정이나 받는데 유닛만 고정이라, **파이 계정이 `physical` 이
아니면 서비스가 안 뜬다.**

- 계정이 `physical` 이면 → 그대로 4절로.
- 아니면 → 4절을 건너뛰고 **수동 실행**으로 간다. 기능은 같고 자동 기동만 없다.

```bash
cd ~/drone_rpi && ./venv/bin/python -u agent.py
```

## 4. 자동 시작 등록 (계정이 `physical` 일 때만)

드론에 붙은 파이에 매번 SSH 로 들어가 손으로 띄울 수는 없다.

```bash
ssh <계정>@<pi주소> 'cd ~/drone_rpi && ./install_service.sh'
```

| 명령 | 하는 일 |
|---|---|
| `./install_service.sh` | 등록 + 즉시 시작 + 부팅 시 자동 |
| `./install_service.sh --disable` | 자동 시작 해제(파일은 남긴다) |
| `journalctl -u drone-agent -f` | 로그 실시간 |
| `sudo systemctl stop drone-agent` | 정지 |

카메라가 빠지거나 `rpicam-vid` 가 죽으면 5초 뒤 자동 재시작한다. 2분에 10번을 넘기면
멈추고 실패로 남긴다 — **계속 재시작한다는 건 고쳐야 할 상태이지 숨길 상태가 아니다.**

## 5. 떴는지 확인

```bash
curl http://<pi주소>:8890/api/health
```

| 필드 | 읽는 법 |
|---|---|
| `cameras` | **여기가 비어 있으면 카메라를 못 물었다.** `[0]` 이 정상 |
| `temp_c` | 온도. `null` 이면 `vcgencmd` 가 없는 것이고 동작에는 지장 없다 |
| `served` / `not_modified` | 엣지가 가져간 횟수 / 새것 없어 거른 횟수 |
| `verdicts_in` | 엣지가 밀어 넣은 판정 건수 |
| `idle_s` | 엣지가 마지막으로 다녀간 뒤 흐른 초. 계속 커지면 엣지가 안 오는 것 |
| `spool` | 링크 단절 구간에 쌓인 것 |

기동 직후엔 `served` 도 `verdicts_in` 도 0 이다. **정상이다** — 말단은 서버이고 먼저
연결하지 않는다. 엣지가 와야 숫자가 움직인다.

## 6. 엣지 쪽에서 해야 할 한 줄

**말단 `config.json` 에는 고칠 것이 없다.** 엣지 주소가 아예 들어 있지 않다 — 말단은
서버이고 엣지가 당겨 가므로 알 필요가 없다. 엣지 기기를 옮겨도 파이는 그대로다.

대신 **엣지의** `edge/config.json` 에서 `terminals[0].host` 가 `"CHANGE-ME"` 로 되어 있다.
여기를 파이의 테일넷 이름이나 IP 로 바꾼다. **기기 주소가 적히는 자리는 여기 하나뿐이다.**

```json
"terminals": [
  { "name": "terminal-1", "host": "<pi 테일넷 주소>", "port": 8890, "cameras": [0] }
]
```

## 7. 막히면 먼저 볼 것

| 증상 | 먼저 볼 것 |
|---|---|
| `사용 가능한 카메라가 없다` 로 즉시 종료 | 기동 후 **6초** 안에 첫 프레임이 안 온 것이다. `rpicam-hello --list-cameras` 부터 다시. 다른 프로세스가 카메라를 잡고 있는 경우도 있다(`sudo systemctl stop drone-agent` 뒤 재시도) |
| pip 가 한참 돌다 실패 | `numpy==2.5.3` · `opencv-python-headless==5.0.0.93` 의 **aarch64 휠이 그 파이썬 버전에 없는 것**이다. 소스 빌드로 넘어간 상태. 파이썬 버전을 확인하고, 안 되면 핀 버전 조정을 논의한다 |
| `deps OK` 대신 `onnxruntime` 오류 | 3-1 절. 무시하고 넘어가도 되는 오류다 |
| 서비스가 안 뜬다 | 3-2 절. 계정명이 `physical` 인지부터 |
| health 는 뜨는데 `cameras` 가 빈 배열 | 카메라 스레드만 죽은 것이다. `journalctl -u drone-agent -n 50` |
| PC 에서 health 에 못 닿는다 | `tailscale ping <pi>` · 파이에서 `curl http://localhost:8890/api/health` 로 안팎을 가른다 |
| 엣지가 안 가져간다 (`idle_s` 만 커짐) | 파이 문제가 아니다. 6절의 `terminals[0].host` |

## 8. 알아 둘 것

- **엣지가 안 가져간 프레임이 대부분이고 그건 정상이다.** pull 구조의 backpressure 다.
  `not_modified` 가 크다고 고장이 아니다.
- **거리에 ego-motion 보정이 없다.** 말단에 MAVLink 텔레메트리가 없어서 `ego_compensated`
  는 `False` 로 남는다. 고도·자세가 들어오면 훨씬 정확해진다.
- **장거리를 막는 것은 모델이 아니라 렌즈다.** Wide(2.75mm)는 `focal_px ≈ 590` 이라
  100m 의 사람이 10px 이다. 표준(4.74mm)이면 1.9배.
- `config.json` 의 `focal_px` 는 **실측 캘리브레이션 값이 아니다**(dFoV 에서 역산한 값).
  체커보드로 재서 덮어써야 한다.
