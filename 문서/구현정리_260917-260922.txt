1. 영문화 — 화면 전체를 영어로
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
기간: 9/17 ~ 9/19 (2단계부터 5단계까지 모두 완료)
사용법: 주소 뒤에 ?lang=en. 기본은 한국어이고 한국어 화면은 한 글자도 바뀌지 않았다.

[무엇을 했나]
- 화면 문구 (2·4단계)
  시연 화면 22개 파일을 먼저 옮기고 나머지 화면도 전부 옮겼다.
  화면에 보이는 한글 1,176건 → 52건.
  남은 52건은 일부러 둔 것이다. 예를 들어 「왼쪽으로 90도」에서 방향을 읽어 내는
  키워드는 영어로 바꾸면 로봇이 반대로 돈다.
  번역 사전은 한국어 1,732개, 영어 1,731개.

- 대본과 장비 이름 (3단계)
  대본 파일에 영어를 나란히 적었다.
  음성 인식 언어는 화면 언어와 따로 고른다. 화면은 영어, 발표는 한국어인 경우가 있어서다.

- 남이 만드는 글자 (5단계)
  목 게이트웨이는 요청받은 언어로 답한다.
  고칠 수 없는 탐지 서비스의 메시지는 우리가 옮기고 원문은 로그에 남긴다.

- 사람이 화면을 보고 찾은 문제
  검사는 전부 통과였는데 언어 버튼을 눌러도 안 바뀌는 자리가 29곳,
  언어 구독(useLang)이 빠진 부품이 53개 있었다. 모두 고치고 검사를 새로 두었다.

[대가]
전달용 빌드가 202KB(19%) 커졌고 거의 전부 사전 두 벌이다.
논문에는 이 크기를 따로 한 줄로 빼서 적는 쪽이 권고안이다.

[아직]
영어로 임무를 생성하는 성능은 이 PC에 모델 가중치가 없어 재지 못했다.

2. 기능 상태 패널
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
기간: 9/20 ~ 9/21
위치: 마일스톤 화면 오른쪽, 하드웨어 카드 옆 (세로로 반씩 나눔)

[무엇을 보여 주나]
「지금 이 배치에서 무슨 기능을 쓸 수 있나」.
k3s 클러스터의 기능 상태 서비스가 계산한 판정을 받아 그린다.

[탭이 아니라 눌러서 들어간다]
  기능        기능 목록. 필수 조건 충족 여부와 선택 조건 수
    ↓ 기능을 누르면
  계층·자원   계층(role)별로 어떤 노드가 무엇을 제공하는지, 요구 자원과 한도(CU·MB)
    ↓ 노드를 누르면
  개발자      서버가 준 원본 값, 다른 후보가 왜 떨어졌는지

「마일스톤 › 노드 › 액션 아이템」과 같은 이동 방식이다.
원본 설계는 탭 셋이었는데, 그대로 옮기면 9/3에 없앤 탭이 이름만 바꿔 되살아나서 이렇게 바꿨다.
기능을 고르지 않고 배치 전체를 보는 「계층 전체 보기」도 따로 있다.

[가상 조건 (What-if)]
「이 노드에 이 태그가 있다면」「예산이 이만큼이면」「이 후보를 빼면」 같은 조건을 걸어
다시 계산해 본다. 계산만 하고 실제 배치는 안 바꾼다.
연달아 눌러도 0.18초 동안 모아 요청 한 번으로 보낸다.

[안전장치]
- 조회와 계산만 열었다. 실제 배치를 바꾸는 요청은 막았다.
- 「설정 기반 · 실측 아님」「가상 조건」 표시는 끌 수 없다.
  바로 옆 하드웨어 카드는 실측값이라 같은 무게로 읽히면 안 된다.
- 「테스트」를 켜면 9/20에 받아 둔 실제 응답을 그대로 보여 준다.
  테스트와 실제를 오갈 때는 양쪽 값을 다 버린다.
  실제 화면에 테스트 노드가 한 줄이라도 남으면 없는 장비를 있다고 말하게 된다.
- 전달용 빌드에도 넣었다. 크기는 한 바이트도 안 늘었다.

3. 드론 연결
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
기간: 9/21 ~ 9/22
범위: 연결과 상태 보기까지. 제어는 아직 없다.

[된 것]
- 연결 관리
  로봇 칸에서 「Go1이냐 드론이냐」 프리셋만 고르면 된다.
  주소를 넣고 「확인」을 누르면 바로 적용된다.
  전에는 맨 아래 「적용」을 따로 눌러야 해서, 화면엔 pi3가 적혀 있는데 실제로는
  pi7에 붙는 문제가 있었다.

- 상태 표시
  연결 관리: 브로커 · 장비 · FC 연결 각각 초록/빨강
  드론 카드: 배터리, 시동(arm), 비행 모드, GPS, 자세, 경고
  카드를 더블클릭하면 상세가 열린다.

- 카드 정리
  전에는 아무것도 안 붙여도 가짜 카드가 여러 장 떴다(옛 대본 장비, 목 게이트웨이의 가짜 장비).
  이제는 실제로 붙은 장비만 뜬다. 드론만 붙이면 한 장.

- 장비 식별
  코드에 박혀 있던 go1-001을 걷어 냈다. 장비가 스스로 이름과 종류를 알려 준다.
  처음 보는 종류도 그대로 받는다.

- 여러 대 동시 연결
  브로커 여러 곳에 동시에 붙는다.
  명령은 그 장비가 붙어 있는 연결로만 나간다. Go1과 드론을 같이 붙여도 엉뚱한 곳으로 안 간다.

[범위]
화면 쪽에서 바뀐 파일 19개. 기록 · 되감기 · 임무 그래프 · 캔버스는 0개.
장비가 바뀌어도 위 두 층은 그대로라는 설계가 코드로 확인됐다.

[아직]
드론이 받겠다고 선언한 명령은 ping 하나뿐이다. 이륙 · 착륙 · 정지 명령과 실제 비행은 아직이다.
다음 단계는 드론이 받을 명령 목록을 받은 뒤 임무를 여러 대로 돌리는 것이다.

4. 로봇 명령 되감기
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
기간: 9/20 ~ 9/21

[전에는]
되감기가 마일스톤과 태스크 두 층에만 닿았다.
로봇에 보낸 명령은 따로 저장돼서, 재생 위치를 10초로 옮겨도 40초의 명령이 떠 있었다.
세션을 닫으면 명령 기록도 사라졌다.

[이제는]
명령을 보낼 때, 로봇이 한 줄 답할 때, 사람이 값을 바꿀 때마다 같은 기록에 적는다.
재생 위치를 옮기면 명령 표도 그 시점까지만 보인다. 세 층이 모두 되감긴다.

[핵심 — 「아직」과 「끝내」를 가른다]
오지 않은 답은 기록할 수가 없다. 그래서 「기다리다 끝났다」는 사실을 대신 적는다.
  답 없음 + 기한 사건 없음 → 아직 기다리는 중
  답 없음 + 기한 사건 있음 → 끝내 안 왔다
느린 것과 죽은 것은 원인이 다르다.

[누가 만든 값인가]
AI · 백엔드 · 사람 · 로봇 넷으로 적는다.
사람이 바꾼 값은 바꾸기 전과 후를 짝으로 남긴다.

[로봇 없이도]
목 게이트웨이가 같은 기록을 흘린다. 실험할 때마다 로봇을 켤 필요가 없다.

[실물 측정 — 완주 13판]
  한 판 기록      최소 68 · 중앙 75 · 최대 78건
  한 판 시간      중앙 78초
  기록 크기       중앙 약 5.4KB (한 판 전체 기록의 약 5%)
  끝내 안 온 답   0건
재생 위치를 10초 → 60초로 옮기면 촬영 명령의 응답이 6줄 → 29줄로 그 시점까지만 찬다.
단, 프로그램으로 확인한 것이고 화면을 띄워 눈으로 본 것은 아직이다.

[논문에 준 영향]
한 판이 75건이면 한 화면에 다 들어온다.
그래서 「볼 양을 줄였다(실패 경로 격리)」는 주장은 빼고
「사후 디버깅이 되는 기록 구조」로 중심을 옮겼다. 격리는 향후 연구.

[아직 기록되지 않는 것]
- 임무 순서도에 자리가 없는 명령
- 사람이 누른 정지
- 같은 명령이 옛 방식과 새 방식으로 두 번 적히는 문제
