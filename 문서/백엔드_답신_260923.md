### 2. 🔴 드론 `state` 본문 항목 목록 — **이미 있다. `문서/CONTRACT_x500.md` §13 이다**

§16-4 가 *"이것 하나가 실제로 남은 것이다"* 라고 한 항목인데,
**그 목적으로 쓴 절이 이미 있다.** 제목이 그대로 *「백엔드 규격용 —
`state.drone.schema.json` 을 만들 때 보는 표」* 다.

| 절 | 무엇 |
|---|---|
| §13-0 | 🔴 **읽기 전 규칙 둘** — 아래에 따로 뽑았다 |
| §13-1 | 공통 헤더 8칸 (타입·형식·필수·없을 때·값의 출처) |
| §13-2 | `state` 본문 **최상위 14칸** (타입·단위·필수·값이 없을 때·**FC 링크 없을 때**) |
| §13-3 | 중첩 객체 — `battery`·`flight`·`gps`·`attitude`·`altitude`·`warnings` |
| §13-4 | **`reason` 어휘 6개** — Go1 의 3개(`periodic`·`mode_changed`·`battery_low`)를 **포함**하고 드론 고유 3개(`fc_link_lost`·`fc_link_up`·`armed_changed`)가 더 있다 |
| §13-5 | **실제로 발행된 `state` 1건 원문** (2026-09-21 21:06 캡처, FC 분리 상태) |

값은 전부 **코드와 실제 브로커 캡처에서 확인한 것**이고 추정값이 없다.
확인 못 한 것은 그 문서 §9 에 따로 모아 뒀다.

#### 🔴 규격을 쓸 때 반드시 반영돼야 하는 것 둘

1. **키는 항상 있다. 없는 것은 값이지 키가 아니다.**
   FC 링크가 없어도 `battery` 키는 사라지지 않고 **`null` 로 온다.**
   → **전부 `required` 에 넣고**, 타입 쪽에서 `["object","null"]` 처럼 `null` 을 허용하면 된다.
   ⚠ **규약(protobuf) 평면은 반대다** — `ping` 응답의 `result` 는 없는 값의 **키가 통째로 빠진다**
   (`map<string,double>` 라 `null` 을 실을 수 없다). **두 평면의 결측 표현이 다르다.**

2. **`null` 을 0 으로 치환하지 말 것.** `null` 은 "모른다", `0` 은 "쟀더니 0" 이다.
   `battery: null` 을 0% 로 해석하면 **잘못된 경보**가 된다.

#### 캡처 1건 (§13-5 원문)

```json
{
  "schema_version": "1.1", "source_id": "x500-001", "node_id": "pi3", "zone_id": "zoneA",
  "timestamp": "2026-09-21T21:06:50.795+09:00", "session_id": "a93f81192e02", "sequence_id": 173,
  "channel": "state", "reason": "periodic",
  "device_status": "degraded", "link": "degraded",
  "fc_link": false, "fc_link_age_s": null, "router_mode": "none",
  "battery": null, "flight": null, "gps": null, "attitude": null, "altitude": null,
  "warnings": []
}
```

⚠ **이 캡처는 FC 가 분리된 상태다.** 그래서 다섯이 `null` 이고 **그게 정상 동작**이다 —
규격에서 이 다섯은 **`null` 을 반드시 허용해야 한다.** 값이 채워진 모습은 아직 MQTT 로
관측하지 못했다.

> ⚠ **전달 방식 주의:** `CONTRACT_x500.md` 에는 **연구실 IP·tailnet 주소가 들어 있다.**
> 그쪽 저장소가 Public 이라고 적어 둔 것을 봤으니, 그대로 커밋하지 말고 §13 만 옮기거나
> 주소를 자리표시자로 바꿔서 넣는 것이 낫겠다.

#### 이 문서로 확인되는 것 둘 (그쪽 안건과 맞닿는다)

- **`session_id` 가 드론에는 이미 있다.** HW 회신 §6-2 에서 `schema.py` 에 신설을 요청 중인
  그 필드인데, pi3 드론 노드는 **이미 발행하고 있다**(12자리 hex, 프로세스 1회 기동 식별자).
- **`sequence_id` 는 `session_id` 가 바뀌면 0 부터**다. `/state` 어댑터의 `seq` 칸이
  **순번 역전**을 보게 된다는 뜻이다 — 우리 쪽은 **순번이 줄면 새 세션으로 보고 버퍼를 비우는**
  처리를 영상 쪽에 이미 넣어 뒀고, 상태 쪽도 같은 규칙으로 읽을 생각이다.
- **`correlation_id` 는 `state` 에 안 실린다.** `status` 에는 **`sequence_id` 가 없다.**

### 3. 관문 B·C-a — 우리 쪽 준비 상태

**코드 작업은 없다.** 다음 자리를 확인했다.

| 무엇 | 자리 | 상태 |
|---|---|---|
| 구역 칸 | `viz-debugger/src/shared/connections.ts` 의 `gateway.zone` | ✅ 있다. 기본값 `zone-503`, **붙을 때 `zoneA` 로 바꾼다** |
| 미디어 연결 칸(주소·카메라 키·토큰 3칸) | `src/shared/connections.ts` 의 `media` · `src/media/presets.ts` | ✅ 있다. 주소는 **비워 두었다**(「아직 없다」는 뜻으로 화면이 막는다) |
| 바이너리 수신·파서·디코드 | `src/media/MediaClient.ts`·`parse.ts`·`decode.ts` | ✅ 넷 다 |
| 탐지 `bbox_space`·`tier:'server'` | `src/tabs/data/vision.ts` | ✅ |
| 드론/로봇 상태 줄 표 | `src/shared/stateRows.ts` | ✅ **MQTT 직결과 `/state` 두 길이 같은 표를 지난다** |

**잠정값 셋과 `StateLayers` 합의도 그대로 유효하다.** 이번 실측에서 로봇 상태가
**「알 수 없음」으로 보이는 것을 합격 모습으로** 보고, 실패로 읽지 않는다.
*"원문은 흐르는데 판정이 없는 화면"* 이 이번에 봐야 할 그림이라는 정리에 동의한다.

**코덱 문자열 `avc1.424028`** 도 받았다. 우리는 `decoder.configure({codec})` 에 **헤더 값을
그대로** 넣고 상수를 안 박았으니 그쪽 실측값이 무엇이든 그대로 설정된다.

**IDR 0.49초**도 받았다. **그 공백을 「끊김·오류」가 아니라 「재개 대기」로 적겠다** —
권고가 맞다고 보고, 지금 화면에 임계 표시가 없어서 그 자리를 하나 넣을 생각이다.

### 4. 관측(4318) — 붙일 준비는 됐고, **아직 코드가 없다**

받으면 그때 발행부를 붙이겠다. **언제쯤 열리는지만 알려 달라**(아래 ②).

### 5. `alignment` 기한부 수용 — 받아들인다

*"실물 탐지가 우리 경로로 오기 시작하면 「부재 = unaligned」로 되돌린다.
그때 부재는 옛 계약이 아니라 생산자 결함이다"* — **그대로 받는다.**

**우리 쪽 문서에도 그 조건과 트리거를 적어 뒀다**(`가시화_실측대비_내작업_260923.md` §4-3).
그쪽 추적표에도 남긴다고 했으니 양쪽에 있다. 트리거는 **탐지 채널·토픽 배선(Phase 6)**,
또는 **AI 가 그쪽 경로로 탐지를 보내기 시작하는 시점**으로 읽었다. 그때 되돌리겠다.

`format` 기본값이 **AI 회신 뒤 최종 확정**인 것도 알았다. 우리 파서는 `normalized`·`absolute`
**둘 다 지원**하므로 어느 쪽으로 정해져도 우리 작업이 없다. **기다리겠다.**

### 6. 드론 브릿지 — 그쪽 §15-7 ③ 에 덧붙인다

*"브릿지를 둘 띄우면 된다. 드론 브로커는 pi3 사설 LAN 이라 서버에서 못 닿는다"* 가 맞다.
우리가 붙어 보면서 확인한 것 둘을 덧붙인다.

- **드론 브로커는 WebSocket 9001 도 연다**(브라우저용). 우리는 그 길로 직접 붙어 있고,
  `zoneA/+/+/{status,state,heartbeat}` 를 구독한다 — **두 번째 칸을 `+` 로 받는다.**
- ⚠ **clientId 는 브로커에서 유일해야 한다.** 웹이 `x500-001` 로 붙으면 노드를 밀어낸다
  (노드가 20초 내 3회 재접속을 감지하면 치명 경보를 찍는다). 우리는 `web-<임의값>` 을 쓴다.
  **브릿지를 둘 띄울 때 clientId 도 갈라 달라** — `MK2_QUARANTINE_PATH` 를 가르라고 적어
  둔 것과 같은 이유다.

### 7. 우리가 묻는 것 — 넷

| # | 묻는 것 | 왜 |
|---|---|---|
| ① | 🔴 **붙어 볼 시각.** 우리는 《여기에 제안 시각을 적는다》 이 가능하다 | 발행자를 켜 둔 동안에만 흐른다고 했으니 시각을 맞춰야 한다. 그 시간에 **합성 송신기와 가짜 발행자 둘 다** 켜 달라 |

| ③ | 🔴 **`status` 채널을 Phase 5 에 구독자에게 열 계획인가** | 지금 어댑터가 `state`·`heartbeat` 만 보낸다. **드론 `status` 는 retained 이고 급사(LWT)가 그 채널에 온다**(`reason:"lwt"`) — 생사 판정의 근거다. 지금은 우리가 pi3 에 **직결**해 받고 있어서 안 막히지만, 경로를 `/state` 로 모으면 **급사 판정이 빈다.** 계획만 알면 된다 |
| ④ | **`state.drone.schema.json` 에서 `session_id`·`sequence_id` 를 어떻게 둘 건가** | 드론은 둘 다 보내는데 `status` 에는 `sequence_id` 가 없다. Go1 쪽은 `session_id` 신설이 아직 HW 작업 중인 것으로 읽었다 — **채널마다 필수 여부가 갈리는지** 확정해 주면 우리도 같은 기준으로 읽겠다 |
