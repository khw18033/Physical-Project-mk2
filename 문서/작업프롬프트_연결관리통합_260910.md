# 작업 지시: 연결은 「연결 관리」 한 곳으로

**날짜**: 2026-09-10
**선행**: `작업프롬프트_화면연결_260910.md` 작업이 끝난 뒤에 착수
**범위**: 연결 설정과 연결 상태를 「연결 관리」 탭으로 모은다

> **`작업프롬프트_화면연결_260910.md` 1절의 「주소 프리셋 UI」와 「연결 확인 버튼」 자리를
> 이 지시서가 대체한다.** 시연 화면에 둔 것을 걷어 내고 연결 관리로 옮긴다.

---

## 0. 왜 옮기는가

앞 지시서는 발표 중에 탭을 옮기고 싶지 않다는 이유로 프리셋을 시연 화면에 두게 했다.
**그 전제가 틀렸다.**

- 연결 관리는 **팝업**이다. 탭을 떠나는 게 아니라 위에 뜬다
- 시연 세팅은 **무대에 오르기 전에 끝낸다.** 발표 중에 주소를 바꿀 일이 없다
- 연결에 관한 것이 두 군데 있으면 「어느 쪽이 진짜냐」가 생긴다

하드웨어(MQTT)든 탐지(HTTP)든 STT든, **연결이라는 관심사는 한 화면에 모이는 것이 맞다.**

---

## 1. 착수 전에 확인할 것

| 확인 | 무엇을 |
|---|---|
| 연결 관리 팝업 | 지금 어떤 대상이 올라와 있고 각각 무엇을 보여 주는가 |
| 앞 작업이 시연 화면에 만든 것 | 프리셋 UI · 연결 확인 버튼 — **걷어 낼 대상** |
| `CONNECTION_TARGETS` | 대상 등록 구조. `detect` 도 여기 올릴 수 있는가 |
| 각 대상의 확인 방법 | `physical` 은 `ping`, `detect` 는 `GET /health`. `stt`·`generate` 는 지금 무엇을 쓰는가 |

---

## 2. 연결 관리가 갖춰야 할 것

대상마다 **네 줄**이면 된다.

| 줄 | 내용 |
|---|---|
| 주소 | 입력 칸. 프리셋이 있으면 고르는 자리도 |
| 상태 | 아래 3절 |
| 확인 | 눌러서 실제로 왕복시키는 버튼 |
| 마지막 확인 | 시각 · 왕복 시간 · 실패했으면 사유 |

대상 넷을 한 화면에 세로로 늘어놓는다.

| 대상 | 주소 | 확인 방법 |
|---|---|---|
| `physical` (로봇) | `ws://...:9001` · 프리셋 넷 | `ping` 왕복 |
| `detect` (탐지) | `http://...` | `GET /health` |
| `stt` | 기존 | 기존 |
| `generate` | 기존 | 기존 |

`detect` 는 2단계-B에서 붙는다. **자리는 지금 만들어 두고 확인은 그때 잇는다.**

### `physical` 프리셋 넷

| 프리셋 | 값 |
|---|---|
| 이름 | `ws://pi7.local:9001` |
| 랩 Wi-Fi | `ws://192.168.50.172:9001` |
| 발표장 핫스팟 | **비어 있다.** 정적 IP를 받으면 채운다 |
| 직접 입력 | 사용자가 적는다 |

---

## 3. 「붙었다」와 「답한다」는 다르다

**이 절이 이번 작업의 요점이다.**

MQTT 브로커에 붙는 것과 로봇이 명령에 답하는 것은 별개다.
브로커는 살아 있는데 로봇이 꺼져 있으면 **연결은 성공이고 왕복은 실패다.**
둘을 한 표시등으로 뭉치면 발표 직전에 무엇이 문제인지 못 가른다.

`physical` 은 상태를 둘로 나눠 보여라.

| | 무엇 | 실패했을 때 |
|---|---|---|
| 브로커 | WebSocket 연결이 서 있는가 | 주소·포트·망 문제 |
| 로봇 | `ping` 왕복이 도는가 | 로봇 전원·상태 문제 |

`detect` 도 마찬가지다 — 주소에 닿는 것과 `200` 이 오는 것은 다르다.

---

## 4. 시연 화면에는 표시등만 남긴다

연결을 **바꾸는** 자리는 연결 관리 하나다. 다만 연결이 끊긴 것을
**시연 중에 알아야 한다.** 팝업을 열어야만 알 수 있으면 늦는다.

- 시연 화면 한구석에 작은 표시등 하나. **읽기 전용**
- 무엇이 끊겼는지가 보여야 한다 — 「로봇 연결 끊김」처럼
- 누르면 **연결 관리 팝업이 열린다.** 거기서 고친다
- 앞 작업이 만든 프리셋 UI와 확인 버튼은 **걷어 낸다**

### 긴급 정지는 그대로 둔다

정지 버튼은 연결 기능이 아니라 안전 기능이다. **시연 화면에 그대로 있어야 한다.**
연결 관리로 옮기지 마라.

---

## 5. 발표 직전 점검 흐름

이 작업이 끝나면 무대 오르기 전 순서가 이렇게 된다. **보고서에 이 순서를 적어라.**

1. 연결 관리를 연다
2. `physical` — 브로커 초록, 로봇 초록. 왕복 시간 확인
3. `detect` — 초록
4. `stt` · `generate` — 초록
5. 닫는다. **시연 중에는 다시 열지 않는다**

넷 중 하나라도 빨간 채로 무대에 오르지 않는다.

---

## 6. 검증

| 검사 | 무엇을 |
|---|---|
| **`verify:one-broker-address`** | 브로커 주소를 **갖는 상태가 하나뿐인가.** 시연 화면이 따로 들고 있지 않은가 |
| **`verify:connection-panel`** (신설) | 대상 넷이 다 올라와 있는가 · `physical` 이 브로커와 로봇을 **따로** 보이는가 · 확인 버튼이 실제 왕복을 돌리는가 |
| `verify:no-physical` · `verify:no-detect` | 대상이 없어도 그 줄만 빨갛고 나머지는 도는가 |
| `verify:physical-port` | 주소·토픽을 아는 면이 `src/physical/` 하나인가 |
| 앞 단계 검사 전부 | 그대로 통과 |
| `verify:standalone` | 증가분 |

---

## 7. 하지 않을 것

- 시연 화면에 주소 입력이나 프리셋을 남기는 것 — **표시등만**
- 긴급 정지를 연결 관리로 옮기는 것
- 대비값을 `connections.ts` 로 되돌리는 것 — `verify:physical-port` 가 잡는다
- `detect` 의 실제 확인 로직 — 2단계-B에서 잇는다. 지금은 자리만
- 연결 관리 팝업의 기존 대상(`stt`·`generate`) 동작 변경
