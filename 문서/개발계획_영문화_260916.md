## 1단계 · 전환 골격 (1일)

**번역을 한 줄도 쓰지 않는다.** 갈아끼울 통로만 만든다.

```
src/shared/language.ts       언어 저장소 — connections.ts 와 같은 꼴
src/i18n/dict.ts             t() · Lang · 시범 키 다섯
src/i18n/ko.ts               시범 키 다섯
src/i18n/en.ts               시범 키 다섯
src/shell/LangSwitch.tsx     세그먼트 — ModeSwitch.tsx 를 본뜬다
```

- 결정 순서: `?lang=` > `localStorage` > `navigator.language` > `'ko'`
- 누락 키는 **한국어로 떨어지고 콘솔에 한 줄.** 빈 문자열도 키 원문도 안 그린다
- 전환 시 `<html lang>` 같이 변경
- 라우터를 넣지 않는다 — 의존성 넷(`react`·`mqtt`·`protobufjs`·`ws`) 유지

**산출물** — 토글이 도는 화면. 시범 키 다섯 개만 영어로 바뀐다
**여기서 멈추고 교수님께 보인다.** 용어와 범위를 번역 1,000줄 쓰기 전에 고칠 마지막 지점

착수 지시서: `문서/작업프롬프트_영문화1단계_260916.md`

## 2단계 · 시연 경로 문구 (2일)

전체 1,249줄 중 **30% 남짓.** 목표는 「영어로 시연이 한 바퀴 돈다」 하나다.

대상: `global-bar` · `ModeSwitch` · 발화 패널 · 승인 화면 · 노드 캔버스

키 규칙 `영역.항목` — `stt.offline` · `pending.plane.business` · `mode.scenario`.
**한국어 원문을 키로 쓰지 않는다.** 원문을 한 글자 다듬으면 영어가 통째로 떨어진다.

### 이 단계의 함정 — `${}` 164곳

문장을 조각으로 쪼개 이어붙이면 영어 어순에서 무너진다.

```ts
t('elapsed.prefix') + sec + t('elapsed.suffix')   // 나쁘다 — 영어로 옮길 방법이 없다
t('elapsed', { sec })                              // 좋다
```

### ⚠ 검사는 언어를 환경에서 받지 않는다 (260917 규약)

2단계에서 문구를 옮길 때마다 **그 문구를 대조하던 검사가 사전을 타게 된다.** 규약 하나를 먼저 박는다.

- **검사 환경의 기본 언어는 언제나 `'ko'`** 다. `language.ts` 의 `fromNavigator()` 가 브라우저에서만
  돌기 때문이다(`window`·`document` 로 판정). Node 21+ 에도 `navigator` 가 있어서 이걸 안 막으면
  **검사 결과가 기계 로캘을 따라간다** — 한국어 윈도우에서 통과하고 CI 에서 깨진다
- **영어 경로를 재려면 검사가 `setLang('en')` 을 명시적으로 부른다.** 환경이 정하게 두지 않는다
- `verify:lang-switch` 6번과 대조군 넷째가 이 규약을 지킨다

260916 에 이걸로 `verify:connection-panel` 이 조용히 깨졌다 —
경위는 `reports/2026-09-17_언어검사_로캘독립.md`.

### 타입 리터럴 1건

`src/shared/pendingSources.ts:46` 의 `part: '하드웨어' | 'AI' | '백엔드'` 를
`'hardware' | 'ai' | 'backend'` 로 바꾸고 표시할 때 사전을 탄다.
**이 저장소에서 한국어가 로직에 관여하는 유일한 자리다** (객체 키 0건 · 비교문 0건).

**산출물** — `?lang=en` 으로 시연 전 구간 통과

### STT — 언어 인자 한 줄

| 무엇 | 고칠 것 |
|---|---|
| `src/stt/SttClient.ts` | `transcribe()` 가 `language` 를 FormData 에 싣는다 |
| `stt/service.py` | **수정 없음** — `language: str = Form(default="ko")` 로 이미 받고 있다 |
| `stt/engines/*.py` | **한 글자도 안 건드린다** (`verify:stt-port` 바이트 동일성) |
| `stt/vocab.py` | 언어 인자를 받아 해당 언어 어휘만 준다. 두 언어를 한꺼번에 밀어넣지 않는다 |
| 발화 패널 | 인식 언어 선택 셋 — `화면 언어 따름` · `한국어` · `English` |

**자동 감지를 기본값으로 쓰지 않는다.** 임무 명령은 한 문장이라 짧고, 짧으면 감지가 틀린다.
틀리면 통째로 엉뚱한 언어로 전사된다. 다만 응답에 `detected_language` 와 `language_probability` 가
이미 실려 오므로(`engines/faster_whisper.py:203`) **「지정한 언어와 다르게 들린다」 경고에만 쓴다.**

**번역 경유는 만들지 않는다.** 신뢰도 임계(REQ-1306)에 안 잡히는 실패가 생기고, registry hotword 그라운딩이 깨진다.

**산출물** — 영어 음성이 장비명을 잡는다

## 5단계 · 생성과 검증 (3일)

### L3 — 영어 프롬프트 판

- `gen-lab/server/prompt.py` 에 `RULES_EN` 을 **나란히** 둔다. `rules_for(..., lang=)` 이 고른다
- **한국어 경로의 문자열을 한 글자도 안 바꾼다** — `goldset` 과 `score:generation` 베이스라인이 그대로 유효해야 한다
- 임무 객체에 `lang` 필드. 생성 시점에 고정되고 그 뒤 안 바뀐다
- 기록 열은 덧붙이기 전용이라(REQ-1404) 소급 번역이 금지된다. 한국어로 생성된 옛 임무는
  영문 화면에서도 한국어 제목 + 「이 임무는 한국어로 생성됐습니다」 한 줄

### 검증 신설 3종 → **실제로는 이렇게 섰다** (260919 대조)

계획은 셋이었고 끝나 보니 **검사가 75종**이다. 이름이 계획과 다른 것이 하나 있어 적어 둔다.

| 계획 | 실제 | |
|---|---|---|
| `verify:i18n-complete` | **`verify:i18n-demo-path` 의 3번이 한다** (`scripts/verify-i18n-demo-path.mjs:248~`) | 이름만 없고 일은 있다 — 아래 ★ |
| `verify:no-raw-korean` | 그대로 섰다 | 4단계에서 저장소 전체로 넓혔다 |
| `verify:lang-switch` | 그대로 섰다 | 1단계에 서고 5단계에 한 번 더 조였다 |

**★ 계획보다 세게 섰다.** 계획은 「없어도 실패가 아니라 목록을 찍는다」였는데, 실제 검사는
**`mode.mock` 하나 말고 결손이 있으면 실패**한다(`EXPECTED_GAP`). 부분 번역을 전제로 무르게
잡아 뒀던 것인데 4단계에서 전부 옮겨져 무를 이유가 없어졌다. `mode.mock` 은 fallback 이 실제로
도는 증거라 **일부러 비운 자리**이고, 채워져도 실패다. 검사 대상은 시연 경로가 아니라 **사전 전체**다.

계획에 없던 검사도 많이 늘었다 — 5단계만 여덟(`gateway-wire` · `log-i18n` · `service-words` ·
`i18n-no-frozen` 등). 목록은 `reports/2026-09-19_영문화5단계.md` §8 에 있다.

### 기존 7종 수정

`verify-autodrive-ai` · `verify-emergency-stop` · `verify-mission-record` · `verify-scenario-mode` ·
`verify-script-autodrive` · `verify-viewpoint-layout`.

한글 문구 대조를 **사전 키 대조**로 바꾼다. 문구가 아니라 키를 보게 하면 번역이 바뀌어도 검사가 안 깨진다.

`verify-stt-port` 는 **예외** — 걸린 한글(`이식:`)이 UI 문구가 아니라 이식본 주석 표식이라 그대로 둔다.

**산출물** — 영어 생성이 돈다. 회귀가 잡힌다
