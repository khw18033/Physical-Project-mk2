# 장치 연동 부록 A — RoboMaster EP (초안)

> 대상: RoboMaster EP 노드를 만드는 개발자·AI
> 작성 2026-09-24 · 가시화(김현우) · 상태 **초안 — 검토 전**
> **먼저 [공통 규약](장치연동_공통규약_260924.md)을 읽는다.** 이 부록은 공통 규약에 EP만의 것을 더한다.

## 0. 한 줄 요약

EP를 **Go1과 같은 `robot`** 으로 보이게 만든다. 파이 하나에 브로커와 노드를 올리고, 노드가 MQTT 명령을 RoboMaster SDK 호출로 바꾼다.
회전·직진은 Go1과 **이름, 단위, 부호까지 똑같이** 받는다. 그래야 웹의 "90도 오른쪽으로 돌고 1m 앞으로" 같은 발화 명령이 EP에도 그대로 통한다.

---

## 1. 구성

```
관제 웹 ──ws:9001──▶ mosquitto (EP용 파이) ◀──1883── ep-node (같은 파이) ──Wi-Fi, RoboMaster SDK──▶ EP
```

| 항목 | 값 | 비고 |
|---|---|---|
| 노드가 도는 기계 | 파이 1대 (Go1의 pi7, 드론의 pi3와 같은 역할) | 어느 파이인지 미정. `node_id`에 그 이름을 쓴다 |
| 브로커 | 그 파이의 mosquitto. 1883 + 9001(WebSocket) | 공통 규약 §2. pi7·pi3의 설정을 그대로 복사하면 된다 |
| EP 연결 | RoboMaster 파이썬 SDK, Wi-Fi(공유기 모드 권장) | 직결(AP) 모드면 파이가 EP의 AP에 붙어야 해서 연구실 망과 동시에 쓰기 어렵다 |
| 웹 쪽 설정 | 연결 관리의 브로커 주소 칸에 `ws://<파이>:9001/mqtt` 한 줄 추가 | 웹 코드는 고치지 않는다 |

**먼저 확인할 것 — SDK가 파이에서 도는가.** RoboMaster SDK가 지원하는 파이썬 판과 CPU(ARM) 조건을 확인한다. 파이에서 안 돌면 SDK를 도는 PC를 노드로 쓰고 브로커만 파이에 둔다. 어느 쪽이든 규약은 같다.

## 3. 명령 어휘

Capability: `["ping", "diag", "turn", "move_forward", "abort"]`

| action | 움직이나 | 파라미터 | 결과 키 | 거부 코드 | 시간 상한 |
|---|---|---|---|---|---|
| `ping` | 아니오 | 없음 | `uptime_s`: 초, `ep_link`: 1/0 | — | 1초 |
| `diag` | 아니오 | 없음 | 노드가 아는 숫자들(`battery_pct`, `ep_link`, `uptime_s` 등). 자유 | — | 2초 |
| `turn` | **예** | `deg`: 도. **+ = 오른쪽(위에서 보아 시계방향)**, − = 왼쪽. 절댓값 5~360 | `deg`: 명령값, `duration_s`: 초, `yaw_deg`: 끝난 뒤 방위(알면) | `INVALID_ARGUMENT`, `mission_in_progress`, `battery_too_low`, `ep_link_down` | 45초 |
| `move_forward` | **예** | `distance_m`: m, 0.05~10 · `vx`: m/s, 0.05~0.30, 없으면 0.15 | `distance_m`: 명령값, `odo_m`: 실제 이동(알면), `duration_s`: 초 | 위와 같음 | `distance_m / vx + 10`초 |
| `abort` | 예 (정지) | `reason`: 1/2/3 (기록용) | 없어도 된다 | **거부하지 않는다** | 즉시 |

### 3-1. 부호와 단위 — 가장 틀리기 쉬운 곳

- **`turn`의 +는 시계방향(오른쪽)이다.** Go1이 그렇고 웹도 그렇게 보낸다.
  - SDK가 쓰는 회전 부호가 이와 반대일 수 있다. **책상 위에서 `turn{deg: 90}`을 보내 EP가 오른쪽으로 도는지 눈으로 확인하고**, 필요하면 노드에서 부호를 뒤집는다. 확인 결과를 §7에 적는다.
- `move_forward`는 **앞으로만** 간다. `distance_m`이 음수면 `INVALID_ARGUMENT`다.
  - 웹은 후진과 옆걸음을 일부러 막아 두었다. EP는 메카넘 휠이라 할 수 있지만 **이번에는 선언하지 않는다.** 필요해지면 새 action 이름(예: `move_lateral`)으로 따로 제안한다.
- **범위 밖 값을 조용히 고치지 않는다.** 예를 들어 SDK가 0.15 m/s보다 느리게 못 간다면, 그 사실을 §7에 적고 그보다 느린 `vx`는 `INVALID_ARGUMENT`로 거부한다. 웹이 범위를 맞춘다.
  - 웹이 지금 보내는 `vx`는 0.05~0.30 m/s다. SDK의 실제 속도 범위를 확인해서 §7에 적어 달라.

### 3-2. 실행 규칙

- **한 번에 하나만 움직인다.** `turn`이나 `move_forward`가 도는 중에 다른 이동 명령이 오면 `mission_in_progress`로 거부한다. `ping`, `diag`, `abort`는 언제든 받는다.
- 시작할 때 `status{state: "EXECUTING", detail: "executing"}`를 한 번 보낸다. 진행 중 보고는 더 없어도 된다.
- `turn` 결과의 `yaw_deg`는 EP가 켜진 뒤 기준의 방위다. 모르면 키를 뺀다.
- `move_forward`의 멈춤 기준은 SDK의 이동 완료 신호 또는 오도메트리다. 무엇을 기준으로 삼았는지 §7에 적는다.
- `battery_too_low`의 문턱은 노드가 정하고 §7에 적는다.
- EP와의 연결(`ep_link`)이 끊겨 있으면 이동 명령은 `ep_link_down`으로 거부한다. `abort`는 그래도 받는다(공통 규약 §7-2).

### 3-3. 정지 — `abort`

공통 규약 §7을 그대로 따른다. EP에서 구체적으로는:
1. 받는 즉시 섀시 속도를 0으로 만든다. 진행 중인 SDK 동작이 있으면 취소한다.
2. 돌던 명령에 `result{ABORTED, failure{code: "aborted", message}}`를 원래 `command_id`로 보낸다.
3. `abort` 자신은 `result{SUCCEEDED}`로 끝낸다.
4. **브로커 연결이 끊기면 스스로 섀시를 멈춘다.** MQTT 클라이언트의 연결 끊김 콜백에서 처리한다.

### 3-4. 구현하지 않는 것

Go1 전용 action(`sdk_start`, `sdk_stop`, `sdk_auto`, `scan_mission`, `scan_continue`, `abort_mission`)은 선언하지 않는다. 오면 `UNIMPLEMENTED`로 거부된다. 웹은 이것을 정상으로 다룬다.
`cancel_request`는 선택이다. 구현하면 §7에 적는다.

## 4. 상태 보고

공통 규약 §6의 머리와 `robot` 필드를 쓴다.

| 키 | EP에서 채우는 법 | EP 링크가 끊기면 |
|---|---|---|
| `battery_pct` | SDK 배터리 구독값 | `null` |
| `position` | SDK 섀시 위치 구독값. `{x, y, heading_deg}`, 단위 m·도. 원점은 노드 기동 시 EP 위치 | `null` |
| `speed_mps` | SDK 섀시 속도 구독값의 크기 | `null` |
| `robot_mode` | `idle` / `moving` / `stopped` | 마지막 값 대신 `null` |
| `in_mission` | 이동 명령 실행 중이면 `true` | `false` |
| `link` (`status`) | `ok` / `degraded`(일부 값만 옴) / `fault`(SDK 연결 없음) | `fault` |

- `position`의 축 방향과 `heading_deg` 부호를 §7에 적는다. 가능하면 **x 앞, y 왼쪽, heading 반시계 +** 로 맞춰 달라(ROS 관례). 맞출 수 없으면 있는 그대로 적는다. 웹이 맞춘다.
- `state`는 평시 5초, 움직이는 동안은 5Hz 이상으로 보낸다.

## 5. 예시 바이트

아래 hex는 저장소의 `.proto`와 protobufjs로 만든 값이다. **실측 캡처가 아니다.** 같은 인코더가 드론의 실측 캡처 두 건(`ping` 요청, `UNIMPLEMENTED` 거부)과 바이트 단위로 일치하는 것을 확인했다. `map` 필드의 순서는 인코더마다 다를 수 있으니 디코딩해서 비교한다.

마지막 줄의 `failure.code`는 예시다. §3-3의 `aborted`처럼 노드가 정한 코드를 쓰면 된다.

웹 없이 시험하려면:

```bash
hex2bin() { python3 -c "open('$2','wb').write(bytes.fromhex('$1'))"; }
hex2bin 0a2a0a0a646f632d7475726e2d31120665702d3030311a047475726e220e0a03646567110000000000805640 turn.bin
mosquitto_sub -h <파이> -V 5 -t 'terminal/ep-001/uplink' -F '%x' &
mosquitto_pub -h <파이> -t terminal/ep-001/downlink -q 1 -f turn.bin
```

또는 [mqtt-command.js](../mqtt-command.js)로:

```js
const ep = createRobotControl({ broker: "ws://<파이>:9001/mqtt", device: "ep-001" })
await ep.ping()
await ep.turn(90)          // 오른쪽 90도
await ep.moveForward(0.5)  // 0.5m 직진
await ep.abort()
```

## 6. 적합성 점검

공통 규약 §11의 13개 항목에 더해:

| # | 확인 |
|---|---|
| A1 | `turn{deg: 90}` → EP가 **오른쪽으로** 돈다 |
| A2 | `turn{deg: -90}` → 왼쪽으로 돈다 |
| A3 | `move_forward{distance_m: 0.5}` → 앞으로 약 0.5m 가서 선다. `odo_m`이 오면 그 값을 적는다 |
| A4 | 이동 중 두 번째 이동 명령 → `mission_in_progress` 거부, 첫 명령은 계속 간다 |
| A5 | 이동 중 `abort` → 1초 안에 선다. 걸린 시간을 적는다 |
| A6 | EP 전원을 끄면 `link: fault`, `battery_pct: null`, 이동 명령은 `ep_link_down` |
