## §1 사이드카의 모양 — **문구 사전**이다

경로 기반(`{"tasks":{"T-11":{"title":"…"}}}`)이 아니라 **한국어 → 영어 한 장**으로 둔다.

```json
{
  "missionId": "MSN-260909-01",
  "note": "본문은 원본이 든다. 여기는 화면에 뜨는 문구의 영어뿐이다.",
  "phrases": {
    "문 앞까지 이동": "Move to the door",
    "2D 맵에서 문 위치 확인": "Locate the door on the 2D map"
  },
  "match_en": { "must": [["door"]], "any": ["go", "move"], "not": ["self-driving"] }
}
```

**왜 문구 사전인가.**

- `events[].payload.criterion` 은 `evaluation.criteria[]` 와 **같은 글자**다. 경로 기반이면
  같은 문장을 두 곳에 적어야 하고, 둘이 갈리는 순간 화면이 두 말을 한다.
- 한국어가 **키로 남는다** — §0 제약 3이 요구하는 모양 그대로다.
- 조회가 함수 하나다: `scriptPhrase(missionId, korean)`.

**위험과 그 대비.** 한 편 안에서 같은 한국어가 두 뜻이면 갈라 적을 수 없다. 편 단위라
확률이 낮고, 아래 §5 검사가 **빠진 것**은 잡는다. 실제로 갈리는 자리가 나오면 그때
그 편만 경로 기반으로 내린다 — 지금 없는 문제를 위해 구조를 무겁게 하지 않는다.

## §2 할 일

### A. `registry.json` — `display_name_en` · `aliases_en`

`zones`·`nodes`·`entities` 에 병기한다. 원본 키는 그대로 둔다. 없으면 한국어로 떨어진다.

**별칭은 새로 짓는 것이다.** 「503호」의 영어 별칭은 번역이 아니라
`room 503` · `five oh three` 처럼 **사람이 그렇게 부르는 말**이다.

### B. 대본 사이드카 일곱 편

`scenarios/MSN-*.en.json`. `library.ts` 가 JSON import 로 싣고, 게이트웨이는 안 읽는다
(화면 표시용이라 게이트웨이가 알 필요가 없다).

### C. 추출 사슬 — `places` · `equipment`

`extract-places.mjs`·`extract-equipment.mjs` 가 registry 의 `_en` 을 `label_en`·
`aliases_en` 으로 실어 나르게 고치고 **다시 뽑는다.** 손으로 안 고친다.

### D. `match_en` — 영어 발화로 대본 고르기

`matcher.ts` 가 지금 언어에 따라 `match` 와 `match_en` 중 하나를 쓴다.

### E. STT 언어

| 무엇 | 고칠 것 |
|---|---|
| `src/stt/SttClient.ts` | `transcribe()` 가 `language` 를 FormData 에 싣는다 |
| `stt/vocab.py` | 언어 인자를 받아 **그 언어 어휘만** 준다. 둘을 한꺼번에 안 민다 |
| `stt/service.py` | `language` 를 `vocabulary()` 로 넘긴다 |
| `stt/engines/*.py` | **한 글자도 안 건드린다** (`verify:stt-port`) |
| 발화 패널 | 인식 언어 셋 — `화면 언어 따름` · `한국어` · `English` |

## §3 지키는 것

- **`?lang=ko` 화면이 한 글자도 달라지면 안 된다.** `_en` 은 더하기만 한다.
- **원본 키를 지우지 않는다.** `_en` 이 없으면 한국어로 떨어진다.
- **한국어가 키다.** 평가 증거의 짝짓기는 한국어로 계속한다.
- **개발 메모는 안 옮긴다.** 화면에 안 뜬다.
- `stt-lab/server/engines/` 와 `viz-debugger/stt/engines/` 의 바이트 동일성.
- 의존성 넷(`react`·`mqtt`·`protobufjs`·`ws`) 그대로.
