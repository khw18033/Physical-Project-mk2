> **주소·토큰은 자리표시자다.** 저장소가 Public이라 실값을 문서에 쓰지 않는다.
> `<서버 tailscale IP>` · `<엣지 tailscale IP>` · `<VZ PC tailscale IP>` · `<pi7 tailscale IP>`.
> 토큰은 메신저 DM 같은 **별도 경로**로 전달한다.

> **업무 평면에 대하여(2026-09-21 추가).** 이번 실측에서 **영상만이 아니라 로봇의 업무 데이터도 뷰어까지**
> 흘린다. 그러려면 서버 `/state`가 가시화 쪽 와이어 형식으로 말해야 하는데 지금은 Phase 1 echo 그대로다.
> **그래서 그 어댑터를 실측대비를 위해 임시로 구현한다**(§3-1-1). 정식 상태 채널 계약 — 구독 즉시 캐시
> 1회 푸시(VZ-I-02)·`hello`·명령 경로 — 은 **Phase 5/7 그대로 남는다.**
> (성격상 Phase 5의 절반을 미리 만드는 것이기도 해서 버려지는 코드는 거의 없다.)

> 🔴 **업무 평면도 엣지를 거친다(2026-09-21 결정).** 지금 배치는 MQTT 브로커와 브릿지가 **서버에**
> 있어서 업무 데이터가 `로봇 → 서버 → 뷰어`로 간다. **그쪽이 임시 배치다** — 설계는 브로커와
> 브릿지를 **엣지에** 두는 것이고(`00-architecture.md` §4-1·§4-2 「엣지 요소 다섯」, BE-T-02),
> *"브릿지를 엣지에 두면 MQTT 연결은 로컬, Kafka 프로듀서 연결이 원격(엣지→서버 아웃바운드)"*
> 이라고 적혀 있다. **이번 실측에서 설계대로 되돌린다** — §3-1-2.
>
> **왜 지금 하나.** 서버와 끊겼을 때 **엣지가 계속 받아 두지 못하면 그 구간의 데이터가 통째로
> 사라진다.** **영상은 버려도 되지만 업무 데이터는 버리면 안 된다** — 서버가 영상 프레임을
> 버리는 것(§5-3)은 오래된 프레임에 가치가 없어서이고, 업무 데이터에는 그 논리가 적용되지 않는다.
> 엣지 브로커가 있어야 그 버티기가 성립한다.
>
> ✅ **백엔드 코드 변경은 0이다** — 브릿지는 환경변수 넷만 바꾸면 엣지에서 돈다(§3-1-2).
> 서버 Kafka 엣지 리스너(9095)도 **단계 1-c에 이미 들어 있고** Phase 4 단계 7-d에서 원격 왕복까지 실측했다.
>
> ⚠ **경로가 둘로 갈린다.** 영상은 `로봇 → 엣지 → 서버 → 뷰어`(홉1 RTP + 홉2 WS),
> 업무는 `로봇 → 엣지 MQTT → 엣지 브릿지 → 서버 Kafka → 뷰어`다. **같은 엣지를 거치지만
> 엣지 안에서 다른 프로세스**이고, 하나가 끊겨도 다른 하나는 흐른다.

## 1. 무엇을 하려는가

### 목표를 한 줄로 좁힌다

> **① 로봇 카메라 한 대, 한 방향의 영상 한 장이 뷰어 화면에 뜬다.**
> **② 같은 실측에서 로봇의 업무 데이터(상태값)도 `엣지를 거쳐` 뷰어 화면에 뜬다.**

여기까지가 이번 전부다. 탐지 오버레이·트윈·다중 카메라·다중 로봇은 그다음이다.
**먼저 한 줄이 흐르게 하고, 그다음에 늘린다.**

②를 함께 두는 이유는 **「경로를 완성했다」를 보이려면 두 평면이 동시에 흘러야** 하기 때문이다.
**둘 다 엣지를 거친다** — 영상은 홉1·홉2로, 업무는 엣지 브로커·엣지 브릿지로.

다만 **②는 두 걸음으로 나눠 닫는다.**

| | 경로 | 노트북 | 무엇을 확인하나 |
|---|---|---|---|
| **②-a** | 발행자 → **서버** 브로커 → 서버 브릿지 → 뷰어 | ✕ | **어댑터와 뷰어가 맞물리는가**(형식 문제를 먼저 턴다) |
| **②-b** | 로봇 → **엣지** 브로커 → 엣지 브릿지 → 서버 Kafka → 뷰어 | ● | **경로가 완성되는가**(설계 배치) |

영상에서 합성 fixture로 서버를 먼저 털고 실영상으로 바꾸는 것과 **같은 순서**다.
**②-a는 엣지 노트북 없이 지금 닫을 수 있고**, ②-b는 노트북이 서야 한다.

### 왜 Phase 4로 끝이 아닌가

Phase 4는 **서버 구간을 완성**했다. 다만 검증을 **합성 프레임**으로 했고, 검증이 끝난 뒤
**엣지 입구를 다시 닫았다.** 그럴 만한 이유가 있었다 — 임시 엣지가 이대규 컴퓨터였고 인증 없는
입구를 열어 둘 수 없었다.

그래서 지금 실제로 흐르게 하려면 **다섯 가지를 새로 만들어야 한다**(아래 둘은 2026-09-21 추가).

| 새로 만들 것 | 누가 | 왜 없나 |
|---|---|---|
| **엣지 노트북** (장비 + 구성) | 조병현 | 전용 장비 확보 전. WSL2 임시 구성은 2026-08-31 철수 |
| **홉2 송신기** (엣지 → 서버) | 조병현 | Phase 4는 이 자리를 합성 fixture로 대신했다 |
| **뷰어의 바이너리 수신 경로** | 김현우 | VZ 전송층이 받는 것을 전부 JSON으로 간주한다 |
| **`/state` VZ 와이어 어댑터**(업무 평면) | 이대규 | `/state`가 Phase 1 echo 그대로라 **붙어도 VZ가 전량 버린다**(§3-1-1) |
| **엣지 MQTT 브로커 + 엣지 브릿지**(업무 평면) | 조병현(브로커 실행) · 이대규(설정·브릿지) | 지금은 둘 다 **서버에** 있다. 설계는 엣지다(§3-1-2). **백엔드 코드 변경 0 — 환경변수 넷** |

나머지는 이미 있다. **이 다섯이 이번 일의 실체다** — 위 셋은 영상, 아래 둘은 업무 평면이다.

> 🔄 **v2.3 현황(2026-09-22) — 다섯 중 셋이 섰다.**
>
> | 새로 만들 것 | 상태 |
> |---|---|
> | **엣지 노트북** | 🟡 **임시 배치로 섰다** — HW 개발 PC. 전용 장비는 여전히 미확보. 🔴 **팀 tailnet 합류 대기** |

### 관문 셋 — 종착점은 뷰어, 중간 확인점이 둘

```
        ┌──────────── 관문 A ────────────┐ ┌──── 관문 B ────┐
 로봇 ── pi7 ──홉1── 엣지 노트북 ──홉2── 서버 ──홉3── 뷰어(VZ 앱)
                                          └─ 확인용 ─ console.html
```

**위 그림은 영상 경로다.** 업무 평면은 같은 엣지를 지나되 **엣지 안에서 다른 프로세스**라
그림에 그리지 않았다 — 경로는 §2 상태표와 §3-1-2에 적었다.

- **관문 A — 로봇 영상이 서버에 도착한다.** 서버 지표가 늘어나는 것으로 판정한다.
- **관문 B — 서버가 내보낸 것이 화면에 뜬다.** VZ 앱 canvas로 판정한다.
- **관문 C — 로봇의 업무 데이터가 뷰어 화면에 뜬다.**(2026-09-21 추가) 엣지 안에서 영상은 **홉2 송신기**가,
  업무는 **엣지 브로커 + 엣지 브릿지**가 맡는다. 둘로 나눠 닫는다:
  - **C-a(단계 4-b, 노트북 ✕)** — 발행자 → **서버** 브로커 → 뷰어. **어댑터와 뷰어의 형식**을 먼저 턴다.
  - **C-b(단계 6-b, 노트북 ●)** — 로봇 → **엣지** 브로커 → 엣지 브릿지 → 서버 Kafka → 뷰어. **경로 완성.**

> **관문 A·B·C는 알파벳 순서가 아니다.** 단계 번호로 보면 닫는 순서는
> **B(4) → C-a(4-b) → C-b(6-b) → A(8)**이고, **앞의 둘은 노트북 없이, 뒤의 둘은 노트북이 서야** 닫힌다.
> 마지막 관문이 A인 것이 이상해 보이지만, **A는 실영상이 필요해서 홉1·홉2가 다 된 뒤에야 닫힌다.**

**`console.html`은 우리(백엔드) 확인용 도구이고 최종 경로에는 없다.** VZ 앱을 기다리지 않고
「서버가 내보낸다」를 먼저 닫으려고 쓴다. 판정용 텍스트 출력(프레임 수·순번 갭·키프레임 여부·
디코더 이름)이 본체이고 캔버스는 덤이다.

## 2. 지금 각 구간이 어떤 상태인가

```
로봇 본체 ─ pi7(온디바이스) ─홉1─ 엣지 노트북 ─홉2─ 서버 ─홉3─ 뷰어
            카메라 5대                          8766      8765
            H.264 ws        RTP/UDP        WS 방식 B   WS 방식 B
```

| 구간 | 상태 | 근거 |
|---|---|---|
| 로봇 카메라 → pi7 | ✅ **있다** — 로봇 설정을 건드리지 않고 이미 떠 있는 WS에 붙는다 | HW 실측 464×400 · **약 29~30fps**(HW 기록이 두 값이다 — 카메라 소스 주석 29fps / 설계서 도착 간격 33.3ms=30fps) · 카메라당 0.55Mbps |
| pi7 → 엣지 **(홉1)** | ⚙️ **코드는 있다.** 다만 ① 기본 송신기가 JPEG 경로이고 ② 켜는 명령 경로가 막혀 있다 | §4-7 |
| 엣지 수신 | ✅ **코드는 있다** — RTP를 프레임으로 재조립하는 수신단 | HW `edge/media_gateway.py` |
| 엣지 → 서버 **(홉2)** | ❌ **미구현.** 이번에 만든다 | 규격은 HW 회신 §8-2 |
| 서버 입구 8766 | ⚙️ **코드는 있다. 꺼져 있다** — 포트가 `0`이고 방화벽 규칙도 없다 | Phase 4 단계 8이 되돌림 |
| 서버 → 뷰어 8765 | ✅ **열려 있다** — 단 방화벽에 **이대규 컴퓨터 한 대만** 있다 | §4-0 |
| 뷰어 (VZ 앱) | ❌ **바이너리 수신 경로 없음.** 이번에 만든다 | §3-3 |
| 뷰어 (`console.html`) | ✅ **있다** | 확인용 |
| **엣지 노트북 실물** | ❌ **없다** | HW README *"미디어 게이트웨이(예정) ※ 전용 장비 확보 전"* |
| — **업무 평면**(영상과 같은 엣지를 거치되 엣지 안에서 다른 프로세스다) — | | |
| 로봇/말단 → **엣지** MQTT 브로커 | ❌ **엣지에 브로커가 없다.** 이번에 올린다 | §3-2(나) 신설 항목 |

### 3-1-1. 백엔드 — `/state` VZ 와이어 어댑터 (업무 평면, 2026-09-21 신설)

> **이것은 실측대비를 위해 임시로 구현하는 코드다.** 정식 상태 채널 계약(구독 관리·캐시 푸시·명령 경로)은
> Phase 5/7이고, 여기서는 **「업무 데이터가 뷰어까지 도달한다」를 이번 실측에서 보이는 데 필요한 최소**만 만든다.
> 성격상 Phase 5의 절반을 미리 만드는 것이기도 해서 **버려지는 코드는 거의 없다.**

#### 왜 필요한가 — 지금 붙이면 전량 버려진다

VZ 수신부는 받은 JSON의 `type`으로 분기하는데 **우리 `/state`가 내보내는 것에는 `type` 필드가 없다** →
기본 가지로 떨어져 버려진다. **연결은 되는데 화면이 빈다** — 영상 쪽의 「연결됨인데 영상만 안 옴」과 같은 종류다.

VZ가 실제로 소비하는 것은 이 한 가지뿐이다(`viz-debugger/src/transport/WsTransport.ts`):

```
case 'data': {
  const sub = this.subs.get(msg.sub);   // ← sub 는 VZ 가 붙인 구독 ID('sub-1', 'sub-2' …)
  if (!sub) return;                     // ← 못 찾으면 그냥 버린다
  sub.handler(msg.envelope);
}
```

🔴 **그래서 「봉투를 감싸기」만으로는 안 된다.** `sub` 값은 **VZ가 자기 안에서 만든 ID**라,
서버가 그것을 알려면 **VZ가 보내는 구독 메시지를 읽어야** 한다. 지금 코드는 그걸 통째로 버린다.

✅ **반대로, 생각보다 적게 만들어도 된다.** VZ 수신부에 `subscribed`·`unsubscribed`는 **처리 가지 자체가 없다** —
보내도 무시되므로 **만들지 않는다.** `hello`도 없어도 깨지지 않는다(표시용 두 값이 비어 있을 뿐이다).
**`data` 하나만 맞추면 된다.**

#### 원칙 — 이중 형식 (기존 것을 깨지 않는다)

> **구독 메시지를 보낸 클라이언트에게만 VZ 계약으로 말한다. 안 보낸 클라이언트는 지금 형식 그대로.**

| 클라이언트 | 구독을 보내나 | 받는 형식 |
|---|---|---|
| 서버 회귀 시험 | ✕ | **지금 그대로** |
| 확인용 뷰어(`console.html`) | ✕ | **지금 그대로** |
| **VZ 앱** | ○ (접속 즉시 자동으로 보낸다) | **`{type:'data', sub, envelope}`** |

🔴 **이 분기가 없으면 회귀 시험과 확인용 뷰어가 같이 깨진다** — 둘 다 지금 형식을 직접 읽는다
(회귀 시험이 `channel`·`message` 두 칸을 단언하고, 확인용 뷰어가 같은 두 칸을 화면에 찍는다).

그리고 이 분기는 임시방편이 아니다 — **원래 구독하지 않은 클라이언트는 아무것도 받으면 안 되는 것이 맞고**,
지금 전부 받는 쪽이 Phase 1 echo의 임시 동작이다. **Phase 5에서는 「지금 형식」 가지만 지우면 정식이 된다.**

#### 고칠 곳 — 새 파일 하나 + `ws_echo.py` 세 곳

**① 새 파일 `backend/gateway/vz_wire.py`** — 소켓을 모르는 순수 함수만 둔다.
`media.py`가 *"소켓을 모른다"*로 돼 있는 것과 같은 구조라 **소켓 없이 단위 시험이 된다.**

| 함수 | 하는 일 |
|---|---|
| `selector_matches(selector, message, channel) -> bool` | VZ 계약 축 `{entity, node, channel}` 매칭 |
| `to_vz_envelope(channel, message, scope) -> dict` | 우리 봉투 → VZ 봉투 11필드 |

**② `backend/gateway/ws_echo.py` — 세 곳**

| 자리 | 지금 | 바꿀 것 |
|---|---|---|
| **(a)** `Gateway.__init__`의 `state_clients` | 소켓 **집합**(`Set`) | 소켓 → 구독표 **사전**(`Dict[소켓, Dict[sub_id, {selector, scope}]]`) |
| **(b)** `state_session`의 수신 루프 | `async for _ in websocket: pass` — **받은 것을 버린다** | 구독·구독해제를 파싱해 그 소켓의 구독표에 넣고 뺀다 |
| **(c)** `_broadcast` | 한 번 직렬화해 전원에게 **같은 문자열** | 클라이언트별로 구독표를 보고 **구독이 있으면 VZ 형식, 없으면 지금 형식** |

**(b) 골자**

```
async for raw in websocket:
    try:
        msg = json.loads(raw)
    except (TypeError, ValueError):
        continue
    if msg.get("type") == "subscribe":
        subs[msg["id"]] = {"selector": msg.get("selector") or {}, "scope": msg.get("scope", "all")}
    elif msg.get("type") == "unsubscribe":
        subs.pop(msg.get("id"), None)
```

**(c) 골자**

```
for client, subs in list(clients.items()):
    if not subs:
        await client.send(raw_payload)          # 지금 형식 — 회귀 시험·확인용 뷰어
        continue
    for sub_id, sub in subs.items():
        if vz_wire.selector_matches(sub["selector"], item["message"], item["channel"]):
            await client.send(json.dumps({
                "type": "data", "sub": sub_id,
                "envelope": vz_wire.to_vz_envelope(item["channel"], item["message"], sub["scope"]),
            }, ensure_ascii=False))
```

⚠ **성질이 하나 바뀐다** — 지금은 직렬화를 **한 번** 하고 모두에게 같은 문자열을 보내는데,
`sub` id가 클라이언트마다 달라 **클라이언트별 직렬화**가 된다. `/state` 클라이언트가 관제 화면 한둘이면
문제 없지만 **알고 바꾼다.**

#### 변환 표 — 11칸 중 셋은 값을 정해야 한다

| VZ 칸 | 우리 값 | 비고 |
|---|---|---|
| `zone` | `message["zone_id"]` | 그대로 |
| `node` | `message["node_id"]` | 그대로 |
| `entity` | `message.get("entity_id") or message["source_id"]` | `entity_id`는 **선택 필드**라 폴백이 필요하다 |
| `channel` | Kafka 토픽의 마지막 칸 | ⚠ **`status`는 VZ 채널 어휘에 없다** — 실측에서는 `state`·`heartbeat`만 내보내고 `status`는 거른다 |
| `ts` | `message["timestamp"]` | ⚠ VZ 쪽 정의는 *"서버 시각"*인데 우리 값은 **생산 시각**이다. 실측엔 지장 없고 **Phase 5에서 정리** |
| `seq` | `message.get("sequence_id", 0)` | 선택 필드라 기본값이 필요하다 |
| `payload` | `message` **통째로** | 봉투 칸을 걷어내지 않는다 — 걷어내면 VZ 화면이 무엇을 읽는지 몰라 **빈 화면**이 나올 수 있다 |
| `scope` | 구독 요청의 `scope`를 **되돌려준다** | 자동 |
| **`quality`** | **`"good"` 고정** | 🔴 **잠정.** 진짜 판정은 Phase 5 가용성이다. `"unknown"`을 주면 화면이 전부 회색으로 떠 관통 판정이 흐려진다 |
| **`aggregation`** | **`"raw"` 고정** | 🔴 **잠정.** 집약을 하지 않으니 정직한 값이다 |
| **`coordinate_frame`** | **`null`** | 🔴 **잠정.** 로봇 `state`에 위치가 실리므로 **엄밀히는 정확하지 않다**(BE-C-04 미정의). **VZ에 「지금 null로 보낸다」를 알린다** |

#### 매칭 규약 둘 — VZ가 쓰고 있는 방식에 맞춘다

1. **`'*'`는 와일드카드다.** VZ가 실제로 보내는 것은 `{entity: '*', node: <구역>, channel: '*'}`다.
2. 🔴 **`node` 축에 구역 식별자가 온다.** VZ 코드 주석이 *"node 축에 zone 식별자를 주면 그 zone의 모든
   node에 매칭된다"*로 적혀 있다 — **백엔드가 동의한 적 없는 규약이지만 이번엔 그대로 받는다.**
   매처가 이렇게 돼야 화면이 뜬다:

```
node_ok = sel_node == "*" or sel_node == message["node_id"] or sel_node == message["zone_id"]
```

   이 규약을 계약으로 굳힐지(*"node 축에 zone을 넣는 것이 맞나, zone 축을 따로 둘 것인가"*)는
   **실측 뒤 VZ와 정리한다.** 지금 진행을 막지는 않는다.

#### 시험

| 무엇 | 어디 |
|---|---|
| 매칭 표 전수 + 변환 + **음성 대조**(구독 없는 클라이언트는 지금 형식) | `tests/test_vz_wire.py` 신설 — 소켓 없이 돈다 |
| 구독 관통 1건(구독을 보내고 `data`를 받는다) | 기존 관통 시험 파일에 1건 추가 |
| **기존 272건** | 🔴 **깨지지 않아야 한다** — 이중 형식이 그 보장이다. **반드시 전부 다시 돌린다** |

#### 되돌리는 법

**(b)의 수신 루프를 `pass`로 되돌리면 어댑터는 죽고 나머지는 그대로 돈다** — 구독을 못 받으면 구독표가 비고,
구독표가 비면 (c)가 「지금 형식」 가지로만 간다. `vz_wire.py`는 아무도 부르지 않는 파일이 된다.

### 3-1-2. 백엔드 — 브릿지를 엣지로 옮긴다 (업무 평면 엣지 경유, 2026-09-21 신설)

#### 왜 — 지금 배치가 임시이고, 엣지 배치가 설계다

`docs/be/00-architecture.md` §4 「구간 2 — 엣지 박스 내부 구성요소」가 **엣지 요소 다섯**을 적는다:
**Mosquitto · MQTT→Kafka 브릿지 · Collector(Agent) · 엣지 Prometheus · K3s.**
§4-2가 위치의 이유까지 못 박았다 — *"브릿지를 엣지에 두면 MQTT 연결은 로컬, Kafka 프로듀서 연결이
**원격(엣지→서버 아웃바운드)** → 사설IP·방향 문제 자연 해소. 서버에 두면 서버가 사설망 뒤 각 구역
브로커로 **역방향 접속**해야 하고 구역 수만큼 연결 관리."* (요구사항 **BE-T-02**)

**즉 지금 서버에 브로커·브릿지가 있는 쪽이 임시 배치다.** 이번 실측이 설계대로 되돌린다.

🔴 **그리고 이것이 두 평면의 차이를 성립시킨다.** 서버와 끊겼을 때 —

| | 끊기면 | 왜 |
|---|---|---|
| **영상** | **버린다**(drop-old) | 오래된 프레임은 가치가 없다. 지연을 지키는 편이 낫다 |
| **업무 데이터** | **버리면 안 된다** | 수위·배터리·임무 상태는 그 구간이 통째로 비면 복구할 수 없다 |

**엣지에 브로커가 있어야 그 버티기가 성립한다.** 브로커가 서버에 있으면 끊긴 동안 로봇의
발행은 **아무 데도 도달하지 않고 사라진다.**

#### ✅ 좋은 소식 — 백엔드 코드 변경은 0이다

브릿지(`backend/ingest/bridge.py`)가 만지는 것이 **전부 환경변수**다. 코드를 한 줄도 고치지 않는다.

| 환경변수 | 서버에서(지금) | **엣지에서** |
|---|---|---|
| `MK2_MQTT_HOST` / `MK2_MQTT_PORT` | `localhost` / `1883`(서버 브로커) | `localhost` / `1883` — **엣지 로컬 브로커**. 값은 같고 가리키는 대상이 다르다 |
| `MK2_KAFKA_BOOTSTRAP` | `localhost:9092` | 🔴 **`<서버 tailscale IP>:9095`** — 엣지 리스너 |
| `MK2_QUARANTINE_PATH` | 서버 저장소 안 | **엣지 로컬 경로** — 봉투 불합격이 여기 쌓인다 |
| `MK2_OTEL_ENDPOINT` | `http://127.0.0.1:4316` | 엣지 Collector `http://127.0.0.1:4317`, 또는 **빈 문자열(계측 no-op)** |

> **`MK2_OTEL_ENDPOINT`를 비워도 업무 경로는 그대로 돈다**(설정 표의 제약 20). 실측을 단순하게
> 하려면 **빈 문자열로 시작**하고, 엣지 관측까지 보려면 그때 엣지 Collector 주소를 넣는다.

**필요한 전제 셋은 이미 갖춰져 있다.**

| 전제 | 상태 |
|---|---|
| 엣지에 백엔드 저장소 + 파이썬 환경 | §3-2(나) **4번**에 이미 있다(합성 송신기 때문에 어차피 필요하다) |
| 서버 Kafka 엣지 리스너 **9095** | **단계 1-c**에 이미 있다 — *"엣지가 업무 데이터를 보내는 길"* |
| 그 경로의 원격 왕복 실측 | **Phase 4 단계 7-d에서 이미 했다** — 컴퓨터에서 produce/consume 왕복 + 저장 소비자 적재 1행 |

#### 구현체 — 아키텍처가 이월로 남긴 선택을 이미 했다

`00-architecture.md` §4-2가 **Kafka Connect + MQTT Source(JVM, 최소 수백 MB 힙)** vs
**브로커 네이티브 Kafka 브릿지** 둘을 이월로 남기고 *"캡스톤 엣지가 저사양이면 후자 유리"*라고 적었다.

**우리는 그 둘이 아니라 셋째 길로 이미 구현했다** — `paho-mqtt` + `confluent-kafka`로 만든
**자체 파이썬 브릿지**(2단 검증·격리·A층 계측 포함). **JVM이 없고 브로커에도 종속되지 않는다.**
§4-2가 *"정직한 약점(자원): JVM은 JVM이다"*로 적어 둔 걱정은 **이 구현에는 해당하지 않는다.**
→ 실측 뒤 `00-architecture.md` §4-2에 이 사실을 적는다(§7).

#### 서버 브릿지(`mk2-ingest`)는 어떻게 하나 — **멈추지 않는다**

두 브릿지가 **서로 다른 브로커**를 보므로 중복 적재가 나지 않는다. 발행자가 붙은 브로커가 경로를 정한다.

| 발행자가 붙는 곳 | 타는 경로 | 어느 관문 |
|---|---|---|
| **서버** 브로커 | 서버 브릿지 → Kafka `localhost:9092` | **C-a**(단계 4-b) |
| **엣지** 브로커 | 엣지 브릿지 → Kafka `<서버>:9095` | **C-b**(단계 6-b) |

**둘 다 같은 Kafka 토픽(`mk2.telemetry.*`)에 들어가 같은 `/state`로 나간다** — 그래서 뷰어 쪽은
경로가 바뀐 것을 모른다. 🔴 **그러므로 화면만 보고는 어느 경로인지 알 수 없다.**
판정은 **어느 브릿지의 로그에 `produce:` 줄이 찍히는가**로 한다.

#### 🔴 끊김 버티기 — 이번 실측에서 처음 재는 것

브릿지의 Kafka 프로듀서 설정을 **우리가 지정한 적이 없다.** 버퍼링은 전적으로 라이브러리 기본값에 맡겨져 있고,
**그 한계를 재 본 적이 없다.**

| 알고 있는 것 | 모르는 것 |
|---|---|
| 프로듀서는 로컬 큐에 쌓고 재시도한다 | **얼마나 오래 / 몇 건까지** 버티는지 |
| 복구되면 쌓인 것을 보낸다 | 큐가 **가득 차면 어떻게 되는지** |

🔴 **알려진 위험:** `produce()` 호출이 **예외로 감싸여 있지 않다.** 큐가 가득 차 예외가 나면
**브릿지 자체가 죽을 수 있다.** 이번 실측에서 **터널을 일부러 끊고 재는 것**이 §7의 산출물이고,
**그 결과에 따라 프로듀서 설정과 예외 처리를 정한다**(이번 범위는 **재는 것까지**다).

#### 되돌리는 법

엣지 브릿지를 끄고 서버 브릿지만 두면 지금 배치로 돌아간다. **서버 쪽은 한 줄도 바꾸지 않았으므로
되돌릴 것이 없다.** 로봇의 발행 대상만 서버 브로커로 되돌리면 된다.

> **지표 서버는 그 표에도 없다.** 실제 설정은 Phase 3·4에서 임시 엣지로 돌려 본 **사본**이 있고,
> 저장소에 커밋되지 않은 파일이라 **이대규가 직접 전달한다.**

> ⚠ **그 사본은 「발신자와 수신자가 같은 컴퓨터」인 임시 구성**이라 수신 주소가 자기 자신으로
> 좁혀져 있다. 실 엣지에서는 **pi7이 다른 기기**이므로 수신 주소를 열어야 한다. 주소만 바꾸면
> 되는 게 아니라 **수신단 설정도 함께 바꾼다.**

> **브릿지(7번 브로커의 짝)는 누가 돌리나 — 백엔드 몫이되 장소가 엣지다.** 코드도 환경변수도
> 백엔드가 정하고(§3-1-2), 도는 곳만 엣지다. **관측 스택과 같은 모양**이다 — 설정은 이대규가 주고
> 올리는 것은 엣지에서 한다. 조병현 씨가 하셔도 되고 이대규가 원격으로 해도 된다. **정하고 시작한다.**

> ⚠ **브로커에 인증을 걸지 않는다(이번 범위).** 서버 브로커도 익명 허용이고, 엣지 브로커는
> **방화벽 `1883` 인바운드가 실질 통제**다. TLS·인증은 Phase 6(§8).

#### (다) 홉2 송신기 — 새로 만드는 것

**규격은 HW 회신 `§8-2`의 「송신기 규격」 표가 기준이다.** 여기서는 요약만 적는다 —
**어긋나면 §8-2가 맞다.**

| 항목 | 내용 |
|---|---|
| 방향 | **엣지가 클라이언트로 서버에 붙는다.** 엣지에 인바운드를 열 필요 없음(이 구간만) |
| 단위 | 한 메시지 = **프레임 한 장**(액세스 유닛). 한 장 8MB 이하 |
| 봉투 | `[4바이트 헤더길이(빅엔디언)][JSON 헤더(UTF-8)][영상 바이트]` |
| 헤더 | **필수 다섯 + 선택 둘.** 상세는 §5-2 |
| 키프레임 판정 | 프레임 안에 IDR이 있으면 참. **서버가 이걸 보고 느린 뷰어를 복구시킨다** |
| 중복 금지 | 같은 카메라로 **소켓 하나**. 두 번째가 붙으면 서버가 끊는다 |
| 송신 측 버리기 | 링크가 막히면 엣지도 서버와 같은 규칙으로 버린다 — **다음 키프레임까지 통째로** |

**붙이는 지점은 CLI가 아니라 함수다.** 엣지 수신단은 *"프레임이 완성될 때마다 콜백을 부른다"*는
구조이고, 그 콜백에서 키프레임 판정과 프레임 참조 부여를 하고 서버로 보내면 된다.
파일로 뽑는 실행 방식은 **홉1 도달 확인용**이지 홉2 배선이 아니다.

**참조 구현이 둘 있다.**

- **백엔드 쪽:** 합성 송신기(`tests/media_publisher.py`) — 프레임 경계 규칙·헤더 부여·봉투 인코딩의
  참조 구현이다. **홉2 송신기가 할 일을 그대로 한다.**
- **HW 쪽:** 카메라 뷰어(`pi/bench/go1_cam_view.py`) — ⚠ **홉3 참조 구현이 아니다.** 경로가
  로봇 → pi7 → 브라우저라 **중앙 서버 구간이 통째로 빠져 있고**, 파일 자신이 운영 구성요소가
  아니라고 적었다. **기법 참조로는 가치가 크다** — WS 프레이밍 · 허브 구조 · 브라우저 디코더
  클라이언트 · 시계 보정 · 브라우저 결함 5건 수정이 전부 거기서 나왔다.
  🔴 **다만 그쪽의 「오래된 것 버리기」는 가져오면 안 된다** — **키프레임을 보지 않는 큐 길이
  제한**이고 복구를 브라우저에 맡긴다. 홉2가 요구하는 것은 **키프레임 인지 방식**이다.

#### (라) 말단 pi7 — 업무 데이터를 엣지 브로커로 보낸다 (2026-09-21 신설)

**영상과 같은 엣지를 거치되 엣지 안에서 다른 프로세스다.** 로봇 노드가 **엣지의 MQTT 브로커로 발행**하고,
엣지 브릿지가 그것을 서버 Kafka로 올린다(§3-1-2). **영상의 홉1·홉2와 무관하게 흐른다** —
하나가 끊겨도 다른 하나는 간다.

| # | 할 일 | 내용 |
|---|---|---|
| 1 | 🔴 **발행 대상 브로커를 엣지로 맞춘다** | `<엣지 tailscale IP>:1883`. **pi7 자신의 브로커로 발행하면 아무 데도 도달하지 않는다.** ⚠ 엣지 방화벽에 `1883`이 열려 있어야 한다((나) 8번) |
| 2 | **`state` 채널을 발행한다** | 공통 헤더 필수 다섯 + 채널 본문. 규격은 이미 §1 회신에서 확정된 그대로다 |
| 3 | **구역 식별자를 `zoneA`로 맞춘다** | 서버·가시화와 같은 값이어야 매칭된다(§3-3 ②) |

> 살아남는다. 서버 브로커로 직접 발행하면 끊긴 동안 발행분이 **그대로 사라진다.**
> 영상은 버려도 되지만 업무 데이터는 그러면 안 된다 — 이것이 §3-1-2가 브릿지를 엣지로 옮기는 이유다.

> ⚠ **이것은 관문 C-a의 필수가 아니다.** 백엔드가 **가짜 발행자**로 C-a를 먼저 닫고(단계 4-b),
> 그다음 이 항목으로 **C-b(단계 6-b)**를 닫는다. 영상에서 합성 fixture → 실영상으로 가는 것과
> **같은 구조**다. ⚠ **가짜 발행자도 엣지 브로커를 향하게 하면 C-b를 로봇 없이 먼저 볼 수 있다** —
> 그때 남는 미지수는 「로봇이 규격대로 발행하는가」 하나뿐이 된다.

> 🔴 **실노드 업무 데이터 관통은 Phase 1~4 어디에서도 해 본 적이 없다** — 전부 가짜 발행자였다
> (pi7 배포본이 구판이라 범위 밖으로 뒀다). **이번이 처음이므로 봉투 불합격이 나올 가능성이 높다.**
> 불합격은 **정상 토픽으로 재발행되지 않고 격리 파일로 간다** — 🔴 **그 격리 파일이 이제 엣지에 있다**
> (§3-1-2의 `MK2_QUARANTINE_PATH`). 진단은 거기부터다(§6).

#### 붙는 곳과 방식

| 항목 | 내용 |
|---|---|
| 붙을 주소 | `ws://<서버 tailscale IP>:8765/media?source_id=<카메라 키>&token=<뷰어 토큰>` |
| 소켓 개수 | **새 소켓 하나를 더 연다.** 지금 쓰는 목 게이트웨이 소켓은 **그대로 두고**, 이 소켓만 우리 서버로 붙인다. (우리 서버에서 `/state`와 `/media`는 같은 주소·포트에 경로만 다르지만, 이번에 붙는 것은 `/media` 하나뿐이다) |
| ⚠ 상태 채널 | **2026-09-21 개정 — 이번에 함께 붙인다.** 백엔드가 실측대비용 와이어 어댑터를 만들어 둔다(§3-1-1). **가시화 코드 작업은 사실상 없다** — 아래 「상태 채널」 절의 확인 둘만 해 주시면 된다. 다만 **정식 계약은 아니다**(구독 즉시 캐시 1회 푸시는 이번에 없다 — Phase 5/7) |
| 프레임 참조 | **객체다**(정수 하나가 아니다). 버퍼 키는 카메라 키와 순번의 조합 |
| 재접속 시 순번 | 엣지가 다시 붙으면 순번이 0부터 시작한다. **헤더에 세션 식별자는 없다** — **순번이 줄어들면 새 세션으로 보고 버퍼를 비운다** |
| 첫 프레임 | 항상 키프레임이다. 붙고 첫 그림까지 **합성 실측 215ms** |
| 끊김 | **정상일 수 있다** — 링크가 좁으면 서버가 오래된 것을 버리고 **키프레임에서만 재개**한다. fps는 떨어지고 지연은 지켜진다 |
| ⚠ 서버가 못 지켜 주는 것 | 링크는 빠른데 **브라우저가 디코드를 못 따라가면** 초과분이 브라우저·OS 버퍼에 쌓여 서버가 손쓸 수 없다. **뷰어가 자기 큐를 관리해야 한다** — 최신 프레임만 그리기 + 디코더 큐 임계 재동기 |
| 토큰 | **화면에서 입력.** 코드·설정·시나리오에 넣어 커밋 금지. 토큰 오류는 재시도해도 같으니 **재연결 루프에서 재시도하지 않는다** |

> **브라우저 결함 5건은 HW가 실기에서 이미 고쳤다** — 소프트웨어 디코드 선호 · 최신 프레임만
> 그리기 · 탭이 뒤로 갔을 때의 보조 타이머 · 특정 캔버스 옵션 제거 · 캐시 금지 헤더.
> 원본이 HW 카메라 뷰어에 있고, 우리 확인용 뷰어에도 옮겨 적었다. **처음부터 겪지 않아도 된다.**

> *"node 축에 zone 식별자를 주면 그 zone의 모든 node에 매칭된다"*는 주석의 규약도 **그대로 구현했다.**

> **뷰어 화면으로는 C-a와 C-b를 구분할 수 없다.** 반드시 **어느 브릿지 로그에 찍히는지**로 판정한다.
> 발행자를 엣지로 돌리는 것을 깜빡하면 **C-a를 C-b로 착각한 채 통과**시키게 된다.

**끊김 버티기 — 이번에 처음 재는 것**(§3-1-2)

터널을 일부러 끊고 **① 엣지가 계속 받는가 ② 얼마나 버티는가 ③ 복구 뒤 쌓인 것이 도달하는가**를 잰다.
🔴 **버퍼 한계와 넘쳤을 때의 동작을 모른다** — `produce()`가 예외로 감싸여 있지 않아 브릿지가
죽을 수 있다. **재는 것까지가 이번 범위**이고, 프로듀서 설정은 그 결과를 보고 정한다.

> ⚠ **끊는 방법은 터널을 내리는 쪽으로 한다** — 서버 서비스를 내리면 다른 파트 작업까지 멈춘다.

## 5. 서버가 어떻게 동작하는가 — 송신기·뷰어를 만들 때 필요한 것

### 5-1. 서버는 영상을 열어보지 않는다

이것이 전부이고, 홉2 송신기 설계의 전제다.

| 하는 것 | 안 하는 것 |
|---|---|
| 토큰 확인 | 디코드 |
| 헤더의 **필수·타입만** 검사(값 어휘는 안 본다) | 재인코딩 · 변환 |
| 헤더에서 **두 칸만** 읽음 — 키프레임 여부 · 프레임 참조 | 썸네일 · 리사이즈 |
| 뷰어 소켓별 큐에 나눠 넣기 | 영상 바이트 건드리기 |
| 소켓마다 독립적인 **키프레임 인지 버리기** | 페이로드 열기 |

서버 통과 시간 **0.1~2ms**. 엣지 입구에서는 버리지 않고 **분기만** 한다(뷰어가 없으면 버린다).

> **왜 안 여나.** 서버가 변환을 하면 통과 시간이 수십 ms가 되고 CPU가 코어 단위로 든다.
> 그리고 프레임 참조를 영상과 **한 메시지로 원자적으로** 묶는 것이 나중에 탐지 오버레이가
> 정확히 겹쳐지는 조건인데, 변환하면 그 묶음이 풀린다.

### 5-2. 헤더 — 필수 다섯 + 선택 둘

```json
{ "frame_ref": { "source_id": "go1-001_front",
                 "capture_timestamp": "2026-09-19T14:23:07.412+09:00",
                 "sequence_id": 4837 },
  "encoding": "h264",
  "keyframe": false,
  "width": 464, "height": 400,
  "codec": "avc1.42C01E",
  "correlation_id": null }
```

| 필드 | 규칙 |
|---|---|
| `frame_ref` | **필수.** 안쪽은 **필수 셋 + 선택 둘**(문자열 식별자·시간 동기 상태). **그 다섯 밖의 필드를 넣으면 그 프레임이 거부된다.** 선택 둘은 안 보내도 된다 |
| `frame_ref.source_id` | **`<개체 키>_<위치>`** — 예 `go1-001_front`. 🔴 **접속 주소의 카메라 키와 같아야 한다.** 다르면 서버가 거부한다 |
| `capture_timestamp` | **ISO 시각 문자열**(정수가 아니다. 콜론 오프셋 + 밀리초). 뜻은 *엣지가 프레임 경계를 확정한 시각* — 촬영 시각이 아니고 말단 지연이 포함돼 있으며 보정되지 않았다 |
| `sequence_id` | 엣지가 매기는 단조 증가 정수. **재접속하면 0부터** |
| `encoding`·`keyframe`·`width`·`height` | **필수.** `encoding`은 선언일 뿐 — 서버는 값 어휘를 보지 않고 페이로드도 열지 않는다 |
| `codec`·`correlation_id` | 선택 |

> ⚠ **코덱 문자열을 상수로 박지 마라 — 영상 파라미터(SPS)에서 읽는다.** 세 바이트가 프로파일·
> 제약 플래그·레벨이다. **실물이 정한다.** 틀린 값을 넣으면 뷰어 디코더 설정이 실패한다.
> 참고로 **합성 fixture와 Phase 4 브라우저 실측은 둘 다 `avc1.42C01E`로 같다.** 스키마·예시
> 파일에 보이는 `avc1.42E01E`는 **예시일 뿐**이니 그 값을 복사해 쓰지 않는다.
>
> 🔴 🔄 **v2.3 — 실물은 또 다르다: `avc1.424028`**(HW §4 실측, Baseline **Level 4.0**).
> 합성값 `avc1.42C01E` 는 Level 3.0 이다. **세 값이 전부 다르다** —
> `42E01E`(스키마 예시) · `42C01E`(합성·Phase 4) · **`424028`(실물)**.
> **「헤더에서 읽는다」는 규칙이 바로 이래서 맞았다.** 서버는 `codec` 을 열지 않으므로 서버 변경은 없고,
> **뷰어가 상수로 박으면 실물에서 디코더 설정이 실패한다.** VZ 는 이미 헤더에서 읽고 있다.

> ⚠ **헤더 최상위에 세션 식별자나 카메라 키를 따로 넣지 않는다.** 규격에 없는 필드다.
> 최상위는 막혀 있지 않아 넣어도 거부되지 않고, **서버가 읽지 않은 채 바이트 그대로 뷰어까지
> 간다**(서버는 재직렬화를 하지 않는다). 다만 규격에 없으니 뷰어가 기대할 근거가 없다 — 쓰지 않는다.
> 재접속 시 순번 리셋은 **순번 역전으로 감지**한다.

### 5-3. 서버가 프레임을 버리는 세 가지 — 연결은 유지된다

| 언제 | 무엇이 일어나나 |
|---|---|
| **헤더가 불량하다** | 필수 필드 없음 · 타입 다름 · 프레임 참조 안쪽에 규격 밖 필드 · 오프셋 없는 시각 → **그 프레임만 버린다.** 거부 지표가 는다 |
| **프레임이 8MB를 넘는다** | 프레임만 버리고 연결 유지 |
| **뷰어가 느리다** | 오래된 것을 버리고 **재개는 반드시 키프레임에서**. fps는 떨어지지만 **지연은 바운드된다** |

### 5-4. 연결이 끊기는 네 가지 — 코드로 구분된다

| 코드 | 뜻 |
|---|---|
| **4401** | 토큰 없음·불일치. **재시도해도 같다 — 재연결 루프에서 재시도하지 않는다** |
| **4404** | 경로 밖 |
| **4400** | 카메라 키 없음 |
| **4409** | **엣지 입구(8766)에만 해당** — 같은 카메라 키로 두 번째 **송신기**가 붙음. 송신 소켓은 카메라당 하나다. ⚠ **뷰어(8765)는 같은 카메라에 여럿 붙어도 된다** — 각자 독립으로 버리기가 걸리고, 느린 뷰어 하나가 다른 뷰어를 굶기지 않는다 |

## 6. 막혔을 때 — 위에서부터 지운다

**위가 안 되면 아래는 볼 필요가 없다.**

| 증상 | 먼저 볼 것 | 그다음 |
|---|---|---|
| 엣지에서 서버가 안 보인다 | Tailscale 도달 | 계정이 갈렸는지 |
| 서버 포트가 안 뜬다 | 주소를 먼저 확인했는지 | 없는 IP에 바인딩 → 컨테이너 기동 실패 |
| Kafka가 컨테이너 안에서 안 붙는다 | **정상이다** — 컨테이너發은 방화벽에 막힌다 | 판정을 엣지나 호스트에서 |
| **`mk2-media` 재기동 실패** | **유닛 이름이 틀렸다** | `mk2-ws-echo`다 |

### 기록하는 방식

Phase 4에서 만든 형식을 쓴다 — 단계마다 **해당하는 것만**:

```
1 문서와 다르게 한 것
2 발견한 것 — 증상 / 실측 원문(그대로 붙여넣기) / 원인 / 조치
3 결정한 것 — 물음·선택지·답
4 이 단계가 서버·장비에 남긴 것 (되돌릴 것 포함)
5 검증하지 못한 것
```

없는 항목은 줄을 쓰지 않는다. **앞 단계 기록은 고치지 않고 뒤에만 붙인다.**
원문을 잃었으면 지어내지 말고 「원문 유실」이라 쓴다.

> **이유:** 기억으로 보고서를 쓰면 일어나지 않은 숫자가 들어간다. 실제로 겪었다.
> **파일에 적힌 것만 보고서로 간다.**
