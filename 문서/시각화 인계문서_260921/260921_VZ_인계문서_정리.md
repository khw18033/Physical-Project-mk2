## 2. 막고 있는 것은 방화벽 한 줄이다

서버 8765 방화벽에 **이대규 컴퓨터 한 대만** 들어가 있다. 내 관제 웹 기기의 주소를 보내기 전에는
**연결 시도 자체가 거부된다.** 증상이 토큰·코드 문제처럼 보이지만 방화벽이다.

```
tailscale ip -4      ← 이 출력을 이대규에게 보낸다
```

보내면 규칙 한 줄이 들어가고 뷰어 토큰이 별도 경로로 온다.
**관문 B·C-a·관통이 전부 이 한 줄에 걸려 있다.** 기기가 여럿이면 전부, 시연 때 바뀌면 다시 보낸다.

### 4-1. 구역 식별자 — 「한 줄」이 아니었다 (260921 · 끝남)

이 정리의 첫 판은 「`registry.ts:26` 한 줄」이라고 적었다. **둘 다 틀렸다.**

**첫째, 쓰는 곳이 다섯이다.** 처음에 셋만 적었다.

| 자리 | 하는 일 | 필요한 것 |
|---|---|---|
| `tabs/data/index.ts` | **구독 selector** — 백엔드에 나간다 | 재구독 |
| `tabs/index.tsx` | `startDataLayer` 인자 | 재구독 |
| `tabs/views/DeviceGrid.tsx` | 레지스트리 `zone` 으로 카드 거르기 | 리렌더 |
| `tabs/views/RiskPanel.tsx` | 같은 필터 | 리렌더 |
| `canvas/scope.ts` | `ViewScope.zoneId` → `useZoneSummary` 집계 필터 | 리렌더 |

**둘째, 값을 통째로 바꾸면 안 된다.** 목 게이트웨이(8790)는 `zone-503` 으로 발행하고
백엔드 `/state` 는 `zoneA` 로 발행한다. 상수를 `zoneA` 로 고치면 **기존 시연 경로가
빈 화면**이 되고, 그대로 두면 관문 C-a 가 성립하지 않는다 — 어느 쪽을 고르든 다른 쪽이 죽는다.

인계문서가 「목 게이트웨이는 그대로 두고 `/state` 를 추가한다」고 했으니 둘이 공존해야 하고,
그러면 **구역은 붙는 게이트웨이를 따라가야** 한다. 그래서 연결 설정(`gateway.zone` 칸)으로
옮겼다 — 주소를 바꾸는 사람이 구역도 같이 바꾼다. 기본값은 `zone-503`(목) 그대로다.

**반영 방식은 이 저장소가 주소에 쓰던 것을 그대로 따랐다**(`transport/index.ts`):
게터로 읽고 · `subscribeConnections` 로 알림을 받고 · 값이 실제로 달라졌을 때만 ·
끊고 다시 건다. 다만 **재연결로는 구역이 안 따라온다** — selector 는 `subscribe()` 하는
순간 전송 계층의 `subs` 에 박히고 재연결은 **박힌 그것을 그대로** 다시 보낸다.
그래서 끊고 다시 거는 대상이 소켓이 아니라 **구독**이다.

<a id="s4-2"></a>

### 4-2. 레지스트리 밖 개체를 화면에 꺼낸다 (260921 · 끝남)

`DataStore.apply` 는 레지스트리에 없는 개체도 **받아 둔다.** 그런데 현황판이
`r.registry?.zone === ZONE_ID` 로 걸러서 **카드가 안 나왔다.** 관문 C-a 에서 백엔드가
보내는 로봇 개체 키는 목 레지스트리에 없으므로 정확히 그 상태가 된다 — 봉투는 쌓이는데
화면은 비어서, **어댑터가 안 붙은 것인지 우리가 안 그리는 것인지 구분할 수가 없다.**

값이 한 번이라도 온 레지스트리 밖 개체를 **따로 구획**으로 그린다(`UnregisteredCard`).
없으면 구획도 안 뜬다.

**판정을 그리지 않는 카드다.** `DeviceCard` 는 payload 가 3층(`StateLayers`)인 것을 전제로
층별 배지를 그리는데 백엔드 어댑터는 원래 메시지를 통째로 넣는다 — 없는 층을 그 카드에
태우면 「미배포」·「정상」 같은 **없는 판정**을 말하게 된다. 적는 것은 아는 넷뿐이다:
개체 키 · 받은 봉투 수 · 채널별 마지막 `ts`·`seq` · payload 원문.

**지나가다 찾은 구멍 하나 —** `deriveDisplayStatus` 의 첫 줄이 `deployment !== 'deployed'`
라, 그 칸이 **아예 없는** payload 가 오면 참이 되어 **「미배포」로 단정**한다. 3층 모양이
아니면 「알 수 없음」으로 두는 가드를 앞에 넣었다. **이 payload 는 관문 C-a 에서 실제로
온다** — 안 고쳤으면 백엔드가 보낸 로봇이 화면에서 「미배포」로 보일 뻔했다.

### 디코드 — 처음부터 겪지 않아도 되는 것

HW 가 실기(464×400 H.264)에서 이미 고친 **브라우저 결함 5건**이 있다. 원본은 HW 카메라 뷰어
(`pi/bench/go1_cam_view.py`)에 있고 백엔드 확인용 뷰어(`backend/gateway/console.html`)에도 옮겨 적혀 있다.

1. `hardwareAcceleration: 'prefer-software'` — 이 해상도에서는 소프트웨어 디코드가 밀리초대이고 **하드웨어 경로가 오히려 늦다**
2. **최신 프레임만** rAF 주기로 그린다 — 디코더 출력을 전부 그리면 밀린다
3. **보조 타이머** — 탭이 뒤로 가면 rAF 가 멈춘다
4. `desynchronized` 제거 — vsync 한 주기를 아끼려던 옵션이 오히려 찢김
5. `Cache-Control: no-store` — 옛 JS 를 캐시로 재사용

**코덱 문자열을 상수로 박지 않는다.** 헤더의 `codec` 을 그대로 쓴다.
실측·fixture 는 둘 다 `avc1.42C01E` 인데 **스키마 예시 파일의 `avc1.42E01E` 는 예시일 뿐**이다.
세 바이트가 프로파일·제약 플래그·레벨이고 **실물이 정한다.**

## 5. 테스트 — 관문 넷

```
        ┌──────────── 관문 A ────────────┐ ┌──── 관문 B ────┐
 로봇 ── pi7 ──홉1── 엣지 노트북 ──홉2── 서버 ──홉3── 뷰어(VZ 앱)
```

| 관문 | 단계 | 성공 조건 | 노트북 |
|---|---|---|---|
| **B** | 4 | 합성 프레임이 **canvas 에 한 장이라도** 뜬다 | ✕ |
| **C-a** | 4-b | `/state` 로 **상태값이 한 건이라도** 뜬다 | ✕ |
| **C-b** | 6-b | 업무 데이터가 **엣지를 거쳐** 뜬다 | ● |
| **A** | 8 | 실영상이 서버에 도착한다(서버 지표) | ● |

**닫는 순서는 B(4) → C-a(4-b) → C-b(6-b) → A(8)** 다. 알파벳 순이 아니다 —
A 는 실영상이 필요해서 홉1·홉2 가 다 된 뒤에야 닫힌다.

**노트북 없이 B 와 C-a 까지 닫을 수 있다.** 거기까지 닫아 두면 노트북이 선 날
**남은 미지수가 경로뿐**이 된다.

| # | 무엇 | 어디 |
|---|---|---|
| 1 | **레지스트리 밖 구획에 로봇 카드가 뜬다** | 현황판 아래 「레지스트리에 없는 개체」 |
| 2 | 그 카드의 **「받은 봉투 n건」이 는다** | 같은 카드 |

⚠ **프롬프트가 든 「관측 패널(`ObservabilityPanel`)의 봉투 수」는 화면에 없다.**
그런 패널 자체가 없고, 봉투 수(`envelope_count`)는 `selfObservability` 가 60초마다
`/observability/client-metrics` 로 **POST 할 뿐 아무 데도 안 그린다.** 그래서 화면 판정은
위 둘이고 둘 다 같은 카드에 있다 — 독립된 두 자리가 아니다.

나머지는 검사로 못 박았다(`verify:stray-entity`, 대조군 2건). 목에는 레지스트리 밖 개체를
발행하는 시나리오가 없어 **검사 안에서만** 흉내 낸다 — `gateway/` 는 안 건드린다.

> 화면 판정을 진짜로 두 자리로 나누고 싶으면 **봉투 수를 어딘가에 그려야 한다.**
> 지금은 안 그린다는 사실만 적어 둔다 — 없는 판정 수단을 있다고 적지 않는다.

### 🔴 C-b 는 화면으로 판정하면 안 된다

서버 브로커 경유(C-a)와 엣지 경유(C-b)가 **같은 Kafka 토픽으로 합류해 같은 `/state` 로 나간다.**
**뷰어 화면으로는 둘을 구분할 수 없다.** 어느 브릿지 로그에 `produce:` 가 찍히는지로만 판정한다 —
발행자를 엣지로 돌리는 것을 깜빡하면 **C-a 를 C-b 로 착각한 채 통과**시킨다.

### 정상인데 실패로 보이는 것 셋

- **끊김** — 링크가 좁으면 서버가 오래된 것을 버리고 **키프레임에서만 재개**한다. fps 는 떨어지고 지연은 바운드된다
- **연결됨인데 영상 없음** — 엣지가 아직 안 붙어 있으면 소켓은 열리고 프레임만 안 온다
- **붙자마자 상태가 안 참** — 구독 즉시 캐시 1회 푸시가 없어 **다음 발행까지 기다린다.** 로봇 상태 1초, **평시 센서는 최대 1분**

## 6. 백엔드에 회신할 것 — 5개

**①②③ 을 보내기 전에는 저쪽이 8765·4318 입구를 열지 않는다.**

| # | 무엇 | 없으면 |
|---|---|---|
| ① | **관제 웹 기기의 tailnet 주소**(`tailscale ip -4`). 여럿이면 전부. ⚠ 아래 주의 | 8765·4318 둘 다 안 열림 — **관문 B·C-a·관통이 전부 막힘** |
| ② | **Collector CORS 허용 origin** + 브라우저가 쓸 **OTLP exporter 종류**(protobuf / json) | 4318 안 열림 |
| ③ | 관제 웹을 **https 로 서빙하는가** | http 로 간주. https 면 `http://…:4318` 이 **mixed content 로 차단**된다 |
| ④ | 실제 `source_id` 확인 | **이미 답이 왔다** — 개체 `go1-001`, 카메라 `go1-001_front` |
| ⑤ | **「발화 원문」 라벨의 실제 키 이름**(`utterance`? `transcript`?) | 금지 라벨 목록에 못 넣는다(문자열 집합이라 이름이 필요하다) |
| ⑥ | 🔴 **`state` payload 가 `StateLayers` 모양이 아니다** — 지금은 화면이 「알 수 없음」으로 표시한다 | 아래 참조 |

**⑥ 에 대해 알릴 것.** 화면은 상태 3층(`device_status`·`availability`·`deployment`·`last_seen`·
`stale_threshold_ms`·`reason`)을 기대하는데, 실측대비용 어댑터는 **원래 메시지를 통째로**
payload 에 넣는다. 가용성 판정이 Phase 5 라 `availability` 가 없는 것도 맞다.

**지금은 그래도 깨지지 않는다** — 3층 모양이 아니면 「알 수 없음」으로 두는 가드를 넣었고,
레지스트리 밖 구획의 카드는 애초에 판정을 안 그리고 원문을 적는다. 그러니 **이번 실측을
막는 것은 아니다.**

알리는 것은 사실 하나뿐이다: **이번 판에서는 상태가 「알 수 없음」으로 보인다.**
어댑터가 `StateLayers` 를 채울지는 **Phase 5 의 정식 계약과 함께 정하자** — 실측대비용
임시 구현에 3층을 억지로 채우게 하면 그 모양이 그대로 굳는다.

⚠ **①을 보낼 때 같이 알릴 것 하나.** env 파일은 tailnet 장비 둘(`desktop-oaujese` ·
`laptop-isk6l1rq`)을 **「우리 것이 아니니 건드리지 않는다」**로 적었는데,
`vz-media-interface.md` §10 은 **`laptop-isk6l1rq` 를 관제 노트북 후보**로 봤다.
**관제 웹을 그 둘 중 하나에서 돌린다면 주소를 보낼 때 그 점을 같이 알린다** — 안 그러면
저쪽이 「남의 장비」로 알고 방화벽을 안 열거나, 열고도 서로 다른 기기로 알고 있게 된다.
(실제 IP 는 여기 적지 않는다.)

추가로 저쪽이 물은 것 둘:

- **DAG 노드 식별자를 `node_ref` 라는 이름으로** 내보내 달라. 저쪽 공통 헤더의 `node_id` 는
  **발행 물리 노드**(저카디널리티, 허용)라 뜻이 다르다
- `vz-stt`·`vz-gen` 이 **어느 기계에서 도는지** — 브라우저가 아니라 별도 프로세스라 gRPC 를 쓸 수 있고,
  셋이 다른 기계면 방화벽 `/32` 대상이 갈린다

### 관측 — 이전 통지에서 바뀐 것

저쪽이 자기 통지 §4 의 세 문장을 **정정했다.** 그대로 두면 없는 경로로 발신 코드를 짜게 된다.

| 원문 | 정정 |
|---|---|
| "HTTP 4318 은 열려 있지 않다" | **열린다** — Tailscale IP 바인딩 + CORS + ufw `/32`. 구현은 ①②③ 회신 뒤 |
| "`<서버>:4316`(TLS)" | **4316 gRPC 가 아니라 4318 HTTP**, **TLS 가 아니라 평문 + ufw `/32`** |
| 「Collector OTLP gRPC `127.0.0.1:4316`」 | 같은 이유로 개정 — 브라우저는 `http://<서버 tailscale IP>:4318` |

우리 쪽 결정(접두사 `vz.` · 60초 · `service.name` 셋 · Unity 트윈 제외)은 **전부 그대로 OK** 다.

## 7. 규칙 충돌 하나 — `VZ-C-07`

`VZ-C-07` 문면이 *"구독·명령 출구는 여전히 하나다"* 인데 **소켓이 둘이 된다**
(목 게이트웨이 8790 은 그대로 두고 `/media`·`/state` 를 추가하므로 실제로는 셋).

- `verify:one-gateway` 는 파일 단위 정규식이라 **검사는 통과**한다
- 그러나 **요구사항 문면은 우회되지 않는다** — "게이트웨이 주소는 하나, 소켓은 경로별 둘"로
  **문면 재협상이 필요하다.** 백엔드도 그렇게 읽고 있다

`verify:view-nodes`(영상 구독 참조 계수)는 **규칙 자체가 유효하다.** 다만 구독할 때 보내는
열기/닫기 메시지는 저쪽 서버에서 아무 일도 하지 않는다 — Phase 4 가 **「연결이 곧 켜기」**로
정해 제어 메시지를 없앴다. **지워도 남겨도 무해하다.**

## 부록 — 값과 어휘

주소·토큰 실값은 `env 정보 및 별도 전달 값_1.txt` 에 있다(**커밋 안 함**).

```
[영상]  ws://<서버 tailscale IP>:8765/media?source_id=go1-001_front&token=<뷰어 토큰>
[상태]  ws://<서버 tailscale IP>:8765/state?token=<뷰어 토큰>
```

주소·포트가 같고 **경로만 다르다.** 목 게이트웨이(8790)는 **그대로 두고** 위 둘을 추가한다.
영상은 바이너리, 상태는 JSON 이다 — **같은 수신 처리로 받으면 영상이 조용히 버려진다.**

| 축 | 값 |
|---|---|
| 구역 `zone_id` | `zoneA` |
| 개체 키(`target_entity_id` 등) | 로봇 `go1-001` · 센서 예 `wl-001` |
| 카메라 키(`/media` 의 `source_id`, 탐지 `frame_ref.source_id`) | `go1-001_front` (그 외 `_chin`·`_left`·`_right`·`_belly`) |
| 구독 selector | `{ entity: '*', node: 'zoneA', channel: '*' }` — **지금 코드 모양 그대로** |
| 채널 | `state` · `heartbeat` (`status` 는 우리 `Channel` 타입에 없어 이번에 안 온다) |

⚠ **개체 키와 카메라 키는 같은 체계의 다른 값이다.**
개체 축에 카메라 키를 넣으면 **레지스트리 조인이 깨진다.**

⚠ **`origin.kind`(탐지 정밀도: `safety_minimal`·`precise`)와 공통 헤더 `origin_kind`
(원천 종류: `real`·`simulation`·`replay`)는 다른 축이다.** 후자는 **원천이 채우고
백엔드는 중계분에 채우지 않는다** — 채우면 「안 보낸 것」과 「백엔드가 채운 것」을 구분할 수 없다.

⚠ **`capture_timestamp` 는 촬영 시각이 아니다.** **엣지가 프레임 경계를 확정한 시각**이고
말단 내부 지연이 포함돼 있으며 보정되지 않았다. **그래서 스트림 staleness 는 이 값이 아니라
뷰어의 마지막 도착 시각으로 판정한다.**
