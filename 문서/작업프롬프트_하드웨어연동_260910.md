## 1. 채널 — 확정된 사실

하드웨어 담당이 실제로 쏴 보고 바이트까지 확인한 뒤 우리 질문에 회신한 내용이다.
**추측이 아니라 관측과 합의다.**

| | |
|---|---|
| 브로커 | `pi7.local:1883` (TCP) · **`ws://pi7.local:9001`** (WebSocket) |
| 프로토콜 | MQTT 5, 인증 없음 |
| 발행 토픽 | `terminal/go1-001/downlink`, QoS 1 |
| 수신 토픽 | **`terminal/go1-001/uplink`**, QoS 1 |
| 페이로드 | **protobuf 바이너리.** JSON 문자열이 아니다 |

**브라우저는 WebSocket 쪽을 쓴다.** 9001 포트다.
응답 세 종(`Acceptance` · `CommandStatus` · `CommandResult`)이 **모두 uplink 하나로** 온다.
종류는 봉투의 `oneof body`가 구분한다.

### 봉투 구조

```
Envelope { field 1 = Command { 1: command_id, 2: target, 3: action, 4: parameters } }
```

`parameters`는 `map<string, double>`이다. 문자열 파라미터를 넣을 자리가 없다.

### action 셋

| action | parameters | 비고 |
|---|---|---|
| `ping` | 없음 | 31바이트. 연결 확인용 |
| `scan_mission` | `steps=8`, `forward_m` | `forward_m`은 스캔 뒤 전진까지 포함. `0`이면 스캔만 |
| `move_forward` | `distance_m` (0.05~10), `vx` (생략 가능) | 전진만. 결과 `{distance_m, odo_m, duration_s}` |

### 웹에서 만드는 법

```js
const payload = Envelope.encode(Envelope.create({ command: {
  commandId : 'cmd-' + Date.now(),
  target    : 'go1-001',
  action    : 'scan_mission',
  parameters: { steps: 8, forward_m: 0 }
}})).finish()

client.publish('terminal/go1-001/downlink', payload, { qos: 1 })
```

## 2. 경계 파일 — STT·생성과 같은 패턴

`src/physical/PhysicalClient.ts` 하나가 **하드웨어를 보는 유일한 면**이다.
이 파일 밖에서 MQTT 클라이언트를 만들거나 토픽 문자열을 적지 마라.

| | STT | 생성 | **하드웨어** |
|---|---|---|---|
| 경계 파일 | `src/stt/SttClient.ts` | `src/generate/LlmClient.ts` | **`src/physical/PhysicalClient.ts`** |
| 연결 대상 | `stt` | `generate` | **`physical`** — 기본값 `ws://pi7.local:9001` |
| 꺼져 있으면 | 음성만 꺼짐 | 생성만 꺼짐 | **로봇 명령만 꺼짐. 대본 재생은 그대로 돈다** |
| 검사 | `verify:no-stt` | `verify:no-llm` | **`verify:no-physical`** (신설) |

### 주소 프리셋 넷

이름이 안 풀릴 때를 대비해 화면에서 고를 수 있게 한다.

| 프리셋 | 값 |
|---|---|
| 이름 | `ws://pi7.local:9001` |
| 랩 Wi-Fi | `ws://192.168.50.172:9001` — 고정 IP |
| **발표장 핫스팟** | **자리만 비워 둔다.** 5GHz 대역·SSID·PW를 전달했고 정적 IP가 나오면 채운다 |
| 직접 입력 | 사용자가 적는다 |

핫스팟 IP는 아직 없다. **값을 지어내 넣지 말고 빈 프리셋으로 두어라.**
받는 즉시 한 줄만 고치면 되게.

### protobuf를 어떻게 넣을 것인가

하드웨어 쪽은 "브라우저면 protobufjs가 `.proto`를 런타임에 읽으므로 컴파일 불필요"라고 했다.
**우리 저장소에서는 정적 코드 생성 쪽이 낫다.** 이유 둘이고 둘 다 이 저장소의 기존 제약이다.

1. `verify:standalone`이 단독 빌드 오염을 KB 단위로 감시한다. 런타임 파싱은 protobufjs 전체가
   들어가지만 정적 생성은 `protobufjs/minimal`이면 된다
2. 런타임 파싱은 `.proto`를 정적 자산으로 서빙해야 한다. `dist/`를 그대로 뿌리는 배포 형태와
   맞물려 경로 문제가 생긴다

그러니 `pbjs`로 정적 모듈을 뽑아 커밋한다. **다만 먼저 숫자를 재라** — 착수 전 KB와 비교해
런타임 파싱이 한도 안에 들어온다면 하드웨어 쪽 방식을 따라도 된다. 보고서에 근거를 남긴다.

### `.proto`를 가져오는 방법

원본은 `HW` 브랜치의 `schema/physical_command.proto` 하나다.
우리 쪽 복사본은 **낡을 수 있다.** 복사본 머리에 출처와 가져온 날짜를 주석으로 적고,
재생성 스크립트에도 같은 URL을 남겨라.

```
https://github.com/khw18033/Physical-Project-mk2/blob/HW/schema/physical_command.proto
```

**스키마를 우리가 고치지 마라.** 고쳐야 할 일이 생기면 하드웨어 쪽에 요청한다.

## 3. 명령 매핑 — 어느 태스크가 무엇을 쏘는가

| 태스크 | action | parameters |
|---|---|---|
| `T-A3` 로봇이 1바퀴 돈다 | `scan_mission` | `steps=8`, **`forward_m=0`** |
| `T-B2` 전방으로 직진 | `move_forward` | `distance_m=n`, `vx` 생략 |
| 연결 확인 (화면 버튼) | `ping` | 없음 |

### 왜 `scan_mission`에 전진을 태우지 않는가

`scan_mission`은 `forward_m`으로 스캔과 전진을 한 번에 할 수 있다. 그런데 **순서도가 스캔과
접근을 다른 마일스톤으로 갈라 놓았다.** 명령 하나가 두 마일스톤에 걸치면 어느 노드를 언제
완료로 바꿀지 애매해진다.

`forward_m=0`으로 스캔만 시키고, 접근은 `move_forward`로 따로 쏜다.
**태스크 경계와 명령 경계를 맞추는 것**이 이 결정의 이유다.
스캔이 끝난 뒤 사람이 화면을 보고 접근을 이어 갈 수 있다는 부수 효과도 있다.

### 방향과 거리의 출처는 한 곳에

하드웨어 쪽이 **`door_turn`과 `move_forward`를 경로 탐색 결과대로 움직이도록 바꿀 수도 있다**고
했다. 지금은 로봇이 스캔에서 문으로 판정한 방향으로 돌지만, 나중에 우리가 산출한 경로를
따르게 될 수 있다.

그러니 **방향과 거리를 정하는 자리를 함수 하나로 묶어 둬라.** 지금은 상수를 내놓고,
경로 산출이 붙으면 그 함수의 속만 바꾼다. 명령을 쏘는 코드가 값의 출처를 몰라야 한다.

### 연결 확인 버튼

`ping`을 쏘고 왕복이 도는지 보는 버튼을 화면 한구석에 둔다.
**발표 직전에 이걸 눌러서 초록이 뜨는지 보고 무대에 오른다.** 시연 중에는 안 쓴다.

## 4. 응답 매핑

| 응답 | 뜻 | 화면 |
|---|---|---|
| `Acceptance{accepted:true}` | 받았다 | 태스크 노드 실행 중 |
| `Acceptance{accepted:false}` | **거절** | 태스크 노드 실패. `rejection.code`와 `message`를 그대로 노출 |
| `CommandStatus` | 진행 보고 | **5절 — 이게 뷰포인트 노드를 채운다** |
| `CommandResult{SUCCEEDED}` | 끝 | 태스크 노드 완료 |
| `CommandResult{그 외}` | 실패 | 태스크 노드 실패 + 사유 |

### 거절을 숨기지 마라

`robot_state_dead`가 실제로 나온 응답이다. 로봇을 안 켜면 시연 당일에도 이게 뜬다.
**화면에 코드와 문구를 그대로 띄워라.** 조용히 실패하면 무대에서 원인을 못 찾는다.
논문의 「실패 경로」 주장과도 같은 방향이다.

## 5. `CommandStatus.detail` — 뷰포인트를 채우는 열쇠

`detail`이 JSON 문자열로 온다. `JSON.parse(detail)`.

```json
{"ack":3,"of":10,"event":"scan_turn","step":3,"steps":8,"yaw_deg":131.0,"note":"ok"}
```

| 필드 | 내용 |
|---|---|
| `ack` / `of` | 이번 임무의 ACK 순번 / 총 ACK 수 |
| `event` | `scan_turn` · `door_turn` · `forward` · `aborted` |
| `step` / `steps` | 그 단계에서 몇 번째인가 — 회전 3/8의 3, 8 |
| `yaw_deg` | 그 시점 방위(도). **모를 수 있다 — `null` 처리** |
| `note` | `ok` · `turn_timeout` · `robot_state_lost` · `forward_timeout` |

### ACK 개수 — 확정

`forward_m=0`이면 **`of`는 9**다. 스캔 여덟에 `door_turn` 하나.
진행률을 `ack/of`로 표시해도 된다.

### 지켜야 하는 것 넷

**㉠ `step`은 1부터 시작한다. 우리 노드 인덱스는 0부터다.**
`index = step - 1`. 이 한 줄을 틀리면 노드가 한 칸씩 밀린다. 화면은 그럴싸하게 돌아가서
눈으로는 못 잡는다. 이 작업에서 가장 흔하게 날 실수이고, 7절 검사가 이것부터 본다.

**㉡ `event`로 갈라라.** `scan_turn`만 뷰포인트 노드를 건드린다.
`forward`는 `T-B2`, `aborted`는 임무 중단, `door_turn`은 아래 참조.

**㉢ `note != "ok"`이면 그 노드에 경고를 남겨라.** `turn_timeout`은 그 각도를 제대로
못 봤다는 뜻이다. 조용히 정상으로 칠하면 안 된다.

**㉣ `yaw_deg`로 노드를 고르지 마라.** `step`이 기준이다. `yaw_deg`는 화면 표시용이고
`null`일 수 있다.

### `door_turn`은 마일스톤이 넘어가는 계기

`door_turn`은 **로봇이 문으로 판정한 방향으로 몸을 돌리는 것**이다. 스캔의 마지막 ACK다.

순서도에는 방향 전환을 뜻하는 태스크 노드가 없다. 초록 노드에서 「문에 접근한다」로
**선이 이어지는 것**이 그 자리다. 그러니 `door_turn`을 새 노드로 만들지 말고
**그 선을 활성화하는 계기**로 쓴다. `T-A3` 완료와 `MS-B` 시작이 여기서 갈린다.

`door_turn`의 `yaw_deg`가 오면 **화면이 고른 각도와 맞는지 대조해 두어라.**
어긋나면 로봇이 우리와 다른 방향을 보고 있다는 뜻이고, 그건 시연 중에 알아야 하는 사실이다.
어긋났을 때 무엇을 할지는 정하지 말고 일단 기록만 남긴다.

### 인덱스를 올리는 자리는 함수 하나

`detail`을 파싱해 인덱스를 내놓는 함수를 하나만 둔다. 노드 갱신 코드는 그 인덱스가
로봇에서 왔는지 대본에서 왔는지 몰라야 한다.

## 6. 문 유무 판정은 아직 대본이 준다

이번 범위에 탐지 연동이 없다. 하드웨어는 **어느 각도를 보고 있는지**만 알려 주고,
**거기 문이 있는지**는 말해 주지 않는다.

| 무엇 | 이번 단계의 출처 |
|---|---|
| 몇 번째 각도인가 | **로봇** — `CommandStatus.detail.step` |
| 그 각도에 문이 있는가 | **대본** — index 2만 `door: true` |

두 출처가 섞이는 자리를 분명히 갈라 둬라. 탐지가 붙을 때 아랫줄만 바꾸면 되게.

### 목 uplink

브로커 없이 개발할 수 있어야 한다. 목 uplink를 하나 둔다.

- `CommandStatus`를 1초+1초 간격으로 `step` 1~8까지 흘리고, 마지막에 `door_turn` 하나
- `of`는 9
- **한 번은 `note`를 `turn_timeout`으로** 내보내 경고 표시가 실제로 뜨는지 본다
- `yaw_deg`가 `null`인 경우도 한 번 섞는다

## 7. 검증

| 검사 | 무엇을 |
|---|---|
| **`verify:status-index`** (신설) | **`step`(1~8)이 노드 인덱스(0~7)로 옳게 옮는가** · `scan_turn`이 아닌 event가 뷰포인트를 안 건드리는가 · `note != ok`가 경고로 남는가 · `yaw_deg: null`에서 안 깨지는가 · `door_turn`이 `MS-B` 전이를 일으키는가 |
| **`verify:command-encode`** (신설) | `scan_mission{steps:8, forward_m:1.0}`을 인코딩하면 **자료의 79바이트 hex와 같은가** · `ping`이 31바이트인가 · `move_forward`가 스키마를 통과하는가 |
| **`verify:physical-port`** (신설) | MQTT 주소·토픽을 아는 면이 `src/physical/` 하나인가 |
| **`verify:no-physical`** (신설) | 브로커가 없어도 화면이 뜨고 **대본 재생·되감기·캔버스가 도는가** |
| `verify:standalone` | **증가분을 숫자로 남긴다.** 한도를 넘으면 보고서에 적고 판단을 물어라 |
| `verify:viewpoint-fill` · `viewpoint-layout` | 1단계 결과 그대로 통과 |
| 기존 전종 | 통과 |

`verify:status-index`와 `verify:command-encode` 둘이 이 작업의 핵심 검사다.
앞엣것은 **한 칸 밀림**을 잡고, 뒤엣것은 **하드웨어가 알아듣는지**를 로봇 없이 증명한다.

## 8. 하지 않을 것

- **객체 탐지 HTTP 연동** — 이번 범위 밖. 뷰 노드 셋도 만들지 않는다
- 중앙 서버 경유 경로 — 시연은 온디바이스 직통으로 확정됐다
- 2D 맵 — 다른 담당이다
- `.proto` 스키마 수정 — `HW` 브랜치 것이다
- `scan_mission`에 `forward_m`을 태워 두 마일스톤을 한 명령으로 묶는 것
- `door_turn`을 새 노드로 만드는 것 — 선을 활성화하는 계기로만 쓴다
- 핫스팟 IP를 짐작해서 넣는 것
- 뷰포인트 노드의 배치·색 — 1단계에서 끝났다
