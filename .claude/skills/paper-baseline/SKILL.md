# paper-baseline

비교 실험에서 우리 편향을 차단하기 위한 규칙이다.

## 검사 가능한 규칙

1. **무가정 실행**: 실행 전 어느 방법이 우수하다고 가정하지 않는다. 코드 주석,
   커밋 메시지, 보고서 초안에 "proposed가 우수함을 보인다" 같은 예단을 쓰지 않는다.
2. **세 결과를 모두 허용**: 결론은 *proposed 우수* / *차이 없음* / *baseline 우수*
   중 하나이며, 셋 다 정상적인 결과다. "차이 없음"을 실패로 취급해 조건을 바꾸지 않는다.
   변별력 없는 시나리오는 변별력 없다고 적는다
   (예: `stable`, `dropout`, `conflict` — 전 규칙 동률).
3. **충돌 시 주장을 고친다**: 논문 주장과 실험값이 충돌하면 **주장을 수정하고
   실험값은 수정하지 않는다.** 지표 정의를 사후에 바꾸는 것도 실험값 수정으로 본다.
4. **baseline 구현 출처 명시**: 가능하면 원저자 공개 구현을 그대로 쓴다. 재구현했다면
   재구현임을 명시하고, 파라미터 선택 근거를 남긴다
   (예: DST의 Θ 질량 하한 0.02 vs 0 — 두 조건을 모두 돌려 보고함).
5. **못 돌리는 방법은 표에 넣지 않는다**: 실제로 실행하지 못한 방법은 비교표·수치
   주장에서 제외하고 관련연구 서술로만 다룬다. 추정치를 표에 채우지 않는다.
6. **시나리오 선별 금지**: 유리한 시나리오만 골라 보고하지 않는다. 사전 등록된
   시나리오 집합 전체를 보고하고, 불리한 칸은 굵게 표시해서라도 남긴다.
7. **합성 표기**: 합성 데이터 결과에는 `synthetic: true` 를 결과 파일과 서술 양쪽에
   명시하고, 외적 타당성 한계를 함께 적는다.
8. **baseline 강화도 보고한다**: 우리 아이디어를 baseline에 넣어 baseline이 강해지면
   그 사실도 보고한다 (예: source grouping을 준 `dst_grouped` 가 `dst_flat` 0.000 →
   0.500 으로 회복).

## 우리가 진 사례 — 반드시 유지한다

- **`dropout_decisive` / absence 지표에서 proposed가 졌다.**
  proposed 9.00 vs `dst_flat` 0.00. paired bootstrap
  proposed − dst_flat = +9.00 [+9.00, +9.00] 로 전부 불리한 방향이다.
  이 지표는 우리가 "0이어야 한다"고 주장한 바로 그 지표였다. 원인은 source-group
  지지 계산이 관측 단위라 소실 시 지지가 0이 되는 구현 결함이었고,
  **이 패배가 프레임워크 결함 발견으로 이어졌다.** 패배 기록을 지우면 결함도 사라진다.
- **AR-WBF 신뢰도 계수를 실측으로 뽑았더니 오히려 나빠졌다.**
  비교와 분리된 seed(1000–1007)의 균등 혼합에서 산출한 계수는
  `{det_a1: 0.667, det_a2: 0.667, det_b: 1.0, det_c: 0.667}` 로 거의 균등해져
  변별력이 낮았고, `zadeh` 에서 `ar_wbf_measured` 는 sem_acc 0.000 으로
  uniform(0.667)보다 나빴다. 즉 **계수 산출 프로토콜 자체가 미해결 논쟁거리**다.
  계수를 우리에게 유리하게 다시 뽑지 않는다. 산출 프로토콜은 실행 전에 고정하고
  근거를 남긴다.

## 서술 체크리스트

- [ ] 비교군 전원이 실제로 실행되었고 동일 스트림을 보았다
- [ ] 사전 등록 지표만 사용했다
- [ ] 불리한 결과가 표와 본문에 모두 남아 있다
- [ ] 재구현 여부와 파라미터 근거가 적혀 있다
- [ ] 합성/실측이 구분되어 있고 한계 절이 있다
- [ ] 주장 문장이 실험값 범위를 넘지 않는다 (CI를 넘는 단정 금지)
