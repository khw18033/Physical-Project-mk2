# 1. 기본 방침

**새 폴더 `viz-debugger/` 에서 새로 만든다. 기존 `web-dashboard/` 는 한 줄도 고치지 않는다.**

> **2026-08-27 갱신 — 최종적으로 한 앱으로 합친다.** 다만 **그릇은 `viz-debugger/`** 이고 방향은
> `web-dashboard/` → `viz-debugger/` 다. 반대로 하면 기존 코드를 고치게 되어 아래 원칙이 무너진다.
> **문서에서 탭 이름은 「임무 설계 및 디버깅」으로 적는다.** `viz-debugger/`는 폴더 경로로만 남긴다 — 이미 이식 주석과 커밋 이력이 이 경로를 참조하고 있어 바꾸면 그 연결이 끊긴다.
> 통합은 **3단계 이후**이고, 그 전까지 이 문서의 원칙은 그대로 유효하다. 구조는 요구사항정의서 §3.1.

같은 저장소 안에 두는 이유는 셋이다.

1. `contracts/` 의 계약 파일 5종을 **상대 경로로 그대로 참조**할 수 있다. 저장소를 나누면 계약이
   두 벌이 되고, 어느 쪽이 원본인지 관리해야 한다.
2. 이식한 코드의 출처가 **같은 저장소의 커밋 이력에 남는다.** 원본이 나중에 고쳐졌을 때
   `git log`로 따라갈 수 있다.
3. 기존 검증 스크립트 5종을 새 작업 중에도 계속 돌릴 수 있다. 이게 원본을 건드리지 않았다는 증거다.

# 2. 기술 스택

## 2-1. 선택과 근거

| 층 | 선택 | 근거 |
|---|---|---|
| 화면 | **React 19 + TypeScript + Vite** | 기존 프로토타입과 동일. 이식하는 코드가 전부 이 스택이라 개조 비용이 0에 가깝다 |
| 목 서버 | **Node + `ws`** (기존 `mock-gateway/` 방식) | 백엔드가 아직 없다. 시나리오 재생·결함 주입을 여기서 한다 |
| 계약 | **JSON Schema (draft 2020-12)** | 기존 `contracts/` 와 같은 방식. `additionalProperties: false` 로 계층 경계를 강제한다 |
| 그래프 렌더링 | **직접 구현 (SVG + 절대 배치)** | §2-3 참조 |
| 기록 저장 | **메모리 + JSONL 파일** (1차) → 필요 시 SQLite | §5 참조 |
| 음성 | **`viz-debugger/stt/` 자체 서비스 (Python). 엔진 알맹이는 `stt-lab/` 에서 무수정 이식** | *(2026-08-28 개정)* 운영 경로가 실험 하네스에 런타임 의존하면 임계값 실측이 운영을 흔든다. §3-6 참조 |
| **임무 생성** | **로컬 LLM (별도 프로세스, 인터페이스 뒤에 은닉)** | *(2026-08-27 인수)* 폐쇄망이 전제라 외부 API를 기본 경로로 둘 수 없다. 모델 규모는 연구실 PC 실측 후 확정 |
| 검증 | **Node 스크립트 (`node:test` 없이 단독 실행)** | 기존 `scripts/verify-*.mjs` 와 같은 방식 |

## 2-2. 웹으로 가는 이유

교수님이 "웹으로 할 필요 없다, 본인 기술 스택에 맞춰"라고 하셨다. 그럼에도 웹으로 간다.

1. **이식 자산이 전부 웹이다.** 통신·상태 보관·명령 추적 코드가 TypeScript로 이미 있다.
   다른 스택으로 가면 이걸 전부 다시 짜야 하고, 9월이 이관에 소모된다.
2. **HCI 팀원에게 링크 하나로 전달**할 수 있다. 초안을 전달하는 것이 협업의 출발점이므로
   (구현 문서 §5) 설치가 필요 없다는 점이 실질적인 이득이다.
3. 사용자 실험을 하게 되면 배포 비용이 0이어야 한다.

**단, 이건 성능 주장이 아니라 접근성 선택이다.** 성능 축으로 싸우지 않는다.

## 2-3. 그래프 렌더링을 직접 구현하는 이유

D3, Cytoscape, React Flow 같은 라이브러리를 쓰지 않는다.

- 필요한 것이 **노드 60개 이하의 계층 DAG 한 종류**다. 범용 그래프 라이브러리의 기능 대부분이 남는다.
- **상태 8종 · 재실행 회차 배지 · 실패 경로 접기 · 시간에 따른 재칠하기**가 전부 커스텀이라,
  라이브러리를 써도 결국 렌더링을 직접 제어하게 된다.
- 예상 구현 화면 5종을 그릴 때 이미 SVG 경로 + 절대 배치 방식으로 만들어 봤고, 그 코드가 출발점이 된다.
- 라이브러리 의존이 없으면 논문의 **계측 오버헤드 측정**(논문 문서 §3-4)에서 변인이 하나 줄어든다.

레이아웃은 계층(depth) 기준 열 배치 + 같은 열 안에서 세로 분산으로 시작한다.
노드가 많아져 겹치면 그때 Sugiyama 계열 알고리즘을 붙인다. **미리 만들지 않는다.**

> **2026-09-01 개정** — 깊이당 열 하나를 무조건 오른쪽에 붙이던 배치가 **폭을 재서 밴드로
> 접는 배치**로 바뀌었다. 대본 노드 분화(17/18/16노드) 뒤 「임무 전체」 폭이 3,300~3,550px 로
> 불어나 첫 화면에서 오른쪽 노드가 안 보였기 때문이다. `TaskGraph` 가 `ResizeObserver` 로
> 자리 폭을 재고 `dagLayout(tasks, availableWidth)`·`treeLayout(...)` 이 `MIN_COLS=3` 까지
> 접는다. Sugiyama 는 **여전히 미착수**다 — 겹침은 밴드 높이를 그 밴드의 최대 열로 잡아 막는다.

## 3-4. 건드리지 않는다

`web-dashboard/` 전체 · `unity-twin/` · `stt-lab/` · `contracts/` 의 기존 5종.

`stt-lab` 은 **실험 하네스로 계속 산다.** 엔진·모델·설정 비교와 CER 측정, 누적 기록이 거기 있고,
`VZ-L-03` 신뢰도 임계를 정할 때 여전히 그걸 쓴다. **다만 운영 경로가 그것을 호출하지는 않는다** — §3-6.

## 3-5. 이식할 때의 규칙

1. 복사한 파일 맨 위에 원본 경로와 커밋 해시를 주석으로 남긴다.
   ```
   // 이식: web-dashboard/src/transport/Transport.ts @ 605eb73 — 무수정
   // 이식: web-dashboard/src/data/plans.ts @ 605eb73 — 8상태·DAG로 개조
   ```
2. **원본 파일은 열어서 읽되 저장하지 않는다.**
3. 이식 후 `npm run verify:*` 5종을 돌려 통과를 확인한다. 하나라도 깨지면 원본을 건드린 것이다.

## 3-6. STT 알맹이 이식 *(2026-08-28 신설)*

음성 인식은 **가시화가 맡기로 한 기능**(`VZ-L-01`)이다. 그런데 실제로 도는 코드는
`stt-lab/` 에 있고, 그건 실험 하네스다. 셋 중 하나를 골라야 했다.

| 안 | 문제 |
|---|---|
| stt-lab 서버를 띄워 HTTP로 부른다 | 운영 경로가 실험 하네스에 런타임 의존한다. 임계값을 실측하러 stt-lab을 만지면 가시화가 흔들린다 |
| `sys.path` 로 import 한다 | 복사는 없지만 의존은 그대로다. 같은 문제 |
| **알맹이만 무수정 복사한다** | **채택.** `transport/` 를 이식할 때와 같은 방식 |

**가져오는 것**은 `engines/base.py`·`engines/faster_whisper.py`·`engines/__init__.py` 와
`registry.py` 의 hotwords 부분(`vocabulary`·`hotwords_string`·`load_registry`·`_targets`)뿐이다.
`scoring.py`(CER·WER)·`store.py`(JSONL 누적)·`main.py`(실험용 라우팅 8개)·`web/index.html` 과
시험 발화 프리셋 67건은 **가져오지 않는다.** 전부 실험 하네스의 일이다.

**복사의 유일한 위험은 두 벌이 갈라지는 것**이므로 `verify:stt-port` 로 이식본이 원본과
바이트 동일한지 검사한다(출처 주석 줄만 예외). 누가 복사본을 고치면 검사가 실패하고,
그때 "원본도 같이 고칠 것인가, 갈라놓을 것인가"를 의식적으로 정하게 된다.
조용히 갈라지는 것만 막으면 된다.

**파이썬 프로세스가 하나 늘어나는 것은 감수한다.** faster-whisper 는 CTranslate2 런타임이라
브라우저에서 돌지 않고, 브라우저 내장 음성 인식은 엔진 종속(`REQ-1302` 위반)에
오디오가 클라우드로 나간다(`NFR-010` 위반). `torch` 는 넣지 않는다 — 들어왔다면 엔진을 잘못 잡은 것이다.

작업 절차는 `작업프롬프트_STT이식_260828.md` 에 있다.

# 5. 기록 저장소 설계

## 5-1. 기록 한 줄

| 항목 | 내용 |
|---|---|
| `seq` | 단조 증가 순번. 되감기의 기준축 |
| `ts` | 서버 시각 |
| `layer` | `mission` / `milestone` / `task` / `action_item` |
| `node_id` | 어느 노드인가 |
| `kind` | `created` · `dispatched` · `acked` · `started` · `progress` · `evaluated` · `failed` · `derived` |
| `produced_by` | `ai` / `backend` / `human` |
| `payload` | 종류별 상세 |

**덧붙이기만 한다.** 지우지도 고치지도 않는다. 실패해도 남는다 — 회의록 §4-5의
"죽은 시점의 메모리 상황을 그대로 올려주고 역추적"이 이 성질에서 나온다.

## 5-2. 시점 복원

특정 `seq`까지의 기록을 앞에서부터 접어(fold) 그 시점 상태를 만든다.
매번 처음부터 접으면 느려지므로 **일정 간격마다 스냅샷을 남기고 그 뒤만 접는다.**

기록 1만 건 기준으로 임의 시점 복원이 **16 ms 이내**(60 fps 한 프레임)에 끝나는 것을 목표로 잡는다.
이 수치는 논문 문서 §3-4 계측 오버헤드 측정의 항목이기도 하다.

## 5-3. 저장 매체

1차는 **메모리 + JSONL 파일 덤프**로 간다. 임무 하나가 수천 건 수준이라 이걸로 충분하고,
파일이 사람이 읽을 수 있는 형태라 디버깅이 쉽다.

임무 여러 건을 한 번에 다루거나 시점 질의가 느려지면 그때 SQLite로 옮긴다.
**미리 넣지 않는다** — 스키마가 굳기 전에 DB를 넣으면 스키마 변경 비용만 커진다.

> **2026-08-31 결정 — 지난 임무의 보관 주체는 백엔드다.** 위 메모리+JSONL은 **현재 임무**의
> 실행 기록 열(되감기·실험용)이고, **임무 이력(지난 임무 목록·결과)은 백엔드가 저장하고
> 가시화는 조회해 보여준다**(`VZ-D-04` 연관점 `BE-S-01`·`BE-Q-01` 그대로). 화면의 임무 이력
> 자리는 연결 자리표시(`mission-history`)로 바꿨다. "임무를 만드는 것"은 우리 것,
> "지난 임무를 보관·조회하는 것"은 남의 것 — 그 선으로 갈랐다.

# 6. 계층 경계를 코드로 강제하기

회의에서 합의된 "태스크까지 범용, 액션 아이템부터 대상 의존"은 **합의만으로는 무너진다.**
다음 두 장치로 막는다.

1. `milestone.schema.json` · `task.schema.json` 을 `additionalProperties: false` 로 두고
   하드웨어 어휘를 필드로 갖지 못하게 한다. 기존 `pipeline.schema.json` 이 좌표를 막는 것과 같은 방식이다.
2. 기종 의존 값은 전부 `action-item` 의 `params` 안에만 두고, 해석 규칙은 `adapters/<profile>.json` 에 둔다.

**판정 기준**: 새 하드웨어 프로파일을 추가할 때 `model/` 과 `views/` 의 마일스톤·태스크 관련 파일을
**한 줄도 고치지 않아야 한다.** 이걸 검증 스크립트로 잡는다 (§7의 `verify:adapter-swap`).

이 판정 기준은 그대로 논문의 측정축이 된다 (논문 문서 §3-5).

| `verify:adapter-swap` | 새 어댑터 프로파일 추가 시 상위 계층 파일 변경이 0인가 (§6) |
| `verify:trace-append` | 기록이 덧붙이기만 되는가. 수정·삭제 경로가 없는가 |
| `verify:replay` | 임의 `seq` 복원 결과가 순차 재생 결과와 일치하는가 |
| `verify:isolation` | 실패 경로 격리 집합에 **근본 원인이 반드시 포함**되는가 |
| `verify:human-trace` | 화면에서 나가는 모든 명령이 `produced_by=human` 으로 기록되는가 |
| `verify:generate-split` | 검증 모듈이 생성 모듈의 내부 상태에 의존하지 않는가. 같은 입력에 **검증 결과가 재현되는가** |
| `verify:no-llm` | 로컬 LLM을 끈 상태에서 **생성만 비활성화되고** 실행·관측·디버깅이 계속 도는가 |
| `verify:standalone` | **본류만 뜨는 단독 빌드**가 성립하는가. *(v1.1 — 「다른 탭」이 「뷰 노드 렌더러」로 바뀔 뿐 검사는 그대로다)* 다른 탭 코드를 import 하지 않는가 (논문 측정축 D) |
| `verify:single-egress` | 명령 발행 경로가 **하나뿐인가.** *(v1.1 — 제어 뷰 노드와 실행 노드가)* 탭③과 탭①이 같은 출구를 쓰는가 |
| `verify:stt-port` | 이식한 `stt/engines/*.py` 가 stt-lab 원본과 **바이트 동일한가** (출처 주석 제외) |
| `verify:voice-audit` | `input_modality: 'voice'` 인데 `voice` 감사 필드가 빠진 명령이 **실제로 거부되는가** |
| `verify:no-stt` | STT 서비스가 전부 실패하는 상태에서 화면이 뜨고 **수동 입력이 살아 있는가**. `probe()` 가 실패 사유를 버리지 않는가 *(260901)* |
| `verify:one-gateway` | 목 게이트웨이가 **하나**이고, 그 하나가 탭 전부를 채우는가. 재연결 후 구독·스냅샷이 복원되는가 |
| `verify:placeholder-default` | *(8/31 신설)* 앱을 그냥 띄우면 남의 데이터 자리가 **자리표시**인가. 자리표시마다 무엇·누가·우리 자리·평면 넷이 다 찼는가 |
| `verify:script-library` | *(8/31 신설)* 대본 세 편이 `registry.json` 세계 위에 있는가. `refEdges` 가 실재 태스크를 가리키고 **`deps` 와 겹치지 않는가**. `nodeKind` 가 문법 5종 안인가 |
| `verify:scenario-mode` | *(8/31 신설)* 대본이 자리표시 기본값을 깨뜨리지 않는가. 진입 둘(정지 미리보기·승인 재생)이 `playing` 으로 갈리고, 끄는 경로는 셸 하나이고, 미리보기가 t=0 프레임만 반영하는가 |

마지막 두 개가 중요하다.
`verify:isolation` 은 **격리해서 좁혔는데 정답을 잘라내는 것**을 막고,
`verify:human-trace` 는 **사람의 개입이 기록에서 빠지는 것**을 막는다. 둘 다 도구의 신뢰성 자체가 걸린 항목이다.

STT 관련 세 검사는 모두 **음성 대조군을 포함한다** — 검사를 무력화한 사본이 반드시 실패로
잡히는지까지 확인한다. 검사가 아무것도 못 잡은 채 통과하던 일이 실제로 있었다
(`reports/2026-08-28_1036_통합구현_검토.md` B항).

기존 `verify:*` 5종도 계속 통과해야 한다 (§3-5).

# 8. STT 계층 *(2026-08-28 신설)*

이식 판단은 §3-6에 있다. 여기는 **이식한 뒤 실제로 어떤 모양으로 도는가**를 적는다.

## 8-1. 프로세스가 하나 늘어난다

```
viz-debugger/
├── (Vite 개발 서버 5174)            ← 화면
├── (목 게이트웨이 8790)              ← 임무 기록 스트림
└── stt/  (FastAPI 8801)             ← 여기가 새로 생긴 것
     ├── engines/    stt-lab 무수정 이식
     ├── vocab.py    stt-lab registry.py 중 hotwords 부분만
     └── service.py  새로 씀. 엔드포인트 하나 (POST /stt/transcribe)
```

faster-whisper는 CTranslate2 런타임이라 **브라우저에서 돌지 않는다.** 브라우저 내장
음성 인식(Web Speech API)은 엔진 종속이라 `REQ-1302`에 어긋나고, 구현체가 오디오를
클라우드로 보내므로 `NFR-010` 로컬 처리 원칙과도 충돌한다. 그래서 프로세스가 하나 는다.

**이건 의존성을 늘리는 것이 아니라 가시화가 맡기로 한 기능(`VZ-L-01`)을 실제로 갖는 것이다.**
`stt-lab/`은 앞으로도 실험 하네스로 그대로 산다 — `VZ-L-03` 신뢰도 임계를 실측할 때는
CER 계산과 누적 기록이 있는 그쪽을 쓴다. **실험은 실험 하네스에서, 운영은 가시화 안에서.**

포트는 기존과 겹치지 않게 `8801`을 쓴다 (web-dashboard `5173`·`8787~8788`, viz `5174`,
목 게이트웨이 `8790`, stt-lab `8799`).

## 8-2. 엔드포인트를 하나로 묶어 둔 이유

`stt-lab/server/main.py`에는 라우팅이 8개 있다(`/api/score`·`/api/runs`·`/api/presets`·
CSV·정적 서빙 …). 그건 **모델을 비교하는 하네스에 필요한 면**이지 운영 화면에 있을 것이 아니다.
운영 서비스는 `POST /stt/transcribe` 하나만 갖는다.

헬스 체크 엔드포인트도 두지 않았다. 살아 있는지는 같은 경로에 GET을 던져 확인한다 —
**응답이 오면(405) 프로세스가 살아 있다는 뜻**이고, 네트워크 자체가 실패하면 꺼져 있다는 뜻이다.
면을 하나로 유지하는 쪽이 stt-lab이 8개로 불어난 길을 다시 밟지 않는 데 낫다고 봤다.

## 8-3. 가시화가 STT를 보는 면

```
화면 (views/UtterancePanel.tsx)
  └ src/stt/          ← 여기가 유일한 면이다
      ├ SttClient.ts   transcribe(blob) → SttResult. 이 밖에서 fetch로 STT를 부르지 않는다
      ├ types.ts       서비스 응답 그대로. 수치를 요약하지 않는다
      ├ confidence.ts  임계 판정 한 곳. 잠정값과 "실측 미완" 표시
      └ availability.ts 서비스가 없을 때 무엇이 꺼지고 무엇이 남는가
```

서비스가 워커나 WASM으로 바뀌어도 갈아끼우는 곳이 `src/stt/` 하나가 되게 하기 위한 경계다.
`verify:no-stt`가 "STT를 부르는 `fetch`가 `SttClient.ts` 밖에 있는가"를 함께 검사한다.

`src/stt/`는 셸이나 다른 탭을 import 하지 않는다 — 끌어오면 탭① 단독 빌드가 깨지고
`verify:standalone`이 잡는다.

## 8-4. 신뢰도를 하나의 숫자로 만들지 않는다

Whisper는 명령 수락 여부를 바로 정할 단일 confidence를 주지 않는다.
`avg_logprob`·`no_speech_prob`·평균 단어 확률을 **각각 그대로** 들고 다닌다.
셋을 임의 가중합해 0~1 점수 하나로 뭉개면 판정 코드는 짧아지지만
**임계를 실측할 근거가 사라진다** — 어느 수치가 걸렀는지 알 수 없고, 가중치 자체가
또 하나의 미확정 값이 되기 때문이다.

**임계값은 아직 정하지 않았다.** `confidence.ts`에 들어 있는 값은 잠정이고 화면에도
"잠정 — 실측 미완"이라고 적혀 있다. 판정이 일어나는 지점만 만들어 두고, 값은 실측 후
그 파일 하나만 고치면 되게 뺐다. 근거는 `reports/2026-08-28_1620_STT이식.md`에 있다.

**이 지점에서 계약과 충돌한다.** `contracts/mission.schema.json`의 `utterance.confidence`는
0~1 숫자 하나이고 `additionalProperties: false`라 세 수치를 필드로 더 넣을 수도 없다.
0단계 합의 사항이라 혼자 바꾸지 않았다 — 세 가지 안과 근거는 위 보고서에 있다.

## 8-5. STT가 없어도 화면은 뜬다

서비스가 꺼져 있거나 무응답이면 **그 기능만 비활성화하고 수동 텍스트 입력 경로를 남긴다**
(`VZ-C-02`·`VZ-G-01`). 화면 전체가 죽거나 무한 로딩에 걸리지 않는다.
`npm run dev`도 STT가 안 떠도 나머지를 그대로 띄운다.

이 판단을 화면 컴포넌트 안에 조건문으로 흩어 놓지 않고 `stt/availability.ts`의 순수 함수
하나로 뽑아 둔 이유는, 나중에 누가 조건 하나를 넓히면서 수동 입력까지 같이 잠가도
아무도 모르기 때문이다. `verify:no-stt`가 그 함수를 실제로 불러 검사한다.

## 8-6. 명령 출구는 여전히 하나다

음성으로 발행되는 명령도 `shared/commandEgress.ts`의 `issueCommand()`를 거친다.
**달라지는 것은 경로가 아니라 감사 필드다** (`REQ-1305`).

```ts
audit: {
  input_mode: 'click' | 'voice',            // 무엇으로 입력했나
  decision_source: 'human',                 // 누가 판단했나
  voice?: { transcript, transcript_edited, avg_logprob, no_speech_prob,
            mean_word_prob, engine, model, audio_ref },
}
```

> *2026-08-28 탭 이식에서 어휘가 하나로 합쳐졌다.* STT 이식 때 쓰던 `produced_by`·`input_modality`
> 대신 `input_mode`·`decision_source` 를 쓴다. 두 벌을 남기지 않기 위해서이고,
> 남은 쪽이 `auditFieldMap.ts` 의 어휘인 이유는 **그 파일이 감사 필드 이름을 가두는 자리**이기
> 때문이다. 그 어휘는 "음성으로 말했고 LLM이 해석했다"를 표현하려고 **입력 수단과 판단 주체를
> 두 축으로 나눈 것**이라 한 축짜리 `produced_by` 보다 담는 것이 많다.
> 이름이 확정되면 여전히 그 파일 하나만 고치면 된다.

`transcript`와 `transcript_edited`를 **둘 다** 남긴다. 원문만 남기면 사람이 고친 오인식을
놓치고, 수정본만 남기면 STT 성능을 나중에 평가할 수 없다.

`input_modality: 'voice'`인데 `voice`가 비어 있으면 **발행을 거부한다.** 타입만으로 막지 않고
런타임에서도 막는 이유는, 나중에 다른 사람이 음성 경로를 추가할 때 `as any` 한 번이면
타입 검사는 통과하고 기록만 조용히 비기 때문이다. `verify:voice-audit`가 가드를 실제로 불러
확인하고, **가드를 지운 대조군이 잡히는지**까지 본다.

**기록은 백엔드 audit-writer가 한다.** 브라우저는 감사 필드를 만들어 전달만 하고 직접 쓰지 않는다.

# 10. 확인이 필요한 것

- 폴더 이름 `viz-debugger/` 로 괜찮은가.
- 그래프 렌더링을 직접 구현하는 판단(§2-3) — 라이브러리를 쓰라는 의견이 있으면 지금이 바꿀 시점이다.
- 기록 저장을 파일로 시작하는 판단(§5-3). 처음부터 DB가 필요한 요구가 있는가.
- 백엔드 연결 시점 — 목으로 어디까지 갈 것인가.
- 새 계약 스키마 6종을 `contracts/` 에 함께 두는 것이 맞는가, `viz-debugger/contracts/` 로 분리할 것인가.
- **로컬 LLM 모델 규모와 실행 위치** — 연구실 PC 실측이 필요하다. 생성 품질이 부족하면
  규칙 기반 생성으로 내려갈 수 있게 인터페이스를 같은 형태로 둔다.
- **`utterance.confidence` 계약** — 0~1 숫자 하나인데 Whisper는 그런 값을 주지 않는다.
  `additionalProperties: false` 라 세 수치를 필드로 더 넣을 수도 없다. 0단계 합의 사항이라
  혼자 바꾸지 않았다. 세 가지 안과 근거는 `reports/2026-08-28_1620_STT이식.md` §계약 충돌에 있다.
- **`VZ-L-03` 신뢰도 임계값** — 지금 들어 있는 값은 잠정이다. 정답·오답·무음·소음을 반복 측정해
  정답 오거부율과 오답 통과율을 비교해야 확정된다. 첫 실측값이 위 보고서에 있다.
- **두 상태 모델의 공존 방식**(3단계 통합 시) — 기존 5개 탭은 `store.ts`의 채널별 최신값 기반이고
  탭①은 기록 열 기반이다. 탭마다 다른 store를 두되 **transport는 하나를 공유**하는 형태가 되는데,
  그러면 구독 관리가 겹친다. 이식 착수 전에 설계를 확정해야 한다.
