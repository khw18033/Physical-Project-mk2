# 1. 🔴 여전히 가장 중요 — `AI-D-03`의 뜻이 바뀌었다

| | 8/21 | 지금 |
|---|---|---|
| 소분류 | 관리자 **명령 의도 해석** | **의사결정 보조 정보 요청** |
| 내용 | 음성·텍스트 명령에서 의도 추출 | 근거 부족 시 등록된 provider에서 필요한 정보만 요청 |

**전혀 다른 요구사항입니다.** 내 연관점 5곳이 이 ID를 가리킵니다 — `VZ-L-01` · `VZ-L-02` · `VZ-L-03` · `VZ-L-04` · `VZ-O-03`.

ID 정합 검사로는 **깨진 참조 0건**으로 나옵니다. `AI-D-03`이 존재하니까요. **끊어지면 알 수 있지만 뜻만 조용히 바뀌면 알 수 없습니다.** ID 체계 고정 안건의 근거가 이제 가설이 아니라 사례입니다.

## 정정 — `AI-C-09`가 통로인 것은 맞다

> 앞선 판에서 *"의도 해석이 사라졌다"* 고 썼는데 그건 과했습니다.

`AI-C-09`(생성형 AI 통합 실행 인터페이스)의 필수 입력에 **`task_type` · `input text refs` · `expected_output_schema`** 가 있습니다. 의도 해석은 여기에 이렇게 태우면 구조적으로 맞습니다.

```
task_type = intent_parse
input     = 가시화가 넘긴 전사 텍스트
output    = { action, target, params }
```

**다만 `AI-C-09`는 어댑터이지 기능이 아닙니다.** "생성형 AI를 어떻게 호출하는가"까지고, 세 가지가 비어 있습니다.

| 빈 것 | 왜 문제인가 |
|---|---|
| **요청하는 주체** | `task_type=intent_parse`로 호출하는 행이 없다. `AI-D-01`은 명시적으로 LLM 비의존, `AI-D-03`은 정보 요청, `AI-S-05`는 추가 정보 선택 |
| **출력 스키마의 내용** | 스키마를 넘기라고만 하고 그 스키마가 무엇인지는 어디에도 없다. 내 `VZ-L-02`가 그걸 그린다 |
| **부재 시 정책** | *"규칙 기반 또는 기존 비-GenAI 경로가 정의돼 있으면"* — 음성 명령의 비-GenAI 경로가 정의돼 있지 않다 |

`AI-C-09`의 **담당이 「하드웨어, 백엔드」** 로 적혀 있는 것도 같은 맥락입니다. Lemonade Server를 붙이는 인프라 작업으로 보고 있다는 뜻이고, **의도 해석이라는 기능 자체는 여전히 주인이 없습니다.**

### 그리고 음성 명령이 선택 기능이 된다

`AI-C-09`는 명시적으로 **선택 기능**입니다. 의도 해석을 여기 태우면 배치에 따라 음성 명령이 통째로 없는 시스템이 됩니다.

이건 나쁘지 않습니다 — 내 `VZ-C-02`("LLM 미연결 시 관련 기능만 비활성화")와 방향이 같습니다. 문제는 **provider가 없을 때 화면이 무엇을 해야 하는지**입니다. 버튼을 숨기나, "지금은 음성을 쓸 수 없습니다"를 띄우나. 알려면 capability 상태가 나까지 와야 하는데 그 경로가 없습니다(→ 3장).

> **나영에게 물을 것 (질문이 구체화됨)**
> 1. 의도 해석을 `AI-C-09`에 `task_type`으로 태우는 게 맞나? 맞다면 그렇게 적힌 행이 하나 필요하다
> 2. 출력 스키마는 누가 정하나?
> 3. GenAI provider가 없을 때 음성 명령은 어떻게 되나? 비-GenAI 경로가 있나
> 4. 그 DISABLED 상태가 가시화까지 전달되나?

# 2. 🆕 이번에 새로 바뀐 것 — 조병현 시트

오늘 오전에는 소분류 2건만 바뀐 줄 알았는데, **30행 전부 '이유'가 재작성**됐습니다. 대부분 서술 정비지만 **실질 변경이 4건** 있습니다.

## 2-1. `HW-C-07` — MAC이 영구 식별자에서 내려왔다

| | 전 | 후 |
|---|---|---|
| 소분류 | MAC 주소 기반 장치 식별 | **고유 `device_id` 기반** 장치 식별 |
| 핵심 | MAC을 장치 식별 정보로 제공 | *"MAC 주소는 현재 네트워크 인터페이스 정보로 활용하되 **장치의 영구 식별자로 단독 사용하지 않는다**"* |

**내 `T3` 다이어그램의 전제가 바뀌었습니다.** 제목이 「MAC 기반 연결 변경」인데 이제 정체성은 `device_id`입니다.

다만 방향은 오히려 맞았습니다 — T3에서 제가 *"IP는 도달성일 뿐 정체성은 논리 식별자로 유지"* 라고 적어둔 것이 이제 **계약으로 뒷받침**됩니다. 제목과 메커니즘만 `device_id`로 고치면 됩니다.

> ⚠️ **라벨 드리프트** — `BE-T-05`의 연관점이 아직 *"HW-C-07(**MAC 매핑**)"* 이라고 부릅니다. 하드웨어가 이름을 바꿨는데 백엔드 참조가 옛 이름입니다.

## 2-2. `HW-R-04` — 온디바이스 인지의 급이 내려갔다

> 로봇 온보드는 **Raspberry Pi와 카메라뿐**이므로 metric distance 센서를 전제하지 않는다. 객체 의미 분류 하나에 안전 기능을 의존시키지 않고, **진행영역과 접근 변화** 등으로 최소 안전 기능을 구성한다. **정밀 객체 분류·추적 결과는 AI**(엣지)에서 온다.

내 `VZ-I-07`(탐지 오버레이 정합)·`VZ-I-09`(추적·궤적)가 **어느 쪽 결과를 그리는지 구분**해야 합니다. 온디바이스는 거칠고, 정밀한 것은 엣지 AI입니다. 두 출처가 같은 화면에 섞이면 신뢰도 표시가 무의미해집니다.

## 2-3. 주기 두 건 — 내 근거에는 영향 없음

| ID | 전 | 후 | 내 영향 |
|---|---|---|---|
| `HW-R-01` | 0.1초 1회 | **20ms (50Hz)** | 로봇 **내부(온보드)** 전달 주기. 내 근거인 `HW-R-02`·`R-03`(임무 중 50ms 발행)은 그대로 |
| `HW-S-08` | NTP 1시간 1회 | **NTP 상시 활성화** | 시각 동기가 더 촘촘해짐. `VZ-O-03`의 "장치는 NTP로 맞추지만 뷰어 단말은 보장 없다" 논리가 더 강해짐 |

**확인 결과 내 주기 산정은 하나도 다시 계산할 필요가 없습니다.**

# 3. 🆕 진나영 +5행 — 미디어 경로가 별도 평면으로 선언됐다

오늘 오전 44행에서 **49행**이 됐습니다. 신설 5건 중 둘이 나와 직접 관련됩니다.

## 3-1. `AI-C-14` 데이터 유형별 경로 분리 — **평면이 셋이 됐다**

> 업무 데이터 · 제어 명령 · 시스템 관측 데이터 · **미디어**로 구분하고 각 유형에 맞는 경로로 보낸다.
> 말단↔엣지는 MQTT, 엣지↔서버는 Kafka, metric·log·trace는 OpenTelemetry, **영상 픽셀은 별도 미디어 경로**.
> **관측 지표를 업무 경로로 보내거나 영상 픽셀을 메시지 브로커에 직접 싣지 않는다.**

**내 문서 전부가 "2평면(업무·관측)"으로 설명하고 있습니다.** 데이터 흐름 구조도, 쉬운설명, 프로토타입 설명서 모두요. 이제 **미디어가 세 번째 평면**입니다. 갱신 대상입니다.

그리고 **영상 변환 지점 논의가 또 한 걸음 나갔습니다.**

| 시점 | 상태 |
|---|---|
| 8/21 | 카메라 원본을 뷰어 형식으로 바꿀 **주체가 세 파트 통틀어 없음** |
| 오늘 오전 | `AI-C-08` GStreamer 어댑터 등장 — 단 경로가 **AI 모듈까지** |
| **지금** | `AI-C-14`로 **미디어 경로가 별도 평면으로 명명됨** |

이제 질문이 이렇게 좁혀집니다 — **"미디어 경로에 뷰어용 출력 분기를 다느냐, 그 어댑터는 누구 것이냐."** 8/21의 "아무도 없다"에서 두 단계 구체화됐습니다.

## 3-2. `AI-E-04` 선택형 보조 인지 — 내가 쓰는 것들이 선택 기능이다

> **고정밀 객체 인지, 단안 깊이, 미확인 객체 분석, 생성형 비전 분석은 모두 선택 기능**이며, 특정 모델·GPU·서버가 없다는 이유로 기본 인지가 중단되어서는 안 된다.

`VZ-I-09`(추적·궤적)와 `VZ-U-06`(미확인 탐지 그룹 확인)이 **선택 기능에 의존**하게 됐습니다. 배치에 따라 아예 없을 수 있다는 뜻입니다. → capability 상태 표시 필요성이 더 강해졌습니다(4장).

## 3-3. 나머지 3건 — 직접 영향 적음

# 4. ⚠️ 계속 유효 — 「이 배치엔 그 기능이 없다」 축

AI 시트가 **capability registry(`AI-C-10`) + 필수/선택 분리(`AI-C-11`) + `DISABLE/DEGRADE/FALLBACK`** 구조입니다. 이번 신설분(`AI-E-04`·`AI-C-13`)이 그 방향을 더 굳혔습니다.

내 상태 표시는 **정상 / 장애 / 미배포 / 판단 불가** 넷인데, 담을 자리가 없는 것이 둘입니다.

| 새 상태 | 뜻 |
|---|---|
| `DISABLED` | 이 배치에는 그 기능이 **아예 없다** |
| `DEGRADED` | **성능 저하 모드**로 돌고 있다 |

**장애와 미설치를 섞으면 관제사가 고칠 수 없는 것을 고치려 듭니다.** `VZ-C-02`는 "내가 연결 못 함"이고 이건 "상대가 선언한 능력 상태"라 축이 다릅니다.

여전히 **신설 후보이지 확정이 아닙니다** — capability 상태가 가시화까지 오는 경로가 없으면 `VZ-C-06`처럼 읽을 값 없는 요구사항이 됩니다.
