# 작업 지시: STT 이식 — 껍데기에 알맹이를 넣는다

**선행**: 0·1단계 완료 · 통합 셸과 공유 계층 (`작업프롬프트_통합_260827.md`)
**대상 요구사항**: `VZ-L-01` · `VZ-L-03` · `REQ-1301`~`1306` · `REQ-305`
**부품 출처**: `stt-lab/` (2026-08-25 구축, `reports/2026-08-25_1506_stt-model-comparison-lab.md`)
**대상 문서**: `구현진행_가시화도구_260826.md` §3-0 · `기술스택_가시화도구_260826.md`

---

## 배경

1단계에서 만든 마일스톤 화면의 발화 패널은 **전부 껍데기**다. 지금 코드에 있는 것은 이렇다.

```tsx
<div className="waveform">▂▅▃▆▂▇▅▃▆▂▅▇▃▆</div>          // 고정 문자열
<blockquote>"{scenario.utterance.text}"</blockquote>      // 시나리오 JSON의 목 문장
{['음성 수신','STT 변환','의도 분석','마일스톤 분리','태스크 생성']
  .map(label => <span>✓ {label}</span>)}                  // 다섯 칸 전부 ✓ 하드코딩
```

**이번 작업은 이 껍데기 안에 실제로 동작하는 STT를 넣는 것이다.**
파형은 진짜 입력 레벨이 되고, 인용문은 진짜 인식 결과가 되고, 진행 막대의 앞 두 칸은
진짜 상태를 따라 움직인다.

**뒤 세 칸(`의도 분석`·`마일스톤 분리`·`태스크 생성`)은 이번 범위가 아니다.**
`VZ-G-01`·`VZ-G-02`이고 로컬 LLM이 필요하다. 한 번에 다섯 칸을 다 하면
"인식이 나쁜 건지 해석이 나쁜 건지"를 가를 수 없다. 뒤 세 칸은 **목 표시를 붙인 채 남긴다.**

---

## stt-lab은 부품 창고다. 띄우는 사이트가 아니다.

`stt-lab/`은 엔진·모델·설정을 같은 오디오로 비교하는 **실험 하네스**다. 자기 화면과
자기 API(`/api/score`, `/api/runs`, 프리셋 67건, CSV)를 가지고 있고, 그건 실험용이지
운영 화면에 있을 것이 아니다. **그 사이트를 띄워서 가시화가 부르는 구조로 만들지 않는다.**

가져오는 것은 **알맹이뿐**이다.

| stt-lab 파일 | 이번에 | 이유 |
|---|---|---|
| `server/engines/base.py` | **무수정 이식** | `REQ-1302` 엔진 추상화가 이미 이 파일에 다 있다 |
| `server/engines/faster_whisper.py` | **무수정 이식** | CUDA→CPU 자동 폴백, 모델 캐시, 로드 시간 분리. 손이 많이 간 코드다 |
| `server/engines/__init__.py` | 무수정 이식 | 엔진 등록 |
| `server/registry.py` 중 `vocabulary()`·`hotwords_string()`·`load_registry()`·`_targets()` | **이식** | `REQ-305` 호칭 사전. registry.json 원본은 복사하지 않고 경로로 참조한다 |
| `server/registry.py` 중 `utterance_presets()` (시험 발화 67건) | **가져오지 않음** | 실험용 정답 세트 |
| `server/scoring.py` (CER·WER) | **가져오지 않음** | 정확도 측정은 실험 하네스의 일이다 |
| `server/store.py` (JSONL 누적·CSV) | **가져오지 않음** | 실험 기록 적재 |
| `server/main.py` | **가져오지 않음** | 실험용 라우팅 8개. 새로 쓴다 (엔드포인트 하나) |
| `web/index.html` | **방식만 참고** | `MediaRecorder` 사용법. 코드를 복사하지 않는다 |

### 왜 복사인가 — 참조도 아니고 실행도 아니고

세 가지 길이 있었다.

1. **stt-lab 서버를 띄워 HTTP로 부른다** → 운영 경로가 실험 하네스에 런타임 의존한다.
   임계값 실측하러 stt-lab을 만지는 순간 가시화가 흔들린다. **채택하지 않는다.**
2. **`sys.path`로 stt-lab을 import한다** → 복사는 없지만 의존은 그대로다. 같은 문제.
3. **알맹이만 무수정 복사한다** → 채택. 0단계에서 `transport/`를 이식할 때 쓴 방식과 같다.

**복사의 유일한 위험은 두 벌이 갈라지는 것이다.** 그래서 이번에 `verify:stt-port`를 만든다.
이식한 파일이 stt-lab 원본과 **바이트 단위로 같은지** 검사한다. 누가 복사본을 고치면
검사가 실패하고, 그때 "원본도 같이 고칠 것인가, 갈라놓을 것인가"를 의식적으로 정하게 된다.
조용히 갈라지는 것만 막으면 된다.

**stt-lab은 앞으로도 그대로 산다.** `VZ-L-03` 신뢰도 임계를 실측할 때 여전히 그걸 쓴다.
CER 계산과 누적 기록이 거기 있기 때문이다. 실험은 실험 하네스에서, 운영은 가시화 안에서.

### 왜 파이썬 프로세스가 하나 더 필요한가

faster-whisper는 CTranslate2 런타임이라 브라우저에서 돌지 않는다. 브라우저 내장
음성 인식(Web Speech API)은 **엔진 종속이라 `REQ-1302`에 어긋나고**, 구현체가 오디오를
클라우드로 보내므로 **`NFR-010` 로컬 처리 원칙과 충돌**한다.

그래서 `viz-debugger/`가 **자기 STT 서비스를 갖는다.** 목 게이트웨이 옆에 서는 프로세스다.
이건 의존성을 늘리는 것이 아니라 **가시화가 맡기로 한 기능(`VZ-L-01`)을 실제로 갖는 것**이다.

## 먼저 읽을 것

1. **`stt-lab/server/engines/base.py`의 파일 머리 주석.** 엔진 추상화가 무엇을 약속하는지.
   특히 `applied_options` — "요청했지만 안 먹은 옵션"이 응답에 드러나야 한다는 규칙.
2. `stt-lab/server/main.py`의 `api_transcribe` — **무엇을 새 서비스에 남기고 무엇을 버릴지** 가리는 기준.
   hotwords를 화면에서 받지 않고 매번 원본에서 새로 뽑는 주석은 반드시 지킨다.
3. `reports/2026-08-25_1506_stt-model-comparison-lab.md` §주요 판단 — 특히
   **"신뢰도 임계값은 아직 정하지 않았다"**. 이번 작업이 그 결론 위에 선다.
4. `contracts/mission.schema.json`의 `utterance` — **아래 5단계의 충돌 지점이다. 먼저 본다.**
5. `viz-debugger/src/shared/commandEgress.ts` — 명령 출구가 하나라는 제약과 감사 필드.
6. `viz-debugger/scripts/dev-all.mjs` — 프로세스를 어떻게 함께 띄우는지.

## 제약 — 반드시 지킬 것

1. **`stt-lab/`을 한 줄도 고치지 않는다.** 부족한 것이 있으면 고치지 말고 보고한다.
2. **이식본도 고치지 않는다.** `engines/`는 무수정 복사다. 고쳐야 할 이유가 생기면
   코드를 쓰기 전에 보고한다. `verify:stt-port`가 이걸 강제한다.
3. **`web-dashboard/`도 한 줄도 고치지 않는다.** 기존 검증 7종이 계속 통과해야 한다.
   `registry.json`은 **읽기만** 한다(복사하지 않는다 — 0단계에서 `contracts/`를 참조만 한 것과 같은 이유).
4. **명령 출구는 여전히 하나다.** 음성으로 발행되는 명령도 `shared/commandEgress.ts`의
   `issueCommand()`를 거친다. 달라지는 것은 **경로가 아니라 감사 필드**다.
5. **STT 서비스가 없어도 화면이 뜬다.** 꺼져 있거나 무응답이면 **그 기능만 비활성화하고
   수동 텍스트 입력 경로를 남긴다**(`VZ-C-02`, `VZ-G-01` 명시). 화면 전체가 죽거나
   무한 로딩에 걸리면 안 된다. `verify:no-stt`로 검사한다.
6. **임계값을 지금 정하지 않는다.** `VZ-L-03`의 신뢰도 임계는 실측 후 확정(Tier 2)이다.
   **판정이 일어나는 지점을 만들고 값은 설정 한 곳으로 뺀다.** 지금 넣는 값은 잠정값이며
   화면과 코드에 **"잠정 — 실측 미완"**이라고 적는다.
7. **하나의 confidence를 지어내지 않는다.** Whisper는 단일 신뢰도를 주지 않는다.
   `avg_logprob`·`no_speech_prob`·단어 확률을 **각각 그대로** 들고 다닌다.
   셋을 임의 가중합해 0~1 점수 하나로 뭉개면 임계를 실측할 근거가 사라진다. (5단계 참조)
8. **감사 필드를 빠뜨리지 않는다**(`REQ-1305`). **기록은 백엔드 audit-writer가 한다.**
   브라우저는 전달만 하고 직접 쓰지 않는다.
9. **JS 의존성을 늘리지 않는다.** 녹음은 브라우저 표준 `MediaRecorder`,
   레벨 미터는 `AnalyserNode`면 된다. 오디오 라이브러리·음성 인식 SDK를 넣지 않는다.
   파이썬 쪽도 `stt-lab/requirements.txt`에서 실험용을 뺀 것 이상을 넣지 않는다
   (**`torch`가 들어왔다면 엔진을 잘못 잡은 것이다**).
10. **목임을 감추지 않는다.** 진행 막대 뒤 세 칸에 아직 목이라는 표시가 남아야 한다.

## 단계

### 1단계 — STT 서비스 (화면보다 먼저)

`viz-debugger/stt/` 에 만든다.

```
viz-debugger/stt/
├── engines/              # stt-lab에서 무수정 이식
│   ├── __init__.py
│   ├── base.py
│   └── faster_whisper.py
├── vocab.py              # stt-lab/server/registry.py 중 hotwords 부분만
├── service.py            # 새로 쓴다. 엔드포인트 하나
├── requirements.txt
└── README.md
```

이식한 파일 맨 위에 출처를 남긴다. 예외 없다.

```python
# 이식: stt-lab/server/engines/faster_whisper.py @ <커밋> — 무수정
# 원본을 고치지 말 것. verify:stt-port 가 바이트 동일성을 검사한다.
```

`service.py`가 갖는 것은 **엔드포인트 하나**다.

| | |
|---|---|
| `POST /stt/transcribe` | 오디오 한 건 → 텍스트 + 원본 수치 + `audio_ref` |
| 응답 | `text` · `segments` · `words` · `avg_logprob` · `no_speech_prob` · `mean_word_prob` · `engine` · `model` · `device` · `compute_type` · `elapsed_sec` · `load_sec` · `applied_options` · `audio_ref` |

- **hotwords는 요청에서 받지 않는다.** 플래그만 받고 어휘는 `vocab.py`가 registry.json에서
  매번 새로 뽑는다. 화면이 보낸 문자열을 믿으면 레지스트리가 바뀌었을 때 조용히 옛 어휘로 인식한다.
- **오디오를 보관한다.** `contracts/mission.schema.json`의 `utterance.audio_ref`가 요구한다.
  `stt/recordings/` 아래에 두고 `.gitignore`에 넣는다. 어디에 무엇을 남기는지 README에 적는다.
- 포트는 기존과 겹치지 않게 잡는다 (web-dashboard 5173·8787~8788, viz 5174, stt-lab 8799).
- `dev-all.mjs`에 붙이되 **STT 서비스가 안 떠도 나머지는 뜬다.** 제약 5다.

**판정 기준**: 화면 없이 `curl`로 `stt-lab/samples/`의 webm 한 건을 보내
텍스트와 세 수치와 `audio_ref`가 돌아온다.

### 2단계 — 어댑터 경계

`viz-debugger/src/stt/` 에 만든다. **가시화 코드가 STT를 보는 유일한 면이다.**

| 파일 | 역할 |
|---|---|
| `SttClient.ts` | `transcribe(blob) → SttResult` 하나. **여기 밖에서 `fetch`로 STT를 부르지 않는다** |
| `types.ts` | `SttResult` — 서비스 응답을 그대로 담는다. 수치를 요약하지 않는다 |
| `confidence.ts` | 임계 판정 한 곳. 잠정값과 "실측 미완" 주석 |

**`verify:standalone`이 계속 통과해야 한다.** `src/stt/`가 셸이나 다른 탭을 끌어오면 단독 빌드가 깨진다.

### 3단계 — 껍데기를 실제로 (`VZ-L-01`)

발화 패널의 세 껍데기를 하나씩 갈아끼운다.

| 지금 | 이번에 |
|---|---|
| `▂▅▃▆…` 고정 문자열 | 녹음 중 **실제 입력 레벨** (`AnalyserNode` 하나) |
| 시나리오 JSON의 목 문장 | **인식 결과**. 사용자가 고칠 수 있다 |
| 다섯 칸 전부 `✓` | 앞 두 칸이 **실제 상태**를 따라간다. 실패하면 그 칸에서 멈추고 이유를 보여준다 |

- 녹음 버튼: `MediaRecorder` + `audio/webm;codecs=opus`. 지원하지 않으면 파일 업로드로 떨어진다.
- **인식된 문장을 표시하고 고칠 수 있게 한다** — 이것이 1차 확인(`REQ-1303`)이다.
  고친 문장이 다음 단계의 입력이 되며, **원문과 수정본을 둘 다 보관한다.**
  (원문만 남기면 오인식을 놓치고, 수정본만 남기면 STT 성능을 평가할 수 없다.)
- `엔진`·`신뢰도` 표시를 실제 값으로 바꾼다. 세 수치는 **접어서** 둔다 — 평소엔 감추고 펴면 원본이 보인다.

**판정 기준**: 마이크로 "503 구역 로봇을 5층 복도로 이동시켜"를 말하면 그 문장이 뜨고,
고칠 수 있고, 뒤 세 칸은 목 표시가 붙은 채 남아 있다.

### 4단계 — 레지스트리 어휘 (`REQ-305`)

- 화면에 **hotwords가 몇 개 적용됐는지** 표시한다(응답의 `applied_options`에서 읽는다).
- hotwords 켬/끔 토글을 둔다. `VZ-L-03` 임계 실측 때 대조군이 필요하다.

### 5단계 — 신뢰도, 그리고 계약 충돌 하나

`confidence.ts`에 판정 함수 하나. 입력은 세 수치, 출력은 `accept | confirm | reject`.
잠정 기준을 넣되 **숫자마다 근거를 주석으로 적는다.** 근거가 "감"이면 그렇게 적는다.
임계 미만이면 다음 단계로 넘기지 않고 재확인을 요구한다. 조용히 통과시키지 않는다.

**여기서 계약과 부딪친다. 반드시 확인하고 넘어간다.**

0단계에서 만든 `contracts/mission.schema.json`은 이렇게 되어 있다.

```json
"utterance": {
  "additionalProperties": false,
  "required": ["audio_ref", "text", "engine", "confidence"],
  "properties": { "confidence": { "type": "number", "minimum": 0, "maximum": 1 } }
}
```

**`confidence`가 0~1 숫자 하나인데, Whisper는 그런 값을 주지 않는다.**
게다가 `additionalProperties: false`라 세 수치를 필드로 더 넣을 수도 없다.

**임의로 가중합해서 채우지 말 것.** 그 순간 제약 7이 깨지고 임계 실측의 근거가 사라진다.
할 일은 셋 중 하나이며, **고르지 말고 보고서에 적고 멈춘다** — 계약은 0단계 합의 사항이다.

1. `confidence`를 표시용 파생값으로 두고 세 수치는 `trace-event`의 `payload`에 싣는다
2. `utterance`를 열어 세 수치를 명시 필드로 추가한다 (스키마 개정)
3. `confidence`를 엔진 비종속 의미로 재정의한다 (예: 평균 단어 확률)

`2단계`(스키마 개정)가 가장 정직해 보이지만, `additionalProperties: false`를 넣은 이유가
계층 경계를 막기 위해서였으므로 **여는 데는 근거가 필요하다.**

### 6단계 — 감사 필드 (`REQ-1305`)

`commandEgress.ts`의 `audit`을 넓힌다. **출구는 그대로 하나다.**

```ts
audit: {
  produced_by: 'human',
  input_modality: 'pointer' | 'voice',
  voice?: { transcript, transcript_edited, avg_logprob, no_speech_prob,
            mean_word_prob, engine, model, audio_ref },
}
```

`input_modality: 'voice'`인데 `voice`가 비어 있으면 **발행을 거부한다.**
타입만으로 막지 말고 런타임에서도 막는다 — 나중에 다른 사람이 음성 경로를 추가할 때
조용히 빠지는 곳이다.

### 7단계 — 검증 스크립트 세 개

기존 두 개와 같은 방식으로 만든다. **음성 대조군을 반드시 넣는다** — 검사가 무력화되면
조용히 통과하는 대신 스스로 실패해야 한다. (`verify:standalone`이 경로 구분자 때문에
아무것도 잡지 못한 채 통과하던 일이 실제로 있었다. `reports/2026-08-28_1036_통합구현_검토.md` B항)

- **`verify:stt-port`** — 이식한 `engines/*.py`가 stt-lab 원본과 바이트 동일한지.
  출처 주석 줄만 예외로 둔다. **한 글자 바꾼 대조군이 실패로 잡히는지**까지 확인한다.
- **`verify:voice-audit`** — `input_modality: 'voice'` 경로가 `voice` 필드 없이 발행되면
  실패로 잡히는지. 필드를 뺀 대조군 포함.
- **`verify:no-stt`** — `SttClient`가 전부 실패를 던지는 상태에서 화면이 뜨고
  수동 텍스트 입력 경로가 살아 있는지.

기존 `verify:single-egress`·`verify:standalone`·나머지도 계속 통과해야 한다.

## 완료 판정

1. 마이크로 말하면 **실제 텍스트가 뜬다.** 파형도 진짜다.
2. 인식 문장을 고칠 수 있고, **원문과 수정본이 둘 다 남는다.**
3. `avg_logprob`·`no_speech_prob`·평균 단어 확률 셋이 **각각** 확인된다. 하나로 뭉개지지 않았다.
4. 임계 미만이면 재확인을 요구하고 다음으로 넘어가지 않는다.
5. **STT 서비스를 끈 채로도 화면이 뜨고 수동 입력이 된다** (`verify:no-stt` 통과).
6. 음성 명령이 `issueCommand()` 한 곳으로 나가고 `voice` 감사 필드가 실린다
   (`verify:single-egress` · `verify:voice-audit` 통과).
7. 이식본이 stt-lab 원본과 같다 (`verify:stt-port` 통과).
8. 진행 막대 뒤 세 칸에 **아직 목이라는 표시**가 남아 있다.
9. `stt-lab/`·`web-dashboard/`에 diff가 없다.
10. `pip list`에 `torch`가 없다.
