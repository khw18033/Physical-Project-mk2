## 왜 하나

사용자가 화면을 보고 지적한 네 가지는 **사실 한 문제다.**

지금 모드가 **세 군데에 흩어져 있다.** 목 렌더는 우상단 토글, 대본 진입은 승인 시 자동,
대본 이탈은 배너 안의 「대본 닫기」. 그래서 —

- 지금 무엇을 보고 있는지 화면만으로 알 수 없고 → 그걸 **글로 설명**하느라 문단이 늘었다 (지적 1)
- 모드를 바꿔도 탭②~⑤가 안 변해서 → 「연결 예정」만 남는다 (지적 2)
- 탭①은 마일스톤당 노드가 하나라 → 모드를 바꿔도 **볼 것이 없다** (지적 3)
- 모드를 확인하고 바꿀 자리가 없다 (지적 4)

**착수 순서는 4 → 2 → 3 → 1이다.** 스위치를 먼저 만들어야 나머지 셋을 화면에서 바로 확인할 수 있다.

## 요구 4 — 우상단 모드 표시·전환 (먼저 한다)

`src/shared/renderMode.ts`의 상태는 **이미 3종**(`placeholder`/`mock`/`scenario`)이다.
모자란 것은 상태가 아니라 **조작 지점 하나**다.

### 만들 것 — `src/shell/ModeSwitch.tsx` (신설), `AppShell` 우상단에 배치

```
모드  [ 일반 ]  [ 시나리오 ▾ ]  [ 목·개발 ]
```

| 칸 | 누르면 | 표시 |
|---|---|---|
| 일반 | `exitScenarioRender()` + `setRenderMode('placeholder')` + 게이트웨이에 `script_close` | 기본값 |
| 시나리오 ▾ | 대본 3편 드롭다운. 고르면 **정지 미리보기**로 진입 (아래) | `시나리오 · 260831-01 정지` / `재생 중` |
| 목·개발 | `setRenderMode('mock')` | 붉은 배지 유지 (끄는 경로 만들지 않는다) |

### 승인 선을 우회하지 않는다 — 이게 이 항목의 핵심 제약

스위치에서 대본을 고르면 **「그린다」까지**다. **재생은 여전히 승인(`VZ-U-07`) 뒤다.**

- 화면: `previewMission(missionId)` 를 새로 만든다 (`src/data/scenario.ts`). 현재 임무를 그 대본으로
  올리되 `headSec: 0` · `playing: false` · `activatedBy: 'preview'`. 사건이 하나도 없으므로 탭①은
  전부 `pending`으로 그린다 — 기존 `displayMission()`의 제안 상태와 같은 성질이다.
- 게이트웨이: `ScriptEngine`에 **`script_preview`** 액션을 새로 만든다. 대본의 **`worldTimeline` 중
  `atSec === 0` 프레임만** 한 번 반영하고 끝낸다. `trace_event`도 `commands`도 내보내지 않고 타이머도 세우지 않는다.
- `renderMode.ts`의 `ScenarioRender`에 **`playing: boolean`** 을 더한다. 정지 화면을 「재생 중」이라고
  적으면 안 된다. `DEFAULT_MODE`는 **건드리지 않는다** (`verify:placeholder-default`).

배너 3종(목·대본·구판)은 세그먼트가 상태를 말해 주므로 **한 줄로 줄인다.** 목 배너의 경고 문구만 남긴다.

## 요구 2 — 탭②~⑤ 시나리오 연계

### 왜 지금 「연결 예정」만 나오는가 — 코드에서 확인한 원인 넷

1. **`entity` 없는 자리는 scenario 분기 자체가 없다.** `PendingSource`는 `entity === undefined`면
   무조건 자리표시로 떨어진다. 해당: `zone-summary` · `risk-state` · `audit-history` · `registry` ·
   `role-scope` · `mission-history` · `hardware-pool-status` · `device-cards`(전체 자리).
2. **탭④는 구조적으로 못 그린다.** `MetricsView.tsx`의 `METRIC_ENTITY = 'edge-node-a'`인데
   **세 대본 cast 어디에도 `edge-node-a`가 없다.** 기본 선택 지표도 `cpu_pct`(원천 `edge-node-a`)라
   시나리오로 들어가도 **탭④ 첫 화면이 자리표시**다.
3. **탭③은 대상이 고정이다.** `ControlPanel.tsx`의 `TARGETS = ['actuator-01','actuator-02']` —
   1편·2편에는 그 장비가 없다.
4. **셋째 상태가 없다.** 지금 화면 상태는 「연결 예정(못 받았다)」와 「값 있음」 둘뿐이다.

### 만들 것 A — 「임시 데이터」의 정체를 대본 t=0 스냅샷으로 못 박는다

지어내지 않는다. 대본 `worldTimeline`에 이미 `atSec: 0` 프레임이 있다
(1편: `robot-01` position·speed_mps·is_moving, `camera-02` in_view).
**정지 화면과 동영상의 관계이지 별개의 목이 아니다** — 승인하면 같은 데이터가 시간축을 따라 움직인다.

게이트웨이 쪽 구현 지점: `gateway/script-engine.ts`의 `startPlayback()` 안에 인라인으로 있는
`worldTimeline` 분배 로직을 **`applyWorldFrame(script, w)` 메서드로 뽑아** 재생과 미리보기가
같은 한 곳을 쓰게 한다. **봉투를 대본이 만들지 않는다**는 기존 규칙은 그대로다 — 장치의
`drive()`로 넣고 장치가 평소대로 낸다.

### 만들 것 B — `PendingSource`에 넷째 상태 「이 대본에는 해당 없음」

| 상황 | 표시 |
|---|---|
| 일반 모드 | `연결 예정` (현행 그대로 — 결정 5) |
| 시나리오 · cast 안 | `대본 — 합성 데이터` (현행) |
| 시나리오 · cast 밖 장비 | `이 대본에 없는 장비` (현행) |
| **시나리오 · 대본에 그 축이 없음** | **`이 대본에는 해당 없음` + 어느 편에서 보이는지** |

넷째가 새로 만드는 것이다. `ZoneMapMini.tsx`가 이미 이걸 손으로 하고 있다
(「이 대본에는 맵이 없습니다」) — 그걸 정식 상태로 올린다.

**축은 대본에서 유도한다. 대본에 축 목록을 손으로 적지 않는다** — 적으면 대본을 고칠 때 한쪽만
바뀌어 조용히 갈라진다. `src/scenarios/axes.ts`(신설)에 유도 규칙 하나만 둔다:

| 축 | 유도 근거 |
|---|---|
| `position` · `speed` | `worldTimeline[].drive` 에 `position` / `speed_mps` 키가 있는가 |
| `water` | `drive.water_level_m` |
| `coverage` | `drive.coverage` 또는 `script.map` |
| `video` | `drive.in_view` |
| `actuator` · `command` | `script.commands` 가 비어 있지 않은가 |
| `risk` · `observability` | **어느 대본에도 없다** — 위험도는 AI 파트(`VZ-I-08`), 관측 지표는 평시 `ObservabilityEmitter` 몫이라 대본이 몰 것이 아니다. 그 사실을 화면에 적는다 |

`PendingSource`에 `axis?: ScenarioAxis` 프롭을 더한다. **자리표시 렌더 자체는 안 바꾼다**(결정 5) —
시나리오 모드에서 축이 없을 때만 갈라지는 분기 하나를 더하는 것이다.

### 만들 것 C — 탭별

| 탭 | 할 일 |
|---|---|
| ② 구역 현황판 | `zone-summary`를 시나리오에서 **cast 기준 집계**로(「대본 2 · 자리표시 N」). `risk-state`는 `axis="risk"` → 「해당 없음 — AI 파트(VZ-I-08)」 |

| ④ 지표 조회 | **시나리오 진입 시 기본 지표를 대본 지표로 자동 전환** — 1편 `robot_speed_mps` · 2편 `coverage_pct` · 3편 `water_level_m`. 대본과 무관한 지표는 목록에서 흐리게. `metrics-push`(edge-node-a)는 `axis="observability"` → 「해당 없음」 |

## 요구 3 — 노드 분화 (대본 JSON)

### 지금

세 편 모두 **마일스톤 1개 = 태스크 1개**다. 마일스톤을 눌러도 노드가 하나뿐이라
DAG·트리 전환도 실패 경로 강조도 볼 것이 없다.

### 분할 원칙 — 임의로 쪼개지 않는다

**노드 문법 5종**을 정하고 마일스톤을 그 부분그래프로 편다.
「왜 이렇게 쪼갰나」에 답이 있어야 논문에서 방어된다.

| 종류 | 뜻 | 계약의 근거 |
|---|---|---|
| `sense` | 값을 받아 온다 | telemetry · coverage · vision 채널 |
| `decide` | 조건이 참인가 | `evaluation.judgedBy` |
| `act` | 명령을 낸다 | `commands[]` · CommandEngine |
| `verify` | 구동 결과가 의도대로인가 | `evaluation.criteria` |
| `report` | 기록·발행 | trace_event · 감사 |

**사용자가 준 단계를 더하거나 빼지 않는다.** 실패 분기도 지어 넣지 않는다.
분화는 **한 단계 안을 펴는 것**이지 단계를 늘리는 것이 아니다.

`ScriptTask`에 `nodeKind?: NodeKind` 를 더하고(선택 필드 — 옛 파일 무효화 안 됨) 노드 위에 칩으로 그린다.

### 되돌아가는 엣지는 `deps` 가 아니다 — 이 항목에서 제일 조심할 곳

`src/graph/layout.ts`의 `depths()`는 **순환 보호가 없다.** 되돌아가는 엣지를 `deps`에 넣으면
무한 재귀해서 화면이 통째로 멎는다. 그런데 결정 2대로 **루프는 그려야 한다.**

그래서 대본에 **`refEdges`** 를 별도 목록으로 둔다:

```json
"refEdges": [
  { "from": "T-27c", "to": "T-23a", "label": "재탐색 요청 → 대상 칸 재선택",
    "note": "deps 에 넣으면 layout.depths() 가 무한 재귀한다 — 점선 참조 엣지로만 그린다" }
]
```

- `TaskGraph`는 이걸 **점선 + `↺ 문구`** 로 그리기만 한다. 레이아웃·깊이 계산에 넣지 않는다.

### 그래프 보기 범위 — 이걸 안 하면 분화해도 안 보인다

`main.tsx`의 `graphTasks`는 **클릭한 마일스톤의 태스크만** 그린다. 그런데 분기·합류는 대부분
마일스톤을 **건넌다** — 1편의 합류(`T-15a` ← MS-D 셋)도, 2편의 되돌아감(MS-F → MS-C)도.

그래서 DAG/트리 토글 옆에 **범위 토글**을 둔다: `[ 이 마일스톤 ] [ 임무 전체 ]`.
기본은 **마일스톤**이다 — HCI 전달본의 화면 흐름(마일스톤 클릭 → 그 마일스톤의 그래프)을 지킨다.
마일스톤 밖으로 나가는 `refEdge`가 있으면 그래프 아래에 **한 줄로 적고** 「임무 전체로 보기」 버튼을 붙인다.
적지 않으면 사용자는 루프의 존재를 모른다 (결정 2와 같은 이유).

`TaskGraph`의 캔버스 높이가 `layoutMode === 'dag' ? 390 : 690` 상수다. 한 열에 세 노드가 쌓이는
마일스톤이 생기고 「임무 전체」는 노드가 열일곱이라 **아래쪽 노드와 참조 엣지 문구가 잘린다.**
노드 위치에서 계산하도록 바꾼다.

### 방법 — 글을 지우지 말고 자리만 옮긴다

설명서를 별도 파일로 옮기면 화면을 고칠 때 한쪽만 바뀌어 조용히 갈라진다.
**이 저장소가 계속 피해 온 실패다.** 그래서 문구는 **원래 있던 컴포넌트 자리에 그대로 두고**,
그리는 위치만 바꾼다.

`src/shared/Explain.tsx`(신설):

```tsx
<Explain id="...">…원래 문단 내용 그대로…</Explain>
```

- 본문에는 **아무것도 그리지 않는다**(`return null`).
- 자기 내용을 「지금 열려 있는 탭」 앞으로 등록한다 (React context `ManualScope` — 셸이 탭마다 감싼다).
- 등록 순서 = DOM 순서 = 설명서의 순서.
- 등록은 마운트 시 한 번(`useEffect`, deps `[scope, id]`), 내용은 ref로 매번 최신을 읽는다.
  매 렌더마다 등록하면 오버레이가 열려 있을 때 되그리기가 요란해진다.

기존 `<p className="board__sub|note|note note--dim|hint">…</p>` **28곳**을 `<Explain>` 로 바꾼다.
기계적 치환이라 위험이 낮다. 다만 `VideoOverlayView.tsx`처럼 `import {` 가 여러 줄인 파일에
import 를 끼워 넣을 때 **줄 중간에 들어가지 않게** 주의한다.

### 우상단 `?` 오버레이

- 세그먼트 오른쪽에 `?` 버튼. 누르면 **현재 탭의 것만** 모달로 뜬다 (결정 4).

- 탭①(디버거)도 같은 방식으로 하나 만든다.
