# 작업 지시: 1단계 — 프로토타입 초안 (HCI 전달본)

**기간**: 2026-09-01 ~ 09-07
**선행**: 0단계 완료 (`작업프롬프트_0단계_준비_260827.md`)
**대상 문서**: `구현진행_가시화도구_260826.md` §4-2 1단계 · §5 (HCI 협업) · §6 (화면 다섯 개)

---

## 배경

0단계에서 폴더 골격·통신 이식·3계층 계약이 섰다. 1단계는 **화면 다섯 개를 목 데이터로
동작하게 만드는 단계**다.

이 단계의 결과물은 **HCI 팀원에게 전달할 물건**이다. 협업이 초안 전달에서 시작하기 때문에
(구현 문서 §5), 초안이 늦어지면 협업 전체가 밀린다.

**그래서 이 단계의 목표는 완성도가 아니라 속도다.** 아래 "하지 않을 것"을 반드시 지킨다.
덜 다듬어진 화면을 전달하는 것이 이 단계의 의도이지 사고가 아니다.

## 제약 — 반드시 지킬 것

1. **기존 코드를 고치지 않는다.** 0단계와 동일. 기존 검증 7종이 계속 통과해야 한다.
2. **하지 않을 것** — 이 단계 범위 밖이다. 당겨오지 말 것.
   - 실제 백엔드 연결 (목으로 충분하다)
   - 기록 저장소·시점 되감기·실패 경로 격리 (2단계)
   - 결함 주입 하네스 (3단계)
   - **시각 디자인 다듬기** — 색 조정, 여백 조정, 애니메이션, 반응형.
     **이게 팀원과 논의할 대상이므로 미리 다듬지 않는다.**
3. **다섯 화면은 하나의 임무를 서로 다른 시점에서 본 것이어야 한다.**
   예상 구현 이미지가 그렇게 맞춰져 있다. 화면마다 다른 데이터를 쓰면 논의가 흐려진다.
4. **상태는 8종 전부 화면에 나타나야 한다.** 특히 `skipped`(건너뜀)와 `not_executed`(미수행)가
   **눈으로 구분**되어야 한다. 색만으로 8개를 구분하려 하지 말고 테두리 모양·아이콘·회차 배지를 함께 쓴다.
5. **계층 경계를 화면에서도 지킨다.** 마일스톤·태스크 화면에 기종 이름이나 파라미터가
   직접 나오지 않는다. 노드에 뜨는 기종명은 **배정 결과의 표시**이지 태스크 정의가 아니다.
6. **나가는 명령은 전부 기록에 남긴다.** 이 단계에서는 기록 저장소가 없으므로
   콘솔 출력 + 메모리 배열로 충분하다. 다만 **`produced_by: 'human'`을 붙이는 경로를 지금 만들어 둔다.**
   2단계에서 저장소만 갈아끼우면 되도록.
7. **목임을 감추지 않는다.** 화면 어딘가에 목 데이터임이 드러나야 한다.
8. **의존성을 늘리지 않는다.** 그래프 라이브러리를 넣지 않는다.

## 단계

### 1단계 — 목 데이터와 시나리오

화면보다 데이터가 먼저다.

- 임무 `MSN-260826-01` 하나를 시나리오 파일로 만든다. 마일스톤 7건, MS-C 아래 태스크 7건
  (T-31~T-37), T-31의 액션 아이템 4건.
- 태스크 의존 관계는 **분기와 합류가 있어야 한다.**
  `T-31 → {T-32, T-33} → T-34 → T-35 → T-36 → T-37`
- 하드웨어 7대를 레지스트리에 넣는다. `go1-02`(온라인) · `arm-03`(**오프라인**) ·
  `cam-4f` · `cam-5f`(점검) · `go1-05` · `amr-11` · `drone-01`(오프라인).
  `arm-03`이 오프라인인 것이 중요하다 — T-32·T-36이 이걸 쓴다.
- 시간에 따른 상태 전이를 **시각과 함께** 정의한다. 예상 구현 이미지의 타임라인이 기준이다.
  (T-31 4~14s 실행, T-32 22s 건너뜀, T-33 22~46s 실행·실패·재실행·완료, … T-35 93s 실패)
- 게이트웨이가 이 시나리오를 재생하고 `trace-event` 형태로 발행한다.

**판정 기준**: 게이트웨이만 띄우고 콘솔로 이벤트 열을 봤을 때, 시각 순서대로
8상태 전이가 전부 흘러가야 한다. **화면 없이 여기까지 확인한다.**

### 2단계 — 그래프 렌더링 기반

- 계층(depth) 기준 열 배치 + 같은 열 세로 분산. 노드 위치는 계산으로 정한다.
- 연결선은 SVG 베지어 곡선 + 화살표. 분기와 합류가 겹치지 않게 나온다.
- 노드 카드: ID · 제목 · 상태 · **배정 하드웨어와 연결 상태**.
- 상태 8종의 시각 부호를 한 곳(`graph/stateStyle.ts` 같은 파일)에 모은다.
  팀원 논의 뒤 여기만 고치면 전 화면이 바뀌어야 한다.

### 3단계 — 화면 다섯 개

`reports/assets/2026-08-26_예상구현_VZ-D-0*.png`를 기준으로 만든다.

| 화면 | 이번 단계에서 동작해야 하는 것 |
|---|---|
| **VZ-D-01 마일스톤** | 발화 처리 진행 막대 · 마일스톤 목록(스크롤) · 하드웨어 목록 · **드래그로 마일스톤에 배정** · 마일스톤 클릭 시 D-02로 |
| **VZ-D-02 노드 그래프** | 태스크 DAG · 8상태 색 · 노드별 하드웨어·연결 상태 · **더블클릭 시 D-03 팝업** |
| **VZ-D-03 액션 아이템 팝업** | 액션 아이템 표 · **로봇 상태 스트립**(배터리·네트워크·IP·펌웨어·온도·하트비트) · 평가 항목 · 버튼(동작만) |
| **VZ-D-04 리플레이** | **D-02와 같은 화면**의 재생 모드. 슬라이더를 끌면 그 시점 상태로 다시 칠해진다 · 임무 이력 목록 · 상태 타임라인 |
| **VZ-D-05 실패 수정** | 실패 노드 강조 · 관련 없는 노드 흐리게 · 수정 팝업(입력 필드는 동작, 재실행은 콘솔 출력) |

전 화면 공통으로 **임무 정지 · 재시작 · 중단 · 임무 이력** 바가 상단에 있어야 한다.

**D-04에 주의한다.** 별도 화면을 새로 만들지 말고 **D-02 컴포넌트에 슬라이더 상태를 주입**하는
구조로 만든다. 두 벌로 만들면 팀원 논의 결과를 두 번 반영해야 한다.

### 4단계 — 트리 표현 (판단 필요)

논문 문서 §6-2에 적힌 문제다. 초안이 그래프안뿐이면 팀원 논의를 거쳐 그래프안만 다듬어지고,
트리안은 대충 만든 상태로 비교에 들어가 **허수아비 비교**가 된다.

**같은 자료 구조에 렌더러만 다른 것이므로 지금 함께 만드는 것이 싸다.**
`graph/layout.ts`를 DAG용과 트리용 두 벌로 두고 토글로 전환한다.

**이 단계를 할지 말지는 착수 전에 확인받는다.** 하기로 하면 3단계와 함께,
안 하기로 하면 논문 문서 §6-2의 대응 2번(논의 결과를 두 안에 동일 반영)으로 간다.

### 5단계 — 전달본 만들기

팀원이 **아무것도 설치하지 않고 열 수 있어야 한다.**

- 시나리오 데이터를 파일로 내장해 게이트웨이 없이도 화면이 채워지게 한다.
- `npm run build` 결과를 정적 파일로 내보낸다.
- 화면 다섯 개가 무엇을 하는 화면인지 **한 장짜리 설명**을 함께 만든다.
  (`viz-debugger/HANDOFF.md`)
- 그 문서 끝에 **논의하고 싶은 항목 7건**을 그대로 옮겨 적는다 (구현 문서 §5-3).
  열린 질문으로 가면 두 배 걸린다.

## 완료 판정

1. 화면 다섯 개가 목 데이터로 뜨고, 마일스톤 → 태스크 → 액션 아이템으로 **클릭해 내려갈 수 있다.**
2. 하드웨어를 드래그해 마일스톤에 배정하면 하위 태스크의 대상이 바뀐다.
3. D-04 슬라이더를 끌면 **같은 그래프**가 그 시점 색으로 다시 칠해진다.
4. 8상태가 전부 화면에 나타나고 `skipped`와 `not_executed`가 눈으로 구분된다.
5. `npm run build` 결과를 **서버 없이 열어도** 화면이 채워진다.
6. `HANDOFF.md`에 화면 설명과 논의 항목 7건이 있다.
7. 기존 검증 7종이 작업 전과 동일하게 통과한다.

**1~6이 되면 그날 바로 팀원에게 전달한다.** 더 다듬고 보내지 않는다.
