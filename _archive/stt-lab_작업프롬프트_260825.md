# 작업 지시: STT 모델 테스트 하네스 `stt-lab` 구축

## 배경

이 저장소는 하이브리드 디지털 트윈 프레임워크의 **가시화 파트**다.
`요구사항정의서.md` §2.13 **F13(음성 인터페이스)** 를 구현하기 전에,
**어떤 STT 엔진·모델·설정을 쓸지 근거를 만들기 위한 실험 하네스**를 먼저 만든다.

**이번 작업은 F13 구현이 아니다.** 대시보드에 음성 기능을 붙이는 것이 아니라,
저장소 루트에 독립된 실험 폴더 `stt-lab/` 을 새로 만드는 것이다.

## 먼저 읽을 것

1. `요구사항정의서.md` §2.13 — REQ-1301~1306.
   특히 **REQ-1302**(STT 엔진 추상화) · **REQ-1304**(명령 어휘는 레지스트리의
   `display_name`·`aliases[]`에서 수신) · **REQ-1306**(신뢰도 임계 처리 — *임계값은 실측 후 확정*).
   → 이 하네스의 존재 이유 중 하나가 **REQ-1306의 그 숫자를 실측해 내는 것**이다.
2. `web-dashboard/mock-gateway/registry.json` — `zones` / `nodes` / `entities` 의
   `id` · `display_name` · `aliases[]` 구조.
3. `web-dashboard/README.md` 의 **"지켜야 하는 규칙"** 절 — 이 저장소의 코드 규율과 서술 톤.

## 제약 — 반드시 지킬 것

1. **`web-dashboard/` 를 일절 수정하지 않는다.** `package.json` · `src/` · `mock-gateway/`
   전부 무변경. `stt-lab`은 완전히 독립된 프로세스이며 대시보드와 포트도 겹치지 않는다
   (대시보드는 5173 / 8787~8788을 쓴다. **stt-lab은 8799**).
2. **npm·Vite를 새로 도입하지 않는다.** 화면은 FastAPI가 서빙하는 **정적 HTML 한 장**이다.
   빌드 단계 없음, `node_modules` 없음. 프레임워크 없이 순수 JS로 짠다.
3. **`registry.json`을 복사하지 않는다.** 실행 시
   `../web-dashboard/mock-gateway/registry.json` 를 읽는다. 경로는 환경변수로 바꿀 수 있게 한다.
   (복사본을 두면 원본이 바뀔 때 조용히 어긋난다.)
4. **엔진은 인터페이스 뒤에 둔다** (REQ-1302). 지금 구현체는 faster-whisper 하나지만,
   나중에 RTZR·CLOVA·Qwen3-ASR을 **파일 하나 추가**로 붙일 수 있어야 한다.
   엔진별 분기문이 라우터나 UI 코드에 나타나면 추상화가 깨진 것이다.
5. **PyTorch를 설치하지 않는다.** faster-whisper는 CTranslate2 기반이라 torch가 필요 없다.
   의존성에 torch가 끌려 들어오면 잘못 잡은 것이다.
6. 녹음 오디오 · 모델 캐시 · 결과 파일은 `stt-lab/.gitignore` 로 제외한다.
   *(F13은 "원본 오디오를 보존하지 않고 전사 텍스트만 남긴다"를 원칙으로 하지만,
   여기 오디오는 운영 데이터가 아니라 모델 간 재현 비교용 시험 자료이므로 로컬 보관한다.
   대신 저장소에는 올리지 않는다. 이 판단 근거를 README에 한 줄 남길 것.)*

### 서버 API

| 메서드 | 경로 | 하는 일 |
|---|---|---|
| `GET` | `/api/models` | 사용 가능 모델 목록 + 현재 디바이스(cuda/cpu)·compute_type |
| `GET` | `/api/vocab` | registry에서 뽑은 hotwords 어휘와 출처(zone/node/entity별) |
| `POST` | `/api/transcribe` | 오디오 + 옵션 → 전사 결과 |
| `POST` | `/api/score` | 전사문 + 정답문 → CER/WER |
| `GET` | `/api/runs` | 누적 실행 기록 |
| `GET` | `/api/runs.csv` | 기록 CSV 내보내기 |

`/api/transcribe` 는 오디오 파일(멀티파트)과 함께 다음을 받는다:
`model` · `language`(기본 `ko`) · `use_hotwords`(bool) · `initial_prompt`(문자열, 선택) ·
`vad_filter`(bool) · `beam_size` · `temperature`.

응답에는 **반드시** 다음을 포함한다:

- `text` — 전사 전문
- `segments[]` — `start` · `end` · `text` · **`avg_logprob`** · **`no_speech_prob`** · `compression_ratio`
- `words[]` — `word_timestamps=True` 로 얻은 단어별 `probability`
- `duration_sec` · `elapsed_sec` · **`rtf`**(= elapsed / duration)
- `model` · `device` · `compute_type` · 적용된 옵션 전체

> `avg_logprob` · `no_speech_prob` · 단어 `probability` 를 화면에 반드시 노출할 것.
> Whisper는 깔끔한 confidence 값을 주지 않으므로, **REQ-1306의 임계값은 이 세 수치를
> 실측해서 정해야 한다.** 이게 하네스의 핵심 산출물이다.

### 화면 (`web/index.html`)

한 페이지 안에 네 구역:

1. **입력** — 마이크 녹음 버튼(MediaRecorder, webm/opus) + 파일 업로드(wav·mp3·m4a·webm).
   녹음 중에는 경과 시간과 간단한 입력 레벨 표시. 녹음본은 재생 가능해야 한다.
2. **설정** — 모델 드롭다운, hotwords 켬/끔 토글(적용될 어휘 개수를 옆에 표시),
   VAD 토글, `initial_prompt` 입력, beam size. 현재 device/compute_type 배지.
3. **결과** — 전사 전문, 세그먼트 표(타임스탬프·텍스트·`avg_logprob`·`no_speech_prob`),
   낮은 확률 단어는 시각적으로 구분(단어별 `probability` 기준). 처리 시간과 RTF.
4. **정확도** — 정답 텍스트 입력란 → CER/WER 계산 → 누적 비교표.
   비교표 각 행: 시각 · 모델 · hotwords 여부 · VAD 여부 · CER · RTF · 발화 길이 · 오디오 파일명.
   **같은 오디오를 설정만 바꿔 다시 돌리는 버튼**을 둘 것 — 이게 없으면 비교가 수작업이 된다.

한국어 UI. 대시보드와 색을 맞출 필요는 없지만 읽기 불편하지 않을 정도의 스타일은 넣는다.

### 명령 발화 프리셋

`registry.json` 의 엔티티·구역을 조합해 **테스트용 발화 문장 목록을 자동 생성**해
화면에 띄운다. 사용자가 그걸 보고 읽어서 녹음하면 정답 텍스트가 이미 정해져 있으므로
CER 측정이 바로 된다. 예: `"503 구역 로봇 상태 보여줘"` · `"2호기 정지"` ·
`"엣지 노드 A 지표 열어줘"`. 문장 틀은 코드 상단 상수로 빼서 늘리기 쉽게 한다.

## 정확도 설정 — 이걸 틀리면 하네스가 거짓말을 한다

명령 발화는 **1~3초짜리 짧은 오디오**다. Whisper는 30초 윈도우 전제로 학습돼 짧은 발화와
무음 구간에서 반복·환각이 잘 난다. 다음을 기본값으로 둘 것:

- `condition_on_previous_text=False` — **필수**. 짧은 발화 반복 환각의 주된 원인이다.
- `vad_filter=True` (Silero VAD) 기본 켬. 단 토글로 끌 수 있게 해서 영향을 측정할 수 있게 한다.
- `language="ko"` 고정 (자동 감지를 쓰면 짧은 발화에서 언어를 틀리게 잡는다).
- `no_speech_threshold` · `compression_ratio_threshold` 는 기본값을 쓰되 응답에 실어 보낸다.
- **`hotwords` 와 `initial_prompt` 는 다른 것이다.** `hotwords` 는 특정 어휘로 편향시키고,
  `initial_prompt` 는 전체 문맥·문체를 유도한다. 둘을 한 입력란으로 합치지 말 것.
  hotwords에는 registry의 `display_name` + `aliases[]` 를 넣는다 (REQ-1304).

## 모델·환경

- 기본 모델은 **`large-v3-turbo`**. 드롭다운에 `tiny` · `base` · `small` · `medium` ·
  `large-v3` · `large-v3-turbo` 를 모두 넣는다.
- **디바이스 자동 판정**: CUDA 사용 가능하면 `device="cuda", compute_type="float16"`,
  아니면 `device="cpu", compute_type="int8"`. 판정 결과를 화면 배지로 보여준다.
- CUDA 초기화에 실패하면 **에러를 내지 말고 CPU로 자동 폴백**하고, 폴백했다는 사실을
  화면에 명시한다. (Windows에서 cuDNN 9 / cuBLAS 미설치로 흔히 실패한다.)
- 모델은 첫 요청 때 받아서 **프로세스 수명 동안 캐시**한다. 같은 모델을 반복 요청할 때
  다시 로드하면 RTF 측정이 무의미해진다. 모델 로드 시간과 추론 시간은 **분리해서** 측정한다.
- 모델 캐시 경로는 `HF_HOME` 또는 `STT_LAB_MODEL_DIR` 로 지정 가능하게 한다.

## CER 계산

한국어는 교착어라 어절 단위 WER보다 **글자 단위 CER**이 기준이다.

- CER = 레벤슈타인 편집거리 / 정답 글자 수. **음절 단위를 기본**으로 한다.
- 참고치로 **자모 분해 CER**도 함께 계산해 표시한다 (`ㄱ`/`ㅏ` 단위 — 종성 하나 틀린 것과
  글자가 통째로 틀린 것을 구분해 준다).
- 비교 전 정규화: 앞뒤 공백 제거, 연속 공백 1칸, 문장부호 제거 여부는 **토글**로 둔다
  (명령 인식에서는 보통 제거하는 게 맞지만 근거를 남기려면 양쪽을 봐야 한다).
- 외부 라이브러리 없이 직접 구현한다 (`jiwer` 등을 끌어오지 말 것 — 40줄이면 된다).

## `stt-lab/README.md` 에 쓸 것

- Windows 기준 실행 절차: venv 생성 → `pip install -r requirements.txt` →
  `python -m server.main` → `http://localhost:8799`
- **GPU를 쓰려면** 무엇이 더 필요한지 (CUDA 12 · cuDNN 9), 안 되면 CPU로 떨어진다는 것
- 측정 항목 해석: `avg_logprob` · `no_speech_prob` · 단어 `probability` 가 각각 무엇이고
  REQ-1306 임계값을 정할 때 어떤 걸 봐야 하는지
- 알려진 실패: 짧은 발화 반복 환각, 무음 구간 환각, 포트 충돌(8799)
- **다음 엔진을 붙이는 방법** — `engines/` 에 파일 하나 추가하고 등록하면 되는 절차 (REQ-1302)

## 완료 판정

1. `python -m server.main` 한 줄로 뜨고 브라우저에서 화면이 보인다.
2. 마이크로 `"503 구역 로봇 상태 보여줘"` 를 녹음하면 전사문과 세그먼트별 확률이 뜬다.
3. hotwords 토글을 끄고 같은 오디오를 다시 돌리면 **두 결과가 비교표에 나란히 쌓인다.**
4. 정답 텍스트를 넣으면 CER이 계산되고 CSV로 내보내진다.
5. `web-dashboard/` 에 대한 `git diff` 가 **비어 있다.**

## 작업 방식

- 한 번에 다 쓰지 말고 **① 서버 뼈대 + `/api/models` → ② 전사 API → ③ 화면 → ④ CER·기록**
  순으로 만들고 각 단계마다 실제로 돌려서 확인한다.
- 주석과 문서는 한국어로, `web-dashboard/README.md` 처럼 **왜 그렇게 했는지**를 적는다.
  무엇을 했는지는 코드가 이미 말하고 있다.
- 확실하지 않은 것을 추측으로 채우지 말고 물어볼 것. 특히 이 저장소의 기존 계약을
  건드려야 할 것 같으면 멈추고 확인한다.
