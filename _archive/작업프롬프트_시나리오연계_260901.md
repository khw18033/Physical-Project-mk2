# 작업 지시: 시나리오가 사이트를 끌고 가게 — 탭 연계 완성과 승인 패널 재배치

**선행**: 사이트 개선 4건 `90c51ca` · 문서 최신화 `fc24202` (작업 트리 깨끗)
**대상 요구사항**: `VZ-U-07`(승인) · `VZ-U-05`(서브태스크 진행) · `VZ-U-01`(탭②) · `VZ-O-01`·`O-02`(탭③) · `VZ-I-04`(탭④) · `VZ-I-06`·`I-07`(탭⑤) · `VZ-D-*`(탭①)
**기준 커밋**: 착수 시점의 `HEAD`
**날짜**: 2026-09-01

---

## 왜 하나

사용자가 화면을 보고 한 말이 요지다.

> 시나리오를 만든 이유는 실제로 사이트가 어떻게 작동하는지 **직접 실행되는 걸 보면서 확인**하고
> 싶은 건데, 로봇 시나리오인데 수문 제어가 보이고 연결 예정이 보이면 그게 힘들다.

지난 작업에서 시나리오 연계를 **자리(slot) 층에서만** 했다. `PendingSource` 에 `axis` 를 붙여
「이 대본에는 해당 없음」을 만든 것까지는 맞는데, **그 위의 패널과 탭은 그대로 서 있다.**

1편(로봇 이동)을 틀어도 탭③에는 `actuator-01 · 수문 제어` 제목과 버튼 줄과 감사 표가 그대로
있고 안쪽 칸만 「해당 없음」이다. **로봇 이야기를 보는 사람 앞에 수문이 있다.**
「해당 없음」 칩을 몇 개 붙이는 것으로는 이 인상이 지워지지 않는다 — 뼈대가 남아 있기 때문이다.

이번 작업은 **연계를 자리 층에서 패널·탭 층으로 올리는 것**이다.

## 0. 남은 것 둘

### 0-1. 모드 스위치가 「우측 상단」이 아니라 가운데다

```css
.global-bar{ ... grid-template-columns:300px 1fr auto; ... }
```

세 칸 격자인데 **요구 1에서 가운데 칸의 안내 문단 2줄을 지웠다.** 남은 자식이
`mission-identity` 와 `nav` 둘뿐이라 `nav` 가 가운데 `1fr` 칸으로 올라왔고 오른쪽 `auto` 칸이 비었다.

- `grid-template-columns:300px 1fr` 로 줄이고 `.global-bar nav { justify-self:end }`.
- 고친 뒤 문서에서 **단서를 지운다** — `가시화_프로토타입_설명서.md`(모드 스위치 절의 「지금은
  가운데에 있습니다」 괄호) · `현재상황_읽기순서.txt`(「지금은 바 가운데에 있다」 줄과
  「지금 남은 것」의 첫째 항목). 고쳐 놓고 문서에 남겨 두면 다음 사람이 또 찾는다.

### 0-2. 3편 정지 미리보기의 수문 개도율이 이야기와 반대다

`MSN-260831-03` 은 **열려 있던 수문을 닫는** 이야기이고 대본이 그렇게 적고 있다.

```json
"initial": { "actuator-01": { "position_pct": 100, "physical_state": "open" } }
```

그런데 `ScriptEngine.previewScript()` 는 `worldTimeline` 의 `atSec === 0` 프레임만 반영하고
`initial` 을 건너뛴다. 3편의 t=0 프레임에는 `sensor-01`·`sensor-02` 수위만 있어서
**미리보기의 개도율이 평시값 0%(닫힘)** 로 보인다 — 출발 상태의 정반대다.

- `previewScript()` 에서도 `initial` 을 반영한다. **재생 경로(`startPlayback()`)에 이미 있는
  `commands.primeState()` 세 줄과 같은 것**을 쓴다 — 두 벌로 적지 말고 함께 뽑아라.
- 「값을 지어내지 않는다」는 원칙에 어긋나지 않는다. 지어내는 것이 아니라 **대본이 적어 둔
  출발 상태를 그대로 놓는 것**이다. `initial` 은 대본이 말하는 t=0 세계 그 자체다.
- `verify:scenario-mode` 에 검사 한 줄: 3편 미리보기 뒤 `actuator-01` 개도율이 100인가.

## 1. 「임무 승인 · 서브태스크 진행」 — 승인만 남기고 진행은 지운다

### 근거 둘

**첫째, 계획 구간은 마일스톤과 같은 값이다.** `gateway/plans.ts` 머리 주석이 스스로 적고 있다.

> 구간(segments)은 대본의 마일스톤이고, 재생기가 태스크 상태를 접어 갱신해 준다.

`ScriptEngine` 이 `foldMilestones()` 결과를 `plans.applyScriptMilestones()` 로 그대로
되돌린다. 즉 `PlanApproval` 의 `SegmentTrack`(서브태스크 진행)은 **탭①의 마일스톤 목록과
같은 값을 한 화면에서 두 번 그린다.** 사용자가 「내용이 안 맞는다」고 한 것의 절반이 이것이다.

**둘째, 화면의 서사가 실제와 어긋난다.** 이 패널은 「백엔드가 계획을 내려주고 우리가 승인한다」를
그리도록 설계됐는데(`BE-X-04` 중계 · 근거의 AI/백엔드 구분 · 중계 단계 표시), 지금 임무는
**가시화 쪽의 대본 조회**에서 나온다. 백엔드 중계 단계를 보여 주는 칸이 그 자리에 있으면
사용자는 지금 무엇을 보고 있는지 헷갈린다.

### 할 일

**빼는 것** — 탭①에서 아래를 없앤다.
- `SegmentTrack`(서브태스크 진행 패널 — 구간 목록·진행 요약·`VZ-U-05` 태그)
- 실패 상세(`faildetail`) — 탭①에 **실패 경로 강조 화면이 이미 있다**(`screen === 'failure'`)
- 중계 단계(`relay_stage`) 표시 — 백엔드 내부 상태다. 필요하면 목·개발 모드로

**남기는 것 — 승인·거부는 임무의 관문이라 없애면 안 된다.**
- 승인·거부를 **탭① 마일스톤 화면의 제안 카드 안**으로 넣는다. 그 자리에는 이미
  「제안 상태 — 대본 … 승인 전에는 아무것도 재생되지 않습니다 / 맞은 키워드」가 있고,
  단독 빌드용 `proposal-fallback` 이 승인·거부 버튼을 갖고 있다. **통합 빌드도 같은 자리를 쓴다.**
- **계획 근거 4층은 펼친 채로 유지한다** — 승인은 되돌리기 어려운 조작이라 접어 두면
  안 보는 근거가 된다(원 설계 판단 1을 그대로 따른다). 다만 그 안의 **「구간별 계획」 절은
  마일스톤 목록과 겹치므로 「N구간 — 아래 마일스톤과 같음」 한 줄로 줄인다.**
- **거부는 사유 없이 보낼 수 없다** — 기존 규칙 유지.

**경로는 건드리지 않는다.** 옮기는 것은 화면 자리이지 호출 경로가 아니다.
승인 버튼은 여전히 `decidePlan()`(백엔드 채널)을 통과해야 하고, 게이트웨이의
`onScriptApproved` → `startPlayback()` 이 그대로 걸려야 한다. **여기가 끊기면 대본 재생이
통째로 막힌다.** 착수 후 세 문장 중 하나로 승인 → 재생까지 반드시 확인하라.

**요구사항을 조용히 없애지 마라.** `VZ-U-05`(서브태스크 진행)는 삭제가 아니라
**탭①의 마일스톤 목록 · 태스크 그래프 · 되감기 타임라인이 충족한다**고 본다.
그 판단을 `요구사항정의서.md` §3.1 배치표에 적어라. 화면만 지우고 시트를 그대로 두면
다음 대조에서 「구현 안 된 요구」로 잡힌다.

**단독 빌드 경계는 그대로다.** `PlanApproval.tsx` 는 `tabs/` 아래에 있고 통합 셸이 프롭으로
주입한다. 얇아져도 그 구조를 유지한다(`verify:standalone`).

## 2. 시나리오가 탭을 끌고 가게 — 세 층

### 축 → 탭 표를 `axes.ts` 에 둔다

축은 이미 대본에서 유도하고 있다(`src/scenarios/axes.ts`). **그 옆에 축→탭 표를 둔다** —
손으로 두 곳에 적으면 갈라진다.

| 축 | 나타나는 탭 |
|---|---|
| `position` | ② |
| `speed` | ④ |
| `water` | ② · ④ |
| `coverage` | ② · ④ |
| `video` | ⑤ |
| `actuator` · `command` | ③ |
| (임무 축) | ① — **항상** |

이 표에서 **대본이 쓰는 탭**이 유도된다.

| 편 | 쓰는 탭 | 안 쓰는 탭 |
|---|---|---|
| `MSN-260831-01` 엘리베이터 이동 | ① ② ④ ⑤ | **③** |
| `MSN-260831-02` 사각지대 탐지 | ① ② ④ ⑤ | **③** |
| `MSN-260831-03` 월류방어벽 개폐 | ① ② ③ ④ | **⑤** |

옛 편(`MSN-260826-01`)은 registry 세계가 아니라 축이 없다 — **판정 대상이 아니고**
지금처럼 구판 세계 안내만 뜬다.

### 층 1 — 탭 바

대본이 안 쓰는 탭은 **흐리게 + 작은 표시**(예: `③ 제어 패널 · 이 대본엔 없음`).
**막지는 않는다.** 눌러서 확인할 수 있어야 한다 — 막으면 「왜 안 눌리지」가 새 질문이 된다.

### 층 2 — 패널 (이번 작업의 핵심)

**대본이 그 패널의 축을 몰지 않으면 패널을 통째로 접는다.** 제목·버튼 줄·표가 남아 있으면 안 된다.
탭 전체가 그런 경우에는 탭 본문을 한 장으로 대체한다.

```
이 대본(MSN-260831-01)은 제어 패널을 쓰지 않습니다

  로봇 이동에는 액추에이터 명령이 없습니다.
  이 탭이 살아나는 편: MSN-260831-03 「월류방어벽 자동 개폐」   [그 대본으로 바꾸기]

  일반 모드로 돌아가면 이 탭의 원래 화면이 그대로 보입니다.
```

「그 대본으로 바꾸기」는 모드 스위치의 대본 선택과 **같은 경로**를 부른다 — 두 벌로 만들지 마라.

패널별 축은 구현자가 파일에서 확인해 지정한다. 착수 전 확인해 둔 대응은 아래와 같다.

| 탭 | 패널 | 축 |
|---|---|---|
| ② | `RiskPanel` 위험도 | `risk` — **어느 대본도 안 미는 축**이라 시나리오에서는 늘 접힌다 |
| ② | `ZoneMapMini` 구역 맵 | `coverage`(맵 있는 편) · `position`(궤적) |
| ② | `DeviceGrid` 카드 그리드 | `position` · `water` |
| ③ | 제어 · 명령 결과 · 감사 이력 | `actuator` · `command` |
| ④ | 지표 조회 | 대본이 미는 축 (기본 지표 자동 전환은 이미 있다) |
| ④ | `metrics-push` 관측 지표 | `observability` — 어느 대본도 안 민다 |
| ⑤ | 영상·탐지 | `video` |

### 층 3 — 자리

남은 자리는 지금 그대로다(연결 예정 / 대본 합성 / cast 밖 / 해당 없음).
다만 **시나리오 중에 보이면서 축이 없어 늘 「연결 예정」인 것**을 정리한다.

- `audit-history`(탭③ 감사 이력) → `axis="command"`. 3편에서는 대본 명령이 실제 엔진을
  통과하므로 값이 차고, 1·2편에서는 패널째 접힌다.
- 탭② `RiskPanel` 안의 `device-cards` → 패널이 접히면서 함께 해소된다.

**의도적으로 남기는 셋** — 접지도 축을 주지도 않는다. 그 이유를 화면(또는 `?` 설명서)에 적어라.

| 자리 | 남기는 이유 |
|---|---|
| 탭① `hardware-pool-status` | 대본 등장 장비의 실측 3행(배터리·RSSI·온도)은 **남이 줄 데이터**라 지어내지 않는다 — 8/31 `VZ-D-07` 결정 |
| `mission-history` | 임무 이력은 백엔드가 준다 |
| `registry` | 레지스트리는 백엔드가 주는 목록이다 |

### 일반 모드에서는 층 1·2가 작동하지 않는다

**흐림도 접힘도 시나리오 모드에서만이다.** 일반 모드는 지금처럼 모든 탭과 패널이 그대로 뜬다 —
그게 「남이 줄 데이터가 어디에 얼마나 있는지」를 보여 주는 화면이기 때문이다. `목·개발` 모드도
전부 그린다(목이 이긴다는 기존 규칙 그대로).

## 3. 지금 무엇이 어디서 보이는지 — 대본 띠에 안내

사용자의 목적이 「실행되는 걸 보면서 확인」이므로 **지금 시각에 무엇이 어느 탭에서 일어나는지**를
화면이 말해야 한다. 지금은 사용자가 탭을 하나씩 눌러 보며 찾아야 한다.

대본 띠(한 줄)를 이렇게 늘린다.

```
대본 MSN-260831-03 「월류방어벽 자동 개폐」 · 합성 데이터 · 재생 중 T+162s
지금: MS-C 위험 수위 10초 유지 판정 → close_gate 발행        [③ 제어 패널로]
```

- **「지금」은 재생 머리(`headSec`) 기준 진행 중인 노드**다. `statusesAt()` 이 이미 태스크·마일스톤
  상태를 함께 돌려주므로 새로 계산할 것이 없다.
- **갈 탭**은 그 노드의 `nodeKind`·`target` 과 그 시각의 `commands`·`worldTimeline` 에서 축을 뽑아
  위의 축→탭 표로 정한다. 후보가 둘이면 둘 다 적는다.
- **정지 미리보기**에서는 「T+0 · 시작 상태」와 첫 마일스톤을 적는다.
- 이 줄은 **탭을 옮겨도 상단에 그대로 있어야 한다** — 셸이 그린다(`AppShell`), 탭이 그리지 않는다.
- 재생이 끝나면 「재생 끝 — 마지막 상태 유지」로 바뀌는 지금 동작은 그대로.

## 검증

| 검사 | 무엇을 |
|---|---|
| `verify:scenario-mode` 확장 | 3편 미리보기 뒤 `actuator-01` 개도율 100 · 1편에서 탭③이 접히는가 · 안내줄이 재생 머리를 따라가는가 · **일반 모드에서는 아무것도 접히지 않는가** |
