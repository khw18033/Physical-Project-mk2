## 왜 하나

탭으로 나눈 기능을 **노드 그래프 안에서 노드로 연결해, 원하는 서브태스크에 딸린 정보를
그 자리에서 보는 것** — 그것이 의도였다. 지금 구조는 그 의도를 화면으로 배신하고 있다.

논문 쪽에서도 같은 결론이 나온다. `HCI_관련연구_차별점_260831.md` 의 차별점 2는
**"화면을 바꾸지 않고 공시 ↔ 통시를 넘어간다"** 인데, 탭 판에서는 **뒷절이 사실이 아니었다.**
탭②~⑤와 탭① 사이를 오가는 것이 바로 화면을 바꾸는 일이고, 옮기는 순간 「어느 태스크를
보고 있었는지」가 화면에서 사라진다. `H1-1`(CSN)이 "스냅샷 방식은 뷰 간 관계 파악이 어렵다"로,
`H1-4`가 **「방향감 상실」** 종속변인으로 이미 지적한 것이다.

**요구사항은 한 건도 죽지 않는다.** 45 → 50건, 삭제 0건.

## 1. 만들 것 — 구조

```
마일스톤 목록 ← 최상위 화면. 그대로 둔다 (VZ-U-05 대체의 근거)
└ 노드 캔버스
   ├ 팔레트 ─────── [장치·위험] [제어] [지표] [영상]        VZ-N-01
   ├ 실행 노드 ──── 지금의 TaskGraph 그대로                 17건
   ├ 뷰 노드 ────── 팔레트에서 꺼낸 것. 태스크에 잇는다      8건
   └ 확대 보기 ──── 오버레이. 캔버스를 교체하지 않는다        VZ-N-05
```

### 두 종류 노드를 절대 섞지 않는다

| | 실행 노드 (task) | 뷰 노드 (view) |
|---|---|---|
| 원천 | 대본·생성기 | 사용자가 팔레트에서 놓는다 |
| `deps` 참여 | O | **X — 절대** |
| 배치 | 자동 (밴드 접기) | 자유 배치. 기본값은 연결한 태스크 아래 |
| 상태 | 8상태 (`VZ-D-06`) | 없음 (데이터 유무만) |

`refEdges` 가 이미 준 교훈 그대로다 — 부수 엣지를 `deps` 에 넣으면 `depths()` 에 순환이
들어가 배치가 깨진다. 뷰 노드 연결은 **`bindings` 별도 배열**로 두고 레이아웃·깊이 계산에서
완전히 뺀다.

### 연결이 곧 범위 — 계약 하나로 못박는다

```ts
type ViewScope = {
  deviceId: string | null;   // task.target
  zoneId: string;            // 레지스트리 (VZ-I-03)
  fromSec: number; toSec: number;  // 그 태스크의 실행 구간
  headSec: number;           // 되감기 머리 (VZ-D-04) — 캔버스 전체가 같은 값
};
```

`VZ-D-04` 가 되감기다. `VZ-D-05` 는 실패 경로 격리다 — **헷갈리지 마라.**
(9/1 보고서 한 곳이 반대로 적었고 9/3에 정의서를 고쳤다.)

전역 노드는 `deviceId: null` + 임무 전체 구간. **연결된 노드와 화면에서 구별되어야 한다** —
연결선 + 머리에 `◂ T-43c` / 연결선 없음 + `전역` 뱃지.

## 2. 최대 위험 — 단독 빌드 경계

**요구사항이 아니라 이것이 이번 작업의 최대 위험이다.**

뷰 노드를 그래프 안에 그냥 넣으면 `tabs/data/` 스토어가 단독 번들에 딸려 들어와
**논문 측정축 D(계측 오버헤드)가 오염된다.** `verify:standalone` 은 단독 진입점의 의존
그래프에 `tabs/` 가 나타나면 실패한다.

해법은 **`PlanApproval` 이 이미 쓰는 패턴 그대로**다.

- 그래프는 `ViewNodeRenderer` 인터페이스만 안다
- **통합 빌드(`integrated.tsx`)가 `tabs/views/*` 를 레지스트리에 주입**한다
- 단독 빌드는 주입하지 않는다 → 팔레트에 뷰 노드가 없거나 `PendingSource` 자리표시만

**`verify:standalone` 은 개정 없이 그대로 통과해야 한다.** 통과하지 못하면 되돌린다.

## 3. 탭 제거가 떨어뜨리는 셸 5개소

`AppShell` 에서 탭을 걷어내면 탭에 매달려 있던 기능 다섯이 같이 떨어진다.

| 지금 | 제거 후 |
|---|---|
| `activeTab` · `app-tabs` nav · `TabView` 라우팅 | **삭제.** 팔레트가 그 자리 |
| `useTabsDataLayer()` | **그대로 셸에 남긴다.** 탭과 무관했다 |
| `TabGate` | **죽는다** → 접힘이 노드 단위로. `PanelGate` 만 살아 뷰 노드를 감싼다 |
| `HelpOverlay(tab=activeTab)` | **캔버스에 놓인 노드들의 설명서**로. 확대가 열려 있으면 그 노드 것 |
| 대본 띠의 「○○로」 (`nowPlaying().tabs`) | **「○○ 노드로」** — 아래 ★ |

★ 지금 「갈 탭」 버튼은 탭이 이미 있으니 이동만 하면 됐다. 노드는 **캔버스에 아직 없을 수 있다.**

> 누르면 — **없으면 만들고(진행 중인 태스크에 연결한 채로), 있으면 하이라이트한다.**

사용자가 팔레트를 몰라도 배너가 가르쳐 준다. 팔레트의 두 번째 진입점이자 시연에서 제일 잘
보이는 동선이 된다.

### 축→탭 표는 축→**노드종류** 표가 된다

`src/scenarios/axes.ts` 의 `AXIS_TABS`·`SCENARIO_PANELS` 가 `tab` 키다.
**표는 여전히 한 곳뿐이어야 한다.** `verify:tab-scope` → `verify:node-scope`.
접힘 규칙은 그대로 — 대본이 그 축을 안 밀면 팔레트 버튼을 흐리게(**막지 않는다**),
이미 놓인 노드는 「이 대본엔 없음」 카드로.

## 4. 캔버스 구성 보존 — 3층 (`VZ-N-04`)

| 층 | 어디에 | 언제 이기나 |
|---|---|---|
| ① 기본 구성 | 대본 사이드카 (읽기 전용) | 사용자 구성이 **없을 때만** |
| ② 사용자 구성 | `localStorage` · 키 `(missionId, milestoneId ∣ __mission__)` | **있으면 항상** |
| ③ 되돌리기 | 캔버스 머리줄 버튼 | 누를 때 ②를 지우고 ①로 |

읽는 순서 `② → ① → 빈 캔버스`. 쓰는 것은 ②뿐.

**새로고침·재접속에 살아남아야 한다.** `VZ-I-02`(재접속 시 현재값 복원)와 같은 원칙이다.
좌표를 대본 JSON이 아니라 사이드카에 두는 것은 **F10 `REQ-1002`** 와 같은 원칙이다.

### 파생 규칙 둘

- **「임무 전체」 보기는 `__mission__` 별도 슬롯.** 마일스톤별 저장만으로는 미아가 된다.
- **DAG↔트리 전환이 뷰 노드를 지우면 안 된다.** 지금 `movedPositions` 는 `layoutMode` 가
  바뀌면 `{}` 로 초기화된다(자동 배치가 다시 계산되니 맞다). 뷰 노드는 **사용자가 놓은 것**이라
  같이 지우면 "내가 만든 게 사라졌다"가 된다. **두 저장소를 분리한다.**

### 반드시 처리할 실패 셋

| 상황 | 처리 |
|---|---|
| `localStorage` 가 막혀 있다 | `try/catch` 로 감싸고 **기본 구성으로 조용히 진행** |
| 연결했던 `T-43c` 가 대본 개정으로 사라졌다 | **지우지 말고 전역 노드로 강등** + 사유 한 줄 |
| 스키마가 바뀌었다 | `version` 필드를 두고, 안 맞으면 버리고 기본 구성 + 한 줄 안내 |

두 번째가 제일 자주 난다 — 대본을 계속 고치고 있다.

## 5. 뷰 노드 4종 — 요약 카드 규격

접는 기준은 **"확대하지 않고도 이상함을 알아챌 수 있는 값"**.

| 노드 | 요약 카드 | 확대 |
|---|---|---|
| 장치 · 위험 | 연결/배터리/자기보고 3층 한 줄 + 위험도 등급 | `DeviceGrid` + `RiskPanel` |
| 제어 | 이 태스크가 낸 명령 수 + 마지막 명령의 4단계 위치 | `ControlPanel` + 감사 이력 |
| 지표 | 미니 스파크라인 + 요약/원본 표기 | `MetricsView` |
| 영상 | 대표 프레임 + 탐지 수 + 프레임 참조 유무 | `VideoOverlayView` |

> **영상 노드만 예외.** 지금 `VideoOverlayView` 는 탭을 떠나면 언마운트되어 프레임 루프가
> 멎는다(`VZ-I-06`). 캔버스에서는 떠나지 않으므로 **접힘 = 정지 프레임 / 확대 = 재생**을
> 계약에 명시하라. 안 그러면 노드 셋을 놓는 순간 프레임 루프가 셋 돈다.

`VZ-U-03`(계층 뷰)이 장치·위험 노드에 함께 온다. 세 깊이의 전환은 **요약 ↔ 확대**가 실현한다.

## 6. 「확대는 탭이 아니다」의 검사 가능한 정의

| 조건 | 왜 |
|---|---|
| 캔버스가 **뒤에 남아 보인다** (오버레이) | 맥락이 안 끊기는 것이 목적 그 자체 |
| 닫으면 **정확히 같은 자리**로 | 「어디였지」가 안 생긴다 |
| 전역에 `activeTab` 류 상태가 **없다** | 있으면 이름만 바꾼 탭이다 |
| 확대는 **한 번에 하나** | 둘이 열리면 분할 화면이고, 곧 탭이 된다 |

`ActionModal` 과 같은 계통으로 만든다.

## 7. 검증 — 신설 3 · 개정 2

| 검사 | 무엇을 |
|---|---|
| **`verify:no-tabs`** (신설) | 전역 `activeTab` 류 상태 없음 · 확대가 캔버스를 교체하지 않음 · 동시 확대 1개 |
| **`verify:node-scope`** (`tab-scope` 대체) | 축→노드종류 표와 화면의 `PanelGate` 사용이 아귀가 맞는가. 세 편의 「쓰는 노드」를 못으로 박는다 |
| **`verify:canvas-persist`** (신설) | 마일스톤을 옮겼다 돌아오면 구성이 사는가 · **DAG↔트리 전환이 뷰 노드를 지우지 않는가** · 저장소가 막혔을 때 기본 구성으로 뜨는가 |
| `verify:layout` (개정) | 최대 x에 더해 **최대 y** — 뷰 노드가 세로를 밀어낸다 |
| `verify:standalone` (**무개정 통과**) | 단독 번들에 `tabs/` 가 들어오면 실패 |

기존 15종 전부 유지.

## 하지 않을 것

- **공유 계층 16건을 건드리지 마라.** 탭과 무관했고 이번에도 무관하다.

- **`useTabsDataLayer()` 를 옮기거나 끊지 마라.** 앱 수명과 같아야 한다.
- **뷰 노드를 `deps` 에 넣지 마라.**
- `web-dashboard`(기준선) · `stt-lab` · `scenarios/*.json` 과 사이드카 · `stt/engines/*.py`
- `capabilities()` 의 `manualInput: true` 고정
