# B. 주기·근거 수정 (5건)

## B-1. VZ-I-04 — 자동 갱신 10초 → **15초**
하드웨어 관측 지표 수집이 **10초에서 15초로 바뀌었습니다**(HW-C-05). 제 갱신 주기의 근거가 그 숫자였으니 같이 옮겨야 합니다.

## B-2. VZ-I-01 · VZ-I-02 — "엣지노드 30초 배치" 근거 삭제
30초 배치 항목(구 HW-C-02)이 **사라졌습니다.** 대신 HW-S-02가 **"평시 1분 + 임계 초과·급변 시 주기 무관 즉시 발행"**으로 바뀌었어요.

- 초기 스냅샷 공백이 "1분 이상" → **"최대 1분"** 으로 완화됩니다. 근거 문장을 고쳐야 합니다.
- 대신 **급변 시 즉시 발행**이 생겨서, 제 화면이 평상시엔 느리다가 이벤트 때 갑자기 몰리는 패턴이 됩니다. 병합 처리(100ms) 근거는 그대로 유효합니다.

## B-3. VZ-I-06 — 영상이 **두 갈래로 갈라짐** (좋은 변화)
HW-R-07이 **"관제용 고해상도 영상 스트림(온디맨드)"**으로 바뀌면서 연관분야 첫머리가 **가시화**입니다. 연관점에도 "가시화 파트의 관제 화면(로봇 시점 실시간 뷰)에 표시"라고 명시됐고요.

- **HW-R-04** = AI 추론용 다운스케일(640급), 추론 주기는 AI 기준
- **HW-R-07** = 관제용 고해상도 15fps, 온디맨드 ← **제 화면용**
- **HW-S-06** = 고정 비전센서, 상시 15fps

제 시트는 이 셋을 뭉뚱그려 놨는데 **분리해서 쓰는 게 맞습니다.** 제가 요청한 게 하드웨어에 반영된 셈이라 근거도 더 단단해졌어요.

## B-4. VZ-U-01 — 하트비트 주기 5초
센서노드 하트비트가 **5초**입니다(HW-S-05). 장치 현황판 갱신 5초와 정확히 맞습니다.

## B-5. VZ-O-02 — **진행률 보고가 생김**
HW-A-04가 **"동작 중 200ms 주기로 진행 상태 보고"**를 정의했습니다. 제 시트는 진행중·확정·실패 3상태인데, 수문처럼 물리적으로 움직이는 동안 **진행 상태를 받을 수 있게** 됐습니다. 3상태는 유지하되 "진행중"에 진행률을 표시할 수 있다는 걸 반영하면 좋습니다.

# C. 신설 필요 (6건) — 팀원이 저를 지목했는데 대응 행이 없음

## C-1. 🔴 계획 승인 UI (PL-05)
> **PL-05** — "검증된 전체 계획과 그 근거를 **가시화가 표시할 수 있는 구조화된 형태로 제공**해야 한다. **승인 전에는 실행되지 않는다.**" 연관분야: **가시화, 백엔드**

**가장 큰 누락입니다.** 제 시트의 승인 절차는 음성 경로(VZ-L-02)에만 있는데, PL-05는 **음성과 무관하게 모든 계획**이 사람 승인을 거치도록 요구합니다. 그리고 근거(전역 임무 → 구역 분할 → 구간별 계획 → 검증 결과)를 펼쳐 보여주는 화면이 필요해요.

→ **VZ-U-07 · 계획 승인 및 근거 표시** 신설 권장

## C-2. 🔴 원격 제어 잠금 표시 (HW-A-05)
> **HW-A-05** — "통신 두절·장치 오류 시 **신규 원격 제어 명령의 실행을 제한**하고 안전 상태 유지. 복구 후 실제 상태를 재확인한 뒤 재개." 연관점: **"장애 표시, 원격 제어 잠금, 복구 후 상태 동기화"**

제 시트에 **제어가 잠긴 상태를 화면에 표시하는 항목이 없습니다.** 버튼이 눌리는데 실제로는 막혀 있으면 관제 화면으로서 위험합니다.

→ **VZ-O-05 · 제어 잠금 상태 표시** 신설 권장

## C-3. 위험도 표시 (RK-02, RK-03)
> **RK-02** — "risk_state·risk_score·evidence·recommended_action을 산출" 연관분야: **백엔드, 가시화**
> **RK-03** — "command issued / ACK received / **physical state changed** / operation completed" 4단계를 제어 이벤트에 연계

RK-03의 **4단계**가 제 3상태와 어긋납니다. 특히 `physical state changed`(실제로 움직였다)가 별도 단계로 있어요. VZ-O-02를 4단계로 맞출지 3상태로 뭉갤지 정해야 합니다.

→ **VZ-I-08 · 위험도 상태 표시** 신설 + VZ-O-02 단계 조정

## C-4. 추적·궤적·불확실성 표시 (PR-01~PR-04)
네 항목 모두 연관분야에 **가시화**가 있습니다.

- **PR-01** track_id 유지, 위치·속도·이동방향·**궤적**을 가시화에 제공
- **PR-02** 카메라 간 통합 track, **불확실 연계는 confidence와 함께 표시**
- **PR-03** 단기 궤적 **예측** 표시 (선택적 확장)
- **PR-04** 분류 confidence와 **uncertainty를 가시화에 함께 제공**

제 VZ-I-07은 **단발 탐지 박스만** 다룹니다. 궤적·추적 연속성·불확실성 표시가 빠져 있어요.

→ **VZ-I-09 · 객체 추적 및 궤적 표시** 신설 권장 (PR-03은 선택적 확장으로 표기)

## C-5. AI 실패 이벤트 표시 (OB-02)
> **OB-02** — "AI 동작 실패 시 실패 유형·컴포넌트·model_version·입력 참조·발생 시각을 **즉시 발행**" 연관분야: **백엔드, 가시화**

정상 지표(OB-01)와 **별도 경로**입니다. 제 VZ-I-04는 지표 질의만 다루는데, 실패 이벤트는 **즉시 도착하는 알림** 성격이라 다릅니다.

→ VZ-I-04에 편입하거나 별도 행

## C-6. 액추에이터 상태 표시 (HW-A-01)
> **HW-A-01** — 대기/동작 중/동작 완료/오류/**상태 확인 불가** 구분, 대기 1초·동작 중 100ms

제 VZ-U-01의 상태 4종과 **어휘가 다릅니다.** 액추에이터는 별도 상태 집합을 갖는데, 이건 §1-4의 "도메인 특화 상태는 도메인 어휘집에 등록"에 해당합니다. VZ-U-01에 **도메인 상태 표시**를 명시하면 됩니다.

# D. 확인 필요 (4건) — 제 전제가 상대 시트에서 사라짐

## D-1. 🔴 좌표 규약이 하드웨어 시트에서 사라짐
HW-R-03의 위치가 **"position(3D + frame_id + source)"에서 그냥 "위치(좌표)"로** 축약됐습니다. `frame_id`·`source`·`odometry`·앵커 보정이 조병현 시트 어디에도 없어요.

나영도 같은 걸 발견했습니다 —
> **GN-02** — "(하드웨어 개정판에 **좌표 규약 행이 명시되지 않아** 구역 사전정보 범주 내 처리 여부 **재확인 필요**)"

**제 VZ-U-02(위치 신뢰도 표시)의 전제가 통째로 흔들립니다.** 통합정립본 v3에는 확정으로 들어가 있는데 엑셀에는 없는 상태예요. 병현에게 확인해야 합니다.

## D-2. 상관키(command_id)가 하드웨어 시트에 없음
통합정립본 v3에서 **"command_id는 전 파트 단일 상관 키"**로 확정됐는데, 조병현 시트의 HW-C-06(ACK)에 언급이 없습니다. 제 VZ-O-01·VZ-U-05가 이걸 전제로 합니다.

## D-3. MQTT가 "후보 기술"로 강등됨
> **HW-C-01** — "현재 MQTT 등은 **후보 기술 또는 구현 예시로만** 두며, 백엔드가 최종 확정한 전송 인터페이스를 따른다"

제 시트의 "브라우저는 MQTT를 직접 못 쓴다" 서술을 **프로토콜 중립**으로 바꾸는 게 안전합니다. 다행히 제 구독 축은 이미 `{entity, node, channel}`이라 계약 자체는 영향 없습니다.

## D-4. 🔴 이대규 시트가 비어 있음
제가 "백엔드가 제공한다"고 적은 것들 — **WS 게이트웨이 · 질의 프록시 · 감사 조회 API · 레지스트리 조회 · RBAC** — 이 **어느 시트에도 없습니다.** 제 수신 7건 중 5건이 여기 걸려 있어요. 시트 채우는 일정을 물어봐야 합니다.

# 정리

**즉시 반영 가능** — A(연관점 ID 교체 20행), B(주기·근거 5건)
**신설 검토** — C-1(계획 승인), C-2(제어 잠금)이 특히 시급. 둘 다 팀원이 명시적으로 가시화를 지목한 항목입니다.
**질문할 것** — D-1(좌표 규약), D-2(상관키), D-4(백엔드 시트 일정)
