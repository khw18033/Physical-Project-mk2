# 작업 지시: 목 데이터를 「무엇을 · 누구에게서 기다리는가」로 바꾼다

**선행**: 탭 ②~⑥ 이식 완료 (`c3a10f5`) · 통합 앱 하나로 동작
**대상 요구사항**: `VZ-I-01`~`I-11` 수신 계열 전체 · `VZ-C-02`(외부 소스 부재 시 동작)
**기준 커밋**: 착수 시점의 `HEAD`. 작업 트리가 깨끗한 상태에서 시작한다

---

## 왜 하나

지금 통합 앱은 **모든 화면이 그럴듯하게 채워져 있다.** 영상이 재생되고, 탐지 박스가 따라다니고,
지표 그래프가 흐르고, 장치 카드에 배터리가 뜬다. **전부 목 게이트웨이가 지어낸 것이다.**

이게 두 가지 문제를 만든다.

1. **시연에서 거짓말이 된다.** 교수님이 "이거 실제로 되는 거냐"고 물었을 때 "목입니다"라고
   답해야 하는데, 화면은 이미 진짜처럼 보이는 상태다. 한 번 그렇게 보이고 나면 나머지 설명도 의심받는다.
2. **무엇이 빠졌는지 안 보인다.** 가시화는 **받아서 그리는 파트**다. 남이 안 주면 못 그리는 것이
   무엇인지가 화면에 드러나야, 다음 회의에서 "이건 누가 언제 주느냐"를 물을 수 있다.

**그래서 화면을 계약서로 만든다.** 목을 지우고 빈칸으로 두는 것이 아니라,
**그 자리에 「무엇을 기다리는지, 누가 보내야 하는지」를 적는다.**

---

## 딱 하나만 틀리면 안 되는 것 — 목이 다 같은 목이 아니다

**이 구분을 못 하면 탭①을 망가뜨린다.** 착수 전에 반드시 정리하고 시작한다.

| | 무엇 | 어떻게 |
|---|---|---|
| **A. 남이 줄 데이터** | 다른 파트가 생산해 우리에게 오는 것. 영상·탐지·지표·장치 상태·감사 이력·레지스트리·위험도… | **자리표시로 바꾼다** |
| **B. 우리가 만드는 목** | 임무 시나리오(`MSN-260826-01`) · 8상태 전이 · 결함 주입 · 되감기 · 노드 그래프 | **그대로 둔다** |
| **C. 상대가 아직 없는 것** | 계약 자체가 없거나 상대 파트 시트에 항목이 없는 것 | **자리표시 + 「상대 없음」 표시** |

**B를 건드리지 않는 이유**가 중요하다. 임무 시나리오는 "아직 못 받은 데이터"가 아니라
**논문의 측정 대상**이다. 결함 주입 60건으로 축소율·재현율을 재는 것이 F14의 실험 설계이고,
그건 **근본 원인을 아는 합성 데이터라야 성립한다**(논문 문서 §측정축). 여기에 자리표시를 넣으면
실험이 없어진다. 탭①의 그래프·상태·되감기는 **지금 그대로가 완성된 모습**이다.

**다만 탭① 안에도 A가 섞여 있다.** 액션 아이템 팝업의 **로봇 상태 스트립**(배터리·RSSI·지연·IP·
펌웨어·관절 온도·하트비트)은 하드웨어가 줄 데이터다(`HW-R-02`·`HW-R-03`·`HW-C-04`).
**임무는 우리 것, 장비 실측값은 남의 것** — 이 선으로 가른다.

## 목 게이트웨이를 끄는 것이 아니다

목 게이트웨이는 **개발과 검증에 필요하다.** `verify:one-gateway` 가 "데이터가 실제로 온다"를
검사하고, 재접속·구독 복원·캐시 정책도 목이 있어야 확인된다. **게이트웨이는 그대로 둔다.**

**결정하는 것은 화면이다.** 데이터가 와도 화면은 기본적으로 자리표시를 그린다.

- **기본값 = 자리표시.** 앱을 그냥 띄우면 A 항목이 전부 자리표시다.
- **개발용 토글**로 목 렌더를 켤 수 있다. 상단 공통 바에 둔다.
- **목 렌더 중에는 화면에 계속 목 배지가 떠 있어야 한다.** 토글을 켠 것을 잊고 시연하면
  원래 문제로 되돌아간다. 배지는 끌 수 없다.
- `verify:placeholder-default` 로 **기본값이 자리표시인지** 검사한다. 대조군은
  기본값을 목 렌더로 바꾼 사본이고, 그게 실패로 잡혀야 한다.

이렇게 하면 `verify:one-gateway` 도 그대로 통과한다 — 게이트웨이는 여전히 발행하고
데이터 계층도 여전히 받는다. 바뀌는 것은 **그리는 층뿐이다.**

## 자리표시가 담아야 하는 것 — 네 가지

사용자 예시가 요구한 두 가지(**어떤 데이터인가 · 어떤 담당이 보내는가**)에 둘을 더한다.
회의에서 바로 짚을 수 있어야 하기 때문이다.

```
┌────────────────────────────────────────────────────────┐
│  객체 탐지 영상 연결 예정                                  │
│                                                        │
│  무엇          영상 스트림 + 탐지 박스 + 추적 궤적            │
│  누가 보내나    하드웨어 → AI → 백엔드                      │
│                HW-R-07 관제용 고해상도 영상(온디맨드)         │
│                HW-S-06 고정 비전센서(CCTV) 영상            │
│                AI-C-08 미디어 입력 관리                    │
│                BE-T-05 사설 IP 라우팅·프록시 중계            │
│  우리 자리      VZ-I-06 · VZ-I-07 · VZ-I-09              │
│  경로          미디어 평면 — 업무·관측 브로커에 싣지 않는다     │
│                (AI-C-14)                                │
└────────────────────────────────────────────────────────┘
```

1. **무엇을 기다리는가** — 데이터 이름. 사람 말로.
2. **누가 보내는가** — **파트 이름과 상대 요구사항 ID.** 사람 이름은 쓰지 않는다.
   파트가 여럿을 거치면 순서대로 적는다(하드웨어 → AI → 백엔드).
3. **우리 쪽 자리** — `VZ-*` ID. 이게 있어야 "우리가 안 만든 게 아니라 못 받은 것"이 증명된다.
4. **경로** — 업무 평면 / 관측 평면 / 미디어 평면 중 어디로 오는가. 세 평면을 나눈 이유가
   여기서 드러난다(`DF-1b`).

**상대가 없으면 그렇게 적는다.** `[상대 없음 — 회의 안건]` 을 눈에 띄게 붙인다.
없는 것을 있는 것처럼 적는 쪽이 훨씬 나쁘다.

## 제약 — 반드시 지킬 것

1. **`web-dashboard/` · `stt-lab/` 을 한 줄도 고치지 않는다.** 기준선이다. 검증 7종이 계속 통과해야 한다.
2. **게이트웨이의 발행을 지우지 않는다.** 화면이 그릴지 말지를 정한다(§목 게이트웨이를 끄는 것이 아니다).
3. **탭①의 임무 계열을 건드리지 않는다.** 위 B 항목. 논문 실험이 걸려 있다.
   단 로봇 상태 스트립은 A다.
4. **사람 이름을 쓰지 않는다.** 「하드웨어 파트」「AI 파트」「백엔드 파트」로 적는다.
   문서 전체가 이미 그 규칙이다(HCI 팀원 표기와 같은 이유).
5. **상대 ID를 지어내지 않는다.** 현행 엑셀에 있는 것만 쓴다. 없으면 「상대 없음」이다.
6. **자리표시 문구를 한 곳에 모은다.** 화면마다 하드코딩하지 않는다.
   `src/shared/pendingSources.ts` 같은 한 파일에 표로 두고 화면은 ID로 참조한다.
   상대 요구사항이 또 바뀔 것이기 때문이다.
7. **레이아웃을 무너뜨리지 않는다.** 자리표시는 원래 그 자리의 **크기를 유지**한다.
   나중에 진짜 데이터가 오면 그 자리에 그대로 들어가야 한다. 화면이 텅 비어 보이면 실패다.
8. **단독 빌드를 지킨다.** `verify:standalone` 통과, 번들 크기를 기록한다.
9. **의존성을 늘리지 않는다.**

## 단계

### 1단계 — 대조표부터 만든다 (코드보다 먼저)

**이 표가 이번 작업의 명세다.** 화면을 먼저 고치면 무엇을 빠뜨렸는지 알 수 없다.

앱을 띄우고 탭 여섯을 다 돌면서 **화면에 보이는 값 하나하나**를 A/B/C로 분류한다.

| 탭·자리 | 지금 화면에 뜨는 것 | 분류 | 무엇 | 누가(상대 ID) | 우리 자리 | 평면 |
|---|---|---|---|---|---|---|
| 예) 탭⑤ 영상 | 합성 영상 + 탐지 박스 | A | 영상 + 탐지 + 궤적 | HW-R-07 · HW-S-06 · AI-C-08 · BE-T-05 | VZ-I-06·07·09 | 미디어 |
| 예) 탭① 그래프 | 태스크 8상태 전이 | B | — | — | VZ-D-* | — |

**빠뜨리기 쉬운 자리를 미리 적어 둔다.** 이것만 있는 것은 아니니 직접 다 돌아본다.

- 탭② — 장치 카드의 배터리·하트비트·연결 상태, 위험도 패널(`VZ-I-08`)
- 탭③ — 액추에이터 상태·개도율, 감사 이력 조회 결과(`VZ-I-05`)
- 탭④ — 시계열 그래프 전부, 구역 요약(`VZ-I-04`)
- 탭⑤ — 영상·탐지·궤적(`VZ-I-06`·`07`·`09`)
- 탭⑥ — 파이프라인 카탈로그(등록처 기반)
- 공유 — 레지스트리 목록(`VZ-I-03`), 역할·권한(`VZ-C-01`), AI 실패 알림(`VZ-I-10`)
- 탭① — **로봇 상태 스트립만** A

**판정 기준**: 표가 다 찼고, A로 분류한 항목 중 상대 ID가 빈 것이 「상대 없음」으로 표시돼 있다.
**이 표를 보고서에 그대로 싣는다.**

### 2단계 — 자리표시 부품과 표

- `src/shared/pendingSources.ts` — 1단계 표를 자료 구조로. ID · 제목 · 무엇 · 보내는 파트와 상대 ID ·
  우리 `VZ-*` · 평면 · 상대 없음 여부.
- `src/shared/PendingSource.tsx` — 자리표시 컴포넌트 하나. **크기를 부모에서 받는다**(제약 7).
- 상단 공통 바에 **목 렌더 토글**. 기본 꺼짐. 켜면 화면 어딘가에 지워지지 않는 목 배지.

### 3단계 — 화면 교체 (탭 하나씩, 검증 돌리며)

1단계 표의 A 항목만 바꾼다. **탭 하나 끝날 때마다 `typecheck` 와 관련 verify를 돌린다.**

### 4단계 — 검증 하나

- **`verify:placeholder-default`** — A로 분류한 자리가 **기본 상태에서 자리표시를 그리는지**,
  자리표시마다 **네 가지가 다 채워져 있는지**(빈 상대 ID는 「상대 없음」 문구가 있어야 통과),
  그리고 **기본값을 목 렌더로 바꾼 대조군이 실패로 잡히는지**.

기존 verify 11종이 전부 그대로 통과해야 한다. 특히 `one-gateway`(데이터는 여전히 온다)와
`standalone`(번들이 늘지 않았다).

### 5단계 — 문서

- `요구사항정의서.md` — 1단계 표에서 나온 **「상대 없음」 항목을 7장 미결에 올린다.**
  위 §읽다가 나올 것 세 건도 함께.
- `가시화_프로토타입_설명서.md` — 화면 설명에 "무엇이 자리표시이고 무엇이 우리 목인지" 한 절 추가.
- `현재상황_읽기순서.txt` — 시연 시 목 렌더 토글을 켜지 말라는 주의.

## 완료 판정

1. 앱을 그냥 띄우면 **A 항목이 전부 자리표시**다. 진짜처럼 보이는 남의 데이터가 없다.
2. 자리표시마다 **무엇 · 누가(상대 ID) · 우리 자리(`VZ-*`) · 평면** 넷이 다 적혀 있다.
3. **탭①의 임무 계열은 작업 전과 똑같이 동작한다.** 그래프·8상태·되감기·실패 경로 격리·STT.
4. 목 렌더 토글을 켜면 예전처럼 그려지고, **지워지지 않는 목 배지가 뜬다.**
5. 자리표시가 원래 자리의 **크기를 유지**한다. 레이아웃이 무너지지 않았다.
6. `verify:placeholder-default` 통과 (대조군 검출 포함). 기존 11종도 전부 통과.
7. `web-dashboard` · `stt-lab` diff 0.
8. 1단계 대조표가 보고서에 실려 있다.
