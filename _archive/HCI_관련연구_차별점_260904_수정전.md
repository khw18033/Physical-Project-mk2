# 2. 국내 HCI 지형에서 우리가 서는 자리 (한 장으로)

```
        일반 사용자 대상                                   전문 사용자 대상
   ┌──────────────────────────────┐          ┌──────────────────────────┐
정 │ 앱·키오스크·웹사이트 UI 비교   │          │ H3-1 웹 분석도구 UX       │
적 │ 어포던스·게슈탈트·레이아웃     │          │ H3-2 사용자 여정 분석도구  │
   │ (KCI에 수백 편 — 이길 수 없다) │          │ H3-4 관제요원용 트래픽 화면 │
   └──────────────────────────────┘          └──────────────────────────┘
   ┌──────────────────────────────┐          ┌──────────────────────────┐
계 │ H2-4 미술관 가이드 인지부하    │          │ H1-1 CSN 계층적 뷰 관리    │
층 │ H2-5 인포그래픽 인지부하       │          │ H1-2 방화벽 계층 가시화     │
   │                              │          │ H3-3 MES 계층 스토리텔링    │
   └──────────────────────────────┘          └──────────────────────────┘
                                             ┌──────────────────────────┐
시                    (거의 없음)             │        ★ 우리 자리 ★      │
간                                            │ 계층 + 시간축 + 실패 격리  │
축                                            │ 전문 사용자 3계층 왕복     │
                                             └──────────────────────────┘
```

**빈칸이 주장이다.** 국내 HCI 논문에서 **「계층」과 「시간축 되감기」가 한 화면에 같이 있는 사례가 없다.**
계층은 있어도 정적이고(H1-2 정책, H1-1 뷰 스택), 시간은 있어도 평면이다(H3-1 추세 그래프).

# 3. 계열 H1 — 계층 탐색과 정보 구조

**H1-1. Contextual Stack Navigator: 시각적 탐색 지원을 위한 공간적 맥락 인지형 계층적 뷰 관리 인터페이스** ★★★
김병민 외 4인 · 한국차세대컴퓨팅학회 논문지 21(1) · pp.91~100 · 2025.02
탐색 중 만든 뷰를 **계층 구조로 저장**하고 시각 단서로 맥락을 준다. **"기존 스냅샷 방식은 뷰 간 관계 파악이 어렵고 인지적 부담을 늘린다"**는 문제 제기. 저수준 작업 분류(Low-level Task Taxonomy)로 유용성 검증.
- **쓰는 자리**: F11 드릴다운 화면 설계 근거 / §3-2 상호작용 횟수 측정 방법론
- **우리와의 차이**: CSN의 계층은 **사용자가 탐색하며 쌓은 것**, 우리 계층은 **시스템이 실제 실행한 임무 구조**. CSN에는 시간축도, 실패 개념도 없다

**H1-2. 방화벽 접근정책의 계층적 가시화 방법에 대한 연구** ★★

- **쓰는 자리**: REQ-1103(하향 드릴다운)·REQ-1105(역할별 기본 뷰)의 국내 직계 선행

# 4. 계열 H2 — 설명가능성과 인지부하

**H2-1. XAI 설명 수준이 인지부하 및 사용자 만족도에 미치는 영향: 금융 AI 시스템의 리스크 수준을 중심으로** ★★★
한노아·황유진·이준기 · 한국컴퓨터정보학회논문지 29(9) · pp.49~59 · 2024.09
참가자 **120명을 8집단**으로 나눠, **위험 수준에 따라 설명의 정보량이 인지부하·만족도에 미치는 영향이 유의하게 다르다**는 것을 요인분석·판별타당성으로 확인.
- **쓰는 자리 ①**: **REQ-1105(역할별 기본 추상화 수준)의 실증 근거.** "왜 L0/L1/L2에 다른 깊이를 주는가"에 국내 실험으로 답한다
- **쓰는 자리 ②**: **§3-3 사용자 실험의 설계 템플릿.** 집단 분할·설문 구성·분석 기법을 그대로 참조
- **주의**: 저쪽은 n=120이고 우리는 n=12~18이다. **그래서 정량 축(§3-1·D·E)이 본체이고 사용자 실험은 보강**이라는 기조가 옳다 — 이 논문이 그 판단을 뒷받침한다

# 5. 계열 H3 — 분석 도구의 UX (우리와 **사용자층이 같은** 유일한 계열)

> **이 계열이 이 문서에서 제일 중요하다.** 국내 HCI 논문 대부분은 "일반 사용자가 서비스를 쓴다"인데,
> 아래 여섯은 **"전문 사용자가 도구를 써서 무언가를 알아낸다"**를 다룬다. 우리 논문의 이웃이다.

# 8. 내세워야 할 HCI 차별점 — 넷으로 좁힌다

> **넷만 쓴다.** 다섯 개가 되는 순간 심사자가 "그래서 기여가 뭐냐"고 묻는다.

## 차별점 1 — 계층이 실행에서 생성된다 (vs H1-1 · H1-2 · H1-3)

국내 계층 UI 논문의 계층은 전부 **미리 정해진 구조**다.
회로의 포함관계, 방화벽 정책 분류, 데이터 큐브 차원, 사용자가 쌓은 뷰 스택 — 모두 **화면을 열기 전에 이미 있다.**

우리 계층은 **임무가 실행되면서 만들어지고 실행마다 달라진다.**
그래서 우리 화면은 "계층을 보여준다"가 아니라 **"이번 실행의 계층은 이랬다"**를 보여준다.
**되감기가 필요한 이유가 여기서 나온다** — 계층 자체가 시간에 따라 변하기 때문이다.

> **한 문장으로**: 기존 계층 UI는 *구조를 탐색*하고, 우리는 *실행을 탐색*한다.

## 차별점 2 — 공시적 관제와 통시적 분석을 한 앱이 갖는다 (vs H3-1 · H3-4)

H3-1이 **국내 용어를 그대로 준다** — 분석 도구가 **공시적(지금 상태)** 위주이고 **통시적(흐름)** UI가 없다는 진단.
H3-4의 관제 화면도 공시적이다.

우리 앱은 **공시적인 것(장치·제어·지표·영상)과 통시적인 것(임무 실행 기록)** 이
**같은 registry·같은 장비 목록** 위에 선다. 우리 통시성은 평면 추세 그래프가 아니라
**계층 구조를 가진 기록의 되감기**다.

> **근거로 붙일 문장**: H3-1의 공시/통시 구분 · H3-5의 「누적 정도·점진적 전환」

### ⚠ 이 차별점은 2026-09-03까지 **주장이 화면과 어긋나 있었다**

v1.0의 문장은 이랬다 — *"탭②~⑤가 공시적, 탭①이 통시적이고, 화면을 바꾸지 않고 넘어간다."*
**뒷절이 사실이 아니었다.** 탭②~⑤와 탭① 사이를 오가는 것이 바로 화면을 바꾸는 일이고,
옮기는 순간 「어느 태스크를 보고 있었는지」가 화면에서 사라진다. 심사자가 화면을 한 번만
보면 걸릴 자리였다.

그리고 그 지적을 **이 문서가 인용한 논문 둘이 이미 하고 있다.**

| 논문 | 이미 한 지적 | 탭 판에 그대로 해당 |
|---|---|---|
| `H1-1` CSN | "스냅샷 방식은 **뷰 간 관계 파악이 어렵고** 인지적 부담을 늘린다" | 탭 다섯은 관계가 화면에 없는 스냅샷 다섯이다 |
| `H1-4` | 종속변인 **「방향감 상실」** | 탭 전환이 정확히 그 변인을 키운다 |

**v1.1에서 탭을 없앴다.** 공시적 화면들은 **뷰 노드**가 되어 통시적 그래프 옆에,
그 태스크에 **선으로 이어진 채** 놓인다. 이제 "지금 이상하다 → 그때 왜 그랬나"가
정말로 **한 화면 안에서** 일어난다. `CSN`이 "탐색하며 쌓은 뷰의 관계를 보존하자"고 한 것을,
우리는 **연결선으로 화면에 남기는** 방식으로 한다 — CSN의 계층은 사용자가 쌓은 것이고
우리 연결은 **실행 구조에 붙는다**는 점이 다르다.

> **한 문장으로**: 기존 분석 도구는 *화면을 갈아 끼우며* 공시와 통시를 오가고,
> 우리는 *한 캔버스 위에서* 오간다.

## 차별점 3 — 설명이 읽기 전용이 아니다 (vs H2-1 · H2-3 · H2-2)

H2-1은 **설명의 깊이가 인지부하를 좌우한다**는 것을 n=120으로 증명했다 — 우리 L0/L1/L2의 근거다.
H2-3은 **"설명을 만질 수 없다"**를 문제로 잡았고, H2-2는 **what if**를 인터페이스로 만들었다.

우리는 셋을 한 화면에서 합친다.
**깊이를 고를 수 있고(L2↔L1↔L0), 만질 수 있고(정지·재실행·파라미터 수정·결함 주입), 반사실을 돌릴 수 있다(F-B).**
국내에 이 셋이 함께 있는 인터페이스 논문은 없다.

> **주의**: REQ-1207(LLM 관여 표시)을 반드시 화면에 남긴다.
> 관측된 사실과 모델이 만든 해석이 구별되지 않으면 위 주장 전체가 무너진다.

## 차별점 4 — 사용자 계층을 왕복하는 단일 도구 (vs H2-1 · H3-4 · H1-1)

H2-1은 설명 깊이를 다뤘지만 **한 종류 사용자**만 본다. H3-4는 **관제요원 전용**이다.
H3-3만이 업무 환경을 조절변인으로 두었으나 **역할 간 이동은 없다.**

우리는 L2(결심자) → L1(운영자) → L0(개발자)를 **하나의 자료 구조 위에서 왕복**한다.
더블클릭으로 내려가고, 접어서 올라온다. **이것이 F11의 설명가능성 정의 그 자체다.**

> **실험으로 만들 것**: 같은 결함 과제를 세 사용자 계층에 주고
> **각 계층에서 근본 원인에 도달하는 데 필요한 상호작용 횟수**를 잰다(§3-2·§3-3).

# 10. 공동 저자에게 넘길 결정 셋

1. **§6-2 — 트리안을 초안 단계에서 같은 완성도로 만들 것인가.**
   H3-3이 「두 패턴 동일 설계 + 조절변인」으로 했다. **권고: 같은 방식(권고안 1).** 초안 착수 전에 정한다.
2. **종속변인 세트 확정.**
   후보: 정답률 · 근본 원인 도달 시간 · **상호작용 횟수**(H1-1) · **방향감 상실**(H1-4) · NASA-TLX · SUS.
   **권고: 상호작용 횟수를 주 지표로, 방향감 상실을 계층 깊이 부작용 지표로 넣는다.**
3. **피험자 미확보 시 대안.**
   H4-2(전문가 평가 + 사용자 평가 병행)로 내려간다. **이 경로를 미리 문서로 확정해 둔다.**
4. **탭/캔버스 요인을 실험에 넣을 것인가** *(2026-09-03 신설)*
   넣으면 조건이 2×2×2로 늘어 n이 부족해진다. **권고: 요인 B(탭/캔버스)를 넣고 격리 요인을
   빼거나, 요인 B를 별도의 소규모 A/B로 분리한다.** 탭 판이 이미 동작하는 빌드로 남아 있어
   (`5tab-baseline` 태그) **구현 비용은 0**이다 — 넣지 않을 이유가 일정이 아니라 표본 크기뿐이다.

| 항목 | 값 | 근거 |
