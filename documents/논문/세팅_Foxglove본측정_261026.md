# Foxglove 본 측정 — 세팅과 순서

**날짜** 2026-10-26
**설계** `실험설계_Foxglove비교_261023` — 질의 여섯·세는 법·공정성 조건은 그 문서가 정했다
**경로** `측정기록_Foxglove경로찾기_261025` — 질의 넷의 길은 이미 찾았다
**이 문서** 무엇을 어느 판으로, 어떤 화면에서, 어떤 순서로 **세는가**

> **이제부터 센다.** 길 찾기 단계는 끝났다.

---

## 0. 가장 중요한 것 — 양쪽을 다 센다

지금까지 Foxglove 쪽만 봤다. **본 측정은 우리 도구도 똑같이 센다.** 한쪽만 세면 비교가 아니다.

| | |
|---|---|
| 재는 것 | **같은 물음에 닿기까지의 조작** |
| 양쪽 | 우리 도구(다시보기) · Foxglove |
| 조건 | 가(기본 화면에서 시작) · 나(꾸민 화면에서 시작) |
| 안 재는 것 | 시간. 피험자가 없다(설계 3절) |

## 1. 쓸 판 — 둘이면 된다

설계는 판 셋을 말했는데 실제로는 **둘로 질의 여섯이 다 커버된다.**

### 주 판 — `261026/010205_MSN-260909-01`

**한 판에 원인 사슬이 네 단계로 들어 있다.**

```
  5.03초  commanded  cmd-o0n547tv  scan_mission (응답 15줄)
 53.70초  commanded  cmd-o0o6opyj  abort        ← 사람이 누른 일시정지
 57.71초  expired    cmd-o0o6opyj  4000ms 안에 답 없음
141.89초  answered   cmd-o0n547tv  「대기 풀림 · 92.7초 기다림」   ← 늦게 효력
145.93초  failed     T-A3          ABORTED · aborted_by_command
```

**「T-A3 는 왜 실패했나」를 물으면 네 단계를 따라가야 한다.** 실패 사유 → 그 명령 → 그 명령의 무응답 → 뒤늦은 효력. 측정 대상으로 이보다 좋기 어렵다.

| | |
|---|---|
| 사건 | 59건 · 155.2초 |
| 실패 태스크 | **T-A3** |
| `expired` | 1건 (Q3) |
| `created` | 17건 (Q5) |
| MCAP | `010205_MSN-260909-01.mcap` |

### 보조 판 — `261026/024124_MSN-260909-01`

**Q6 전용.** `adjusted` 2건(`speed 0.35→0.25` · `clearance 0.18→0.30`)이 든 유일한 판이다. 실패 태스크는 T-B1.

| MCAP | `trace.mcap` *(이름이 다르다 — 다른 판은 `<판이름>.mcap`)* |
|---|---|

### 쓰지 않는 판

완주 판(`015835`)은 실패가 없어 질의 대상이 없다. `210837` 은 `created` 가 0이라 Q5 를 못 본다. 둘 다 MCAP 은 뽑아 뒀으니 필요하면 쓴다.

## 2. 조건 가·나

| | 출발점 | 재는 것 |
|---|---|---|
| **가** | 판을 연 **직후의 기본 화면** | 한 번만 보는 비용 |
| **나** | 그 도구에서 할 수 있는 **최선으로 꾸민 화면** | 되풀이해 보는 비용 |

**꾸미는 비용은 따로 한 줄로 적고 질의마다 나누지 않는다**(설계 3절).

> **우리 도구는 가와 나가 같을 수 있다.** 꾸밀 것이 없다 — 노드를 누르면 명령 표가 나온다. 그러면 「꾸미는 비용 0 · 두 조건 같음」으로 적는다. **그것도 결과다.** 억지로 다르게 만들지 마라.

## 3. Foxglove 세팅

### 패널 넷 — 표준 배치

```
┌──────────────────────────┬──────────────────────────┐
│ ① Raw Messages           │ ② State Transitions      │
│   — 명령 조회             │   — 띠 (계열 셋)          │
├──────────────────────────┼──────────────────────────┤
│ ③ Raw Messages           │ ④ Table                  │
│   — 돌려 쓰는 칸          │   — 목록 조회             │
└──────────────────────────┴──────────────────────────┘
```

### 조건 가 — 파일을 열고 **아무것도 안 꾸민 상태**에서 시작

판을 열면 기본 레이아웃(3D · Image 등)이 뜬다. **그 상태가 출발점이다.** 질의마다 거기서 시작해 패널을 만들고 경로를 치는 것까지 센다.

### 조건 나 — 위 배치를 미리 꾸며 두고 시작

패널 넷을 띄우고 경로를 비워 둔 상태가 출발점이다. **꾸미는 데 든 조작을 따로 세어 적는다.**

### 경로 — `010205` 기준

```
①  /mission/action{payload.taskId=="T-A3"}
②  계열1  /mission/action/response{payload.taskId=="T-A3"}.payload.line
    계열2  /mission/task{nodeId=="T-A1"}.status
    계열3  /mission/task{nodeId=="T-A2"}.status
③  Q2 → /mission/action/response{payload.taskId=="T-A3"}.payload.line
    Q3 → /mission/action{kind=="expired"}
    Q5 → /mission/task{nodeId=="T-A3"}{kind=="created"}.producedBy
④  Q6 → /mission/human            ← 표 (최신 1건만 보인다)
    Q6 계열  /mission/human.payload.after   ← 띠로 두 건 갈림
    Q6 계열  /mission/human.payload.before
```

**③이 Q2 → Q3 → Q5 를 그 순서로 돌려 쓴다.**

> **Q6 경로 바로잡음 (261026)** — `adjusted` 는 변환기 `topic_of()` 의 `HUMAN_KINDS` 에
> 걸려 `/mission/human` 으로 간다. `/mission/task` 에는 `producedBy=="human"` 인 줄이
> 하나도 없다. 앞판에 적혀 있던 `/mission/task{producedBy=="human"}` 은 틀린 경로였고,
> 그 경로로는 세 패널 모두 `Waiting for next message...` 에서 멈춘다.
>
> 판 `024124` 의 `/mission/human` 은 두 건뿐이다.
>
> | atSec | nodeId | field | before | after |
> |---|---|---|---|---|
> | 112.395 | T-B1 | speed | 0.35 | 0.25 |
> | 140.858 | T-B1 | clearance | 0.18 | 0.30 |

### 잊지 말 것

- **⏮ → ▶ 로 한 번 돌린다.** Raw Messages 와 Table 은 재생 머리가 메시지를 지나가야 찬다. 155초짜리라 배속을 올려도 된다. **그 「한 번 돌리기」도 조작에 든다**
- **확대하지 마라.** 재생 범위가 묶인다
- 문자열은 반드시 따옴표로

## 4. 우리 도구 세팅

### 조건 가 — 기본 화면

```
◷ 임무 이력 → 261026 → 010205_MSN-260909-01 → 「다시보기」
```

여기까지가 **판을 여는 비용**이고, Foxglove 의 「파일 열기」와 같은 자리다. **출발점 이전이라 안 센다**(설계 3절).

연 직후 화면이 출발점이다.

### 조건 나

꾸밀 것이 있으면 꾸미고 그 비용을 적는다. 없으면 **「꾸밀 것 없음 · 가와 같음」**으로 적는다.

## 5. 질의 여섯 — 무엇이 정답인가

**정답을 미리 적어 둔다.** 그래야 「닿았다」를 판정할 수 있다.

| | 묻는 것 | 정답 (`010205`) |
|---|---|---|
| **Q1** | T-A3 가 낸 명령 | `scan_mission`(5.03초) · `abort`(53.70초) · `abort`(155.23초) **셋** |
| **Q2** | `cmd-o0n547tv` 의 응답 줄 | **15줄.** 마지막이 「ABORTED · aborted_by_command」(145.93초) |
| **Q3** | 53.70초 `abort` 는 늦은 것인가 끝내 안 온 것인가 | **끝내 안 왔다.** 57.71초 기한 사건 · 4000ms |
| **Q4** | T-A3 실패 시점(145.93초)에 T-A1·T-A2 상태 | 둘 다 **완료** |
| **Q5** | T-A3 의 계획값을 누가 만들었나 | **`backend`** (`created` 사건 · 0초) |
| **Q6** | 사람이 바꾼 값과 그 전후 *(판 `024124`)* | `speed 0.35→0.25`(112.4초) · `clearance 0.18→0.30`(140.9초) |

### 판정 셋

| | 뜻 |
|---|---|
| **닿는다** | 그 도구가 답을 직접 보여준다 |
| **눈으로 맞춰야 한다** | 두 자리를 사람이 대조해야 답이 나온다 |
| **안 닿는다** | 어떤 조작으로도 답에 못 간다 |

**가운데를 아끼지 마라.** 시각 보고 두 토픽을 대조해 알아낸 것은 닿은 것이 아니다. 그걸 「안 닿는다」로 적으면 과장이다.

## 6. 기록지

질의마다 **네 칸 × 두 도구 × 두 조건**.

```
판: _______  질의: Q_  도구: 우리 / Foxglove  조건: 가 / 나

조작:  1. ______________  2. ______________  3. ______________
       4. ______________  5. ______________  ...

조작 수: ____
판정:    닿는다 / 눈으로 맞춰야 한다 / 안 닿는다
답:      ______________________________
정답과 같나: 예 / 아니오
```

**조작을 하나씩 적는다.** 합계만 적으면 설계 7절의 「경로 전문」이 안 나오고, 그게 없으면 조작 수는 믿을 근거가 없는 숫자다.

꾸미는 비용은 조건마다 한 줄:

```
조건 나 · 꾸미는 비용 — 우리: ____  Foxglove: ____
```

## 7. 순서

**질의마다 양쪽을 연달아** 한다. 판마다 도구를 바꾸지 않는다 — 같은 기준으로 세려면 그래야 한다.

```
1.  조건 가 · Q1  →  우리 · Foxglove
2.  조건 가 · Q2  →  우리 · Foxglove
3.  …  Q5 까지
4.  판을 024124 로 바꿔 조건 가 · Q6
5.  그다음 조건 나 로 같은 순서
```

**조건 가를 전부 끝내고 나로 간다.** 꾸며 놓고 기본으로 돌아가면 이미 길을 알고 있어 기본 조건이 오염된다.

### 하루에 다 하지 마라

열두 칸(여섯 × 두 조건)을 한 번에 하면 뒤로 갈수록 익숙해져 수가 줄어든다. **조건 가를 한 번에, 조건 나를 다른 때에** 하는 쪽이 낫다.

---

## 8. 끝나면

설계 7절의 표 둘을 채운다.

- **표 가 — 닿는가** (주장의 본체)
- **표 나 — 조작 수** (보조)
- 경로 전문을 부록으로

그리고 **설계 8절을 읽는다.** Foxglove 가 여섯을 비슷한 조작으로 다 답했으면 **축을 뺀다.** 결과를 보고 정하는 것이 아니라 미리 정해 둔 기준에 대본다.

§3-4 와 §5-5 가 채워지면 **측정축 여섯이 전부 찬다.**
