# 작업 보고: 객체 탐지 상태판 — 지정 탐지 대상을 장비별로(`targets_device` 먼저)

**관련**: 앞 작업 [`2026-11-24_탐지모델상태판.md`](2026-11-24_탐지모델상태판.md) ·
대상이 프로세스 단위라는 합의 [`../협의/스캔탐지_창구_계획_261124.md`](../협의/스캔탐지_창구_계획_261124.md) §180
**상태**: **가시화 쪽은 끝났다.** 고친 요약 함수를 실제 Redis 결과(go1 · pi12)에 돌려 장비별로 갈리는 것을 확인했다.
상태판 화면에 뜬 모습은 아직 못 봤다.

> 한 줄 요약 — go1 에 person, pi12 에 chair 를 따로 줬는데 객체 탐지 카드에는 둘 다 「person · chair」로 떴다. data_stream 결과의
> `targets` 는 프로세스 전체를 합친 목록이고, 장비별 대상은 새 칸 `targets_device` 에 있었다. 가시화가 그 칸을 먼저 읽게 고쳤다.
> data_stream 코드는 고치지 않았다.

---

## 1절 — 무엇이 문제였나

### 증상

data_stream 에서 go1 에는 `person`, pi12 에는 `chair` 를 지정했다. 실제 탐지는 따로 됐는데, 상태판 카드에는 두 장비 모두
「person · chair」로 떴다.

### 실측 (Redis `vision_stream:<소스>:targeted` 마지막 한 건, 읽기 전용 `XREVRANGE`)

| 소스 | `targets` | `targets_device` | `provisional` | 실제 검출 |
|---|---|---|---|---|
| `robot1`(go1) | `[person, chair]` | `[person]` | `[person, chair]` | — |
| `pi12` | `[person, chair]` | `[chair]` | `[person, chair]` | chair 3 |

- 비전 프로세스 하나가 두 장비를 맡는다. `targets` · `provisional` · `cues` 는 그 장비들의 대상을 **합친** 값이다. 원래 합의도 대상을
  프로세스 단위로 정했다(협의 §180).
- 장비별 대상은 `targets_device` 에 따로 실린다. 11-24 · 25 의 결과(`ep-001` · `pi13` · `cam360`)에는 이 칸이 없다 — data_stream 에
  그 뒤 새로 생긴 칸이다.

### 가시화 쪽 원인

창구 요약 `summarizeVisionEntry` 가 `result.targets` 만 꺼내고 `targets_device` 는 버렸다. 그 값을 `targetInfo` 가 「런처 설정」 대상으로
그대로 써서 카드 줄 · 상세 대상 칩 · 변경 기록이 모두 합친 목록을 보였다. Redis 키는 소스별이라 장비끼리 섞인 것은 아니다.

## 2절 — 무엇을 고쳤나

| 파일 | 바뀐 것 |
|---|---|
| `scripts/vision-redis-latest.mjs` | `targets_device` 가 비어 있지 않으면 그것을 `targets` 로. 원래 목록은 `targetsAll`, 어디서 왔는지는 `targetScope`(`device` · `all`). `provisional` 은 장비 대상 안의 것만 |
| `src/detect/status/latestStore.ts` | `RedisLatest` 에 `targetsAll` · `targetScope` |
| `src/detect/status/targets.ts` | `TargetInfo.processTargets` — 프로세스 전체가 이 장비 대상과 **다를 때만**. 이 화면의 스캔 판(mission)에서는 null |
| `src/detect/status/views/DetectStatusParts.tsx` | 상세 「지정 탐지」 칸에 「같은 프로세스 전체」 한 줄(흐리게). 카드 한 줄에는 안 적는다 |
| `src/i18n/ko.ts` · `en.ts` | `dms.tg.processTargets` |
| `scripts/verify-detect-status.mjs` | 아래 3절 |

변경 기록(「대상 바뀜」)은 `info.targets` 를 비교하므로 따로 손대지 않아도 장비별 대상으로 비교한다.

### 정한 것

- **`targets_device` 가 빈 목록이면 `targets` 로 내려간다.** 빈 목록의 뜻(지정 없음 · 아무것도 안 찾음)을 data_stream 에서 확인하지 못했다.
  칸이 없는 옛 판과 같게 다룬다.

## 3절 — 검사

`npm run verify:detect-status` 통과. 더한 것:

- 실측 모양 그대로 — go1 은 `person` 만, pi12 는 `chair` 만, `provisional` 도 장비 대상 안의 것만
- 대조군 — `targets_device` 가 없거나 빈 옛 판은 `targets` 를 쓴다
- 상세에 프로세스 전체가 따로 보인다 / 대조군 — 같거나 옛 판 · 이 화면의 판이면 안 적는다

그 밖에 `tsc -b` · `verify:dict-shape` · `verify:i18n-data` · `verify:i18n-no-frozen` 통과.
실제 Redis(`100.125.104.23:6380`)에 고친 `readLatest` 를 돌려 `robot1 → [person]` · `pi12 → [chair]` 를 확인했다.
