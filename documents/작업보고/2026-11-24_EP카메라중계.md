# 작업 보고: RoboMaster EP 카메라 — 로봇 노드의 H.264 WebSocket 중계를 화면에서 받는다

**날짜**: 2026-11-24
**커밋**: 이 보고서와 같은 커밋 — 브랜치 `khw_VZ`
**관련**: HW `pi/robot/ep_camera.py` · `_media_status`(HW 커밋 `bfec5dd`) · 같은 날 추론 스트림 10004 → `ep-001`(`2bec1b5`)
**상태**: **가시화 쪽은 끝났다. 실물 확인 기록은 없다.** 이 작업은 다른 세션에서 했고, 커밋 전에 코드 · 검사로 다시 확인했다
(`verify:ep-camera` · `verify:connection-panel` · 타입 검사 통과). EP 를 붙여 실제 영상이 뜨는지는 아직 남았다.

> 한 줄 요약 — pi1 에 붙은 RoboMaster EP 의 카메라를, 로봇 노드가 같은 프로세스에서 H.264 WebSocket(:8091)으로 내보낸다.
> 화면은 노드가 `status.media` 로 알린 주소로 붙어 WebCodecs 로 풀고 캔버스에 그린다. Go1 · A2 · 드론의 MJPEG 길은 그대로다.

## 1절 — 와이어 (HW `ep_camera.py`)

```
텍스트   {"t": "hello", "codec": "avc1.4d6029", "cam": "ep-001"}   붙은 뒤 첫 키프레임 직전에 한 번
바이너리 [키프레임 1바이트][float64 BE 시각 ms][Annex-B 액세스 유닛]
```

- 붙는 것이 켜기, 끊는 것이 끄기다. 보는 사람이 없으면 중계가 20초 뒤 상류를 끄고 소켓을 닫는다.
- 중계는 첫 키프레임까지 아무것도 안 보낸다. 코덱 문자열은 SPS 에서 매번 읽어 `hello` 에 싣는다(화면이 상수로 박지 않는다).

## 2절 — 주소 (`status.media`)

로봇 노드는 retained `status` 에 실제로 도는 영상 경로를 싣는다(`transport` · `url` · `port` · `path` · `available` · `streaming` · `avc` · `last_error`).

| 순서 | 주소 |
|---|---|
| 1 | 블록의 `url`(ws:// · wss://) — 노드가 공개 주소를 알 때(`EP_CAM_ADVERTISE_HOST`) |
| 2 | 브로커 호스트 + 블록의 `port` · `path` |
| 3 | 블록이 아직 안 왔으면 기본값 `:8091` `/ws` |

`available: false` 이거나 `transport` 가 `websocket` 이 아니면(옛 RTP 등) **주소를 짓지 않는다** — 지어 붙이면 「못 붙었습니다」의 원인을 엉뚱한 데서 찾는다.
EP 카메라 위치는 `front` 하나다.

## 4절 — 검사

`verify:ep-camera` — 와이어 뜯기 · 디코더 입력 · media 블록 저장 · EP 주소 · 받는 부품 갈래. 대조군 12건:
hello 거름 셋(t 가 hello 아님 · codec 없음 · JSON 아님) · 프레임 거름 셋(too_short · bad_flag · empty_payload) ·
`streaming` · `avc` 변화는 주소를 다시 안 짓는다 · EP 의 없는 위치는 null · `available:false` → 주소 없음 · `transport:rtp` → 주소 없음 ·
Go1 은 MJPEG 그대로 · MJPEG 중계 주소는 `<img>` 그대로.

`verify:connection-panel` — 실물 브로커 프리셋이 넷 → 다섯(EP 추가).

## 5절 — 남은 것

- **실물 확인**: pi1 로봇 노드(ep)를 `EP_CAM_ENABLE` 로 띄우고, 하드웨어 카드 상세 · 전체 장치 확인에서 영상이 뜨는지 · 「카메라 확인」 걸음이 통과하는지.
- 브라우저는 WebCodecs 가 있어야 한다(Chrome · Edge).
