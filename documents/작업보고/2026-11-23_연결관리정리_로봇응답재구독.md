# 작업 보고: 연결 관리 탭 정리 · 로봇 응답 구독을 연결이 바뀔 때 다시 붙인다

**날짜**: 2026-11-23
**커밋**: `a2cdd1b`(객체 탐지 줄 합치기) · `3a4aeea`(로봇 응답 재구독) · `d8b60fa`(탭 정리) · `3cbbc97`(그중 연결 판 부분) · `0333a27`(탐지 방식 선택 모양) — 브랜치 `khw_VZ`
**관련**: 탐지 방식 기본값의 근거 [`../작업프롬프트/작업프롬프트_스캔탐지_data_stream_구현계획_261123.md`](../작업프롬프트/작업프롬프트_스캔탐지_data_stream_구현계획_261123.md)(결정 13)

> 한 줄 요약 — 연결 관리 탭을 시연에 맞게 줄였다. 따로 있던 「객체 탐지」 줄을 「객체 탐지 추론 스트림」 칸 안으로 넣어 탐지 방식(옛 탐지기 / data_stream)을
> 그 칸 맨 위에서 고르게 했고, 맨 위 여섯 순서를 정하고, 일회용 동영상 · 이미지 칸과 안 쓰는 대상 넷을 판에서 뺐다.
> 따로, 생성 임무 판에서 명령 노드가 대기에 남던 것을 고쳤다 — 로봇 응답 구독이 연결 목록이 바뀌어도 다시 붙지 않았다.

**맨 위 여섯**(`d8b60fa`): 로봇 · 카메라 · 객체 탐지 추론 스트림 · 3D 가상환경 · 가상 맵 · 장애물 탐지 영상. 나머지는 그 뒤에 원래 순서로.

**판에서 뺀 것**(`d8b60fa`):

- 3D 가상환경의 동영상 두 칸(`video` · `video2`) · 장애물 탐지 영상의 주소별 동영상 칸(`videoPerRow`) · SAR · 3D 복원의 이미지 칸 — 일회용 시연용이었다.
- 생성 서비스 · SAR 영상 · 3D 복원 · 자율주행 로봇(`autodrive`)은 `hidden: true`. 대상 · 저장 키 · 기본값은 남아 그 값을 읽는 기능은 그대로다. 생성 주소는 `GenerateAddress` 칸에서 받는다.

**추론 스트림 포트 선택지**(`d8b60fa`): data_stream `70da254` 의 `SOURCES` 에 있는데 빠져 있던 넷 — `10005 realsense` · `10006 cam360_slice` · `10007 a2` · `10012 drone2`. 처음 깔리는 기본 포트 줄(`VISION_DEFAULT_PORTS`)에는 넣지 않았다.

## 2절 — 왜

- **탐지 방식을 추론 스트림 칸에서 고르는 까닭.** data_stream 스캔 창구가 추론 스트림 포트로 붙는다. 그래서 「어느 편이 매칭에 서는가」를 그 칸 맨 위에서 정하는 것이 맞다고 봤다(`a2cdd1b`).
- **목록 · 저장 키는 그대로.** `CONNECTION_TARGETS` 의 `detect` 대상 · 저장 키 `detect.base` · 확인 대상은 건드리지 않았다. 판에서 그리는 자리만 옮겼으므로 저장된 주소와 머리줄 표시등이 그대로 돈다.
- **숨김은 지우지 않는다.** `hidden` 은 「판에 안 그린다」만 뜻한다. 그 값을 읽는 기능 · 확인 · 검사는 목록을 그대로 본다.
- **새 포트를 기본 줄에 안 넣은 까닭.** 줄마다 `/health` 를 1초마다 묻고, 연결 관리를 안 열어 본 사람의 화면에 안 쓰는 장비 카드가 늘어난다(`vision/presets.ts` 주석).
- **기본값 data_stream.** 사용자 결정(계획서 결정 13). 게이트웨이 기동 값(`SCAN_DETECT_SOURCE`)도 없으면 `datastream` 이고, `SCAN_DETECT_SOURCE=legacy` 로 띄우면 옛 탐지기 편이 선다.
- **옛 탐지기 묶음을 아예 안 그린다.** 처음(`a2cdd1b`)에는 data_stream 이면 흐리게 두고 안내 한 줄을 붙였는데, 지시로 「옛 탐지기」일 때만 보이게 바꿨다(`3cbbc97`).

## 3절 — 로봇 응답 재구독

`useRobotUplink` 는 임무 id 가 바뀔 때만 브로커에 다시 붙었다. 생성 임무는 **제안이 뜬 순간부터** 같은 임무 id 로 화면에 서 있어서, 그때 있던 로봇 연결에만 귀가 열렸다.
그 뒤에 연결 관리에서 로봇(가짜 Go1 등)을 붙이고 승인 · 시작하면, 걸음은 새 연결로 나가고 실행기는 응답을 받는데(`robotCommands.ts` 의 `terminalAnswer` 는 제 연결에 직접 귀를 연다)
화면 기록은 한 줄도 못 받아 명령 노드가 대기에 남았다. 서버 판 `261123/162408` · `173347` 이 그것이다.

고친 것: `useConnections()` 를 부르고 `physicalWsUrls().join('\n')` 을 효과의 의존값에 넣었다(`[missionId, urls]`). 연결 목록이 바뀌면 다시 그려지고, 주소가 달라졌으면 다시 붙는다.

## 6절 — 검사

## 7절 — 한계 · 남은 것

- **로봇 응답 재구독의 실물 재확인.** 고친 뒤 생성 임무 판을 다시 돌려 명령 노드가 칠해지는지 본 기록이 커밋에 없다.
- `a2cdd1b` 에서 쓰던 `.conn-sub--idle` · `.conn-sub__note` 스타일이 `style.css` 에 남아 있다. `3cbbc97` 뒤로 쓰는 곳이 없다.
- 숨긴 네 대상(생성 서비스 · SAR · 3D 복원 · 자율주행 로봇)의 값은 판에서 못 고친다. 저장된 값이나 기본값 · 환경변수로만 바뀐다(생성 주소는 `GenerateAddress` 칸).
- 동영상 칸을 그리는 패널 코드(주소별 키)는 남아 있다 — `verify:media-cues` 가 그 코드를 본다. 칸을 다시 켜려면 `connections.ts` 에 칸만 되살리면 된다.
- 추론 스트림 포트 이름은 이 뒤 `2bec1b5` 에서 10004 가 `ep-001` 로 바뀌었다([탐지 모델 상태판 보고](2026-11-24_탐지모델상태판.md) 쪽).
