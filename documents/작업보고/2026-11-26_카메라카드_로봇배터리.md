# 작업 보고: 고정 카메라 카드에 붙은 로봇(Go1)의 배터리가 같이 뜨던 것

**날짜**: 2026-11-26
**커밋**: 이 보고서와 같은 커밋 — 브랜치 `khw_VZ`
**관련**: [하드웨어 카드 살아 있는 줄](../../viz-debugger/src/main.tsx) (`CardStatusLine`) · 360 카메라 상태 `viz-debugger/src/fixedcam/cameraState.ts`
**상태**: **고쳤다.** 검사는 통과했다. 고친 뒤의 화면은 아직 실물(Go1 + 카메라)로 다시 보지 않았다.

> 한 줄 요약 — Go1 과 360 카메라(`http://100.125.104.23:10001/frame`)를 같이 붙이면 카메라 카드 한 줄에 배터리가 둘 떴다.
> 하나는 카메라 것, 하나는 **Go1 의 MQTT 배터리**였다. 카메라 · 3D 가상환경 카드는 자기 상태만 찾게 고쳤다.

---

## 1절 — 증상과 실물 확인

- 카메라 상세 창: 배터리 하나(카메라 `X-State` 의 `battery.level_pct` — 받아 본 값 96 %, 충전 중).
- 판의 카메라 카드 한 줄: 배터리 둘.
- 사용자 실물 확인(261126): 배터리를 안 싣는 다른 카메라를 붙여도 배터리가 떴다(= Go1 값). Go1 연결을 끊자 그 배터리가 사라졌다.

## 2절 — 원인

카드 한 줄(`CardStatusLine`)은 고정 카메라에 `HardwareLink` + `CameraStateDots` 를 이어 그린다. 상세 창은 `CameraStateDash` 하나라
배터리가 하나다.

`HardwareLink` 는 MQTT 장비 상태를 `devices[hardwareTarget(entityId)]` 로 찾는다. 그런데

```ts
export function hardwareTarget(vizEntityId: string): string {
  return commandTarget() ?? TARGET_OF[vizEntityId] ?? vizEntityId;
}
```

`commandTarget()`(붙은 로봇이 밝힌 id)이 있으면 **넘겨받은 id 를 안 본다.** 그래서 카메라 카드(`fixed-cam-1`)에서도 `go1-001` 의 상태가
나오고, 그 상태에 `battery_pct` 가 있어 `mqttFilled` 가 참 → MQTT 갈래에서 Go1 의 온라인 · 배터리 칩을 그렸다. 로봇이 안 붙어 있으면
`devices['fixed-cam-1']` 이 없어 「연결됨 · n초 전」만 나왔다 — 그래서 동시에 붙었을 때만 생겼다.

`encode.ts` 주석의 「조회가 빗나가면 빈 화면일 뿐 해롭지 않다」가 성립하지 않는 경우다 — 빗나가는 게 아니라 **남의 값으로 찬다.**
같은 부품을 쓰는 3D 가상환경 카드도 같은 문제가 있었다.

## 3절 — 결정

세 안 중 1안(사용자 선택).

| 안 | 내용 | 판단 |
|---|---|---|
| **1 (택함)** | 로봇이 아닌 카드만 자기 id 로 찾게 하는 옵션 | 범위가 카드 줄 하나. 로봇 · 드론 카드는 그대로 |
| 2 | `hardwareTarget()` 자체를 로봇 화면 id 에만 붙은 로봇을 주게 | 부르는 곳 10곳 넘음 · 드론 카드가 지금 동작에 기댐 — 이번 문제에 과함 |
| 3 | 카메라 카드에서 `HardwareLink` 를 빼고 연결 칩을 따로 그림 | 같은 코드 두 벌 · 3D 카드는 그대로 남음 |

## 4절 — 고친 자리

| 파일 | 바뀐 것 |
|---|---|
| `viz-debugger/src/physical/encode.ts` | `cardStateId(id, ownOnly)` 신설 — `ownOnly` 면 자기 id, 아니면 `hardwareTarget` |
| `viz-debugger/src/physical/HardwareLink.tsx` | prop `ownStateOnly`(기본 false). 찾는 id 를 `cardStateId(entityId, ownStateOnly)` 로 |
| `viz-debugger/src/main.tsx` | `CardStatusLine` 이 고정 카메라 · 3D 가상환경 카드에 `ownStateOnly` 를 켬 |
| `viz-debugger/scripts/verify-card-own-state.mjs` · `package.json` | 새 검사 `verify:card-own-state` |

3D 가상환경 카드는 자기 이름으로 연결 장비에 적히고(`twinDevice.ts` · `noteConnectedEntity(name, 'twin')`) MQTT 상태를 로봇 id 로 받지
않으므로, 옵션을 켜도 잃는 값이 없다.

## 5절 — 검사

| 검사 | 결과 |
|---|---|
| `verify:card-own-state` (새) | 통과 — Go1(`go1-001`)이 밝힌 상태에서 ① 카메라 · 3D 카드는 자기 id ② 로봇 카드(`robot-01`)는 `go1-001` ③ `main.tsx` · `HardwareLink` 가 실제로 그렇게 부름. 대조군 4/4 잡힘(고치기 전 모양 · 카메라 옵션 빠짐 · 3D 옵션 빠짐 · `HardwareLink` 가 옵션 버림) |
| `tsc --noEmit` | 통과 |
| `verify:device-cards` · `drone-via-state` · `fixed-camera` · `command-target` · `no-hardcoded-target` · `verify-hygiene` · `crlf-safe` · `no-raw-korean` · `i18n-no-frozen` | 모두 통과 |

## 남은 것

- 고친 뒤 화면을 실물(Go1 + 360 카메라 동시 연결)로 다시 보지 않았다 — 카메라 카드에 배터리가 하나(카메라 것)만 남고, Go1 카드는 그대로인지 확인이 필요하다.
- 검사는 찾는 id 와 원본 호출을 본다. 컴포넌트를 실제로 렌더해 칩 수를 세지는 않는다(이 저장소 검사가 컴포넌트를 렌더하지 않는 방식).
