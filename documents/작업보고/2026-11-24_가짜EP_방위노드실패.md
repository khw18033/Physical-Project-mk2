# 작업 보고: 가짜 RoboMaster EP · 로봇을 못 고르면 방위 노드(T-A2)를 실패로 닫는다

**날짜**: 2026-11-24
**커밋**: 이 보고서와 같은 커밋 — 브랜치 `khw_VZ`
**관련**: [임무를 모는 로봇 고르기](2026-11-24_임무로봇고르기.md) · 규약 [부록 A — RoboMaster EP](../규약/장치연동_부록A_로보마스터EP_260924.md)
**상태**: **가시화 쪽은 끝났다.** 검사는 통과했다. 화면(브라우저)에서는 아직 띄워 보지 않았다.

> 한 줄 요약 — 실물 없이 다기종 임무를 보려고 가짜 EP(`fake:ep`)를 넣었다. 그것으로 가짜 Go1 + 가짜 EP 를 붙이고 박스 편을
> 배정 없이 시작하자, 「로봇 현재 위치와 각도 파악」(T-A2) 노드가 「진행」에 남았다. 로봇을 못 고르면 실패로 닫게 고쳤고,
> 판정 기준(action)을 각 편의 실행기와 맞췄다.

## 1절 — 가짜 EP (`fake:ep`)

연결 관리 물리 장비 프리셋에 「가짜 EP (실물 없이 화면 확인)」을 더했다. 가짜 Go1 · 가짜 드론과 같은 자리(`fakeDevice.ts`)에서
mqtt.js 자리만 바꾸고, 그 뒤(정체성 · 카드 · 명령 인코딩 · 응답 디코딩)는 실물과 같은 코드를 지난다.

| 항목 | 값 |
|---|---|
| 장비 id · 종류 · 기종 | `ep-fake` · `robot` · `robomaster_ep` (실물 `ep-001` 과 안 겹친다, 카드에 「목」) |
| Capability | `ping` · `diag` · `turn` · `move_forward` · `abort` — 부록 A §3 그대로. Go1 전용(`teleop` · `move_relative` · `scan_mission` …)은 `UNIMPLEMENTED` |
| 부호 | `turn` + = 오른쪽(시계). state 의 `heading_deg` 는 반시계 + (x 앞 · y 왼쪽) |
| 범위 | 회전 \|deg\| 5~360 · 거리 0.05~10 m · 속도 0.05~0.30 m/s. 밖이면 `INVALID_ARGUMENT` (고치지 않는다) |
| 실행 규칙 | 이동 중 둘째 이동 → `mission_in_progress`. `abort` → 돌던 명령 `ABORTED`(`aborted`) 뒤 자신은 성공 |
| 결과 키 | `turn` → `deg` · `duration_s` (`yaw_deg` 는 실물 부호를 아직 안 재 싣지 않음), `move_forward` → `distance_m` · `odo_m` · `duration_s` |
| 상태 | 평시 5초 · 움직이는 동안 5 Hz (§4). `robot_mode` idle / moving |
| 카메라 | 없음 — 주소에 호스트가 없어 영상 칸이 빈다 |

가짜 장비에는 추론 포트가 묶여 있지 않다. 카드를 끌어 놓아 로봇을 정해도 스캔 편은 「주소를 정할 수 없다」(`no_address`)에서 선다.

## 2절 — 방위 노드(T-A2)가 「진행」에 남던 것

**재현**: 가짜 Go1 + 가짜 EP, 박스 편(`MSN-261123-02`)을 배정 없이 시작 → T-A0 은 `robot_choice` 실패 · 알림이 뜨는데 T-A2 는 「진행」.

**원인** (`prepStage.ts`): 시작하면 T-A2 를 먼저 `running` 으로 칠하고, 방위를 읽을 장비를 고른다. 못 고르면 옛 표 `go1-001` 로
물러서 그 state 를 기다린다. 가짜 이름은 `go1-fake` 라 영영 안 오고, 15초 뒤 경고만 남겼다. 스캔 실행기(`scanDetectLink.ts`)는
같은 판정으로 이미 T-A0 을 닫았는데 준비 단계만 그 판정을 안 봤다.

**같이 드러난 반대 경우**: 실물 이름(`go1-001`)이 붙어 있으면 배정이 없어도 T-A2 가 Go1 방위로 「완료」가 됐다(검사를 옛 코드에 돌려 확인).

**고침**
- 시작할 때 로봇을 못 고르면(`many` · `manyAssigned` · `assignedAway`) T-A2 를 `failed`(`code: robot_choice`, 사유)로 닫고 탐지 기록에 한 줄. 알림은 스캔 실행기가 이미 띄우므로 하나만. 하나도 없으면(`none`) 전처럼 기다린다.
- 실패한 판은 늦게 온 state(`checkPose`) · 15초 경고가 덮지 않는다.
- 준비 단계의 노드 칠하기가 `failed` 를 받는다(`kind: evaluated`). 정지 · 일시정지 뒤에도 실패는 칠한다 — 「진행」으로 남는 것이 더 나쁘다.
- **판정 action 을 실행기와 맞춤**: 옛 문 찾기(`door-scan` — `MSN-260909-01` · `MSN-261027-01`)는 `scan_mission`, data_stream 스캔은 `turn`.
  `turn` 하나로 보면 실물 Go1(scan_mission 있음) + EP(없음)에서 스캔은 Go1 로 도는데 T-A2 만 「로봇이 둘」로 실패한다.

## 3절 — 다른 임무

| 임무 | 로봇을 못 고르면 |
|---|---|
| data_stream 스캔 셋(`MSN-261123-01` · `-02` · `-03`) | T-A0 · T-A2 실패 + 알림 |
| 옛 문 찾기 둘(`MSN-260909-01` · `MSN-261027-01`) | T-A2 실패 + 알림 (`scan_mission` 기준) |
| AI 생성 · 정량 명령 | 노드를 칠하기 전에 멈춘다 → 노드는 대기, 알림만 (바꾸지 않음) |
| 장치 두 대 편 | 자리 배정 방식이라 해당 없음 (바꾸지 않음) |

가짜 장비 둘은 `scan_mission` 이 없어 옛 문 찾기 편에서는 「로봇 없음」(`none`)이 된다 — 가짜로 확인하려면 새 편을 쓴다.
