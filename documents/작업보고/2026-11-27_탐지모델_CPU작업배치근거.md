> 한 줄 요약 — 물체 추적을 켜자 `track` 칩 상세의 근거가 「돌고 있는 배치표에 없음 → data_stream 기기 (자원 배분 없이 띄운 비전)」로 나왔다.
> 실제로는 오케스트레이터가 배치표의 **CPU 작업** `object_track.server` 로 노트북에 두었다. 상태판이 실행 장치를 GPU 단위에서만 찾아서였다.
> 모델 → 기능 표(`track → object_track`)를 두고, GPU 단위에 없으면 배치표의 `<기능>.server` CPU 작업에서 찾는다.

## 1절 — 무엇이 틀렸나

2026-11-27 12:48 요청 `req-d99d2dce33` (robot1, 지정 탐지 + 물체 추적):

| 근거 | 값 |
|---|---|
| 배치표 GPU 단위 | `targeted` → `book-4vg1edpvi5` |
| 배치표 CPU 작업 | `object_track.server` → `book-4vg1edpvi5` · `object_track.device@robot1` → `pi7` (명세 없음으로 못 뜸, data_stream 이 아는 문제) |
| 실행 기록 | `object_track.server` applied — 「`book-4vg1edpvi5` (data_stream 기기)」 |
| 결과 `vision_stream:robot1:track` | `node_id BOOK-4VG1EDPVI5` · 입력 `targeted_detect` / `targeted` · 추적기 `botsort` |

장치(노트북)는 맞았지만 근거 문장이 틀렸다 — 배치표에 있는데 「없음」이라 했다. `placementOf` 가 `plan.gpuUnits[].models` 에서만 모델 이름을 찾는데,
`track` 은 GPU 단위가 아니라 기능 단계 CPU 작업으로 배치된다. 서버 단계가 파이로 가면 꼬리표까지 「노트북」으로 틀렸을 것이다.

상세 칸은 장치(`from|node`)마다 모델을 묶었으므로, 고치면서 그대로 두면 같은 노트북의 `targeted`(GPU) · `track`(CPU 작업)이 한 묶음이 되어
`track` 이 GPU 근거 · 몫 · 실행 위치로 읽힌다. 그래서 묶음도 갈랐다.

## 2절 — 무엇을 고쳤나

| 파일 | 바뀐 것 |
|---|---|
| `src/detect/status/placement.ts` | `CPU_STAGE_MODELS = { track: 'object_track' }` · `placementOf` — GPU 단위에 없고 표에 있는 모델이면 배치표 `cpuUnits` 의 `<기능>.server`. 같은 요청의 단위 기록이 있으면 그 노드, 못 떴거나(failed) 끝났으면(stopped) 쓰지 않고 data_stream 기기. `Placement.cpuTask?` |
| `src/detect/status/views/DetectStatusParts.tsx` | 묶음 키에 `cpuTask` — GPU 단위와 CPU 작업은 따로. 근거 「오케스트레이터 배치표(시각)의 CPU 작업 {작업} 가 {노드} 에 둠」. 「실행 위치」 줄(GPU `applied` 의 문장)은 GPU 단위에만 |
| `src/i18n/ko.ts` · `en.ts` | `dms.pl.whyCpu` |

- 서버 단계를 쓰는 까닭: `track` 결과는 비전 프로세스 안의 서버 단계가 낸다(결과의 `producer.tier = server`). 기기 단계(`.device@<소스>`)는 다른 일이다.
- 기능이 늘면 `CPU_STAGE_MODELS` 에 더한다. 표에 없는 모델은 예전과 같다.
