# Unitree A2-W 가시화 연동 구현 보고 (2026-11-12)

대상: Unitree A2-W 실물 1대, PC2 브리지(`a2-bridge/`), 가시화 웹(`viz-debugger/`)

## 요약

- A2-W 내부 사용자 PC(PC2)에 유선으로 접속했다. 네트워크 구조는 조사 문서(A2 Pro 기준)와 같았다.
- PC2에 브리지를 올렸다. 브리지는 PC1이 내보내는 DDS 상태를 받아 Go1과 같은 장치 규약(MQTT + protobuf)으로 내보낸다. 웹에서는 A2가 Go1과 같은 하드웨어 카드, 상세 상태판, 수동 제어 탭으로 뜬다.
- 웹에서 하는 일:
  - 위치, 방위, 속도, 배터리, 모드 보기
  - 전방 카메라 MJPEG 보기
  - 키보드 속도 제어(teleop), 조종기 명령 14종, 모의 실행과 실제 제어 전환
- 확인한 것:
  - 손으로 짠 protobuf 코덱이 웹과 바이트 단위로 맞는다(9/9).
  - 명령 왕복, 카메라 약 10 fps, 모의 실행 명령 처리.
  - 실제 제어에서는 사용자가 키보드로 몰았다. **A/D(옆 이동)만 반응이 없다고 보고됐다. 원인은 아직 모른다.**
- 확인하지 못한 것:
  - 조종기 명령 대부분의 실제 동작(특히 API를 추정한 고속, 오르기, 몸 높이).
  - 모드 이름표(`fsm_name`)가 모드마다 어떤 값인지.
- 지금은 노트북이 Pi 자리를 대신한다. 노트북을 PC2에 유선으로 직접 연결해 쓴다. 최종 구성(PC2 ↔ 라즈베리파이 ↔ Tailscale)은 [2026-11-12_A2W라즈베리파이전환계획.md](2026-11-12_A2W라즈베리파이전환계획.md)에 따로 적었다.

## 1. 네트워크와 PC2 실측

조사 문서: 저장소 루트 `Unitree A2-W 내부 개발 PC 접속 제어 방식 조사.md` (A2 Pro 기준). A2-W에서도 같은 구조였다.

| 장치 | 주소 | 확인 내용 |
|---|---|---|
| PC1 (보행 제어) | 192.168.123.161 | PC2에서만 닿는다. 노트북(124 대역)에서는 안 닿는다 |
| PC2 (사용자 PC) | 192.168.124.162 (`net1`) / 192.168.123.162 (`eth0`) | SSH 열림, 비밀번호 로그인 허용. 계정 `unitree` |
| 전방 / 후방 라이다 | 192.168.124.20 / .21 | ping 응답 |
| 노트북 | 192.168.124.100/24 (고정) | 로봇에 DHCP가 없어서 직접 넣었다 |

- **물리 연결:**
  - 본체의 PC2 "이더넷+12V" 원형 항공 커넥터 → 변환 케이블 → 노트북 USB 랜 동글 순서로 연결했다.
  - 바깥 링을 끝까지 돌려 잠가야 링크가 잡힌다. 링크 속도는 100 Mbps였다.
- **PC2 환경:**
  - OS와 런타임: Ubuntu 22.04.4, 커널 6.5.2-rt8, Python 3.10.
  - DDS와 SDK: Python `cyclonedds` 0.10.2, ROS 2 Humble(`rmw_cyclonedds_cpp`), unitree_sdk2 C++(`/opt/unitree_robotics`)가 설치되어 있다. **설치된 C++ SDK에는 A2 헤더가 없다.**
- **PC2에서 이미 도는 서비스:** `advanced_slam`(DDS는 `eth0`에 고정), nginx :80("Unitree SLAM" 웹 화면).
- **PC2 네트워크 제약:**
  - 무선랜 장치가 없다.
  - 기본 경로(default route)가 없어 인터넷이 안 된다.
- **PC2 시계:** 노트북보다 약 8분 느리다. 웹은 받은 시각으로 신선도를 재므로 지금은 영향이 없다.

### 1.1 DDS에서 쓰는 토픽 (eth0, 도메인 0)

| 쓰임 | 토픽 | 비고 |
|---|---|---|
| 위치, 속도, 자세 | `rt/lf/sportmodestate` (`unitree_go/SportModeState`) | **A2-W에서는 `mode` 값이 늘 0이다.** 모드 판정에 못 쓴다 |
| 배터리 | `rt/lf/secondary_bmsstate` (`unitree_hg/BmsState`) | `rt/lf/bmsstate`는 전부 0이다. 둘 중 0이 아닌 값을 쓴다 |
| 모드 | sport RPC `GetState` (api 1034) | `fsm_name`(예: `ai_free_walk`, `ai_phase_walk`), `speed_level`, `auto_recovery_switch` |
| 고수준 제어 | sport RPC (`a2.SportClient`) | `Move`, `StopMove`, `StandUp`, `Damp`, `SwitchGait` … |
| 전방 카메라 | videohub RPC (`go2.VideoClient.GetImageSample`) | 1920×1080 JPEG, 장당 약 200 KB, 초당 약 20장 |

- `rt/wirelesscontroller`에는 조종기 입력이 나오지 않았다. 150초 동안 관찰했다.
- 조종기 버튼이 어떤 API를 부르는지는 DDS에서 볼 수 없었다.

## 2. PC2 브리지 (`a2-bridge/`)

```
PC1 ─DDS(eth0)─▶ PC2: a2_bridge.py ─MQTT 5─▶ mosquitto (1883 / ws 9001) ─▶ 가시화 웹
                       └─ HTTP :8090 /stream/1 (MJPEG, 전방 카메라) ──────────▶ 가시화 웹
```

| 파일 | 역할 |
|---|---|
| `a2_bridge.py` | DDS 구독, sport RPC, MQTT 노드, 카메라 HTTP 서버 |
| `physical_wire.py` | `physical_command.proto` 손 코덱. PC2의 protobuf 3.12와 버전을 맞추지 않으려고 직접 짰다 |
| `test_wire.mjs` | 위 코덱을 웹의 `protocol.js`와 바이트 단위로 대조한다 |
| `mosquitto.conf`, `run.sh`, `stop.sh` | 브로커 설정, 브로커와 브리지 기동, 종료 |
| `README.md` | 배치, 실행, 동작 설명 |

- **PC2 배치:**
  - PC2에 인터넷이 없어서, 필요한 것을 노트북에서 받아 `scp`로 `~/viz_a2` 폴더 하나에 넣었다. **시스템에는 아무것도 설치하지 않았다.**
  - mosquitto 2.0.11과 의존 라이브러리: Ubuntu 22.04 `.deb`를 `dpkg -x`로 풀기만 했다.
  - `unitree_sdk2py`: 패키지 폴더를 복사했다(GitHub 최신본, A2 SportClient 포함).
  - paho-mqtt 2.1.0: 휠을 풀었다.
- **장치 정체:** `entity_id: a2-001`, `entity_type: robot`, `device_type: unitree_a2`.
- **발행하는 것:**
  - `zoneA/robot/a2-001/status|state|heartbeat`: status는 retained와 LWT를 단다. state는 10 Hz, status와 heartbeat는 5초 간격이다.
  - `terminal/a2-001/uplink`: Capability와 명령 응답.
- **Capability:**

  | 묶음 | action |
  |---|---|
  | 기본 | `ping`, `abort`, `teleop` |
  | 실행 모드 | `set_dry_run` |
  | 조종기 명령 | `damp`, `lock_stand`, `lie_down`, `unlock_gait`, `high_speed`, `recovery_stand`, `climb`, `handstand`, `erect`, `auto_recovery`, `speed_down`, `speed_up`, `height_down`, `height_up` |

- **state 본문에 더한 것:**
  - `dry_run`
  - `robot_modes`: `fsm_name`, `speed_level`, `auto_recovery`, `posture`, `gait`, `height_offset_m`, `handstand`, `erect`
  - `attitude`, `body_height_m`

### 2.1 안전 장치

- **늘 모의 실행으로 뜬다.**
  - 모의 실행은 명령에 응답만 하고 로봇 API를 부르지 않는다.
  - 웹 수동 제어 탭에서 「실제 제어」를 고르고 확인 창을 거쳐야 실제 제어로 바뀐다.
  - 모드를 바꾸는 순간 움직이던 중이면 먼저 `StopMove`를 부른다.
- **teleop 감시:**
  - 20 Hz로 `Move`를 부른다.
  - `hold_ms`(최대 1초) 안에 다음 명령이 없거나 브로커가 끊기면 `StopMove`를 부른다.
  - 속도는 vx 0.4, vy 0.3, vyaw 1.0을 넘지 않게 브리지에서 한 번 더 자른다.
- **abort(Space 키):**
  - 거절하지 않는다. 대기 중인 동작은 `ABORTED`로 닫고 `StopMove`를 부른다.
  - 그 뒤 1초 동안 teleop을 거절한다(Go1과 같다).
- **`damp`(비상정지):** 대기 줄을 거치지 않고 바로 `Damp`를 부른다.

### 2.2 조종기 명령 매핑

조종기 표(A2-W)를 따랐다. **조종기가 실제로 어떤 API를 부르는지는 확인하지 못했다.** 아래는 SDK 이름과 B2-W 예제를 근거로 고른 것이다.

| 키 | action | 조종기 | 부르는 API | 근거 |
|---|---|---|---|---|
| 1 | `lock_stand` | L2+A 첫 번째 | `StandUp` | Go2 계열의 "관절 잠금 서기" |
| 2 | `lie_down` | L2+A 두 번째 | `StandDown` | 〃 |
| 3 | `unlock_gait` | START | `BalanceStand` | Go2 계열의 "잠금 풀기" |
| 4 | `high_speed` | L2+START | `SwitchGait(1)` | **추정** (B2-W 예제가 0/1로 걸음을 바꾼다) |
| 5 | `recovery_stand` | L2+X | `RecoveryStand` | 이름이 같다 |
| 6 | `climb` | R1+X | `SwitchGait(2)` | **추정** |
| 7 / 8 | `handstand` / `erect` | R1 두 번 / R2 두 번 | `HandStand` / `BipedStand` (1/0 토글) | 이름이 같다 |
| 9 | `auto_recovery` | Y+B | `SetAutoRecovery` 토글 | 이름이 같다. 지금 값은 GetState에서 읽는다 |
| 0 | `damp` | L2+B | `Damp` | 조종기 표의 "Damping Mode(Emergency Stop)" |
| `-` / `=` | `speed_down` / `speed_up` | 방향패드 | `SpeedLevel(±1)` | 지금 단계는 GetState에서 읽는다 |
| `[` / `]` | `height_down` / `height_up` | L1+방향패드 | `BodyHeight(±0.02)` | **추정**. 값이 상대값인지 절대값인지 모른다 |

부저 켜기·끄기(F1 세 번)는 대응하는 API가 없어서 넣지 않았다.

## 5. 남은 문제와 확인할 것

1. **A/D(옆 이동)가 실제 제어에서 반응이 없다.**
   - `Move`가 오류 없이 0을 돌려준다. 즉 로봇이 vy를 받고도 무시한다.
   - 바퀴형이라 지금 걸음(`ai_free_walk`, `ai_phase_walk`)에서 옆 이동을 안 하는 것으로 보이지만 확인하지 못했다.
   - L2+A는 바퀴/다리 전환이 아니라 자세 잠금이다(조종기 표).
   - 옆 이동이 끝내 안 되는 기종이면, 수동 제어 탭의 옆 이동 지원 표시를 "안 됨"으로 바꿔야 한다.
2. **조종기 명령의 실제 동작을 확인해야 한다.**
   - 키를 하나씩 눌러 보면서 `fsm_name`이 어떻게 바뀌는지 기록한다.
   - 추정한 셋(`high_speed`, `climb`, `height_*`)은 결과에 따라 API나 인자를 고친다.
3. **「로봇 모드」의 자세, 걸음, 몸 높이는 마지막 명령 기준이다.**
   - 조종기로 바꾸면 화면과 실제가 어긋난다.
   - 2번에서 `fsm_name` 대응표가 나오면 로봇 보고값으로 바꾼다.
4. **mosquitto WebSocket(9001)이 모든 인터페이스에 열린다.**
   - 설정은 124 대역에만 열게 했지만, mosquitto 2.0.11 WebSocket 리스너는 bind 주소를 무시한다. 그래서 123 제어망에도 열려 있다.
   - 그 망에는 PC1뿐이라 당장 문제는 없다. Pi로 옮기면 PC2에는 브로커가 없어지므로 함께 정리된다.
5. **카메라 대역폭.** 10 fps면 약 16 Mbps다. Pi와 Wi-Fi를 거치면 줄여야 할 수 있다(전환 계획 §5).
6. **저장소 추적.** `a2-bridge/`는 루트 `.gitignore` 허용 목록에 없어서 지금 git에 잡히지 않는다. 올리려면 `!/a2-bridge/` 한 줄이 필요하다. 웹 변경도 아직 커밋하지 않았다.
7. **자동 시작이 없다.** PC2를 재부팅하면 `~/viz_a2/run.sh`를 다시 실행해야 한다.
