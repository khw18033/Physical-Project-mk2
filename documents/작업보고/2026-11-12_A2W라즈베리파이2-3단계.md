1단계 보고: [2026-11-12_A2W라즈베리파이1단계설정.md](2026-11-12_A2W라즈베리파이1단계설정.md)
작업 프롬프트: `pi-a2/PROMPT.md` 2단계(로봇에 연결), 3단계(브리지를 Pi 브로커로 옮기기) 1~4번

## 요약

- 1단계에서 남은 확인 항목은 사람이 다른 PC에서 확인해 끝났다.
  - Tailscale(`pi10.tailcb6bfb.ts.net`)로는 1883, 9001, 8090이 열리고 ws MQTT 접속이 된다.
  - 같은 Wi-Fi(`192.168.50.73`)로는 1883, 9001, 8090이 막히고 22만 열린다.
- 2단계를 마쳤다.
  - PC2 ping이 된다.
  - Pi → PC2 SSH 키 접속이 된다. `ssh-copy-id`의 비밀번호는 사람이 넣었다.
  - PC2 상태는 확인만 했다.
- 3단계 1~4번을 마쳤다.
  - 브리지 0.3을 PC2에 올렸다. 기존 파일은 백업했다.
  - 브리지를 손으로 한 번 띄웠다. Pi 브로커에 `[mqtt] connected 192.168.124.50:1883`으로 붙었다.
  - `./pi/check-pi.sh robot`의 robot 항목은 **모두 OK** 다. status, state(30건/3초), 카메라 snapshot을 확인했다.
  - **`dry_run`은 `true`다.** 브리지 시작 로그, status, state 셋 다 같다.
- 하지 않은 것
  - 실제 제어 전환, `downlink` 발행. Pi에서는 구독만 했다.
  - PC2 crontab, `autostart.sh`(4단계).
  - PC2 시스템 설정.
- 손으로 띄운 브리지는 **지금도 PC2에서 돌고 있다**(PID 2903). 3단계 5번 웹 확인에 쓰도록 그대로 두었다.

### PC2 `~/viz_a2/bridge.log` 첫 30줄

브리지를 띄운 지 2분이 넘었지만 로그는 아직 4줄뿐이다. 그 전부를 싣는다.

```
[run] remote broker 192.168.124.50 (local mosquitto not started)
[a2-bridge] id=a2-001 nic=eth0 broker=192.168.124.50:1883 dry_run=True camera=8090
[mqtt] reconnected after 0s
[mqtt] connected 192.168.124.50:1883
```

- `nic=eth0`은 DDS 쪽 NIC(123 대역)다. 브로커 쪽 NIC는 `--uplink-nic`(기본 `net1`)이다.
- `[mqtt] reconnected after 0s`는 첫 접속인데도 찍힌다. 동작에는 영향이 없다. 브리지 코드의 표시 문제로 보인다 (부록 참고).

## 3. 바꾼 파일

| 구분 | 경로 | 내용 |
|---|---|---|
| Pi 새로 만듦 | `~/.ssh/id_ed25519`, `~/.ssh/id_ed25519.pub` | PC2 접속용 키 |
| Pi 새로 만듦 | `~/.ssh/known_hosts` | PC2 호스트 키 |
| PC2 수정 | `~/.ssh/authorized_keys` | `ssh-copy-id`로 Pi 공개 키 한 줄 추가 (사람이 함) |
| PC2 덮어씀 | `~/viz_a2/{a2_bridge.py,physical_wire.py,run.sh,stop.sh,mosquitto.conf,README.md}` | 브리지 0.3. 이전 것은 `*.bak-20261112-142610` |
| PC2 새로 만듦 | `~/viz_a2/autostart.sh` | 4단계용. 아직 쓰지 않았다 (백업할 이전 파일 없음) |
| PC2 새로 만듦 | `~/viz_a2/bridge.log.bak-20261112-142610` | 이전 로그 보존 |
| PC2 덮어씀 | `~/viz_a2/bridge.log` | 새 브리지 로그 |
| PC2 갱신 | `~/viz_a2/__pycache__/` | `py_compile` 결과 |

- Pi 시스템 설정은 바꾸지 않았다.
- PC2에서 바꾼 것은 `~/viz_a2`와 `~/.ssh/authorized_keys`뿐이다. crontab, 네트워크, 패키지, systemd는 건드리지 않았다.

## 4. 넘겨받은 파일을 고쳐 쓴 곳

없다.
- `deploy-to-pc2.sh`, `check-pi.sh`, `pc2/viz_a2/*`는 그대로 썼다.
- 3단계 3번 명령에는 `< /dev/null`만 덧붙였다. ssh 세션이 표준 입력에 묶이지 않게 하려는 것이다.

## 5. 주의

- **ssh로 백그라운드 실행을 하면 ssh가 돌아오지 않는다.**
  - 3단계 3번 명령은 `nohup … &`인데도 ssh 클라이언트가 끝나지 않고 계속 붙어 있었다. PC2의 `bash -c` 부모(PID 2902)가 남아 있다.
  - Pi 쪽 ssh를 끊은 뒤에도 브리지는 계속 돌았다(nohup).
  - 4단계에서 `autostart.sh`를 ssh로 띄울 때는 다음 중 하나를 쓰기를 권한다.
    - `ssh -f …`
    - `setsid nohup … > log 2>&1 < /dev/null &`
- 로봇 모드가 `ai_free_walk`로 보고된다. 로봇 쪽 기본 상태이고, 이번 작업에서 바꾸지 않았다.
- PC2 시계가 약 9분 느리다. 메시지의 `timestamp`도 PC2 시계를 따른다.

## 6. 되돌리기

노트북 직결 방식(PC2 로컬 브로커)으로 돌아갈 때:

```
ssh unitree@192.168.124.162 '~/viz_a2/stop.sh'
# 0.2 파일로까지 되돌릴 때만:
ssh unitree@192.168.124.162 'cd ~/viz_a2 && for f in a2_bridge.py physical_wire.py run.sh stop.sh autostart.sh mosquitto.conf README.md; do [ -f $f.bak-20261112-142610 ] && cp -a $f.bak-20261112-142610 $f; done'
# 그 뒤 PC2 에서 (노트북 직결):  cd ~/viz_a2 && ./run.sh
```

- 0.3의 `./run.sh`(A2_BROKER 없이)도 노트북 직결로 동작한다. 그래서 파일 되돌리기는 꼭 필요하지 않다.
- Pi 키를 지우려면 PC2 `~/.ssh/authorized_keys`에서 `pi10-a2` 줄을 지운다.

## 부록: `reconnected after 0s` 로그

- `a2_bridge.py` 419~420행은 `lost_at` 값이 있으면 `reconnected`를 찍는다.
- 317행은 시작할 때부터 `lost_at = time.time()`을 넣는다. 「처음부터 안 붙는 경우」에도 끊김 경고를 내기 위해서다.
- 그래서 첫 접속에도 `reconnected after 0s`가 찍힌다.
- 끊김 경고 기능(0.3)에 딸린 표시 문제일 뿐이다. 접속과 발행은 정상이다.
- 고친다면 「한 번이라도 붙었는지」를 따로 표시하는 값을 두면 된다. 원본 `a2-bridge/`에서 고칠지 판단해 주길 바란다. 이번에는 고치지 않았다.
