> 한 줄 요약 — 모델이 낸 임무는 승인해도 캔버스에만 올라가고 로봇 관문이 열리지 않아 노드가 대기에 멈췄다.
> 정량 명령 임무가 쓰는 길(승인 → 관문 → 「임무 시작」 → 한 걸음씩)을 그대로 쓰도록, 액션 아이템을 걸음으로 바꾸는 실행기를 붙였다.
> 거리 · 각도는 승인 칸에서 **사람이 채우고**, 명령이 없는 과업은 **사람이 「확인」으로 닫는다.** 1단계는 `turn` · `move_forward` · `abort` 만 낸다.

## 1절 — 무엇을 정했나

계획서(`f4fe132`) §1 의 결정이다. 방향은 사용자가 정했다 — 「정량 명령 임무가 쓰는 실행 길을 다시 쓴다」.

| 항목 | 결정 |
|---|---|
| 실행 길 | 정량 명령 길 그대로. 승인 때 걸음을 임무에 굳혀 싣고, 관문 · 「임무 시작」 · 발행 규칙은 같다 |
| 값이 없을 때 | 생성 규칙상 거리 · 각도는 적지 않는다(`action-items.json` rules). **승인 칸에서 사람이 채운다** — 다 채우기 전에는 승인 버튼이 안 선다. 채운 값의 주체는 `human` |
| 명령 없는 과업 | sense · decide · verify · report 와 액션 아이템이 빈 act 는 **사람이 「확인」 · 「실패로 닫기」로 닫는다.** 자동 완료하면 하지 않은 판정을 한 것처럼 보인다 |
| 1단계 범위 | `turn` · `move_forward` · `abort` 만. 수문(`open_gate` · `close_gate`)은 2단계. `scan_mission` 은 생성 임무에서 **막는다** |
| 순서 | 의존성 위상 순서로 한 줄. 한 임무에 장비 하나 |
| 생성 조건 | 「액션 아이템까지」 스위치, 기본은 끈다 |

원칙은 정량 명령과 같다 — **받을 수 없는 액션 아이템이 하나라도 있으면 임무 전체가 실행 불가다.** 앞부분만 내면 모델이 낸 계획과 다른 것이 로봇에 나간다. 계획 보기(캔버스에 올리기)는 그래도 된다.

구현하면서 계획서와 달라진 것:

| 계획서 | 구현 | 이유(코드 주석) |
|---|---|---|
| 10 m 넘는 직진은 나눠 낸다 | 0.05~10 m 밖이면 받지 않는다 | 사람이 칸 하나에 적는 값이고, 더 가야 하면 계획을 다시 세우는 것이 맞다 (`fillProblems`) |
| 사람 확인 버튼은 노드 상세에 | 실행 상태 카드(`GeneratedRunStatus`)에 | 노드 상세는 열어야 보인다. 실행이 버튼을 기다리는 것을 모르면 판이 멈춘 것처럼 보인다 |
| 승인 칸은 `PlanApproval.tsx` 또는 제안 카드 | 발화 판 제안 카드(`main.tsx`) | 승인의 문은 `acceptProposal` 하나 |

### 승인 → 실행

```
생성 (「액션 아이템까지」 켬) → proposal.ts 가 액션 아이템을 그대로 싣는다
제안 카드: GeneratedRunProposal — 명령 과업 n · 사람 확인 과업 n · 장비 · 거부 · 채울 값
           값이 비었거나 범위 밖(turn |deg| 5~360 · move_forward 0.05~10 m)이면 버튼이 막힌다 — 문구 「승인: 실행 준비」
승인 → acceptProposal: action_params_filled(값 · 모델 값) 기록 → 걸음을 params.generated_run 에 굳힘 → markApproved()
       실행 불가면 지금까지처럼 캔버스에만 (관문 안 열림) · 값이 덜 채워졌으면 문도 스스로 승인하지 않는다
「임무 시작」 → robotClient: wantsStepMission() · 한 판에 한 번 · 장비 고르기 · 장비가 밝히지 않은 동작이면 안 냄
       → runGenerated: 명령 과업은 issueStepsToEnd (앞 걸음 종료 뒤 다음, 마지막 종료까지)
                       사람 확인 과업은 노드를 「사람 확인 대기」(실행기 사건)로 세우고 버튼을 기다림
                       실패 · 「실패로 닫기」 · 정지 · 판 바뀜 → 뒤의 것은 하나도 안 낸다
```

`abort` 는 화면이 낸 정지로 나간다 — 경로 접근의 도착 정지와 같은 이름 · 같은 사유 값(`STOP_REASON.screen`). 걸음 자르기는 정량 명령과 같은 함수(`turnStepCommands` · `forwardStepCommands`)다. 노드는 명령이 들고 간 과업 id 로 칠해진다(정량 명령과 같은 길).

## 3절 — 생성 서비스 · 런처 (`9dfcf81` · `274ac84`)

이 노트북(MX450 2 GB)에서는 태스크 판 생성이 llama-server 응답 한도 600초를 넘겨 쓸 수 없다. gen-lab README 에 따르면 같은 판이 GPU 7 GB 장비에서는 25~38초였다. 그래서 GPU 가 큰 PC 에서 gen-lab 만 띄우고 노트북 화면이 그쪽을 부르게 했다.

| 자리 | 한 것 |
|---|---|

| `.gitignore` · `README.md` · `gen-lab/README.md` | 빌드본을 화이트리스트에 · 쓰는 법. 같은 PC 에서 `viz-dev.exe` 와 같이 켜면 8802 가 겹친다 |

## 4절 — 도중에 잡은 문제

| 문제 | 원인 | 고친 것 |
|---|---|---|
| 대본 계획이 AI 임무를 덮어씀 (261123 실측) | 정답셋 문장은 대본(`MSN-260831-01`)에도 맞아 게이트웨이가 대본 계획을 승인 대기로 만든다. AI 결과를 골라 승인해도 그 계획이 「임무 승인」 창에 남았고, 거기서 승인하면 대본이 덮어썼다 | `9dfcf81` — `shell/missionBridge.ts`: AI 결과를 고르거나 승인하면 같은 발화의 대기 중 대본 계획을 거부로 닫고, 늦게 온 대본 계획도 받지 않는다. 돌아온 거부는 대본 제안일 때만 지운다. 새 발화를 내면 표시를 내린다 |
| 화면 생성 프롬프트가 컨텍스트를 넘음 | 대본이 아홉 편으로 늘면서 화면만 예시를 아홉 편까지 실어 태스크 판 프롬프트가 약 2만 토큰(컨텍스트 16384)이 됐다 — 측정한 조건(예시 2편)에서 조용히 벗어나 있었다 | `4ae6919` — `fewshot.ts`: 정답셋 셋(`MSN-260831-01~03`) 안에서 2편만. 맞은 편이 없어도 앞의 2편만. 액션 아이템 판은 `action-items.json` 의 정답을 예시에 싣는다(빈 배열이면 예시가 규칙을 이긴다) |
| `scenario.ts` 가 실행 계획을 import 하면 여러 검사가 깨짐 | `presets.ts` → … → `scenario.ts` → `actionCommands.ts` → `stepScript.ts` → `presets.ts` 고리. `STEP_VX = APPROACH_VX` 가 초기화 전 값을 읽었다(`verify:no-physical` 외 여럿) | 직접 import 하지 않고 `runFill.ts` 가 읽힐 때 계산을 등록한다. 등록이 없으면 계획만 선다 — 모르는 채로 내는 쪽보다 안전하다 |
| 사람 확인이 대기 사건에 덮임 | 열은 `(atSec, seq)` 순이고 실행기 대역이 사람 대역보다 위라, 시계가 안 흐른 판에서 같은 시각이면 대기가 뒤로 읽힌다 | `recordHumanVerdict` 가 그 노드의 마지막 사건보다 뒤(같으면 1 ms 뒤)에 놓는다 |

## 5절 — 검사

커밋에 이름이 남은 검사만 적는다.

| 검사 | 보는 것 |
|---|---|
| `verify:generated-run` (새, `4ae6919`) | 모델을 부르지 않고 정답셋 셋을 생성 결과 모양으로 바꿔 화면과 같은 함수에 넣는다. ① `01` 명령 과업 `T-11b · T-13b · T-14a · T-15b`, 사람 확인 13개, 채울 값 3칸, 장비 `robot-01`, 순서가 의존성을 지킴 · `02` 실행 가능 · 채울 값 2칸 · `03` 은 `close_gate` 가 「2단계」로 실행 불가 ② 거부 6종(`blocked` · `vocabulary` · `targets` · `not_act` · `shape` · `cycle`) · 명령 과업 없으면 실행 불가 ③ 빈칸 · 범위 밖(3° · 400° · 0.01 m · 12 m) · 정상 값의 걸음 · `abort` 가 화면 정지로 ④ 실행 순서 · 사람 확인 · 실패 · 정지 ⑤ 승인 문 ⑥ 대조군 둘(`scan_mission` 을 막지 않는 사본 · 실패한 과업 뒤에도 계속 내는 사본) |
| `verify:no-leak` 6번 (넓힘, `4ae6919`) | 화면 예시와 측정 경로 예시가 글자까지 같은지를 액션 아이템 판까지 · 화면 예시가 맞은 편이 있든 없든 2편이고 정답셋 안에서만 |
| `verify:plan-supersede` (새, `9dfcf81`) | 게이트웨이를 띄워 화면의 다리로 세 경우 — AI 를 고르면 대본 계획이 rejected · 늦게 온 대본 계획도 rejected · 대조군(새 발화면 대본 제안이 다시 선다). 커밋 기록: 고치기 전 동작 사본은 3건 모두 실패로 잡혔다 |
| `verify:one-broker-address` (넓힘, `dfd1733`) | 4절 마지막 줄 |

계획서 §6 에 적힌 것 중 「가짜 Go1 로 끝까지」 · `verify:no-publish-before-approval` · `verify:proposal-gate` 를 AI 편 길로 다시 돌린 결과는 커밋에 남아 있지 않다.

## 6절 — 쓰는 법

1. GPU 가 큰 PC 에서 저장소 최상단의 `gen-lab-server.exe` 를 더블클릭하고, 창에 뜬 주소를 확인한다.
2. 노트북 화면의 발화 판 「생성 서비스 주소」 칸에서 **GPU PC (100.125.71.51)** 를 누르거나 그 주소를 적고 「적용」.
3. 「태스크까지 생성」과 「액션 아이템까지 낸다」를 켜고 생성한다.
4. 제안 카드에서 실행 계획 · 거부 사유를 보고, 「사람이 채울 값」(회전 °, 오른쪽 + · 직진 m)을 채운 뒤 「승인: 실행 준비」.
5. 「임무 시작」을 누르면 걸음이 나간다. 「사람 확인 대기」가 뜨면 카드의 「확인」 · 「실패로 닫기」로 닫는다.

## 7절 — 한계와 남은 것

- **실제 생성은 아직 못 해 봤다.** 이 노트북에서는 600초 한도를 넘는다. 큰 GPU 장비에서 `gen-lab-server.exe` 로 띄워 「액션 아이템까지」 판을 실제로 생성해 봐야 한다.
- **실물 Go1 로 화면 확인이 남았다.** 지금 확인은 검사(정답셋 · 가짜 의존)까지다.
- **사람 확인이 많다.** `MSN-260831-01` 은 과업 17개 중 명령 과업이 4개라 「확인」을 13번 눌러야 끝난다. 실물에서 불편하면 「앞의 명령 없는 과업 한꺼번에 확인」을 더한다(계획서 §7).
- **GPU PC 주소 `100.125.71.51` 은 고정값이다.** 다른 장비를 쓰면 직접 입력한다. 생성 서비스는 인증이 없어 Tailscale 주소로만 여는 것을 권한다.
- 계획서 머리의 상태 줄은 아직 「계획. 구현하지 않았다」다 — 고치지 않았다.
- **2단계:** 수문(`open_gate` · `close_gate`, 게이트웨이 명령 길) · 장치 여러 대 · 병렬 걸음 · 거리 · 각도를 앞 과업 결과(탐지 · 경로)에서 채우기 — 스캔 탐지 계획서의 위치 결과와 이어진다.
