## 1절 — 무엇을 정했나 (사용자 결정)

| 항목 | 결정 |
|---|---|
| 저장 | 서버가 연결돼 있으면 **서버에만**. 불안정하거나 끊겼을 때만 이 PC 파일에 |
| 목록 | 서버가 연결돼 있으면 **서버 목록만** (이 PC 목록과 합치지 않는다) |
| 끊긴 동안 쓰던 판 | 끝날 때까지 이 PC, 끝난 뒤 통째로 서버에 (판을 두 곳에 나누지 않는다) |
| 대피 판 올리기 | 자동. 서버 붙기 전의 기존 기록은 `history:push` 로 수동 1회 |
| 이 PC 창구가 없는 화면 | 서버가 끊기면 「저장처 없음」 — 메모리에 쌓지 않는다 |
| 서버 주소 칸 | 연결 관리가 아니라 **임무 이력 화면**에. 상단 바와 목록 · 그래프 칸 사이의 한 줄 가로 띠 |
| 기본 주소 | `http://100.102.8.102:8850` |

1차(`a19eb80`)는 이 PC 와 서버 양쪽에 쓰고 목록을 합쳤다. 사용자가 위 규칙으로 바꾸라고 해서 계획서를 먼저 쓰고 2차(`99a7a91`)로 다시 짰다.

## 2절 — 서버와의 약속

API 는 개발 서버에 붙어 있던 기록 창구(`scripts/mission-records.mjs`)와 **같은 모양**으로 정하고 앞부분만 `/api/v1` 로 바꿨다. 그래서 가시화 쪽은 뿌리 주소만 바꾸면 된다.

| 메서드 | 경로 | 하는 일 |
|---|---|---|
| GET | `/api/v1/health` | 서버 확인 — `service: "mission-history"` 를 봐야 「연결됨」 |
| GET | `/api/v1/runs` | 판 목록 (`mission.json` 에서 `view` 를 뺀 요약) |
| PUT | `/api/v1/runs/{날짜}/{판}/{mission\|progress}.json` | JSON 덮어쓰기 |
| POST | `/api/v1/runs/{날짜}/{판}/images/{detect\|robot}/{이름}` | 그림 |
| GET | `/api/v1/files/{날짜}/{판}/{경로}` | 저장된 파일 |

지우는 창구는 없다(이력은 지우지 않는다). 서버는 브라우저가 직접 부르므로 CORS · 사설망 허용 머리를 연다.

서버 담당이 만든 것: PostgreSQL 16, 명세 §5 권장안의 표 두 개(`mission_runs` · `mission_run_images`), 그림은 디스크에 두고 경로만 DB 에, 매일 22:00 자동 백업(30일 보관). 적합성 검사 44/44.

## 3절 — 가시화 쪽에서 만든 것

### 저장 · 조회

| 파일 | 하는 일 |
|---|---|
| `src/record/historyServer.ts` | 주소 저장(기본 주소 포함) · 10초마다 health · 상태 판정 · 서버 쓰기(5초 한도) |
| `src/record/recordClient.ts` | 판마다 저장처 고르기(`chooseSink`) · 실패 뒤 저장처 바꾸기(`nextSink`) · 한 출처 목록 · 서버 판 다시보기 |
| `src/record/recorder.ts` · `controlRecorder.ts` | 판을 열 때 저장처를 고르고, 서버 쓰기가 실패하면 그 판을 이 PC 로 옮긴다(서버로 보낸 그림도 다시 떠서) |
| `src/record/evacuations.ts` | 대피 판 목록 — 새로고침에도 남는다(`localStorage`) |
| `src/record/historyUpload.ts` | 끝난 대피 판을 `progress.json` → 그림 → `mission.json` 순서로 자동 올리기. 이 PC 파일은 지우지 않는다 |
| `scripts/mission-records.mjs` | 이 PC 창구에 판 파일 목록(`GET …/files`) 추가 · 깨진 JSON 을 500 대신 400 으로 |

**상태 판정.** 미설정 · 확인 중 · 연결됨 · **불안정** · 닿지 않음 · 임무 이력 서버 아님 · 서버 오류. 서버 쓰기가 한 번 실패하면 곧바로 불안정이 되고, health 가 **두 번 연속** 성공해야 연결됨으로 돌아온다 — 와이파이가 흔들릴 때 판이 서버와 파일을 오가며 쪼개지는 것을 줄인다.

## 4절 — 기존 판 올리기와 확인

```
npm run history:push -- http://100.102.8.102:8850
올림 136/136판 · 44.1MB
```

| 확인 | 결과 |
|---|---|
| 서버 목록 | 140판 = 136판 + 적합성 검사 판 4개(`000101`, 화면에서 숨김) |
| 그림 | 표본 해시가 바이트까지 같다 |
| JSON | 서버가 JSONB 로 넣어 칸 순서 · 공백이 바뀐다(명세 §5 허용). 표본 4판 8개를 칸 순서를 무시하고 비교해 값이 8/8 같다 |
| 화면 | 새 브라우저에서 기본 주소로 「연결됨 · 서버 판 136개」 |
| 다른 기기 | 사용자가 Tailscale 에 붙은 다른 기기에서 같은 목록 · 다시보기를 확인했다 |

다른 기기의 기록을 올리다가 비행 판 하나가 NUL 문자 때문에 거절된 일은 같은 날 다른 세션이 고쳤다(`5339c07`, [NUL 문자 거절 보고](2026-11-19_임무이력서버_NUL문자거절.md)).

## 5절 — 도중에 잡은 문제

| 문제 | 원인 | 고친 것 |
|---|---|---|
| 이 PC 창구가 깨진 JSON 에 500 | `JSON.parse` 예외가 그대로 서버 오류로 나갔다 | 400 으로. 적합성 검사가 처음 잡았다 |
| 가짜 서버에 붙었는데 「서버 오류 HTTP 404」 | 기본 포트 8790 을 게이트웨이(`gateway/config.ts`)가 127.0.0.1 에 쓰고 있었다. Windows 가 0.0.0.0:8790 을 겹쳐 열어 주어 `localhost` 요청을 게이트웨이가 받았다 | 가짜 서버를 8820 으로. 뜬 뒤 자기 health 를 물어 다른 프로그램이 받으면 멈춘다 |
| 그래프 칸이 상단 바보다 오른쪽으로 튀어나옴 (1280px 창에서 265px) | 리플레이 격자 `300px 1fr` — `1fr` 은 내용보다 좁아지지 못하는데, 그래프 캔버스가 자기 칸 폭을 재서 그려 되먹임이 생겼다 | `minmax(0,1fr)`. 1280 · 1816 · 2560px 에서 오른쪽 끝이 같다 |
| 새 브라우저에서 기본 주소가 안 섬 | 기본 주소 상수가 모듈 초기화 코드보다 아래에 있어, 처음 읽을 때 아직 없는 상수를 읽다(TDZ) 예외를 `catch` 가 삼켰다 | 상수를 위로. 「모듈을 처음 읽을 때 기본 주소」 검사 추가 — 기존 검사는 다 읽은 뒤 다시 초기화해서 못 잡았다 |
| `verify:mission-history` 가 늘 실패 | `dd7dbac` 에서 셸의 오른쪽 목록 판을 뺐는데 검사는 셸도 목록을 그려야 한다고 봤다 | 지금 구조(리플레이 기둥 한 자리 · ◷ 버튼은 그 화면으로)를 보게 고침 |
| `verify:i18n-no-frozen` 실패 | `fixedcam/CameraStateView.tsx` 의 `Tiles()` 에 `useLang()` 없음(`9d7d4e2`) | 한 줄 추가. 화면 버그는 아니었다 — 부모가 걸고 있었다 |

## 7절 — 쓰는 법과 한계

- **새 기기**: Tailscale 에 붙이고 가시화를 열면 기본 주소로 자동 연결된다. 입력할 것이 없다.
- **서버 붙기 전에 쌓인 기록**: 그 기기에서 `history:push --dry` → `history:push`. 그 기기가 Tailscale 에 못 붙으면 `mission-history/` 를 복사해 와서 `--dir` 로.
- **Tailscale 밖 기기는 서버에 못 닿는다.** 서버에 인증이 없어 서버 담당이 tailnet 안에서만 열었다. 밖에서 써야 하면 서버 담당과 LAN 개방 · 인증을 따로 정해야 한다.
- **적합성 검사는 필요할 때만.** 돌릴 때마다 서버에 `000101` 시험 판이 쌓인다(지울 수 없다).
- **판 이름이 겹치는 경우.** 판 키는 「날짜/시작 시각_임무 id」라 두 기기가 같은 임무를 같은 초에 시작하면 겹친다. `history:push` 는 그 판을 「이미 있음」으로 건너뛴다. 실제로는 거의 없다.
- 대피 판 수 · 올리기 진행은 띠를 한 줄로 줄이면서 화면에서 뺐다(동작은 그대로다). 필요하면 상태 알약 옆에 짧은 표시를 다시 넣을 수 있다.
