# A2-W 라즈베리파이(pi10) 1단계 설정 보고 (2026-11-12)

전환 계획: [2026-11-12_A2W라즈베리파이전환계획.md](2026-11-12_A2W라즈베리파이전환계획.md)
작업 프롬프트: `pi-a2/PROMPT.md` 1단계 (책상에서 Pi 기본 설정, 로봇 없이)

## 요약

- A2-W용 Pi는 새 `pi-a2`가 아니라 **기존 `pi10`** 을 쓴다.
  - 호스트 이름과 Tailscale 이름(`pi10.tailcb6bfb.ts.net`)은 바꾸지 않았다.
  - 프롬프트와 스크립트의 `pi-a2`는 `pi10`으로 읽는다.
  - 웹 접속 주소: `ws://pi10.tailcb6bfb.ts.net:9001/mqtt`.
- 1단계를 마쳤다. `check-pi.sh`의 network, tailscale, services, mqtt 항목이 **모두 OK** 다.
- 작업 전에 pi10에서 도는 브로커가 없음을 확인했다. Go1이나 다른 장비의 브로커와 겹치지 않는다. A2 전용 브로커다.
- 확인하지 못한 것:
  - 다른 PC에서 ws 9001 접속(Tailscale 경유)
  - wlan0 쪽에서 1883과 9001이 실제로 막히는지
  - 재부팅 뒤 자동 복구. 4단계에서 확인한다.
- PC2와 로봇에는 아무것도 하지 않았다. 2단계부터 다룬다.

## 2. 결정 사항 (사람 확인)

| 질문 | 결정 |
|---|---|

추가 확인:
- Tailscale 주소 `100.114.142.85:9001/mqtt`로 WebSocket 핸드셰이크를 보내 `101` 응답을 받았다.
- Tailscale 주소 1883으로 `$SYS/broker/version`을 구독해 응답을 받았다.
- eth0 설정은 재부팅 뒤에도 남는다.
  - `a2-pc2`는 NM 키 파일로 저장되었다.
  - `netplan-eth0` 자동 연결 끄기는 netplan yaml에 `autoconnect: "false"`로 기록되었다.

## 7. 주의

- **`sudo systemctl restart nftables`(또는 `start`)를 쓰지 않는다.**
  - `nftables.conf` 첫 줄의 `flush ruleset`이 tailscaled 규칙까지 지운다.
  - a2viz 표를 다시 올릴 때는 `sudo nft -f /etc/nftables.d/a2.nft`를 쓴다.
- 부팅 때는 문제가 없을 것으로 본다.
  - nftables는 `Before=network-pre.target`이라 tailscaled보다 먼저 돈다.
  - 그래서 flush가 끝난 뒤 tailscaled가 규칙을 넣는다.
  - 실제 재부팅 확인은 4단계에서 한다.
- 브로커는 인증 없이 열려 있다. 방화벽(a2viz 표)이 빠지면 wlan0 쪽에 그대로 노출된다.
- `/etc/NetworkManager/system-connections/SysAILAB_5GHz.nmconnection`은 작업 전부터 0바이트였다. 실제 연결은 netplan 프로필로 된다. 손대지 않았다.

## 8. 되돌리기

```
sudo nft delete table inet a2viz
sudo sed -i '/nftables.d\/a2.nft/d; /A2-W 브로커\/카메라 포트 제한/d' /etc/nftables.conf
sudo systemctl disable nftables
sudo systemctl disable --now a2-camrelay mosquitto
sudo rm /etc/systemd/system/a2-camrelay.service /etc/mosquitto/conf.d/a2.conf /etc/nftables.d/a2.nft
sudo nmcli con delete a2-pc2
sudo nmcli con mod netplan-eth0 connection.autoconnect yes
```

## 9. 남은 일

✋ 사람이 할 일:
1. 다른 PC에서 `ws://pi10.tailcb6bfb.ts.net:9001/mqtt` 접속을 확인한다.
2. 같은 Wi-Fi(192.168.50.x)의 다른 PC에서, Tailscale을 거치지 않고 `192.168.50.73:9001`과 `:1883`에 접속이 **안 되는지** 확인한다.
3. 2단계를 준비한다.
   - Pi 랜 포트를 항공 커넥터 변환 케이블에 꽂고, 링을 끝까지 돌려 잠근다.
   - 전원은 보조배터리로 준다.
   - `ssh-copy-id` 때 PC2 비밀번호를 넣는다.

다음 단계:
- 2단계: PC2 ping, SSH 키 등록, PC2 상태를 확인만 한다.
- 3단계: 브리지를 Pi 브로커로 옮긴다.
- 4단계: 자동 시작을 설정하고 재부팅으로 확인한다.
- 웹 프리셋에 `pi10`을 추가한다. 노트북 쪽 `presets.ts`에서 한다.
