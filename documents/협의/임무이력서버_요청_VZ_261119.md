# 임무 이력 서버 요구사항 명세 (VZ → 서버)

> 보내는 쪽: 가시화(VZ) · 작성 2026-11-19
> 받는 쪽: 서버 담당
> 함께 보는 파일: `viz-debugger/scripts/check-history-server.mjs` (적합성 검사 — 이 파일 하나만 있으면 돌아갑니다)
> 참고 구현: `viz-debugger/scripts/history-server-mock.mjs` (같은 API 를 폴더에 저장하는 가짜 서버)

## 0. 요약

가시화 웹의 **임무 이력**(끝난 판의 목록과 다시보기)은 지금 웹을 띄운 PC 의 `mission-history/` 폴더에만 저장됩니다.
그래서 다른 PC·태블릿에서는 그 이력을 볼 수 없습니다. **서버 DB 에 같이 저장해서, 어느 장치에서든 모든 판을 조회**하려고 합니다.

부탁드리는 것은 **HTTP 서버 하나**입니다.

- 판마다 JSON 문서 두 개(`mission.json` · `progress.json`)와 그림(JPEG)을 받아 저장합니다.
- 판 목록과 저장된 파일을 돌려줍니다.
- 브라우저가 직접 부르므로 **CORS 를 열어야** 합니다.

API 모양은 지금 가시화 개발 서버에 붙어 있는 저장 창구와 **같은 모양**으로 정했습니다. 경로 앞부분만 `/api/v1` 로 바뀝니다.

서버가 붙으면 **서버가 기본 저장처**가 됩니다.
- 가시화는 서버가 연결돼 있으면 기록을 **서버에만** 쓰고, 목록도 **서버 목록만** 봅니다.
- 서버가 끊기거나 불안정하면 그동안의 판은 가시화 PC 파일에 대피했다가, 서버가 안정되면 그 판을 **통째로 다시 올립니다**(§6-3).

가시화 쪽(주소 입력 칸 · 연결 상태 · 서버 우선 저장 · 대피와 자동 올리기 · 기존 파일 올리기)은 이 명세대로 **이미 만들어 두었고**, 가짜 서버로 시험했습니다(§8).

**완료 기준은 하나입니다:** `node check-history-server.mjs http://<서버>:<포트>` 가 전부 통과하는 것(§7).

## 1. 지금 저장되는 것 (2026-11-19 실측)

판(run) 하나가 폴더 하나입니다. 키는 **날짜 + 판 이름** 두 개입니다.

```
mission-history/
  261021/                          날짜 (YYMMDD, 웹을 띄운 PC 의 시계)
    102025_MSN-260909-01/          판 이름 (HHMMSS_임무id)
      mission.json                 어떤 임무였나 · 결과 (요약 + 임무 정의 전체 `view`)
      progress.json                어떻게 진행됐나 (기록 열 · 로봇 명령/응답 · 탐지 결과 · 로그)
      images/detect/*.jpg          탐지 서버가 내준 그림
      images/robot/*.jpg           로봇이 찍어 보낸 원본
```

| 항목 | 실측 |
|---|---|
| 판 수 | 135판 (15일치) — 임무 판 117 · 조작 판 18 (`CTL-` 수동 제어 · `FLT-` 비행) |
| 전체 크기 | 48MB (그림 955장 · JSON 270개) |
| `progress.json` 최대 | 659KB |
| `mission.json` 최대 | 27KB |
| 그림 최대 / 평균 | 208KB / 37KB |
| 판 하나의 그림 최대 | 29장 · 판 하나 최대 1.6MB |

판의 종류는 둘입니다. 서버는 **둘을 구분할 필요가 없습니다** — 같은 방식으로 저장하고 돌려주면 가시화가 가릅니다.

- **임무 판** — `mission.json` 에 `recordKind` 칸이 없습니다.
- **조작 판** — `mission.json` 에 `"recordKind": "control"` 이 있습니다. 그림은 없습니다.

## 2. 범위

**이번에 할 것**

1. 서버 확인(health) 1개, 쓰기 2개, 읽기 2개 — 모두 5개 API (§3)
2. DB 에 판 · 문서 · 그림 저장 (§5)
3. CORS (§6-1)

**이번에 하지 않는 것**

- **삭제 API 는 만들지 않습니다.** 이력은 지우지 않는다는 것이 팀 규칙입니다. 시험으로 돌린 판도 남깁니다.
  `DELETE` 요청이 오면 4xx 로 거절하면 됩니다.
- 인증·권한 — Tailscale 망 안에서만 쓰므로 v1 에는 넣지 않습니다. 붙일 때는 `Authorization: Bearer <토큰>` 머리로 하자는 것만 정해 둡니다(CORS 허용 머리에 이미 넣어 달라고 했습니다).
- 화면 녹화 영상(`video/`) — 이번 범위가 아닙니다.
- 검색·통계 API — 목록 하나면 됩니다. 필터는 가시화가 합니다.
- JSON 내용 해석 — 서버는 문서를 **열어 보지 않고 그대로 저장했다가 그대로 돌려주면** 됩니다.
  (목록 정렬 · 색인을 위해 몇 칸을 꺼내 쓰는 것은 괜찮습니다 — §5)

## 3. API

뿌리 주소: `http://<서버>:<포트>/api/v1` (포트는 정해 주세요. 가짜 서버는 8820 을 씁니다 — 가시화 게이트웨이가 8790 을 쓰므로 그 번호는 피해 주세요.)

| # | 메서드 | 경로 | 하는 일 |
|---|---|---|---|
| A1 | GET  | `/api/v1/health` | 서버 확인 |
| A2 | GET  | `/api/v1/runs` | 판 목록 |
| A3 | PUT  | `/api/v1/runs/{date}/{run}/{file}` | JSON 문서 쓰기 (`file` = `mission.json` \| `progress.json`) |
| A4 | POST | `/api/v1/runs/{date}/{run}/images/{kind}/{name}` | 그림 쓰기 (`kind` = `detect` \| `robot`) |
| A5 | GET  | `/api/v1/files/{date}/{run}/{path…}` | 저장된 파일 읽기 |

모든 응답에 CORS 머리(§6-1)를 붙입니다. 오류 응답 본문은 `{"error": "<사유>"}` 꼴의 JSON 으로 해 주세요.

### 3-0. 이름 규칙 — 먼저 검사하고, 틀리면 400

경로의 이름은 **저장 전에 정규식으로 검사**해 주세요. `..` 이나 `/` 가 섞인 이름으로 다른 판이나 서버 파일을 쓰거나 읽지 못하게 하려는 것입니다.
경로 조각은 URL 인코딩되어 옵니다(판 이름에 `.` 이 있을 수 있음). 디코딩한 뒤 검사합니다.

| 자리 | 정규식 | 예 |
|---|---|---|
| `date` | `^\d{6}$` | `261021` |
| `run` | `^\d{6}_[A-Za-z0-9_.-]{1,80}$` | `102025_MSN-260909-01` · `152717_CTL-mt4-01` |
| `file` | `^(mission\|progress)\.json$` | `mission.json` |
| `kind` | `^(detect\|robot)$` | `detect` |
| `name` | `^[A-Za-z0-9_.-]{1,120}\.(jpg\|jpeg\|png)$` | `frame_000113_target_overlay.jpg` · `rot_045.jpg` |

### A1. `GET /api/v1/health` — 서버 확인

가시화가 **10초마다** 부릅니다. 이 응답으로 「연결됨」을 띄웁니다. 아무 200 이 아니라 **`service` 값을 봅니다** — 주소를 다른 서버로 잘못 넣었을 때 「임무 이력 서버가 아님」으로 따로 알려 주기 위해서입니다.

```json
200
{
  "ok": true,
  "service": "mission-history",
  "apiVersion": 1,
  "serverTime": "2026-11-19T01:42:05.000Z",
  "runCount": 135
}
```

| 칸 | 필수 | 뜻 |
|---|---|---|
| `service` | **필수** | 정확히 `"mission-history"` |
| `apiVersion` | **필수** | `1` |
| `serverTime` | 필수 | ISO 8601 |
| `runCount` | 권장 | 목록에 나오는 판 수. 가시화 화면에 「서버 판 N개」로 뜨고, **이 값이 바뀌면 화면이 목록을 다시 읽습니다** — 다른 장치가 쓴 판이 바로 보이게 하는 장치입니다. |

DB 가 죽었는데 프로세스만 살아 있으면 503 을 주세요(가시화는 「서버 오류 HTTP 503」으로 띄웁니다).

### A2. `GET /api/v1/runs` — 판 목록

```json
200
{
  "dir": "physical-db@server-01",
  "runs": [
    { "date": "261117", "run": "161335_CTL-mt4-01", "mission": { "schema": "control-record/1", "recordKind": "control", "...": "..." } },
    { "date": "261021", "run": "102025_MSN-260909-01", "mission": { "schema": "mission-record/2", "missionId": "MSN-260909-01", "label": "...", "outcome": "done", "...": "..." } }
  ]
}
```

- **`mission` 은 저장된 `mission.json` 에서 `view` 칸 하나만 뺀 나머지 전부**입니다. 칸을 고르거나 이름을 바꾸지 말아 주세요 — 가시화가 목록 줄을 그릴 때 그 칸들을 씁니다(§4).
  (`view` 는 임무 정의 전체라 커서 뺍니다. 다시보기를 열 때 A5 로 `mission.json` 전체를 따로 읽습니다.)
- **`mission.json` 이 아직 없는 판은 목록에 넣지 않습니다.** 가시화는 `progress.json` → 그림 → `mission.json` 순서로 쓰기 때문에, 이렇게 하면 반쯤 올라간 판이 목록에 안 보입니다.
- 저장된 `mission.json` 이 깨져서 읽을 수 없으면 그 줄은 `"mission": null` 로 주세요(목록 전체를 실패시키지 않습니다).
- **정렬: 최근 것이 먼저** — 문자열 `"{date}/{run}"` 내림차순.
- 페이지 나누기는 v1 에서 하지 않습니다. 판이 수천 개여도 요약은 판당 1KB 안팎이라 한 번에 줍니다. 5,000판에서 2초 안에 답하면 충분합니다.
- `dir` 은 선택입니다(서버 이름 같은 것). 없으면 빈 문자열로 둡니다.

### A3. `PUT /api/v1/runs/{date}/{run}/{file}` — JSON 문서 쓰기

- 본문: `Content-Type: application/json`, UTF-8 JSON 문서 하나.
- **덮어쓰기(upsert)** 입니다. 판이 없으면 만들고, 있으면 그 파일을 통째로 바꿉니다.
- **같은 파일이 판이 도는 동안 계속 다시 옵니다.** 가시화 기록기는 1.5초마다 바뀐 것을 확인해 바뀐 파일을 통째로 다시 보냅니다. 한 장치가 판 하나를 돌리면 대략 **초당 1~2건**입니다. 마지막에 온 것이 이깁니다.
  같은 파일에 대한 요청은 가시화가 **차례로**(앞 요청 응답을 받은 뒤) 보내므로 순서 역전은 신경 쓰지 않아도 됩니다.
- **JSON 이 깨졌으면 400** 이고 저장하지 않습니다.
- 크기 상한은 **32MB 이상**으로 해 주세요(실측 최대 0.7MB · 리허설이 길어지면 커집니다).
- **읽는 쪽이 반쯤 쓴 문서를 보지 않게** 해 주세요(트랜잭션 · 임시 파일 후 교체 등). 목록과 쓰기가 동시에 일어납니다.

```json
200  { "ok": true, "path": "261021/102025_MSN-260909-01/mission.json" }
400  { "error": "깨진 JSON 입니다" }          // 또는 이름 규칙 위반
413  { "error": "본문이 너무 큽니다" }
```

### A4. `POST /api/v1/runs/{date}/{run}/images/{kind}/{name}` — 그림 쓰기

- 본문: 그림 바이트 그대로(`Content-Type: image/jpeg`, 드물게 `image/png`). multipart 가 아닙니다.
- 같은 이름이 다시 오면 **덮어씁니다**(탐지가 판을 다시 시작하면 같은 이름의 새 그림이 옵니다).
- **빈 본문은 400.** 그림 하나 상한은 15MB 이상.
- 그림 내용을 검사·변환하지 마세요. 받은 바이트 그대로 돌려줘야 합니다.

```json
200  { "ok": true, "path": "261021/102025_MSN-260909-01/images/detect/frame_000113_target_overlay.jpg", "bytes": 38211 }
```

### A5. `GET /api/v1/files/{date}/{run}/{path…}` — 저장된 파일 읽기

`path` 는 `mission.json` · `progress.json` · `images/detect/<name>` · `images/robot/<name>` 넷 중 하나의 꼴입니다.

- 쓴 그대로 돌려줍니다. `mission.json` 은 **`view` 를 포함한 전체**입니다.
- `Content-Type`: `.json` → `application/json; charset=utf-8`, `.jpg/.jpeg` → `image/jpeg`, `.png` → `image/png`.
- 없으면 **404**. 이름 규칙 밖이거나 판 폴더 밖을 가리키면 4xx.
- 그림은 `<img src>` 로 바로 씁니다. `Cache-Control` 은 `no-store` 로 해 주세요(같은 이름이 덮어써질 수 있습니다).

## 4. 문서 모양 — 서버가 알아 두면 좋은 칸

서버는 문서를 그대로 저장하면 되지만, 색인 칸을 뽑을 때 참고하도록 실제 칸을 적습니다.

**임무 판 `mission.json`** (`schema: "mission-record/2"`)

```
schema, folder, missionId, label, startedAtIso, updatedAtIso, endedAtIso, outcome, done, of,
failedTaskId, reason, headSec, robotDriven, testMode, imageCount, path, pathFailure, connections, view
```

- `outcome`: `"done"` · `"failed"` · `"stopped"` · `null`(아직 도는 중이거나 끝 표시 없이 끊김)
- `startedAtIso` · `updatedAtIso` · `endedAtIso`: ISO 8601 (UTC)
- `view`: 임무 정의 전체(태스크 그래프). **목록에서는 빼고, A5 에서는 줍니다.**

**조작 판 `mission.json`** (`schema: "control-record/1"`)

```
schema, recordKind("control"), folder, sessionKind, deviceId, missionId, startedAtIso, updatedAtIso,
endedAtIso, closeReason, counts, actions, missions, flight, telemetry
```

**`progress.json`** — 가시화만 읽습니다. 서버는 열어 볼 필요가 없습니다.

```
schema, missionId, updatedAtIso, headSec, trace, viewpointFrames, robot, robotFrames, detect,
detectLog, prep, notifications, images  (자율주행 편은 nav · obstacle 추가)
```

문서 모양(`schema` 값)은 가시화 쪽에서 앞으로도 바뀔 수 있습니다. **서버가 칸을 검증하거나 모르는 칸을 버리면 안 됩니다.**

## 5. 저장 — 권장안 (DB 종류는 서버 담당이 고릅니다)

API 만 지키면 내부 구조는 자유입니다. 참고로 권장안을 적습니다.

```sql
-- 판 하나 = 한 줄
CREATE TABLE mission_runs (
  date          CHAR(6)      NOT NULL,          -- '261021'
  run           VARCHAR(90)  NOT NULL,          -- '102025_MSN-260909-01'
  mission_doc   JSONB,                          -- mission.json 전체 (view 포함). NULL 이면 목록에 안 나옴
  progress_doc  JSONB,                          -- progress.json 전체
  -- 색인용으로 mission_doc 에서 꺼낸 칸 (선택)
  record_kind   VARCHAR(16)  GENERATED ALWAYS AS (COALESCE(mission_doc->>'recordKind', 'mission')) STORED,
  mission_id    VARCHAR(90)  GENERATED ALWAYS AS (mission_doc->>'missionId') STORED,
  created_at    TIMESTAMPTZ  NOT NULL DEFAULT now(),
  updated_at    TIMESTAMPTZ  NOT NULL DEFAULT now(),
  PRIMARY KEY (date, run)
);

-- 그림 = 한 줄 (바이트는 bytea 또는 디스크/오브젝트 저장소 경로)
CREATE TABLE mission_run_images (
  date          CHAR(6)      NOT NULL,
  run           VARCHAR(90)  NOT NULL,
  kind          VARCHAR(8)   NOT NULL,          -- 'detect' | 'robot'
  name          VARCHAR(130) NOT NULL,
  content_type  VARCHAR(32)  NOT NULL,
  bytes         BYTEA,                          -- 또는 storage_path TEXT
  updated_at    TIMESTAMPTZ  NOT NULL DEFAULT now(),
  PRIMARY KEY (date, run, kind, name)
);
```

- `JSONB` 는 칸 순서를 바꾸고 공백을 없앱니다 — **괜찮습니다.** 가시화는 파싱해서 씁니다. 다만 값(숫자 정밀도 · 한글 · 빈 배열 · null)은 그대로여야 합니다.
- 목록(A2)은 `mission_doc - 'view'` 로 만들면 됩니다(PostgreSQL).
- 그림은 지금 속도로 하루 수십~수백 장(수 MB)입니다. `bytea` 로 넣어도 되고 디스크에 두고 경로만 넣어도 됩니다.
- **판 키 `(date, run)` 은 장치를 가리지 않습니다.** 두 장치가 같은 임무를 **같은 초에** 시작하면 키가 겹치는데, 실제로는 일어나기 어려워 v1 에서는 「마지막에 쓴 것이 이긴다」로 둡니다.

## 6. 비기능 요구

### 6-1. CORS — 필수

가시화 웹(Vite 개발 서버 `http://<PC>:5173` 등, 출처가 여럿)이 **브라우저에서 서버를 직접** 부릅니다. 중계 서버가 없습니다.
모든 응답(오류 포함)에 다음을 붙이고, `OPTIONS` 사전 요청에는 204 로 답해 주세요.

```
Access-Control-Allow-Origin: *
Access-Control-Allow-Methods: GET, PUT, POST, OPTIONS
Access-Control-Allow-Headers: Content-Type, Authorization
Access-Control-Allow-Private-Network: true
Access-Control-Max-Age: 600
```

`Access-Control-Allow-Private-Network` 는 Chrome 이 사설망(Tailscale `100.x`) 주소로 요청할 때 사전 요청에서 확인하는 머리입니다. 없으면 브라우저에 따라 막힐 수 있어 넣어 달라고 합니다.

### 6-2. 망

- Tailscale 망 안에서 닿는 주소(예: `http://100.x.x.x:<포트>`)로 열어 주세요. 가시화를 띄운 PC 와 다른 장치(태블릿 등) 모두에서 닿아야 합니다.
- HTTP 로 충분합니다. 가시화 웹이 나중에 HTTPS 로 서면 서버도 HTTPS 여야 합니다(브라우저의 혼합 콘텐츠 차단) — 그때 다시 맞춥니다.

### 6-3. 성능 · 안정성

| 항목 | 기준 |
|---|---|
| health 응답 | 1초 안 (가시화는 4초 넘으면 「닿지 않음」으로 봅니다) |
| 쓰기 빈도 | 장치당 초당 1~2건, 장치 3대 동시 |
| 몰려오는 쓰기 | 서버가 끊겼다 돌아오면, 그동안 가시화 PC 에 대피한 판이 한꺼번에 올라옵니다(판당 수 MB · 몇 판). 같은 판을 다시 올리면 덮어쓰기로 받으면 됩니다 |
| 쓰기 응답 | 5초 안. 가시화는 쓰기 한 건이 5초를 넘거나 5xx · 408 · 429 면 서버를 「불안정」으로 보고 그 판을 PC 에 대피시킵니다. 4xx(이름 규칙 · 깨진 JSON)는 서버 탓으로 보지 않습니다 |
| 목록 | 5,000판에서 2초 안 |
| 원자성 | 쓰는 도중의 문서가 목록·읽기에 보이지 않을 것 |
| 보존 | 지우지 않음. 백업 방법은 서버 담당이 정해 알려 주세요 |
| 재시작 | 서버를 다시 띄워도 저장된 판이 그대로 |

## 7. 수용 기준 — 이것이 통과하면 끝

1. **적합성 검사 전부 통과**
   ```
   node check-history-server.mjs http://<서버>:<포트>
   ```
   (`viz-debugger/scripts/check-history-server.mjs` 한 파일만 서버 PC 에 복사해 Node 18 이상으로 돌리면 됩니다.)
   health · CORS · 쓰기 · 덮어쓰기 · 거절(`..` · 깨진 JSON · 빈 그림 · DELETE) · 읽기 · 목록 모양 · 정렬까지 44개를 봅니다.
   `C5`(Private-Network 머리)만 실패하면 경고로 두고 나머지는 전부 통과해야 합니다.
   검사가 쓰는 판은 날짜 `000101` 아래에 생기고, 가시화 화면은 이 날짜를 숨깁니다.
2. **실제 기록 올리기** — 가시화 PC 에서 `npm run history:push -- http://<서버>:<포트>` 로 지금 있는 135판(48MB)이 실패 없이 올라갈 것.
3. **화면 확인** — 가시화 임무 이력 탭 맨 위 칸에 서버 주소를 넣으면 「연결됨 · 서버 판 N개」가 뜨고, **다른 장치**에서 같은 주소를 넣었을 때 같은 목록이 보이고 다시보기가 열릴 것.
