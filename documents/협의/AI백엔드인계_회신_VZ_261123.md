## 1. 주소만 바꾸는 방식은 쓰지 않을 예정입니다

인계 문서에는 `VITE_GATEWAY_HTTP/WS` 를 그쪽 8899 로 바꾸면 된다고 되어 있습니다.

그런데 그 주소는 저희 앱이 원래 쓰는 **저희 게이트웨이 자리**입니다(기본 `127.0.0.1:8790`). 대본 재생 · 승인 · 명령 센터 · 감사 기록이 전부 여기서 옵니다.

배포 가이드 §3-0-1 에서 "우리가 안 낸다"고 적으신 다섯 개도 사실은 **저희 게이트웨이가 내는 것**입니다.

| 경로 | 저희 앱에서 쓰는 곳 |
|---|---|
| `GET /actions?entity=` | 명령 센터 |
| `GET /audit?` | 데이터 탭 감사 기록 |
| `/insight/<id>` | 위험 패널 |
| `/server-metrics` | 셸 서버 상태 카드(개발 서버 중계) |
| `POST /observability/client-metrics` | 앱 자기 관측 |

그래서 게이트웨이 주소를 그쪽으로 바꾸면, 그 다섯 카드만 비는 것이 아니라 **저희 기능 대부분이 멈춥니다.**

**저희가 할 일:** 연결 관리에 **「AI 백엔드(FMS)」 주소 칸을 따로** 만들어 8899 를 거기에 넣을 예정입니다. 저희 게이트웨이 주소는 그대로 둡니다. 패치의 `fmsApi.ts` 가 `GATEWAY.http` 를 쓰는 부분은 이 새 칸을 읽도록 바꿀 예정입니다.

**부탁:** 인계 문서 §0-0 · §2-1 과 배포 가이드 §3-0-1 · §3-2-1 의 "주소 둘만 바꾸면 된다"는 안내를 고쳐 주시면 좋겠습니다. 저희 앱 기준으로는 맞지 않는 안내입니다.

## 2. 패치는 내용을 옮겨서 쓸 예정입니다

패치는 FMS 화면 여섯을 **뷰 노드**로 붙입니다(`viewNodes.tsx` · `axes.ts` · `verify-view-nodes.mjs`).

저희는 이 기능들을 하드웨어 카드 아래 **「기능」 판**에 넣을 예정입니다. 그 판은 이미 그쪽 8765(capability)를 읽고 있어서 성격이 맞습니다. 「기능」 판은 탭 없이 "목록을 누르면 상세가 겹쳐 뜨는" 구조라서(저희 검사 `verify:no-tabs` 가 탭을 막습니다), 화면 배치는 저희가 다시 짤 예정입니다.

| 패치의 부분 | 할 예정인 것 |
|---|---|
| `fmsApi.ts` · `useFms.ts` · `FmsShell.tsx` · `fms.css` | 거의 그대로 가져다 씁니다(주소 칸만 §1 처럼 바꿉니다) |
| 각 화면의 상세(`*Zoom`) | 「기능」 판의 겹쳐 뜨는 상세 화면 본문으로 씁니다 |
| 각 화면의 카드(`*Card`) | 판의 한 줄 요약으로 줄이거나 쓰지 않습니다 |
| 문구(ko · en) | 가져오되 키 이름만 저희 판에 맞게 바꿉니다 |
| `viewNodes.tsx` · `axes.ts` · `verify-view-nodes.mjs` 변경 | 가져오지 않습니다 |

**순서:** 스택 켜고 끄기(`fms-stack`)와 계층 지표(`fms-tiers`)를 먼저 붙이고, 나머지 넷(`fms-twin` · `fms-recommend` · `fms-subtasks` · `fms-deployment`)은 그다음에 할 예정입니다.

## 3. 확인 부탁드립니다

1. **8899 와 8765 는 늘 같은 기계에서 함께 뜨나요?** 그렇다면 「AI 백엔드」 주소 칸 하나에 두 포트를 묶을 예정입니다. 따로 뜰 수 있으면 칸을 둘로 두겠습니다.
2. **8765 도 다른 출처(CORS)와 Tailscale 주소에서 열려 있나요?** 8899 는 실측 표가 있었는데 8765 는 찾지 못했습니다.
3. **계정은 어떻게 보는 게 좋을까요?** 스택 켜기에는 그쪽 로그인(Bearer · `may_operate_stack`)이 필요한데, 저희 앱에도 따로 역할이 있습니다. 저희는 화면에 "AI 백엔드 계정: ○○" 처럼 **따로 표시할 예정**입니다. 두 계정을 하나로 맞출 계획이 있으시면 알려 주세요.

## 4. 인계 문서 §7 요청에 대한 답

### 4-1. `verify:emergency-stop` 이 깨졌다는 것

지금 저희 헤드(`3b0e972`)에서 돌려 보니 **10개 항목이 모두 통과**합니다(실패 0 · 종료 코드 0). 클론하신 뒤에 고쳐진 것 같습니다. §7-2 는 지워 주셔도 됩니다.

### 4-2. 폐기된 요구사항 ID

- 숫자는 말씀하신 그대로 맞습니다(`AI-D` 159 · `AI-C` 91 · `AI-R-03` 6 · `AI-E-03` 2 · `AI-P` 12). 다만 대부분은 `documents/` 의 옛 문서에 있고, 코드에 있는 것은 약 20곳입니다.
- 짚으신 `plans.ts:49` 는 주석이라 **화면에는 뜨지 않습니다.** 화면에 뜨는 것은 게이트웨이 문구 `'AI 계획 생성기 (AI-D-01)'` 같은 자리입니다.
- 저희는 번호를 새 번호로 바꾸기보다, **화면 문구에서 요구사항 ID 를 아예 뺄 예정입니다.** 운영자에게는 의미 없는 번호라서요.
- 정리가 끝나면 다시 알려 드리겠습니다.
