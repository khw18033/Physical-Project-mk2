## 3. 쓰는 법

**임무 이력 탭 서버 칸**

- `http://100.102.8.102:8850` 을 넣습니다. `100.102.8.102:8850` 만 넣어도 되고, 뒤에 `/api/v1` 까지 붙여도 가시화가 떼어 냅니다.
- 붙으면 「연결됨 · 서버 판 N개」가 뜹니다.

**Tailscale 밖 기기**

- 닿지 않습니다. 요청서 §6-2 대로 Tailscale 망 안에서만 열었습니다(§2 대로 인증이 없기 때문입니다).
- 태블릿 · 다른 PC 는 Tailscale 앱으로 팀 tailnet 에 넣으면 같은 주소로 붙습니다.

**명령 (`viz-debugger` 에서)**

```
npm run history:check -- http://100.102.8.102:8850          적합성 검사
npm run history:push  -- http://100.102.8.102:8850 --dry    올릴 판만 미리 보기
npm run history:push  -- http://100.102.8.102:8850          기존 판 올리기 (§7-2)
```

## 4. 저장 · 보존 · 백업

**표 — 명세 §5 권장안 그대로**

- 두 표의 칸 이름 · 형 · 길이 · NULL · 생성 칸 · 기본 키가 §5 와 같습니다.
- 다른 곳은 한 줄입니다: `mission_run_images` 의 `bytes BYTEA` 자리가, §5 가 적어 둔 다른 길인 `storage_path TEXT` 입니다. 그림 바이트는 서버 디스크에 받은 그대로 두고, DB 에는 그 경로만 넣습니다.
- 문서는 `JSONB` 로 넣으므로, §5 에 적힌 대로 칸 순서와 공백은 바뀌고 값은 그대로입니다.
- 표 길이 때문에 이런 쓰기는 400 으로 거절됩니다.
  - `missionId` 가 90자를 넘는 경우 (`mission_id VARCHAR(90)`)
  - `recordKind` 가 16자를 넘는 경우 (`record_kind VARCHAR(16)`)
  - 11-17 에 받아 둔 기록 123판 기준으로는 최대 14자 · 7자였습니다.
- 크기 상한은 JSON 32MB, 그림 15MB 입니다(넘으면 413).

**보존**

- 지우는 창구가 없습니다. `DELETE` 는 405 로 거절합니다.
- 서버 프로그램의 DB 계정에도 지우기 권한이 없습니다.
- 서버를 다시 띄워도 저장된 판은 그대로입니다.

**백업**

- 매일 22:00(KST)에 자동으로 한 번 돕니다. 최근 30일치를 남깁니다.
- 필요할 때 수동 백업을 따로 뜹니다.
- 한 번에 함께 뜨는 것:
  - DB 두 표(`mission_runs` · `mission_run_images`)
  - 그림 폴더 전체

## 5. 서버에 이미 있는 판 — 날짜 `000101` 시험 판

- 적합성 검사를 두 번 돌려서, 날짜 `000101` 아래에 시험 판 6개가 있습니다.
  - 두 번 모두 `CONFORMANCE` · `CTL-check` · `ORPHAN` 셋씩 만들었습니다(시각 `164700` · `172846`).
  - 이 가운데 목록에 나오는 것은 4개입니다. `ORPHAN` 은 `mission.json` 이 없어서 목록에 안 나옵니다.
- 가시화 화면은 `000101` 을 숨기므로 목록에 보이지 않습니다. 팀 규칙(이력은 지우지 않음)대로 남겨 둡니다.
- health 의 `runCount` 는 명세 §3 A1 대로 「목록에 나오는 판 수」이므로 이 4개도 셉니다.
  - 화면의 「서버 판 N개」는 실제 판보다 4개 많게 나옵니다(지금 4 → 135판을 올리면 139).
  - 적합성 검사를 더 돌리면 돌릴 때마다 목록에 나오는 판이 2개씩 늘어납니다.
