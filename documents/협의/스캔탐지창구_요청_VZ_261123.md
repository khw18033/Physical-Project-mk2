# 스캔 탐지 창구 요청 (VZ → data_stream)

> 보내는 쪽: 가시화(VZ) · 작성 2026-11-23
> 받는 쪽: `JNY03/physical_demo` `data_stream` 브랜치 담당
> 함께 보는 문서: [`../작업프롬프트/작업프롬프트_스캔탐지_data_stream_구현계획_261123.md`](../작업프롬프트/작업프롬프트_스캔탐지_data_stream_구현계획_261123.md) (가시화 쪽 계획)
> 상태: **요청 초안.** 이 창구를 누가 만들지는 아직 정하지 않았습니다(§8). 이 문서는 무엇이 필요한지만 적습니다.

## 0. 요약

- 지금 「문 쪽으로 이동」·「박스 앞까지 이동」은 별도 탐지 프로그램(`detect_api_server.py` + `mqtt_stream_receiver.py`, `:8000`)을 씁니다. 회전은 pi7 GO1 의 `scan_mission` 하나에 묶여 있습니다.
- 그 탐지 모델을 `data_stream` 으로 옮길 계획이 있다고 들었습니다. 그래서 **data_stream 이 명령을 받는 창구**를 만들어 주시면, 가시화가 그 창구로 같은 임무를 돌리려 합니다.
- 흐름은 **준비 → (회전하며 각도 표시) → 산출 요청 → 결과**입니다.
- 회전은 가시화가 `turn 45°` 를 여러 번 보내서 합니다. 한 번 돌 때마다 가시화가 「지금 이 각도」를 표시하면(`mark`), **data_stream 은 이미 받고 있는 그 장치의 카메라 스트림에서 프레임 한 장을 잡아** 그 각도의 대표로 씁니다. 그래서 GO1 이 아니어도 data_stream 이 영상을 받는 장치면 됩니다.
- data_stream 은 **대상의 위치**(스캔 시작 기준 방위 · 거리)까지만 내 주시면 됩니다. **경로는 가시화가 계산합니다.**
- 도면 · 받침대 자세 추정은 쓰지 않습니다. 박스 편처럼 탐지 결과만으로 갑니다.
- 문 · 박스 외에 **임의 물체(@)** 도 같은 흐름으로 찾으려 합니다. 이쪽은 글로 된 질의를 열린 어휘 모델에 넘기는 방식을 생각하고 있습니다(§4).

지금 data_stream 은 프레임을 계속 받아 추론만 하고, 요청을 받는 창구 · 각도 묶음 · 로봇 기준 방위가 없습니다(`server_stream_multi_source.py` 의 경로는 전부 「최신 것 읽기」). 아래는 그 빈자리를 채우는 데 필요한 것입니다.

---

## 1. 전체 흐름

```
가시화                              data_stream                        장치(로봇)
  │ POST /scan/prepare  ──────────▶ 장치 → 영상 소스 찾기 · 모델 올림(이미 있으면 그대로)
  │ GET  /scan/status   ◀────────── state: loading → ready
  │ POST /scan/mark {0}  ─────────▶ 그 소스의 다음 프레임 잡기 → 0° 대표
  │ turn 45 ─────────────────────────────────────────────────────────▶ 회전 → 완료 응답
  │ POST /scan/mark {45} ─────────▶ 45° 대표
  │   … (90 · 135 · 180 · 225 · 270 · 315)
  │ turn 45 ─────────────────────────────────────────────────────────▶ 시작 방향으로 돌아옴
  │ POST /scan/finish   ──────────▶ 수집 닫음 · 산출 시작
  │ GET  /scan/result   ◀────────── running → done | failed
  │ (경로 계산 → turn · move_forward 를 장치에)
```

- 장치에 보내는 명령(`turn` · `move_forward`)과 그 완료 응답은 가시화가 다룹니다. data_stream 은 장치를 움직이지 않습니다.
- 회전 중 각도마다 결과를 기다리지 않습니다. 결과는 회전이 끝난 뒤 한 번에 받습니다.

## 2. 프레임 수집

- **`prepare` 의 `device` 로 영상 소스를 고릅니다.** 이미 받고 있는 소스(`robot1` · `robot2` · `a2` 등)와 장치 ID(`go1-001` 등)를 잇는 표가 data_stream 에 하나 필요합니다(§8-6). 소스를 못 찾으면 `prepare` 가 `failed` + `error: "no_stream"` 을 돌려주세요.
- **`mark` 를 받으면, 그 요청을 받은 시각 뒤에 들어온 프레임**을 잡아 주세요. 회전 직후 흔들림을 피하려고 **약 0.5초 뒤의 프레임**을 원합니다(숫자는 맞춰 드릴 수 있습니다).
- 1.5초 안에 새 프레임이 없으면 그 각도는 `frame_captured: false` 로 응답해 주세요. 가시화는 그 각도를 「받지 못함」으로 두고 회전을 계속합니다.
- 같은 각도에 `mark` 가 다시 오면 **마지막 것**이 그 각도의 대표입니다.
- 잡은 프레임이 직전 프레임과 같으면(카메라가 얼었으면) 판정에서 빼고 결과에 그 사실을 적어 주세요.

## 3. 창구 (HTTP)

모든 응답은 JSON, **CORS 허용**(`Access-Control-Allow-Origin: *`, POST 의 `OPTIONS` 포함). 포트는 정해 주세요(§8).

### 3-1. `POST /scan/prepare`

```json
{ "scan_id": "MSN-261123-01-20261123T101500Z", "device": "go1-001",
  "target": "door", "query": null, "steps": 8, "step_deg": 45 }
```

- `target`: `door` | `box` | `object`. `object` 일 때만 `query`(예: `"소화기"`)가 있습니다.
- `scan_id` 는 가시화가 만듭니다. 같은 `scan_id` 로 다시 보내면 같은 응답을 주세요(멱등).
- 같은 `target`(·`query`)의 모델이 이미 올라가 있으면 바로 `ready`.
- 응답: `{ "scan_id", "state": "loading" | "ready" | "failed", "stream": "robot1", "model": "<이름·판>", "error": null }`

### 3-2. `GET /scan/status?scan_id=`

```json
{ "scan_id": "...", "state": "loading|ready|collecting|running|done|failed|cancelled",
  "angles_captured": [0,45,90,135,180], "error": null }
```

- `ready` 가 될 때까지 가시화가 1초마다 묻습니다.

### 3-3. `POST /scan/mark`

```json
{ "scan_id": "...", "rotation_deg": 45 }
```

- 응답: `{ "scan_id", "rotation_deg": 45, "frame_captured": true, "frame_n": 18342, "captured_at": "2026-11-23T10:15:31.204Z" }`
- **2초 안에** 응답해 주세요. 가시화는 응답을 받은 뒤에 다음 `turn` 을 보냅니다(그래야 잡는 동안 장치가 돌지 않습니다).
- 응답 뒤 가시화는 곧바로 `/scan/frame?kind=original` 로 그 각도 그림을 가져가 각도 칸에 띄웁니다.

### 3-4. `POST /scan/finish`

```json
{ "scan_id": "..." }
```

- 마지막 회전이 끝난 뒤 가시화가 보냅니다. 이것이 산출의 시작 신호입니다.
- 응답: `{ "scan_id", "state": "running" }`

### 3-5. `GET /scan/result?scan_id=`

```json
{
  "scan_id": "...", "state": "done", "target": "door", "query": null,
  "frames": [
    { "rotation_deg": 0,  "frame_n": 18301, "found": false, "score": 0.08, "box_xyxy": null, "reason": "후보 없음" },
    { "rotation_deg": 90, "frame_n": 18366, "found": true,  "score": 0.71, "box_xyxy": [412,96,598,470],
      "bearing_deg": 96.4, "distance_m": 2.35, "distance_valid": true }
  ],
  "best": { "rotation_deg": 90, "bearing_deg": 96.4, "distance_m": 2.35, "distance_valid": true,
            "distance_note": null },
  "evidence": { "cues": [ ["색", 0.82, "문틀 갈색 비율 61%"], ["기준영상", 0.79, "기준 문 사진과 유사도 0.79 ≥ 0.75"] ],
                "enough": true },
  "reason": "90° 방향에서 문을 찾았습니다 — 색 · 기준영상 단서 통과",
  "model": "<이름·판>", "computed_at": "2026-11-23T10:16:02Z"
}
```

| 필드 | 뜻 | 필수 |
|---|---|---|
| `frames[]` | 프레임을 잡은 **모든 각도**. 못 잡은 각도는 빠집니다. | 예 |
| `frames[].found` · `score` | 그 각도의 판정과 점수. 점수는 확률이 아니어도 됩니다 — 이름만 적어 주세요. | 예 |
| `frames[].box_xyxy` | 원본 해상도 픽셀 `[x1,y1,x2,y2]`. 못 찾았으면 `null`. | 예 |
| `frames[].reason` | 못 찾은 각도의 짧은 이유. | 아니오 |
| `best` | 이동할 대상 하나. 못 찾았으면 `null` 이고 `state` 는 `done` 입니다. | 예 |
| `bearing_deg` | **스캔 시작 방향 기준, 시계 방향 +, −180~180.** `rotation_deg + atan((u−cx)/fx)` (§5). | 예 |
| `distance_m` · `distance_valid` | 카메라에서 대상까지 거리(m). 믿을 수 없으면 `distance_valid: false` + `distance_note` 에 이유. | 예 |
| `evidence.cues[]` | `[단서 이름, 0~1, 설명 한 줄]`. 근거 카드에 그대로 표로 나옵니다. | 예 (빈 배열 가능) |
| `reason` | 사람이 읽는 한 문장. | 예 |

- `state: failed` 는 **산출 자체가 안 된 것**입니다(잡은 프레임 없음 · 모델 오류). `error` 에 이유를 적어 주세요. 「찾지 못함」은 `done` + `best: null` 입니다.

### 3-6. `GET /scan/frame?scan_id=&rotation_deg=&kind=`

- `kind`: `original` | `overlay`(상자를 입힌 것, 결과 뒤) | `crop`(대상만 잘라낸 것, `found` 인 각도만).
- 응답은 `image/jpeg`. 각도별 판정 화면 · 근거 카드 · 임무 기록에 씁니다.

### 3-7. `POST /scan/cancel`

```json
{ "scan_id": "..." }
```

- 사람이 정지를 누르면 보냅니다. 수집 · 산출을 멈추고 `state: cancelled`.

### 3-8. `GET /health`

- 지금 있는 `/health` 에 `scan: { ready_targets: ["door","box"], busy_scan_id: null, devices: {"go1-001": "robot1"} }` 정도를 더해 주시면, 가시화 연결 판의 「확인」 버튼이 씁니다.

## 4. 대상별 모델

| `target` | 바라는 것 |
|---|---|
| `door` | 지금 탐지기의 문 판정(색 · 모양 · 기준영상 · 채도 관문)을 옮긴 것. 관문 결과는 `evidence.cues[]` 로. |
| `box` | 지금 탐지기의 박스 판정(YOLO 점수 관문 · 거리 유효범위). **`river` 프로필은 cardboard box 를 미끼로 버리므로 따로 두어야 합니다.** |
| `object` | `query` 를 text 질의로 쓰는 열린 어휘 모델(YOLOE text 모드 등). 지금 YOLOE 는 분류를 시작할 때 한 번만 고정하므로, `prepare` 에서 질의가 바뀌면 다시 임베딩해 주세요. |

## 5. 방위와 거리

- **방위:** `rotation_deg` 는 가시화가 `mark` 로 알려 준 값입니다. 상자 가운데 `u` 와 그 장치 카메라의 `cx` · `fx` 로 `rotation_deg + atan((u−cx)/fx)`. 지금 `vision_config.yaml` 에서 로봇 카메라 FOV 가 `null`(UniDepth 추정)이라 **쓸 장치 카메라마다 내부 파라미터 보정**이 필요합니다. 어안이면 왜곡 보정도 같이.
- **거리:** 옮겨 오는 모델의 보정 곡선이든 UniDepth 든 좋습니다. 다만 **`distance_valid` 하나로 믿어도 되는지 분명히** 알려 주세요(지금 `dist: null` / `space` 로 나뉘는 것 대신). 가시화는 `false` 면 움직이지 않습니다.
- 회전 오차(여러 번 나눠 돈 오차)는 가시화가 장치 방위로 보정합니다. data_stream 은 `rotation_deg` 를 그대로 믿으면 됩니다.

## 6. 시간

| 구간 | 바라는 한도 |
|---|---|
| `prepare` → `ready` | 60초 안 (이미 올라가 있으면 즉시) |
| `mark` 응답 | 2초 안 |
| `finish` → `done` | 8각도 기준 30초 안 |

가시화는 이 한도를 넘기면 「탐지 응답 없음」으로 멈추고 움직이지 않습니다. 숫자는 맞춰 드릴 수 있습니다.

## 7. 한 번에 하나

- 한 장치에 동시에 한 판만 받으면 됩니다. 다른 `scan_id` 가 진행 중일 때 `prepare` 가 오면 `409` 와 진행 중인 `scan_id` 를 돌려주세요.

## 8. 상의할 것

1. **이 창구를 누가 만드나.** data_stream 쪽에서 만들지, 가시화가 data_stream 저장소에 직접 붙일지 정해야 합니다.
2. **포트와 호스트.** sysai-server2(`100.102.8.102`)의 새 포트 하나를 생각하고 있습니다.
3. **`object` 질의 언어.** 가시화는 발화에서 뽑은 한국어(예: `"소화기"`)를 그대로 보냅니다. 영어 질의가 필요하면 data_stream 이 옮길지, 가시화가 `query_en` 을 같이 보낼지 정해야 합니다.
4. **GPU 메모리.** `river` 와 스캔용 모델 셋이 함께 올라가도 되는지.
5. **기준영상 · 보정 자료.** 지금 탐지기의 문 기준영상 · 거리 보정 곡선을 그대로 가져올 수 있는지. 그 자료는 GO1 앞 카메라 기준이라, 다른 장치 카메라에서는 다시 맞춰야 할 수 있습니다.
6. **장치 → 영상 소스 표.** 장치 ID(`go1-001` · A2 등)와 data_stream 소스 이름(`robot1` · `a2` 등)을 어디에 둘지. data_stream 설정에 두는 쪽을 생각하고 있습니다.
