이번 기능에 중요한 사실:

1. **가시화는 스트림만 읽는다**(계획 §1-4). 모델이 어디서 도는지는 `orchestration_stream` 의 배치표에, 그 장치가 무엇인지는 `node_resource_stream` 에 있다.
2. **`/health` 에는 실행 장치가 없다.** `/health.host` 는 영상을 받는 data_stream 서버의 호스트 이름이다(`server_stream_multi_source.py:1305`). 비전 프로세스 위치가 아니다.
3. **지금 규칙에서는 탐지 모델이 모두 data_stream 노트북에서 돈다.** GPU 작업(yoloe · river · targeted · unidepth · moge2_aerial)은 `role=gpu` 노드에만 두고 파이로 옮기지 않는다(`placement.py` `place_gpu`). 그 노드가 로컬이 아니면 「원격 GPU Executor 없음」으로 실패한다(`controller.py` submit). 파이에 가는 것은 CPU 작업(`cpu_units`, 예: `cam360_slice`)뿐이고, 이것도 비교 측정 전이라 지금은 data_stream 기기에 둔다.
   → 이 기능은 **지금은 거의 늘 「노트북」을 보여 준다**. 노드가 늘거나 CPU 탐지 모델이 생길 때를 대비한 표시다.
4. 노드 이름이 문서마다 다르다. 자원표는 WSL 을 `book-4vg1edpvi5-1`, `nodes.json` 은 `book-4vg1edpvi5-wsl` 로 적었다. 로컬 노드 이름은 `DS_NODE_NAME` 이 있으면 그것, 없으면 호스트 이름이다(`probe.node_name()`). **화면에 노드 이름을 박아 두지 않고 role · baseline 으로 종류를 가른다.**

## 4. 맞추는 법 — (소스, 모델) → 노드

1. `orchestration_stream` 최근 N건(예: 500)을 읽는다.
2. `event_id` 로 겹침을 거르고 `execution_id` 별 마지막 기록을 만든다(`latest_by_execution`).
3. 마지막 기록이 `applied` · `running` · `degraded` · `replanned` 인 실행만 남긴다(`stopped` · `failed` 는 뺀다).
4. 그 실행의 `request_id` 로 `planned` 기록을 찾아 `plan.gpu_units[]` 를 펼친다 → `(소스, 모델) → {node, unit, fps_cap, need_mb}`.
   - 같은 (소스, 모델)이 둘이면 `ts` 가 늦은 것.
   - `replanned` 면 `detail.to_node` 가 이긴다.
5. 판의 행(`DetectSourceRow.source`)과 칩(`VisionModelSummary.model`)으로 찾는다. 이름이 같은 체계다(배치표 `sources` = data_stream 소스 이름, `models` = 레지스트리 선택지 키 = `/health vision.<모델>` 키).
6. 못 찾으면 **추정**: `/health.host` 를 data_stream 기기로 보고 「노트북?」.
7. 노드 → `node_resource_stream` 에서 그 노드의 마지막 `added`/`baseline` 기록(하드웨어)과 마지막 기록(사용량 · ready).

## 6. data_stream 에 물을 것 (협의)

1. `orchestration_stream` · `node_resource_stream` 을 가시화가 XREVRANGE 로 **최근 N건** 읽어도 되는가 (계획은 「읽기만」이라 적었으니 될 것으로 본다).
2. `running` 기록에 `node` 와 `models` · `sources` 를 같이 적어 줄 수 있는가 — 지금은 `planned` 의 배치표와 맞춰야 해서, `planned` 가 maxlen 에 밀려나면 맞출 수 없다.
3. 로컬 노드 이름을 `DS_NODE_NAME=book-4vg1edpvi5-wsl` 로 고정하는가 (자원표 `-1` 과 nodes.json `-wsl` 이 다르다).
4. 오케스트레이터를 안 쓴 실행(런처 「자원 배분」 끔)도 위치를 알 길이 있는가 — `vision_telemetry:*` 키를 가시화가 읽어도 되는가, 아니면 `/health vision.<모델>` 에 `host` 한 칸을 더해 줄 수 있는가.
