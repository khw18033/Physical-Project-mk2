# AI 생성 임무 실행기 — 가시화 쪽 구현 계획

> 작성 2026-11-23 · 대상: `viz-debugger` (가시화)
> 상태: **계획.** 구현하지 않았다.
> 방향(사용자 2026-11-23): **정량 명령 임무가 쓰는 실행 길(승인 → 관문 → 「임무 시작」 → 걸음 발행)을 다시 쓴다.**

## 0. 지금 상태 (2026-11-23 코드 확인)

| 자리 | 지금 | 파일 |
|---|---|---|
| 생성 요청 | `actions` 를 안 켠다(기본 `false`). 생성기는 액션 아이템을 낼 수 있지만(3단계, 10-23) gen-lab 측정에서만 켜져 있다. | `src/generate/LlmClient.ts` |
| 생성 결과 → 화면 | 과업마다 `actionItems: []` 로 비운다. | `src/generate/proposal.ts` (`tasksFromGenerated`) |
| 승인 | 캔버스에 올리고 과업마다 `created` 사건을 심는다. **로봇 관문은 정량 명령(`steps`)만 연다** — AI 편은 일부러 안 연다. | `src/data/scenario.ts` (`activateGenerated`) |
| 결과 | 명령이 안 나가고 노드는 대기에 멈춘다. | |

정량 명령 임무가 도는 길은 이미 있다:

```
stepMissionView()  → view.params.step_commands = [{ taskId: 'T-Q1', action, parameters }, …]
승인 → markApproved()
「임무 시작」 → wantsStepMission() → issueStepMission(client, view.params)
            → issueSteps(): 한 명령씩, 앞 명령의 종료 응답을 받은 뒤 다음
로봇 응답 → 명령이 든 taskId 로 노드를 칠한다 (robotBridge.ts)
```

**요점: AI 임무도 `view.params.step_commands` 를 만들어 주면 같은 길로 돈다.** 칠하는 길은 이미 범용이다 — 명령이 자기 과업 id 를 들고 가면 된다.

| # | 내용 | 안 |

## 2. 액션 아이템 → 걸음

### 2-1. 바꾸는 규칙 (`src/generate/actionCommands.ts` 새 파일)

```
과업마다:
  node_kind != act                    → 명령 없음 (사람 확인 과업)
  action_items == []                  → 명령 없음 (생성기가 이유를 why 에 남긴 것) · 사람 확인 과업
  action_items[i].params.action 이
    equipment.json actions[target] 에 없음      → 거부 (생성 어휘 밖)
    scan_mission                                 → 거부 (1단계 금지)
    open_gate · close_gate                       → 거부 (2단계)
    abort                                        → { taskId, action: 'abort' }  값 필요 없음
    turn · move_forward                          → 값이 있으면 그 값, 없으면 「채울 값」으로 표시
```

- **거부가 하나라도 있으면 그 임무 전체가 실행 불가다.** 정량 명령과 같은 원칙이다(`stepScript.ts` — 「절반만 읽고 나머지를 지어내지 않는다」). 승인 칸에 무엇이 왜 거부됐는지 적는다. 화면에 올려 보는 것(계획 보기)은 지금처럼 된다.
- 값의 범위 검사는 정량 명령의 것을 쓴다(`TURN_MIN_DEG` 등 `stepScript.ts` 상수 — turn 5~360 · move_forward 0.05~10 m). 10 m 를 넘으면 정량 명령처럼 나눠 내고 나눈 것을 적는다.
- 결과는 `view.params.step_commands` 에 싣는다 — 각 걸음에 **생성 임무의 과업 id**(`T-11b` 등)를 그대로 단다.

### 2-2. 장비 고르기

- 액션 아이템의 `target` 은 레지스트리 이름(`robot-01` 등)이다. 실제 장치는 `deviceIdentity.ts` 가 레지스트리 이름 → 장치를 잇는 길을 쓴다.
- 이어진 장치가 없거나, 그 장치가 밝힌 동작(Capability)에 그 명령이 없으면 **승인 칸에서 막는다.** 발행 직전에도 한 번 더 본다(지금 `issueStepMission` 이 `move_relative` 를 보는 자리와 같은 방식).
- 1단계는 **한 임무에 장치 하나**다. 서로 다른 로봇이 섞여 있으면 실행 불가로 표시한다(계획 보기는 된다).

## 3. 값 채우기 (결정 2)

- 승인 칸(`PlanApproval.tsx` 또는 발화 판의 제안 카드)에 「채울 값」 줄이 선다: `T-11b 문 앞까지 주행 · move_forward · 거리 [   ] m`.
- 발화에 숫자가 있었고 생성기가 그 값을 `params` 에 적었으면 미리 채워 두되 **고칠 수 있게** 둔다.
- 다 채워야 승인 버튼이 선다. 범위 밖이면 그 칸에 이유를 적는다.
- 기록: 승인 직전에 `human` 사건 `action_params_filled { task_id, action, params }` 를 남긴다. 「모델이 무엇을 냈고 사람이 무엇을 채웠나」가 갈려야 한다(`activateGenerated` 의 「값을 정한 쪽이 주체다」).

## 4. 명령 없는 과업 (결정 3)

- 실행 순서에서 그 과업 차례가 오면 노드가 「사람 확인 대기」로 선다. 앞 과업이 끝나기 전에는 누를 수 없다.
- 노드 상세에 「확인」 · 「실패로 닫기」 둘. 누르면 `human` 사건을 남기고 다음 걸음으로 간다.
- **「실패로 닫기」나 정지 → 뒤의 걸음은 안 나간다.**
- 이 기다림 때문에 걸음 발행이 한 번에 쭉 나가는 지금 `issueSteps()` 로는 부족하다. 걸음 사이에 「사람 확인」 칸을 끼울 수 있는 실행기가 필요하다 (§5 S4).

| **S9 검사** | `scripts/verify-generated-run.mjs` (새) | §6. |

순서: **S3 → S2 → S6 → S5 → S4 → S7 → S8 → S1 → S9.** 규칙(S3)과 승인 칸(S6)을 먼저 세우면, 생성기를 켜지 않고 정답셋 임무(`gen-lab/goldset/missions/MSN-260831-0{1,2,3}.json`, 액션 아이템이 들어 있다)를 넣어 끝까지 돌려 볼 수 있다. 생성 스위치(S1)는 마지막이다.

- 정답셋은 생성 결과와 모양이 다르다 — 과업이 맨 위 `tasks[]` 에 있고 마일스톤은 `task_ids` 만 든다. 생성 결과는 `milestones[].tasks[]` 다. 검사(S9)에 이 둘을 바꾸는 작은 변환을 둔다. 액션 아이템 한 건의 모양은 둘이 같다: `{ item_id, target, adapter, params: { action, … }, status, telemetry_ref }`.
- **사람 확인 과업이 많다.** `MSN-260831-01` 은 과업 17개 중 명령이 있는 것이 4개(`T-11b` · `T-13b` · `T-14a` · `T-15b`)라 「확인」을 13번 눌러야 끝난다. 1단계는 그대로 두고 실물에서 불편하면 「앞의 명령 없는 과업 한꺼번에 확인」을 더한다(§7).

## 6. 검사

- **승인 전 발행 없음:** `verify:no-publish-before-approval` · `verify:proposal-gate` 가 AI 편 실행 길을 넣고도 그대로 통과.
- **정답셋 셋으로 끝까지 (가짜 Go1):**
  - `MSN-260831-01`: `move_forward` 셋(값 채움) · `abort` 하나 · 명령 없는 과업은 사람 확인 → 걸음이 과업 순서대로, 앞 명령 종료 뒤에만.
  - `MSN-260831-02`: `move_forward` 둘.
  - `MSN-260831-03`: 수문 → **실행 불가**(2단계), 계획 보기만 된다.
- **거부:** 어휘 밖 동작 · `scan_mission` · 장치 없음 · 장치가 그 동작을 안 밝힘 · 장치 둘 → 승인 버튼이 안 서고 이유가 적힌다.
- **값:** 빈칸 · 범위 밖 · 10 m 초과(나눔) · 생성기가 적은 값 미리 채움.
- **사람 확인:** 「확인」 전에는 다음 걸음이 안 나간다. 「실패로 닫기」 · 정지 뒤에는 아무것도 안 나간다.
- **문 찾기 스캔 안 따라 나감:** AI 편 승인 + 시작 뒤 `scan_mission` 이 한 번도 발행되지 않는다.
- **정량 명령 · 대본 편 무손상:** 지금 검사(`verify-script-*` · 정량 명령 검사)가 그대로 통과.

## 7. 2단계 이후

- 수문(`open_gate` · `close_gate`): 게이트웨이 명령 길(`gateway/commands.ts` `ACTION_CATALOG`)로 내는 갈래.
- 장치 여러 대 · 병렬 걸음(의존성 없는 과업 동시 실행).
- 명령 없는 과업을 한꺼번에 확인하기(§5 끝).
- 거리 · 각도를 사람이 아니라 앞 과업 결과(탐지 · 경로)에서 채우기 — 스캔 탐지 계획서(`작업프롬프트_스캔탐지_data_stream_구현계획_261123.md`)의 위치 결과와 이어진다.
