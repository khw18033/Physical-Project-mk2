## 1. 긴급정지를 기록 열에 남긴다

### 지금

```
pauseMission()    → recordCommanded() 를 부른다        ✅
emergencyStop()   → 안 부른다                          ❌
```

**일시정지는 적히고 긴급정지는 안 적힌다.** 비대칭에 이유가 없다.

Outline §4-5 가 「사람이 만든 값을 적는다」고 주장하는데 정지는 사람 행동의 대표다.
9/21 보고서도 「사람이 누른 정지는 `robot.stopped` 에만 남고 되감아도 명령 표에 안 보인다」고
적었다.

### 할 일

`emergencyStop()` 이 `recordCommanded` 와 그 답을 남기게 한다. `pauseMission()` 과 **같은 모양**이다.

### ⚠ 건드리면 안 되는 선

9/20 지시서가 **「긴급정지 경로의 동작은 한 줄도 안 바꾼다」**고 못박았고
`verify:emergency-stop` 이 지킨다. 그 선은 그대로다.

- `abort` 발행 · 추적 중단 · 타이머 정지 · 화면 잠금의 **순서를 안 바꾼다**
- 2·3·4 가 1 의 결과를 안 보는 뼈대를 **안 바꾼다**
- 발행이 예외를 던져도 잠그는 것을 **안 바꾼다**
- **기록만 더한다.** 기록은 이미 나간 뒤에, 또는 이미 받은 뒤에 적는다

`verify:emergency-stop` 이 초록인 채로 끝나야 한다. 빨개지면 선을 넘은 것이다.

## 2. 사람 층에 자동 명령이 섞여 있다 — 이 작업의 핵심

### 실측 — 오늘 실물 판에서 본 것

`mission-history/260921/114930_MSN-260909-01` 의 기록 열 79건 중 사람 층이 12건이다.
그 안이 **섞여 있다.**

```
seq 1000000  mission_restarted  nodeId=MSN-260909-01  payload{from:'button'}   ← 진짜 사람
seq 1000001  scan_mission       nodeId=robot-01       payload{steps:8,…}       ← 자동 명령
seq 1000002  scan_continue      nodeId=robot-01       payload{task_id:'no-node'} ← 자동 명령
seq 1000003  scan_continue      …                                              ← 자동 명령
   ⋮
```

`mission_restarted` 는 사람이 단추를 눌렀으니 맞다. **나머지는 사람이 누른 적이 없다.**

Outline §4-5 의 핵심이 「값마다 인공지능·백엔드·사람·로봇 중 누가 만들었는지 적는다」인데,
이 상태로 기록 그림을 논문에 실으면 **첫 질문이 「이게 왜 human 이냐」**다.

### 두 가지가 한 뿌리다

260920 에 액션 층을 더하면서 **사람 층의 옛 명령 줄을 안 지웠다.** 그래서

- 태스크가 있는 명령 → **사람 층과 액션 층에 두 번** 들어간다
- `task_id: 'no-node'` 인 명령 → **사람 층에만** 있고 주체가 틀렸다

### 할 일 — 층의 뜻을 하나로 정한다

> **사람 층은 사람이 한 일만 담는다. 명령은 종류를 가리지 않고 액션 층이 담는다.**

| 무엇 | 어디로 |
|---|---|
| `mission_restarted` 처럼 사람이 누른 것 | **사람 층에 그대로.** 주체 `human` 유지 |
| 태스크가 있는 자동 명령 | **액션 층만.** 사람 층 복사본을 없앤다 |
| `task_id: 'no-node'` 인 자동 명령 | **액션 층에 들인다.** 주체는 실제로 낸 쪽(`backend`) |

### ⚠ `NO_NODE` 를 액션 층에 들이는 것은 9/20 판단을 뒤집는 것이다 — 이유를 적는다

9/20 에 「순서도에 자리 없는 명령을 액션 층에 넣으면 어느 노드도 보여 줄 수 없는 외톨이
행이 된다」고 걸렀고 `verify:sdk-bridge` 가 지킨다.

**그 판단은 화면에 대한 것이었다. 기록에 대한 것이 아니었다.**

기록 열과 화면은 다른 물건이다. Outline §4-6 이 이미 「기록에는 다 남기고 화면은 깊이로
가른다」고 적었다. 같은 규칙을 여기 적용한다.

- **기록 열에는 들어간다** — 실제로 나간 명령이고 응답도 왔다
- **노드 밑에는 안 붙는다** — 붙을 노드가 없다. 화면은 지금 그대로

`verify:sdk-bridge` 는 **화면 쪽 조건으로 좁혀 고친다.** 「액션 층에 들어가면 실패」를
「노드에 붙으면 실패」로 바꾼다. 검사를 무르게 하는 것이 아니라 **보는 자리를 바로잡는 것**이다.

### ⚠ 그런데 이것이 분모를 건드린다 — 3절이 그래서 있다

## 3. 분모를 움직이지 않는다 — 측정이 둘로 나눠 보고한다

### 왜 이 절이 따로 있나

9/21 에 **재기 전에** 분모 경계를 정했다. 「`NO_NODE` 를 뺀다 — 기록 열이 분모다」였고,
그때 코드가 하는 그대로였다.

2절이 `NO_NODE` 를 기록 열에 들이면 **그 문장만으로 분모가 저절로 커진다.**
9/21 표의 「`NO_NODE` 까지 넣었다면 약 107」이 그 크기다. 75 가 107 이 된다.

**이것을 그냥 두면 골대를 옮긴 것이 된다.** 축 가를 뺀 판정이 100 미만이었는데
코드를 고쳐서 100 을 넘기는 모양이 된다. 107 로는 축 가가 어차피 안 살아나므로
얻는 것도 없고 잃는 것만 있다.

### 할 일

`measure:trace-scale` 이 **두 줄로 나눠 내놓는다.**

```
분모 (노드에 붙은 액션)        … ← 9/21 과 같은 정의. 이 숫자가 §5-2 에 간다
노드에 안 붙은 명령            … ← NO_NODE. 따로 적는다
합계 (기록 열 전체)            …
```

**세는 자리는 하나로 둔다.** 9/21 에 `tally()` 하나로 모은 것을 쪼개지 마라.
재료를 다르게 넣는 것이지 세는 규칙이 둘이 되는 것이 아니다.

### 판정

재측정에서 **분모가 9/21 의 75 언저리에 그대로 있어야 한다.** 크게 움직이면 2절에서
무언가를 잘못 옮긴 것이다. 움직였으면 멈추고 보고해라 — 혼자 판단해서 분모를 맞추지 마라.

## 4. 실물 판을 다시 쌓는다

### 왜

지금 50판은 전부 9월 중순 코드가 기록했다. 1·2절을 고치면 기록되는 내용이 달라진다.
**고친 뒤 다시 태워야 논문이 서술하는 시스템과 숫자를 만든 시스템이 같아진다.**

### 어떻게

- 대본은 **`MSN-260909-01`** — 9/21 과 같은 편이어야 견줄 수 있다
- **완주 13판**을 목표로 한다. 9/21 과 같은 수라 중앙값을 바로 맞댈 수 있다
- 완주 못 한 판도 **버리지 마라.** 9/21 이 미완주 25판을 같이 쟀고 그게 판정의 근거였다
- **정지를 누른 판을 최소 둘** 만든다. 1절이 실제로 기록되는지 보려면 필요하다
- 판마다 `mission-history/` 에 그대로 쌓인다. 지우지 마라

### 1·2절이 실제로 들어갔는지 새 판에서 확인

| 확인 | 기대 |
|---|---|
| 정지한 판 | 정지가 **명령으로 적히고** 되감으면 명령 표에 뜬다 |
| 사람 층 | `mission_restarted` 류만 남는다. `scan_*` 이 없다 |
| 액션 층 | `no-node` 명령이 들어 있고 주체가 `backend` 다 |
| 중복 | 같은 명령이 두 층에 없다 |

## 6. 검사

### 신설 셋

| 검사 | 보는 것 | 대조군 |
|---|---|---|
| `verify:stop-recorded` | 긴급정지가 명령으로 기록 열에 들어가는가. **동작 순서는 그대로인가** | 기록을 지운 사본 · 순서를 바꾼 사본이 둘 다 잡혀야 |
| `verify:human-layer-pure` | 사람 층에 자동 명령이 없는가 | `scan_mission` 을 사람 층에 도로 넣은 사본이 잡혀야 |
| `verify:no-command-dup` | 같은 명령이 두 층에 없는가 | 복사본을 되살린 사본이 잡혀야 |

**대조군 없는 검사는 통과해도 아무것도 증명하지 않는다.** 9/20 에 두 번 스스로 걸린
자리다. 일부러 틀린 사본이 반드시 잡히는지 같이 확인해라.

대조군은 **LF 로 정규화한 원본**에서 만든다(`readSource()`). `verify:crlf-safe` 가 지킨다.

### 고칠 것

- `verify:sdk-bridge` — 「액션 층에 들어가면 실패」 → 「노드에 붙으면 실패」 (2절 ⚠)
- `verify:human-trace` — 사람 층의 정의 자리가 바뀐다
- 그 밖에 빨개지는 것

**파일 하나를 고치면 그 파일을 보는 검사도 같은 커밋에서 고친다.** 한 번도 빨간 채로
넘어가지 않는다.

## 9. 이것이 끝나면

논문 §5 의 숫자가 **오늘 코드가 기록한 판**에서 나온다. §4-5 가 단서 없이 참이 되고,
§4-8 에서 「`NO_NODE` 는 기록 열 밖」이 「기록되지만 노드에 안 붙는다」로 바뀐다.

그다음은 Foxglove 비교와 화면으로 되감기 손 확인이다. 둘 다 코드 수정이 아니다.
