# 작업 지시: 사람이 바꾼 값을 되감아 볼 수 있게 한다

**날짜** 2026-10-26
**선행** `작업보고/2026-10-26_adjusted판.md` **3절** — 그 보고서가 원인 둘을 이미 짚었다
**범위** 되감기 화면의 「사람이 바꾼 값」 목록. **기록 쪽은 손대지 않는다**
**목표** **기여 1 의 마지막 예외를 닫는다**
**로봇** **필요 없다.** 사건이 `261026/024124_MSN-260909-01` 에 이미 있다

---

## 0. 무엇이 안 되나

`adjusted` 사건 둘이 기록 열에 들어갔다. 그런데 **되감기 화면에서 볼 수 없다.**

```
112.40초  adjusted  T-B1  human  { field: "speed",     before: "0.35", after: "0.25" }
140.86초  adjusted  T-B1  human  { field: "clearance", before: "0.18", after: "0.30" }
```

기여 1 이 **「세 층이 모두 재실행 없이 되감긴다」**고 주장한다. 명령도 응답도 되감긴다. **사람이 바꾼 값만 안 된다.** 지금 기여 1 의 유일한 예외다.

---

## 1. 원인 둘 — 성격이 다르다. 같이 다루지 마라

### 가 — 액션 층 시각 2부의 누락 (단순)

`views/ActionModal.tsx`

```ts
const planChanges = planAdjustments(displayMission().headSec, traceFor(view), task.id);
                                    ^^^^^^^^^^^^^^^^^^^^^^^^^
```

**라이브 재생 머리를 읽는다.** 2부에서 명령 표를 `actionsAt(second)` 로 옮겼는데 **이 줄이 빠졌다.** 같은 작업의 미완성이다.

### 나 — 10월 25일에 **일부러 막은 것** (주의)

되감기 화면에서는 노드를 눌러도 실패 화면으로 안 바뀐다. `failure` 가 거짓이라 폼과 그 안의 목록이 **통째로 안 그려진다.**

**이건 손보기 커밋 `167bf7e`(「다시보기에서 노드를 열어도 되감기가 안 풀린다」)의 결과다.** 되감기 중에 노드를 열면 되감기가 풀리던 문제를 막은 것이고, **그 판단은 맞다.**

> **그냥 풀지 마라.** `167bf7e` 가 무엇을 막았는지 먼저 읽고, **그 이유를 깨뜨리지 않는 길**로 간다.

---

## 2. 설계 — 입력칸과 목록을 가른다

**되감기에서 값을 바꿀 수는 없어야 한다.** 과거를 보는 중에 입력칸이 뜨면 「지금 고치면 그때가 바뀌나」로 읽힌다.

| | 라이브 | 되감기 |
|---|---|---|
| **입력칸**(진입 속도·최소 클리어런스) | 띄운다 | **안 띄운다** |
| **「사람이 바꾼 값」 목록** | 띄운다 | **띄운다 · 슬라이더를 따른다** |

그러면 원인 나 를 우회할 수 있다 — **목록을 폼 밖으로 빼면** `failure` 조건과 무관해진다.

**이것은 후보이지 결정이 아니다.** 다른 길이 더 나으면 그 길로 가되 **보고서에 왜 그 길인지 적어라.** 화면 구조는 되돌리기 비싸다.

---

## 3. 증명 — 이 판으로 사진을 찍는다

`261026/024124_MSN-260909-01` 을 이력 다시보기로 연다. **로봇을 다시 돌리지 않는다.**

| 슬라이더 | 보여야 할 것 |
|---|---|
| **100초** | 「사람이 바꾼 값」 **비어 있다** |
| **120초** | `speed 0.35 → 0.25` **한 줄** |
| **141초 이후** | **두 줄** |

세 장을 찍어 보고서에 넣는다. **사람이 눈으로 본다** — 검사는 글자만 본다.

그리고 **라이브 판에서 입력칸이 그대로 뜨는지** 확인한다. 되감기에서 감추려다 라이브까지 감추면 `adjusted` 를 만들 길이 사라진다.

## 4. 검사

### 신설 하나

| 검사 | 보는 것 | 대조군 |
|---|---|---|
| `verify:adjust-rewind` | ① 목록이 **`second` 를 받는다** · ② 되감기에서 목록이 그려진다 · ③ 되감기에서 **입력칸은 안 그려진다** · ④ 라이브에서는 입력칸이 그대로 | `displayMission().headSec` 로 되돌린 사본 · 되감기에서 목록을 안 그리는 사본 · 되감기에 입력칸을 띄우는 사본 · 라이브 입력칸까지 감춘 사본 |

대조군은 **LF 로 정규화한 원본**에서 만든다(`readSource()`).

### 깨질 만한 것

`verify:action-modal-rewind`(2부 신설) — 같은 파일을 본다. **조건을 빼지 말고 보는 자리를 옮겨라.**

그리고 `167bf7e` 가 세운 검사가 있으면 **그것이 반드시 초록이어야 한다.** 되감기가 다시 풀리면 이 작업은 실패다.

## 5. 하지 않을 것

- **기록 쪽** — `adjusted` 는 이미 제대로 적힌다. `actionTrace.ts` · `trace.ts` · `fold.ts` 를 건드릴 일이 없다
- **폼의 자리와 값** — 10월 26일에 「그대로 두고 논문에 밝힌다」로 정했다. 입력칸을 어디에 띄울지, `before` 를 어디서 읽을지는 이번 범위가 아니다
- **명령에 붙는 조정을 만드는 코드** — 범위 밖. 그리는 자리만 있는 채로 둔다
- **판을 다시 태우는 것** — 사건이 이미 있다
- **`167bf7e` 되돌리기** — 1절 나
