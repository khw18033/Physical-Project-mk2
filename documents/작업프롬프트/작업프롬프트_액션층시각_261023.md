# 작업 지시: 액션 층 시각이 0으로 적힌다 — 되감기가 거기서 안 먹는다

**날짜** 2026-10-23
**찾은 경위** Foxglove 에 실물 판을 넣었더니 응답 네 줄이 **전부 0초**에 겹쳐 「Zoom for more」가 떴다
**범위** 액션 층 사건의 `atSec`. **다른 층은 손대지 않는다**
**목표** **명령과 응답이 실제로 오간 시각에 적힌다.** 지금은 24판에서 0이다

> **순서** 밀려 있는 지시서 셋보다 **이것이 먼저다.** 기여 1 에 직접 걸리고,
> 고치기 전에는 새로 뽑는 판도 같은 결함을 안고 나온다.

---

## 0. 무엇이 틀렸나 — 실측

판 `260929/204133_MSN-260929-02` 에서 **같은 명령이 층마다 다른 시각**으로 적혀 있다.

```
사람 층     turn            atSec 37.8
액션 층     commanded       atSec 0      ← 같은 명령
액션 층     answered ×4     atSec 0
태스크 층   T-E3 started    atSec 37.8
태스크 층   T-E3 failed     atSec 38.8
```

### 전수 조사 — 보관 113판

| | |

| 명령·응답 사건 | 719건 |

처음에 「시연 대본 13판은 정상」이라 적었는데 **틀렸다. 성한 판이 하나도 없다.**

|---|---:|---:|---|---|

한 명령(`cmd-hiiztmpg`)의 응답 30줄이 이렇게 적혀 있다.

```

26.64 30.80 32.55 33.18 37.18 38.91 39.53 43.59 45.29 45.92
48.0 48.0 48.0 48.0 48.0 48.0 48.0        ← 일곱 줄이 한 점
```

**§5-1 의 표가 여기서 깨진다.** 「60초에 39줄」이라 적은 행은 실제로는 48초 값이다. 48초 뒤로는 재생 머리를 밀어도 줄이 안 늘어난다. §4-1 의 태스크 식별자 반례와 같은 그림인데, 이쪽이 더 나쁘다 — 식별자 쪽은 경로가 **안 돌아서 멈추고**, 이쪽은 **돌면서 조용히 틀린 시각을 적는다.**

### 왜 고치나

기여 1 이 **「세 층이 모두 재실행 없이 되감긴다」**고 주장한다. 액션 층 시각이 0이면 재생 머리를 어디 두든 명령이 전부 보이거나 전부 안 보인다. **되감기가 액션 층에서 안 먹는다.**

§5-1 의 그 표 — 5초에 0건, 10초에 6줄, 60초에 39줄로 차오르던 것 — 은 **시연 대본 판에서 잰 것이다.** 생성 임무에서는 그 표가 안 나온다.

## 1. 원인 둘 — 이미 잡았다. 조사부터 하지 마라

### 원인 가 — `durationSec` 이 0인데 거기에 맞춰 자른다

`viz-debugger/src/data/scenario.ts`

```ts
function actionAtSec(atSec?: number): number {
  const at = atSec ?? state.headSec;
  return Math.max(0, Math.min(at, state.current.durationSec));
}
```

**`Math.min(at, durationSec)`** 가 범인이다. 생성 임무는 `durationSec` 이 **0**이다 — 길이를 모르는 임무이니 당연하다. 그래서 **아무리 늦게 나간 명령도 0으로 깎인다.**

**`durationSec` 이 얼마든 상관없다** — 실제 판이 그보다 길면 그 뒤가 전부 깎인다. 생성 임무가 0 인 것은 길이를 모르는 임무이니 당연하고, 시연 대본이 48 인 것은 대본에 적힌 길이다. **둘 다 실제로 흐른 시간과 상관이 없다.**

자르는 장치 자체는 **대본 재생용**이다. 대본은 길이가 정해져 있으니 그 밖으로 나가면 안 된다. 그런데 **실물 기록은 대본이 아니다.** 대본용 장치를 라이브에 그대로 쓴 자리다.

### 원인 나 — `elapsedSec()` 가 조용히 0을 준다

`viz-debugger/src/physical/robotSession.ts:480`

```ts
export function elapsedSec(): number {
  if (session.startedAtMs === null) return 0;
  return (Date.now() - session.startedAtMs) / 1000;
}
```

`MSN-260929-02` 14판은 전부 **`startedAtMs = null`, `started = false`** 다. 드론 임무라 Go1 세션을 안 거친 것으로 보인다. 그래서 `elapsedSec()` 가 0을 주고, 호출부가 그 0을 그대로 `atSec` 으로 넘긴다.

**주석이 「시작 전에는 0이다」를 의도라고 적어 뒀다.** 그 의도는 맞다 — 탐지 시료와 여덟 칸이 그 시계를 쓴다. 문제는 **명령이 나가는 시점에 세션이 안 섰다면 그것은 0초가 아니라 「모른다」**라는 것이다. 0을 돌려주면 그 둘이 같아 보인다.

### 원인 다 — 사람 명령 경로는 `atSec` 을 아예 안 준다

`viz-debugger/src/physical/humanCommands.ts`

`recordHumanCommand` 와 `recordHumanAnswer` 가 `recordCommanded`·`recordAnswered` 를 부르면서 **`atSec` 을 안 넘긴다.** 그러면 `actionAtSec` 이 `state.headSec` 으로 떨어진다. 되감아 둔 상태에서 명령을 내면 **과거 시각에 적힌다.**

지금 판에서는 이게 안 드러났다 — 사람 명령이 적은 판뿐이다. **그래도 고친다.** 가·나 를 고쳐도 이 길이 남으면 같은 증상이 다시 난다.

## 2. 혼자 정하지 말 것 — 고치기 전에 보고해라

**`Math.min` 을 그냥 지우면 안 된다.** 대본 재생 쪽이 그 자름에 기대고 있을 수 있다. `scenario.ts:687` 근처가 `durationSec` 을 늘려 가며 라이브를 받는 장치(`LIVE_STRETCH_SEC`)인데, 그쪽과 어떻게 맞물리는지 먼저 봐야 한다.

### 보고할 것 셋

| | 무엇 |
|---|---|
| **1** | `actionAtSec` 의 자름이 **누구를 위한 것인가.** 그 자름이 없으면 무엇이 깨지는가 |
| **2** | `durationSec` 이 0인 임무에서 **재생 머리는 어떻게 움직이는가.** 자름을 라이브에만 끄면 재생이 어긋나는가 |
| **3** | `elapsedSec()` 가 **0 대신 무엇을 줄 수 있는가.** 후보 둘을 적고 고른 이유를 밝혀라 |

3번 후보로 짐작되는 것.

- **세션 시작 대신 임무 시작을 기준으로** — `mission.json` 의 `startedAtIso` 가 있다. 다만 그 시계와 탐지 시료의 시계가 어긋날 수 있다
- **「모른다」를 그대로 올린다** — `null` 을 주고 호출부가 기록할 때 결정한다. 조용한 0보다 낫지만 받는 쪽이 늘어난다

**어느 쪽이든 보고 후 결정이다.** 시계를 바꾸는 일이고 탐지·뷰포인트가 같은 시계를 읽는다.

## 3. 고쳤다는 것을 무엇으로 보이나

### 3-1. 목으로 — 세 대본

**셋 다 시각이 퍼져야 한다.** 성한 대본이 없으므로 「지금과 같아야 한다」는 회귀 기준이 **없다.**

회귀는 **48초 이전 구간**으로 본다. 시연 대본 판의 0~48초 액션 사건은 지금과 **같아야** 한다. 달라지면 자름 말고 다른 것을 건드린 것이다. 그 뒤 구간은 **48을 넘어 퍼져야** 한다.

### 3-2. 되감기가 액션 층에서 먹는지

`MSN-Q-*` 한 편으로 §5-1 의 표를 다시 만든다.

```
재생 머리     접힌 명령     응답 줄
 5초            ?             ?
10초            ?             ?
...
```

**시각이 퍼져야 이 표가 만들어진다.** 지금은 전부 0이라 아무 줄이나 같은 값이 나온다.

### 3-3. 실물로 한 판

**이것이 합격 기준이다.** 생성 임무 한 편을 실물 로봇으로 돌려 액션 층 시각이 퍼지는지 본다.

로봇이 안 붙으면 3-2 까지만 하고 **「실물 미확인」을 보고서 제목 옆에 적어라.**

### 3-4. 옛 판은 못 고친다

**이미 깎여 적힌 381건은 되살릴 수 없다.** 다시 만들 수 없는 기록이고 **37판 전부가 영향을 받는다** — 일부만 믿고 쓸 수가 없다. 논문에서 어디까지 쓸지는 따로 정하는데, **되감기를 말하는 자리에는 한 판도 못 쓴다.**

## 4. 검사

### 신설 둘

| 검사 | 보는 것 | 대조군 |
|---|---|---|
| `verify:action-time` | 액션 층 사건의 `atSec` 이 **같은 명령의 사람 층·태스크 층 사건과 어긋나지 않는다** · `durationSec` 이 0인 임무에서도 시각이 0으로 깎이지 않는다 | `Math.min` 을 되돌린 사본 · `elapsedSec` 이 0을 주는 사본 · `atSec` 을 안 넘기는 사본 |
| `verify:action-replay-generated` | **생성 임무**에서 명령 층이 재생 머리를 따라간다 — 과거 시점에는 그때까지 오간 것만 | 시각을 0으로 적는 사본 |

둘째가 핵심이다. 기존 `verify` 들이 전부 시연 대본을 전제로 쓰였을 가능성이 높다 — **그래서 이 결함이 108종을 통과했다.**

대조군은 **LF 로 정규화한 원본**에서 만든다(`readSource()`).

### 깨질 만한 것

`verify:action-trace` · `verify:fold-actions` · `verify:sdk-bridge` · 되감기 관련 전부. **이름으로 확인해라.**

고칠 때 원칙은 하나다. **검사가 보는 자리를 옮기는 것이지 조건을 빼는 것이 아니다.**

- **탐지·뷰포인트 시계 건드리기** — 그쪽은 `elapsedSec` 의 0을 의도대로 쓰고 있다. 2절 3번에서 영향만 보고하고 바꾸지 마라
- **옛 판 고치기** — 3-4. 다시 만들 수 없다
- **태스크 식별자 걷어내기** — 별도 지시서
- **생성기 액션 아이템** — 별도 지시서. 다만 **그쪽을 돌리기 전에 이것을 고쳐라** — 안 그러면 새로 나오는 액션 아이템도 0초에 적힌다
- **Foxglove 변환기** — `tools/foxglove/trace_to_mcap.py` 는 기록을 그대로 옮길 뿐이다. 손대지 마라

## 7. 이것이 끝나면

### 논문에서 바뀌는 자리

| 자리 | 무엇 |
|---|---|
| **§2-4 기여 1** | 「세 층이 모두 되감긴다」를 **생성 임무에서도** 쓸 수 있다 |
| **§5-1** | 표를 생성 임무로 한 번 더 만든다. 지금은 시연 대본 하나다 |
| **§6-5 측정 결함** | 둘에서 **셋**으로 늘었다가, 고치면 다시 줄어든다 |
| **§5-2** | 옛 24판의 액션 층 시각을 믿을 수 없다는 것을 적는다 |

### Foxglove 비교가 풀린다

판 1 후보 둘(`204133`·`205212`)이 **둘 다 전부 0**이라 지금은 쓸 수 없다. 정상 시각과 실패가 겹치는 판이 113판에 하나도 없다.

고치고 나서 **판 1·2·3 을 새로 뽑는다.** 실패 판, 무응답 판(`expired` 0건), 값 바꾼 판(`adjusted` 0건). 셋 다 지금 기록에 없다.

### 그리고 이것을 보고서에 적어라

**이 결함을 찾은 것은 우리 검사 108종이 아니라 남의 도구였다.** Foxglove 에 넣었더니 응답 네 줄이 한 점에 겹쳐 「Zoom for more」가 떴고, 그게 실마리였다.

§3-4 와 §5-5 가 해외 도구 비교를 「가장 큰 구멍」이라 적어 뒀는데, **그 비교를 준비하는 과정이 이미 한 건을 값했다.** 논문에 쓸 수 있는 이야기다.
