### 1-2. 사건 종류와 `producedBy`

**`producedBy` 값 넷**: `'ai' | 'backend' | 'human' | 'robot'` — `src/model/types.ts:71` (`ScenarioEvent`), 같은 합집합이 `src/scenarios/types.ts:121` (`ScriptEvent`)에 한 벌 더 있다. `twin` · `vision` 은 없다.

**사건 종류(`kind`)** — `kind` 의 타입은 `string` 이고(`src/model/types.ts:71`) 목록으로 묶인 것은 액션 층 넷뿐이다.

| 묶음 | kind | 정의 위치 |
|---|---|---|
| 액션 층 (목록) | `commanded` · `answered` · `expired` · `adjusted` | `ACTION_KINDS` `src/data/actionTrace.ts:49-58`, 만드는 함수 `commandedEvent`(139) · `answeredEvent`(174) · `expiredEvent`(199) · `adjustedEvent`(216) |
| 태스크 층 (흩어져 있음) | `created`(계획 · `scenario.ts:1053`) · `started` · `evaluated` · `failed` · `progress` (`taskRunner.ts:401-414,790`) · `derived`(대본 — `MSN-260831-02.json` 등, 「어느 태스크의 2회차인가」 `src/scenarios/types.ts:123`) | 문자열로 직접 적음 |

**새 kind 를 넣어도 `fold.ts` 를 안 고쳐도 된다.** `foldStatuses` 는 액션 kind 를 건너뛰고(`src/data/fold.ts:87`), `nodeId` 가 태스크 id 가 아닌 사건도 건너뛴다(`fold.ts:88`). 그래서 새 사건의 `nodeId` 를 **`commandId`** 로 두면 태스크 색에 닿지 않는다. 거꾸로 `nodeId` 를 태스크 id 로 두면 `fold.ts:89` 가 그 사건의 `status` 로 태스크를 칠한다 — 7절 ③.

`fold.ts` 마지막 변경은 `84ce2e2`(2026-09-21)이다(`git log -1 -- src/data/fold.ts`). 지시서의 「9/21 이후 0줄」과 맞다.

### 1-3. 장비 어댑터 구조

**원칙: 장비는 스스로 밝힌다.** `src/physical/deviceIdentity.ts` 머리말(1-44). 원천 셋 — `capability`(규약 uplink `{device_id, actions[]}`) > `registration`(상태의 `entity_id · entity_type · device_type`) > `topic`. 종류 문자열을 코드가 목록으로 정하지 않는다(31-37).

| 장비 | 붙는 길 | 근거 |
|---|---|---|
| Go1 · 드론(pi3) · **MT4(pi6)** | MQTT(웹소켓) 브로커. 명령 `terminal/<id>/downlink`, 응답 `terminal/+/uplink`, 상태 `zone/+/+/…`. 연결 관리 「physical」 칸에 브로커 주소 여럿(`src/shared/connections.ts:162`, `list: true`) | `src/physical/PhysicalClient.ts:86-112`, `src/physical/robotClient.ts:78` `syncRobotClients`, 상태 수신 `src/physical/deviceState.ts:184` (`noteConnectedEntity(…, 'mqtt')`) |
| 드론 비행 계통 | 위와 별도로 FC 링크 · 비행 실행 창구 | `src/physical/fcxFeed.ts` · `flightRunCommands.ts` (이번 점검 범위 밖) |
| 고정 카메라 | HTTP 로 상태 · 영상 | `src/fixedcam/fixedCamera.ts:138`, `cameraState.ts:170` (`'camera'`) |
| 3D 가상환경 PC | 주소가 답하는지만 본다 | `src/virtualmap/twinDevice.ts:120` (`'twin'`) |

연결 장비 저장소의 길은 다섯이다: `'state' | 'mqtt' | 'server' | 'camera' | 'twin'` (`src/shared/connectedDevices.ts:51`).

**새 장비를 붙이는 길**: 노드가 같은 규약으로 브로커에 `status.registration` · `capability` 를 내면 웹은 코드 수정 없이 장비로 본다. 화면이 기종별 판을 그리려면 판정 함수 하나가 필요하다 — MT4 는 `isArmDevice`(`src/physical/armControl.ts:67`, 팔 동작 선언 또는 상태의 `arm_state`)로 가른다. `adapters/unitree_go1.json` 은 실행 중 장비 붙이기에 안 쓰이고 `verify:adapter-swap` · `score-generation` 만 읽는다.

## 3절. 없는 · 부분 기능의 구현 방안

묶어서 제안한다. 모든 안의 공통 전제:

- **새 사건은 `nodeId = commandId`** 로 둔다. 그러면 `fold.ts:88` 이 저절로 건너뛰어 `fold.ts` 를 안 고친다.
- 새 kind 는 **`predicted` · `measured` · `violated` 셋**만 늘린다(지시서 4장). 되돌림 · 재전진 · 원인은 `commanded` 칸 덧붙이기와 `derived` 로.
- 새 kind 목록과 만드는 함수는 **새 순수 파일 하나** `src/data/experimentTrace.ts` 에 둔다(`actionTrace.ts` 와 같은 이유 — Node 검사가 직접 연다). `ACTION_KINDS` 에는 **안 넣는다** — 넣으면 `measure:trace-scale` 의 액션 층 셈(`measure-trace-scale.mjs:42-44`)과 `foldActions` 가 바뀐다.
- 주체 합집합에 `twin` · `vision` 을 더한다(`model/types.ts:71`, `scenarios/types.ts:121` 두 벌을 함께). 기존 사건 모양은 그대로다.
- seq 대역 하나를 새로 잡는다(예: `EXPERIMENT_SEQ_BASE = 2_500_000`). 대역이 안 갈리면 `TraceStore` 가 중복으로 지운다(`trace.ts:63-81`).

### A2 · A3 · A4 MT4 명령 · 응답 칸

- 무엇을 만드나: ① 응답의 결과 맵을 기록 열에 **숫자 그대로** 싣는 칸. ② (하드웨어가 되면) 그리퍼 닫는 정도 · 전류 값을 받는 자리.
- 어디에: `src/data/actionTrace.ts` `answeredEvent` 에 선택 칸 `result?: Record<string, number>` (종료 줄만), 부르는 쪽 `humanCommands.ts:82` · `robotCommands.ts:792,994` · `robotBridge.ts:82`. 팔 상태 칸은 `armControl.ts` `ArmView`.
- 어떻게: `UplinkMessage.result`(이미 받는다)를 종료 줄일 때만 payload 에 붙인다. `device` 칸처럼 **값이 있을 때만 칸을 만든다** — 9 · 10월 판과 모양이 같게.
- 기록 열에 미치는 영향: `answered` 에 선택 칸 하나. 새 사건 없음.

### D1 ~ D4 가역성 판정과 막기

- 무엇을 만드나: 왕복 [a, a⁻¹] 를 트윈에 묻고 `reversible` · `irreversible` · `boundary` 를 정해 발행 관문에 쓰는 자리.
- 어디에: `src/twin/reversibility.ts`(순수 — 판정 규칙), 관문은 B1 실행기의 발행 직전. 사람 덮어쓰기 단추는 H2 와 같은 판.
- 어떻게:
  - **역동작은 웹이 만든다**를 제안한다. 관절 이동의 역은 「시작 관절값으로의 `move_joint`(절대)」로 웹이 실측 시작값만으로 만들 수 있고, 그래야 G1 의 실물 역동작과 트윈 왕복 시험이 **같은 명령**을 쓴다. 그리퍼 닫기의 역은 열기, 펌프 흡입의 역은 배출이지만 **물체가 움직였는지는 트윈만 안다** — 그래서 판정은 트윈 결과로 한다.
  - 판정: 왕복 끝 관절값이 시작값과 문턱 안이고 충돌이 없으면 `reversible`, 의도된 접촉(`expectsContact`) 밖의 물체가 움직였거나 충돌이면 `irreversible`, 문턱 경계 · 관절 한계 근처면 `boundary`.
  - `irreversible` · `boundary` 면 발행하지 않는다. 사람이 「그래도 보냄」을 누르면 `adjusted`(`field: 'reversibility_gate'`, `before: 'blocked'`, `after: 'sent'`)를 남기고 보낸다.
- 기록 열: 왕복 결과는 `predicted` 의 payload 칸 `roundTrip: { verdict, deltas }` 로(지시서 4장의 `roundTrip?`). `commanded` 에 선택 칸 `reversibility` 를 실어 되돌림이 읽게 한다(D4). 덮어쓰기는 기존 `adjusted`.
- 원칙: 지킴. `adjusted` 의 기존 모양(`taskId · field · before · after`)을 그대로 쓴다.
- 검사와 대조군: `verify:reversibility-gate` — 가짜 트윈이 `irreversible` 을 주면 발행 0건, 덮어쓰기 뒤에는 발행 1건 + `adjusted(human)` 1건. 대조군: 판정을 무시하고 보내는 사본, 덮어쓰기를 `backend` 로 적는 사본.
- 의존: C 전부, B2.
- 작업량: M.
- 위험: 「원위치」 문턱을 누가 정하나(5절 ⑦). 끝점 이동(`move_cart`)의 역을 끝점으로 만들면 관절 해가 달라질 수 있어 **역은 늘 관절 절대값**으로 만든다.

## 7절. 지시서와 다르게 판단한 곳

1. **기록 열에 쓰는 자리는 다섯이 아니라 열넷이다** (1-1). 입구(`appendTrace`)는 여전히 하나다. 새 사건도 `scenario.ts` 의 기록 함수 하나를 늘려 그 입구로만 넣어야 한다.
2. **B4 의 박힌 id 파일은 8이 아니라 12** (주석 밖 기준). 막지는 않지만 `ActionModal.tsx:297-301` 은 편을 안 보고 id 로 Go1 판을 띄운다 — 「부분」으로 적었다.
3. **`derived` 는 이미 다른 뜻이다.** 대본에서 `derived` 는 「어느 태스크의 2회차」이고 `nodeId` 가 태스크 id, `status: rerunning` 이다(`MSN-260831-02.json`, `scenarios/types.ts:123`). 원인 표시를 같은 kind 로 적되 **`nodeId` 를 태스크 id 로 두면 `fold.ts:89` 가 그 태스크를 다시 칠한다.** 그래서 원인 · 복원 판정의 `derived` 는 `nodeId = commandId` 로 두고 `payload.method` 로 뜻을 가르는 것을 전제로 했다. 이것이 싫으면 새 kind 하나(`diagnosed`)가 필요하다 — 원칙 2 와 저울질할 일이다.
4. **트윈 요청의 관절은 `q:[…]` 보다 `j1..j4` 키를 권한다.** 장비 규약 값이 `map<string,double>` 이라(`proto:41`) 실물 명령이 이미 그 모양이다. 같은 키를 쓰면 변환 층이 하나 준다(5절 ④).
5. **역동작 명령에는 새 `commandId` 가 붙는다.** 지시서는 「새 식별자 만들지 않기」라 했지만 장비 규약상 명령마다 고유 id 가 있어야 응답을 짝짓는다(`PhysicalClient.ts:404-406,482`). 「역동작이 어느 명령의 역인가」는 `reverse_of` 가 원 id 로 가리키므로 **새 개념 식별자는 안 만든다**고 읽었다.
6. **A3 의 「`answered` payload 에 칸 추가」는 종료 줄에만** 붙이는 것으로 했다. `answered` 는 수락 · 진행 · 종료 여러 줄이라(`actionTrace.ts:174-197`) 모든 줄에 붙이면 같은 값이 여러 번 남는다. 동작 경계의 관절 스냅샷은 그것과 별개로 `measured(robot)` 에 남긴다 — 하나는 장비가 준 결과, 하나는 상태 관측이다.
7. **새 kind 는 `ACTION_KINDS` 에 넣지 않는다.** 넣으면 `measure:trace-scale` 의 액션 층 분모가 바뀐다 — 2026-10-22 에 「골대를 옮기지 않는다」고 정한 그 숫자다(`measure-trace-scale.mjs:20-24`).
8. **I7 을 4절 맨 앞으로 옮겼다.** 지시서는 「막는 것이 있으면 앞당긴다」고 했고, 실험 판이 덮어쓰이면 다시 얻을 수 없다.
